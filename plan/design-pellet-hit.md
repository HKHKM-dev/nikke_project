## 1. 何を足すか

プリバティ：アンカインド・メイド（313。SG）の S1「ペレットが 30 回命中した時、照準線に最も近い敵 2 機に最終攻撃力の X% のダメージ」は、射撃（トリガー）ではなく的に当たったペレットを数え、累計が 30 の倍数に届いたトリガーで出る（端数を持ち越す。ちょうど 30 の倍数でも出る。C-0408）。

今の語彙では書けない。回数トリガーは SG も 1 トリガーを 1 回と数え（`normalShot`）、命中も 1 トリガーを 1 回（`normalHit`。ペレットのどれかが当たる）と数える（`skills/types.ts` の `ShotCountKind`）。

## 2. 語彙: 回数の種類 `pelletHit`

```json
{
  "kind": "damage",
  "trigger": { "count": "pelletHit", "everyRef": 1 },
  "damageType": "skill",
  "ref": 2
}
```

- **量**: 1 発ごとに、その発で的に当たったペレットの数を足す。モデルは期待値で持つ: SG は `shotCount` × 当たったペレットの割合。割合はゲージ（C-0150）と同じで、的の表を使う枠（条件が自動）は区間の弾丸命中率（表の値が当たったペレットの割合）、手入力の枠は弾丸命中率 × `SG_PELLET_GAUGE_HIT_RATE`（0.75）。SG 以外（`shotCount` 1）は `normalHit` と同じ量（弾丸命中率）。
- **発火**: 既存の回数トリガーと同じ `advanceShotCount`。累計が N の倍数を越えた（整数ならちょうど届いた）発で 1 回発火し、端数を持ち越す。戦闘中はリセットしない。`during`（フルバースト中だけ数える）・`stacksRef` も既存のまま書ける。
- **数えないもの**: 外れたペレット（「命中した時」）。コンテナに当たったペレットは、モデルに障害物が無い（前提の外）ので数えない。ゲームで数えるかは確かめていない（V-0373「分からないこと」）。
- **書けない所**: `every` / `everyRef` を省いた毎回（1）は拒否する（1 発で複数のペレットを数えるので、1 発に 1 回の畳み込みと食い違う）。循環（`cycle`）も拒否する（循環は発の数で段を進める。`skills/cycles.ts` の `cycleShotFrames`）。確率のきっかけ（`chance`）は `CHANCE_COUNT_KINDS` に入れない。
- **1 発で N を越える量**: `advanceShotCount` は 1 発で 1 回しか発火しないので、1 発の量が N を超えたら `RangeError` にした（N がペレット数より小さい定義を通さないため。既存の種類は 1 発の量が 1 以下なので当たらない）。

型の変更:

- `ShotEvent.pellets?`（省略は `hits`）、`ShotLog.pelletHits?`（1 パス目が書く。バッチの出来事の列は `pelletHits` から作り直す）。
- `shotCountWeight('pelletHit')` = `pellets ?? hits`。

## 3. 録画で数えた入力 `pelletHits`（照合だけ）

モデルの量は期待値なので、録画の発ごとの当たった数のばらつき（S1 が 3 発目で出るか 4 発目で出るか）は再現しない。録画と発の番号まで比べるために、障害物（`obstacles`）と同じ形の入力を足した。

- `TeamInput.pelletHits`: `{ slotIndex, counts }[]`。`counts[k]` は k + 1 発目に的に当たったペレットの数（0 以上・`shotCount` 以下の整数。`validatePelletHits`）。有る発は期待値の代わりにこの数を `pelletHit` の回数に足す。ダメージとゲージには効かない。利用者の計算には出さない。
- 照合の `setup.pelletHits`: `{ slot, counts }[]`。`counts` は同じ録画の、use が input で値が整数の配列の観測値の id（V-0373 では `390-02`）。

## 4. 照合の指標 `skillHitShotIndices`

- 引数 `slot`・`skill`・`count`。枠のスロット `skill` の倍率ダメージ（持続ダメージを除く）の最初の `count` 回が、それぞれ枠の何発目（1 始まり。同じフレームの発を含む）の射撃で出たか。
- 録画では、S1 のヒット（発の約 6f 後に単独で出る）の直前のトリガーの番号（撃った順）と比べる（`390-04`）。
- モデルは発の 1 発目から数える。録画 390 は 2 区間目だけを撃ったので、モデルの発の時刻（1 区間目から撃つ）とは合わないが、番号は入力 `pelletHits` で決まるので比べられる。

## 5. 退化と影響

- 既存の定義は `pelletHit` を使わないので、数値は変わらない（`npm test` の全件が数値を変えずに通る。`firstPass.test.ts` の退化のテストは、比べから `pelletHits` の列を外した）。
- プリバティ：アンカインド・メイドの S1 を定義した。スペック固定・単騎・180 秒の AUTO（灼熱の BigArms・3 分モード）では S1 は 53 回で、通常攻撃の合計の約 3 割を足す。sim と calc は一致する（`privatyUmTeam.test.ts`）。

## 6. リスク・残り

- 期待値の数え方は、当たった割合が 1 発ごとに揺れる分を均す。S1 の回数の平均は合うが、区間の境目の前後で 1 回ずれうる（`normalHit` の期待値と同じ性質）。
- S2 の 2 つめ（フルバースト中のペレット 30 回命中ごとの弾丸チャージと攻撃力▲）は、`pelletHit` に `during: 'fullBurst'` を付けて書ける見込みだが、撮っていないので未対応の notes のまま。S2 の 1 つめ（1 トリガーでペレット 5 個以上命中でリロード速度▲）は、累計ではなく 1 発の閾値なので別の語彙が要る（未対応の notes のまま）。
- ヒットのフレームは発と同じ（実測は約 6f 後。C-0408）。遅れは `delayFrames` の検査の範囲外なので入れていない（backlog 4-20 と同じ話題）。

## 7. 手計算の予測（予測ファイルにできない予測）

V-0373 は、語彙が無く仮説ごとに定義（回数の種類）を切り替えるので、撮る前の予測を予測ファイルにできず、検証記録の「予測」の節に手計算で書いて撮る前に commit した。`records:close` は予測ファイルか「探索」「予測なし」しか認めなかったので、手計算の予測を認める形を足した（2026-10-09 のオーナーの承認「1 で進めて（閉じる検査を直す）」）。

- **印**: 予測ファイルが無く、「予測」の節に「手計算」と書いてある（「探索」「予測なし」は書かない）記録（`close.ts` の `isHandPrediction`）。
- **順の検査**: `records:close` が git の履歴で、「予測」の節がいまと同じ中身の最も古い commit（記録の改名・番号の振り直しをたどる。途中で書き足して元に戻した節もあるので、続いていなくてよい。同じ文が観測値より前にあったことは示せる）を予測の commit とみて、この記録の観測値がどれもそれより後の commit で足されたかを見る（予測ファイルの控えの検査と同じ `orderOf`）。節を commit していない・いまの中身が観測値より後の commit にしか無い・観測値が前か同じ commit なら誤り。調べられなければ誤り。
- **予測ファイルとの違い**: 値は手計算なので、予測との比べの表（`records:check`）は出ない。モデルとの照合は観測値の `compare` で行う（V-0373 では `390-04`）。結論の下書き（`records:new -- claim`）の「確定にできる条件」は予測ファイルを見るので、手計算の予測の記録の結論は人が確かめる。
- **使いどころ**: 予測ファイルで書ける予測は予測ファイルにする（`setup` の上書きと `addEffects` の差し替えで書ける仮説を含む）。手計算は、足していない語彙を仮説に含む予測に限る。
