# V-0903: コア強化の倍率の丸めは、小数で掛けた値の偶数への丸めか

- 問い: 戦闘力がモデルと 1 だけ合わない取得があるのは、コア強化の倍率の丸め（C-0016）の形のせいか
- 話題: 育成・ステータス
- 日付: 2026-11-28
- 状態: 調査中

## 条件

- 型: 撮影なしの絞り込み（録画は撮らない）。V-0685 と同じく、育成データのスナップショット（`private/builds/` の取得）の戦闘力と、同じ取得の育成から出したモデルの値を突き合わせる（`npm run build:combat-power`）。
- 使った取得: 2026-09-24〜11-28 の 11 回（`.raw.json` のあるもの全部。のべ 2,210 件）。
- きっかけ: 2026-11-14・11-18・11-28 の取得で、それぞれ 1 体ずつ（のべ 3 件・2 体）の戦闘力が、モデルより 1 大きかった。ほかの取得とほかのキャラは差 0（plan/design-combat-power-sort.md 4 節）。

## 予測

なし

## 読み方

- 合わない 3 件で、前後の取得との育成の違いを見る。違ったのはシンクロ Lv とリサイクルルームの Lv だけだった（装備・キューブ・スキル Lv は同じ）。
- 戦闘力の丸めの幅から、攻撃力・HP・防御力のどれがいくつずれれば合うかを出す。アリーナの戦闘力（キューブだけが違い、キューブはコアの外なので、コア強化の倍率の丸めは同じ）でも同じ幅を出して重ねる。
- コア強化の倍率を掛けた値（`applyCoreRatio`）が、整数で計算してちょうど .5 になる組を、全取得から拾う。
- 丸めの形の候補を、全取得の全キャラの戦闘力で比べる:
  - いまの形（整数で計算し、ちょうど .5 なら偶数へ）
  - 倍精度の浮動小数で value × (1 + core × ratio / 10000) などを計算してから偶数へ丸める形（式の書き方を 4 通り）
  - 単精度の浮動小数で計算する形（6 通り）
  - 素の値と、好感度・リサイクルルームの分を別々に丸める形（5 通り）

## 分かったこと・分からないこと

- 分かったこと:
  - 合わない 3 件は、どれもコア強化の倍率を掛けた値が整数ではちょうど .5 になり、いまのモデルが偶数（切り捨て）に丸めたステータスだった（攻撃力 2 件・防御力 1 件。どれもコア 5、倍率 ×1.1）。そのステータスを 1 大きくすると、戦闘力とアリーナの戦闘力の幅に両方とも入る。
  - 同じくちょうど .5 で偶数（切り捨て）に丸めた攻撃力・防御力はほかにものべ 12 件あり、そちらは切り捨てのままで戦闘力が合う。四捨五入（いつも切り上げ）にすると、その 12 件が外れる。
  - 倍精度の浮動小数で value × (1 + core × ratio / 10000) を掛け、偶数への丸め（C# の Math.Round の既定）で整数にすると、11 回の取得の 2,210 件が全部差 0 になる。合わない 3 件は、掛けた値が浮動小数の誤差で .5 を少し超える（例: 472,615 × 1.1 = 519,876.50000000006）ので切り上がる。合う 12 件は、掛けた値がちょうど .5 になる。C-0016 の根拠の 3 点（plan/verification.md Stage 12）も、この形で同じ値になる。
  - 単精度の浮動小数で計算する形は 15 件か 5 件、別々に丸める形は 286〜570 件外れる。
- 分からないこと:
  - 倍精度の式の書き方（1 + core × ratio / 10000 を先に作るか、(10000 + core × ratio) / 10000 か、など）。4 通りのうち (10000 + core × ratio) / 10000 の形だけが、コア 7 で違う値になりうるが、取得のちょうど .5 のコア 7 の 2 件では同じ値で、見分けられない。モデルは 1 + core × ratio / 10000 の形にした。
  - ゲーム内のキャラ画面のステータスで、合わない 3 件のステータスを直接見てはいない（戦闘力からの逆算）。
