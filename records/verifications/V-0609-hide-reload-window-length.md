# V-0609: 敵のジャンプの間のハイド中のリロードの境（リロード 1.73 秒の SR 単騎）

- 問い: リロードの秒 + 約 12f が、録画のハイド（約 110f）より長くモデルの窓（117〜118f）より短いキャラは、敵のジャンプの間のハイド中のリロードを終えるか
- 話題: 射撃（間隔・リロード・チャージ）
- 日付: 2026-11-01
- 録画: `0862`、`0863`
- 状態: 調査中
- 派生元: `V-0606`

## 条件

- 型: 撮る。V-0606「分かったこと・分からないこと」の 2 つ目と、plan/design-hide-reload.md 6 節の 3。
- 仮説の出どころ: ハイド中のリロードのバーの 0 の点から消える（取り消し）までの長さ（`0815-13`・`0816-10`・`0077-47`）が、モデルの狙えない窓（`range-3min-jump`。1 回 2 秒）より短い。込め終わりがリロードの秒 + 約 12f なのは C-0828（12f は C-0135）。
- モデル（C-0828 の形。`hideShooter`）では、射撃姿勢維持型でない武器は、リロードの秒 + 12f が窓（117〜118f）に収まれば終える。録画のハイドの長さで決まるなら、約 110f に収まらなければ終えない。リロードの秒 + 12f がその間に来るキャラで、2 つが分かれる。
- キャラ: アドミ（SR・入力が UP・6 発・リロード 1.73 秒）。リロードの秒（`packages/core/data/characters/172.json`）は約 101.8f で、+ 12f が約 113.8f。キャラのデータで、リロードが 1.67 秒より長く 1.79 秒以下なのはアドミだけ。
  - 1.67 秒のキャラ（6 体）は + 12f が約 110.2f で、`0815-13`・`0816-10` のハイドとほぼ同じ長さになり、どちらの仮説でも結果が割れうる（見分けに使えない）。1.8 秒以上のキャラは + 12f がモデルの窓とほぼ同じか長い。
- 最小構成: アドミ単騎・操作・オートバースト OFF。S1（被弾 20 回でのチャージダメージ倍率▲。範囲外）・S2（受けるダメージ▼）はダメージだけで、発の刻みとリロードに効かない。バーストのリロード速度▲は、オートバースト OFF の単騎ではバーストを使わないので起きない。
- 見分けの要: ジャンプの前に、そのマガジンを 1〜5 発撃っていた回（窓の始まりのチャージの途中の発は部分チャージで撃つ。C-0109）。窓の始まりにマガジンが空（6 発目を撃った後か、ふだんのリロードの中）の回は、ふだんのリロードなので数えない。
  - SR の発と発の間は約 82f、リロードを挟む間は約 183f（モデル）で、窓の始まりがマガジンのどこに来るかは録画ごとに決まる（ジャンプの時刻は録画で違う。C-0552・C-0553）。モデルの既定の窓で回すと、1〜4 回目のうち 3 回が見分けの要に当たる（5 回目は戦闘の終わりの直前で、明けの後に撃てない）。1 本で 2〜3 回を見込む。

## 予測

撮る前に固定する（2026-11-01）。仮説はモデルのコード（窓の長さかハイドの長さ）を切り替えるので、予測ファイルにせず、ここに手で書く。どの回も、窓に入る前に撃ったそのマガジンの発の数（部分チャージの発を含む）を r（1〜5）とする。

- 見分け方: 回ごとに、明けの後の発の数（6 か 6 − r か）で決まる。バーが満ちたか、満ちる前に消えたか（`reload.ts --mode fit` の canceled）を裏取りに使う。1 回でも分かれるが、反復実測にするため 2 本で数える。
- 回によってハイドの長さが違う（`0077-47` の 1 回目だけが他より約 5f 長い）なら、同じ録画の中で終える回と終えない回が混ざる（H3）。そのときは、回ごとのバーの 0 の点から消えるまでの長さ（終えない回）と、明けの後の 1 発目の時刻を並べ、ハイドの長さで分かれるかを見る。
- H1 なら、`0815-13`・`0816-10`・`0077-47` のバーが窓の終わりより早く消えるのは、取り消しの時刻がハイドの終わりより早いことになり、ハイドの長さの読みを見直す。H2 なら、ハイド中のリロードの込め終わりを、窓ではなくハイドの長さ（明け）で切る形がモデルに要る（設計書 3 節の案 B に近い）。

## 読み方

1. 総ダメージの増分は `node tools/captures/hud.ts <動画> --mode jumps`、RELOADING のバーは `node tools/captures/reload.ts <動画> --mode fit`（取り消された回は canceled）。照準の横の残弾は `tools/captures/ammo.ts`（V-0606 の読み方と同じ）。
2. ジャンプごとに、窓に入る前のそのマガジンの発の数 r（部分チャージの発を含む）、バーの 0 の点と消えたフレーム、満ちたか、明けの後にリロードの前に撃った発の数を読む。
3. モデルとは、録画のジャンプの窓（`setup.jumpWindows`）を入れて比べる（ジャンプの時刻の読み方は plan/captures/guide.md「3 分モードのジャンプの時刻」）。

## 結果

- 撮影は計画どおり（アドミ単騎・灼熱・3 分モード・スペック固定 ON・オート射撃 ON・オートバースト OFF を、出撃画面・左上のボタン・戦闘履歴で確かめた。キャラは出撃画面の 3 枠目）。
- 2 本とも、1〜4 回目のうち 2・3 回目は窓の始まりにマガジンが空（ふだんのリロード）で、見分けの要は 1・4 回目の 4 回（`0862-01`・`0863-01`）。

  - 部分チャージの発の 3 回は、バーが部分チャージの発とほぼ同じフレームから伸び、発から約 109f で取り消され、その 70f 後に明けの後の 1 発目を撃った（`0862-02`・`0863-02`）。バーの 0 の点から消えるまでは `0815-13`・`0816-10` と同じ長さ。
  - 0863 の 4 回目は、ふだんのリロードと同じく 3 発目のフレームからバーが伸び、ふだんの長さで満ちた。バーの 0 の点から明けの後の 1 発目までは約 190f で、明けは満ちた約 6f 後（明けの後の 1 発目の 70f 前）。この回のハイドは、0 の点から約 120f あった。
- 読み（仮説。この 2 本と V-0610 の録画から立てた）: 窓の始まりにチャージの途中なら、部分チャージの発は窓の始まりから約 8〜10f 後に出て、リロードはその発から始まる。窓の長さはモデル（117〜118f）のままで、部分チャージの発の分だけ、ハイド中のリロードに使える長さが短い。0863 の 4 回目は、窓の始まりにチャージが満ちていて、窓の始まりに撃ってリロードを始めた回と読める。部分チャージの発から明けまでの約 109f は、V-0610 の A2・紅蓮：ブラックシャドウの部分チャージの発の回とも、満ちてから撃つまでの長さ（H）の差を除いて同じ（V-0610「結果」）。
- いまのモデル（部分チャージの発とリロードの始まりを窓の始まりに置く。C-0109・C-0828）は、部分チャージの発の回で終えてしまい、3 回とも録画と合わない。

## 分かったこと・分からないこと

- 分かったこと:
  - リロードの秒 + 約 12f がモデルの窓より短く録画のハイドより長いアドミは、チャージの途中で窓に入った回（3 回）はジャンプの間にリロードを終えず、窓の始まりにフルチャージの発を撃った回（1 回）は終えた。
- 分からないこと:
  - 部分チャージの発が窓の始まりから遅れる長さ（約 8〜10f）と、それがほかの武器（押下チャージ型・チャージの無い武器）のハイド中のリロードの始まりにもあるか。`0815-13`・`0816-10`（押下チャージ型）のバーの 0 の点はモデルの窓の始まりと 0〜3f の差と読んだが、モデルの窓は録画の窓と同じではない。
  - `0077-47` の 1 回目だけ長い回（バーの 0 の点から消えるまで）が、0863 の 4 回目と同じ形（窓の始まりに撃った回）か。
  - 窓の始まりの直後（チャージの満ちる前）に撃ったときの扱い。
