# V-0318: フルバーストの後のゲージは 0 から溜まり直すか（録画 221・079・019 の読み直し）

- 問い: フルバースト中はバーストゲージが溜まらず、フルバーストが終わった時点で 0 から溜まり直す（C-0264。録画 019 の目視 1 本で単独実測・観測値なし）は、フルバーストの後に BURST バーが再び見えた所の読みで繰り返すか
- 話題: バーストゲージ
- 日付: 2026-10-08
- 録画: `221`、`079`、`019`
- 結論: `C-0264`
- 状態: 完了

## 条件

- C-0264（仮説・単独実測）: フルバースト中はゲージが溜まらない。フルバーストが終わった時点でゲージは 0 から溜まり直す。根拠は Stage 7 の録画 019 の目視（2026-09-23。観測値の ID は無い）だけ。モデル（`burst/controller.ts`）はこの形で、フルバーストの後の満タンのフレームの比べ（C-0207 など）はこのモデルの上で合っている。
- BURST バー（`gauge.ts`）は、フルバースト中・CT 待ち・チェーン中は別の UI になり読めない（「-」）。バーは本当のゲージの約 12.6〜96% だけを映す（C-0084。約 12.6% までは 0px）。
- 録画（フルバーストの後のバーはどれも読んでいない）:
  - `221`: ココア（I）+ デルタ（II）+ ラピ（III・操作）。オートバースト ON。
  - `079`: ラム（I）+ デルタ（II）+ ヘルム（III・操作・宝物あり）。オートバースト ON。全員 CT 40 秒で、2 回目からは CT が律速（`079-12`）。
  - `019`: エーテル（I）+ デルタ（II）+ ノワール（III・操作）。オートバースト ON。C-0264 の出どころの録画だが、観測値は無く、バーの数値は読まれていない。
- 最小構成: 見ているのはフルバーストの後のバーの長さと伸び方だけ。編成の未確定の要素（ヘルムの宝物版のゲージ、エーテルの S2 のゲージなど）は伸びの速さに効くが、「0 から始まるか」には効かない。

## 予測（撮る前に書く）

既存の録画の読み直し。フルバーストの後のバーは、この節を commit した後に読む。モデルの指標に無いので予測ファイルは作らない（予測ファイルによる数値の予測なし）。

| 仮説                                     | フルバーストの後にバーが初めて見えたフレーム                              | その後                                                                  |
| ---------------------------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| H0（C-0264。溜まらず、0 から溜まり直す） | 0%（0px）                                                                 | 最初に光るのは、その後の伸びの速さで本当の 12.6% 溜まるまでの時間のあと |
| H1（フルバースト中も溜まる）             | 10 秒分の量（その後の伸びの速さ × 10 秒。12.6% を越えるなら光って見える） | 見えた時点から伸び続ける                                                |
| H2（溜まった分を持ち越す・0 に戻らない） | フルバーストの直前のバーの長さ（多くは 100%）                             | —                                                                       |

- 見分け方: フルバーストの後のバーの最初の数フレームの長さで、H0 と H1・H2 が分かれる。H1 の見込みは、その後の 0 → 満タンの時間 T で 10 秒 ÷ T × 100%（T が 80 秒以下なら 12.6% を越える）。どの録画も T は 20〜40 秒の見込みで、H1 なら 25〜50% が見える。
- 外れたときの影響: H0 なら、C-0264 の根拠に観測値を足す（2〜3 本目。確定にするかはオーナーの判断）。H1・H2 なら、`burst/controller.ts` のフルバースト中のゲージの扱いを見直す。

## 読み方

1. `gauge.ts --mode series` で戦闘の全フレームの充填率を出し、「-」（読めない）が 500f 以上続いた区間（フルバースト・チェーン）の後に、バーが初めて見えたフレームとその充填率を取る。
2. その後、最初に 0 より大きくなったフレーム（最初に光った）と、満タン（バー消失）までのフレームを取る。
3. 読んだ値は観測値にする（`source` に `V-0318`）。

## 結果

2026-10-08 に、予測の commit（4560fb01）の後で読んだ。観測値は `221-15`。

- `221`（ゲージが律速）: 4 回のフルバーストの後、バーは約 600f 読めない区間の後に見えるが、最初の 18〜21f はバーの上にフルバーストのタイマーの「00.00」が重なって 13〜21% と読まれる（画で確かめた。数字の白がバーの明るい画素に数えられる）。重なりが消えた所（f3248・5749・8269・10765）から 0% で、最初に光るのは 55〜105f 後（f3303・5846・8374・10832。光った値 0.9〜6.2%）、満タンは見えてから 559〜663f 後。0 に戻らずに伸びる。
- `079`・`019`（CT が律速）: フルバーストの後も CT 待ちの表示が続き、バーが見えるのは満タン（100%）の 1〜3 フレームだけで、0 から溜まり直すかは読めなかった。
- 予測との比べ: H0（0 から溜まり直す）が当たった。H1（フルバースト中も溜まる）なら、満タンまで約 600f（約 10 秒）の速さで 10 秒分溜まり、見えた時点でほぼ満タンのはずで、外れた。H2（持ち越す）も外れた。
- 弱い所: 読めたのは 1 本（4 回）だけ。

## 分かったこと・分からないこと

- **フルバーストの後のゲージは 0 から溜まり直す**（録画 221 の 4 回）。C-0264 の根拠に観測値を足した（状態・等級は変えていない。確定にするかはオーナーの判断）。
- フルバーストの直後の約 20f は、バーの上にタイマーの「00.00」が重なり、`gauge.ts` が 13〜21% と誤読する（読むときの注意）。
- 分からないこと: CT が律速の編成で、フルバーストの後に溜まり始める時刻（バーが CT 待ちの表示で隠れる）。
