## 1. 背景と目的

- 育成状況は、JSON の「読み込む」「書き出す」「消す」だけができる（[design-combat-power-sort.md](design-combat-power-sort.md) 5 節）。画面で直すことはできず、ゲームで育成を進めたら、育成データを取り直して読み込み直すしかない。
- 目的は、**育成の変化を手で直すこと**（スキル Lv を上げた・装備を替えた、など）。育成状況を一から作ること・所持の増減を映すことは、今回の目的に入れない（9 節）。

## 2. いまの形

- JSON の形はスナップショット（`BuildSnapshot` の版 1）。`synchroLevel`・`recycleRoom`（tid → Lv）・`characters`（resourceId → 1 体分）を持ち、1 体分は `growth`（Lv・限界突破・コア強化）と育成入力（好感度・装備・キューブ・コレクション・リサイクルルームの写し・その他攻撃加算）に、`skillLevels`・`treasure`（tid・Lv・段階）を足したもの。
- 画面は、読み込んだファイルの文をそのままブラウザに保存し（`nikke-calc.roster.v1`）、検査を通したスナップショットを計算に使う。読み込んだ育成状況は書き換えない。
- 育成状況の育成は、ニケをスロットに入れたときと、読み込んだときに、スロットへ写す（`rosterFields`・`applyRoster`）。スロットの育成は写しで、スロットで変えても育成状況は変わらない。シンクロ LV とリサイクルルームは、編成で共通の「共通育成」へ写す。
- スロットの育成の欄（`BuildSection`・`SkillSection` と、好感度・限界突破・コア強化の欄）は、スロットの番号と編成の `dispatch` に結び付いていて、ほかの所からは使えない。
- 宝物は API の Lv で持ち、段階は Lv から決める（`treasurePhaseOfLevel`。Lv 1・2 = 段階 2・3。C-0744）。Lv 0 は段階が未確定（`phase: null`）で、読み込みは Lv に合わない段階を止める。このため、段階 1 は今の形では書けない。
- 宝物の `tid` は、キャラのデータの `treasure.favoriteId` と同じ値（手元のスナップショットの宝物のある全キャラで一致した。2026-11-12）。

## 4. JSON の形（版 2）

- `formatVersion` を 2 にする。版 1 との違いは 2 つ。
  - 宝物の `phase`: Lv 0 のとき、`null`（未確定）に加えて `1`（画面で選んだ段階 1）を持てる。Lv 1・2 は今までどおり段階 2・3 だけ。
  - `editedAt`（任意。ISO の日時の文字列）: 画面で編集した育成状況が、最後に編集した日時を持つ。取得のままのスナップショットには無い。
- 読み込みは版 1 と版 2 を通す。版 1 は今までどおりの検査（段階は Lv から決まる値だけ）で読み、中では版 2 として持つ。ほかの版は「この版の育成状況は読めない」で止める。
- 取得した Lv 0 を段階 1 に読み替えることはしない（API の Lv 0 が段階 1 かは確かめていない）。`phase: 1` は、利用者が画面で選んだ値としてだけ入る。
- 書く側: `npm run build:import`・`build:fetch` は版 2 で書く（`editedAt` は付かず、`phase: 1` も出ない）。`private/builds/` の版 1 のスナップショットは、そのまま読める（写し直しは要らない）。
- 読む側の CLI（`sim-run.ts --build`・`build:combat-power`）: 版 2 を読む。`editedAt` があれば「画面で編集した育成状況（日時）」と 1 行出す（取得のままのスナップショットと取り違えないため）。画面の読み込みの知らせには出さない。
- 段階から Lv への写し（編集画面が使う）を core に置く: 段階 1・2・3 → Lv 0・1・2。段階 1 の Lv 0 は、形を満たすための値。

## 5. 画面の持ち方

### 5.1 保存

- 読み込んだファイルの文は、今までどおりそのまま保存する（`nikke-calc.roster.v1`。書き換えない）。
- 編集は、別のキー（`nikke-calc.roster.edits.v1`）に「編集の重ね」として保存する。
  - 中身: `formatVersion`（1）・`editedAt`・`characters`（resourceId → 編集した 1 体分）と、変えたときだけ `synchroLevel`・`recycleRoom`（tid → Lv の全体）。
  - 編集した 1 体分は、編集できる項目の全部（限界突破・コア強化・好感度・装備・キューブ・コレクション・スキル Lv・宝物）。変えた項目だけでなく丸ごと持つ。
  - 読み込んだ値と同じになった 1 体分・アカウント全体の値は、重ねから外す。重ねが空になったらキーを消す。
- この持ち方にする理由:
  - 「編集済み」は重ねにあるかどうかで決まり、「読み込んだ値に戻す」は重ねから外すだけで済む（3 節の 7・10）。
  - 読み込んだ JSON を書き換えないという今の作りが残り、キャラのデータに無いキャラ・`unmapped` も今までどおり書き出しに残る。
  - 保存の量が増えない（読み込んだ文を 2 つ持たない）。

### 5.2 編集を重ねた育成状況

- 画面が使う育成状況（スロットへの写し・一覧の並び・ニケ一覧の印）は、読み込んだ JSON に重ねを当てたもの。
- 当て方は 1 つの純関数にする: 読み込んだ JSON（生の値）と重ねから、書き出す JSON（生の値。版 2）を作る。それを core の読み込みの検査（`readBuildSnapshotValue`）に通したものを、画面が使う。書き出すものと画面が使うものが同じ道を通るので、編集で作った値も読み込みと同じ検査を受ける。
  - 重ねのあるキャラは、編集できる項目を重ねの値にする。
  - アカウント全体の `synchroLevel`・`recycleRoom` は、重ねにあればその値にする。
  - キャラごとの Lv: 重ねに `synchroLevel` があるとき、読み込んだ Lv が読み込んだシンクロ LV と同じキャラは、新しいシンクロ LV にする。違う Lv のキャラはそのまま（3 節の 16）。
  - キャラごとのリサイクルルームの写し（共通・クラス・企業の 3 つ）: 重ねに `recycleRoom` があるとき、キャラのクラスと企業から引き直す。
  - `editedAt` を付け、`formatVersion` を 2 にする。重ねが無ければ、読み込んだ JSON のまま。
- キャラのデータに無いキャラは、検査が飛ばすので編集画面に出ない。書き出しにはそのまま残る。Lv は上の規則で直すが、リサイクルルームの写しは直せない（クラスと企業が分からない）。

### 5.3 編集の操作

- ニケの育成を変える・ニケを読み込んだ値に戻す・アカウント全体の値を変える・アカウント全体を読み込んだ値に戻す・全部を読み込んだ値に戻す、の 5 つ。どれも重ねを作り直して保存し、`editedAt` を今の時刻にする（全部を戻すとキーを消す）。
- 読み込んだ値と同じかの比べは、項目ごとに比べる（装備の OL の行は位置をそろえてから比べる。キーの順や、位置の欄の有無で違うと判定しない）。
- 入力欄（`IntInput`）は、打った値が範囲に入るたびに確定する（スロットの欄と同じ）。打っている途中の値も保存される。

### 5.4 スロット・共通育成への写し

- ニケの育成を変えた・戻したとき: 全部の編成のスロットのうち、そのニケのいるスロットの育成（限界突破・コア強化・好感度・装備・キューブ・コレクション・スキル Lv・宝物の段階）を、育成状況の値で上書きする（3 節の 8。スロットで試した値は消える）。
- アカウント全体の値を変えた・戻したとき: 共通育成のシンクロ LV とリサイクルルームを、どちらも育成状況の値にする（片方だけを変えたときも両方を写す。ニケの「丸ごと」と同じ流儀）。
- 全部を戻したとき: 読み込んだときと同じ（`applyRoster`。シンクロ LV・リサイクルルームと、育成状況にいるニケの全部のスロット）。
- スペック固定の間も写す。写した値は、固定を外すと効く（今の読み込みと同じ）。
- 宝物の段階が未確定のニケは、今までどおり宝物なしでスロットへ写す。編集画面で段階を選べば、その段階で写る。

### 5.5 読み込む・書き出す・消す

- 読み込む: 確かめずに読み込み、重ねを消す（3 節の 12）。読み込んだファイルが新しい基準になる（編集した育成状況の書き出しを読み込むと、その中身が「読み込んだ値」になる）。
- 書き出す: 5.2 節の JSON を書く。ファイル名は、JSON に `editedAt` があれば `nikke-builds-<取得日>-edited.json`、無ければ今までどおり `nikke-builds-<取得日>.json`（編集した育成状況の書き出しを読み込み、編集せずに書き出したものにも `-edited` が付く）。
- 消す: 読み込んだ JSON と重ねの両方を消し、今までどおりスロット・共通育成を既定に戻す。確かめの文に、編集があるときは「編集した値も消える」と足す。

### 5.6 読めないとき

- 読み込んだ JSON の保存が読めないとき（今もある扱い）: 理由をメニューに出す。「編集」は押せない。重ねには触れない。
- 重ねが読めない・重ねを当てた結果が検査を通らないとき（キャラのデータや検査が変わった後など）: 重ねを消さずに、理由をメニューに出す。画面は読み込んだ値（重ねなし）を使う。「全部を読み込んだ値に戻す」で重ねを捨てられる。
- 重ねにあるニケが、読み込んだ育成状況にいない・キャラのデータから無くなったとき: その 1 体分は当てない（重ねには残す）。
- ブラウザの保存に書けないとき（保存が使えない・満杯）: 編集はその画面の間だけ効かせ、メニューと編集画面に「編集を保存できなかった」と出す。

## 6. 編集画面

### 6.1 開き方

- アカウントのメニューの並びを「読み込む」「書き出す」「編集」「消す」にし、その下に「全部を読み込んだ値に戻す」を置く。
  - 「編集」は、育成状況が無い・読めないときは押せない。押すと、メニューを閉じて編集画面を開く。
  - 「全部を読み込んだ値に戻す」は、編集が無いときは押せない。押すと、メニューの中で確かめる（「消す」と同じ `InlineConfirm`）。
- 編集画面はモーダルで、モダン UI とクラシックのどちらでも同じものが開く。幕（モーダルの外）・Esc・✕・下部の「閉じる」で閉じる。保存は欄ごとに済んでいるので、閉じるときに確かめない。
- スペック固定の間も開ける。欄は固定の値にせず、育成状況の値を出して編集できる。

### 6.2 全体の形

```
┌ 育成状況の編集 ───────────────────────────────── ✕ ┐
│ [バッジの絞り込み] [編集済みのみ] │ ニケ A      [前のニケ][次のニケ] │
│ ┌──────────────────────────┐ │ 好感度・限界突破・コア強化        │
│ │ ▣ アカウント全体       ✎ │ │ スキル 1・スキル 2・バースト       │
│ ├──────────────────────────┤ │ 装備（4 部位。種類・Lv・OL 3 行）  │
│ │ [顔] ニケ A  ★★★ 07  ✎ │ │ キューブ                          │
│ │ [顔] ニケ B  ★★☆        │ │ コレクション（宝物）              │
│ │ [顔] ニケ C  ★★★ MAX ✎ │ │ [読み込んだ値に戻す]              │
│ └──────────────────────────┘ │                                   │
├──────────────────────────────────────────────────────┤
│ [全部を読み込んだ値に戻す]                     [閉じる] │
└──────────────────────────────────────────────────────┘
```

### 6.3 左の一覧

- 先頭に「アカウント全体」を固定で置く（絞り込みで消えない）。開いたときはこれを選んだ状態にする。
- その下に、育成状況にいるニケ（キャラのデータにあるもの）を並べる。育成状況にいないニケは出さない。
- 並びは、ニケ一覧で選んでいる並びと向き（戦闘力・名前・ID・OP）。編集画面を開いた時点の並びで固定し、開いている間は編集で戦闘力や OP が変わっても行を動かさない。開き直すと並び直る。編集画面に並べ替えの欄は置かない。
- 1 行は、顔の絵（ニケ一覧の四角の絵と同じ）・名前・限界突破の星とコア強化の印・編集済みの印（✎）。限界突破とコア強化は、スペック固定でも育成状況の値を出す。画像の無い配信（アーティファクト）では、今の絵の部品と同じく枠とバッジだけになる。
- 絞り込み: ニケ一覧と同じバッジの絞り込み（属性・バースト段階・クラス・武器種・企業。同じ種類は OR、種類どうしは AND）と、「編集済みのみ」。編集画面の中だけの状態で、ニケ一覧の絞り込みとは連動しない。名前の検索は置かない。
- 「アカウント全体」にも、シンクロ LV かリサイクルルームを変えていれば編集済みの印を出す。

### 6.4 右の編集欄（ニケ）

- 欄はスロットの育成の欄と同じ部品・同じ範囲。
  - 好感度（1〜キャラごとの上限）・限界突破・コア強化（0〜レアリティの上限）
  - スキル 1・スキル 2・バーストの Lv（1〜10）
  - 装備 4 部位（なし・T9・T9 企業・OL、Lv 0〜5、OL の行 3 つまで。行は上昇値の % で選ぶ）
  - キューブ（なしか種類、Lv 1〜15）
  - コレクション（なし・R・SR と Lv 0〜15。宝物のあるニケは、宝物の段階 1〜3 も選べる）
- 宝物の選び方と、JSON への写し:

  | 選んだ値           | `treasure`                                       | `collection`                                                                        |
  | ------------------ | ------------------------------------------------ | ----------------------------------------------------------------------------------- |
  | なし               | `null`                                           | `null`                                                                              |
  | R・SR              | `null`                                           | その種類と Lv（R と SR の間で替えたときは Lv を保ち、なし・宝物から替えたときは 0） |
  | 宝物の段階 1・2・3 | `tid` はキャラのデータの宝物の ID、Lv は 0・1・2 | `null`                                                                              |
  - 段階が未確定の宝物（Lv 0・`phase: null`）は「宝物（段階は未確定）」と出す。この値は、ほかの値から選び直すことはできない（読み込んだ値に戻すと戻る）。

- キャラごとの Lv・リサイクルルームの写し・その他攻撃加算の欄は出さない。
- 計算に使えない育成（マスタに無いキューブなど）は、スロットの欄と同じく、欄の下に理由を出す。保存は止めない。
- 欄の上限とこの確かめには、そのニケのキャラのデータが要る。選んだニケの分だけ読み（スロットのキャラと同じ `useCharacterCache`）、読む間は「読み込み中」と出す。

### 6.5 右の編集欄（アカウント全体）

- シンクロ LV（1 以上）と、リサイクルルームの研究の Lv（共通・クラス 3 つ・企業 5 つ。0 以上）。欄は共通育成のリサイクルルームと同じ部品。
- リサイクルルームの欄を変えると、その研究の tid の Lv を変える（欄に無い tid はそのまま残す）。
- 「読み込んだ値に戻す」は、シンクロ LV とリサイクルルームを読み込んだ値に戻す。

### 6.6 戻す・前後のニケ

- 「読み込んだ値に戻す」（右の欄の中。ニケとアカウント全体のそれぞれ）: 編集していなければ押せない。確かめずに戻す。
- 「全部を読み込んだ値に戻す」（下部）: 編集が無ければ押せない。押すと、その場で確かめる（`InlineConfirm`。「編集した N 体とアカウント全体の値を、読み込んだ値に戻す。スロットと共通育成も育成状況の値になる」。ブラウザの確認の窓は使わない）。
- 「前のニケ」「次のニケ」: 絞り込んだ後の一覧の順で、ニケの間だけを動く（「アカウント全体」へは行かない）。端では押せない。「アカウント全体」を選んでいるときは出さない。選んでいるニケが絞り込みで一覧から外れたとき（「編集済みのみ」で戻したなど）は、右の欄はそのまま出し、前後のボタンは押せない。
- 前後で動いたら、一覧のその行が見える位置へスクロールする。

### 6.7 狭い画面

- 2 つの枠を横に並べられない幅では、一覧と編集欄を切り替える: 開くと一覧、行を選ぶと編集欄、編集欄の「一覧へ」で戻る。

## 7. スロットと共通育成の「育成状況の値に戻す」

- スロット（モダン UI の育成・設定のモーダルと、クラシックのスロットの「育成」の中）: そのニケが育成状況にいるときだけ出す。押すと、スロットの育成（5.4 節の 1 項目目と同じ項目）を育成状況の値にする。確かめない。
  - スロットの値が育成状況と同じとき・スペック固定の間は押せない。
- 共通育成: 育成状況があるときだけ出す。押すと、シンクロ LV とリサイクルルームを育成状況の値にする。値が同じとき・スペック固定の間は押せない。
- 「同じ」の比べは 5.3 節と同じ（項目ごと）。

### 8.4 段 2 の実装（2026-11-12）

8.2 節のとおりに作った。作りながら決めたことと、8.2 節・5〜7 節との違い:

- スロットの育成をまとめて置き換える操作は、編成の操作を足さずに、育成の欄の変更（スロットの育成の一部）をいまの操作（限界突破とコア強化・育成入力・スキル Lv・宝物の段階）に分ける関数にした（`team.ts` の `growthFieldsActions`）。育成の欄（`components/GrowthEditor.tsx`）は変えた項目だけを返し、スロットはこの関数で、育成状況の編集は `rosterEdits.ts` の `patchedCharacterEdit` で受ける。「育成状況の値に戻す」は、全部の項目を同じ関数に渡す。
- 編集した 1 体分の宝物は、段階を変えたときだけ書き直す（段階が未確定の宝物は、ほかの項目を編集しても未確定のまま残る）。宝物を付けたら R・SR のコレクションは外す（育成状況の検査は両方あると止める）。宝物の tid は、いまの宝物のものを使い、無ければキャラのデータの宝物の ID。
- 当てた結果が検査を通らない編集は、保存せず入れない（欄は範囲の中の値しか出さないので、ふつうは起きない）。入れなかったこと・ブラウザに保存できなかったことは、メニューと編集画面に出す。
- 編集の保存が読めない間（5.6 節）は、「編集」も押せない（読めない重ねの上に編集を重ねない）。「全部を読み込んだ値に戻す」で捨てると、また編集できる。
- 「読み込んだ値に戻す」（ニケ・アカウント全体）は、右の欄の見出しの行に置いた（6.2 節の図では欄の下。欄が長く、下だとスクロールしないと見えない）。
- 一覧の行の顔の絵には、絵の上のバッジ（属性・武器種・バースト段階）を出さない（行の絵は小さい。絞り込みで探す）。
- ニケの編集をスロットへ写すとき、そのニケのスロットが無い編成・一覧は元のものをそのまま返す（どのスロットにもいないニケを編集するたびに、編成を保存し直し、計算の入力を作り直さないため）。
- 保存した重ねからは、編集できる項目だけを当てる（Lv・リサイクルルームの写しが入っていても当てない。欠けた項目は検査で止まる）。
- モーダルの外枠（`components/Modal.tsx`）と、押せないことのあるボタン（`components/InertButton.tsx`）を部品にして、スロットの育成のモーダル・メニュー・編集画面で使う。
- 編集の問題（入れなかった・保存できなかった）は編集画面にだけ出す（メニューの知らせには出さない）。保存できなかったときは、再読み込みすると保存できた所まで戻る。
- 編集画面を閉じる・メニューから開くときは、待っている確かめ（消す・全部を読み込んだ値に戻す）をやめる。
- 育成状況が無い・読めないときは、編集の保存だけが残っていても「全部を読み込んだ値に戻す」を押せない（戻す先が無い。読み込み直すか消すと、編集も消える）。
- スロットの「育成状況の値に戻す」を押せるかの比べでは、宝物を付けているスロットに残っている R・SR のコレクションを見ない（計算は宝物を使う）。
- R・SR を選んだら宝物は外す（キャラのデータに宝物が無いのに育成状況に宝物があるニケでも、選んだ値が入る）。
- アカウント全体のシンクロ LV の欄に上限は置いていない（共通育成の欄と同じ）。キャラの Lv の表を超える値を入れると、追従するキャラの戦闘力が出せなくなり、戦闘力の並びで後ろに回る（その数は一覧に出る）。
- core: キャラごとのリサイクルルームの写しを研究から作る処理を `recycleRoomOfResearch`（`shiftypad.ts`）にし、取り込みの写しと、編集の当て方の両方で使う。
- 1 回の確定（読み込んだ JSON の parse → 重ねを当てる → 検査）は、手元の育成状況で約 1 ms。変えたキャラだけを検査する形にはしていない（10 節）。
- 確かめたこと（10 節の段 2）: テストと、ブラウザでの操作（クラシックとモダン UI）。手元の育成状況を読み込み、アカウント全体とニケの編集 → 保存と再読み込みの後の復元 → スロットと共通育成への写し → ニケ・全部を戻す → 編集済みのみ・バッジの絞り込み・前後のニケ → 書き出し（版 2・`editedAt`・名前の `-edited`）→ 書き出したファイルの読み込み直し → スロットと共通育成の「育成状況の値に戻す」→ スペック固定の間の編集 → 宝物の段階 1 と R への付け替え → 狭い幅での一覧と編集欄の切り替え。段階が未確定の宝物は、手元の育成状況に無いので、作った値のテストで見た。
