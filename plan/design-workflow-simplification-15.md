## 2. 結論の状態を手で「確定」に直す

**いま**

- `records:new claim` は、確定にできる条件（[verification-guide.md](verification-guide.md) 2.2 節）を `claimDraft`（`records/drafts.ts`）で見て、1 つでも欠ければ「仮説」と理由を書く。
- 最小構成の警告は、結論の対象（`--subject`）の要素を除いて、録画の編成のうち確定の結論が無い要素を挙げる（`relevance.ts` の `relevanceOf`）。スキル定義では、同じ検証記録で一緒に足す結論どうしが、まだ確定でないので互いを警告に出す。
- 19 本の全部で、結論の状態を sed・node・使い捨ての `claims.mjs` で「確定」に直した（1 本 2〜8 分）。レイでは手での書き換えを auto mode の分類器が拒み、オーナーに可否を聞いた。`records:close --mark` の後は警告が消えていた。

**案**

- `records:close --mark` が、その検証記録の結論のうち、仮説の理由が最小構成の警告だけのものについて、同じ検証記録の結論を確定とみなして警告を計算し直す。警告が消えたものを確定に書き換え、書き換えた ID を出す。ほかの理由（scope の無い観測値・許容外など）が残るものは仮説のまま。
- 確定にできる条件は変えない（同じ検証記録の結論が全部確定になったときの状態で判定するだけ）。

## 4. 生成物の書き換えが残る

**いま**

- `records:check` は回すたびに生成物（`GENERATED_PATHS`）を書き換える。生成物は PR に入れないので、手元に変更が残る。
- 残った変更で、クラウドの環境の応答の終わりの検査（コミットしていない変更）が止め、`pr:prep` が「作業中の変更がある」で止める。セッションは `git checkout` で戻す（30 本中 14 本、2〜4 回ずつ）。イヴでは `git checkout -- plan/` を分類器が拒んだ（通れば設計書の編集も消えていた）。
- 検証記録 289〜310 件の予測の表が書き換わった例が 2 本ある（エード・ジュリア）。main の上で `records:check` を回しても再現しなかった（11 節）。

**案**

- `records:check`・`records:close` は、書き換えた生成物を終わりに HEAD の版へ戻す（`--keep-generated` で残す）。中身を見たいときは今と同じく `records:minimal`。
- `pr:prep` は、作業中の変更が生成物だけなら、止めずに戻して進む。

## 5. 残差の前後比べ

**いま**

- コード（モデル）を変えた PR は、全部の観測値の残差が変わらないか・どう変わったかを確かめる。`records:residual` は ID を指定しないと使い方を出して終わり、main の版と比べる手段が無い。
- 11 本中 6 本が、全部の ID を並べる・`git stash` や一時の worktree で main の値を取る・比べるスクリプトを書く、を毎回した（1 回 2〜4 分＋自作）。

**案**

- `records:residual -- --all` で全部の観測値を出し、`--base <ref>` でその版の値と比べて、予測か判定が変わった行だけを出す。基の版は一時の worktree で回す（残差の覚え `residual-cache.ts` が効く）。

## 6. モデルの中を見る道具

**いま**

- `records:model` は 1 回に 1 つの指定（指標と args）しか出せない。ループで 20 回以上呼んだ本や、一括で回す道具を自作した本（ブレッディ）がある。`--setup` は毎回ほかの観測値のファイルから手で写し、引数の誤り（`n` の抜け・`crit` が無い）で止まる。
- 発の列・バフの区間・バーストの時刻を見るため、19 本中 12 本が使い捨ての sim（`_tmp_*.ts`・`zz*.test.ts` など。リポジトリの中に置いた本もある）を書いた（1 本 2〜15 分）。撮る前は録画 id が無いので `records:model` が使えない。`npm run sim` は区間の表を出すが、出来事の列は出さない（出力は 48KB）。

**案**

- `records:model` は指標の後に `指標:{args}` を並べて 1 回で複数出す。`--like <観測値 ID>` でその観測値の setup と args を使う。
- `npm run sim` に `--events shots,bursts,buffs [--from 秒 --to 秒]` を足し、出来事の列を短く出す（撮る前も `--ids` で回せる）。
