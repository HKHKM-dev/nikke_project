# 設計書: 読めない編成の保存を、知らせずに上書きしない

- 何のための文書か: 画面がブラウザに保存した編成（選んでいる編成と、保存した編成の一覧）を起動時に読めなかったとき、どう扱うかを決める
- 関連: 課題 `records/backlog/web-legacy-team-save.json`、[design-ui-rebuild.md](design-ui-rebuild.md) 5.1 節（版の無い旧形式の読み込みを消した）、[design-combat-power-sort.md](design-combat-power-sort.md) 8 節の 2026-11-08 の行（育成状況の読めない保存は、消さずに理由を出す）
- 起案: 2026-11-09
- 状態: 承認（2026-11-09。案 A と 4 節の論点を推奨どおり）

## 1. いまの動き

- 編成の保存（`nikke-calc.team.v1`）は版つき（`TEAM_FORMAT_VERSION`）。中身は選んでいる編成のスロットと、全編成で共通の設定（敵・コンソール・シンクロ LV・戦闘時間など）。起動時に `parseTeamState` で読み、読めなければ null（`readTeamJson` の失敗の理由は捨てる）。
- 保存した編成の一覧（`nikke-calc.parties.v1`）は `parseParties` で読む。全体が読めなければ null（理由は作らない）。1 つの編成だけ形が合わないときは、その編成を空にする。
- App.tsx は、読めなければ初期値（と空にした編成）のまま `restored` にし、直後の effect がそれで保存を上書きする。利用者には何も出ない。
- 読めない保存になるもの:
  - 編成: JSON として読めない・版の無い旧形式（Stage 3〜13）・未知の版（新しい版の画面で保存した後に古い画面を開いたなど）・形が合わない・キャラの一覧に無いニケ・同じニケが 2 枠。
  - 一覧: JSON として読めない・版が無いか未知・選んでいる番号や編成の数が合わない（全体）と、1 つの編成の形が合わない（その編成だけ）。
- 版の無い旧形式は、2026-11-07 までは版 0 として読み替えていた。読まなくなったのは design-ui-rebuild.md 5.1 節から。
- キーが無いとき・ブラウザの保存が使えないときは、`readStorage` が null を返す。どちらも読めない保存ではない。

## 2. 案

### 案 A（推奨）: 退避して知らせる

- 起動時に読めなかった保存は、上書きする前に元の文字列のまま別のキーに退避する。
- 退避してから、読めたところまでで始めて保存する。編成が読めなければ初期値、一覧の 1 つの編成が読めなければその編成を空にする。
- 退避が 1 件でもある間は、毎回の起動で、ページの上（見出しの下）に知らせを出す。1 件ごとに「書き出す」と「消す」を付ける。
- 長所:
  - 消さずに理由を出す点で、育成状況の扱いとそろう。育成状況は、読み込んだときにだけ保存を書くので、読めない保存を同じキーに残せる。編成は変更のたびに保存を書くので、別のキーに移して残す。
  - 何も失わず、画面は止まらない。旧形式に限らず、どの読めない保存にも効く。
- 短所: 退避を戻す（読み込み直す）手段は画面に無い。いまは編成の取り込み欄が無い。書き出したファイルは、将来の取り込みか手作業で使う。

### 案 B: 了承するまで保存しない

- 読めなかったら知らせを出し、利用者が「初期値で上書きする」を押すまで保存しない。
- 短所:
  - 押さずに編成を作ると、閉じたときに失われる。
  - 元の保存は、書き出さない限り、押した時点で消える。
  - 変更のたびに保存するいまの作りと合わない。

### 案 C: 旧形式の読み込み（移し替え）を戻す

- 版の無い旧形式（Stage 3〜13）を、2026-11-07 より前のように版 0 として読む。
- 短所:
  - 11-07 までは読み替えて版つきで書き直していた。残っているのは、旧形式のまま 11-07 より後に初めて開いた保存だけで、見込みは小さい。
  - 読み込みを消すと決めた design-ui-rebuild.md 5.1 節を戻すことになる。
  - 未知の版・形が合わない・一覧に無いニケには効かない。案 A か B は別に要る。

## 3. 推奨

案 A。育成状況と同じく消さずに理由を出し、旧形式に限らずどの読めない保存でも何も失わない。案 C は残っている見込みが小さく、消すと決めた読み込みを戻すことになり、ほかの読めない保存にも効かない。

## 4. 論点

1. 扱う範囲: 1 節の読めない保存をすべて同じ扱い（退避して知らせる）にするか。推奨: 同じにする。どれも利用者から見れば「保存した編成が消えた」で、分ける理由が無い。
2. 保存した編成の一覧の 1 つの編成だけ読めないとき。推奨: 読める編成はいまどおり使い、一覧の元の文字列を退避して「編成03 を空にした」と知らせる。
3. 選んでいる編成の 1 枠だけ読めない（一覧に無いニケなど）とき、その枠だけ空にして残りを読むか。推奨: 読まない。編成ごと退避して初期値にする。いまの検査（`readTeamJson`）のままにし、枠ごとに読み捨てる判断は足さない。
4. 知らせの置き場所。推奨: ページの上（見出しの下）。App.tsx で両方の表示モードに 1 か所で出す（読み込みの失敗の表示と同じ所）。育成状況の知らせはアカウントのメニューの中だが、編成の知らせは開かなくても気づける所に出す。

決定（2026-11-09、オーナー）: 案 A。論点 1〜4 は推奨どおり。

## 5. 案 A の形

### 5.1 読む

- 編成は `readTeamJson` を直接呼び、失敗の理由を使う（`parseTeamState` は、キーが無いときも読めないときも null を返して区別できない）。
- 一覧にも、理由を返す読み込みを足す（`readParties`）。結果は次のどれか。
  - 全体が読めない: 理由を返す。理由の文は `readTeamJson` の形にそろえる（「JSON として読めません」「この版の一覧は読めません（formatVersion …）」「一覧の形が合いません」）。
  - 読めた: 読めなかった編成の番号の列も返す。
- 一覧の 1 つの編成を、次のように分ける。
  - null（未使用の編成）は正しい中身として扱う。
  - オブジェクトでない値と、形が合わないものは読めない。
  - 選んでいる編成の欄はいまどおり見ない（中身は編成のキーが持つ）。読めないものに数えない。
- 編成のキーと一覧のキーは、別々に退避と知らせの対象になる。

### 5.2 退避する

- 退避は 1 件を 1 つのキーに置く: `nikke-calc.unreadable.<team|parties>.<退避した時刻のミリ秒>`。1 つのキーに一覧で持つと、そのキーが壊れたときに足すことが上書きになり、退避が消える。キーを分ければ、その恐れが無い。
- 中身は `{ raw, error, savedAt }`。
  - `raw`: 元の文字列。
  - `error`: 読めない理由。一覧の 1 つの編成なら「編成03: 編成の JSON の形が合いません」の形。
  - `savedAt`: 退避した時刻（ISO 8601）。
- 同じ種類で同じ `raw` の退避がもうあれば足さない。
- 種類ごとに新しいほうから 5 件まで持ち、古いものは消す。版の違う画面を行き来すると、編集のたびに文字列が変わるので増え続けるため。
- 退避は、キャラの一覧を読んだ後のコールバックの中で、`setRestored(true)` の前に同期して書く。state を通して effect で書くと、保存の effect との順番が保証されず、退避の前に上書きされうる。
  - localStorage は同期で読み書きするので、StrictMode で復元が 2 回走っても、2 回目は重複の判定で落ちる。
  - 復元の effect には取り消しの印を付け、片付けた後の結果を state に入れない。
- 退避を書けなかった（ブラウザの保存が満杯など）とき:
  - 編成と一覧のどちらも保存しない（`restored` を立てない）。編成の切り替えは 2 つのキーにまたがるので、片方だけを止めると中身が食い違う。
  - 知らせに「保存できないので、この画面の変更は残りません」と理由を出す。元の文字列はメモリに持ち、「書き出す」を出す。
  - 保存の書き込み（`writeStorage`）は、成否を返すように直す。
- キャラの一覧を読めなかったときは、いまどおり復元も保存もしない。退避の知らせは出す（退避は index を使わずに読める）。

### 5.3 知らせ

- 退避が 1 件でもある間は、毎回の起動で出す。文は退避した起動にも、その後の起動にも合うように、何を戻したかを過去のこととして書く。
  - 編成: 「<日時> に、ブラウザに保存した編成を読めなかったので、選んでいた編成と共通の設定（敵・コンソールなど）を初期値に戻しました。」
  - 一覧の全体: 「<日時> に、ブラウザに保存した編成の一覧を読めなかったので、選んでいる編成のほかを空にしました。」
  - 一覧の一部: 「<日時> に、ブラウザに保存した編成03・05 を読めなかったので、空にしました。」
  - どれも、続けて理由と「元の保存は残してあります。」を出す。日時は日本時間で書く。
- 1 件ごとに「書き出す」と「消す」。
  - 書き出す: 元の文字列をそのまま（理由や日時で包まない。将来の取り込みでそのまま読めるように）ファイルに落とす。名前は `nikke-calc-unreadable-<team|parties>-<日本時間の YYYYMMDD-HHmm>.json`。JSON として読めない文字列もそのまま落とす。
  - 消す: 育成状況の「消す」と同じく、欄の中で確かめてから消す。ブラウザの確認の窓は、claude.ai のアーティファクトの枠の中では出ない。消すと元の保存は戻らない。
- 消さずに知らせだけ閉じる手段は設けない。退避を残したい人は、書き出してから消す。
- 中身を読めない退避のキーは、理由を「退避の中身を読めません」にして、同じく書き出し・消すを出す。

### 5.4 しないこと

- 編成を初期値に戻したとき、育成状況から写していたシンクロ LV・コンソールは写し直さない。いまの動きと同じで、育成状況を読み込み直せば写る。
- 育成状況の読めない保存の書き出しは、この設計に入れない。
