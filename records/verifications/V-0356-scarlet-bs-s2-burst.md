### 既存の録画を使わない理由

- **047**（ラム + デルタ + 紅蓮BS。最小構成）: 定義を書く前に、HUD の総ダメージの増分を全フレーム分解して、窓の中と外の 1 ヒットの値・5 回のフルバーストの段の列・フルバーストの中の発の数・照準の横の残弾を読み、それをもとに定義（burst の effects[0] の `assumes`、S2 の 14 発）を決めた（凍結の記録。[design-stage11-scarlet-bs.md](../../plan/design-stage11-scarlet-bs.md) 0.2・0.3・13 節）。5 つの効果を見分ける値はどれも、同じ録画で前に読んで仮説を立てた値なので、比べる指標にできない（[skills-guide.md](../../plan/skills-guide.md) 2 節）。
- **046・055・070・071**（単騎）: フルバーストにならないので、5 つとも起きない。
- **048〜053**（リター・クラウン・アリス・モダニア・紅蓮BS。スペック固定 OFF か迎撃戦）: 紅蓮BS のほかに未確定の要素が残り、最小構成でない。
- **084**（ココア + ニヒリスター（操作）+ 紅蓮BS（AI））: ニヒリスターに仮説の結論（C-0401・C-0219）が残り、ゲージとフルバーストの時刻に効く。AI の紅蓮BS の射撃の刻みは測っていない（C-0149 は操作キャラで読んだ値）。窓の中の 1 ヒットの値（burst の effects[1]・effects[2]）だけなら、ニヒリスターの効果は自分だけなので効かない形で読み直せる候補だが、ほかの値を読むときに HUD の増分を見ており、S2 と段の間隔の変更は読めない。新しい録画が撮れないときの代わりにとどめる（「次に撮るもの」）。

### 予測ファイルの範囲外（手で書く仮説と見分け方）

**段の数え方**（burst の effects[0] の `assumes`）。フルバーストごとに、窓の前の最後の段の後に撃った段なしの発の数 p、窓の中の発の数 n（窓の中は毎発で段）、窓の後で最初に段が出たのが何発目か k を読む。録画の p・n から見分けるので、モデルとの射撃の位相のずれ（下の注意）に依らない。

| 仮説                                       | k                                 |
| ------------------------------------------ | --------------------------------- |
| H1（通算のカウンタ。窓の中の段は戻さない） | p + n + k ≡ 0 (mod 3) となる 1〜3 |
| H2（段が出るたびにカウンタを数え直す）     | いつも 3                          |
| H3（窓の中の発をカウンタに数えない）       | p + k ≡ 0 (mod 3) となる 1〜3     |

- モデル（H1）の 5 回の p・n・k は、`npm run sim -- --ids 311,20,225 --fixed-spec --controlled 3 --enemy range-bigarms-fire --events range-3min-jump` の循環の表（予測ファイルと同じ出来事のセット）。5 回とも p + n + k ≡ 0 (mod 3)。
- 1 回のフルバーストで、H1 と H2・H3 は p・n の組によって同じ k になることがある（p + n ≡ 0 なら H1 と H2 が同じ）。5 回のうち、見分けられる回（仮説どうしの k が違う回）の数を「結果」に書く。

**弾丸チャージ**（skill2 の effects[1]）。フルバーストごとに、開始の直前の照準の左の残弾 r（リロード中なら「リロード中」とバーの進み）と、開始からマガジンが空になるまでの発の数 m を読む。

| 仮説                                             | r > 0（マガジンの途中）のとき | リロード中のとき                                                                               |
| ------------------------------------------------ | ----------------------------- | ---------------------------------------------------------------------------------------------- |
| H1（▲の後の最大 14 の 100% を足す。14 で止める） | m = 14                        | リロードを待たずに撃ち、m = 14                                                                 |
| H0-refill（弾丸チャージなし）                    | m = r                         | リロードの残りを待ってから m = 14（1 発目がリロードの残りぶん遅れる。リロードの長さは C-0149） |
| H0-ammo（最大装弾数▲なし）                       | m = 9                         | m = 9                                                                                          |

- 1 発目までの長さは、フルバースト開始から 1 発目までが実機でモデルより長い既知のずれ（凍結の記録の範囲外の 1。[design-stage11-scarlet-bs.md](../../plan/design-stage11-scarlet-bs.md) 13 節）があるので、リロード中の回は、r > 0 の回の m ほどはっきりしない。リロードの残り（バーの進み）から H0-refill の 1 発目の遅れを出し、それより十分早いかで見る。
- 窓の判定のフレーム（`assumes` の「射撃のフレームで判定」。着弾で判定するかもしれない）は、バーストのカットインの中か窓の端に発が来た回だけで見える。来なければ「分からないこと」に残す。

### 注意（合っても合わなくても書くこと）

- `window-shots-*` は、フルバースト開始から 1 発目までの既知のずれ（上）で 1 発少なく出うる。それだけが外れたら、5 つの効果ではなく射撃の位相の残差として書き、効果の結論には使わない。
- `normal-in`・`tier-*-in` の録画の値は、どのフルバーストの窓の中の発でもよい（同じ値）。予測ファイルの `frame`・`n` はモデルの 1 回目の窓の中の発を指す。会心の発は使わない（会心は会心のパターンで組み直せるが、指標は会心なしで固定した）。段 B は 3 ティックに分かれる（C-0047）ので、`tier-count` は 3 ティックを 1 回に数える。

## 読み方

- 取り込み: `node tools/captures/intake.ts <元ファイル> --id NNN --name sr+sr+rl_cocoa+delta+scarlet-black-shadow --rid 311,20,225 --controlled 3 --target BigArms --element Fire --mode range-3min --fixed-spec on --auto-fire on --auto-burst on`。撮影後、戦闘履歴のパネルで枠順と名前を確かめ、予測ファイルの `team` と違えば `records:predict` を出し直す（値は変わらないことを確かめて commit する）。
- 1 ヒットの値・段のヒット: HUD の総ダメージの増分（`tools/captures/hud.ts`）。紅蓮BS の値は、ココア・デルタの SR の 1 発とは値の組で分ける（[captures/guide.md](../../plan/captures/guide.md)「1 ヒットの値（多人数）」）。紅蓮BS は操作キャラなので、照準付近のポップアップでも確かめられる。
- 残弾と発: 照準の左の残弾（`tools/captures/reticle-ammo.ts`。マガジンの長さと弾丸チャージの増えが 1 発の精度で読める。V-0163）。発のフレームは残弾が減ったフレーム（HUD の増分と同じフレーム）。
- フルバーストとバースト使用の時刻: 右のバースト欄の段の切り替わり（`gauge.ts --mode events` と画面。guide.md「バーストの段の切り替わり」）。窓の明けは、通常攻撃の値が窓の中の値から外の値に戻った発で挟む。
- 観測値は `records/observations/<録画 id>.json` に、`source` を V-0356、`compare` を予測ファイルの指標と同じ `metric`・`args`・`setup` にして書く。手で見分ける p・n・k と r・m は `use: record` の観測値にし、`method.note` に読み方を書く（繰り返し使うなら、指標 `cycleWindowPattern`（窓ごとの [p, n, k]）と `fullBurstMagazine`（フルバーストごとの [r, m]）を `METRICS` に足して予測と結び付ける。足すときは同じ PR に入れ、予測を出し直してから読む）。
- 結論の案（読んで合ったとき）: (1) S2 の 2 つの効果は説明文どおり（skill2 の effects[0]・effects[1]）、(2) バーストの攻撃力▲とチャージダメージ▲は説明文どおり（burst の effects[1]・effects[2]）、(3) 段の間隔の変更は窓の中で毎発、カウンタは通算（burst の effects[0]）。同じ録画の観測値の組で互いを未確定の要素として数えるので、3 件を作ってから `npm run records:check` で警告を確かめる。
