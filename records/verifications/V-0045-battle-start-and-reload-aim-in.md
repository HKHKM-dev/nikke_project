# V-0045: 戦闘開始の起点と画面の出方、リロード完了から最初の発まで

- 問い: 戦闘開始（残り時間の表示が出たフレーム）は、敵名の表示・照準の横の残弾・キャラの動きとどういう順番か。リロード完了から次のマガジンの最初の発までは何フレームか
- 話題: 射撃（間隔・リロード・チャージ）
- 日付: 2026-09-29
- 録画: `L-AD`、`L-AI`、`L-AN`
- 結論: `C-0114`、`C-0115`、`C-0116`
- 状態: 完了
- 派生元: `V-0044`

## 条件

- 旧の単騎・AUTO・3 分モードの録画 3 本を読み直した（撮影はしていない）。ブラン（AR・`L-AD`）、エレグ（MG・`L-AN`）、チャイム（SMG・`L-AI`）。どれも 2026-08-29 の録画で、枠アイコンの上の残弾表示が無い（`ammo.ts` は使えない）。
- クラウド環境の Drive の設定が旧プロジェクトのフォルダ（old_nikkecalc）を指していて、今の録画（054・072〜074 など）は取り寄せられなかった。旧の録画だけで読んだ。
- オーナーの問い（2026-09-29）: 戦闘開始のフレームは、右上のタイマーが出た時・残弾の UI が出た時・キャラが動き始めた時・敵名の表示が消えた時のどれを起点にしているか。リロード完了から発射までを複数回読み、平均を出してほしい。

## 予測（撮る前に書く）

- 戦闘開始: 記録（V-0002・V-0023・C-0078）は、残り時間の表示が出たフレームを起点にしている。ほかの UI との前後は読んでいない。構えの約 12f（C-0114）の一部が UI の出方のずれなら、キャラが動き始めるのはタイマーより後のはず。
- リロード: 最終弾から次の 1 発目は、リロードの時間より 20〜24f 長い（C-0059）。構え（C-0114）がリロードの後にもあるなら、リロード完了の表示から最初の発までは 12f 前後になる。

## 読み方

1. `timer.ts --mode changes` で戦闘開始 S（+89f 前後の変わり目）を取り、S の前後を ffmpeg で 1 フレームずつ切り出して、敵名の表示・残り時間・照準の横の残弾・カメラ・最初の発を読む。
2. `hud.ts --mode jumps` で総ダメージの増分の列を取り、82〜84f（AR・SMG）・172f（MG）の空きをリロードとする。的のジャンプの窓をまたぐ空き・長さが違う空きは使わない。
3. 各リロードの明けの前後を 1 フレームずつ切り出し、リロード完了（RELOADING のバーが消えて照準の横の残弾が最大に戻ったフレーム）と、最初の発（照準の横の残弾が 1 減ったフレーム）を読む。最初の 2〜4 回で、最初の発のフレームが総ダメージの増分のフレームと一致したので、以降の最初の発は増分のフレームを使った。

## 分かったこと・分からないこと

- 戦闘開始の起点は、右上のタイマー（03:00）が出たフレーム。タイマーと総ダメージの表示・カメラの切り替えは同じフレームで、照準の横の残弾は 2f 後、敵名の表示はその約 36f 前に消えている。キャラの背中からの視点に替わるのは S+6〜8 で、そこから最初の発まで 5〜6f。
- リロード完了から最初の発までは、AR・SMG・MG とも 12〜13f（23 回の平均 12.13f）で、戦闘開始・窓の明けの構え（C-0114）と同じ長さ → C-0115（確定）。ハイドからの構えは、戦闘開始・窓の明け・リロードの後のどれにもある。C-0114 の根拠にリロードの後を足した。
- 最終弾からリロード完了までは、構え解除 13f（C-0110）とリロードの時間（ゲーム内の時計の秒）の和で合う。最終弾から次の 1 発目の 82〜84f・172f は、構え解除 + リロード + 構えで説明がつく → C-0116（仮説）。リロードの秒は 58.82f で数えると AR・SMG と MG の両方で引く値がそろい、1 秒 = 60f ではそろわない（V-0011 で決まらなかった秒の換算の手がかり）。
- 分からないこと: 今の録画（2026-09）でも同じか（Drive の設定で取り寄せられなかった）。SG（C-0114 の `074-02`）・チャージ武器のリロードの後。最終弾からリロードのバーが出るまでの間が構え解除か（この録画では直接は読んでいない）。
