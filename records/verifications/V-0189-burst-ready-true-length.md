# V-0189: 満タン → I の段の本当の長さ

- 問い: ゲージが律速の回で、満タン（BURST バーが消えた発）から I の本当の発動（CT が走り出す）まで何フレームか。C-0073 の I の段（表示の印で数えた 28〜30f）と同じか
- 話題: バーストの段階とフルバースト
- 日付: 2026-10-05
- 録画: `018`〜`021`、`038`〜`044`、`047`〜`050`、`063`
- 状態: 調査中
- 派生元: `V-0164`

## 条件

- 課題: `plan/backlog.md` 2-19。[design-burst-ct-delay.md](../../plan/design-burst-ct-delay.md) 2.3 節の 1。
- モデル（`burst/controller.ts`）: ゲージが満タンになったフレームから 29f（`BURST_READY_DELAY_FRAMES`。C-0073）で I を撃つ。I の CT が明けていなければ CT が明けたフレームに撃つ。モデルのゲージの 100% は本当の満タン（BURST バーが消える発）に合わせてある（C-0079・C-0083）。
- C-0073 の段の長さは、表示の印で数えた（V-0021）: I の段は「BURST バーが消えたフレーム → II のアイコンに替わったフレーム」、II の段は「II のアイコン → III のタイマーが出たフレーム」、III の段は「III のタイマー → 00.00」。
- C-0258（確定）: CT が律速の発動では、本当の発動（CT が走り出す）は CT の 0 から 0〜2f（平均約 0.8f）。欄の新しい CT の秒はその 0 の 3〜4f 後、次の段のアイコンはさらに 3f 後。つまり、新しい CT の秒は本当の発動の約 2〜3f 後、次の段のアイコンは約 5〜6f 後に出る。
- C-0079（確定）: BURST バーが消えるのは、残りを埋める発が当たったフレーム（総ダメージの HUD の増分と同じフレーム。V-0025 で 37 回中 36 回）。
- したがって、I の段の終わりの印（II のアイコン）は本当の発動より 5〜6f 遅れて出るのに、始まりの印（バーが消える）は発のフレームで遅れが無いなら、本当の満タン → I は 29f より短い。I → II・II → III は同じ種類の印どうし（アイコン → タイマー）なので、遅れは打ち消し合う。
- 既に見たもの（仮説の出どころ。比べる指標にしない）:
  - `063-11`（063 の 4 回目、f5648 のバー消失 → 「20」が 26f・II のアイコンが 29f）。V-0164 で読んだ。
  - 018・019・021 の 2 回目の I の CT の 0（`018-18`・`019-12`・`021-18`）と、1 回目のバーが消えたフレーム（`018-08`・`019-07`・`021-05`）。これらから下の読み方 B を当てると 1 回目の I の本当の発動が出せる（後付け。根拠にしない）。予測を書く前に、018 の 1 回だけをこの式で数えた（3779.2 − 2354.7 − 22.1 − 1379 ≈ 23.4f）。
- 編成と CT（`data/skills/` で `cooldownReduction` を持つのはアニス：スター・ニヒリスター・リター・ラム）:
  - 018〜021: エーテル（I・CT 40 秒）・デルタ（II）・III。1 回目はゲージが律速、2 回目からは I の CT が律速。CT の短縮なし。
  - 038・047（ラム）、039・048〜050（リター）: I に CT の短縮がある。読み方 A（表示）だけに使う。
  - 041〜044・063（フラワー、I・CT 20 秒）、040（アドミ、I）: 読み方 A だけに使う。
- 見ている事象は右のバースト欄の表示と、段の長さ（C-0073 でキャラ・編成によらない）。ゲージが律速の回は I の CT が明けているので、CT に効くスキルの未確定は読み方 A に効かない。読み方 B は 020（CT の短縮なし）だけを根拠にする。

## 予測（撮る前に書く）

既存の録画の読み直し。比べる値（読み方 A の新しい CT の秒のフレーム、読み方 B の 020 の 2 回目の CT の 0）は読む前に書いた。

| 仮説                                                               | 読み方 A（バー消失 → 新しい CT の秒 → II のアイコン）                                                                               | 読み方 B（020: 2 回目の CT の 0 から逆算した本当の発動 − バー消失）        |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| L29: 本当の満タン → I は 29f（いまのモデル）                       | 新しい CT の秒はバー消失の 31〜32f 後、II のアイコンは 34〜35f 後（表示の遅れが C-0258 と同じなら）。C-0073 の 28〜30f とは合わない | 28〜30f（予測ファイル records/predictions/V-0189.json の L29 の値 ±1〜2f） |
| L23: 本当の満タン → I は約 23f（表示の遅れが C-0258 と同じ）       | 新しい CT の秒はバー消失の 25〜27f 後、II のアイコンはその 3f 後（28〜30f。C-0073 と同じ）                                          | 22〜25f（L29 の値 − 5〜7f）                                                |
| LX: ゲージが律速の回は、表示の遅れが CT が律速の回と違う（C-0258） | 新しい CT の秒 → II のアイコンが 3f でない、または A から出した本当の発動と B が 2f より離れる                                      | A の 26 − (2〜3)f と合わない                                               |

- 見込み: L23（018 の 1 回を後付けで数えた 23.4f と、`063-11` の 26f・29f から）。
- 見分け方: 読み方 B は表示の遅れに左右されない（CT の 0 は 1/100 秒の表示から外挿し、両端の表示の遅れは同じ）。B が 28〜30f なら L29、22〜25f なら L23。読み方 A は、新しい CT の秒の位置が全部の回で 25〜27f にそろうか（L23）、31〜32f か（L29）。A − (C-0258 の新しい CT の秒の遅れ) と B が 2f 以内で合わなければ LX で、C-0258 と食い違うので止まる。
- バー消失そのものが本当の満タンより遅れて出る（表示の遅れ）なら、A・B はどちらもバー消失から数えるので、本当の満タン → I は L23 の値より長くなる。これは A・B では見分けられない。C-0079 の「バーが消えるのは発の当たったフレーム」を回ごとに総ダメージの HUD の増分で確かめる（読み方 3）。モデルの発のフレームは HUD の増分に合わせてあるので、HUD の増分と同じフレームならモデルの満タンと同じ時刻とみなせる。
- 外れたときの影響: L23 なら、モデルはゲージが律速の回の I を約 6f 遅く撃っている。フルバーストの入りも 6f 遅れ、20 秒ごとにフルバーストに入る編成では毎回効く。与ダメージへの効きは小さい（窓が 1 回あたり約 0.1 秒ずれるだけ）が、C-0073（確定）の I の段の文とモデルの定数を直すことになり、オーナーの判断が要る。フルバーストの入りの時刻と比べる観測値（III のタイマーの 00.00 で数えたもの）は、表示の遅れの分だけモデルとずれて見えるようになる。

## 読み方

1. 各録画のゲージが律速の I の発動（I のアイコンが出たとき、I の顔に CT の秒が出ていない回）を選ぶ。バーが消えたフレームは V-0025 の観測値（`018-08` など）の注記にある。
2. 読み方 A: 右のバースト欄（1740,420 から 180×150）を切り出し、バーが消えたフレームの前後を 1 フレームずつ並べ、I の顔に新しい CT の秒（「40」「20」）が出た最初のフレームと、II のアイコンに替わったフレームを控える。I の顔に CT の秒が出ていた回（CT が律速）は外す。
3. 同じ回で、総ダメージの HUD の増分（`hud.ts --mode jumps`）がバーの消えたフレームにあるかを控える。
4. 読み方 B（020）: 2 回目の I（エーテル）の CT の残り秒（1/100 秒）が出ている区間を 1 フレームずつ並べ、CT の 0（残り u のフレーム g から g + u ÷ 0.017）を出す。1 回目の本当の発動 = CT の 0 − あいだのフルバーストの入りの止まり（`020-03` の 1 回目）− 020 の時計の傾きで数えた 40 秒（V-0164 の `018-19` と同じ取り方）。C-0258 の「CT の 0 から再開まで」は足さない（1 回目の発動で CT が始まり、2 回目の CT の 0 で終わるので）。ただし V-0164 で同じ取り方の CT の 0 どうしの間隔に残った約 0.8f（`018-19` など）と同じ程度の偏りは含みうる。これからバー消失を引く。
5. 読んだ値は観測値にする（`source` に `V-0189`）。B の値は `gaugeFullToActivation`（n = 0）と比べる観測値にする。
