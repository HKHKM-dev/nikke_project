# V-0108: 誘導弾の RL の爆発は、何にも当たらなければゲージを溜めないか。小さな箱 1 つでどれだけ溜めるか

- 問い: I-DOLL・フラワーのフルチャージの発の爆発は、空（何にも届かない所）ではゲージを溜めず、小さな箱 1 つにだけ届けば的以外の 1 ヒット × フルチャージ倍率（35,000）を溜めるか（C-0177）

- 状態: 保留

## 条件

- オーナーの判断（2026-10-03、backlog 4-7）: C-0176 の余分な伸びは、出どころの物を特定するまでモデルに入れない（V-0107 の案 (b)）。そのために、空と小さな箱を撃つ録画を撮る。
- V-0107 の `134`（操作で的以外を撃つ）で、総ダメージが増えないままバーが約 4.5px の 1〜3 倍ずつ伸びた（`134-01`）。何も無いように見える所の爆発でも伸びたので、「爆発そのものが溜める」か「見えない所の物に届いた」かが分からない。どこにも届かない爆発が 0 かは確かめていない。
- バーは本当のゲージの約 12.6% までは 0px のまま（C-0084）なので、空や箱を撃つ前に、的のヒットでバーを見える所まで溜めておく。オートバースト OFF なので、満タンにすると後の伸びが読めない（満タンの手前で止める）。
- フラワーの数値: 的の 1 ヒット 28,000 × 2.5 = 70,000（約 9.5px）、的以外の 1 ヒット 14,000 × 2.5 = 35,000（約 4.7px）、倍率が乗らなければ 14,000（約 1.9px）。1px は本当の約 0.74%（C-0084）。

## 予測（撮る前に書く）

予測ファイルなし（予測なし。比べる指標が METRICS に無い）。撮る前に、仮説ごとの見え方を次のように書いた。

| 仮説                                                | 空に撃った発            | 小さな箱 1 つだけに届いた発          |
| --------------------------------------------------- | ----------------------- | ------------------------------------ |
| H1: 的以外の物に当たった分だけ溜まる（C-0177）      | バーは動かない（0px）   | 4〜5px（35,000）                     |
| H2: 爆発そのものが溜める（何に届いたかに依らない）  | 1 発ごとに 4〜5px       | 4〜5px（箱の分が足されれば 9〜10px） |
| H3: 的以外の 1 ヒットにはフルチャージ倍率が乗らない | （H1 か H2 のどちらか） | 1〜2px（14,000）                     |

- 撃たずに構えている間に被弾しても、バーは動かない見込み（`134` の f6180〜6546 で、被弾の赤い画面の間にバーが動かなかった）。動けば、被弾のゲージが別の出どころになる。
- 見分けられるか: 1px は約 7,400 なので、0・14,000・35,000・70,000 は px で分かれる。空の発が 6 発とも 0px なら H2 は外れ。
- 外れたときの影響: H2 なら、AUTO の余分な伸びは「的に当たらなかった爆発」ではなく「的に当たった発の爆発が別に数えられる」形を探すことになる（V-0107 の (a) か別の仮説）。H3 なら、`134-01` の 1 個ぶん約 4.5px は 2〜3 個ぶんの和で、1 個の量の読みを直す。

## 読み方

1. V-0107 と同じ: `gauge.ts --mode series` で BURST バーを全フレーム読み、`hud.ts --mode jumps`（レシピ `hud-jumps@1`）の総ダメージの増分とフレームで並べる。
2. 発のフレームは、構え → 発射の画（`ffmpeg` の切り出し）と、照準の横の残弾の表示で取る。空・箱の発ごとに、爆発（か弾が消えた）フレームの前後のバーの px を読む。
3. 箱が壊れたか、次に撃つまでに戻ったかを画で見る（C-0151: 射撃場のコンテナは 1 ヒットで壊れる）。
