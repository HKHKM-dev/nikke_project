## 条件

**何を確かめるか**

- 遅れの表（`burst/landing.ts` の `MEASURED_BURST_DELAYS`）のレイヴンの行は、効果の遅れが 0（未測定。C-0332 の model）。ヒットの遅れ（43f）は C-0233 で確定した。A.N.モードの持続ダメージ▲（burst の effects[1]）が、III の発動のフレームで付くのか、ヒットと同じフレームで付くのかを、V-0205 の録画 `225` を読み直して確かめる（2026-10-07 にオーナーが別の作業と決めた）。
- C-0332（確定・厳密一致）は、▲が tick ごとにその時点の状態で乗ること（T1）と式の置き場所を、録画 `173`（ラム + デルタ + レイヴン）で決めた。`173` では 1 回目のバーストの▲の乗った最初の tick が III の発動から動画で 54f だった（`173-11`。窓の端の手がかりで、判定には使っていない）。止まり 22f を引くとモデルで 32f で、ヒット（43f）より前になる。これは仮説の出どころで、`173` の値はこの検証の比べには使わない。
- `225` の既にある観測値（`225-01`・`225-02`）はヒットの時刻と値だけで、S1 の tick は読んでいない。

**編成**

- 録画 `225`: ココア（311。I）+ デルタ（20。II）+ レイヴン（851。III・操作・AUTO 射撃 ON）、オートバースト ON。射撃場・灼熱の BigArms・3 分モード・スペック固定。
- **最小構成**: ココアは定義が効果なし（V-0031）、デルタは C-0081 で、どちらも機構が確定している（V-0205 で `minimalWarnings` に警告なし）。観測したい事象（tick に▲が乗り始めるフレーム）に効く未確定の要素は、A.N.モードの効果の時刻だけ（▲の値と置き場所は C-0332 で確定）。

**読み方の前提**

- III の発動は、III のタイマーが 00.00 になったフレーム（`225-01` の f1371・3751・6130・8509・10889）。止まり（C-0069。モデルは 22f）の中はダメージも止まる（C-0071）ので、tick は止まりの明けの後に出る。ヒットは発動から動画で 64〜65f（`225-01`）。
- S1 の tick は 1 秒おきで、全スタックの和が 1 つのダメージ（C-0182）。値をスタックの数で割った 1 スタックの値で比べる（指標 `dotStackTickDamage`）。tick の位相は撃った時刻で決まるので、録画の tick がモデルの tick と同じフレームに来るとは限らない。比べるのは「止まりの明けからヒットまで（動画で発動の 22〜64f）に来た tick」の 1 スタックの値。
- 止まりの明けの後の tick には、S1 の攻撃力▲（フルバーストの始まりで付く。C-0185）とフルバースト補正が乗る。持続ダメージ▲の有無は、1 スタックの値が 1.8944 倍（1 + 持続ダメージ▲ 0.8944。C-0332 の置き場所）違うことで見分ける。

## 予測（撮る前に書く）

読む前に書いた（2026-10-07）。H0 はいまのモデル（効果は III の発動のフレームで付く）で、値は予測ファイル（records/predictions/V-0294.json）。モデルでは 5 回とも、発動の後の最初の tick が発動とヒットの間（モデルで 12〜39f）に来る。A1 の値は、遅れの表のレイヴンの行の効果の遅れを 43 にしてモデルを回した値（このファイルの範囲外。手で書く）。

| 仮説                                            | 止まりの明けからヒットまでの tick の 1 スタック（会心なし / 会心） | ヒットの後の tick の 1 スタック |
| ----------------------------------------------- | ------------------------------------------------------------------ | ------------------------------- |
| H0: いまのモデル（発動のフレームで付く）        | `tick-1`〜`tick-5`（343,883.1）/ `tick-1-crit` など（458,510.8）   | H0 と同じ                       |
| A1: ヒットと同じフレーム（発動の 43f 後）で付く | 181,526.1 / 242,034.9（H0 の 1 / 1.8944）                          | H0 と同じ                       |
| A2: 発動とヒットの間で付く                      | 間の tick のうち、前は A1 の値、後は H0 の値                       | H0 と同じ                       |

- **H0 を予想する**。`173` の 1 回目で、▲の乗った最初の tick がヒットより前（モデルで 32f）だった（`173-11`）。ラピの攻撃力▲も 1 ヒット目より前に付いた（V-0201 の `221-08`）。
- 止まりの明けからヒットまでの 43f に tick が来る回は、5 回のうち 3〜4 回の見込み（tick の間隔の約 59f のうち 43f）。来た回の tick の値で H0 と A1 を見分ける。来なかった回は比べない（観測値にしない）。
- A2 は、止まりの明けの直後の tick が H0 の値なら外せる（止まりの中は見分けられない。V-0201 と同じ）。
- 1 スタックの値は、`173-03`（ラムの編成）と同じ 343,883.1 を予想する（ココア・デルタは与ダメージを変えない）。
- 当たったときの影響: H0 なら、遅れの表のレイヴンの行の効果の遅れは 0 のまま、未測定の注記を外せる。A1 なら効果の遅れを 43 にする（発動からヒットまでの tick が▲なしになる）。A2 なら、間の値を表に入れる。
- 外れたときの影響: どの仮説の値とも合わなければ、S1 の攻撃力▲かフルバースト補正の付く時刻も疑う（その場合は持続ダメージ▲の時刻は決めない）。

## 読み方

1. `npm run records:read -- 225 --recipe hud-jumps --source V-0294` で HUD の増分を取る。各回の発動（`225-01` のフレーム）の前後で、S1 の tick（1 スタックの値の整数倍。V-0150・V-0227 の読み方）を発（フルチャージ）と分けて並べる。
2. 各回の止まりの明けからヒットまでに来た tick のフレームと値、スタックの数（値 ÷ 1 スタックの値が整数になる数）を取る。会心かは値の格子（4 : 3。`173-04`）で決める。
3. 来た回の 1 スタックの値を観測値（`dotStackTickDamage`。`args` は予測ファイルと同じ。会心かどうかで `crit` の指標を選ぶ。許容 `abs: 1`）にする。来なかった回は観測値にしない。
4. 各回の「発動 → 止まりの明けの後の最初の tick」の動画のフレーム数と、その tick とヒットの後の最初の tick の 1 スタックの値を記録する（`record`）。

- 5 回のフルバーストのどれも、止まりの明けからヒット（発動の 64〜65f 後。`225-01`）までに S1 の tick が 1 つ出た（発動の 55・53・52・51・50f 後。`225-08`）。どれもヒットより前。予測の見込み（3〜4 回）より多かった。

- 発動の前の最後の tick（26〜31f 前）は、どれも▲もフルバースト補正も無い 1 スタック 82,012.3 の整数倍で、ヒットの後の最初の tick（109〜114f 後）も▲の乗った値。`173`（ラムの編成）の 1 回目の 54f（`173-11`）とも揃う。
- 結論: C-0421（確定・厳密一致）。遅れの表のレイヴンの行の効果の遅れは 0 のまま（注記と定義の assumes の「未測定」を外した。C-0332 の model も書き替えた）。1 スタックに割った値（`225-03`〜`225-07`）だけでは機械の等級の候補が単独実測になる（端数が出るため）ので、読んだ整数の tick の値そのものも比べる観測値にした（`225-09`。3,438,831 とモデル 3,438,831.19。V-0189 の C-0285 と同じ扱い）。

## 分かったこと・分からないこと

- **C-0421（確定・厳密一致）**: レイヴンの A.N.モードの持続ダメージ▲は、ヒット（発動の 43f 後）より前に付き、止まりの明けの後の最初の S1 の tick から乗る。
- 分からないこと: 止まりの明けからモデルのフレームで 28f までのどこで付くか（その間に tick が無い）。
