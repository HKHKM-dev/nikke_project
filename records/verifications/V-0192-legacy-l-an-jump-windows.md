# V-0192: 旧 L-AN の的のジャンプの窓を、録画のゲーム内の時計で秒に直して与えると、L-AN-01 は許容内に入るか

- 問い: 旧の録画 L-AN（エレグ・MG 単騎 AUTO）の的のジャンプの窓を、録画の残り時間の表示（C-0141 の速さ）でゲーム内の秒に直して jumpWindows に与えると、L-AN-01 は残差の一覧で許容内に入るか
- 話題: 敵・的・場面

- Stage: plan/backlog.md 2-21（V-0088 の残り）
- 録画: `L-AN`
- 状態: 打ち切り

## 条件

- 撮影はしない。旧の録画 L-AN（エレグ・MG 単騎・AUTO。2026-08-29）を Drive から取り寄せて読み直す。
- 比べる値は `L-AN-01`（与ダメージ。許容 ±2%）。照合の組み方は残差の一覧と同じ（敵 `range-bigarms-fire`・出来事 `range-3min-jump`・条件は自動・中遠の着地点 B）。
- **`L-AN-01` は結論に結び付けない照合で、エレグはスキル定義が無い（予測は通常攻撃だけ）。許容内に入っても結論は作らない。** 窓の観測値（`use: input`）を作り、照合の入力にするところまでにする。

**いま分かっていること**

- V-0088 は、旧の録画は残り時間の 1 秒あたりのフレーム数が違う（`L-AN-06`）ので、フレームを 1f = 0.017 秒でゲーム内の秒に直せないとして、L-AN の窓を作らなかった。戦闘開始 f749（`L-AN-03`）から最後の増分 f11403 まで 10,654f で、モデルの 180 秒（10,588f）より 66f 長い。
- V-0086・V-0088 の「次に撮るもの」は「60fps に引き伸ばす前のフレーム（vfr）で読み直す」だった。
- 旧の録画では、残り時間の 1 秒が動画の約 59.2〜59.3f で、旧の世代の中の最終弾 → リロード完了の傾きもほぼ同じ速さ（C-0141 確定）。
- `L-AN-02`（V-0036 のジャンプの始まりの秒）は、戦闘開始からのフレームを 0.017 秒/f で数えた値（2 回目 f4610 → 65.64 秒）。

## 予測（撮る前に書く）

読み直しの前（2026-10-05）に、いまの照合（H0。代表値）だけを予測ファイル `records/predictions/V-0192.json` に固定した。H1（録画の窓）の値は窓を読まないと出ないので、V-0088 と同じく、窓の観測値を作ってから `override` の `jumpWindows` で足して固定し直す（このため、予測との比べの表では H0・H1 とも後付けになる）。

| 仮説                                                                 | 見えるはずのもの                                                                                    | 見分けられるか                   |

| H0: 録画の窓を与えても許容外のまま                                   | 残差の一覧の判定が「許容外」のまま                                                                  | 見分けられる（残差の一覧の判定） |

- 判定の目安: 観測値の許容（±2%）。
- 見込み: H1（V-0036）。ただし旧の録画は時計の速さが違い（C-0141）、MG は撃ち続けている間は毎フレーム当たるので、180 秒の中の動画のフレームがモデルより約 0.6% 多いぶんは、窓を与えても残る。
- 外れたときの影響: 結論は作らないので、`L-AN-01` の照合が許容外のまま残るだけ。

## 読み方

1. 録画のフレームの刻みを `ffprobe` で確かめる（引き伸ばしの有無）。
2. HUD の増分を、レシピ `hud-jumps`（V-0088 と同じ）で読む。残り時間の秒の変わり目を `timer.ts --mode changes` で読む。
3. 窓を V-0086 の読み方（終わりは着地の後の最初の発の 12f 前、始まりは終わりの 2 秒前とジャンプの前の最後の発の 1f 後の遅いほう）で、戦闘開始からのフレームで作る。
4. フレームをゲーム内の秒に直す。録画の時計（残り時間の秒の変わり目）で直したものを観測値にし、`L-AN-01` の `compare.setup.jumpWindows` に書く。予測ファイルに H1 を足して固定し直し、`npm run records:check` で照合する。

### 読み方の 1〜4（2026-10-05、クラウド環境で Drive から取り寄せて）

**録画のフレームの刻み（読み方の 1）**

- `ffprobe` で、名目 60fps（`r_frame_rate` 60/1）・平均 59.999fps・18,159 フレーム。フレームの時刻の間隔は 0.0155〜0.0176 秒に揺れるだけで、0.025 秒を超える欠け（引き伸ばしで重複フレームが挿入される所）は 1 つも無い。
- 解析ツール（`hud.ts`・`timer.ts` ほか）は `-fps_mode passthrough` で元のフレームを読む。V-0088 が読んだフレーム番号は、もともと引き伸ばす前のフレームだった。
- したがって、V-0086・V-0088 の「60fps に引き伸ばす前のフレームで読み直す」は、フレームの数え方を変えても何も変わらない。窓を作れなかった理由は、フレームの数え方ではなく、旧の録画の時計の速さ（C-0141。`L-AN-06`）だった。

**増分と残り時間（読み方の 2）**

- HUD の増分をレシピ `hud-jumps`（キャッシュ `hud-jumps@1`）で読んだ。最後の値 61,648,644 は `L-AN-01` と同じ。最後の増分は f11403、最初の増分は f761（戦闘開始 f749 の 12f 後。`L-AN-03` と同じ）。
- 30f 以上の止まりは、172f 前後のリロードのほかに、的のジャンプの 5 回（`L-AN-02` の始まりと同じ回）と、的が元の位置にいた 5 回（193〜218f。`L-AN-02` の note）があった。
- 残り時間の秒の変わり目（`timer.ts --mode changes`）は f809 から f11346 まで。読みが割れた変わり目（前後と 59f 前後で並ばないもの）を除くと 173 点で、当てはめた傾きは 59.19f/秒（`L-AN-06` の 59.212 と同じ）、残差は ±2.6f。

**窓（読み方の 3・4）**

- V-0086 の読み方で作り、観測値 `L-AN-07`（`use: input`）にした。フレームから秒へは、残り時間の変わり目を線で結んで直し、戦闘開始 f749 を 0 秒にした。読んだフレームは `L-AN-07` の note。
- 窓の長さは 4 回目だけ 1.83 秒（最後の発の 1f 後のほうが遅い）で、ほかは 2 秒。
- 2 回目の前の最後の発はマガジンの最終弾で、着地の後の最初の発 f4779 は、リロード完了の見込み（最終弾の 160f 後。`L-AN-05`）の 9f 後になる。2 回目の終わりは、着地ではなくリロードで決まっているかもしれない。V-0088 の 056 の 4 回目と同じで、読み方どおりに終わりを置いた。
- この直し方で、最後の増分 f11403 は 179.98 秒になる。今の録画（`056-11` の note。最後の増分がモデルの 180 秒の最後のフレームの 4f 後）と同じく、戦闘の終わりの直前に来る。1f = 0.017 秒で直すと 182.8 秒になり、180 秒に収まらない（V-0088 が窓を作らなかった理由）。

**照合**

- `L-AN-01` の `compare.setup.jumpWindows` に `L-AN-07` を書き、`npm run records:check` で回した。結果は予測の表の H1 のとおり −0.37% で、許容内。残差の一覧の許容外は 15 件 → 14 件。
- 参考（予測ファイルの外。`sim-run.ts --jump-windows` に秒の並びを渡した使い捨ての試算）: 同じフレームを 1f = 0.017 秒で直した窓では 60,988,740（−1.07%）で、これも許容内。窓の端は 0.2〜1.1 秒遅くなる。
- `L-AN-07` を `L-AN-06` の速さ（59.212f/秒）で一様に直しても、窓の端はどれも 0.06 秒以内で同じ。

## 分かったこと・分からないこと

- **`L-AN-01` は H1**。録画の窓（`L-AN-07`）を `jumpWindows` で与えると、残差の一覧で許容内（−0.37%）になる。V-0036 のその場の書き換えと同じ向き。窓のフレームを 1f = 0.017 秒で直しても許容内（−1.07%）なので、判定は秒への直し方に左右されない。
- 旧の録画 L-AN は 60fps に引き伸ばされていない。窓を作れなかったのは時計の速さの違い（C-0141）で、その録画の残り時間の変わり目で秒に直せば、窓を作れる。直した最後の増分は 180 秒に収まる。
- **結論は作らない**（状態は、結論の無い記録の書き方に合わせて打ち切りにした。V-0088・V-0095 と同じ）。`L-AN-01` は結論に結び付けない照合で、エレグはスキル定義が無い（予測は通常攻撃だけ）。録画 1 本の合計の一致で、区間ごとの発の数は比べていない（L-AN には区間ごとのヒット数の観測値が無い）。
- 分からないこと:
  - 旧の録画では、残り時間の 1 秒に動画のフレームが今より約 0.6% 多い（C-0141）。MG が撃ち続ける間は毎フレーム当たるなら、180 秒の発の数はモデルより多くなるはずだが、今回の照合の差（−0.37%）にこれがどれだけ入っているかは分けていない。
  - 2 回目の窓の終わりが、着地とリロードのどちらで決まっているか（読み方の 3・4）。
