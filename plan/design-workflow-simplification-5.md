## 1. 最小構成の印の手入れを道具にする

**いま**

- 結論の `minimal` の印は 471 件（191 の結論）。印の要素は `ラピ：レッドフード burst.notes[2]` のように、スキル定義の **notes の添字**で指す（`relevance.ts` の `elementsOf`）。
- 語彙の PR は notes を効果に書き直す。そのたびに、同じキャラの notes の添字がずれ、ほかの結論の印を手で直している: #743 で C-0188（`notes[3]` を消し、`burst.notes[3]` → `notes[2]`）、#739 で C-0658（印を 2 つ消す）、#730 で C-0579・C-0681・C-0699（印を書き替え）。直近の語彙の PR 8 件のうち 3 件。
- 直し忘れは検査に掛からない。`records/claims.ts` の検査は印の形しか見ず、要素が今もあるかは見ない。添字がずれて別の notes を指しても、その notes の警告を黙って外す。
- いまの main で数えると、確定の結論の印 439 件のうち **134 件が、どの組の警告も抑えていない**:
  - 52 件: 要素がもう無い（notes が効果に書き直された・数が減った。例 アニス：スター `burst.notes[1]` を指す C-0198〜C-0259 の 10 件ほど、エレグ `skill2.notes[1]` の C-0114・C-0135・C-0141）。
  - 62 件: 要素が結論の結び付いた効果になり、未確定の要素から外れた。
  - 20 件: 感度か静的な判定で、いまは効かないと決まった。
- あわせて、同じ (要素, 理由) の印が結論ごとに書き写されている（重複 172 件。例 たきなの `burst.effects[0]` の同じ理由が C-0709〜C-0712 の 4 件に、ラピ：レッドフードの戦闘補助の notes の同じ理由が C-0715・C-0716 に 9 件ずつ）。

**案**

- **(a) 付け替えを自動に**: `records:close`（と `records:check`）が、変更のあったスキル定義（`origin/main` との差）の notes を、前の版と今の版で `ja` の文の一致で対応づけ、印の添字を新しい番号に書き替える。対応先が無い（notes が消えた・効果になった）印は、その結論と要素を出す。
- **(b) 行き先の無い印を落とす**: `records:check` が、印の要素が根拠の観測値のどの録画の要素にも無いとき、エラーにする（今の 52 件のような印を新しく作らない）。
- **(c) 使われていない印を出す**: 要素はあるが、どの組の警告も抑えていない印は、[minimal.md](minimal.md) に「使われていない印」として出す（落とさない。感度や結論の状態が変わればまた要る）。
- **(d) 一度だけ掃除する**: 行き先の無い 52 件を消す。使われていない 82 件（62 + 20）は、推奨は残す（(c) の一覧に出るだけ。結論が棄却されて要素が未確定に戻ると、また要る）。オーナーが「消す」なら一緒に消す。
- **(e) 同じ理由の印を 1 つに**: 印の `element` に要素の並びも書けるようにする（同じ結論の中で同じ理由を書き写さない）。結論をまたぐ重複は、理由が結論ごとに読めるほうがよいので、そのまま。

**効果**: notes を効果にする PR で、ほかの結論の印を探して直す手間が無くなる（道具が直すか、直せないものを名指す）。添字のずれで別の notes を外す誤りを検査が止める。印の 471 件のうち 52 件が減り、新しい結論の印を書く量も (e) で減る。

**気をつけること**:

- (a) の文の一致は、notes の文を直した同じ PR では外れる。そのときは (b) のエラーか (c) の一覧に出るので、手で直す。
- 閉じた検証記録は書き換えない（印は結論の側にある。[design-minimal-check.md](design-minimal-check.md) の決めごとのまま）。
- 実施は道具の PR 1 つ（(a)〜(c)・(e) とテスト）と、掃除の commit（(d)。生成物の差は `records:check` と `records:minimal` で作り直す）。警告の数が変わらないこと（消すのは何も抑えていない印だけ）を PR に書く。

## 2. 1 PR の結果を書く先を絞る

**いま**（段 11・12 の語彙の PR。#730・#737〜#739・#743）

1 つの PR の結果を、次の 5 か所に書いている。

| 書く先                                                                                                              | 書いている中身                                                                 | 他と重なる所     |
| ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ---------------- |
| 結論の JSON（`records/claims/`）                                                                                    | 結論・根拠・モデル側                                                           | —（正）          |
| 検証記録（`records/verifications/`）                                                                                | 読み方・結果・分かったこと                                                     | —（正）          |
| 段の設計書の 3.x 節「読んで分かったこと」と「経過」（例 [design-skill-stage12.md](design-skill-stage12.md) 3.1 節） | 結論の中身の言い換え（「S1 の攻撃力▲は … 乗る（C-0715）」）と、1 PR 1 行の経過 | 結論・検証記録   |
| [design-skill-stages.md](design-skill-stages.md)「経過」                                                            | 段の PR ごとに 1 行（足した語彙・録画・V-・C-・次の PR）                       | 段の設計書の経過 |
| PR の本文（スカッシュのコミットの本文。1.6〜3.6KB）                                                                 | 変更・確かめ（値と結論）・残差                                                 | 検証記録・結論   |

- 第 4 回の 4 で「モデルを変えない確定は経過に書かない」とした後も、モデルを変える PR では、段の設計書と段の一覧の両方に同じ 1 行を足し、設計書の「読んで分かったこと」に結論を言い換えている。#743 は 1 つの結果を 5 か所に書いた。
- [design-skill-stages.md](design-skill-stages.md) の経過は段の PR ごとの行で伸び（35KB）、並行する段の PR どうしが同じ節の末尾で衝突する。

**案**

- [design-skill-stages.md](design-skill-stages.md)「経過」は、段の出来事（起案・決定・閉じた）だけを書く。段の中の PR ごとの行は、段の設計書の経過だけに書く。
- 段の設計書の「読んで分かったこと」は、次の PR や論点に効く判断だけを書き（例「撮影 D は要らない」「この 3 回は分けられず PR 2 で見る」）、結論の中身は ID で指す。経過は「PR N を実装した（V-NNNN、C-…）。次は …」の 1 行にする。
- PR の本文の型を決め、`records:close` が題名の案と一緒に本文の骨組みを出す: 「変更」（コード・データ。人が書く）、「確かめ」（V-NNNN と結論の ID・状態・等級の一覧。道具が出す）、「既存の残差」（許容外の件数の前後。道具が出す）、「そのほか」。値と読み方は検証記録にあるので本文に書き写さない。
- 書き方は [skills-guide.md](skills-guide.md) 1.4 節（経過）と [verification-guide.md](verification-guide.md) 9 節（PR）に 1 行ずつ足す。前の経過は直さない。

**効果**: 語彙の PR ごとに、同じ結果の言い換え 2〜3 か所が減る。段の一覧の経過の衝突が減る。PR の本文は道具の出す骨組みに「変更」を足すだけになる。

**気をつけること**: PR の本文はスカッシュのコミットの本文になり、`git log` で経緯を引く手掛かりでもある。ID が並んでいれば結論と検証記録に辿れるので、引く手掛かりは減らない。
