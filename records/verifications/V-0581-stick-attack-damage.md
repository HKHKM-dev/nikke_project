# V-0581: 発射体付着ダメージ▲は攻撃ダメージ▲と同じ枠か（クラウンの攻撃ダメージ▲とラピ：レッドフードの付着）

- 問い: 発射体付着ダメージ▲と攻撃ダメージ▲が同じ付着のヒットに乗ったとき、1 つの和 (1 + Σ攻撃ダメージ + Σ付着) で掛かるか、別の乗数 (1 + Σ攻撃ダメージ) × (1 + Σ付着) で掛かるか
- 話題: 1 発の式・バフの掛かり方
- 日付: 2026-10-31
- 録画: `0821`、`0822`
- 結論: `C-0796`
- 状態: 完了
- 派生元: `V-0580`

## 条件

- 型: 撮影。台帳（`records/recordings/*.json` の `team`）に、ラピ：レッドフード（16）が撃っていて、味方に攻撃ダメージ▲を配るキャラ（17・226・330・352・451・473）と同じ編成の録画は無い（録画 0731・0732 はラピ：レッドフードが撃たない枠。2026-10-31 に調べた）。
- 背景: 発射体付着ダメージ▲の置き場所（`damage.ts` の `PROJECTILE_STICK_BUCKET`）は、発射体爆発ダメージ▲（C-0205）にそろえて攻撃ダメージ▲と同じ枠にした仮定。付着▲どうしが 1 つの和であること（C-0724）と、受けるダメージ▲とは別の乗数であること（C-0794）は確かめた。攻撃ダメージ▲の乗った付着は読んだことが無い（ラピ：レッドフード自身の S1 の攻撃ダメージ▲は戦闘補助のときだけで、そのときはバーストの付着▲が付かない。自分に乗るかも確かめていない）。
- 見るヒット: ラピ：レッドフードの S2 の粘着榴弾の付着の 1 ヒット（どの距離帯でもコア。C-0724）。
- 攻撃ダメージ▲ A: クラウン（330・II）のバーストの「味方全体に攻撃ダメージ 36.24%▲（15 秒）」（C-0393・C-0499）。III のラピ：レッドフードのバーストの付着▲（421.2%・10 秒）とフルバーストより 5 秒ほど長く残るので、その「尾」（フルバーストの後、クラウンのバーストの 15 秒の終わりまで）の付着には、A と S2 の常時の付着▲ s = 150.72% だけが乗る（フルバースト補正もバーストの付着▲も無い）。クラウンの S2 のリラックスの回復の後の攻撃ダメージ 20.99%▲（7 秒。C-0271）も、フルバーストの外で同じ形に乗る。
- 攻撃ダメージ▲の有無は、比べる付着の値を見ずに、前と後のラピ：レッドフードの通常攻撃の 1 ヒット（攻撃ダメージ▲は通常攻撃に別の乗数で乗る。C-0018）で決める（V-0580 の読み方）。
- 最小構成: 鈴原サクラ（836・I・AI）+ ◎クラウン（330・II・AI）+ ラピ：レッドフード（16・III・操作）。V-0580（録画 0809・0810）のデルタをクラウンに替えただけで、付着の▲なしの値と鈴原サクラの受けるダメージ▲（C-0794）は確かめてある。基本バースト段階 I の味方がいるので、ラピ：レッドフードは戦闘補助でなく、S1 の攻撃ダメージ▲は付かない。クラウンは全スロットが確定の結論に結び付く（S1 の発動者基準の攻撃力▲は、バーストを使ったラピ：レッドフードに 15 秒付き、尾の付着の最終攻撃力を上げる。C-0393 の形）。ラピ：レッドフードの未対応の notes（付着のヒットのゲージ）はバーストの時刻にだけ効く。未確定は付着▲の置き場所だけ。
- 仮説（F は付着の 1 ヒットに掛かる▲の乗数）:
  - E1（攻撃ダメージ▲と同じ枠。いまのモデル）: F = 1 + A + s
  - E2（別の乗数）: F = (1 + A)(1 + s)
  - 攻撃ダメージ▲の無い付着は、どちらの仮説でも同じ値（532,807。受けるダメージ▲ありで 624,343。V-0580）。

## 予測

予測ファイルは作らない（E2 は定数を替えるので `setup` の上書きで出せない）。下はいまのモデル（E1。main の 4f6af163）を、撮影と同じ編成・スペック固定で回した値（コア・会心なし・距離ボーナスなし）。E2 は E1 × (1 + A)(1 + s) ÷ (1 + A + s)。

| 付着                               | A      | 受けるダメージ▲ | E1（モデル） | E2          | E2 ÷ E1 |
| ---------------------------------- | ------ | --------------- | ------------ | ----------- | ------- |
| クラウンのバーストの尾             | 36.24% | なし            | 872,375.4    | 1,038,427.5 | 1.190   |
| クラウンのバーストの尾             | 36.24% | あり            | 1,022,249.5  | 1,216,829.3 | 1.190   |
| リラックスの後（フルバーストの外） | 20.99% | なし            | 577,413.0    | 644,642.6   | 1.116   |
| リラックスの後（フルバーストの外） | 20.99% | あり            | 676,612.5    | 755,392.2   | 1.116   |
| 尾とリラックスが重なった           | 57.23% | あり            | 1,097,023.1  | 1,404,300.9 | 1.280   |

- 見分けられる: どの行も E1 と E2 は 11% 以上離れ、会心の × 1.25（コア + 会心 ÷ コア）とも距離ボーナスの × 1.15 とも重ならない。モデルでは 1 回のフルバーストの後に尾の付着が 2 つ前後、リラックスの後の付着が 3 分で数個出る。
- フルバーストの窓の中の付着（バーストの付着▲ 421.2% とフルバースト補正も乗る）も E1 と E2 で 29〜45% 離れるが、▲の種類が多いので対照にとどめる。

## 読み方

1. `node tools/captures/intake.ts` で取り込む（`--rid 836,330,16 --controlled 3 --target BigArms --element Fire --mode range-3min --fixed-spec on --auto-fire on --auto-burst on`）。
2. `npm run records:read -- <録画 id> --recipe hud-jumps --source V-0581 --write` で総ダメージの増分を取る。
3. 撮ってみると、クラウンも MG で毎フレーム撃つので、ラピ：レッドフードの通常攻撃の 1 ヒットは単独では出ず、増分はラピ：レッドフードとクラウン（と鈴原サクラ）の通常攻撃の和になった。そこで読み方を替え、付着の候補の増分（45 万〜250 万）から、E1・E2 の付着の値（攻撃力の段・攻撃ダメージ▲・受けるダメージ▲・コア/会心/距離ボーナスの組の全部）を引いた残りが、前後 10f に繰り返し出る増分（同じフレームの通常攻撃の和）か 0 と ±2 で一致するかを見た。
4. 分かれた付着の 1 ヒット（重なりを引いた値）を、モデルの同じ段の付着と比べる。重なりの値は、モデルのその段の 2 人の通常攻撃の 1 ヒットの和と同じかも確かめた（例: 尾の受けるダメージ▲ありの段で、ラピ：レッドフードのコア 30,681 + クラウンのコア 23,530 = 54,211）。

## 分かったこと・分からないこと

- 分かったこと: 発射体付着ダメージ▲は、攻撃ダメージ▲と 1 つの和 (1 + Σ攻撃ダメージ + Σ発射体付着ダメージ) で付着のヒットに掛かる（別の乗数ではない）。いまのモデル（`PROJECTILE_STICK_BUCKET` = `attackDamage`）の仮定が合っていた。モデルは変えない（注記の「仮定」を結論に置き換える）。
- 分からないこと: 攻撃ダメージ▲の出どころはクラウンのバーストと S2 だけ。
