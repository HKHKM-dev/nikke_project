## 2. 語彙

### 2.1 戦闘補助でない側の行（PR 1）

- 説明文: S1「フルバーストタイムが発動した時、自分が戦闘補助状態でなければ、自分に攻撃力 X%▲・N 秒間維持」、バースト「バーストⅢで使用した時: 照準線に最も近い敵 1 機に最終攻撃力の X% の追加ダメージ」。
- **戦闘補助の有無**: 戦闘補助は「戦闘開始時およびフルバーストタイムが終了した時」に、基本バースト段階 I の味方の有無（部隊構成）で付く・消える。編成は戦闘の間に変わらないので、どの時点でも同じ結果になる。そこで、戦闘補助の有無を状態にせず、編成の条件 `burstStepMix` で書く（論点 2）。戦闘補助でない ⇔ `burstStepMix: { otherBurstStep: "Step1", present: true }`。数え方は、いまの `countsAsBurstStep` のまま（再突入するキャラは I と数えない。C-0203）。
- **「バーストⅢで使用した時」**: 戦闘補助でなければバーストは III のまま（基本バースト段階が III）、戦闘補助ならバースト I に変わる（2.5 節）ので、使った段は戦闘補助の有無と 1 対 1 に決まる。そこで、III の行も同じ `burstStepMix` で書き、`assumes` に「使った段は編成で決まる」と書く（論点 3）。
- **足す語彙**: `damage` に `burstStepMix` を開く（いまは `passive`・`timed`・`cooldownReduction`・`heal`・付与・`burstReentry` だけ）。編成の条件を満たさない効果は最上位で外す（`skills/composition.ts`）ので、1 パス目は変わらない。S1 の攻撃力▲は、いまの `timed` のまま書ける。
- 照準線に最も近い敵 1 機は、敵 1 体の前提ではその敵（`assumes`）。追加ダメージがバーストのヒットのどれだけ後に出るか（`delayFrames`。段 11 の PR 5 の C-0707 と同じ読み方）と、フルバースト補正をどのフレームで取るかは、読みで決める。
- 阻止部位の攻撃ダメージ▲は、前提の外の notes のまま（C-0443）。バーストの III の行の爆発範囲▲は未対応の notes のまま（爆発範囲はダメージの式に無い。棚卸し 0.2 節）。

### 2.2 粘着榴弾（PR 2）

- 説明文（S2）: 「通常攻撃で N 回攻撃した時、自分に「粘着榴弾」」「機能：粘着する発射体を発射し、命中した位置に付着させる。フルバーストタイム中に起爆される」「発射体付着ダメージ：最終攻撃力の X% のダメージ」「発射体爆発ダメージ：最終攻撃力の Y% のダメージ」「最大装弾数：1 発」。
- **撃つ時**: 回数のきっかけ `{ count: "normalShot", everyRef: 1 }`（射撃の回数。弾丸命中率が 1 の枠では命中と同じ列）。数え方（戦闘中ずっと通しで数えるか）は、いまの回数のきっかけの規則のまま書き、読みで確かめる。
- **付着**: 撃った榴弾が的に当たったフレームに、付着ダメージの 1 ヒット。飛ぶ時間（撃ってから当たるまで）・コアに当たるか・ゲージを溜めるかは読みで決める（遅れは `delayFrames`、ゲージは `gaugeHits`、コアは的の表の行の流儀）。
- **起爆**: 説明文は「フルバーストタイム中に起爆される」だけで、時刻と数が書かれていない。2 つの読み:
  - **K1（溜めて、フルバーストの始まりに起爆）**: フルバーストの外で付着した榴弾は付いたまま溜まり、フルバーストの始まりに付いている数だけ爆発する。フルバーストの中で撃った榴弾は、付着した後すぐ（か決まった遅れで）爆発する。
  - **K2（付着は 1 つだけ）**: 「最大装弾数：1 発」を付着していられる数と読み、次の榴弾で前の榴弾が置き換わる（か、その時に起爆する）。フルバーストの始まりに爆発するのは最大 1 つ。
  - 見分け方: フルバーストの始まりの爆発の値（1 つ分か、付着した数の分か）と、フルバーストの外で爆発のヒットが出るか。0116・0117 では、フルバーストの前に付着が何回もある（通常攻撃の回数で見積もれる）。
- **語彙**: K1 なら、カウンタ `stickyGrenade`（付着している榴弾の数。上限は読みで決める）を目録に足し、付着ごとに `counterChange` で 1 足し、起爆は `damage`（`fullBurstStart`・`perCount: { counter: "stickyGrenade" }`）と `counterChange`（0 に戻す）で書く。フルバーストの中で撃った分は、付着と同じきっかけの `damage`（条件 `inFullBurst`）で書く。`damage` の `perCount` はいま `burstUse` のきっかけだけなので、`fullBurstStart` に開く。K2 なら、カウンタの上限を 1 にした同じ形で書ける。
  - 代わりの形（論点 4）: 粘着榴弾を 1 つの効果の種類（独自の弾）にまとめ、付着・溜め・起爆をその中で持つ。
- **1 ヒットの式**: 付着・爆発とも、説明文は「ダメージ」で、追加ダメージやスキルダメージの種別は書かれていない。いまの `damage` の種別のどれで 1 ヒットが合うかを読みで決める。爆発のヒットには発射体爆発ダメージ▲を掛ける（`projectileExplosion` の流儀。2.3 節）。

### 2.3 発射体付着ダメージ▲と発射体爆発ダメージ▲（PR 2）

- 説明文: S2「戦闘開始時、自分に発射体付着ダメージ X%▲（持続）・発射体爆発ダメージ Y%▲（持続）」、バーストの III の行「自分に発射体付着ダメージ X%▲（N 秒間維持）」。
- **付着▲**: stat `projectileStickDamage` を足す（一覧の「発射体付着ダメージ」の行の最初の使い手）。付着のヒットにだけ掛ける。式の中の置き場所（発射体爆発ダメージ▲のように付着のヒットだけの別の項か、攻撃ダメージ▲と同じ加算の枠か）は、S2 の常時の▲だけの付着（バーストの III の窓の外）と、バーストの▲が加わった付着（窓の中）の 1 ヒットの比で決める。
- **爆発▲**: いまの stat `projectileExplosionDamage`。いまは RL の通常攻撃と `projectileExplosion` の印の付いた自動攻撃にだけ掛かる（`damage.ts` の `explosionHitMultiplier`）。粘着榴弾の起爆のヒットに掛け、ラピ：レッドフードの MG の通常攻撃には掛けない（MG の弾は発射体の爆発を持たない）。付着のヒットに掛かるかは読みで確かめる。
- 定義は、S2 の 2 つを `passive`（`self`）、バーストの付着▲を `timed`（`burstUse`・`self`・`durationRef` 7。条件は 2.1 節の `burstStepMix`）で書く。

### 2.4 回数条件の変更と有利コード（PR 2）

- **回数条件の変更**: バーストの III の行「スキル2粘着榴弾発動回数条件 N 回▼・X 秒間維持」。窓の間だけ、S2 の回数のきっかけの N を減らす。いまの `cycleEvery`（紅蓮：ブラックシャドウ。段の循環の間隔の変更）は段の循環にだけ書けるので、回数のきっかけを持つ効果の N を減らす形に広げる（減らす相手はスロットで指す。形は実装で決める）。数は窓の始まりで数え直すか、通しの数のまま窓の中の N で判定するかは、読みで決める（窓の中の付着の数で見分ける）。
- **有利コード**: S2「戦闘開始時、自分に「電撃コードの敵に有利コードのダメージ適用」（持続・解除不可）」。電撃コードの敵を、自分のコードに対して有利として扱う。いまのモデルは、属性有利を自分と敵のコードの組で決める。そこで、自分の効果（`passive` の印の stat）で有利に扱う敵のコードを足し、有利の判定（有利コードの攻撃ダメージ `elementDamage` の掛かり方を含む）をその組にも広げる。灼熱の的では効かないので、0116・0117 では見えない。撮影 B（電撃の的）で、通常攻撃の 1 ヒットが有利の値になるかを見る（論点 6）。

### 2.5 バースト段階の変更（PR 3）

- 説明文（S1）: 「戦闘開始時およびフルバーストタイムが終了した時、部隊構成による効果・該当効果のみ適用。基本バースト段階がⅠの味方がいない場合、自分に「戦闘補助：バースト I に変更」（持続・解除不可）、いる場合、自分に「戦闘補助消去」」。
- **語彙**: 効果 `burstStepChange`（`step: "Step1"`・`burstStepMix: { otherBurstStep: "Step1", present: false }`）を足す。持つ枠のバーストの段（`BurstUnit` の段）を、バーストのチェーンを組む前に差し替える。編成で決まる静的な効果で、`burstReentry` と同じく 1 つの定義に 1 つまで。戦闘開始時とフルバースト終了時の付け直しは、編成が変わらないので結果が同じ（`assumes`）。名前の付いた状態「戦闘補助」は目録に足さない（読む側が、同じ定義の `burstStepMix` だけのため。論点 2）。
- **ほかの効果への効き**: 差し替えた段は、バーストのチェーン（どの枠が I を使うか）にだけ効かせる。ほかのキャラの `burstStepMix`（「基本バースト段階が〜の味方」）は、説明文の「基本」どおり差し替える前の段で数える（確かめていない。`assumes` に書き、使い手が同じ編成に入る時に確かめる）。
- **戦闘補助の側の行**:
  - S1「フルバーストタイムが発動した時、自分が戦闘補助状態なら、味方全体にバーストスキルクールタイム X 秒▼・攻撃ダメージ Y%▲（N 秒間維持）」: `cooldownReduction`（`fullBurstStart`・`allies`）と `timed`（`fullBurstStart`・`allies`・`attackDamage`）。条件は `burstStepMix: { otherBurstStep: "Step1", present: false }`。
  - バースト「バーストⅠで使用した時: 自分にバーストスキルクールタイム 20 秒▼・爆発範囲▲、味方全体にスキル発動者基準で攻撃力▲」: `cooldownReduction`（`burstUse`・`self`）と `timed`（`burstUse`・`allies`・`attack`・`casterAttack`）。20 秒は説明文の直書きなので、`cooldownReduction` に即値の欄（`seconds`）を足す（`ref` とちょうど片方）。自分のクールタイム▼は、同じフレームで始まった自分のバーストの CT を縮める（同じフレームの発動の後に当てる。[design-stage10.md](design-stage10.md) 4 節の規則のまま）と読み、バースト欄の CT の明けで確かめる。爆発範囲▲は未対応の notes のまま。
- 画面: 効果の出どころに「（戦闘補助）」「（戦闘補助でない時）」のように出す。バーストの段の表示は差し替えた段にする。

2. **スノーホワイト：ヘビーアームズ（ロックオン・オートファイア・使用回数）**: 1 と「カウンタの数だけ順番に攻撃し、1 回ごとに減らす」形を共有する（オートファイア準備の装填数）。フルアクティブの「使用回数を使い切った時に解除」は、カウンタが 0 になった時のきっかけ（段 11 の `{ counterFull }` の逆向き）。既存の録画は 0328（単騎・手動。オートファイアのヒット）だけで、ほかは撮影。
3. **T4 の残り**: 定義の無い使い手（ドロシー・アルカナ）を定義する時。
4. **状態の中身の値と維持時間の変更**: 定義のある使い手がいないので、使い手を定義する時に足す。
5. **使用武器の変更を名前の付いた状態の中身にする**（段 11 の論点 1 の代わりの案）: 状態の名前を他の効果が読む使い手（ナユタ・ギルティ：マイティバニー・シン：スウィフトバニー）を定義する時。

## 6. 論点

決定（2026-10-28、オーナー）: 論点 1〜9 は推奨どおり。論点の文は諮った時のまま。

1. **段 12 の対象**（0.3 節）
   - 推奨: ラピ：レッドフードの全スロット（と PR 4 のモランの宝物版の S2）。いまのモデルとの差がいちばん大きく、戦闘補助でない側（ふだんの編成の側）は既存の録画 0116・0117 で撮影を待たずに確かめられる。
   - 代わりの案: ミハラ：ボンディングチェーンとスノーホワイト：ヘビーアームズ（段 11 の 4 節の 3。カウンタの数だけ出る攻撃を共有し、ミハラ：ボンディングチェーンの S1 は既存の録画 0119・0490・0492 で確かめられる）。定義の無い使い手につながる語彙（カウンタ・自動攻撃）は多いが、効きはラピ：レッドフードより小さく、スノーホワイト：ヘビーアームズはほとんどが撮影。
2. **戦闘補助の書き方**（2.1・2.5 節）
   - 推奨: 状態にせず、編成の条件 `burstStepMix` と、段を差し替える静的な効果 `burstStepChange` で書く。戦闘補助は編成だけで決まり、戦闘中に付き外れしない。`burstReentry` と同じ流儀で、1 パス目に動的な仕組みを足さない。
   - 代わりの案: 名前の付いた状態「戦闘補助」（持続・解除不可）を目録に足し、戦闘開始時とフルバースト終了時に付ける・消す形で書き、各行を条件 `selfState` で分ける（説明文の形どおり。状態がバーストの段を変える仕組みを、チェーンを組む所に足す）。
3. **「バーストⅠ・Ⅲで使用した時」の条件**（2.1 節）
   - 推奨: 戦闘補助の有無と同じ `burstStepMix` で書き、`assumes` に「使った段は編成で決まる」と書く。ラピ：レッドフードでは使った段と戦闘補助が 1 対 1 で、語彙が増えない。
   - 代わりの案: 「バーストを使った時の段」の条件を足す（説明文どおり。使い手はいまラピ：レッドフードだけ）。
4. **粘着榴弾の書き方**（2.2 節）
   - 推奨: いまの語彙の組み合わせで書く（付着は回数のきっかけの `damage`、付着している数はカウンタ `stickyGrenade`、起爆は `perCount: { counter }` の `damage` とカウンタの戻し）。段 10・11 のカウンタの語彙がそのまま使え、起爆の形（K1・K2）の違いはカウンタの上限と起爆のきっかけの違いで書ける。
   - 代わりの案: 粘着榴弾を 1 つの効果の種類（独自の弾。付着・溜め・起爆を中に持つ）にする。定義は読みやすいが、ほかの効果（回数条件の変更・付着▲）が読む先が新しい種類になり、使い手はラピ：レッドフードだけ。
5. **PR 1・2 を既存の録画の読み直しにするか**（3.1・3.2 節）
   - 推奨: する。0116 の前の回で読み方と値を決め、0116 の後の回と 0117 で再現を見る。足りなければ撮影 D を同じ依頼に足す。
   - 代わりの案: 撮影 D（ラピ：レッドフードを唯一の III にした編成）を先に撮り、それで決める（0116・0117 は I-DOLL・サンも III で、どちらがバーストを使ったかを回ごとに読む手間がある）。
6. **撮影 B（単騎・電撃の的）を入れるか**（2.4・3.2 節）
   - 推奨: 入れる。有利コードは灼熱の的では見えず、単騎の電撃の的なら、通常攻撃の 1 ヒットの未確定の要素が有利コードだけになる。付着の刻みも、単騎なら射撃の回数を HUD で数えられる。
   - 代わりの案: 有利コードは未対応の notes のまま残し（灼熱の的の録画では効かない）、B は撮らない。付着の刻みは 0116・0117 の読みだけで決める。
7. **モランの宝物版の S2 を段 12 に入れるか**（PR 4）
   - 推奨: 入れる。語彙は `cooldownReduction` の条件 `selfState` だけで、撮影の依頼を A・B と同じ回にまとめられる。モランの残りの未対応はこの行だけになる。
   - 代わりの案: 入れない（段 12 をラピ：レッドフードだけにする）。モランの行は、熱血の状態を読むほかの使い手を定義する時に回す。
8. **PR の順**（1 節）
   - 推奨: PR 1 → PR 2 → PR 3・PR 4（PR 1・2 は撮影を待たない。撮影の依頼は PR 1 の読みの後に 1 回で出し、録画が届いた順に PR 3・4 と PR 2 の B の分を進める）。
   - 代わりの案: 起案が決まったらすぐ撮影の依頼を出す（D は入れずに出し、要れば後で足し撮り）。
9. **段 11 の閉じ残り（一覧の区分の表）**（棚卸し 0.4 節）
   - 推奨: 段 12 の PR 1 に入れて直す（生成物の作り直しも同じ PR）。
   - 代わりの案: 段 12 の前に、区分の表だけを直す小さな PR を出す。
