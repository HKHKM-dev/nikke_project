# V-0133: I-DOLL・フラワーのバーストのヒットは、モデルの I の発動から何フレーム遅れるか

- 問い: I-DOLL・フラワー（I）のバーストのヒットは、モデルの I の発動（C-0073 の読み方では I のアイコンが II のアイコンに替わるフレーム。単騎ではチェーンの UI に替わるフレーム）から何フレーム遅れるか。単騎のチェーンの UI のフレーム（077-23 の起点）は、モデルの I の発動と同じフレームか
- 話題: スキル・キャラ固有
- 日付: 2026-10-04
- Stage: plan/design-burst-landing.md 5 節の 2（ほかのキャラの遅れ）。backlog 2-4
- 録画: `063`、`080`、`134`
- 状態: 調査中
- 派生元: `V-0106`

## 条件

- 撮影なし。既存の録画の読み直し。
  - `063`: フラワー（I）+ デルタ（II）+ アスカ（III・操作）。射撃場・灼熱の BigArms・3 分モード・スペック固定・AUTO・オートバースト ON。
  - `080`: フラワー（I）+ ユニ（II）+ アスカ（III・操作）。同じ条件。ユニのバーストにも倍率ダメージがあるので、フラワーのヒットと見分ける。
  - `134`: フラワー単騎・操作（AUTO 射撃 OFF・オートバースト ON）。的以外を撃つ（V-0107）。
- 発端（V-0106）: フラワー単騎（`077`）では、バーストのヒットは I の発動（BURST バーの位置がチェーンの UI に替わったフレーム）の 11f 後（`077-23`。5 回とも）。ただし、その I の発動は満タンの 31〜32f 後（`077-22`）で、C-0073（満タン → I の発動 28〜30f。多人数の録画で、I のアイコンが II のアイコンに替わったフレームで読んだ）より 2f ほど遅い。モデルの I の発動は満タンの 29f 後（C-0073）なので、`077-23` の起点がモデルの発動と同じフレームかが決まっていない。
- モデルの I の発動は、チェーンの段が進むフレーム。多人数の録画では、C-0073 と同じく I のアイコンが II のアイコンに替わったフレームで読む（`063-03` の読み方）。I・II の段ではフルバーストの入りの止まり（C-0069）は無いので、動画のフレームの差がそのままモデルのフレームの遅れになる（`burstHitDelays` は `videoFrameOf` の差）。
- フラワーのバーストに、バースト使用時の効果は無い（`data/skills/304.json` の burst は `burstDamage` だけ）。だから効果の遅れは読まない。

## 予測（撮る前に書く）

読む前に書いた（2026-10-04）。予測ファイル（records/predictions/V-0133.json）は、いまのモデル（遅れ 0）の値だけを持つ。遅れの値の仮説は遅れの表の行で切り替わるので、ここに手で書く。`077-23`（11f）は仮説の出どころなので、比べる指標にしない（読み直しの規則。plan/skills-guide.md 2 節）。

| 仮説                                                                                  | `063`・`080` の「I → II のアイコン → フラワーのヒット」 | `134` の「チェーンの UI → ヒット」 | 表に入れる値         |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------- | ---------------------------------- | -------------------- |
| L1: チェーンの UI はモデルの I の発動と同じフレーム                                   | どの回も 11f（±1f）                                     | 11f（±1f）                         | ヒットの遅れ 11f     |
| L2: チェーンの UI はモデルの I の発動より 2〜3f 遅れて出る（`077-22` と C-0073 の差） | どの回も 13〜14f                                        | 11f（±1f）                         | ヒットの遅れ 13〜14f |
| H0: いまのモデル                                                                      | 0f                                                      | 0f                                 | —                    |

- **L1 を予想する**。単騎のチェーンの UI と、多人数の II のアイコンは、どちらも I の段が終わったことを示す同じ出来事の表示とみるため。満タン → I の発動の 2f の差（`077-22` と C-0073）は、満タン（バーが消えたフレーム）の側の読みの差とみる。
- 見分け方: L1 と L2 は、多人数の録画の値（11f か 13〜14f か）で分かれる。134 は `077-23` の再現（チェーンの UI の読み方が録画によらないか）。
- 合わせて、多人数の録画の満タン（バーが消えて I のアイコンに替わったフレーム）→ I の発動も読み、C-0073 の 28〜30f と比べる（記録だけ）。
- 外れたときの影響: どちらでも、フラワーのバーストの 1 ヒットの値（`077-01` ほか）はヒットの時点でバフが変わらないので変わらない見込み（フラワーの S1・S2 にバフは無い）。効くのは、ヒットがフルバーストの始まりや窓の境目をまたぐ編成だけ。回ごとに 2f 以上ばらつけば（どちらの仮説にも合わない）、表には入れず、何で決まるかを調べる。

## 読み方

1. HUD の総ダメージの増分（`hud.ts --mode jumps`。レシピ `hud-jumps` のキャッシュ）から、フラワーのバーストのヒットのフレームを取る。値は、単騎では `077-01`・`077-02` と同じ 1 ヒット、多人数ではバフの乗った大きな 1 ヒット。I の発動の後の 30f の中の、通常攻撃と違う値の増分を探す。080 ではユニのバーストのヒット（II の発動の後）と取り違えないよう、I・II の発動のフレームとの前後で分ける。
2. 右のバースト欄を切り出し（`still.ts --crop`）、1 フレームずつ並べて、満タン（BURST バーが消えて I のアイコンに替わる）と I の発動（I のアイコンが II のアイコンに替わる。134 はチェーンの UI に替わる）のフレームを読む。替わり目は、前のフレームと次のフレームの画で確かめる。
3. I の発動 → ヒットの差を、回ごとに観測値（`burstHitDelays`。`compare`）にする。満タン → I の発動は記録だけの観測値にする。
