# V-0425: 自動バーストで CT が律速のときの発動の遅れ（C-0258 の再現）

- 問い: 機構が確定した 3 人編成・オートバースト ON の新しい録画で、CT が律速の発動は CT の 0 から 0〜2f で、欄の新しい CT の秒はその 3〜4f 後に出るか
- 話題: バーストの段階とフルバースト
- 日付: 2026-10-11
- 状態: 調査中

## 条件

- C-0258（仮説）の再現。根拠は録画 018・019・021（エーテル・デルタ・III）の CT が律速の発動 13 回と CT の 0 どうしの間隔 8 個（V-0164）で、どれも読み方を合わせた録画。042 は仮説の出どころ。
- 編成はサクラ（I・CT 40 秒）・デルタ（II）・I-DOLL・サン（III。操作）。3 人とも機構が確定したキャラで、CT▼を持つキャラはいない。単騎では次の段のアイコンが読めないので 3 人編成が最小。3 人とも撃たせてゲージを早く溜め、CT を律速にする。
- backlog 2-33（既存の確定の点検で仮説にした結論）。2026-10-10〜11 の点検（plan/design-investigation-review.md 1.4.3 節）で、反復実測の再現が仮説・値・読み方を決めるのに使った録画（結論の `decidedOn`）の中にしか無かったので仮説にした。確定に戻すには、決めるのに使っていない録画の再現を足す。過去の録画の読み直しはしない（2026-10-11 のオーナーの決定）ので、新しく撮る。
- 新しい録画は 2026-10-08 のゲームの更新（plan/captures/index.md「ゲームの更新の境目」。境目は録画 344 / 345）の後になる。根拠の録画は更新の前なので、合わなかったときは結論の誤りか更新の影響かを、この録画だけでは分けられない（design-investigation-review.md 1.2 節）。そのときは係数で合わせず、更新の後と書いて残差として残す。
- 撮影は backlog 2-33 の 12 件でまとめて計画した（束ねた撮影の記号 A〜I は V-0416「次に撮るもの」の表）。
- 共通の条件: 的は灼熱タブの BigArms・3 分モード（range-3min）・スペック固定 ON・ゲージ表示は右。撮影プロトコル（plan/captures/index.md）のとおり、出撃画面と戦闘履歴（キャラ名）を写す。

## 予測

なし。見分け: 本当の遅れ 0〜2f（C-0258）と、旧の「4〜7f」（欄の表示で数えた遅れ）は、CT の 0 どうしの間隔の読み（±0.5f）で分けられる。1 本に CT が律速の発動が 3〜4 回、CT の 0 どうしの間隔が 2〜3 個。

## 読み方

1. `timer.ts --mode changes` で時計の傾きと止まりを読む。
2. 右のバースト欄を ffmpeg で 1 フレームずつ切り出して目で読み、CT の 0（最後に出た 1/100 秒の値 u とそのフレーム g から g + u ÷ 0.017）、新しい CT の秒（「40」）が出たフレーム、次の段のアイコンのフレームを取る（V-0164 と同じ。画像はコミットしない）。
3. 本当の遅れ = CT の 0 どうしの間隔 − あいだの止まり − その録画の時計の傾きで数えた 40 秒。
4. 判定の目安: 本当の遅れが 0〜2f（読みの幅 ±0.5f）で、欄の CT の秒が CT の 0 の 3〜4f 後に出れば再現。
