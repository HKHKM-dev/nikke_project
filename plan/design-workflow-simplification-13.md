## 2. 撮影待ちのブランチが古い決まり・道具のまま進む

**いま**

- スキルの定義や検証のセッションは、撮影の依頼を出してから撮影が届くまで、数日そのままになる（上の表の 7 本は 11-12 に作られ、11-13 の夜〜11-14 に作業を再開した）。
- その間に main の決まりと道具は変わる（11-12 の基から 11-14 までに、AGENTS.md・`.claude/`・`tools/`・手引きを変えた commit が 7 本。見直しの段を絞った #1135 もその 1 つ）。
- 再開したセッションは、作業コピーの古い AGENTS.md と古いフックのまま見直しまで進み、main を取り込むのは見直しの後の `pr:prep` が初めて。
- その結果:
  - フックが入っていない作業コピーで、見直しの後に止まった（#1148）。
  - 見直しの段を絞った後なのに、要らない `/simplify` を 5 本で回した（#1137・#1138・#1139・#1144・#1145）。`/simplify` は 1 回で裏のエージェント 4 本（1 本あたり約 8〜9 万トークン）と、直し・commit・テストの回し直し 1 回を使う。
- 決まりの文（AGENTS.md）は、セッションの始まりと再開のときに作業コピーから読み込まれる。作業コピーが古ければ、読み込まれる決まりも古い。

**案**

- セッションの始まり・再開（SessionStart）と、オーナーの発言（UserPromptSubmit）のフックで、次を満たすときにトピックブランチを origin/main へリベースする（`pr:prep` のリベースと生成物の衝突の扱いを使い、確認と push はしない）:
  - `claude/` のブランチにいて、作業ツリーに変更が無い。
  - origin/main に、ブランチの基より後の commit がある。
- 衝突したら、リベースをやめて元に戻し、「main を取り込めなかった（衝突）。`npm run pr:prep` で取り込む」と知らせる。
- 取り込んだときは、AGENTS.md・手引き・フックが変わったかをフックの出力に出す（例:「main を取り込んだ。AGENTS.md の『コミット手順』が変わった。読み直す」）。セッションの中の決まりの文は再開まで古いままなので、変わった節を読み直させる。
- 知らせるだけにする形（リベースはせず、「main に決まり・道具の変更が N 件。取り込んでから進める」と出す）もできる。

**効果**: 再開した作業が、いまの決まりとフックで進む。要らない見直しと、フックの無い作業コピーでの止まりが無くなる。見直しの前に main を取り込むので、`pr:prep` の衝突も早く見つかる。

**気をつけること**: リベースは push 済みのブランチの履歴を書き換えるので、次の push は強制になる（`pr:prep` は今もそうしている）。自動にすると、オーナーが手で何かしている途中でも動きうるので、作業ツリーに変更があるときは動かさない。

## 3. `/simplify` の要否をフックで見る

**いま**: 見直しの段を絞った決まりは文だけで、機械は見ていない。2 節の 5 本は古い決まりで動いていたが、決まりを読んでいても、規模の見積もりを誤れば同じことが起きる。

**案**

- PreToolUse（Skill の `simplify`）のフックで、ブランチの基（origin/main との merge-base）からの差分を見る。`packages/`・`apps/`・`tools/` の（テストを除く）新しいファイルが無く、追加が 100 行以下なら、呼び出しを止めて「構造が変わる PR ではない（AGENTS.md「コミット手順」の 1）。`/code-review` へ進む」と返す。
- 置き場所は見直しのフック（`tools/git/review-flow.ts`）に足す。止めた `/simplify` は印を付けない（PostToolUse が来ない）ので、止まりの判定は `/code-review` から始まる。
- ファイルの分割（移しただけで追加が多い差分）は、追加の行数で 100 行を超えるので通る。

**効果**: 要らない `/simplify`（2 節では 7 本中 5 本）が無くなる。

**気をつけること**: 行数の線は AGENTS.md の文と同じものを使う。線を変えるときは、文とフックの 2 か所を直す（フックのコメントで AGENTS.md の節を指す）。

## 4. 見たが案にしなかったもの

- **環境の Stop のフック（commit していない変更・push していない commit）**: 9 本のうち 5 本で、合わせて 8 回出た。どれも直後に commit・push して続けており、止まりにはなっていない。クラウドの環境のフックで、リポジトリでは変えられない。
- **裏の `pr:prep` を待つ間の応答の終わり（#1139）**: 終わった知らせで自動で再開していて、オーナーの手は要っていない。見直しのフックがある作業コピーなら、一度は止める。
- **PR の念のための確認（`send_later`）**: 確認の回数を減らせるかは、GitHub の知らせが届かなかった例を数えていないので、この回では扱わない。
