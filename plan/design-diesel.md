## 0. 範囲

ディーゼル（72。SSR・防御・エリシオン・風圧・MG・バースト II・CT 20 秒）の全スロット（S1・S2・バースト）を、基礎版と宝物版の両方で定義する。

- 宝物: おもちゃの汽車セット。解放の順は S2 → バースト → S1。オーナーのディーゼルは段階 3 で、3 つのスロットがどれも宝物版になる。宝物はスペック固定でも反映され、外せない（トーブと同じ。C-0986 の根拠のオーナーの回答）ので、撮れるのは宝物版だけ。
- 基礎版は、宝物版と同じ文の行を宝物版の録画で確かめる（トーブの基礎版と同じ扱い。C-0986。基礎版と宝物版の違いは S1 の 2〜3 行目・S2 の命中の回数と貫通ダメージ▲・バーストの挑発の形）。
- [skill-catalog.md](skill-catalog.md) 2 節の機械の読みでは語彙の残りは無いが、1 行ずつコードと照らすと、S2 の「フルスタック状態ならスタック解除後、味方全体に弾丸チャージ（宝物版は貫通ダメージ▲も）」が今の語彙で書けない。フルスタックの消費のきっかけ `{ fullStack }` を書けるのは回復（`heal`）と使用武器の変更（`weaponChange`）だけ（`skills/parse/trigger.ts`・`instant.ts`）。

## 2. 語彙

### 2.1 フルスタックの消費のきっかけを、弾丸チャージと timed に開く（論点 1）

- `{ fullStack: "<id>" }` を、`ammoRefill`（即時効果）と `timed` にも書けるようにする。意味は今と同じ: 持ち主（自分）のその状態の件がフルスタックになったフレーム f に発火し、その状態のスタックを全部外す（f + 1 で閉じる）。同じきっかけの効果がいくつあっても、消費は 1 回。
- 読み込みの検証（`validateFullStackTriggers`）は今のまま（同じ定義に、その状態を自分にスタックで付ける射撃の回数のきっかけの付与が要る）。
- 1 パス目だけが作るきっかけ（`FrameEvents.fullStacks`。流し直しの `replayEvents` では作らない）なので、timed は 1 パス目が件を登録する形で書ける（`{ coverHealed }` の timed と同じ。[design-skill-stage17.md](design-skill-stage17.md) 2.1 節）。1 パス目で窓を追う stat（攻撃力・射撃に効く stat など）を書けるかは、`{ coverHealed }` の timed と同じ決まりに従う。貫通ダメージ▲は 2 パス目だけが読む stat。
- 消費する状態の一覧（`skills/holders/sources.ts` の `consuming`）に、`{ fullStack }` の timed（今は stat `weapon` だけ）を足す。即時効果は今も全部を見ている。
- **弾丸チャージの量は、スタックを外した後の最大装弾数で数える**: 説明文の「スタック解除後」のとおり、`{ fullStack }` の弾丸チャージは f + 1（外れた後）の最大装弾数で量を出し、残弾はその最大装弾数で止める（射撃の回数のきっかけの弾丸チャージが f + 1 の最大装弾数で数えるのと同じ所で分ける。`frame/firstPass/instants.ts`）。ディーゼルの撮影では、外れる前の最大装弾数で数えても、f + 1 で 300 に削られて同じ残弾になることが多く、見分けられない見込み（V-0763 の予測）。
- 退化: 今の使い手（クラウンの S2 の回復・ラプラス：アルティメットヒーローの S1 の使用武器の変更）は変わらない。

### 2.2 足さないもの

- **S1 の 150 回の数え方の別の読み**: 「ヘイト状態の間の命中だけを数える」読み（グレイブの S2 の `during: { state }` の形）は、`stackChange` には書けない。定義は「命中は戦闘を通して数え、150 回目にヘイト状態なら足す」（今の回数のきっかけと条件の意味）で書き、撮影で見分ける（論点 3）。合わなければ、そのとき `stackChange` に `during: { state }` を開く。
- **スタック可能バフ効果のスタック量▲の、ほかの味方のスキルのスタック**: 未対応の notes（論点 3）。
- **最大HP のみ▲**: notes のまま。

## 3. 定義の案（`data/skills/72.json`）

1 節の表の「書き方」のとおり。基礎版は `skills`、宝物版は `treasureSkills` に、3 スロットとも書く。効果の順はスロットの説明文の順。`claims` は撮影の後に書く。

- S1 の基礎版は効果の無いスロット（`noEffect`）。
- 宝物版の S1 の `stackChange` は、宝物版の S2 の付与（段階 3 では必ず一緒に宝物版）に足す。`assumes` に「自分のイチゴキャンディの分だけ」「スタックが 0 の時も 1 段で付ける（確かめていない）」を書く。

## 6. リスク・留意点

- 撮影の編成は 2 体で、フルバーストが無い。S1 の防御力▲（フルバースト）は起きない（間接なので比べるものが無い）。
- ディーゼルを操作しない枠にする。操作キャラの枠アイコンの上には「残弾/最大」が出ないので、マガジンの途中の最大装弾数（スタックの数）は操作しない枠でしか読めない（[captures/guide.md](captures/guide.md)「残弾（操作キャラ）」・V-0435）。
- 射撃場の 3 分モードでは的の攻撃が当たる（C-0551）。宝物版 S1 の回復（被弾・ヘイトの間）は起きうるが、回復を受けた時の効果を持つ枠が編成に無いので、比べる値に効かない。

## 7. 論点（オーナーに決めてもらうこと）

1. **フルスタックのきっかけを弾丸チャージと timed に開く**（2.1 節）。推奨: 開く。弾丸チャージの量は外した後の最大装弾数で数える。
2. **基礎版も定義するか**（0 節）。推奨: 両方定義し、基礎版は宝物版と同じ文の行を宝物版の録画の結論で裏付ける（トーブの基礎版と同じ）。基礎版にしかない行（S1 のフルバースト中の被弾の回復・バーストの挑発）は、ダメージに効かない notes。
3. **宝物版 S1 のスタック量▲の読み**（1 節・2.2 節）。推奨: 自分のイチゴキャンディに足す分だけを効果にし、ほかの味方のスキルのスタック可能バフに足す分は未対応の notes。150 回は戦闘を通して数え、150 回目にヘイト状態なら足す読みで書き、撮影で「ヘイトの間だけ数える」読みと見分ける。スタックが 0 の時の扱い（モデルは 1 段で付ける）も撮影で見る。
4. **撮影の編成**（4 節）。推奨: I-DOLL・フラワー（I・操作）・ディーゼル（II）を 1 本。オートバースト ON。
