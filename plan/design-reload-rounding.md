# 全弾リロードの 1 回ごとの丸め（端数の持ち越しをやめるか）

- 何のための文書か: 全弾リロードの 1 回分のフレーム数を、いまの端数の持ち越し（C-0145 の model）から、録画の 1 回ずつの長さ（V-0680・V-0681）に合う形に変えるかを決める
- 関連: C-0145（リロードの秒はゲーム内の時計で進む）・C-0148（最終弾 → 次の 1 発目 = リロード + 24f）・C-0135（最終弾 → 込め終わり = リロード + 約 12f）・C-0149（射撃姿勢維持型のリロードに足す 11f）・C-0959（ハイド中のリロードの切り上げ）・C-0964（1.67 秒は 1 回ずつ同じ長さ）・C-0502（スキルの CT は 1 回ごとに ceil で数え直す）、V-0680・V-0681・V-0695、[design-weapon-seconds.md](design-weapon-seconds.md) 10.5 節（持ち越しを入れた経緯）、[design-hide-reload.md](design-hide-reload.md) 10・11 節、backlog の 2-58・2-61
- 起案: 2026-11-07
- 状態: 実装した（案 E。13 節、ラプラスの撃ち切りは案 F。16 節）

## 0. 要約

- 録画では、全弾リロードの最終弾 → 込め終わりが、どのリロードの秒でも 1 回ごとに同じ整数で、端数を持ち越していない（V-0681。C-0964 は 1.67 秒だけ）。
- 丸めは四捨五入でなく、⌈x + c⌉（x はリロードの秒 ÷ 0.017）の形に乗る。c は MG 以外で 10.76〜11.18f、MG で 11.71〜11.94f の幅に収まる。
- いまのモデルは、1 回分を ⌊x + 持ち越し⌋ にしていて、平均は x だが、1 回ずつは 0〜1f 違う。
- 案 A（推奨）: 1 回分を ⌈x + c − 12⌉ にし、持ち越しをやめる（込め終えてから 1 発目までの 24f はそのまま）。試しに当てると許容外は 60 → 74 件。8 件はヒットの指し先のずれで、7 件は時刻が動いた（4 節）。

## 1. いまのモデル

- `frame/shooter.ts` の `nextChunkFrames`: 全弾リロードの 1 回分は、端数つきの長さ（`FiringParams.reloadChunkFrames`。リロードの秒 ÷ 0.017 に、リロード速度と射撃姿勢維持型の 11f（C-0149）を入れた値）に、前の回の端数（`reloadCarry`。最初は 0.5）を足して切り捨て、残りを次へ持ち越す。
- 込め終えたら、1 発目まで 24f（`reloadFirstShotFrames`。C-0148）待つ。最終弾 → 1 発目は、平均で x + 24。
- 分割リロード（SG）の段は、切り上げて持ち越さない（C-0154）。ハイド中のリロードの 1 回分は ⌈x⌉ + 12f（C-0959・C-0841）。どちらもこの文書では変えない。

## 2. 録画で分かったこと（V-0680・V-0681）

- 最終弾（照準の残弾）→ 込め終わり（バーが消えたフレーム）は、どの録画でも 1 つの値に揃う（外れた回は、最終弾の読みが 1f ずれた形）。持ち越す形の 1f 違う回（秒の端数の割合で出る）は、どの秒でも見えない。

## 3. 案

- **案 A（推奨）**: 全弾リロードの 1 回分を ⌈x + c − 12⌉ にし、端数を持ち越さない（`reloadCarry` を消す）。c は武器モデルの値（MG 以外 11.06f・MG 11.8f。2 節の幅の中ほど。名前は実装で決める）。込め終えてから 1 発目までの 24f（C-0148）は変えない。
  - x はいまの `reloadChunkFrames`（リロード速度と射撃姿勢維持型の 11f を入れた値）のまま。
  - c の値は 2 節の幅の中ならどれでも、読んだ録画の整数は変わらない。幅の外の値（例えば MG と MG 以外で同じ c）では、どれかの録画と 1f 合わない。
- 案 B: 1 回分を ⌊x⌋ にする（武器種で分けない）。MG の 2 本は 1f 短い。試しに当てると許容外 78 件。
- 案 C: 四捨五入（⌊x + 0.5⌋）。1 回ずつの長さが 1 秒・2 秒で合わない。許容外 65 件。採らない。
- 案 D: いまのまま（持ち越し）。1 回ずつは 0〜1f 違うが、長い区間の平均（発の数・与ダメージ）は較正値と合っている。C-0964 と V-0681 の結論は、モデルが未反映のまま残る。

## 5. 確かめてから入れること・残る論点

1. RL の 1 回ずつの長さ（最終弾が HUD で取れない）。バーの値（0 の点 → 込め終わり）は SR と 0.2f の差（V-0057 の A-2）で、同じ c とみる。
2. MG の c: エマ（端数 0.06）は MG 以外の c でも合うので、MG の全部で違うかは 2 本（モダニア・ルドミラ：ウィンターオーナー）だけで決めている。
3. SMG 1 秒（ミサト）の 1f。回数が 2 回で、HUD の値（`0005-03`）も 71f。
4. ハイド中のリロード（⌈x⌉ + 12。C-0959）は、案 A の ⌈x + c − 12⌉ + 12 より、多くの秒で 1f 長い。窓の丸め（117 か 118f）と合わせて決めた値なので、ここでは変えない。
5. 射撃姿勢維持型（紅蓮BS）の 11f（C-0149）とリロード速度▲の中の長さは、いまの x のまま丸める。録画で 1 回ずつは確かめていない。

## 9. 読み足しで分かったこと（V-0681。2026-11-07）

8 節の判断の代わりに、オーナーの指示で読む録画を増やした（実装は止めたまま）。根拠と回ごとの値は V-0681 と、その観測値。

- 全弾リロードは、どの武器種・撃ち方でも 1 回ごとに同じ長さで、端数を持ち越さない（RL・射撃姿勢維持型・押下チャージ型を含む）。
- 込め終わりは、リロードの始まり（RELOADING のバーの伸びを長さ 0 に遡った点。端数つき）から ⌈始まり + x + c⌉。c は全部の武器種で 1 つの幅（V-0681「始まりのずれ」の節の 11.78〜11.95f）に入る。2 節の「MG とそれ以外で c を分ける」形（案 A）は、SMG 1 秒と AR 1 秒が同じ c で入らず、成り立たない。
- 武器種の違いは、始まりが最終弾のフレームからずれる量（ずれ）で出る:
  - チャージの無い武器（AR・SMG・SG）: 発射レートの蓄積（C-0058）の最終弾の余りから出る本当の発の時刻（最終弾のフレーム − 余り ÷ 1 フレームの蓄積）。MG（毎フレーム撃つ速さ）は約 0f。
  - 入力が UP のチャージ武器: 約 −1.1f（SR・RL、チャージ時間・リロードの秒によらない）。
  - 射撃姿勢維持型: 撃ってから ⌈S⌉ − H − 約 1.1f（紅蓮BS・A2・レイヴン）。撃ったフレームでなく、チャージが満ちた時点に結び付く（A2 で、撃つのが 1f 遅れた回もバーの始まりは同じ時点）。
  - チャージで撃つ押下チャージ型（アニス：スター・ネオン：ビジョン・アイ・リバーレリオ）: 約 0f。
  - 連射で撃ち切る押下チャージ型（ラプラス）: リロードの始まりは最後から 2 発目の約 1.5f 後に揃い、最終弾から数えると最後の間隔（2〜4f）で変わる。わけは分からない。
- 込め終わりから次のマガジンの 1 発目まで（照準の残弾。A2・レイヴンは着弾から）: チャージの無い武器 12f、入力が UP と押下チャージ型 ⌈チャージ⌉ + 12f、射撃姿勢維持型 ⌈チャージ⌉ + H + 11f（紅蓮BS 30f・レイヴン 約 86f・A2 約 94f）。
- 7 節の「RL の録画どうしで c が両立しない」は、ずれを最終弾のフレームの 1 つの値とみていたためで、撃ち方ごとのずれを入れると両立する。

## 10. 案 E（9 節を受けた案。3 節の案 B（⌊x⌋）とは別）

- **案 E（推奨）**: 全弾リロードの 1 回分（射手が込め終えるまで待つ整数）を、最終弾のフレームから ⌈x + c + ずれ⌉ − k にする。端数は持ち越さない。x はいまの `FiringParams.reloadChunkFrames`（リロード速度と、射撃姿勢維持型の 11f（C-0149）を入れた値）のまま。

| --- | --- | --- | --- |
| チャージの無い武器（AR・SMG・SG・MG） | 最終弾の発射レートの蓄積の余りから（毎フレーム撃つ速さでは 0） | 12 | リロード明けの 24f（C-0148）のうち、込め終わりの後の 12f |

- c は 11.9f（V-0681 の幅の中。幅の中ほどの 11.86f では、A2 の 1 回分が境目の 1f 下に出る）。ずれの −1.1f は録画の値（満ちてから撃つまでの 1f（`chargeFullToShotFrames`）に約 0.1f 足りない分は分からない）。新しく合わせる値は、この 2 つ。
- 射撃姿勢維持型は、ずれ（⌈S⌉ − H − 1.1）と込め終わり → 1 発目（⌈チャージ⌉ + H + 11）の ⌈S⌉ と H が、いまのモデルの発と発の間（⌈チャージ⌉ + ⌈S⌉ + 11）と打ち消し合い、入力が UP の式に 11f（C-0149）を足した形に一致する。C-0149 の 11f はそのまま使える。

- 未確定と注記して残すもの: 連射で撃ち切る押下チャージ型（ラプラス）は、チャージの無い武器と同じく蓄積の余りから出す（最後の間隔が 3〜4f の回は合わない）。

## 14. ラプラスの撃ち切りの読み直しで分かったこと（V-0695。2026-11-08）

backlog の 2-61。10 節で未確定と注記して残した、連射で撃ち切る押下チャージ型（ラプラス：アルティメットヒーローの変更後の武器）の読み直し。根拠と回ごとの値は V-0695 と、その観測値。

## 15. 決めてほしいこと（案 F）

- **案 F（推奨）**: 使用武器の変更の撃ち切りで起きる残弾数減少のリロードの始まりを、変更後の武器の最後の発のフレームから、その発の発射レートの蓄積の余りのぶん前にする（`reloadStartOffset` のチャージの無い武器の形を、変更後の武器の最後の発の射手の状態で出す。ずれは −1 − 余り ÷ 1 フレームの蓄積。ラプラスは 291.67f）。13 節の 1 フレーム前の固定の値を置き換え、ラプラスの未確定の注記（C-0984 の model・10 節）を外す。
  - 実装の形（案）: `frame/firstPass.ts` で、撃ち切りで変更を終える発のときに、変更後の武器の射手のずれを `reloadStartOffset` で出して枠ごとに持ち、残弾数減少の `drainAmmo` の startOffset に足す（数行）。
  - 試しに当てると、ラプラスの録画 12 本の比べる観測値の残差はどれも変わらない（整数の込め終わりは ⌈291.67 + 147.06 + 11.9⌉ = 451f で、いまと同じ。V-0695「モデルとの比べ」。コミットしていない）。撃ち切りの残弾数減少を持つのはいまラプラスだけで、ほかのキャラには効かない。
- **案 G**: いまのまま（1 フレーム前の固定の値）。コードのコメントと C-0984 の model の文を「リロードは蓄積の上の最後の発の時刻に結び付く。いまの値は整数で同じになる近似」に書き換える。
- 120 発目が 1f 遅れて出る回は、どちらの案でもモデルに入れない（分けるものが分からない。根拠の無い変更をしない）。最終弾のフレームを比べる観測値を作るときは、0〜1f の揺れを許容に入れる。
- 結論: V-0695 から、ラプラスの撃ち切りのリロードの始まりは蓄積の上の最後の発の時刻に結び付き、見える最終弾は 0〜1f 遅れる、という結論を起こす（比べる指標が無いので仮説の見込み）。

## 17. 指標を sim の射撃の列から読む（2026-11-08）

デイリーレビューの指摘（オーナーが直すと決めた）。13 節で指標 `reloadToNextShotAt` を周期（`computeCadence`）の式にしたが、周期は区間のバフで定常の 1 マガジンを作るので、案 E で 1 回ごとに 1f 揺れる長さ（マガジンの発数・窓・途中のバフで変わる最終弾の蓄積の余り）を 1 つの値にまとめていた（例: `0510-03` は sim の 1 本目（9 発）の後が 141f、15 発の後が 142f で、指標は 142）。フレームループの退行も拾えない。

- `reloadToNextShotAt`: 1 パス目の射撃の列から、最終弾が引数 `frame` の区間にあるリロードの回（最終弾 → 次のマガジンの 1 発目）を読む。録画の読みと同じく、狙えない窓とバーストの止まりに掛かる回は除く。引数 `n`（0 始まり）でその区間の n 回目、省略は回ごとの中央値（観測値の多くは区間の中の回の中央値）。区間に読める回が無ければ比べられない（定常の周期で埋めない）。
- `0510-03`・`0511-03` は「3 スタックの間の 1 本目のマガジン」の回なので `n: 0` にした（ほかの観測値は中央値のまま）。
- 分割リロードの枝（1 段の端数つきの長さ + 24f）は、sim の列を読むので無くなった（射手の段の数 + 1 段の切り上げの値になる）。いま分割リロードの武器でこの指標を使う観測値は無い。
- `reloadFramesAt`（端数つきの x を返していた。比べる観測値は無い）は、予測（V-0224・V-0262・V-0358）が語彙として指すので消さず、同じ回の最終弾 → 込め終わり（全弾リロードは ⌈ずれ + x + c⌉）にした。sim の最終弾 → 1 発目から、込め終わり → 1 発目（`cadence.ts` の `reloadCompleteToFirstShotFrames`）を引く。録画ではレシピ `reload-segments` の最終弾 → 完了と比べる。
- 残差: `0510-03`・`0511-03` が +1 → 0（どちらも許容内のまま）。ほかの比べる観測値は変わらない。
