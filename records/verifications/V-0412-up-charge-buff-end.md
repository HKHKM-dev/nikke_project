# V-0412: 入力が UP のチャージ武器は、チャージの途中でチャージ速度▲が切れると経過を持ち越すか（録画 303・304 の読み直し）

- 問い: 入力が UP の SR（ココア）は、ユニの S1 のチャージ速度▲がチャージの途中で切れるとき、前の発からの経過を持ち越して▲なしのチャージ時間まで待つか（C1）、撃った時点の待ちのまま撃つか（C0）
- 話題: 射撃（間隔・リロード・チャージ）
- 日付: 2026-10-10
- Stage: backlog 2-32
- 録画: `303`、`304`
- 結論: `C-0528`
- 状態: 完了

## 条件

**何を確かめるか**

- ▲の付き始め（速度が上がるとき）は、入力が UP の SR（C-0523）も RL（C-0526）も経過を持ち越す。押下チャージ型は▲の切れ目（速度が下がるとき）でも持ち越す（C-0380）。
- モデルは入力が UP のチャージ武器の▲の切れ目にも同じ規則（C1）を当てている（plan/design-charge-carryover.md の案 1-A）が、確かめていない。V-0410 の切れ目の判定は▲の長さを前提にし、誘導弾の飛ぶ時間（k）の幅もあって 4 回が見分けられず、1 回は C0 寄りだった。
- ここでは、▲の切れる時刻 E を画面で読み、着弾の遅れの無い SR（ココア）の発で見る。フルバースト開始時の▲はフルバーストと同じ 10 秒の窓に乗り、窓の終わりの直前の発まで付く（C-0459。ドレイクの攻撃力▲）。ユニの S1（160.json の skill1 の effects[0]）も同じきっかけ（フルバースト開始時）で 10 秒。

**編成**

- 録画 `303`・`304`（V-0263）: ノワール（271。III・SG）+ レイヴン（851。III・RL・射撃姿勢維持型）+ ユニ（160。II・RL・操作・撃たない）+ ココア（311。I・SR・入力 UP・1 秒）、オートバースト ON。射撃場・灼熱の BigArms・3 分モード・スペック固定 ON。
- **最小構成**: ココアの発の間隔に効く未確定の要素は無い。チャージ速度を変える効果は編成でユニの S1 だけ（定義で確かめた。レイヴンの S1 は攻撃力▲、ノワールの S2 は最大装弾数▲と弾丸チャージで、リロードを挟む間は数えない）。ノワールのバーストの命中率▲（C-0396・C-0442。仮説）は、当たるかとコアに当たるかに効くが、発の時刻に効かない。
- ココアは SR で着弾 = 発射なので、HUD の増分のフレームを発射のフレームとして読む（V-0410 の誘導弾の飛ぶ時間の幅が無い）。

**読み方の前提**

- I_base・I_b（ココアの▲なし・▲ありの発の間）は、同じ録画の窓の外・窓の中の、リロードを挟まない発の間の最も多い値で取る。モデルの値は 82f・77f（スペック固定の S1 は 8.97%）。
- E は画面中央上のフルバーストのタイマーが 00.00 になるフレーム（窓の終わり。C-0510 の読み方）。▲の切れ目はその ±3f の中とみる（C-0459 は発の単位で「窓の終わりの直前の発まで」で、1 フレームまでは決めていない）。

## 予測（撮る前に書く）

読む前に書いた（2026-10-10。手計算。コードを切り替える仮説なので予測ファイルは無い）。各フルバーストで、E を跨ぐココアの 2 発 F_a < E ≤ F_b（リロードを挟まない）の間 D = F_b − F_a を見る。

| 仮説                                              | D                                                        |
| ------------------------------------------------- | -------------------------------------------------------- |
| C0（撃った時点の待ちのまま）                      | I_b（F_a で▲ありの待ちを決め、途中で切れても縮めたまま） |
| C1（経過を持ち越す。いまのモデル。C-0380 と同じ） | I_base（切れた後は▲なしのチャージ時間まで待つ）          |

- 見分け方: E が F_a + 3 から F_b − 3 のあいだにある回だけ数える（E の ±3f の幅で、跨ぐ 2 発が入れ替わらない回）。I_base − I_b は 5f の見込みで、SR の着弾は発射と同じフレームなので、D は ±1f で読める。
- 予想: **C1**（C-0380 と同じ）。V-0410 の 080 の 2 回目のフラワー（C0 寄り）が気になるが、予想は変えない。
- 外れたときの影響: C0 なら、入力が UP のチャージ武器は「上がるときだけ持ち越す」形で、押下チャージ型（C-0380）と違う。モデルの `chargeElapsed` を、入力が UP の武器では速度が下がるときに使わない形に直す。1 回のフルバーストで、窓の終わりを跨ぐ 1 発が 5f 前後ずれるだけで、総ダメージへの効きは小さい。

## 読み方

1. E: 画面中央上のフルバーストのタイマーの欄を、窓の終わりの前後で 1 フレームずつ並べ、00.00 になったフレームを読む。III のタイマーの 00.00（窓の始まり）も同じく読んでおく（V-0410 と同じ）。
2. HUD の増分（`npm run records:read -- <録画 id> --recipe hud-jumps --source V-0412` のキャッシュ）から、ココアの発を 1 発の値の格子で分ける（ほかのキャラの増分と重なった増分は差し引く）。
3. 窓の外・中の発の間から I_base・I_b を出す。各フルバーストの F_a・F_b・E を観測値（記録）にする。

## 分かったこと・分からないこと

- **C-0528**: 入力が UP の SR（ココア）は、チャージの途中でチャージ速度▲（ユニの S1）が切れると、前の発からの経過を持ち越し、▲なしのチャージ時間まで待って撃つ（C1）。2 本の録画の 12 回で同じ。付き始め（C-0523・C-0526）と合わせて、入力が UP のチャージ武器は、速度が上がるときも下がるときも押下チャージ型（C-0380）と同じ規則。モデル（plan/design-charge-carryover.md の案 1-A）と合う。
- V-0410 の 080 の 2 回目のフラワー（C0 寄り）は、E を予測の幅で置いた読みで、誘導弾の飛ぶ時間の幅もあった。この録画の E は読み直していない。
- 分からないこと: ユニの S1 の▲が E の何 f 前後で切れるか（±3f の中）。入力が UP の RL の切れ目（V-0410 では見分けられない回が残った）。
- **最小構成**: ココアの発の間隔に効く未確定の要素は無い（条件の節）。
