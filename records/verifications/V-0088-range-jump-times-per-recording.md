# V-0088: 録画ごとの的のジャンプの時刻を入力で与えると、単騎の与ダメージの許容外は許容内に入るか

- 問い: 録画ごとの的のジャンプの時刻をモデルの入力で与えると、単騎 AUTO の与ダメージの許容外（`056-02`・`L-AN-01`）は許容内に入るか。多人数の録画 48〜50 の時刻は単騎の組（C-0064・C-0066・C-0068）から決められるか
- 話題: 敵・的・場面
- 日付: 2026-10-02
- Stage: V-0065「次の候補」の 2（的のジャンプの時刻が代表値 C-0057 のまま）
- 録画: `048`〜`050`、`056`、`072`、`L-AN`、`L-AD`
- 状態: 調査中
- 派生元: `V-0065`

## 条件

- 撮影はしない。既存の観測値（ジャンプの時刻・与ダメージ・区間ごとのヒット数）と、モデルで進める。録画 48〜50 を回すには実ビルド（メインのチェックアウトの `scratch/blablalink/builds-all.json`。リポジトリに入れない）が要るので、その部分はメインのチェックアウトで回す（V-0065 の CLI）。
- 比べる値は残差の一覧（plan/residuals.md）と同じ組み方（`compare.setup`: 敵 `range-bigarms-fire`・出来事 `range-3min-jump`・条件は自動・中遠の着地点は観測値のとおり）。許容は観測値の `tolerance`（与ダメージは ±2%）。
- **結論は、単騎（`056`・`L-AN`）からだけ作る**。録画 48〜50 は未確定の要素が複数混ざるので、時刻の決め方の確かめにとどめ、結論は作らない（AGENTS.md「事実と記録」）。

**いま分かっていること**

- モデルの的のジャンプは 1 組の代表値（C-0057。`data/enemies.json` の `range-3min-jump`、V-0009 の 5 本の中央値）。録画ごと・武器種ごとの違いはモデルの範囲外にしてある（C-0061・C-0064 は確定、C-0068 は仮説。C-0062 は棄却して C-0068 に置き換えた）。同じ条件でも 3 回目以降は揃わないことがある（C-0065 確定・C-0063 仮説）。
- V-0036（2026-09-29 の読み直し）で、`056-02`（クラウン・MG）と `L-AN-01`（エレグ・MG）は、録画ごとのジャンプの時刻（`056-07`・`056-08`、`L-AN-02`）でモデルを回すと許容内に入った。区間ごとのヒット数（`056-08`）とモデルの区間ごとの発の数も揃った。`L-AD-01`（ブラン・AR）は時刻を替えても広がり、ジャンプの時刻では説明がつかない。
- V-0036 は「出来事の代表値をその場でだけ書き換えて回した」ので、残差の一覧には反映されていない。残差の一覧では `056-02`・`L-AN-01` はいまも許容外（plan/residuals.md）。
- **録画ごとの窓を入力で与える経路は V-0086（2026-10-02）で入った**: 照合の `compare.setup.jumpWindows` に、録画で読んだ窓を持つ観測値（`use: input`。値は [始まり, 終わり, …] のゲーム内の秒。同じ録画のもの）の id を書くと、出来事のセットの狙えない窓（代表値）と着地点の区間の切れ目をそれで置き換える（`records/observations.ts`・`enemies.ts`）。予測ファイルの `setup`・`override` にも書ける。窓の読み方（終わりは着地の後の最初の発の構え 12f 前、始まりは終わりの 2 秒前とジャンプの前の最後の発の 1f 後の遅いほう）は V-0086 の「オーナーの決定の実施」。いま窓を付けてあるのは SG 単騎の 5 本（`074-27` など）だけで、`056`・`L-AN` にはまだ窓の観測値が無い。`sim-run.ts` には対応する引数が無い（録画 48〜50 を回すときに要る）。
- 録画 48〜50 の時刻: 録画 48 は 1・2・4 回目（`048-01`。HUD の停止で読んだ値で、フルバーストの入りの止まり C-0069〜C-0071 を含む）と 1・2 回目の画面の読み（`048-02`）。録画 49・50 は 1〜4 回目を HUD の停止（`049-03`・`050-01`）と残り時間（`049-05`・`050-03`。止まりを含まない）で、5 回目を残り時間（`049-04`・`050-02`）で読んである。どれも始まりだけで、窓の終わり（着地の後の最初の発）は読んでいない。
- 多人数でも 1・2 回目は単騎の組（RL・SMG／AR・MG／SG）のどれかの時刻になる（C-0066 確定。17 本）が、どの組になるかは編成では決まらず、同じ編成の 048 と 049・050 でも違った（V-0016）。単騎の組の時刻は `070-01`（RL・SMG）・`073-01`・`072-01`・`072-02`（AR・MG）・`074-01`（SG）。

1. `056`・`L-AN` の窓の観測値（`use: input`。V-0086 の読み方）を作る。始まりは `056-07`・`056-08`・`L-AN-02` の時刻、終わりは着地の後の最初の発（V-0036 の読み直しで使った `hud.ts --mode jumps` の列。観測値に無ければ録画のある環境で読む）。`056-02`・`L-AN-01` の `compare.setup.jumpWindows` に書き、`npm run records:check` で残差の一覧に出す（H0・H1）。予測ファイルにも H1 を足して固定し直す。
2. `056-08` の区間ごとのヒット数と、窓を与えたモデルの区間ごとの発の数を並べる。
3. 録画 48〜50 の時刻（`048-01`・`048-02`、`049-05`・`049-04`、`050-03`・`050-02`）を、単騎の 3 つの組の時刻（`070-01`・`073-01`・`074-01`）と回ごとに並べ、差を出す（H2a・H2b）。HUD の停止で読んだ値はフルバーストの入りの止まり（1 回あたり約 22f。C-0070）を含むので、残り時間で読んだ値（`049-05`・`050-03`）を優先する。録画 48 の 3 回目と、3 本の窓の終わりは未読なので、`tools/captures/hud.ts --mode jumps` と `timer.ts --mode changes` で読む（録画のある環境）。
4. 録画 48〜50 の窓を入力にして V-0065 の CLI で回し、V-0065 の表に列を足した新しい記録を作る（この記録では結論にしない）。`sim-run.ts` に窓を渡す引数（観測値の id か秒の列）が要る。

## 分かったこと・分からないこと

（起票時）

- 分かっていること: 上の「いま分かっていること」。入力の経路（`jumpWindows`）は V-0086 で入っているので、設計は要らない。
