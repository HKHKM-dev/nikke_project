- 根拠: V-0382（`077-45`・`134-08`・`223-03`・`081-22`）。C-0220（確定。満タン → I の替わり目と、替わり目 → フラワーのヒット）・C-0285（確定。満タン → 本当の発動）・C-0289（確定。発動の止まり 1 ティック）・C-0258（確定。次の段の表示は本当の発動の数 f 後）。参考に C-0499（仮説。クラウンの効果は替わり目より前に付く）

## 0. 要約

- I・II の遅れの定数（C-0219 ニヒリスター・C-0220 フラワー・C-0230 ユニ・C-0479 アドミ）は、右のバースト欄の六角形の替わり目から数えた値。モデルはこれを本当の発動（満タンから 23f。C-0285）に足しているので、満タンから数えたヒットが実機より 4〜5f 早い。V-0382 で、新しく読んだ 2 本（223・081）と後付けの 2 本（077・134）がどれもそうだった（いまのモデルで 4 件とも許容外）。
- 推す直し方（3.1 節の A）: 定数はそのまま、I・II の遅れを足す起点を「替わり目」（本当の発動の 5f 後。3.2 節）にする。チェーン・CT・フルバーストの窓は本当の発動のまま。
- 手元の試しで、許容外は **36 → 26**（減る 10・増える 0）。V-0382 の 4 件と、クラウンの効果の付き始め（`302-14`〜`302-22`）が許容内に入る。ほかの観測値は動かない（5 節）。

## 1. 時点の並び（I・II の発動）

| 時点                                 | 満タンからの動画のフレーム | 根拠・モデル                                                                                     |
| ------------------------------------ | -------------------------- | ------------------------------------------------------------------------------------------------ |
| 満タン（BURST バーが消えた発）       | 0                          | C-0083                                                                                           |
| 本当の発動（CT が走り出す）          | 23                         | C-0285。モデルの発動のフレーム（`BURST_READY_DELAY_FRAMES`）                                     |
| 発動の止まり（1 ティック）           | 本当の発動の 1〜3f 後      | C-0289。`ACTIVATION_STOP_VIDEO_FRAMES` = 1（動画のフレームの換算だけ）                           |
| 次の段の六角形の替わり目             | 29                         | C-0220（`134-05`）。C-0258（新しい CT の秒は本当の発動の約 2.7f 後、六角形はその 3f 後）とも合う |

- 替わり目は本当の発動の 6f 後（動画）で、そのうち 1f は発動の止まり。ゲーム内の時間では 5f。いまのモデルは、この 5f を抜いてヒットを置いている。
- 照合の指標 `burstHitDelays` は替わり目（モデルでは発動の止まりの後）からの差だけを比べるので、この差が見えなかった（design-activation-stall-video.md 3.5 節）。V-0382 で足した `gaugeFullToBurstHit` は、満タン（HUD の増分のフレーム）からヒット（同じ）までを比べ、替わり目の読みを通らない。
- II の替わり目は I の替わり目の約 29f 後（C-0285 の I → II。替わり目どうしで数えた）。V-0382 の II の 2 本（223・081）も、I の 1 本と同じだけ早かった。

## 2. 遅れの表に無い I・II のキャラ

- 遅れの表に無いキャラ（遅れ 0。未測定）のヒット・効果は、いまどおり本当の発動に置く（A でも変えない）。
- 裏付け: 測った I・II の効果の付き始めは、どれも替わり目より前だった。クラウン（II）は替わり目の 3〜6f 前（C-0499）、リター・クルミ・エマ：TU（I）は替わり目の 1〜2f 前の発に▲が乗る回がある（V-0370・V-0371・V-0376）。本当の発動は替わり目の 6f 前なので、「遅れの無い効果は本当の発動の頃に付く」と読める。A では、クラウンのモデルの効果（本当の発動）が替わり目の 5f 前になり、`302-14`〜`302-22` が許容内に入る（5 節）。
- C-0499 の文（「モデルは発動より前に効果を置けないので、遅れ 0 がいちばん近い」）は、A では「モデルの発動（本当の発動）は替わり目の 5f 前なので、遅れ 0 で合う」になる。`model` 欄だけを直し、状態は仮説（単独実測）のまま。

## 3. 論点（オーナーの判断）

### 3.1 直し方

| 案                                                    | 中身                                                                                                                                                                                                                                                                                                                                      | 試し（許容外。いま 36） |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| **A（推奨）: 定数はそのまま。起点を替わり目に揃える** | `burst/schedule.ts` に `HEXAGON_AFTER_ACTIVATION_FRAMES` = 5 と `hexagonFrameOf(a)`（I・II は `a.frame + 5`、III は `a.frame`）を足す。`withBurstDelays` は遅れを `hexagonFrameOf` に足す。替わり目を起点にする指標（`activationVideoFrameOf`・`burstEffectDelay`）も `hexagonFrameOf` から数える。`MEASURED_BURST_DELAYS` の値は変えない | 26                      |
| B: 定数を本当の発動から数え直す                       | I・II の行に 5 を足す（フラワー 14 → 19、ニヒリスター 9・9 → 14・14、ユニ 124 → 129、アドミ 19 → 24）。`burstHitDelays`・`burstEffectDelay` の起点も 5f 後にずらす                                                                                                                                                                        | 26（A と同じ）          |
| C: 直さない                                           | 結論の `model` に「絶対の時刻は 4〜5f 早い（未実装）」と書く                                                                                                                                                                                                                                                                              | 36                      |

- A を推す理由:
  1. 遅れの定数は動画で替わり目から読んだ値そのままで、これからほかのキャラの遅れを読むときも、読んだ値を表に書けばよい。B は表に書くたびに 5 を足すことになる。
  2. B は確定の結論 C-0219・C-0220・C-0230 の文（「替わり目から N f」）を訂正（棄却して置き換え）することになる。A は文を変えない（design-activation-stall-video.md 3.2 節の A と同じ考え方）。
  3. 「替わり目は本当の発動の 5f 後」を 1 か所（定数 1 つ）に置ける。III の起点（4 節）を同じ形で扱うときも、`hexagonFrameOf` に足せばよい。
- A でも B でも、チェーン・CT・フルバーストの窓・与ダメージの計算の順は変わらない（動くのは I・II の遅れの行のヒットと効果のフレームだけ）。

### 3.2 5f の値

- 5 = 満タン → 替わり目 29f（C-0220）− 満タン → 本当の発動 23f（C-0285。モデルの `BURST_READY_DELAY_FRAMES`）− 発動の止まり 1f（C-0289。`ACTIVATION_STOP_VIDEO_FRAMES`）。確定の結論とモデルの定数から出る値で、V-0382 の観測値に合わせた値ではない。
- V-0382 の 4 件の差は、5 なら 0〜+1、4 なら −1〜0 で、どちらも許容（±2f）の中。C-0285 の 23f は 22.6〜23.9f の幅を持つので、観測値からは 4 と 5 を分けられない。推奨は 5（合わせ込みをしない。モデルのほかの定数と同じ出どころ）。

### 3.3 結論

- 新しい結論（話題「バーストの段階とフルバースト」）: 「I・II の発動の次の段の六角形の替わり目は、本当の発動のゲーム内 5f 後（動画では発動の止まりを含めて 6f 後）。I・II の遅れの定数はそこから数えるので、遅れて出るヒットは満タンから I は 29f + 定数、II は 58f + 定数（動画のフレーム）」。根拠は V-0382 の観測値。値を決めた録画（134。C-0220）と別の録画（223・081）で再現し、予測を読む前に固定したので、道具の等級の候補は反復実測の見込み（077・134 は後付けで、根拠に数えない）。確定にするかは、道具の候補と最小構成の検査を見てから決める。
- C-0219・C-0220・C-0230・C-0479 の `model` 欄に、起点が `hexagonFrameOf`（本当の発動の 5f 後）であることを書く。文は変えない。
- C-0499 は 2 節のとおり `model` 欄だけ。

### 3.4 派生: III の起点（起票するか）

- III の遅れの定数（イサベル C-0165・ヘルム・ノワール・ラピ・ドレイク・クイーン・レイヴン・マナ・モダニア・ソルジャーE.G.・雪子）は、フルバーストのタイマーが 00.00 になるフレームから数えた値で、モデルはフルバーストの入り（III の本当の発動）に足している。00.00 が III の本当の発動の何 f 後かは確かめていない（C-0258 の「次の段の表示は本当の発動の数 f 後」が III でも同じなら、III の遅れも絶対の時刻がずれている）。
- この設計では III を変えない（`hexagonFrameOf` は III で発動のフレームを返す）。起票するか（backlog に 1 行足すか）を決めてほしい。推奨: 起票する（既存の録画で、満タンから III の遅れのヒットまでを読めば確かめられる。III のキャラの遅れが確定の結論で、ほかが機構の確定したキャラの録画を選ぶ）。

## 6. 実装（承認の後。3.1 節の A の場合）

1. `burst/schedule.ts`: `HEXAGON_AFTER_ACTIVATION_FRAMES` = 5（コメントに 3.2 節の出どころ）と `hexagonFrameOf` を足し、`activationVideoFrameOf` を `videoFrameOf(schedule, hexagonFrameOf(a))` にする。
2. `burst/landing.ts`: `withBurstDelays` の起点を `hexagonFrameOf(activation)` にする。冒頭のコメントと表の I・II の行のコメントに起点を書く。
3. `records/observations.ts`: `burstEffectDelay` を `effectFrameOf(a) − hexagonFrameOf(a)` にする。
4. 5 節の単体テストの期待値を直し、`hexagonFrameOf` のテストを足す。`SkillSection.tsx` の注記（4 節）。
5. `npm run records:check` で 5 節の動きを確かめ、`npm run records:minimal` で感度を計算し直す。
6. 3.3 節の結論を作り、`model` 欄を直す。V-0382 を閉じる。backlog 2-30 を消す（3.4 節を起票するなら 1 行足す）。この設計書の状態を「承認・実装済み」にする。

## 7. 決定と実装（2026-10-09）
