## 0. 範囲

遅れの表（`packages/core/src/burst/landing.ts` の `MEASURED_BURST_DELAYS`）の `effectFrames` は発動の印（I・II は六角形の替わり目、III はタイマーの 00.00。`hexagonFrameOf`）から数えるが、0 だけは印でなく本当の発動（印の 5f（I・II）・6f（III）前）で発火する（`withBurstDelays` が 0 の欄を書かず、`effectFrameOf` が発動のフレームを返す）。そのため「印ちょうど」は書けない。これを書けるようにするかを決める。

- ヒットの遅れ（`hitFrames`）の 0 の読み方（III は 00.00、I・II は本当の発動。`hitFrameOf`）は範囲の外。
- 遅れの表に行の無いキャラの効果を本当の発動に置くこと（[burst-effect-delay-candidates.md](burst-effect-delay-candidates.md) 2.7.2 節の案 C）は変えない。

## 1. いまの `effectFrames: 0` の行（調べた。2026-11-15）

表の 28 行（(a) 6・(b) 3・(c) 8・(e) 11）が `effectFrames: 0` を持つ。各行のキャラのバースト使用時の効果（trigger が `burstUse`・`{ count: burstUse }` の効果。`perBurstHit` の damage とバーストの倍率ダメージは除く）の付き始めを、結論で次のように分けた。

| 分類           | 意味                                     | 行（resourceId）                                                                                                                                                               |
| -------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| (a) 効果なし   | 発火を読む効果が無い（値は効かない）     | 304・160・300・71（`perBurstHit` だけ）・190（間接の notes だけ）・511（`perBurstHit` だけ）                                                                                   |
| (b) 未測定     | 効果はあるが、付き始めを測った結論が無い | 271（C-0226）・161・60（C-0678 は窓の中だけ）                                                                                                                                  |
| (c) 本当の発動 | 印より前の発・ヒットに▲が乗ると確かめた  | 352（C-0167）・834（C-1295）・10（C-0611・C-0513）・831（C-1065）・871（C-0614）・870 の攻撃力▲（C-0522）・103（C-0683。ヒットに乗る同じ発動の▲からの間接）・515（C-1251。同） |
| (d) 印         | 印より前に乗らず、印の後に乗ると確かめた | 870 の S2 の有利コードの攻撃ダメージ▲だけ（C-0522。行の 1 効果）                                                                                                               |
| (e) 両方を含む | 測った範囲が本当の発動と印の両方を含む   | 500（C-0691）・19（C-0742）・94（C-0807）・403（C-1011）・101（C-0420）・851（C-0421）・170（C-0923）・314（C-0581）・223（C-0938）・581（C-1051）・313（C-0679）              |

- **印として確かめた行は無い**。(d) は 870 の行の 2 つの効果のうち 1 つで、同じ行の攻撃力▲は (c)。表の 1 行は効果ごとに起点を分けられないので、どの案でも 870 の行は本当の発動のまま（C-0522 の `model` のとおり未反映。2.7.2 節の案 C）。
- (c) の行を印に動かすと、印より前の発に▲が乗った観測と矛盾する（834・871 は窓の終わりの側でも）。(e) の行には、本当の発動から数えた値で合わせた待ち（870・871 の 1more、103 の追加ダメージ、223 の武器の変更の delayFrames・待ち）を持つものがあり、印に動かすならそれらも同じだけ減らすことになる。

## 2. エレグ：ブーム・アンド・ショック（502）を 00.00 ちょうどにしたときの値（手元の試し）

502 の行を 00.00 ちょうどに置き（試しは比べる設定の `origin: 'activation'` で発動から 6f にした）、順番の攻撃の `delayFrames` を 5 から 6 にして 1 ヒット目を同じフレームに保ち、全部の観測値で `npm run records:residual` を回して、いまの形と比べた。

- 変わったのは録画 1217 の 2 つだけで、どちらも結論に結び付けていない観測値（命中の数え方が効く）:
  - `1217-08`（`counterAfterBursts`）: 2 回目の発動の後の幽霊キャプチャー数が 1 減り、許容内から許容外になる。
  - `1217-10`（`eventFrames` の `counterUp`）: 2 回目の発動の直後に、実測の列に無いキャプチャーの増加が 1 つ入り、許容内から許容外になる。
- 2 回目の発動では、キャプチャーの増加が 00.00 の頃に重なり、発火を 1f 前に動かすと減少との前後が入れ替わる。どちらの順が実機かは、この 2 つの観測値（結論にしていない）のほかに根拠が無い。
- 結論に結び付いた観測値（C-1312〜C-1315 ほか）の値は変わらない。

- 表を読む側への影響: `hitOffsets` はヒットの側だけなので、どの案でも変わらない。`sameActivationBuffsOnHit` の行は (c)・(e) で、どの案でも本当の発動のまま。窓の終わりを発動から数える行（`windowFromActivation`。260・100）は 0 でないので、どの案でも変わらない。
- 案 B・C の得: 印ちょうどを書けること。いま印として確かめた行は無く（1 節）、502 も 00.00 ちょうどと 1f の間を見分ける根拠が無い（2 節）ので、すぐに使う行は無い。
- 案 C は、0 の意味が `hitFrames`（III は 00.00）と `effectFrames` でそろう面があるが、`hitFrames` の 0 は I・II では本当の発動なので、そろうのは III だけ。

## 4. 推奨

**案 A**。理由:

1. 印ちょうどとして確かめた行が無い（1 節）。B・C は、使う行の無い書き方のために型と読む側を広げる。
2. 502 を 00.00 ちょうどにする根拠が無い。1f は読んだ範囲の中で、00.00 ちょうどにすると、結論にしていない 2 つの観測値が許容外になる（2 節）。AGENTS.md「根拠のない変更は行わない」。
3. 印ちょうどの行が要る結論が出たら、そのとき案 B の形で足せる（いまの行の意味を変えずに足せるので、先に入れておく得が無い）。

`landing.ts` の 502 の行の注記は、いまの形を述べていて直す所が無い。
