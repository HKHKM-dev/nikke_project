# V-0685: 戦闘力の算出の式

- 問い: キャラ一覧などに出る戦闘力は、育成のどの値からどの式で決まるか
- 話題: 育成・ステータス
- 結論: `C-0981`、`C-0982`
- 日付: 2026-11-07
- 状態: 完了

## 条件

- 型: 撮影なしの絞り込み（録画は撮らない）。育成データのスナップショット（`private/builds/` の 2026-09-24・10-06・10-24・10-29 の 4 回の取得）の戦闘力と、同じ取得の育成から出したモデルの値を突き合わせる。
- 戦闘力の実測: ShiftyPad（Blablalink）の GetUserCharacterDetails の `combat`（GetUserCharacters の `combat` と同じ値）と `arena_combat`。ゲーム内の画面の戦闘力と同じものかは、録画の頭に写った画面の値 1 件で確かめる（「結果」）。
- 式の出どころ: 外の資料（[references.md](../../plan/references.md)「戦闘力の式の解説」の nikke.gg）の式。係数（18・0.7・100・1.3・スキル Lv あたり 0.01／0.02）はこの資料のままで、取得の値に合わせて決めていない。資料に無い加算（OL・キューブ・コレクション・宝物）は、ゲームのデータの値をそのまま使う:
  - OL のオプションの行: ShiftyPad の `stateEffects` の `function_battlepower`（オプションの ID 700GGLL ごと）
  - キューブ: CDN の `/equip/<locale>/cube_<id>.json` の `powers`（キューブの Lv ごと）
  - コレクション（R・SR）と宝物: CDN の `/equip/<locale>/favorite_<id>.json` の `powers`（コレクションの Lv 0〜15 ごと。宝物は段階 1〜3 ごと）
- 攻撃力・HP・防御力: 取り込み（`toBuildSnapshot`）の育成入力を `computeCombatStat` に通した値（キャラ画面の表示値と同じ式。C-0744 の段階もここで決まる）。アリーナの戦闘力は、キューブをアリーナ用の欄（`arena_harmony_cube_tid`・`arena_harmony_cube_lv`）に替えて同じ計算をする。
- 会心率・会心ダメージは全キャラが 15%・150%（CDN の roledata の `critical_ratio`・`critical_damage`）。

## 予測

なし

## 読み方

- 式（K のスキル Lv の項は資料のまま。OL・キューブ・コレクションの項は資料に無いので、データの値を 1/10000 にして K に足すと置いた）:

  ```text
  戦闘力 = round(S × K / 100)
  S = (1 + 会心率 × (会心ダメージ − 1)) × 攻撃力 × 18 + (HP + 防御力 × 100) × 0.7
  K = 1.3 + 0.01 × (S1 の Lv + S2 の Lv) + 0.02 × バーストの Lv
        + (OL の各行の function_battlepower の和 + キューブの powers[Lv − 1] + コレクションの powers[Lv]) / 10000
  ```

  - 会心率・会心ダメージは CDN の素の値（OL・キューブ・コレクションの会心の効果は S に入れない）。攻撃力・HP・防御力はキャラ画面の値（バフ前）。
  - 宝物はコレクションの代わりに宝物の `powers`（段階によらず同じ値）を足す。
  - 浮動小数で S × K / 100 を出し、いちばん近い整数にする。整数だけで書けば S × (13000 + 100 × (S1 + S2) + 200 × バースト + 加算の和) / 1,000,000。

- 一致は、モデルの値を丸めた整数が取得の `combat`（`arena_combat`）と同じこと（差 0）で見る。

- 4 回の取得の全キャラで、`combat` と `arena_combat` がモデルの値の丸めと差 0 で一致した。丸めを切り捨て・切り上げにすると、半分ほどのキャラで 1 ずれる（四捨五入だけが全件に合う）。
- 段階を分けた確かめ:
  1. 装備・キューブ・コレクションの無いキャラ（スキル Lv 1/1/1）は、資料の式だけで差 0。スキル Lv を「Lv − 1」で数えると全員が約 3% 下に外れる（Lv のまま数える）。
  2. 残りのキャラで「取得の戦闘力 ÷ S × 100 − 1.3 − スキル Lv の項」を出すと、OL の行の `function_battlepower` の和 / 10000 を引いた残りが、キューブ・コレクションの組ごとに同じ値に揃った（キューブもコレクションも無いキャラは残り 0）。その値が、キューブの `powers[Lv − 1]`、コレクションの `powers[Lv]`、宝物の `powers`の和 / 10000 と一致した。キューブの `powers` は 16 種とも同じ表。
  3. 会心の OL の行（会心率・会心ダメージ）を持つキャラも、S を素の会心で出して差 0（OL の会心は `function_battlepower` の側にだけ入る）。T9・T9 の企業装備は、ステータスのほかに加算を持たない（T9 だけのキャラも差 0）。
  4. アリーナの戦闘力は、アリーナ用の欄のキューブで、ステータス（キューブの HP・攻撃力・防御力）と `powers` の両方を替えると差 0。欄が空ならキューブなしで差 0（ふだんの欄のキューブを使わない）。
- 宝物 Lv 0（V-0544 の、2026-10-06 までの Lv 0 のキャラ。09-24・10-06 の 2 回）だけは、取り込みの段階が未確定（`phase: null`）で `computeCombatStat` が宝物のステータスを足さないので、そのままでは外れる。宝物のステータス（`treasureStats`）と宝物の `powers`（1288）を足すと、本体・アリーナとも差 0 になった（宝物のステータスは Lv 0 でも乗る。plan/design-stage12.md 11.1 節と同じ）。
- OL の行の `function_battlepower`（取得に出たオプション × Lv の値）は、属性ダメージのほかは 69 × Lv、属性ダメージは 82.8 × Lv の四捨五入（Lv2 = 166、Lv15 = 1242）で、出た値は全部この規則に合った。9 オプション × Lv 1〜15 のうち、取得に出ていない組がある（「分からないこと」）。
- ゲーム内の画面との一致: 録画 0153・0156・0159（2026-10-03）の頭のミサト（833）の詳細の画面は、戦闘力 201,501・攻撃力 300,707（スキル Lv 1/1/1・キューブなし・装備なし。録画の台帳）。2026-10-06 の取得のミサトの育成（好感度・リサイクルルーム）を Lv 707（画面の Lv）にしてモデルに通すと、攻撃力 300,707、式の値 201,500.88 → 201,501 で、画面と同じ。ShiftyPad の `combat` は、画面の戦闘力と同じ式の値とみてよい。

## 分かったこと・分からないこと

- 分かったこと（C-0981）: 「読み方」の式で、戦闘力は 1 の位まで決まる。要るのは、キャラ画面の攻撃力・HP・防御力（モデルにある）、CDN の会心率・会心ダメージ、スキル 3 つの Lv、OL の各行の `function_battlepower`、キューブの `powers`、コレクション（宝物）の `powers` だけ。アウトポスト・企業タワーなど CDN に無い加算は戦闘力に入っていない（無くても全件が合う）。アリーナの戦闘力は、キューブだけをアリーナ用の欄に替えた同じ式。
- 分からないこと:
  - 会心の項の形: 全キャラが会心率 15%・会心ダメージ 150% なので、`(1 + 会心率 × (会心ダメージ − 1)) × 18`（= 19.35）を、攻撃力に掛かる 1 つの係数と見分けられない。素の会心が違うキャラが出たときに確かめる。
  - スキルの Lv のうち、取得に出ていないもの（Lv あたり一定の増え方は、取得に出た Lv で合っている）。
  - OL の `function_battlepower` の、取得に出ていないオプション × Lv の組（69 × Lv・82.8 × Lv の規則からの予想。C-0982）。キューブとコレクションの Lv のうち取得に出ていないものは、CDN の `powers` の表にあるが、戦闘力との一致は見ていない。
  - T9 より下の装備と、取得に出ていないレベルの範囲。どちらもステータス（攻撃力・HP・防御力）を通してだけ効くとみているが、確かめていない。
  - 丸めのちょうど .5 の扱い（偶数への丸めか四捨五入か）は、出ていないので見分けていない。
  - 編成（部隊）の戦闘力が各キャラの和かは見ていない（一覧の並び替えには要らない）。
