### 11.11 番号の道具（9 節の 7 の後半。2026-10-11）

- `npm run records:renumber -- <古い ID> <新しい ID> [--dry-run]` を足した（`packages/core/scripts/records-renumber.ts`。純粋な部分は `src/records/renumber.ts`）。検証記録・結論・観測値の番号を、ファイル名（検証記録と予測ファイル・結論のファイル。追跡しているものは `git mv`）と、作業ツリーの文書・データ・コードの中の参照ごと置き換える。観測値の根拠の書き方の範囲（「`<録画>-NN`〜`<録画>-MM`」）に古い ID が入っていれば、展開して置き換え、まとめ直す。V・C の範囲の書き方とバッククォートの無い観測値の範囲は、ID だけ置き換えて場所を出す（人が直す）。
- 新しい ID は、手元に無く、どのブランチも足したことが無く、どのファイルにも出てこない（範囲の中を含む）ものに限る。リベース・マージの途中では動かない（main と自分のブランチが同じ番号を足していると、どちらの参照か見分けられない）。AGENTS.md の PR の手順の 1 と design-stage20.md 3.6 節を、重なったらリベースを中止して自分のブランチで振り直す形に直した。
- 対応（古い ID → 新しい ID）は道具が出す。ファイルには残さず、commit の文に書く（振り直すのは、たいてい main に入る前の番号なので）。
- テストの例の ID は、実在の番号と重ならない 9 千番台にした（道具はコードの中の ID も置き換えるので、実在の番号を例に使うと、その番号を振り直したときにテストまで書き換わる）。コードの中を置き換えたときは、道具が `npm test` で確かめるよう出す。
- 番号の回避: 空き番号の見方を、main を含むすべてのブランチの歴史に広げた（`records-data.ts` の `idsInBranches`。元は main に無い commit だけを見ていて、main より古いブランチでは、main が後から足した番号が見えなかった）。`records:read`（観測値の空き番号）と `intake.ts`（`--id` の録画の番号。使われていれば次の空き番号を出して止まる）にも入れた。
- 録画の番号の振り直しは扱わなかった（E: と Google Drive の動画のファイル名と、観測値の ID の頭も変わる）。backlog 5-4 に残した。
- 設計書が大きさの目安（50KB）を超えたので、11 節と経過をこのファイルに移した（元の文書には 1 行のポインタを残した）。
- 確かめ: 一時的な作業ツリーで、検証記録・結論・観測値を 1 件ずつ実際に振り直し（観測値は根拠の範囲の中のもの）、`records:check`・`npm test`・`format:check` が通ることを見た。手元の記録は書き換えていない。
