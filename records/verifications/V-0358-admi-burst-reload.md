## 条件

**なぜ確かめるか**

- 最小構成の検査の束 4（根拠の無い効果。[plan/design-minimal-relevance.md](../../plan/design-minimal-relevance.md) 11 節）。アドミの burst の effects[0]（味方全体のリロード速度▲）に根拠の結論が無く、[plan/minimal.md](../../plan/minimal.md) で録画 040・042・043 を根拠にする確定の結論の警告に残っている。片付け方は backlog 5-2 と同じく、最小構成の録画の読み直しか撮影で結論を作る（[plan/design-skill-claims-5-2.md](../../plan/design-skill-claims-5-2.md)）。
- burst の effects[1]（味方全体のクリティカルダメージ▲）も根拠なしだが、最小構成の検査の警告には出ていないので、この記録の対象にしない（「分かったこと・分からないこと」）。

**説明文**（`data/characters/172.json`）: バースト「味方全体に リロード速度 {値 1}%▲（{値 2} 秒）・クリティカルダメージ {値 3}%▲（{値 4} 秒）」（Lv10 で 50.91%・10 秒）。定義は `data/skills/172.json` の burst の effects[0]（`target: allies`・`trigger: burstUse`）。機構の結論: リロード速度▲の効き方は C-0013（時間 × (1 − Σ速度)）、チャージの無い武器の最終弾から次のマガジンの 1 発目までは C-0148、RELOADING のバーの長さは C-0135。

**録画 042 を選んだ理由（最小構成か）**

- 042 は I-DOLL・フラワー（I・AI）+ アドミ（II・AI）+ アリス（III・操作）+ I-DOLL・サン（III・AI）。射撃場・灼熱の BigArms・3 分モード・スペック固定 ON（台帳）。II はアドミだけなので、どのフルバーストでもアドミがバーストを使う（モデル）。
- 見るのは**サン（AR・60 発）のマガジンの最終弾から次のマガジンの 1 発目まで**の長さ。フラワーとサンは機構が確定したキャラ。未確定の要素はアドミとアリスに残るが、サンのリロードの長さに効きうるのはアドミの effects[0] だけ:
  - アリスの S1（チャージ速度▲・チャージダメージ▲。対象は最終攻撃力の上位 2 機で、モデルではアリスとアドミ）とバースト（自分のチャージ速度▲・攻撃力▲）は、AR のリロードの長さを変えない。skill2 の notes[1]（回復）も変えない。
  - アドミの burst の effects[1]（クリティカルダメージ▲）と skill1 の notes[0]（被弾 20 回でのチャージダメージ倍率▲。3 分モードでは的が反撃するので起きうる）も、射撃の時刻を変えない。
  - ほかの効きうる▲: サンのバーストの最大装弾数▲（C-0364）でサンが III の回はリロードしないので、サンのリロードを読めるのは、アリスが III の回の窓の中と、窓の外だけ（予測ファイルの note）。
  - 最小構成の検査がこの組に警告を出すか（感度で外れるか）は、観測値を足した後の `records:check` で見る。出たら、効かない理由（上）を印にするかをオーナーに諮る。
- ほかの録画を使わない理由:
  - 040（アドミ + ユニ + ラム（操作）+ クイーン（真））: 窓の中と外のラムのリロードは、凍結の記録（plan/verification.md の Stage 10「録画 40」）で読まれ、リロード速度▲の式（C-0013）の出どころになった。同じ値を比べれば後付けになる。クイーン（真）の仮説（C-0270・C-0361）も混ざる。
  - 043（フラワー + クラウン + アリス + マナ + アドミ）: II にクラウンもいて、クラウンの S1 の味方全体のリロード速度▲（C-0394）の窓がアドミの窓と重なる回がある。マナの根拠なしの効果も混ざる。
- 042 で既に読んだ値（`042-01`〜`042-10`。予測ファイルの `predicted.seen`）は、的のジャンプ・フルバーストの入りの止まり・CT・ゲージの時刻で、リロードの長さではない。凍結の記録の「録画 42」で読んだのは、アリス・アドミ・フラワーの発の間隔とアリスの 1 発で、サンの発とアリスの RELOADING のバーは読んでいない。

## 予測（撮る前に書く）

- 読み直し（比べる値を読む前に予測を commit する）。予測ファイル: records/predictions/V-0358.json（H1・H2）。数値はそちら。

| 仮説                       | サンのリロード（窓の中）          | 見え方                                                                                                                                      |
| -------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| H1: いまの定義（味方全体） | 窓の外より短い（`sun-reload-in`） | 窓の中のサンの「最終弾 → 次の 1 発目」が `sun-reload-in`、窓の外（最初のバーストの前・窓が切れた後）が `sun-reload-out`・`sun-reload-after` |
| H2: アドミ自身にだけ付く   | 窓の外と同じ                      | 窓の中も外も `sun-reload-out` と同じ                                                                                                        |

- 見分け方: H1 と H2 の窓の中の差はリロードの長さの約 4 割（予測ファイル）で、1 回のリロードでも分かれる。値は説明文の値と機構の結論（C-0013・C-0148）だけで決まり、合わせ込みの定数は無い。
- 判定の目安: 窓の中のリロードの中央値が `sun-reload-in` と ±3f（V-0262 のサンの窓の中の散らばり。`302-13`）で合い、窓の外の中央値が `sun-reload-out` と ±3f で合えば H1。窓の秒数（10 秒）は、窓の終わりの後のリロードが `sun-reload-after` に戻るかで見る。
- 補助: アリス（操作・SR）の RELOADING のバー（最終弾 → 完了）は、モデルのリロードの長さに約 11〜13f を足した長さ（C-0135）なので、窓の中と外の**差**を `alice-reload-out` − `alice-reload-in` と比べる（H2 では差が 0）。アリスのチャージ速度▲（未確定）はバーの長さに効かない。
- 外れたときの影響: H2 なら、アドミを含む編成の味方のリロードが窓の中で短くなりすぎ、射撃の数が多めに出る（定義の対象を直す）。値か秒数が違うなら、定義の `ref` の読みを直す。

## 読み方

1. 録画 042 を Drive から取り寄せる（[plan/captures/index.md](../../plan/captures/index.md)「クラウド環境での取り寄せ」）。
2. HUD の総ダメージの増分を、直した hud.ts（V-0327）で読む（`npm run records:read -- 042 --recipe hud-jumps --source V-0358 --write`）。サンの 1 発は SR・RL の増分より 1 桁以上小さいので値で分ける（V-0262 の `302-13` と同じ読み方）。前の空きから 50〜60 発の後の空きを、マガジンの最終弾 → 次のマガジンの 1 発目とする。
3. アドミのバーストの発動のフレームを、右のバースト欄（II の六角形の替わり目。[plan/captures/guide.md](../../plan/captures/guide.md)「バーストの段の切り替わり」）で読み、窓はそこからゲーム内の 10 秒（フルバーストの入りの止まりを足す）とする。III がアリスかサンかもバースト欄の顔で確かめる。
4. 空きを、窓の中・窓の外に分ける。フルバーストの入りの止まり・的のジャンプ・窓の境にかかる空きは除く。窓の中・外のそれぞれの中央値を観測値にし、`compare` の `metric`・`args`・`setup` を予測ファイルの指標と同じにする（許容 ±3f）。
5. 補助: アリスの RELOADING のバーを `--recipe reload-segments` で読み、窓の中と外のバーの長さの中央値の差を、`use: record` の観測値にする（`alice-reload-*` の差と本文で比べる）。
