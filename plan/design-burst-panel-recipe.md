## Context

右のバースト欄の表示の時刻（I・II の六角形の替わり目、III のタイマーの 00.00、顔の CT の秒が消えたフレーム）は、遅れて出るヒットの起点（C-0503・C-0516）や段どうしの間隔（C-0285・C-0512・C-0515）の読みに繰り返し使っている。どれも ffmpeg で欄を切り出し、1 フレームずつ並べた一覧を目で読んだもので、道具が無い（design-investigation-review.md 5 節）。これを `npm run records:read` のレシピにする。

## 1. 欄の見え方（試作で確かめたこと）

1920×1080 の録画で、欄を 1740,400 から 180×180 で切り出して見た（一覧を目で見たのは録画 0022・0039・0042・0077・0222・0248 など。画素の特徴は 5 節の 34 本の全編）。

- **六角形**（x 1754〜1779・y 428〜451 の平均の色）: I は緑、II は橙か黄、III は赤。段が替わると、新しい六角形はしばらく白く光る（彩度が落ちる）。光りは替わり目の前にも後にも掛かり、新しい色が出るのが替わり目の 25f ほど後の回もある（077 の 2〜5 回目。替わり目では緑が消えて白い「II」の字だけが出る）。手読みの替わり目（`0077-28`・`0164-41` の「緑の終わり」・`0042-31` など）は、どれも**前の段の色が終わった次のフレーム**。暗い場面では緑の明るさが 150 を切る（022 の 9 回目）。
- **00.00**: III のタイマーが 00.00 になったフレームから、六角形が消え、バーの行（y 438〜446）が紫になる（`0038-22` の読み方の「FULL BURST!」の表示と同じフレーム）。直後に画面全体が暗くなって紫が一度消え、「FULL BURST!」の表示が消えると戻る。フルバースト中は背景の橙を II・III の色と取り違える。
- **CT の明け**: 顔の枠（x 1785〜1884・y 465〜554。段の候補の 1 人目）は、CT 中は暗い幕の上に白い秒の字が出る。明けたフレームで字が消えて幕が取れ、白以外の画素の平均の明るさが 1.3〜1.8 倍に上がる（ドレイク 63 → 93、クイーン（真）23 → 37 など）。C-0512 の「顔の CT の秒の表示が消えたフレーム」と同じフレーム。
- **CT の明けと取り違える動き**（試作で画を見て分けた）: 段の待ちが切れて（段のタイマーが 00.00）顔が秒を残したまま右へ滑り出す（明るさが 2 フレーム続けて上がる。六角形も同時に消える）、次の段の顔が滑り込む（前のフレームで暗くなったばかり）、替わり目で顔が入れ替わる（白い髪の顔は白の画素が多く、秒の字と区別できない）、戦闘の終わりに欄が消える。どれも六角形の分類の切り替わりと同じか 1 フレーム後に来る。ほかに、場面の色が変わって秒の字が白でなくなる回と、欄が光で隠れる回があった（5 節）。

## 2. 読み方

2 段にする（既存のレシピと同じく、録画を読む所と純粋な関数を分ける）。

1. **フレームごとの特徴**（キャッシュ `burst-panel@1`。`derived/<録画 id>/burst-panel@1.tsv`）: ffmpeg で欄を全フレーム切り出し、六角形の平均の色（R・G・B）、バーの行の紫の画素の数、顔の枠の白の画素（min(R,G,B) > 215）の数と白以外の画素の平均の明るさを出す。1 本 20〜60 秒。
2. **事象**（純粋な関数 `recipes/burst-panel-lib.ts`）:
   - フレームの分類: 紫の画素が 100 以上ならフルバースト。そうでなく、六角形の色の最大が 120 以上・彩度（最大 − 最小）が 75 以上なら、色相で I（90〜160°）・II（25〜70°）・III（25° 未満か 330° 超）。ほかは「読めない」（白い光り・欄が隠れた・バーの表示）。前後と違う 1 フレームだけの色は読めないにする。
   - 段の順: I → II → III → フルバーストの順にだけ進む。フルバーストの後は、次の I の緑が出るまで II・III の色を読まない。
   - 段の替わり目: I の段で I の後に II、II の段で II の後に III が来たら（間の読めないフレームは 40f まで）、前の段の色の最後のフレームの次を替わり目にする。
   - 00.00: III の段で、III の次に初めてフルバーストになったフレーム。
   - CT の明け: 顔の枠の白以外の明るさが前のフレームより 8 以上かつ 1.25 倍以上上がり、前の 2 フレームとも白の画素が 300 以上（秒の字がある）のフレーム。1 節の取り違えを除く: 前後のフレームも上がる、前のフレームの明るさがその前の 0.8 倍未満、替わり目の前後 2f、六角形の分類がそのフレームか前のフレームで切り替わった。そのフレームの段（替わり目からは次の段）で I・II・III に分け、段の外（最初の I の緑の前）は捨てる。
3. **観測値**（`kind: timing`・`use: record`・`unit: f`。値はフレームの列）: I → II の替わり目、II → III の替わり目、00.00、I・II・III の段の CT の明け。事象の無い件（単騎の録画の II → III など）は出さない。替わり目の note に、新しい色が出るまでの読めないフレームの長さ（白い光り）を書く。CT の明けの値は、その段の表示の事象（I は I → II、II は II → III、III は 00.00）の 15f 前までにある候補（CT が律速の発動の明け）だけにし、ほかの候補（ゲージを待つ間の明けなど）は note にフレームを並べる（6 節の 2）。
4. `--opt` は持たない。欄を左に出した録画には使わない（3 節）。

## 3. 範囲の外

- **新しい CT の秒（「40」など）が出たフレーム**（`0192-16`・`0222-21` などの N）: 顔が右へ滑り出す途中に出るので、顔の枠の明るさでは取れない（試作で 4 本とも取れなかった）。backlog 5-6 の 3 つに入っていない。要るなら字の形で探す別の版にする。
- **I の段の始まり（BURST バーが消えたフレーム）**: `gauge.ts` で読む（C-0083）。
- **候補が 2 人の段の 2 人目の顔**: 枠の位置が下にずれる。読むのは 1 人目の枠だけ。
- **欄を左に出した録画**（367・368。guide.md「バーストの欄の左右」）: 位置が違う。
- **画面中央上のフルバーストのタイマーの 00.00（窓の終わり）**: 欄の外。

## 4. 確かめ方

- 単体テスト（`recipes/__tests__/burst-panel-lib.test.ts`）: 合成の特徴の行で、分類・替わり目（白い光りを挟む回・新しい色が遅れて出る回）・00.00（フルバースト中の紫の途切れと背景の橙）・CT の明け（取り違えの 4 つの形）を確かめる。録画は要らない。
- 既存の録画: 手読みの観測値のある録画をレシピで読み、手読みの値と比べる。比べは検証記録 V-0447 に書いた（6 節の 3）。

## 5. 試作での比べ（2026-10-17）

手読みの観測値のうち、表示の時刻をフレームで書いたもの 49 件（34 本）を、試作（2 節の読み方）と比べた。比べた ID と、承認の後のレシピ（版 1）での差は V-0447。

- 00.00（25 件）・I → II（9 件）・II → III（4 件）・CT の明け（11 件）の手読みのフレーム 198 個のうち、197 個が 0f の差で同じ。違ったのは `0042-03` の 1 回目の 00.00 だけ（手読み f1365、レシピ f1366）。still.ts で切り出すと f1365 は 09.52、f1366 が 00.00 で、レシピが合っている（`0042-31` の読み方と V-0358 の「FULL BURST!」の f1366 とも同じ）。6 節の 4。承認の後のレシピ（版 1）では、このほか `0039-18` のゲージ待ちの CT の明け（f3524）が値に入らず note に出る（6 節の 2）。
- 試作の途中で見つけて直したもの: 022 の 9 回目の I → II（暗い緑で 1f 早く切れた。明るさの下限を 150 → 120）、224 のクイーン（真）の CT の明け（暗い顔で上がりが 13。上がりの下限を 15 → 8）、フルバースト中の II → III の取り違え（段の順を足した）。
- CT の明けの候補（1 節の取り違えを除いた後）: 段の表示の事象（I は I → II、II は II → III、III は 00.00）の 15f 前までにあるものは、事象までの長さが I 6〜7f（1 個だけ 11f）、II 5〜10f、III 6〜8f にそろう。画で見た揺れの大きい候補は本物だった。事象の前にない候補（ゲージを待つ間の明けなど）は 16 個あり、画で見て本物 13 個・偽物 3 個（場面の色の変化 2・欄が光で隠れた 1）。

## 6. 決めたこと（2026-10-17。どれも推奨どおり）

1. **読む事象**: (a) backlog 5-6 の 3 つ（替わり目・00.00・CT の明け） / (b) 新しい CT の秒（N）と I の段の始まりも足す。**推奨は (a)**。N は今の特徴では取れず（3 節）、I の段の始まりは `gauge.ts` がある。
2. **CT の明けの出し方**: (a) 候補を全部、段ごとの値に入れる / (b) 値は段の表示の事象の 15f 前までにある候補（CT が律速の発動の明け）だけにし、ほかの候補（ゲージ待ちの明けなど）は note にフレームを並べる / (c) (b) の値だけを出し、ほかは出さない。**推奨は (b)**。手読みの CT の明け 36 個のうち 35 個は (b) の値に入る（入らないのは `0039-18` のゲージ待ちの f3524。note には出る）。ほかの候補には偽物が混ざる（5 節）ので値には入れず、使うときは画で確かめる。
3. **照合の記録**: (a) 新しい検証記録（探索）に、比べた手読みの観測値の ID と差を書く。レシピの値は観測値に書き込まない（`near-landing` の前例。design-records-automation-log.md 8.7 節） / (b) レシピの値を観測値に書き込み、手読みの値と並べる。**推奨は (a)**。同じ値を 2 つ持たない。
4. **`0042-03` の 1f の差**: (a) この PR の検証記録で訂正する（レシピで f1366 を読んだ観測値を足し、`0042-03` に invalid を付け、C-0071 と C-0069 の根拠の ID を付け替える。結論の文は変わらない） / (b) backlog に起票して別に行う / (c) 訂正しない。**推奨は (a)**。design-records-automation.md 7 節の 6 の (a) の手順で、見ている事象（止まりの区間）と同じ録画・同じ読み直しの範囲に収まる。
