- 関連: [design-stage1-2.md](design-stage1-2.md)、[roadmap.md](roadmap.md)
- 目的: 計算値と実測値の突き合わせ結果と、そこから較正した定数を記録する。
- 方針（2026-09-22 決定）: 「90 秒の総ダメージ」で合わせるのはやめ、式の要素ごとに実測しやすい量で検証する。
  - 攻撃力は Blablalink（ShiftyPad）の表示値を正とする。ゲーム内表示は上乗せ分があるので絶対値では比較しない。
  - ダメージ式は射撃場の 1 ヒット数値で検証する。時間や距離のブレ、スキルの影響を受けにくい。

## Stage 2-A: ダメージ式（1 ヒットの実測）

射撃場で通常攻撃 1 ヒットの表示値を読む。敵は雑魚（防御 100）とし、属性相性なし・距離ボーナスは適正距離で撃つ（RL は距離ボーナスなし）。バーストは撃たない。通常攻撃に影響するスキル（自己バフ・攻撃ダメージ増加・弾数変化）を持たないキャラを選ぶ。

期待値の式（1 ヒット、期待値ではなく実値）:

```
基礎     = 攻撃力（ゲーム内表示の実攻撃力。ここは上乗せ込みの値をそのまま使う） − 100
1 ヒット = 基礎 × 武器倍率（SG は 1 ペレット分 = damage / shotCount）
           × (1 + コア命中なら (coreDamageRate − 1) + 会心なら (crit.damage − 1) + 距離ボーナスなら 0.3)
           × 属性有利なら 1.1
           （小数点以下は四捨五入。SR/RL はさらに × fullChargeDamage）
```

### 測定条件（2-A 共通）

- 場所: 射撃場。敵は雑魚（防御 100）。敵の属性と「コアの有無」を記録する（コアが無い的ならコア列は空欄）。
- 編成: 測定するニケ 1 体だけを出撃させる（味方バフの混入を防ぐ）。バーストは撃たない（自動バースト OFF）。
- 位置: 移動せず初期位置で撃つ。適正距離かどうかは、1 発の値が 1.3 倍違うかで判別できるので、判別結果を記録する。
- 撃つ弾: 戦闘開始直後の最初のマガジンだけ読む（「通常攻撃 N 回で自己バフ」型のスキルが乗る前）。SR/RL はフルチャージのみ。SG は 1 ペレットの値。
- 記録する値: そのニケの部隊画面の攻撃力（コンソール・装備込みの表示値そのまま）と、1 ヒットの 4 パターン。会心は 15% なので同条件の中で大きい方が会心。
- スキル 1・2 が通常攻撃の 1 発の値に影響しないキャラを使う（`packages/core/data` のスキル説明文から抽出。持っているものを優先）:

結論:

- 倍率グループの構造（1 + コア 1.0 + 会心 0.5 + 距離 0.3 の加算、チャージ倍率と武器倍率の乗算）は 6 武器種で一致した。
- 「戦闘中の攻撃力（逆算値）」と「Lv400 無凸の計算値」の関係を、当初は「一律 ×1.12365 の乗算係数」と解釈していたが、**2026-09-23 に誤りと判明**。正しくは後述のとおり「装備・好感度はいずれも割合ではなく固定値の加算」であり、キャラごとに基礎攻撃力が異なるため一律の乗算係数では説明できない（SR を 2 凸として再計算したことで偶然 ×1.12365 に近い値が出ていた）。詳細は次項。

### スペック固定の仕様（2026-09-23 再検証）

公式のお知らせ・パッチノート・ヘルプで「スペック固定」の数値仕様（Lv・凸・装備ティア等）を明記した一次資料は見つからなかった（下記「調査した情報源」）。そのため、ユーザーが過去に独自作成・検証してきた計算ツール（`D:\NIKKE_Damage_Calculator\シミュレーター本体.html`、以下「参照シミュレータ」）の `applyFixedSpecBuilds()` / `applyFixedSpecBuildForRid()` 実装と、本リポジトリの 1 ヒット実測（上表）を突き合わせて仕様を再構成した。参照シミュレータの成長曲線（レベル×グレード/コアの式）はユーザー本人が「計算式で無理やり近似させたもの」と明言しており誤差を含むため、**素のステータスは本リポジトリの `computeStat`（Stage 1 で ShiftyPad と一致確認済み）を正とし、参照シミュレータからは装備・好感度の離散テーブル値のみを採用した**。

**ビルド仕様**（参照シミュレータの実装 + 実測との一致で裏付け）:

- Lv400（`state.syncLevel = 400`）
- 限界突破・コア強化: レア度の**上限まで**。SR は 2 凸（コア強化なし）、R は凸なし（仕様上 0 で固定）。**SSR のみ未確定**（下記）
- スキル 1・2・バースト: 全 Lv10
- 装備: 4 部位とも T9 Lv5、オーバーロード（OL）ステータスは「なし」×3 スロット
- キューブ: なし、コレクション（人形）強化: 0（未強化）、企業タワー / リサイクルルーム（コンソール）: 全項目 0
- 好感度: 凸段階に応じた上限ランク（詳細下記、SSR のみ未確定）
- 宝もの: キャラごとに個別設定（`FIXED_SPEC_TREASURE_STAGE`）。今回の参照 6 体はいずれも対象外（0）。参照シミュレータのリストは SSR 18 体のみが対象（うち 16 体は Stage3=解放済み、シュガーは Stage2、ロザンナは Stage1）。宝ものはスキル説明文の差し替えにのみ使われ、基礎ステータス（攻撃力・HP・防御）には影響しない実装だった。

装備（T9 Lv5）のステータス加算値は **クラス別の固定値の合算**（攻撃力に対する割合ではない）。参照シミュレータの内部テーブル（頭/胴/腕/足の 4 部位合計）:

**未確定（要追加検証）**:

1. SSR の限界突破・コア強化: 0 凸/コア 0 が有力（grade MAX 案は 18% も外れるため棄却）だが、1 体のみのデータでは確定できない。別の SSR（できれば非ピルグリムで、企業・クラス・武器種がエマと異なる個体）で同じ約 0.7% の差が再現するか確認が必要。
2. SSR の好感度上限: rank30 か rank40 か、あるいはそれ以外か。上と同じ追加測定で切り分けられる。ピルグリム所属 SSR で検証できれば「ピルグリムのみ rank40」仮説自体の妥当性も判定できる。

4. 参照シミュレータの装備 T9Lv5・好感度テーブルの数値自体の出典（データマイニングか実測か）は未確認。SR/R での高精度一致から実用上は信頼できるが、独立した一次資料での裏取りはできていない。

## Stage 2-B: 発射サイクル（時間の実測）

モデルの変更点（`packages/core/src/cadence.ts`, `weapons.ts`）:

- チャージ武器: 毎発 `チャージ時間 + 22f`。リロード後の 1 発目も同じ（RL の 200f = 120 + 82 で確認）。`chargeReleaseFrames = 22`（参考 OSS の値と一致）。チャージ 1.5 秒（ベローダ）でも 90 + 22 = 112f で一致。
- 非チャージ武器: 発射レートを 1 フレームごとに蓄積し、1 発分たまったフレームで発射（フレーム切り上げではない）。AR 720rpm は 5f 固定。MG は「60rpm 開始、1 発ごとに +100rpm、3600rpm 上限」で 1 発目→300 発目が 390f（実測 387f）。以前の切り上げモデル（467f）は誤りだった。
- リロード後の 1 発目: AR は即射撃（遅延 0）。MG は約 20f の初弾遅延（`spinUpFirstShotFrames = 20`）。
- サイクル = 初弾遅延 + マガジン（1 発目→最終弾） + リロード。以前の「装弾数 × 間隔 + リロード」から変更。
- SMG（1440rpm）は蓄積モデルの 2.5f 平均（24 発/秒）で一致（ミサト）。参考 OSS の切り上げ 3f 説は誤り。
- SG（90rpm = 40f）は未計測。蓄積でも切り上げでも 40f で同じ。

計測手順のメモ: 発射の検出には、SR/RL は手元の反動（フレーム差分の局所平均）、AR は同じ手元差分のパルス列、MG は HUD の総ダメージカウンター領域の変化（1 ヒットごとに更新）が有効だった。残弾カウンターは数字がロール表示されるため毎フレーム変化してしまい使えない。

### 録画条件（2-B）

- 録画: PC 版を 60fps で録画（Xbox Game Bar の Win+G、または OBS。設定で 60fps を確認）。解像度は問わない。戦闘開始の合図から最初のリロード完了後の 1 発目までを含める（15 秒程度）。
- 操作: 射撃ボタンを押しっぱなしにするだけ。移動・カバー・バーストはしない。SR/RL はフルチャージ攻撃を連続で撃つ（押しっぱなしで自動的にフルチャージ連射になる）。
- 未計測で残っているもの: SG（90rpm = 40f、分割リロードの実時間）。動画を `D:/nikke_project/plan/captures/` に置けば同じ手順で計測できる。
