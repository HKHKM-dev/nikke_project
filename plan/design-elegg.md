## 1. 何を足すか

エレグ（500。Supporter・MG・バースト II・CT 20 秒）の S2 の後半「ターゲットが出現した時、味方全体にバーストゲージのチャージ 100%（戦闘中 1 回発動）」を、先に入れる。

ねらいは検証の道具にすること。戦闘開始の直後にゲージが満タンになれば、1 回目のフルバーストの時刻から、ゲージの溜まり方（弾のゲージ・物を壊した分・最初の発の余分など、いままでの残差の出どころ）を外せる。バーストの時刻や、バースト中の効果だけを見たい検証で、編成のゲージの未確定の要素を減らせる。

エレグ：ブーム・アンド・ショック（502）は別のキャラで、ここでは扱わない。

## 3. 段 1: S2 のゲージ

### 3.1 語彙（足さない）

いまの語彙で書ける（2026-10-26 に `parseSkillDefinition` が通ることを確かめた）。

```json
{
  "kind": "burstGauge",
  "trigger": "battleStart",
  "target": "allies",
  "ref": 4,
  "assumes": {
    "ja": "射撃場の的（ターゲット）は戦闘開始時に出現するとみなす",
    "en": "The shooting-range target is assumed to appear at the start of battle"
  },
  "claims": ["C-0662"]
}
```

- 発火: 1 パス目は、射撃の回数トリガーでない `burstGauge` を発火の次のフレームのゲージに足す（`frame/firstPass.ts`。ヘルム編）。戦闘開始なら 1 フレーム目に 100% が入る。
- 「戦闘中 1 回発動」: `battleStart` は 1 回しか発火しないので、欄は要らない。
- 「ターゲットの出現」を `battleStart` で書く理由: モデルの敵は射撃場の的 1 体で、的はターゲット（C-0139・C-0622）で、戦闘の始めからいる。新しいトリガーは使い手が 1 体なので入れない（[design-named-state.md](design-named-state.md) 3.6 節）。出現が戦闘開始より遅れると分かれば、遅れの欄を足す（6 節の論点 2）。
- 目録の分類（「ターゲットの出現」は前提の外（構造））は、射撃場の的については「戦闘開始時とみなして書ける」に直す。D・バイパー・ロザンナの同じ行は今回は触らない。

### 3.2 確かめること（検証記録を 1 本起こす）

| 記号 | 問い                                                                        | 見る観測量                                                        |
| ---- | --------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| U1   | 射撃場（BigArms）でも発動するか（的をターゲットとみなすか）                 | BURST バーが撃つ前に満タンになるか                                |
| U2   | 発動のフレーム（戦闘開始・的の出現・最初の命中のどれか）                    | 満タンに見えるフレームと戦闘開始の差                              |
| U3   | 100% がゲージの最大値そのものか（チャージ速度を掛けるか・端数が残るか）     | 満タンから 1 回目のバーストまでの間、バーが伸び切っているか       |
| U4   | 満タンから、バーストの使用までの間（オートバースト ON の I 段の使用の時刻） | 1 回目の I・II・III の使用のフレーム                              |
| U5   | 戦闘中 1 回だけか                                                           | 単騎で、チェーンが切れてゲージが 0 に戻った後に、満タンが来ないか |

撮影の計画は V-0504（編成・予測・撮影の依頼）。決めたこと:

- エレグは撃たない操作枠にする（オート射撃 OFF）。ゲージに入るのが S2 のチャージだけになり、エレグの通常攻撃の条件を測らなくてよい。
- 単騎（U1・U2・U3）: 単騎はバースト II だけなので、満タンの後は I の段の待ちが続く（撮る前は約 600f で切れると見込んだが、切れなかった。V-0504）。U5（戦闘中 1 回）は編成の 2 回目の溜まり方で見た。
- 編成（U4）: 鈴原サクラ（I）・ソルジャーF.A.（II・CT 20 秒）・エレグ（3 枠目・操作）・I-DOLL・サン（III）。3 枠目にキャラがいると戦闘開始の操作枠は 3 枠目になるので、撃たないエレグを 3 枠目に置く（2026-10-26 のオーナーの判断）。エレグを II より右の枠に置き、オートバースト ON で、エレグのバーストを発動させない（6 節の論点 3）。I・III は CT 40 秒なので、チェーンのたびにソルジャーF.A. の CT は明けている。
  - オートバーストが同じ段の候補から左（若い枠）を選ぶことは C-0663（III の段で確かめた）。V-0504 の録画でも、II の段で毎回左のソルジャーF.A. が撃った。
  - エレグの II が 1 回でも入った録画は、段 1 の根拠にしない（段 2 の残差の記録にとどめる）。
- モデルには撃たない枠が無いので、モデルではエレグも撃つ。比べるのは 1 回目のフルバーストの入りまで（そこまでにエレグの弾は効かない）。

## 4. 検証の道具として使う条件

AGENTS.md の「機構が確定したキャラ」にならないと、エレグを入れた録画を他の機構の根拠にできない。段 1 だけでも、S2 のゲージの結論が確定（反復実測以上）すれば、エレグを撃たない操作枠にし、バーストを使わない編成では道具として使える（通常攻撃の条件は撃たないので要らない）。

- モデルには撃たない枠が無い。比べる指標は、1 回目のフルバーストの入りまでのように、エレグの弾が効かないものにする。2 回目以降のサイクルや総ダメージを比べるなら、撃たない枠をモデルに入れるか、エレグを撃たせて通常攻撃の条件を測る（そのときに起案する）。

エレグのバーストを使わない限り、S1・S2 の前半（どちらも的がブームインストール状態のときだけ）とバーストの効果は起きない。最小構成の検査がこれらの未対応の notes を効きうる要素に出したら、効かない理由（その録画でエレグのバーストが無い）を、その結論の `minimal` に印として書く（[design-minimal-relevance.md](design-minimal-relevance.md) 11.3 節）。

## 8. 段 2: バースト

### 8.1 何を足すか（定義の形）

バーストの 3 行（2 節の表）を、`500.json` の burst の 2 件の未対応の notes と置き換える。値はどれも説明文の `description_value_NN`。

```json
[
  { "kind": "burstDamage", "ref": 3, "damageType": "skill" },
  {
    "kind": "state",
    "state": "boomInstall",
    "trigger": "burstUse",
    "target": "enemy",
    "durationRef": 5,
    "contents": [{ "stat": "enemyDefenseDown", "ref": 4 }]
  },
  {
    "kind": "timed",
    "trigger": "burstUse",
    "target": "allies",
    "stat": "distributedDamage",
    "ref": 1,
    "durationRef": 2
  }
]
```

- バーストスキルダメージ: Stage 5 の `burstDamage`（burst スロットの先頭）。ヒットは発動の直前のバフで出す（`BURST_HIT_USES_PRE_ACTIVATION_BUFFS`）。敵が持つ stat（受けるダメージ▲・防御力▼）はヒットの時点の値を読む（`frame/plan.ts` の `burstHitBuffs`）。ヒットの遅れが測れたら、遅れの表（`burst/landing.ts` の `MEASURED_BURST_DELAYS`）に行を足す。
- ブームインストール: 防御力▼の式は C-0556 のもの（防御力 × (1 − X) を引く）で、語彙はある（2 段目の段 2）。状態として付けるのは、段 3 の S1・S2 が「対象がブームインストール状態なら」で見るため。
- 分配ダメージ▲: `timed` の `distributedDamage`（分配ダメージにだけ別の乗数 (1 + Σ) で掛かる。C-0349・C-0391）。

### 8.2 語彙（足すもの: 敵に付く状態の付与）

いまの付与（`kind: 'state'`）は味方の枠に付くものだけで（`parseStateGrantEffect` が `holder: 'ally'` を求める）、敵に付く付与は名前の付いた状態の設計の後の拡張（[design-named-state.md](design-named-state.md) 8.3 節）にとどめてある。使い手はエレグが最初になる。

- **案 A（推奨）: 8.3 節の形をいま入れる**。
  - 目録に `boomInstall: { name: { ja: 'ブームインストール', en: 'BOOM Install' }, holder: 'enemy' }` を足す（id は英語版の状態名。5.1 節の id の付け方）。
  - 付与の `target: "enemy"` を受け、そのときは状態の `holder` が `enemy` であることを求める。窓は敵（`skills/holders.ts` の `ENEMY`）を持ち主にして作る。
  - 中身は敵が持つ stat（`enemyDefenseDown`・`damageTaken`）だけを書ける。窓は今の `damageTaken` と同じく味方全体の区間の値に写す（`isEnemyEffect`）。
  - 条件 `enemyState` で付与の窓を見るのは段 3 で足す（段 2 では見る側がいない）。dot の状態の区間（5.5 節）と同じ列にまとめるのも段 3。
- **案 B: 段 2 は `timed`（`enemyDefenseDown`・`target: "allies"`。ルドミラ S1 と同じ形）で書き、段 3 で状態の付与に書き換える**。段 2 の語彙は増えないが、段 3 で同じ効果を書き直し、結論のモデル側も直す。

段 2 だけ見れば見る側のいない状態だが、段 3 の S1・S2 の条件が見ることは説明文で決まっていて、名前の付いた状態の設計 3.6 節（使い手のいない語彙は入れない）には当たらない。中身の窓は `timed` と同じに作るので、値は案 A・B で変わらない。撮る前の予測は、どちらの案でも今ある `timed` の形を上書き（`addEffects`）で入れて出せる。

### 8.3 確かめること（検証記録を起こす）

| 記号 | 問い                                                                                        | 見る観測量                                                                                |
| ---- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| B1   | バーストスキルダメージの値（説明文の値 × 最終攻撃力の式で出るか。フルバーストの補正の有無） | 各回のバーストのヒットの値（会心・会心なし）                                              |
| B2   | ヒットのフレーム（II の発動からの遅れ。III のタイマーの 00.00 より前か後か）                | II の六角形の替わり目からヒットまで                                                       |
| B3   | 同じ発動の防御力▼が、そのバーストのヒットに乗るか                                           | B1 の値が、▼なし（H-b）と▼あり（H-a）のどちらと端数まで合うか                             |
| B4   | 防御力▼の付き始め（発動の次のフレーム・ヒットの後のどちらか）                               | 発動の前後の、味方の通常攻撃の 1 ヒットの値（▼の有無で `攻撃力 − 防御` が変わる。C-0556） |
| B5   | 防御力▼の切れ目（付き始めから 10 秒 = 588f か）                                             | 切れ目の前後の 1 ヒットの値                                                               |
| B6   | 分配ダメージ▲が、ほかの味方の分配ダメージに乗るか（別の乗数 (1 + Σ) で、説明文の値か）      | 編成 D の雪子のバーストの分配ダメージのヒットの値                                         |

- 仮説（撮る前に予測を固定する）:
  - B2: 遅れ 0（モデルの今の既定。ヒットは発動のフレーム）か、遅れあり（値を読む）。遅れが III の 00.00 を越えれば、ヒットにフルバーストの補正が乗る（B1 の値で見分けられる）。
  - B3: H-b（乗らない。遅れ 0 なら今のモデルの既定で、ヒットは発動の直前の値を見る）と H-a（乗る）。値の差は「▼の量 × 説明文の倍率」だけで、1 未満の一致で見分けられる見込み（的の防御力は C-0556 の 100）。H-a が遅れ 0 で起きたら、同じ発動の中の順の書き方（[design-burst-landing.md](design-burst-landing.md) 3 節の `sequential`。いまはイサベルだけ）を広げるかを、そのとき決める。
  - B4・B5: W0（発動の次のフレームから 588f。C-0556 の窓の形）と W1（ヒットから 588f）。B2 が遅れ 0 なら W0 と W1 は同じなので、見分けるのは B2 に遅れがあるときだけ。
  - B6: 乗る（雪子の真紅の華の▲と足し合わせる）と、乗らない。
- 分配ダメージ▲の窓の切れ目は見ない（編成 D で分配ダメージが出るのは、雪子のバーストの発動の 1 回だけ）。窓は説明文の 10 秒とし、効果の `assumes` に書く。

### 8.4 編成（最小構成）

単騎のエレグはバースト II だけでチェーンが進まない（V-0504）。I・III は機構が確定したキャラにする。

| 編成 | 1 枠目              | 2 枠目                  | 3 枠目                        | 見るもの | 本数 |
| ---- | ------------------- | ----------------------- | ----------------------------- | -------- | ---- |
| C    | 鈴原サクラ（I・AI） | I-DOLL・サン（III・AI） | ◎エレグ（II・操作・撃たない） | B1〜B5   | 2 本 |
| D    | 鈴原サクラ（I・AI） | 雪子（III・AI）         | ◎エレグ（II・操作・撃たない） | B6       | 2 本 |

- 共通: 射撃場・BigArms・灼熱・3 分モード・スペック固定 ON・オート射撃 OFF・オートバースト ON（V-0504 の編成 B からソルジャーF.A. を抜き、3 人にした形）。
- II はエレグだけにする。I・III は CT 40 秒、エレグは CT 20 秒なので、どのチェーンでもエレグの CT は明けていて、II は毎回エレグ。C-0663 の左の枠の優先は効かない。
- エレグの S2 のゲージ（C-0662）で 1 回目のチェーンは戦闘開始から約 1.5 秒で始まり、モデルとフレームまで合う（`0665-07`・`0666-07`）。1 回目のエレグのヒットと▼の付き始めの時刻を予測しやすい。

- 雪子（編成 D）: スロットの効果と notes の根拠はすべて確定（`plan/skills.md`）。雪子のバーストの分配ダメージは発動の直前のバフで出る（C-0351）ので、約 29f 前のエレグの発動で付いた▲が乗るかを、雪子の同じ発動の▲（C-0349。乗らない）と分けて見られる。雪子の通常攻撃の条件（MG の的での値）は比べる値に効かない（比べるのはバーストのヒットだけ）。最小構成の検査がそれを出したら、効かない理由を印で書く。

### 8.5 エレグを撃たせるか

**撃たない（推奨）**。段 1 と同じく、エレグは 3 枠目の操作枠でオート射撃 OFF にする。

- 撃たなければ、S1・S2 の前半（ブームインストール中の命中の回数のトリガー。段 3）は実機で起きない。B1〜B6 の値に段 3 の要素が混ざらない。エレグの通常攻撃の条件（MG のコア命中率など）も測らなくてよい。
- モデルには撃たない枠が無いので、モデルではエレグも撃つ。エレグの弾が効くのはゲージだけ（S1・S2 の前半は未対応の notes のままで、モデルでも起きない）なので、比べる指標は次のどれかにする。
  - 1 回目のチェーンの値（バーストのヒットの値・▼の付き始めと切れ目の前後の 1 ヒット）。ゲージは S2 で満タンから始まるので、1 回目のチェーンまでの時刻はエレグの弾に依らない（C-0662）。
  - 発動から数える量（`burstHitDelays` など）。2 回目以降の回も比べられる。
  - 2 回目以降のバーストのヒットの値は、鈴原サクラの▲の窓との重なりがモデルと実機で違いうるので、記録（`use: record`）にとどめ、読んだ▲の有無で手で式と比べる。
- 最小構成の検査が S1・S2 の前半の未対応の notes を効きうる要素に出したら、効かない理由（その録画でエレグは撃っていない）を結論の `minimal` に印として書く（4 節と同じ）。
- 撃たせる案は採らない。撃たせるとブームインストール中に S1・S2 の前半が起き、未確定の要素が増える（段 3 で撮る）。
