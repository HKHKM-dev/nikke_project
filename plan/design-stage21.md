## Context

モデルは、1 秒を 60 フレームとして数えている（`packages/core/src/weapons.ts` の `FPS = 60`）。射撃の刻みの較正（C-0001・C-0002・C-0014 など）は、録画の動画のフレームで読んだ値を、そのままモデルのフレームとして使っている。

2026-09-27 の検証で、**ゲーム内の時計の 1 秒は、録画の動画の 60f ではなく約 58.82f**（1 フレームにつき約 0.017 秒）だと分かった（C-0048）。スキルの持続もこの時計で進む（C-0050）。つまり、今のモデルでは次の 2 つの単位が混ざっている。

- 動画のフレームで較正した値（射撃の刻み・段階の演出の遅れなど）
- 秒で持つ値を 60 倍したもの（戦闘の長さ・スキルの持続・CT・フルバーストの長さ・的のジャンプ）

秒で持つ値は、録画と比べて約 2% 長く数えている。この Stage では、**モデルの 1 フレームを「動画の 1 フレーム = ゲーム内の 0.017 秒」と定め、秒で持つ値の換算をそれに合わせる**。

- フルバーストの残り時間を 1 フレームずつ読むと、刻みは 0.0170〜0.0171 秒（`044-02`）。1/60 秒とは合わない。

### 0.2 コードの中の時間の換算（`FPS` の使われ方）

`FPS` は core のあちこちと `scripts/sim-run.ts` で使われている。役割で分けると 4 つ。

| 役割                                | 場所                                                                                                                                                                                                                                               | 今の換算            |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------- |
| (a) 秒で持つ長さ → フレーム         | `burst/fixedCycle.ts` の `durationToFrames`（戦闘の長さ・スキルの持続・バーストの CT・フルバーストの長さ）、`frame/events.ts`（的の出来事）、`frame/landing.ts`（着地点の区間）                                                                    | 秒 × 60             |
| (b) 武器の CDN の秒・rpm → フレーム | `weapons.ts` の `secondsToFrames`・`MAX_RPM`、`frame/firing.ts`（リロード・チャージ）、`frame/shooter.ts`（MG の撃ち直し `rateOfFireResetTime`）、`cadence.ts`（rpm の蓄積）                                                                       | 秒 × 60、rpm ÷ 3600 |
| (c) フレーム → 秒（出力）           | `calc/model.ts`・`sim/teamResult.ts`・`sim/engine.ts`（秒ごとの集計）・`burst/schedule.ts`・`cadence.ts`・`skills/timeline.ts`・`frame/landing.ts`（注記の文）                                                                                     | フレーム ÷ 60       |
| (d) フレームで持つ定数              | `burst/controller.ts`（段階の遅れ 20f・チェーンの打ち切り 600f・フルバーストの既定 600f）、`burst/fixedCycle.ts`（固定サイクル 1200・600・600f）、`weapons.ts` の `DEFAULT_WEAPON_MODEL`（22f・20f）、`sim/firing.ts` の `MEASURED_CHARGE_CADENCE` | そのまま            |

(d) の定数は、中身で 2 つに分かれる。

- **動画のフレームで測った値**（そのまま使える）: 22f（C-0001）、20f（C-0002）、紅蓮BS の +3f・+9f（C-0014）、段階の遅れ 20f（C-0008、仮説・未較正）。
- **本当は秒の値**（(a) に移す）: フルバーストの既定 600f（= 10 秒）、チェーンの打ち切り 600f（ゲーム内のチェーン待ちのタイマー 10 秒。C-0009 は目視で約 600f）、固定サイクル（Stage 5・6 の 20 秒周期）。

### 0.3 武器の刻み（(b)）は、単純には置き換えられない

武器の CDN の秒や rpm もゲーム内の時計で進むなら、(b) も 1 秒 = 58.82f で換算するのが筋になる。既存の実測で試算した（モデルの計算だけ。録画は読み直していない）。

- **MG のスピンアップ**（verification.md の MG の再較正、`cadence.test.ts`）: 今のモデルは、実測より最大 4f 遅い。rpm を 1 秒 = 58.82f で蓄積すると、最大 2f に縮む。
- **AR の 720rpm**: 実測は 5f ごとに 1 発で、60 発で 295f。今のモデル（端数を持ち越す蓄積）は 1 秒 = 60f で 5f ちょうどになる。1 秒 = 58.82f にすると 4.9f ごとになり、60 発で約 289f になって合わなくなる。「1 発ごとに経過時間をリセットする（端数を持ち越さない）」方式なら AR は 5f で合うが、その方式では MG のスピンアップが 20f 以上遅れて合わない。
- **チャージとリロード**: 較正の補正（C-0001 の +22f、C-0014 の +3f・+9f、リロードの補正）は、秒 × 60 との差として決めている。換算を変えると、補正の値を読み直すことになる。

武器の刻みは、ゲームの計算方式（端数の扱い）が分かっていないので、換算だけ変えても合う保証がない。**この Stage では (b) を変えず、別の段（21-C）で録画と照らしてから決める**。

### 0.4 変えると動く数値

- 秒で持つ長さが約 2% 短くなる。180 秒の戦闘は 10,800f から約 10,588f になり、スキルの持続・CT・フルバーストの長さも同じ割合で短くなる。
- 単騎 180 秒の射撃数は約 2% 減る（V-0002 の読みでは、紅蓮BS 単騎で 175 → 174 発）。バーストの周期・フルバーストの回数も動きうる。
- 「確定」の結論にひもづく観測値（`npm test` で落ちるもの）のうち、影響しうるのは合計（`046-02`・`047-02`。C-0025、±2%）とフルバーストの回数（`018-01` など。C-0022）。1 ヒットの値（`hitDamage`）は変わらない。

## 1. 方針

1. **モデルの 1 フレーム = 録画の動画の 1 フレーム = ゲーム内の 0.017 秒**と定める。定数を 2 つに分ける。
   - `GAME_SECONDS_PER_FRAME = 0.017`（ゲーム内の時計。(a)・(c) と、(d) のうち秒の値に使う）
   - 武器の換算は、21-C で決めるまで今の値（1 秒 = 60f）を `WEAPON_FRAMES_PER_SECOND` として残す（(b)）
2. **動画のフレームで測った定数は変えない**（(d) の前半）。
3. **秒で表示する値は、ゲーム内の秒にする**（(c)）。画面の「秒」は、ゲームの残り時間の秒と同じになる。
4. モデルの数値が動くので、段を分けて、動いた量を残差の一覧と検証記録に残す。係数は合わせに行かない。「確定」の結論にひもづく観測値が許容幅の外に出たら、その結論の根拠を見直す（許容幅を広げて通さない）。

## 3. 推奨案 A の中身

### 3.1 定数と換算の関数

- `packages/core/src/time.ts`（新規）に置く:
  - `GAME_SECONDS_PER_FRAME = 0.017`
  - `gameSecondsToFrames(seconds)`: 長さ（持続・CT・フルバースト・戦闘の長さ）。丸めは 3.4 節
  - `gameSecondsToFrame(seconds)`: 時刻（出来事の境目）。四捨五入
  - `framesToGameSeconds(frames)`: 出力
- `weapons.ts` の `FPS` は、武器の換算専用の `WEAPON_FRAMES_PER_SECOND = 60` に名前を変える（21-A）。`MAX_RPM` はそのまま（1 フレームに 1 発の上限）。
- `durationToFrames`（`burst/fixedCycle.ts`）は `gameSecondsToFrames` に置き換える。

### 3.2 フレームで持っている「秒の値」

| 定数                                      | 今             | 変更後                                            |
| ----------------------------------------- | -------------- | ------------------------------------------------- |
| `FULL_BURST_FRAMES`（既定のフルバースト） | 600            | 10 秒から換算（`burst_duration` の無い枠だけ）    |

| 段階の遅れ（20f × 3）                     | 20f            | 変えない（動画のフレーム。C-0008 は仮説・未較正） |

### 3.3 的の出来事（`data/enemies.json` の `range-3min-jump`）

C-0025 の数値（最初 31 秒・長さ 2 秒・36.4 秒ごと）は、**動画のフレームを 60 で割って秒にした値**（Stage 16-B）。換算を変えると、同じ秒のままでは読んだフレームとずれる。推奨は、**読んだフレームが変わらないよう、ゲーム内の秒に直して書き換える**（×60 ÷ 58.82。最初 約 31.6 秒・36.4 秒ごと → 約 37.1 秒ごと）。長さの 2 秒は、読んだ停止の長さ（111〜126f）の中に 2 秒 = 約 118f が入るので、2 秒のまま。

別案は、`enemies.json` にフレームで書く案。出来事の型が秒なので、型を変えることになる。

### 3.4 丸め

- 長さ: 今の `durationToFrames` は切り上げ。7 秒は 411.76f → 切り上げで 412f。クラウンの S2 の 7 秒は、▲の付いた発の区間が 411f だった（`056-04`。最初と最後の▲の発を含めて数えた）。窓 `[開始, 開始 + 長さ)` の長さと、▲の発の区間の長さの対応は、実装のときに `056-04` をテストにして決める（21-B）。
- 時刻: 今の四捨五入のまま。

### 3.5 出力（(c)）

- 秒で出す値（フルバーストの開始の秒・区間の秒・DPS の「毎秒」・秒ごとの集計）は、`framesToGameSeconds` で出す。
- 画面と CLI の「180 秒」は、ゲームの残り時間の 180 秒と同じ意味になる。
- `sim-run.ts` の出力と画面の文言で、「秒」がゲーム内の秒だと分かるように注記する。

### 3.6 やらないこと（この Stage の外）

- 武器の換算（(b)）の変更 → 21-C で録画と照らして決める。決まるまでは 1 秒 = 60f のまま（未実装の注記は要らない。較正値として合っているため）。
- フルバーストに入るときに残り時間が止まること（C-0049、仮説）のモデル化。止まっているあいだ射撃やスキルの時間も止まるかが分かっていない。
- 描画が重い場面の扱い（C-0052、仮説）。

## 7. 実施の記録

### 7.1 21-A（2026-09-27）

名前と呼び分けだけで、モデルの数値は変えていない。

- `packages/core/src/time.ts` を足した: `FRAMES_PER_GAME_SECOND`（この段では 60）、`gameSecondsToFrames`（長さ・切り上げ。入力の検査は `durationToFrames` のもの）、`gameSecondsToFrame`（時刻・四捨五入）、`framesToGameSeconds`（出力）。
- `burst/fixedCycle.ts` の `durationToFrames` は消し、使っていた所（バーストの CT・フルバーストの長さ・戦闘の長さ・スキルの持続・CT 短縮）を `gameSecondsToFrames` にした。
- 3.2 節の定数（フルバーストの既定・チェーンの打ち切り・固定サイクル）は、秒から `gameSecondsToFrames` で出す形にした（この段では 600・600・1200 / 600 / 600 のまま）。段階の遅れ（20f）は動画のフレームの値なので変えていない。
- `weapons.ts` の `FPS` は `WEAPON_FRAMES_PER_SECOND` に改めた。使うのは `secondsToFrames`（チャージ・リロード）・`MAX_RPM`・MG の撃ち直し（`frame/shooter.ts`）だけ。
- 出力の秒（`calc/model.ts`・`sim/teamResult.ts`・`sim/engine.ts` の秒ごとの集計・`burst/schedule.ts`・`cadence.ts`・`skills/timeline.ts`・`frame/landing.ts` の注記・`scripts/sim-run.ts`）は `framesToGameSeconds`、出来事と着地点の境目は `gameSecondsToFrame` にした。
- テストで秒からフレームに戻していた所（`simCalc`・`stage8Team`・`stage9Treasure`）は `gameSecondsToFrame`（四捨五入）にした。21-B で 1 秒が整数のフレームでなくなっても、同じ比べ方のまま使える。
- 確認: core に `FPS` の直の参照は残っていない。テスト 755 件（`time.test.ts` の 4 件を足し、`fixedCycle.test.ts` の換算のテストを移した）が数値を変えずに通った。`npm run records:check` の生成物に差分なし。`npm run sim`（紅蓮BS 単騎・3 分モード）の合計も前と同じ。

### 7.2 21-B（2026-09-27）

モデルのゲーム内の秒を、1 フレーム 0.017 秒で数えるようにした。残差の動きは V-0006。

- `time.ts`: `GAME_SECONDS_PER_FRAME = 0.017`、`FRAMES_PER_GAME_SECOND = 1 ÷ 0.017`。割り算の誤差で整数のすぐ隣に出た値がずれないよう、ごく小さな幅（1e-9）を足し引きする。
- **長さの丸めは切り捨てにした**（3.4 節）。7 秒は 411.8f で、切り上げの 412f では録画 56 のクラウンの S2（`056-04` の 411f）と合わず、切り捨ての 411f で合った。モデルでも、回復した発の次のフレームから 411f のあいだ▲が付くことを `records/__tests__/stage21Time.test.ts` で確かめる。180 秒は 10,588f、10 秒は 588f、CT 40 秒は 2,352f。時刻（出来事の境目）は四捨五入のまま。
- 固定サイクル（Stage 5・6）は、通常 10 秒・フルバースト 10 秒をそれぞれ換算した和を 1 サイクル（1,176f）にした。20 秒を 1 回で換算すると 1,176f、10 秒 2 つは 588f × 2 で、たまたま同じだが、和にしておけば「通常 + フルバースト = 1 サイクル」の検査が崩れない。
- 的のジャンプ（3.3 節）: `data/enemies.json` を最初 31.62 秒・37.128 秒ごと・2 秒にした（読んだフレーム 1,860f・2,184f が変わらない）。注記にも換算の理由を書いた。

## 8. 21-C: 武器の換算（設計・2026-09-27）

実施の記録は 7.4 節。

### 8.1 問い

武器の CDN の秒（チャージ・リロード・MG の撃ち直し `rateOfFireResetTime`）と rpm（間隔・MG のスピンアップ）を、1 秒 = 60f のまま換算するか、ゲーム内の時計（1 秒 = 1 ÷ 0.017f）で換算するか。0.3 節で見たとおり、換算だけ変えても合う保証はないので、**既存の録画で確かめてから決める**。新しい撮影は要らない見込み。

### 8.2 分かっていること

凍結した記録の値で 3 案を試算した（V-0011 の「予測」。モデルの計算だけで、録画は読み直していない）。

| 案  | 秒                     | rpm                                     |
| --- | ---------------------- | --------------------------------------- |
| W0  | 1 秒 = 60f（今のまま） | 1 フレームごとに rpm ÷ 3600（今のまま） |
| W1  | 1 秒 = 1 ÷ 0.017f      | 1 フレームごとに rpm ÷ 60 × 0.017       |
| W2  | 1 秒 = 1 ÷ 0.017f      | W0 と同じ                               |

- **rpm で決まるもの**は向きが割れている。AR・SMG の長い区間（60 発・120 発）は W0・W2 に合い、W1 では 5〜6f 短くなる。MG のスピンアップは W1 のほうが近い。
- **秒で決まるもの**（リロード）は、RL の 2 本・AR・ラムが W1・W2 に 0〜1f で合い、W0 は 1〜2f 長い。MG のリロードは、どの案より実測が長い。
- **チャージの間隔**は、解放遅延（C-0001 の 22f）を読み直せば、どの案でも合う（W1・W2 では 23f）。見分けに使えない。
- 端数を持ち越さない方式（1 発ごとに経過時間をリセット）は、SMG・MG で大きく外れるので案に入れない（V-0011）。
- 差の多くは 1〜2f で、凍結した記録の読み方の違い（武器ごとに反動・HUD・残弾表示、表示の遅れを仮定して引いたもの、「約」の付いた値）と同じ大きさ。**凍結した値のままでは決められない。**

### 8.3 方針

1. 既存の録画（Stage 2-B の `001`〜`007`、MG の `035`・`041`、ラムの `040`、紅蓮BS の `046`・`047`）を、**同じ読み方で読み直して観測値にする**（V-0011 の「読み方」）。どの値も「発射 → 発射」の間隔で読み、表示の遅れを仮定して引かない。
2. 3 案の予測と並べ、8.4 節の基準で採る案を決める。
3. 採る案が W0 以外なら、較正値（C-0001 の 22f、C-0014 の +3f・+9f、C-0002 の 20f）を読み直した値で新しい結論にし、古い結論は棄却にする。係数は合わせに行かない（1 節の 4）。
4. 3 分モードの合計（`054-02`・`056-02`・`L-*` など）は判定に使わない。的のジャンプの 1 回目のずれ（V-0009・V-0010）が混ざるため。変化は検証記録に残すだけにする。

### 8.4 判定の基準

- 比べるのは、案によって予測が違う値だけ（8.2 節で「見分けられない」としたものは除く）。
- 値ごとに、読み直した値（マガジンごとの散らばりがあればその幅）± 1f に予測が入れば「合う」とする。
- **秒と rpm は別々に決める**。どちらも、合わない値の無い案が 1 つだけなら、その案にする。どの案でも合わない値（今の見込みでは MG のリロード）は、判定から外して V-0011 に残し、別の問いにする。
- 合わない値の無い案が複数あるか、1 つも無いなら、**W0 のまま**にする（根拠のない変更をしない）。

### 8.7 21-C2 の結果（2026-09-27）

- **秒は W0 のまま**（1 秒 = 60f）。見分けられる値（SR・RL のリロード）は W0 と W1 の両方に ±1f で合い、8.4 節の基準では決まらない。

### 8.8 21-C3 でやること（2026-09-27 に推奨案で承認）

8.5 節の 21-C3（「採る案が W0 以外のときだけ」）は、rpm だけを W1 にする形になる。C-0059 は 8.5 節の範囲の外なので、足すかどうかをここで決めてほしい。

1. **rpm の換算を W1 にする**（C-0058）: `cadence.ts` の蓄積を 1 フレーム 0.017 秒にする（rpm ÷ 60 × 0.017）。1 フレームに 1 発の上限は変えない（MG の定常は 1 フレーム 1 発。design-mg-fire-rate.md）。秒の換算（`secondsToFrames`・撃ち直しの `rateOfFireResetTime`）は 1 秒 = 60f のまま。
2. **AR・SMG・SG のリロードの後の遅れを足す**（C-0059）: `WeaponModel` に遅れの定数を足し、`firstShotFrames` で使う。値は W0 の秒の換算での読み（AR 22f・SMG 23f・SG 20〜21f）から決める。推奨は、武器種ごとに分けず **22f** の 1 つにし（チャージ武器の解放遅延 C-0001 と同じ値）、武器種ごとの 1〜2f の違いは読みの幅として V-0011 に残す案。別案は武器種ごとの値（AR 22・SMG 23・SG 21）。
3. MG のスピンアップのテスト（`cadence.test.ts` の「最大 4f 遅い」）は、W1 で差が縮むので、差の上限を読み直した値にする。凍結した発射フレーム列のテストは作り直す。
4. 変わる予測（単騎の合計など）は、残差の一覧の前後を V-0011 の後の新しい検証記録に残す。3 分モードの合計は判定に使わない（8.3 節の 4）。
