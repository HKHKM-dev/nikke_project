# 最小構成の検査: 窓の端だけを決める仮説の語彙

- 関連: [design-minimal-relevance.md](design-minimal-relevance.md)（この設計はその続き。3.5 節の `when`・4.1 節の感度・4.3 節の印）、[design-investigation-review.md](design-investigation-review.md) 2.4 節（出どころ）、[backlog.md](backlog.md) 5-12
- 作成日: 2026-10-17
- 状態: 承認（2026-10-17。6 節の論点 1〜5 を案のとおり）。実施済み（8 節）

## 1. 目的

- バースト使用時の効果の付き始め・切れ目の仮説（C-0511 など）を定義の効果に結ぶと、その効果は未確定の要素になり、同じ録画を根拠にするほかの確定の結論に最小構成の警告が出る。V-0378・V-0393・V-0396・V-0397・V-0402〜V-0404・V-0406 で、組ごとに手で印（design-minimal-relevance.md 4.3 節）を書いた。
- 印の理由はほとんど同じ形をしている: 「仮説が決めるのは窓の端の数 f だけで、効果があること・値・長さは確定の結論で決まる。この観測値は窓の端から離れている（か、端に依らない）」。
- いまの語彙では、この「端の数 f にだけ効く」を書けない。`when`（3.5 節）は録画ごとの条件で、観測値の時刻は見ない。感度（4.1 節）は効果を外す（P−）・常に効かせる（P+）の 2 通りなので、効果の値がある観測値ではいつも「効く」になる。
- この設計で、**仮説の結論に「実機の窓の端は、モデルの窓の端から何 f の範囲にある」を書く語彙**を足し、感度でその範囲だけ端を動かして、効かない組の警告を自動で外す。

## 2. 語彙 `edge`

```json
"edge": { "start": [0, 7], "end": [0, 7] }
```

- 仮説の結論にだけ書ける。`subject.places` が必須（端を動かす効果は、その場所の効果）。
- `start`・`end`: 実機の窓の付き始め・切れ目が、モデルの窓の付き始め・切れ目からずれうる範囲（フレーム。負は早い側）。`[min, max]`、整数、`min ≤ max`、絶対値は 30f 以下（「数 f」の語彙にとどめる）。どちらか 1 つは書く。書かない端は動かさない（その端はモデルのとおりとみなす）。
- 意味: この仮説が決めるのは、書いた場所の効果の窓の端の位置だけで、効果があること・値・対象・長さ以外の欄は、ほかの確定の結論で決まっている。
- 長さが確定の結論で決まっていて、付き始めだけの仮説（C-0514 など）は、付き始めがずれれば切れ目も同じだけずれるので、`end` にも同じ範囲を書く。

## 3. 判定

### 3.1 端だけ未確定の要素

要素 E（定義の効果）の `claims` のうち、確定・範囲外でなく、`when` が成り立つもの（いまの「開いた結論」。design-minimal-relevance.md 2 節の 3）が、**すべて `edge` を持つ仮説で、その `subject.places` が E の場所を含み**、かつ E の `claims` に**確定の結論が 1 つ以上ある**とき、E は「端だけ未確定」とする。

- 確定の結論が無い要素（効果があること自体が仮説）は、端だけ未確定にしない（いまのまま）。
- 開いた結論が 2 つ以上なら、範囲は端ごとに和をとる（いちばん広い `min` といちばん広い `max`）。

### 3.2 感度の変換（端を動かす）

O が sim の `compare` を持ち（`usesSensitivity`）、E が端だけ未確定のとき、P−・P+ の代わりに次の 2 通りを回す。

- **広げる**（P⊃）: 付き始めを `start.min`、切れ目を `end.max` だけ動かす。
- **縮める**（P⊂）: 付き始めを `start.max`、切れ目を `end.min` だけ動かす。
- どちらかの予測が基準 P0 から許容（`compare.tolerance`）を超えて動けば効きうる。どちらも許容の中なら、その組からこの要素を外す。
- 窓の端の近くのどのフレームも、広げるか縮めるかのどちらかで効果の有無が入れ替わるので、端の範囲の中のどこに実機の端があっても、2 通りで見落とさない（範囲の端の点で比べる。範囲の中の点で初めて効く形は無い。効果は窓の中で一定の値なので）。
- E 以外の要素はモデルの窓のまま（4.1 節と同じ）。
- 6c（未確定の要素はモデルの窓を信じない）との関係: 端だけ未確定の要素は、窓のきっかけ・長さ・値が確定の結論で決まっているので、モデルの窓を信じてよい。信じないのは、仮説が開いている端の範囲だけで、その範囲は全部動かして見る。

### 3.3 sim での端の動かし方

- 対象は timed の定義の効果だけ（状態の付与は、同じ状態の付与を 1 つの件の列にまとめるので、1 つの付与の端だけを動かせない。端だけ未確定にしない）。

- 定義の効果に、検査だけが書く内部の欄 `edgeShift: { start, end }`（フレーム）を付けた定義で sim を回す（データの JSON には書けない。読み込みの検査で弾く）。
- 解いた効果（`ResolvedTimedEffect`・状態の付与）に写し、件を作るところ（`skills/holders.ts` の `readItems`）で、その効果の件ごとに始まりと終わりを動かす（戦闘の範囲に切り詰め、長さ 0 以下の件は消す）。
- 限界: 1 パス目（射撃の列・ゲージ・バーストの時刻）は前から順にフレームを進めるので、**付き始めを早める**（負の `start`）変換は、きっかけのフレームより前の 1 パス目の読みには効かない（バフの区間の表と 2 パス目のダメージには効く）。そこで、負の `start` を当てる要素のうち、分類（4.2 節の 5）が与ダメージの値・会心率でないもの（射撃・バーストの時刻など、1 パス目で読む効果）は、端だけ未確定の扱いをせず、いままでの P−・P+ で判定する。

### 3.4 結果の置き場所と古さ

- 感度の結果の 1 件（観測値 × 要素）に、変換の種類（`mode: "edge"`）と、使った範囲を持たせる。`relevanceOf` は、いまの要素の判定（端だけ未確定か・範囲）と結果の種類・範囲が合わなければ古いとみる（静的な判定に戻し、「感度の結果が無いか古い」に数える）。結論の状態や `edge` を変えたら、`records:minimal` で計算し直す。
- `SENSITIVITY_VERSION` を 2 に上げる。

### 3.5 sim と比べない観測値

- `compare` の無い観測値（時刻・間隔・回数・ゲージを人が読んだもの）は、いままでの静的な判定のまま。端の範囲は使わない（観測値の `scope.frames` は動画のフレームで、止まりを挟むとモデルのフレームと揃わないため）。
- これらの組の印（C-0260・C-0261・C-0424 などのアニス：スターの印の多く）は残す。

### 3.6 生成物の書き方

- [minimal.md](minimal.md) の要素の理由に、端だけ未確定で、端を動かすと効くものは「仮説 C-NNNN（端）・感度で効く」と出す。外れたものは出さない（ほかの外れた要素と同じ）。

## 4. 書き込む結論と範囲（案）

モデルでは、遅れの表に行の無いキャラのバースト使用時の効果は、本当の発動のフレームに付き、維持時間で切れる。III のタイマーの 00.00 は本当の発動の 6f 後（C-0516）、I・II の六角形の替わり目は 5f 後（C-0503。C-0520 の文では 6f 後。どちらでも下の範囲は変わらない）。各仮説の文が許す範囲を、モデルの端からのずれに直すと次のとおり（`end` は、長さが確定で端が一緒に動く分）。

| 結論   | 効果                                                    | 仮説の文が許す付き始め                                                   | `start`   | `end`     |
| ------ | ------------------------------------------------------- | ------------------------------------------------------------------------ | --------- | --------- |
| C-0511 | 雪子 burst の effects[1]（1more の攻撃力▲）             | 00.00 の 5f 前（他の形なら 00.00 の 1f 後）                              | `[0, 7]`  | `[0, 7]`  |
| C-0513 | ラピ burst の effects[1]（攻撃力▲）                     | 00.00 の 7〜8f 前より後・1f 前まで                                       | `[0, 5]`  | `[0, 5]`  |
| C-0514 | アスカ burst の effects[0]（攻撃ダメージ▲）             | 00.00 の 5f 前より後（00.00 の 1f 後まで）                               | `[0, 7]`  | `[0, 7]`  |
| C-0520 | アニス：スター burst の effects[1]・effects[2]          | 替わり目の 7f 前より後・3f 前まで                                        | `[0, 3]`  | `[0, 3]`  |

- どれも付き始めが本当の発動より前になることは無い（バースト使用がきっかけ）ので、`start.min` は 0。負の変換（3.3 節の限界）は当たらない。

- 書いた後、既存の印のうち、自動で外れる組の印は消す（6 節の論点 4）。

## 5. 確かめ方

- `records:minimal` の生成物（[minimal.md](minimal.md)）で、上の結論の sim と比べる組（雪子の C-0347〜C-0360、アスカの C-0075・C-0087・C-0345、クイーン（真）の C-0307・C-0310・C-0354 など）が、印を消しても警告にならない。
- 単体テスト（`packages/core/src/records/__tests__/`）:
  - `edge` の検査（仮説だけ・`subject` 必須・範囲の形）。
  - 端だけ未確定の判定（確定の結論が無い・`edge` の無い開いた結論が混ざる・場所が合わない、では端だけ未確定にならない）。
  - 端を動かす変換で、窓の端から離れた観測値は外れ、**窓の端の範囲の中の観測値は残る**（外れてはいけない例）。範囲を書かない端は動かない。
  - 結果の種類・範囲が今の判定と合わなければ古いとみる。
  - 負の付き始めを、1 パス目で読む分類の効果に当てない。

## 6. 論点（オーナーの判断）

1. **判定の仕方**: 端を動かす感度（3.2 節。sim を 2 通り回す）にするか。代わりに、比べるフレームとモデルの窓の端の距離を静的に測る案もあるが、指標ごとに「どのフレームを読むか」（バーストのヒットは発動の直前のバフ・通常攻撃は発射の時など）を持つ必要があり、取りこぼしやすいので採らない案にしたい。
2. **範囲の書き方**: 端ごとの `[min, max]`（2 節）にするか、両側に同じ幅の 1 つの数（`frames: 7`）にするか。バースト使用時の効果は本当の発動より前に付かないので、片側の範囲が書けるほうが、バーストのヒット（発動の直前のバフ）の組を外せる。
3. **各仮説の範囲**（4 節の表）。とくに C-0522 の有利コードの▲の上限。
4. **既存の印の扱い**: 自動で外れる組の印は消すか、残すか（残すと、生成物には「印」として出たまま）。消すのは、印の理由と同じ判断を機械がするようになった分だけにする案。
5. **sim と比べない観測値**（3.5 節）は対象外にして、その印は残すか。

## 8. 実施の記録（2026-10-17）

- データの形: 結論の `edge`（`records/claims.ts` の `ClaimEdge`・`validateMinimalFields`）。定義の timed の内部の欄 `edgeShift`（`skills/types.ts`。読み込みの欄の一覧に無いので JSON には書けない）を、解いた効果に写し（`skills/resolve.ts`）、件を作るところで動かす（`skills/holders.ts` の `shiftEdges`）。
- 判定: `records/relevance.ts` の `edgeRangeOf`（端だけ未確定か・範囲の和）。感度の結果の `edge`（範囲・広げる・縮めるの差）を持たせ、`relevanceOf` は範囲が合わない結果を古いとみる。`SENSITIVITY_VERSION` は 2。
- 感度: `records/sensitivity.ts` の `edgeShiftOf`・`edgeDefinition`。端だけ未確定の要素は、P−・P+ の代わりに広げる・縮めるを回す。
- 書き込み: 4 節の表の 7 件の仮説に `edge`。
- 印の整理（論点 4）: 理由が窓の端（付き始め・切れ目）の判断で、`edge` を入れて自動で外れるようになった組の印を外した（結論 27 件・92 組。C-0075・C-0082・C-0085・C-0087・C-0205・C-0207・C-0211・C-0213・C-0227・C-0297・C-0307・C-0308・C-0310・C-0345・C-0347〜C-0351・C-0354・C-0355・C-0357・C-0358・C-0360・C-0400・C-0424・C-0557）。印を外しても [minimal.md](minimal.md) の警告のある組の数は変わらない（外した組は、どれも端を動かしても許容の中）。理由が「バーストを撃たない録画」の印（C-0570・C-0576・C-0578）と、sim と比べない観測値の印（3.5 節）は残した。
- テスト: `packages/core/src/records/__tests__/minimalEdge.test.ts`。外れてはいけない例として、録画 258 の観測値 `258-04` の比べるフレームを、雪子の 1more の▲の窓の付き始めの 3f 後・切れ目の 3f 後に動かすと、端を動かす感度で効く（警告に残る）ことを確かめる。
