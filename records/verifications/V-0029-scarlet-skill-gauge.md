# V-0029: 紅蓮：ブラックシャドウのスキルのヒットで溜まるゲージ

- 問い: 紅蓮BS の S1 の段（A・B・C）のヒットは、それぞれ 1 ヒットでどれだけゲージを溜めるか
- 話題: バーストゲージ
- 日付: 2026-09-28
- 録画: `046`、`055`、`070`、`071`
- 結論: `C-0085`
- 状態: 完了
- 派生元: `V-0028`

## 条件

- V-0028: 1 ヒットのゲージは CDN の `target_burst_energy_pershot` そのまま（C-0083）。BURST バーは本当のゲージの約 12.6〜96% を映し、1px ≈ 本当の 0.74%（C-0084）。
- 紅蓮BS の単騎の録画 46 で、通常攻撃の 1 発（フルチャージ）は 5px、その後のスキルのヒット 3 回（227,119）は 3〜4px ずつ伸びた（`046-12`）→ C-0085（仮説）。モデルは通常攻撃の弾だけでゲージを溜めるので、録画 47 の 1 回目の満タンが遅く出る（`047-11`）。
- 紅蓮BS（225）: RL・フルチャージ倍率 1.5、`target_burst_energy_pershot` 25,000、`burst_energy_pershot` 12,500。S1 はフルチャージ攻撃 3 回ごとに段 A（スキルダメージ）→ B（分配ダメージ。的 1 体では 1/3 ずつ 3 ティック）→ C（分配ダメージ）を順に出す（`data/skills/225.json`）。
- 録画 46 はオートバースト ON（単騎なのでチェーンが切れ、ゲージは何度も 0 から溜まり直す）。055・070・071 は AUTO 射撃 ON・オートバースト OFF。

## 予測（撮る前に書く）

撮影はしない。既存の録画を読む。B のティックは `046-12` で 1 回分を見た後なので、その部分の予測は引きずられている。

| 仮説                                                                                | 見えるはずのもの                                                                |
| ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| S1: スキルのヒットは、段によらず 1 ヒットで `target_burst_energy_pershot`（25,000） | A・B・C のどのヒットも 1 ヒット 3.4px 前後（2.5%）。B は 3 ティックで 10px 前後 |
| S2: スキルのヒットは `burst_energy_pershot`（12,500）                               | どのヒットも 1.7px 前後。B の 3〜4px は合わない                                 |
| S3: 分配ダメージ（B・C）のティックだけが溜める（弾として飛ぶもの）。A は溜めない    | A のヒットのフレームではバーが伸びない。B・C のティックは 3.4px 前後            |
| S4: ゲージはダメージの大きさに比例する                                              | 大きいヒット（C）ほど大きく伸びる                                               |

見込み: S1 か S3。

- 外れたときの影響: 1 サイクル（フルチャージ 3 発）のゲージが、通常攻撃 3 発の 11.25% に対して、S1 なら +12.5%（A 1 + B 3 + C 1 ヒットなら 5 ヒット）でほぼ倍になる。ゲージが律速の 1 回目のフルバーストと、紅蓮BS を入れた編成の 20 秒周期の回に効く。

## 読み方

1. 録画 46・55・70・71 で `hud.ts --mode jumps` と `gauge.ts --mode series` を全フレーム回し、HUD の増分（1 ヒットの値）ごとに、そのフレームのバーの伸び（px）を取る。バーが 0px（本当の 12.6% 未満）や 113px（約 96% 以上）の区間、バーが見えないフレームは外す。
2. HUD の増分の値で、通常攻撃（207,265 など）・段 A・B・C のヒットに分ける（段の順は、フルチャージ攻撃の通算の回数でも確かめる）。
3. 種類ごとに 1 ヒットの伸び（px）の分布を出し、C-0084 の縮尺で本当の量に直して、仮説と比べる。
4. 満タン（バーが消える）までの合計でも確かめる: 0 から溜め始めた回で、通常攻撃と各段のヒットの数を数え、1 ヒットの量の仮説で合計が 100% に届くヒットと、バーが消えたヒットを比べる。
5. 読んだ値は観測値にする（`source` に `V-0029`）。

## 結果

読んだ日: 2026-09-28。観測値は `046-13`（1 ヒットの伸び）・`046-14`（満タンまでのヒット数）・`046-15`（段のヒットの遅れ）。

### 1 ヒットの伸び（`046-13`）

- 通常攻撃（フルチャージ）は 5px。C-0084 の縮尺で本当の約 3.7%（25,000 × 1.5 = 3.75%）。
- 段 A・段 B の 1 ティック・段 C は、どれも 3〜4px（本当の 2.2〜3.0%）。25,000（2.5% = 3.4px）と合う。B は 3 ティックで 3 回伸びる。C は大きなヒットでも 1 ティックぶん（3px）。
- 仮説 S2（12,500 = 1.7px）・S3（A は溜めない）・S4（ダメージに比例）は外れ。

### 満タンまでの合計（`046-14`）

- 単騎の 4 本とも、1 回目にバーが消えたのは通常攻撃の 20 ヒット目で、そこまでに段のヒットが 10 ヒット（A 1・B 3・C 1 の 2 巡）あった。通常攻撃 37,500 × 20 + 段 25,000 × 10 = 1,000,000 ちょうどで、1 つ前の通常攻撃（962,500）ではバーは 113px のまま消えなかった。
- 途中の px も、この足し方と C-0084 の縮尺から予測した値と 1px 以内で合う（046 の 1 回目の 1〜26 ヒット目）。
- 046 だけ、f1670 に総ダメージの増えない発があり、そのフレームにバーが 3px 伸びた。射撃の刻み（43f おき）の位置なので、的に当たらなかった発とみられる（V-0028 のデルタの当たらなかった発と同じく、半分ほど溜める）。これを足しても、消えるヒットは同じ。

### 段のヒットの遅れ（`046-15`）

- 直前の通常攻撃のヒットから、A・B の 1 ティック目・C は 1〜8f、B の 2・3 ティック目は 15〜21f・30〜36f。モデルでは射撃から 5f（B は 5・19・33f）に置いた。

### モデルの変更と残差

- 定義の書式に、段の `gaugeHits`（ゲージを溜めるヒットの、射撃からの遅れ）を足した（`skills/types.ts`・`skills/cycles.ts`）。1 ヒットは射手の `target_burst_energy_pershot`（フルチャージ倍率なし）× (1 + ゲージ速度)。弾丸命中率は掛けない。
- 1 パス目（`frame/firstPass.ts`）で段の循環を追い（規則は `skills/cycles.ts` の `cycleFires` と同じ。間隔の変更の窓はトリガーが自分の `burstUse` のものだけ扱う）、段のヒットのゲージを当たるフレームに予約する。窓の中の段（フルバースト中）は、状態機械が溜め中でないのでゲージには入らないが、段のポインタは進める。
- `data/skills/225.json` の S1 の 3 段に `gaugeHits` を書いた。
- テスト: 1 パス目の予約が `planSkillHits` の段と遅れから出したものと一致すること、単騎で通常攻撃 20 発目に満タンになること、定義が無ければ 27 発目になること、書式の検査。録画 47 の予測のフルバーストの開始は 646 → 497（V-0028 の前と同じ）に戻り、V-0028 で `it.fails` にした FB1 の段の並びのテストは `it` に戻した。
- 残差（`npm run records:check`）: `047-11`（録画 47 の 1 回目の満タン）は +160f → +11f、`047-02`（紅蓮BS の与ダメージ）は −4.07% → +0.33% で、どちらも許容内に戻った。ほかの値は変わらない。
- 単騎の 1 回目の満タンは、戦闘開始から数えるとモデルが約 34f 早い（実測 046 1,153f・055 1,152f・070 1,152f、モデル 1,118f）。満タンに届く発（通常攻撃 20 発目）は同じなので、差は射撃の刻み（リロードの間隔など。roadmap「3 分モードの射撃の細部」の紅蓮BS 単騎の空き）で、ゲージの量ではない。比べる観測値にはしていない。

## 分かったこと・分からないこと

- **S1 が当たり**: 段のヒットは段によらず 1 ヒットで `target_burst_energy_pershot`（フルチャージ倍率なし）→ C-0085 を確定（厳密一致）にした。
- 分からないこと:
  - ほかのキャラの倍率ダメージ（射撃の回数トリガーのダメージ、分配ダメージ、バーストスキル）のヒットでもゲージが溜まるか。モデルに入れたのは紅蓮BS の S1 の段だけ。V-0028 で合った編成（ドレイク・イサベル・アスカなど）は、溜まるとしても 1 回目の満タンまでのヒットが少ないか、溜まらない。
  - 当たらなかった発のゲージ（046 の f1670 は 3px。V-0028 のデルタは約半分）。

## 次に撮るもの

撮影は要らない。ほかのキャラの倍率ダメージがゲージを溜めるかは、既存の単騎の録画（ドレイク 36 など）で同じ読み方をする。
