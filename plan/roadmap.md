## Stage 1: core 最小版 — キャラの素のステータス

- **入力**: Blablalink 公開 CDN（キャラ一覧・キャラ詳細 JSON）
- **処理**:
  - パス難読化を解決して CDN からキャラ一覧・レベル別ステータス・武器種を取得し、JSON 化するスクリプト
  - レベル・限界突破・コアから最終攻撃力を算出する関数
  - 武器種ごとの基本パラメータ（発射レート・装弾数・リロード時間・武器倍率・チャージ仕様）のデータ定義
- **出力**: リポジトリ同梱の正規化済みキャラデータ、攻撃力算出 API
- **検証**: 算出した攻撃力が数体分ゲーム内表示と一致する
- **完了条件**: 全キャラの取得が成功し、攻撃力の一致テストが通る

## Stage 2: calc v1 — 通常攻撃のみの静的 DPS

- **入力**: ニケ 1 体（レベル・限界突破・コア）、敵（防御力・属性・コア有無）、コア命中率、距離ボーナス有無
- **計算**:
  ```
  1発期待ダメージ = (攻撃力 − 防御力) × 武器倍率 × (1 + コア期待値 + 会心期待値 + 距離) × 属性有利
  DPS            = 1発期待ダメージ × 秒間発射数（装弾数・リロード時間から平均化）
  総ダメージ      = DPS × 180
  ```
- **出力**: 1 発あたり期待ダメージ、DPS、180 秒の総ダメージ
- **スコープ外**: スキル・バフ・バーストは一切なし
- **検証**: 射撃場の実測値と比較
- **完了条件**: 武器種 6 種それぞれで実測との差が説明可能な範囲に収まる

## Stage 3: calc v2 — 5人編成の合算

- **入力**: 5 枠の編成（各ニケの育成 3 項目）、敵設定
- **計算**: Stage 2 の計算を 5 体分行い合算
- **出力**: キャラ別内訳と合計
- **スコープ外**: まだスキル・バフなし
- **検証**: 各キャラ単体の結果の和と一致する

## Stage 4: スキルモデル段階 A — 常時発動パッシブ

- **入力**: スキル定義 JSON（無条件・常時の自己/味方ステータス上昇のみ）、スキル Lv
- **処理**:
  - DSL の最小語彙を設計（対象・ステータス種別・値の参照先）
  - 数値は Blablalink の `description_value` のインデックス参照にし、スキル Lv に追従させる
  - 対象キャラを数体だけ定義
- **出力**: 常時バフを反映した calc の結果
- **検証**: スキル Lv を変えると数値が追従する。未定義キャラは「未対応」と表示される

## Stage 5: 固定サイクルのフルバースト

- **入力**: バーストサイクル長（手入力、既定 20 秒）、フルバースト時間
- **計算**: サイクルを「フルバースト区間 / 非区間」の 2 区間に分けて期待値化。バーストスキルの倍率ダメージ（1 回分）をサイクルごとに加算
- **スコープ外**: CT 短縮
- **検証**: フルバースト稼働率 0% / 100% の極端値で Stage 3 の結果と整合する

## Stage 6: スキルモデル段階 B — バースト時トリガーの持続バフ

- **入力**: 「フルバースト時に N 秒間 攻撃力 +X%」型のスキル定義
- **処理**: バフの付与/失効タイミングでサイクルを区間に分割するアルゴリズムを導入（固定サイクル前提なので静的に分割できる）
- **検証**: 持続時間がサイクル長以上のとき常時バフと一致する

## Stage 7: sim v1 — 通常攻撃のフレームシミュ

- **処理**: 60fps で発射・弾数・リロード・チャージを再現。スキルなし
- **検証**: calc v1（Stage 2）の結果と一致する整合性テスト
- **完了条件**: 武器種 6 種で calc と sim の差が許容範囲内

## Stage 8 以降（順序は設計フェーズで決める）

- sim: バーストゲージ蓄積・バースト段階・バフ持続
- スキルモデル段階 C: 発射数トリガー・フルチャージトリガー・条件付き（HP 等）
- スキルモデル段階 D: CT 短縮・最終弾トリガー・スタック。sim 優先で実装し、calc は近似
- 育成入力の拡張: OL 装備・キューブ・好感度・企業タワー
- 公開準備: GitHub パブリックリポジトリ化、ライセンス表記、データ同梱可否の確認、GitHub Actions による GitHub Pages デプロイ
- アカウント連携の検討
