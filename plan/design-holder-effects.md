## 0. 目的と方針

- 目的: 実機と同じく、効果を受けるキャラ（持ち主）ごとに「いま受けている効果の一覧」を持ち、フレームごとに起きた出来事で一覧を変える形に組み直す。2 段目の語彙（消去・解除・切り替え・スタックの操作・状態の出来事・バリアなど。[design-skill-catalog.md](design-skill-catalog.md) 9 節の段の候補 1〜4）を、段を足さずに一覧の操作として書けるようにする。
- 方針:
  1. **値を変えない**。各段で、計算の結果と表示がいまと同じであること（浮動小数の足し算の順による末尾の差は除く。論点 5）を確かめる（4 節）。モデルの値を変えないので、結論は作らず、変えない。
  2. **読む側は一つずつ移し、最後に窓を消す**。段 A〜C の間は、窓（`BuffWindow` など）と記録を一覧の履歴から書き出し、読む側（ダメージの式・calc・sim・観測値の指標・画面）は変えない。段 D で、読む側を一つずつ一覧・履歴を直接読む形に移し、段 E で窓の書き出しを消す。区間は窓ではなく、履歴を値の変わり目で切ったものなので残す（論点 9）。
  3. **段の制約は再現する**。いまの段（1・1.5・2・2.5 段目）が判定に入れる窓の範囲を、一覧の件に付けた段の印で再現する。制約を外すのはモデルの変更なので、根拠ができてから 1 つずつ（論点 2）。
  4. **定義と語彙は変えない**。スキル定義の JSON と DSL の型は触らない。[design-named-state.md](design-named-state.md) 8 節の後の拡張の語彙の形（`selfState`・`removeOn`・`group`・`{ ended }`・`while`・敵に付く状態）はそのまま使い、実装の置き場所（段の位置と「解除で切る」段。同 8.5 節）だけを一覧の操作に置き換える。

## 1. いまの作り

いまの作り（効果の持ち方・窓の作り方・1 パス目のループ・困る所）は、別紙 [design-holder-effects-current.md](design-holder-effects-current.md)（以下「いまの作りの別紙」）に置く。節の番号は本体と同じで、この設計書で 1 節の番号（1.3 節など）を挙げたときは、いまの作りの別紙の節を指す。

- **1.1 効果の持ち方**: 持続バフ・状態・循環の間隔の変更は窓、吸収回復の維持は内部の終わりのフレーム、常時の効果は枠ごとの常時の値、敵の受けるダメージ▲は味方全員の窓、敵の状態は出どころの無い区間、即時効果はその瞬間の記録で持つ。
- **1.2 2 パス目の窓の作り方**: 効果ごとに「発火 → 受け手 → 窓」を作り、効果どうしが見合う所を 1・1.5・2・2.5 段目の順に閉じる。段の制約は、実機で確かめた規則ではない。
- **1.3 1 パス目のループ**: 射撃に効く stat などの窓だけを追い、ループの後で 2 パス目がすべての窓を作り直す。1 パス目で窓を追う stat には、段が要る語彙を書けない。
- **1.4 いまも受け手ごと**: 窓も持続時間も受け手ごとなので、いまの語彙の範囲では、キャラごとに効果を持つ実機と同じ値になる。
- **1.5 困る所**: 後からまとめて作る・段で閉じる・二重の実装・敵が持ち主でない。

## 2. 組み直した形

### 2.1 用語

- **持ち主**: 効果を持つ側。味方の枠と、敵（1 体の前提）。目録の `StateHolder`（`ally`・`enemy`）と同じ語。
- **件**: 一覧の 1 行。いまの窓の和集合の単位にあたる（出どころ × 効果 × 持ち主。状態は出どころ × 状態 × 持ち主）。付き直しは同じ件を延ばし、外れた後に付けば新しい件になる。
- **一覧**: 持ち主ごとの、いま持っている件（付いた順）。
- **履歴**: 件の一生（付いた・延びた・スタックが増えた・外れた）の記録。窓・区間・記録はここから書き出す。件は外れても消さずに履歴に残し、一覧はいま効いている件への索引にする。

### 2.2 件の形（案。名前は仮）

```ts
/** 持ち主。味方の枠と、敵（1 体の前提） */
type Holder = { kind: 'ally'; slotIndex: number } | { kind: 'enemy' };

/** 一覧の 1 件 */
type HeldEffect = {
  holder: Holder;
  /** 付けた枠 */
  sourceSlotIndex: number;
  /** 何の件か。同じ持ち主で、出どころとこれが同じなら同じ件（付き直し） */
  item:
    | { kind: 'passive'; effect: ResolvedEffect }
    | { kind: 'timed'; effect: ResolvedTimedEffect }
    | { kind: 'state'; state: NamedStateId; contents: ResolvedStateContent[] }
    | { kind: 'healWindow'; effect: ResolvedInstantEffect }
    | { kind: 'cycleEvery'; effect: ResolvedCycleEvery }
    | { kind: 'enemyState'; state: NamedStateId };
  /** 付いたフレーム（付き直しでは変えない） */
  start: number;
  /** 終わり方: フレーム（秒・持続・戦闘の終わり）、持ち主の発数、出来事 */
  until: { frame: number } | { shots: number; counted: number } | { event: 'fullBurstEnd' | 'ammoSpent' };
  /** スタックする件の、段 k の始まり（k − 1 番目）。スタックしない件はキーごと無い */
  stackStarts?: number[];
  /** 段の印（2.5 節） */
  stage: 1 | 1.5 | 2 | 2.5;
};
```

- 値は件に持たせない（解決済みの効果の値を読む）。確率のきっかけの件は機会の列を持ち、強化の件は付いた瞬間の参照の値を持つ（いまと同じ式で値を出すため。2.6 節）。
- 書き出しに要る印も件に持つ（状態の件に、射撃の回数のトリガーの付与が発火を足したか。いまの `NamedStateWindow.shotCount`）。
- 常時の件（スキルの常時パッシブと、静的な状態）は、戦闘の始めから終わりまでの件で、段の印は 1（いまの常時の値と同じく、どの判定にも入る）。育成の効果層は件にせず、持ち主の常時の値として持つ（論点 3 の決定の読み）。
- 解除不可の印など、2 段目の語彙が要る欄は、その語彙を足す時に足す（使い手のいない欄は入れない）。
- 段 A の実装（`skills/holders.ts`）: 件の列（`HeldTrack`。出どころ × 効果 × 持ち主。状態は出どころ × 状態 × 持ち主）が、発火の始まりの列と段の印を持ち、件（`HeldItem`）は始まりの列から作る（2.7 節）。確率のきっかけの件の列は機会の列を持ち、強化は件の列にせず、発火の始まりだけを持ち、ループの後に履歴を閉じる時に受け付けと値の小片を決める（`amplify`。段 A までの 2.5 段目と同じ作り方。段 B で書き出しから移した）。

### 2.3 一覧の操作

1. **付ける**: 発火 1 つを、対象の持ち主ごとに一覧へ入れる。同じ件があれば延ばす（終わりを、その発火からの終わりと比べて遅い方にする。発数の維持は数え直す）。スタックする件は段を 1 つ足し、全段の終わりを数え直す（いまの `STACK_REFRESH` の `all`）。同じ件が無ければ新しい件を作る。
2. **続きとみなす境目**は、件の種類ごとにいまの規則のまま。
   - 持続バフ・状態・循環の間隔の変更・スタック: 終わりのフレームちょうどの付き直しも続き（いまの和集合の `f ≤ end`）。
   - 吸収回復: 終わりのフレームちょうどに付けば、新しく付いた（`healed` を起こす。`createHealWindow` の `f < end`）。
3. **外す**: 終わりに達した件は、そのフレームの付与を済ませた後に一覧から外す（終わりのフレームちょうどの付き直しを続きにするため）。出来事で終わる件は、その出来事のフレームで閉じる。
   - 発数: 持ち主の N 発目の射撃の次のフレーム。付いたフレームの持ち主の射撃も数える（いまの `shotCountWindows` が `f ≥ s` の射撃を数えるため。ループでは手順 1 の射撃が先に済んでいるので、付ける時に同じフレームの射撃を数えに入れる）。
   - フルバーストの終わり: 付いた後に来る最初の終わり。
   - 撃ち切り: 1 パス目が基礎の武器に戻すフレーム（`weaponChangeEnds`）。
4. **値を出す**: 持ち主のフレーム f の値は、常時の件の値と育成の効果層に、ほかの `start ≤ f < end` の件の値を付いた順（時刻の順。論点 5）に足したもの（スタックは効いている段の数だけ）。常時の件と育成の効果層を先に足すのは、いまの常時の値と同じ順。
5. **見る**: 条件・順位・強化の参照は、段の印で見える件だけを見る（2.5 節）。
6. **書き出す**: 履歴から、いまの形の窓・区間・記録を作る（段 E まで。2.6 節）。

### 2.4 フレームの中の順番

1 パス目の手順 1・2（射手、ゲージと状態機械）はいまのまま。手順 3 は、いまの順を段で並べ直し、段 1 にすべての stat を入れる。

回復 → 段 1 の件（条件なし・順位の対象でない効果と付与）→ 段 1.5 の件（条件つき）→ 段 2 の件（順位の対象）→ 段 2.5 の件（強化）→ 即時効果

- 常時の件は、ループの前（フレーム 0）に一覧に入れる（いまの戦闘開始時の窓と同じく、1 発目から効く）。1 パス目より前に常時の値を読む所（着地点の計画 `planLandings`、ゲージの量の前計算）は、この初めの一覧の値を読む。常時の件が途中で外れうる語彙（効果解除など）を足す時に、フレームごとに読む形に直す。
- いまの順（1.3 節）と同じ結果になる。手順 3 の中の順が効くのは、同じフレームに付いた件が判定に入るかと、弾丸チャージが同じフレームに付いた最大装弾数▲を見るかだけで、どちらも段の順で決まる（条件は段 1、順位は段 1・1.5 の同じフレームの件を見る。即時効果はすべての件の後）。射手は f − 1 までに付いた件しか見ないので、手順 3 の中の順に依らない。

### 2.5 段の印（いまの見え方の再現）

| 見る側                                                                 | 見える件                                                                                                     | いまの出どころ      |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------- |
| 射手（最大装弾数・リロード・チャージ・装弾数無限・使用武器の変更など） | 射撃に効く stat の件。f − 1 までに付いたもの                                                                 | 1 パス目の手順 1    |
| 当たり（ゲージ・命中の期待値）                                         | 当たりの stat の件（条件なし・順位の対象でない効果と、状態の中身）。f − 1 までに付いたもの                   | 1 パス目の手順 1    |
| 条件 `selfBuffed`                                                      | 育成の効果層と、段 1 の件（常時の件と、同じフレームに付いたものを含む）                                      | 2 パス目の 1.5 段目 |
| 順位（最終攻撃力）                                                     | 育成の効果層と、段 1・1.5 の攻撃力の件（常時の件と、同じフレームに付いたものを含む。確率のきっかけは期待値） | 2 パス目の 2 段目   |
| 強化の参照                                                             | 同じ出どころ・スロット・stat の、段 1〜2 の件（同じフレームに付いたものを含む）                              | 2 パス目の 2.5 段目 |
| 区間（ダメージの式）                                                   | すべての件（状態だけの stat は、着地点の計画があり持続の命中率▲を使う時だけ命中率に足す）                    | 2 パス目の区間      |

- 状態の件の段は、その状態の付与のいちばん後の段（いまと同じ）。
- 表の細部はいまのコードが正で、新旧の比べ（4 節）で確かめる。

### 2.6 書き出し（段 A〜D の橋渡し）

- 書き出しは、読む側を移し終えるまでの橋渡しで、段 E で消す（区間は残す。論点 9・10）。段 A〜C の区間は、書き出した窓からいまの組み立て方で作り、段 D の 1 で履歴から作る形に移す。
- 書き出すもの: `BuffTimeline` の各欄（`windows`・`stateWindows`・`namedStateWindows`・`applications`・`conditionSkips`・`rankings`・`heals`・`cycleWindows`・`segments`）。形と意味はいまのまま。`FirstPassResult` の窓の欄（`firingWindows`・`rankAttackWindows`・`hitWindows`・`namedStateWindows`。テスト用）は、段 B でテストを移した後に読む所が無くなったので消した。
- 件 1 つからの書き出し:
  - 和集合の件: 窓 1 つ。
  - スタックする件: 段ごとの窓（いまの `stackWindows` と同じ）。
  - 確率のきっかけの件: 期待値の小片（いまの `chancePieces`）。
  - 強化の件: 参照する件が効いている所と、切れた所の小片（いまの 2.5 段目の作り方）。
  - 状態の件: 状態の窓と、中身ごとの窓。
- 常時の件は、窓ではなく、いまと同じく常時の値（`passive` と区間の常時の効果）に書き出す。
- **並び**: 時刻の順（論点 5）。窓は始まりの順、記録はフレームの順にし、同じフレームのものは手順 3 で付けた順（段 → 出どころの枠 → 定義の順 → 持ち主 → スタックの段）に並べる。区間の値もこの順に足すので（[design-stage6.md](design-stage6.md) 9 節の浮動小数の加算順を、窓の作る順から時刻の順に改める）、いまの値と浮動小数の末尾が変わりうる。
- 区間の鍵（`slotKeys`）に入れる効果の出どころは、定義の順（出どころの枠 → スロット → 効果 → 中身）に並べ直す（段 A）。区間の中の効果は時刻の順なので、そのまま鍵に入れると、同じ効果の組の区間が、付いた順の違いで別のグループに割れる。いまの作る順も効果ごとに窓がまとまっていたので、グループの分け方は変わらない。

### 2.7 件を作るのは 1 パス目だけ（段 A から）

- 1 パス目のループが、すべての件を一覧で持つ（射撃に効く stat などだけを追うのをやめる）。射手・当たり・条件・順位・強化の参照・弾丸チャージは、一覧を直接読む。順位の材料（`skills/ranking.ts` の `finalAttacksAt`）の入力も、窓の列から一覧の件に替える。
- `planTeamRun`（`frame/plan.ts`）は、1 パス目の履歴から書き出す。2 パス目での作り直しはやめ、`planBuffTimeline` の入口も消す（論点 4）。出来事の列の流し直し（`replayEvents`）は、倍率ダメージの発動（`planSkillHits`）が使うので残す。
- 手で射撃の列と時刻表を与えて窓を確かめていたテストは、1 パス目から作る形に書き直す（段 B）。
- 窓を作る関数のうち、始まりの列から件を作るもの（`unionWindows`・`shotCountWindows`・`untilNextEndWindows`・`effectWindows`・`stackWindows`・`chancePieces`）は、段 A で件の作り方として一覧が使う形にした（件の列は発火の始まりの列を持ち、入力（始まり・機会・持ち主の射撃・撃ち切り・フルバーストの窓）が変わった時に件を作り直す。撃ち切りで終わる件とフルバーストの終わりで終わる件は、`untilNextEndWindows` に終わりの列を渡す。段 B で `untilWeaponChangeEndWindows` から名前を改めた）。旧の実装だけが使う関数（`untilFullBurstEndWindows`・`selfBuffedAt` など）は、段 B で旧の実装と一緒に消した。
- 窓を作るコードが 1 つになるので、1 パス目で窓を追う stat に書けない語彙の制限（1.3 節）は要らなくなる。制限を外すのは、使うキャラの定義の時（使い手のいない語彙は入れない）。

### 2.8 敵を持ち主にする（段 C）

- 敵の受けるダメージ▲（`damageTaken`）を敵の件にする。値は、いまと同じく味方の各枠の区間の値に足す（敵 1 体の前提で、敵が受ける全ダメージに掛かる。C-0138）。書き出しも、いまと同じく味方の各枠の窓にする（[design-named-state.md](design-named-state.md) 8.3 節の「味方全体の窓に写す」と同じ）。
- バーストのヒットが、ヒットのフレームの敵の側のデバフを見る規則（`burstHitBuffs`。C-0163・C-0167）は、敵の件をヒットのフレームで読む形になる。値は変わらない。
- 敵の状態（持続ダメージが付けるハッキングなど）を敵の件にし、出どころを持たせる。始まりと終わりは、いまの `dotActiveSpans`（最初の発火から最後の tick まで）のまま。条件 `enemyState` は敵の一覧を見る（どの出どころの件でもよい。いまと同じ）。
- 検証を広げる: 敵の件になる効果には、持ち主ごとに違いうる絞り込みと維持（自分を除く・状態・バースト段階・発数の維持など）を書けないようにする。いまの定義の `damageTaken` は、どれも対象が味方全体で絞り込みが無い（2026-10-15 に確かめた）ので、値は変わらない。

### 2.9 履歴を読む形（段 D・E）

段 D で読む側が直接読むのは、次の 3 つ（名前は仮）。どれも、段 A〜C の間に窓と記録を書き出している元そのもので、新しく作るものではない。

- **件と出来事**: 件（2.2 節。外れた件も残す）と、件ごとの出来事（付いた・付き直した・スタックが増えた・外れた）。いまの窓・状態の窓・循環の窓・付いた記録（`applications`）に当たる。
- **値の小片**: 値が時間で変わる件（確率のきっかけ・強化）の、値の変わり目の列。いまの期待値の小片・強化の小片に当たる。
- **判定の記録**: 条件を満たさずに発火しなかった記録・順位の記録・回復の記録（いまの `conditionSkips`・`rankings`・`heals`）。

```ts
/** 件の出来事 */
type HeldEvent = { frame: number; item: HeldEffect; kind: 'applied' | 'refreshed' | 'stacked' | 'ended' };

/** 履歴 */
type HolderHistory = {
  /** 件（付いた順。外れた件も残す） */
  items: HeldEffect[];
  /** 出来事（フレーム順） */
  events: HeldEvent[];
  /** 判定の記録（いまの conditionSkips・rankings・heals） */
  skips: ConditionSkip[];
  rankings: RankingRecord[];
  heals: HealRecord[];
};

/** 件の絞り込み */
type HeldEffectFilter = Partial<{ holder: Holder; sourceSlotIndex: number; skill: SkillSlot; stat: BuffStat }>;

/** フレーム f に持ち主に効いている件（一覧） */
declare function activeAt(history: HolderHistory, holder: Holder, frame: number): HeldEffect[];
/** 絞り込んだ件（付いた順） */
declare function itemsOf(history: HolderHistory, filter: HeldEffectFilter): HeldEffect[];
/** 件の出来事（フレーム順） */
declare function eventsOf(history: HolderHistory, item: HeldEffect): HeldEvent[];
```

- 段 B で、件を読む関数 `itemsOf`（絞り込んだ件。時刻の順）・`activeItemsAt`（持ち主にフレーム f に効いている件）と、強化の値の小片（`HolderHistory.amplified`）を置いた（`skills/holders.ts`。件は `HeldItemView`）。出来事（付き直し・外れた）の読み方は、使う読む側を移す段で足す。
- 区間は、件と値の小片から作る（段 D の 1）。境目は、件の始まり・終わりと値の小片の変わり目に、いまと同じくフルバーストの端・発動・着地点の境目を足したもの。段 E の後に `BuffTimeline` に残るのは、区間と履歴。

### 2.10 範囲の外

- 段の制約を外すこと（論点 2）。
- 2 段目の語彙。組み直しの後に、一覧の操作として足す（6 節）。
- スキル定義の JSON と DSL の型。
- 常時の値・即時効果・持続ダメージと自動攻撃の tick（論点 3・8）。
- 射手・バーストの状態機械・1 発の式。calc・sim・画面・観測値の指標は、段 D で読む形だけを移す（計算の結果と表示は変えない）。
- 観測値の指標の名前（`buffWindowStarts` など）。観測値のファイルが名前で参照しているので、読む形を移しても名前は変えない。

## 4. 確かめ方（各段の完了の条件）

1. `npm test` が、テストの期待値を変えずに通る（窓と区間の形を見るテストが、そのまま退化の確かめになる）。足し算の順で値の末尾が変わるテストだけ、許容つきにする（論点 5）。
2. 新旧の比べ（論点 6）で、`BuffTimeline` と `FirstPassResult` が一致する（段 A〜C）。並びは時刻の順に揃えて比べ、値は足し算の順で生じる差（相対 1e-12 程度）だけを許す。
3. `npm run records:check` で、生成物（`plan/residuals.md`・`plan/claims.md`・`plan/skills.md`・`plan/minimal.md` など）の差分が値の末尾だけで、許容の内外・結論は変わらない。
4. `npm run records:minimal` で、感度（`records/minimal/sensitivity.json`）の「効きうるか」が変わらない（値の差は末尾だけ）。
5. 速さ（論点 7）を測って経過に書く。
6. CI と同じ確認（AGENTS.md のコミット手順の 2）が通る。

比べで差が出たら、新しいコードの誤りとして直す。ただし、差の出どころがいまの 1 パス目と 2 パス目の食い違いだと分かった時は、どちらに合わせるかがモデルの変更になるので、直さずにオーナーに諮る。

段 D の各段では、2 の代わりに、移す読む側の結果を、窓を読む形と履歴を読む形の両方で同じ実行の中で出して比べる（区間・倍率ダメージの発動・calc と sim の結果・sim の記録の出来事・観測値の予測・画面に出すまとめ）。窓がまだあるので比べられる。比べのコードはその段の中だけに置き、段を閉じる時に消す。窓で数えていた所（スタックの段ごとの窓を 1 つずつ数える指標など）で、件で数えると値が変わる時は、直さずにその段で諮る。

段 E では、1・3〜6 が段 D の終わりと同じ結果（生成物に差分が出ない）で、窓の型を消しても typecheck が通る（窓を読むコードが残っていない）ことを確かめる。

## 5. 危険と対策

- **境目の規則の取り違え**（付き直しの `f ≤ end` と吸収回復の `f < end`、発数の数え始め、射撃の回数のトリガーの f + 1、使用武器の変更の頭の 1 フレーム（`weaponStartTrim`））: 件の種類ごとの単体テストと、新旧の比べで拾う。
- **足し算の順**: 時刻の順に変えるので（論点 5）、値の末尾が変わる。比べとテストの許容は、足し算の順だけで生じる差（相対 1e-12 程度）に絞り、それより大きい差は誤りとして調べる。区間の鍵（`keyOf`）は値を 6 桁で丸めるので、丸めの境目で区間のまとまりが変わることがある（calc の値は許容の中で変わる）。
- **後から付いた件が勝つ stat**: 使用武器の変更は、後から付いた件の武器を使う（`applyResolvedEffect`）。並びを時刻の順に変えると、2 つの変更が重なる時に選ぶ件が変わりうるが、いまの定義では 1 体に 1 つしか無いので値は変わらない（2026-10-15 に確かめた）。2 つ目を持つ定義を足す時に、選び方を確かめる。
- **段の見え方の取り違え**: 2.5 節の表を単体テストにする（見る側ごとに、同じフレームに付いた件と、後の段の件が見えるか）。
- **1 パス目が重くなる**: すべての件を毎フレーム追う。一方で、2 パス目の作り直しは無くなる。前後を測る（論点 7）。
- **段 D の間の 2 つの読み方**: 窓と履歴の両方が出ている間は、読む側が混ざりうる。移した読む側からは窓の参照を消し、どの読む側をどの段で移したかを経過に書く。
- **画面の結果の型を替える**（段 D の 6）: `TeamSlotResult` を読む所（画面・記録の道具・テスト）を同じ段で直す。表示が変わらないことは、画面のまとめを作る所を純関数に切り出し、窓から作ったまとめと履歴から作ったまとめを比べて確かめる。

## 7. 論点

決定（2026-10-15、オーナー）: 論点 1・2・6〜11 と、段 A〜C の構成（3 節）は推奨どおり。段 D・E はオーナーの指示で足した。論点 3・4・5 は代わりの案（論点 3 は決定の読みを付けた。論点 4 に合わせて段 A・B の中身を組み替えた）。

1. **組み直す時期**（決定: 推奨どおり）
   - 推奨: 2 段目の段の候補 1（自分の状態の条件と外れ方）より前。段の候補 1〜4 の語彙はどれも一覧の操作なので、先に組み直せば、二重の実装と段の追加を避けられる。
   - 代わりの案: 2 段目の語彙を足しながら、要る所から組み直す。
2. **段の制約**（決定: 推奨どおり）
   - 推奨: 当面は件の段の印でいまの見え方を再現する。外すのはモデルの変更なので、根拠（検証）ができてから 1 つずつ。
   - 代わりの案: 組み直しと同時に外し、実機と同じく起きた順に見る。値が変わりうる。
3. **一覧に入れる範囲**（決定: スキルによる効果は、常時の値であっても一覧に入れる）
   - 推奨: いま窓を持つもの（持続バフ・デバフ、状態、吸収回復の維持、循環の間隔の変更）と、敵の受けるダメージ▲・敵の状態（段 C）。常時の値（常時パッシブ・静的な状態の中身・育成の効果層）は件にしない（変わらないので件にする利点が無く、着地点の計画など 1 パス目より前に読む所もある）。即時効果も件にしない（その瞬間に CT・弾数・ゲージを変えるだけ）。
   - 代わりの案: 常時の値も件にする。効果解除・消去の相手になる時に揃うが、読む所が増えて段 A が大きくなる。常時の効果を外す語彙を足す時に件にすれば足りる。
   - 決定の読み: 推奨の範囲に、スキルの常時パッシブと静的な状態（中身つき）を、戦闘の始めから終わりまでの件として足す（2.2・2.4 節）。育成の効果層（OL・キューブ・コレクション）はスキルによる効果でないので、持ち主の常時の値のまま。即時効果は、値を持ち続けないので件にしない（決定は常時の値について。即時効果の扱いは推奨のまま）。
4. **2 パス目の入口（`planBuffTimeline`）**（決定: 代わりの案。入口を消し、テストも 1 パス目から作る）
   - 推奨: 残し、中身を一覧の流し直しにする（段 E の後は、区間と履歴を返す）。テストが射撃の列と時刻表を手で与えて、効果の始まりと終わりを確かめているため。本番（`planTeamRun`）は 1 パス目の履歴を使う。
   - 代わりの案: 消して、テストも 1 パス目から作る。テストの書き直しが大きい。
   - 決定の読み: 件を作るのは 1 パス目だけにする（2.7 節）。一覧の流し直しは作らず、段 A で 1 パス目に一覧を入れる。手で射撃の列と時刻表を与えていたテストは、段 B で 1 パス目から作る形に書き直し、旧の実装と同じ場面で比べてから旧の実装を消す（3 節）。
5. **書き出しの並び**（決定: 代わりの案。時刻の順にする）
   - 推奨: いまの並びを再現し、値をビット単位で同じにする。新旧の比べを等価で見られる。段 E の後も、区間の値を足す順（件の並び）としてこの順を使う。
   - 代わりの案: 時刻の順にする（読みやすい）。浮動小数の末尾が変わりうるので、比べと一部のテストを許容つきにする。
   - 決定の読み: 窓・件・記録を時刻の順に並べ、同じフレームのものは手順 3 で付けた順にする（2.6 節）。区間の値もこの順に足す。比べと一部のテストの許容は、足し算の順だけで生じる差に絞る（4・5 節）。
6. **新旧の比べ方**（決定: 推奨どおり）
   - 推奨: 段 A・B の間だけ旧の実装を残し、比べの仕掛け（`planTeamRun` の中で旧の実装も回し、時刻の順に揃えて比べ、値は足し算の順で生じる差だけを許し、食い違えば例外にする）を置く。仕掛けは、テストの準備と記録の道具からだけ入れるスイッチにする（画面の計算には入れない）。仕掛けを入れて `npm test`・`records:check`・`records:minimal` を回せば、テストの全編成・録画ごとの条件・感度の変種で比べられる。段 B を閉じる時に旧の実装ごと消す。
   - 代わりの案: 比べを、録画ごとの条件の編成だけを流す固定のテストにする。仕掛けは要らないが、テストの編成と感度の変種を比べない。
7. **速さ**（決定: 推奨どおり）
   - 推奨: 目安は置かず、各段の前後で `npm test` と `records:minimal` の時間を測って経過に書く。遅くなった時は、原因を調べてから諮る。
   - 代わりの案: 目安（例: 1.5 倍以内）を完了の条件にする。
8. **持続ダメージ・自動攻撃**（決定: 推奨どおり）
   - 推奨: この組み直しでは件にしない（tick の刻みとゲージの予約は `frame/dot.ts` の追跡のまま）。敵の状態だけを敵の件にする（段 C）。持続ダメージを外す語彙などが要る時に、件にするかを決める。
   - 代わりの案: 持続ダメージを敵の件にし、tick を件から出す。段 C が大きくなる。
9. **区間を残すか**（段 D・E。決定: 推奨どおり）
   - 推奨: 残す。区間は窓ではなく、履歴を値の変わり目（件の始まり・終わり、値の小片、フルバーストの端、発動、着地点の境目）で切ったもの。calc はこの単位でグループにして式を呼び（[design-stage6.md](design-stage6.md) 8 節の 5）、sim も同じ区間の値を読むので、sim と calc が同じ値を読む形が保てる。段 D の 1 で、窓からではなく履歴から作る形に移す。
   - 代わりの案: 区間もやめ、sim は一覧の値をフレームごとに読み、calc は履歴から自分のグループを作る。値の出し方が sim と calc で 2 つになり、整合のテスト（`simCalc.test.ts`）の前提が変わる。
10. **記録の欄も消すか**（段 E。決定: 推奨どおり）
    - 推奨: 消す。付いた記録・発火しなかった記録・順位・回復は、履歴が出来事と判定の記録として持つので、`BuffTimeline` に別に書き出すと二重になる。読む側（`frame/plan.ts` の `{ applied }`・観測値の指標・画面）は、段 D で履歴を読む形に移す。
    - 代わりの案: 記録の欄は残し、窓だけを消す。段 D で移す読む側が少なくて済む。
11. **2 段目を始める時期**（決定: 推奨どおり）
    - 推奨: 段 E の後。2 段目の語彙を、窓の書き出しと、移す前の読む側を気にせずに書ける。
    - 代わりの案: 段 C の後に始め、段 D・E と並べて進める。早く始められるが、段 E までは、2 段目の語彙が作る件の変化（途中で外れる・切り替わる）も窓に書き出し、移す前の読む側が正しく読めることを確かめる必要がある。
