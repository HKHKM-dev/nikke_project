# V-0169: クラウンの S2（リラックスの回復と攻撃ダメージ▲）は説明文どおりか（録画 056 の読み直し）

- 問い: クラウンの S2 を「通常攻撃 43 発ごとにリラックスを 1 スタック、20 スタックで解除して自分を回復し、回復が適用された時に味方全体へ攻撃ダメージ▲（7 秒）」と読んで、モデルは単騎 AUTO の録画 056 と合うか
- 話題: スキル・キャラ固有
- 日付: 2026-10-05
- 録画: `056`
- 状態: 調査中

## 条件

- 目的: クラウン（330）の S2 の効果（回復・回復時の攻撃ダメージ▲）を結論に結び付ける（plan/design-skill-claims-5-2.md 3.2 節の決定。最小構成の録画だけ読み直す）。
- 録画 `056` はクラウン単騎・AUTO・自動バースト OFF・スペック固定 ON・灼熱の的・3 分モード。単騎なので未確定の要素はクラウン自身だけ（最小構成）。バーストを使わないので S1・バーストは出ない。
- 説明文（`packages/core/data/characters/330.json` の skill2）は「通常攻撃で 43 回**攻撃した**時」にリラックス 1 スタック、20 スタックで解除して回復、「回復効果が適用された時」に味方全体へ攻撃ダメージ▲（7 秒）。定義は `data/skills/330.json` の skill2（heal の `everyRef`・`stacksRef` と、`healed` の timed）。
- 前に読んだもの: `056-04`（▲の窓の長さ。V-0004）は、説明文の倍率（×1.2099）で▲の発を見分けて読んだ。▲の 1 ヒットの値そのものと、回復の間のヒット数は読んでいない。`056-08`（的のジャンプで切った区間ごとのヒット数）は区間の切れ目が違うので、回復の間のヒット数は出ない。
- HP が満タンでも回復が適用されるかは、3 分モードの的が反撃するので、この録画では分からない（問いの外。凍結の記録の録画 41 にある）。

## 予測（撮る前に書く）

仮説ごとに、この録画で何が見えるはずか。見分けられるか。外れたときの影響。数値は予測ファイル（records/predictions/V-0169.json。npm run records:predict -- V-0169）を指す。既存の録画の読み直しなら、冒頭の「録画」に挙げてから予測を出し、読む前に commit する。

| 仮説               | 中身                                                      | 回復の間の当たる数（`heal-hits`）                                                                      |
| ------------------ | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| H1（予測ファイル） | 説明文どおり。**発**を数える（43 発 × 20 = 860 発で回復） | 860 発のうち当たる数の期待値（MG の弾丸命中率が 1 より少し低いので、860 より数発少ない。予測ファイル） |
| H2（手で書く）     | **命中**を数える（外れた発はスタックにならない）          | どの回も 860 ちょうど                                                                                  |
| H3（手で書く）     | リロードや的のジャンプでスタックが消える                  | H1 より多い・回によってばらつく                                                                        |

- 見分け方: 1 回ごとの差は H1 と H2 で数ヒットしかない（外れの数のばらつきと同じくらい）。6 回の合計で見る（H1 なら 860 × 6 より十数ヒット少ない、H2 なら 5,160 ちょうど）。
- 回復の回数: モデルは 6 回（6 回目は戦闘の終わりの約 3 秒前）。6 回目が無ければ、どこかで数え方がずれている。
- ▲の窓の中の 1 ヒット（`s2-*`）: 攻撃ダメージ▲は会心・コアの加算の外で掛かる（C-0018）ので、窓の外の値 × 1.2099。距離ボーナスの有無は着地点で変わるので、両方を予測し、読めた方と比べる。▲の倍率は `056-04` で発を見分けるのに使った（説明文の値）ので、この指標は「窓の中の値の絶対値が式どおりか」の確かめにとどめる。
- 外れたときの影響: H2・H3 なら定義の heal のトリガー（`normalShot` の数え方）を直す。▲の値が合わなければ、攻撃ダメージ▲の置き場所か値を見直す。

## 読み方

1. 録画を取り寄せる（`node tools/captures/fetch.ts 056`）。
2. `npm run records:read -- 056 --recipe hud-jumps`（総ダメージの全フレームの増分）で増分を取り、1 増分を「窓の外の値 × {1, 1.2099}」×（コア・会心・距離）の格子の和に分解する（同じフレームに 2 ヒットが重なる回がある。`056-05` の重複フレーム）。
3. ▲の発の並びから、窓ごとの最初の▲のヒットを決め、その間のヒット数を数える（観測値 `heal-hits` に対応。指標 `healHitCounts`）。
4. 窓の中の 1 ヒットの値を、格子の組み合わせごとに 1 つずつ拾う（観測値の指標 `hitDamage`。予測ファイルと同じ `args`・`setup`）。
