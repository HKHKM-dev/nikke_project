# backlog.md を 1 件 1 ファイルにする（2026-11-01）

- 何のための文書か: [design-pr-conflicts.md](design-pr-conflicts.md) 3.3 節の案 3（課題を 1 件 1 ファイルに置き、`plan/backlog.md` を生成物にする）の形と、移し方・手順の文書の直しを決める。
- 関連: 先例の結論の 1 件 1 ファイル（`records/claims/` → `plan/claims.md`。[design-stage20.md](design-stage20.md) 3.3 節）、生成物を main でだけ作り直す（design-pr-conflicts.md 5 節）、進み具合の書き写しの検査（[design-workflow-simplification-6.md](design-workflow-simplification-6.md) 2 節）。
- 状態: 承認待ち

## 1. いまの形と困りごと

- `plan/backlog.md` は型が「現状」の手書きの文書で、節ごとに列の違う表（1.2・1.3・2・3・6・7 節）、箇条（8 節の開いた課題、8.2 節の閉じた課題）、空の節の「（なし）」、各節の冒頭の書き方の説明がある。
- 並行する PR が同じ節の末尾に行を足したり、隣の行を消したりして衝突する（手で直すファイルでいちばん多い。design-pr-conflicts.md 2 節）。

## 2. 案

### 2.1 置き場所と 1 件の形

- 課題 1 件を `records/backlog/<名前>.json` に置く。節の冒頭の説明と表の列は雛形 `records/backlog/template.md` に置く（2.3）。`npm run records:check` が両方から `plan/backlog.md` を作り直す。
- 形は JSON（結論と同じ）。中身は表のセルか 1 行の箇条で、Markdown の本文を持たないので、frontmatter の利点が無い。読むのも検査も `records:check` の道具（`readJson`）で足りる。

```json
{
  "section": "2",
  "cells": {
    "課題": "防御力▼の後の防御力の丸めの、.5 ちょうどの向き",
    "いま分かっていること": "C-0790 は …",
    "次の 1 手": "撮らない（未確定と明記。2026-11-01 のオーナーの判断）",
    "要るもの": "—"
  }
}
```

```json
{
  "section": "8",
  "order": 10,
  "text": "PR の衝突（2026-11-01 起票）→ 一部完了: [design-pr-conflicts.md](design-pr-conflicts.md)。残りは 3.3 節"
}
```

- 項目:
  - `section`: 節の番号（雛形の印にある `1.1`・`1.2`・`1.3`・`2`・`3`・`4`・`5`・`6`・`7`・`8`・`8.2`）。
  - 表の節は `cells`（列の名前 → セルの文。列の名前は雛形の表の見出しのまま。`#` の列は持たない）。箇条の節は `text`（行頭の `- ` を除いた 1 行）。どちらも Markdown を `plan/backlog.md` に置いたときの形で書く（リンクは `plan/` からの相対パス）。
  - `order`: 節の中の並び（数。小さいほど上）。2 節は持たない（番号順）。
- 列ごとの項目名（英語のキー）にしないのは、列の名前を雛形の 1 か所にだけ置き、JSON を読む人が列を取り違えないため。

### 2.2 ファイル名と ID

- 2 節の課題（`#` の列のあるもの）は、ファイル名を番号にする（`records/backlog/2-43.json`）。`#` の列はファイル名から出す。記録が「2-33」「backlog 2-44」で指しているので、いまの番号はそのまま引き継ぐ。
- ほかの節の課題は、起票のときに付ける英小文字とハイフンの短い名前（`pr-conflicts.json`・`hit-rate-sum-miranda.json` など）。節を移っても（8 → 8.2、1.3 → 1.2）名前は変えない。番号を振らないので、並行する PR どうしで重ならない。
- 2 節の新しい番号は、`records/backlog/` と、どのブランチ（手元か origin）も足したことのある `2-NN` の最大の次（`idsInBranches` と同じ見方）。重なったときは `pr:prep` がリベースの前に止めて、空いた番号を出す（V・C・録画の重なりと同じ所。`collisions` に足す）。直すのは人で、ファイルの名前と自分のブランチの中の参照を変える。`records:renumber` には入れない（文の中の「2-45」は検証記録の ID のような目印が無く、ほかの数の並びと見分けられない）。2 節に足すのは数日に 1 件なので、道具で振り直すほどではない。
- `records:check` は、2 節のファイル名が `2-NN` の形であること、ほかの節が `2-NN` の形でないことを見る。

### 2.3 雛形（節の見出し・冒頭の説明・列）

- `records/backlog/template.md` は、いまの `plan/backlog.md` から行を抜いた骨組み（題名・冒頭・節の見出し・節の説明）で、行の入る所に印を置く。

```markdown
### 1.2 撮るかどうかがオーナーの判断待ち（保留を含む）

<!-- backlog 1.2 | 見たいこと | 結論 | 撮り方の案の所 | 行 | -->

## 8. 課題（設計書のあるもの）

1 行の形は「題名（起票日）→ 状態: …」（いまの説明のまま）

<!-- backlog 8 -->
```

- 印は `<!-- backlog <節> -->`（箇条）か、`<!-- backlog <節> | 列 | … | -->`（表。列は見出しの順）。生成は、表なら `<!-- prettier-ignore -->` と見出しと行（詰めた形）、箇条なら `- ` の行、課題が無ければ「（なし）」に置き換える。表の列を雛形に置くので、列を足す・名前を変えるのは雛形と、その節のファイルの `cells` を直す 1 つの PR になる。
- 冒頭の「書き方」は、起票の手順（2.6）に書き換え、生成物の冒頭の「このファイルは生成する（手で書かない）」の行を足す（claims.md と同じ）。雛形はめったに変わらないので、雛形の衝突は残っても困らない。

### 2.4 並び

- 2 節は番号順。ほかの節は `order` の小さい順、同じなら名前順。移すときは、いまの並びのまま 10・20・30 … を振る。
- 足すときは、末尾なら節の最大より大きい数、先頭なら最小より小さい数（負でも小数でもよい）。並行する PR が同じ数を選んでも、名前順で並ぶだけで衝突しない。
- 起票日で並べる案は採らない: 8 節はいま起票日の順ではなく（話題でまとめた並び）、表の節の行は起票日を持たない。

### 2.5 閉じた課題と空の節

- 表の節の行は、閉じたらファイルを消す（いまの「閉じたら行を消す」と同じ）。
- 8 節の課題を閉じたら、`section` を `8.2` にして `text` を閉じた形に直し、`order` を 8.2 節の先頭（最小より小さい数）にする。8.2 節のファイルはそのまま残す（いまの 8.2 節と同じ）。
- 課題の無い節は「（なし）」と出す。いまの 1.1 節の「- なし（2026-11-01）」は「（なし）」になる（移したときの唯一の文の違い。日付は git の履歴で引ける）。

### 2.6 起票と直しの手順（雛形の冒頭に書く）

- 足す: `records/backlog/` にファイルを 1 つ足す（2.1・2.2・2.4）。直す・閉じる: そのファイルを直すか消す。`plan/backlog.md` は手で直さない（`records:check` が作り直す。PR には入れず、マージの後に main の CI が作り直す）。
- 手元で一覧を見たいときは `npm run records:check`（か `records:minimal`）を回す。

### 2.7 records:check の検査

`records:check` が落とす（ほかの検査と同じく、生成の前にまとめて出す）:

- `section` が雛形の印に無い。表の節に `cells` が無いか、列の名前が雛形の列（`#` を除く）と合わない。箇条の節に `text` が無い。`cells` と `text` の両方がある。
- セル・箇条に改行がある。セルに、エスケープしていない `|` がある。
- ファイル名の形（2.2）。2 節でない課題に `order` が無いか、数でない。
- 文の中の検証記録・結論の ID（`V-NNNN`・`C-NNNN`）が無い。`plan/` からの相対リンクの先のファイルが無い。

### 2.8 進み具合の書き写しの検査の移し先

- いまは `pr:prep` が、ブランチで足した `plan/backlog.md` 8 節（8.2 節を含む）の行のうち、検証記録・結論の ID か「PR N を実装」を含むものを出して止める（`progressCopies`。`--allow-progress` で通す）。
- 移した後も `pr:prep` に置き、見る所を、ブランチで足すか変えた `records/backlog/*.json` のうち `section` が `8`・`8.2` のものの `text` にする（main の版と同じ文なら見ない）。足した行を見るいまの検査と同じものを拾う。`--allow-progress` もそのまま。
- `records:check` に移して全部のファイルを見る案は採らない: 通す口（`--allow-progress`）が無くなり、いまの検査より強くなる（ブランチで触っていない課題まで落とす）。

### 2.9 生成の経路

- `packages/core/src/records/backlog.ts`（読む・検査・書く。純粋な部分）と、`records-data.ts` の `loadBacklog`・`BACKLOG_PATH`。`records-check.ts` が `plan/backlog.md` を書き、`GENERATED_PATHS` に足す（`pr:prep` が main の版に戻し、`ci-generated.ts` が main で作り直して commit する）。`records:check` の整形（`format-retry.ts`）に `plan/backlog.md` と `records/backlog` を足す。
- `records:renumber` は追跡しているファイルの中の V・C・観測値・録画の ID を書き換えるので、`records/backlog/*.json` も追加の手当て無しで直る。

### 2.10 書き換える手順の文書

- `AGENTS.md`: 「記録の置き場所」の表の `plan/backlog.md` の行を `records/backlog/`・`plan/backlog.md`（現状・生成。課題は 1 件 1 ファイル）にする。「文書の書き方」の進み具合の行（「backlog.md 8 節…への書き写しは `pr:prep` が止める」→ 8 節・8.2 節の課題のファイル）と、詰めた表の例から backlog.md を外す（生成物は道具が詰めた形で書く）。
- `plan/verification-guide.md` 閉じる段（「backlog.md の行を直す」→ 課題のファイルを直す）。
- `packages/core/scripts/records-close.ts` が出す「残り」の文と冒頭の注記。
- `tools/git/pr-prep.ts` の冒頭の説明（2 の書き写しの検査）。
- `records/backlog/template.md`（いまの backlog.md の冒頭・各節の説明。起票の手順を 2.6 に）。
- 設計書・検証記録（型が記録）は書き換えない。「backlog.md に足した」などの過去の記述は、書いた時点の版を指す（AGENTS.md「文書の書き方」）。`plan/requirements.md`・`plan/roadmap.md` の「backlog.md」へのリンクは生成物を指したままでよい。
- Claude Code のメモリ（`bash-pitfalls.md` の「道具が止めたファイル（… backlog など）」）からも backlog を外す。

## 3. 移し方と確かめ方

- 一度きりの移し替えの道具（スクラッチパッドに置く。リポジトリには入れない）で、いまの `plan/backlog.md` を読み、行ごとにファイルを書く。名前（2.2）は手で付けて道具に渡す。
- `records:check` で作り直した `plan/backlog.md` と、移す前の版の差分が、1.1 節の「（なし）」（2.5）と整形だけであることを確かめる。
- テスト: 雛形の印の読み、表・箇条・「（なし）」の書き出し、検査の各項目、2 節の番号順と `order` の並び、`collisions` の 2 節の番号の重なり、`progressCopies` の課題のファイル版。`plan/backlog.md` が入力と合っているか（ほかの生成物と同じく CI が作り直してから見る）。

## 4. 採らない案

- **1 件 1 ファイルを Markdown + frontmatter にする**: 2.1 のとおり本文が無い。
- **全部の課題に連番の ID（`B-NNNN` など）を振る**: 振り直しの手当て（`records:renumber`・`pr:prep` の重なりの検査）が全件に要る。名前なら重ならない。いまの 2 節の番号だけを引き継ぐ。
- **列を英語のキーにして、列の名前を生成の道具（TypeScript）に置く**: 列の定義が雛形と道具の 2 か所に分かれる。
- **8.2 節（閉じた課題）を生成物に載せない・ファイルを消す**: いまの文書の中身を変える。閉じた課題を一覧で引く使い方を残す。
