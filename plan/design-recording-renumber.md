## Context

- 前例の 2 回は、E: と I: の両方で手で名前を変えた。

## 2. 方針

既存の `records:renumber` に録画の種類を足す（`npm run records:renumber -- 124 480`）。3 桁の素の番号を録画と読む。

1. 確かめる（何も書き換えない）: 古い録画がある・新しい番号が空いている・リポジトリの外の移す先が空いている
2. リポジトリの外のファイルの名前を変える（E: → I:）
3. リポジトリの中を置き換える（ファイルの移しと、文書・データ・コードの中の参照）
4. 報告する（対応・置き換えた数・人が直す所・`backup-log.md` に足した段落）

`--dry-run` では 1 と、2〜3 で何をするかの一覧だけを出す。

## 3. 振り直せる録画

- 通し番号の録画（001 から。`L-` の旧の録画は扱わない）。番号は 3〜4 桁（1000 からは 4 桁。古い番号も新しい番号も）。
- 2 桁のファイル名の時代（001〜063。動画 `20260922-01_SR_delta.mp4`、証拠フレーム `20260922-01_SR_delta_f<フレーム>….jpg`）も、番号の部分だけを新しい番号にする（`20260922-480_SR_delta.mp4`。残りは変えない）。命名規約の「既存の録画（01〜63）と証拠フレームは改名しない」は、ふだんの改名の話で、振り直しはこの道具で行う。
- 古い番号: `records/recordings/<古い番号>.json` がある。
- 新しい番号が空いている:
  - `records/recordings/<新>.json` と `records/observations/<新>.json` が無い
  - どのブランチ（手元か origin。main を含む）も `records/recordings/<新>.json` を足したことが無い（`recordingIdsInBranches`）
  - 文書・データ・コードに、1.1 節の確かさの高い形で新しい番号が出てこない（範囲の中を含む）
  - E: と I: に、新しい番号の動画とスクショ（`<YYYYMMDD>-<新>_*`）・証拠フレーム（`<新>_f*`）・`derived/<新>/` が無い
- リベース・マージの途中では動かない（既存と同じ）。

## 4. リポジトリの中の置き換え

確かさの高い形（1.1 節）だけを置き換える。

- `records/recordings/<古>.json` → `<新>.json`（`git mv`）。`id` と `file` の番号を書き換える。
- `records/observations/<古>.json` → `<新>.json`（`git mv`）。`recording` と、観測値の `id` の頭を書き換える（`124-01` → `480-01`。NN は変えない）。
- 予測ファイルの `recording` を含め、文書とデータの中の次の形:
  - バッククォートの `` `124` ``
  - 「録画」の後の番号の並び（「録画 124」「録画 124・178」「録画（124〜126・178）」。区切りは `・`・`、`・`〜`）。001〜063 は 2 桁の書き方（「録画 41」）も同じ録画と読む
  - 観測値の ID（`124-NN` のうち、観測値のファイルにあるものだけ）。根拠の書き方の範囲（「`` `124-01`〜`124-05` ``」）は、既存の観測値の振り直しと同じく、展開してから置き換えてまとめ直す
  - JSON の文字列 `"124"`（`records/` の下の JSON だけ）
  - ファイル名 `<YYYYMMDD>-124_`（001〜063 は `<YYYYMMDD>-41_`）・`124_f<数>`・`derived/124/`
- 範囲の書き方（`` `064`〜`066` ``・「録画 400〜402」）に古い番号が入っていれば、展開して置き換え、まとめ直す（例: 401 → 480 なら「400・402・480」）。
- 録画をまたぐ観測値の範囲（「`` `174-06`〜`177-06` ``」）に古い番号が入っていれば、置き換えずに場所を出す（人が直す）。
- 置き換えなかった素の番号のうち、同じ行に「録画」がある所を、行の番号つきで出す（人が見る）。
- 凍結の文書（`plan/verification.md`・`plan/captures/legacy-usage.md`・`backup-log-old.md` ほか）の中も、ほかの文書と同じく置き換える（参照がいまの番号を指すように。10 節の 3）。

## 5. リポジトリの外の名前の変え方

E:（`capturesDir()`）と I:（`backupDir()`）の両方で、次を変える。どちらかが無い環境（クラウド環境など）では、その側は変えずに一覧を出す。

| もの                 | 見つけ方                                                            | 変え方                                       |
| -------------------- | ------------------------------------------------------------------- | -------------------------------------------- |
| 動画                 | 台帳の `folder` と `file`                                           | 番号の部分だけを変える                       |
| 録画に付くスクショ   | 同じフォルダで、動画と同じ名前（拡張子の前）で始まる `.png`・`.jpg` | 同上                                         |
| 証拠フレーム         | `frames/<古>_f*` と、`frames/<動画の名前>_f*`（2 桁の時代）         | 同上（後の 6 節の 2）                        |
| 中間出力のキャッシュ | `derived/<古>/`。`*.meta.json` の sha256 が台帳の sha256 と同じもの | フォルダの名前を変え、meta の `video` を直す |

- 先に全部の移す元があるか・移す先が無いかを確かめてから変える。途中で失敗したら、そこで止めて、変えたものと変えていないものを出す（変えたものは戻さない。もう一度回すと、変えた後の名前を見つけて続ける）。
- I: に無いもの（まだ同期していないフレームなど）は、I: では変えずに出す（E: で変えた名前で、次に手で同期する）。
- 中身を書き換えないので、sha256 は台帳の値のまま。
- `plan/captures/backup-log.md` に 1 段落を足す（日付・古い番号 → 新しい番号・E: と I: のどちらで変えたか。前例の 2 回と同じ書き方）。過去の行のファイル名は、ほかの文書と同じく置き換える（いまの名前を指すように）。

## 6. 決めにくい所

1. **E: と I: を道具が変えるか、一覧だけを出すか**（10 節の 1）
2. **証拠フレームの持ち主**: 番号が重なったとき、`frames/<番号>_f*` には日付も識別子も無いので、どちらの録画のフレームか名前からは分からない。案: このブランチの文書に名前が出てくるフレームだけを変え、出てこないものは場所を出す（人が見る）。重なっていない（もう一方の録画が無い）なら、全部変える。
3. **重なったときの derived/**: もう一方の録画のキャッシュかもしれない。meta の sha256 が台帳と同じときだけ移す。違えば残す（作り直されるだけ）。

## 8. テスト

- 純粋な部分（`renumber.ts`）: 録画の番号の置き換え（バッククォート・「録画」の後の並び・範囲の展開とまとめ直し・観測値の ID・ファイル名・JSON の文字列）、置き換えない形（ほかの数の一部・素の番号）、人が直す所の検出、新しい番号の出てくる数。例の番号は実在と重ならない 9 百番台（既存のテストの例の 9 千番台と同じ考え）。
- リポジトリの外の名前の変え方: 一時フォルダを E: と I: に見立てて（`NIKKE_CAPTURES_DIR`・`NIKKE_BACKUP_DIR`）、動画・スクショ・フレーム・derived が変わることを確かめる。
- 実際の記録: 一時的な作業ツリーで、録画を 1 本（観測値と結論の根拠のあるもの）振り直し、`records:check`・`npm test`・`format:check` が通ることを見る（E: と I: は一時フォルダ）。手元の記録は書き換えない。

## 9. この設計書の外

- 番号が重ならない仕組みの強化（commit の前の番号の取り合い）。`intake.ts` は既にブランチの歴史を見ている。いまの重なりは commit 前の同時の取り込みだけで、頻度が低い。
- `L-` の旧の録画の振り直し（`E:/old_nikkecalc/` の `path` で指し、ファイルを移さない）。

## 10. 決めること

1. E: と I: の名前の変え方。**推奨: 道具が変える**（`--dry-run` で一覧を見てから回す。E: と I: が無い環境では一覧だけ）。理由: `intake.ts` が既に E: と I: に書いている。I: で直接変えれば Drive の上げ直しが要らない。手で変えると、前例のように台帳と食い違う余地が残る。代わりの案: 道具は一覧（PowerShell の `Rename-Item` の行）を出すだけで、オーナーが回す。
2. 証拠フレームの持ち主（6 節の 2）。**推奨: 6 節の 2 の案**。
3. 振り直せる録画を 064 以上に限る（3 節）。推奨は「限る」。
4. 「録画」の後の並びとバッククォートの番号のほかは置き換えず、同じ行に「録画」がある素の番号を出す（4 節）。**推奨: そうする**。

### 10.1 決まったこと（2026-10-17）

1. 道具が E: と I: の名前を変える（推奨のとおり）。
2. 証拠フレームは、6 節の 2 の案（推奨のとおり）。
3. 064 以上に限らない。001〜063 も、番号の部分だけを新しい番号にする（3 節）。凍結の文書の中も置き換える。`L-` は扱わない。番号は 4 桁まで扱えるようにする（オーナーの指示）。
4. 確かさの高い形だけを置き換え、同じ行に「録画」がある素の番号を出す（推奨のとおり）。
