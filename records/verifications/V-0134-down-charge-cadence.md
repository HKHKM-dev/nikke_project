# V-0134: 押下チャージ型（DOWN_Charge）の発の刻み: 解放の有無とチャージ時間の切り替わり（アニス：スター単騎）

- 問い: 押下チャージ型のアニス：スターの発と発の間に解放（C-0143 の 23f）が無いのは、押下チャージ型の性質か。チャージの途中でチャージ時間が変わる（バーストの発動・窓の終わり）と、次の発はいつか
- 話題: 射撃（間隔・リロード・チャージ）
- 日付: 2026-10-04
- Stage: plan/design-anis-star-s2-burst.md 10.1 節・10.3 節の論点 12（backlog 2-18）
- 録画: `161`、`164`、`165`
- 状態: 調査中
- 派生元: `V-0123`

## 条件

**何を確かめるか**

- アニス：スター（17）の武器は押下チャージ型（`inputType` が `DOWN_Charge`。ほかに 5 体。plan/design-stage22.md 0.4 節）。モデルは未対応の武器（`damage.ts` の `down-charge`）として、ふつうのチャージ武器（`UP`）と同じ刻み（発と発の間 = チャージ + 解放 23f。C-0143）で撃たせている。
- バーストの窓の外の発の間隔は 1 秒チャージ（59f）だけで、解放が無い（`164-08`。録画 161 も同じ）。窓の中の 42f（C-0214）も解放が無い。どちらも「押下チャージ型は解放を足さない」で説明できるかを確かめる。
- 解放を外すだけ（下の H1・P0）では、録画 165 の満タンまでのフレーム（`165-10`）が許容外になった（設計書 10.1 節）。その原因が、ゲージの溜まり方か、発の位相（チャージ時間の切り替わりでの次の発の時刻）かを切り分ける。

**モデル側で先に分かったこと**（2026-10-04。コードを一時的に切り替えて回した値。コミットしていない）

- `165-10` は発の位相に敏感で、許容 ±30f では仮説を見分けられない。同じモデルでも、フルバーストの回ごとに満タンまでのフレームが大きく動く（下の表の n = 0〜4）。H1・P0 の +39f は、この振れの中にある。
- H1 にすると、ほかの読みはモデルが実測に近づく: 録画 161（的のジャンプあり・バーストなし）の発の数はモデル H0 99 発 → H1 122 発（実測は `161-02`）。録画 164 のバーストの回数はモデル H0 6 回 → H1・P0 7 回 → H1・P1 8 回（実測は `164-06`）。どちらも読み済みの値なので、仮説の出どころにとどめ、比べる指標にしない。
- H1・P1 のモデルでは、録画 164 の自分のバーストの発動から最初の発まで 13f（H1・P0 は 30f、いまのモデルは 53f。実測は 1 回目の窓で 12f。`164-05`）。

**編成**（最小構成）

- 主は録画 164（アニス：スター単騎・操作・AUTO 射撃 ON・オートバースト ON。V-0123）と録画 161（同じ単騎でオートバースト OFF。V-0116）。単騎なので、HUD の総ダメージの増分はアニス：スターの発・S1 の追加ダメージ・シューティングスターだけ。
- 録画 165（アニス：スター（操作）・デルタ・イサベル。V-0125）は、発動の直前の発からの経過（下の x）がばらつくので P1 と P4 を見分けるのに使う。デルタ・イサベルの定義にはチャージ時間・チャージ速度に効く効果が無く、アニス：スターの発の刻みに入る未確定の要素は押下チャージ型の刻みだけ。

## 読み方

1. 録画 164 の全体を `tools/captures/hud.ts --mode series` で読み、総ダメージの増分を、アニス：スターの発（胴体 1〜2 ヒット + 追加ダメージ。値の組は `161-03`〜`161-06`・`164-01`・`164-02`）とシューティングスター（`164-03`・`164-04` とそのコアの値）に分ける（164-05 と同じ使い捨てのスクリプト）。発のフレームの列を観測値にする（`use: record`）。
2. 発動のフレームは `164-06` の 7 つ。窓は発動から 588f（10 秒）とする。窓の終わりの前後 2f に発があれば、e の比べから外す。
3. 発と発の間を次に分けて、観測値にする（それぞれ `use: record`、単位 f）。
   - a. 窓の外・マガジンの中（`164-08` の f2589〜2884 は除く）
   - b. 窓の外・リロードを挟む（`164-08` の 1 か所は除く）
   - c. 窓の中・リロードを挟む（`164-05` の 1 回目の窓は除く）
   - d. 発動を跨ぐ間隔と x（7 回。1 回目の窓の最初の発 f1910 は読み済みで、その前の発は読んでいない）
   - e. 窓の終わりを跨ぐ間隔と、窓の終わりから次の発まで（7 回）
4. 録画 165 の同じ読みで、アニス：スターの発動（I。フルバーストの回 6 回と、I だけで切れる回）ごとの d・e と x。デルタ（コア 1 ヒット）・イサベル（10 ペレット）の増分と重なるフレームは、候補の値の和に分ける（guide「1 ヒットの値（多人数）」）。
5. 録画 165 のフルバーストの入り（`165-12` の 6 つ）の後の満タン（`gauge.ts --mode events` のバー消失）の n = 1〜4 を、`fullBurstToGaugeFull` の観測値にする（`use: compare`。予測ファイルと突き合わせる）。
6. 録画 161（バーストなし）は、b（リロードを挟む間隔）を全部読む。探索として、的のジャンプの窓の明けから最初の発まで（モデルは C-0110 の「待ちからの 1 発目」= チャージ + 解放 − 13f）を、窓の時刻とあわせて読む。
7. 判定: a が 59f・82f のどちらにそろうかで H1 と H0、b・c で R1 と R2、d・e の組で P0・P1・P2・P4。見分けられるのは、どの間の差も 10f 以上あるから（P1 と P4 は x が 31f 以上の発動だけ）。
