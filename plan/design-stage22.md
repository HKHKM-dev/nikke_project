## Context

モデルは、チャージ武器（入力が UP の SR・RL）の発を**すべてフルチャージ**として扱う。射撃場 3 分モードの的のジャンプのように攻撃できる的がいなくなる窓（Stage 16-B）に入ると、チャージを捨てて、ハイドしてリロードを始める（`frame/shooter.ts` の `hideShooter`）。

V-0037 の読み直しと、オーナーの知見（2026-09-29）で、次の 2 つがモデルと違うと分かった。

1. **部分チャージ**（C-0109、確定）: チャージの途中で攻撃できる的がいなくなると、その時点のチャージで撃つ。押下チャージ型（DOWN_Charge）は挙動が違う（モデルでは今も未対応の武器）。
2. **待ちからの 1 発目**（C-0110、仮説）: 撃たずに待っていた状態（戦闘開始・窓の明け）からの 1 発目は、発と発の間より約 12〜13f 早い。

この Stage では、この 2 つをモデルに入れる。

## 0. 設計前に分かったこと（2026-09-29）

### 0.1 チャージの 1 周期の内訳（照準の横のチャージの表示）

照準の横に、チャージの倍率の表示（100% からフルチャージ倍率まで）が出る。1 フレームずつ読んだ内訳（観測値は `046-17`・`046-19`・`075-05`・`075-06`）:

| 区間                                                                                  | 紅蓮BS（RL・チャージ 0.3 秒・倍率 1.5） | ラム（SR・チャージ 1 秒・倍率 2.5） |
| ------------------------------------------------------------------------------------- | --------------------------------------- | ----------------------------------- |
| 構え解除モーション（撃った後。表示が止まる・スコープが閉じる。紅蓮BS 等は硬直を含む） | 約 13f                                  | 約 13f                              |
| 構えモーション（100% のまま）                                                         | 約 12f                                  | 約 9f（窓の明けからは約 11f）       |
| チャージ（100% → フル。直線）                                                         | 17f                                     | 58〜59f                             |
| フルになった次のフレームで撃つ                                                        | 1f                                      | 1f                                  |
| 発と発の間（合計）                                                                    | 43f（C-0014）                           | 82f（C-0001 の 60 + 22）            |
| 待ちからの 1 発目（戦闘開始・窓の明け）                                               | 29〜30f                                 | 70f                                 |

- 射撃の流れ（オーナー、2026-09-29）: ハイド（初期状態）→ 構えモーション → チャージ開始 → チャージ完了（射撃）→ 構え解除モーション → 構えモーション → …。紅蓮BS 等は、射撃と構え解除モーションの間に硬直が入る。構えモーション・構え解除モーションはすべての武器種にある。
- ハイドしていた状態（戦闘開始・窓の明け）からは構え解除が無いので、発と発の間から構え解除（と硬直）を除いた長さが 1 発目になる。**モデルはハイドからも発と発の間と同じ長さで撃つ**ので、1 発目が紅蓮BS で 13f、ラムで 12f 遅い。
- 硬直の項目は `maintain_fire_stance`（0 でないのは紅蓮BS 23・レイヴン 83・A2 84 だけ）とみられる。紅蓮BS の撃った後の区間（13f）は、硬直の無いラムの構え解除（13f）と同じ長さで、紅蓮BS の中で硬直と構え解除の内訳は分けていない。レイヴン・A2 は実測が無い（6 節の 2）。

### 0.2 部分チャージの値

- 部分チャージの 1 発の値は、撃った時のチャージの表示に比例する。フルチャージ倍率を F、チャージの進みを p（0〜1）とすると、**倍率は 1 + (F − 1) × p**（フルチャージの発の値 × (1 + (F − 1) × p) / F）。
  - 紅蓮BS: 表示 145%（F = 1.5）で 0.969 倍、148% で 0.988 倍（`046-17`・`071-04`）。
  - ラム: 0.1 節の区間で前の発からの間を p に直すと、58f → p ≈ 0.62 → 0.77 倍（実測 0.767）、24f → p ≈ 0.02 → 0.41 倍（実測 0.410）、32f → 0.50 倍（実測 0.492）（`075-02`）。
- 進みが小さくても撃つ（p ≈ 0.02 の例）。構え解除・構えのモーションの間（チャージの前）に窓が始まったときは撃たない（紅蓮BS の 4 回目のジャンプ。`046-18`）。
- 部分チャージの発は、「フルチャージの発」の回数（`fullChargeShot`）に**数えない**。紅蓮BS の S1 の段（フルチャージの発 3 発ごと）は、4 本とも部分チャージの発を飛ばして数えていた（046・055・071 は部分チャージの後の 3 発目で段 B。`046-20`）。的に当たらなかった発（C-0108 のコンテナ）は数える（070）。
- **部分チャージの発のゲージは読めていない**（その時刻のバーが 0px）。フルチャージ倍率のゲージ（`fullChargeBurstEnergy`、操作キャラだけ。C-0083）が部分チャージでどうなるかは未確認。

### 0.3 部分チャージの後

- 窓に入ると、照準の下に RELOADING が出て遮蔽物に下がる（部分チャージの発から 18〜19f、フルチャージの発から 29〜31f。`046-18`）。窓の明けに RELOADING が消え、残弾は窓に入る前と同じ（リロードは込め終わらずに取り消し。Stage 16-B の約束のまま）。
- 窓の明けから 1 発目までは 0.1 節の「待ちからの 1 発目」。

### 0.4 押下チャージ型（DOWN_Charge）

- 6 体（アニス：スター・ネオン：ビジョン・アイ・ラプラス：アルティメットヒーロー・シンデレラ・ベスティー：タクティカル・アップ・リバーレリオ）。モデルは未対応の武器として扱っている（`damage.ts` の `down-charge`）。この Stage でも対象にしない。

### 0.5 リロードの後の 1 発目

- 最終弾から次のマガジンの 1 発目までは、今のモデル（リロード + 発と発の間と同じ待ち）で合っている（紅蓮BS の 172f は C-0014、ラムは HUD の増分で最終弾から 200f）。「待ちからの 1 発目」が早いのは、戦闘開始と窓の明けだけとして扱う。

## 1. 方針

1. **待ちからの 1 発目**（22-A）: チャージ武器の構え解除モーション（硬直を含む）を武器のモデルの定数（`aimOutFrames`、13f）として持ち、戦闘開始と窓の明け（ハイドから構える）の 1 発目は、発と発の間からそのぶんを引いた長さで撃つ。リロードの後は今のまま（0.5 節）。
2. **部分チャージ**（22-B）: 窓の始まりのフレームに、チャージの進み p > 0 なら、その時点の倍率で 1 発撃つ（残弾を 1 減らす）。撃ってから、今までどおりハイドしてリロードを始める。p は、発と発の間の最後の「チャージの区間」（`chargeFrames` フレーム）のうち、窓の始まりまでに進んだ割合。
3. 部分チャージの発は、通常攻撃の回数（`normalHit`・`shot`）には数え、フルチャージの発の回数（`fullChargeShot`）には数えない（0.2 節）。
4. 部分チャージの値は、倍率を 1 + (M − 1) × p にする。M はチャージのバフを込めたフルチャージ倍率（`applyChargeBuffs`。C-0020・C-0099）。バフのある場合の比例は未確認（0.2 節は素の倍率だけ）で、仮定として画面に出す。
5. sim と calc は、今と同じく 1 発ごとの値と発の数で一致させる。窓のある戦闘では calc は発の列を数える形（`countAllShots`）なので、部分チャージの発を区間ごとに別に数える。
6. 押下チャージ型は対象にしない（0.4 節）。

## 2. 案の比較

| 論点                     | 推奨                                                                    | 別案                                                                                   |
| ------------------------ | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 部分チャージの発の持ち方 | 発の記録（`ShotLog`）に、部分チャージの発のフレームと p の列を足す      | 発ごとの種類の列を全部の発に持たせる（変更が大きく、ほとんどの発はフルチャージのまま） |
| 部分チャージの発のゲージ | 1 + (F_e − 1) × p（ダメージと同じ形。F_e はフルチャージのゲージの倍率） | フルチャージ倍率を掛けない（素のゲージ）。どちらも未確認（0.2 節）                     |
| 待ちからの 1 発目の定数  | 武器によらず 13f（紅蓮BS・ラムの実測）                                  | 硬直の項目（`maintain_fire_stance`）のある武器だけ変える。ラムの 70f と合わない        |
| 段の分け方               | 22-A（1 発目）→ 22-B（部分チャージ）                                    | 1 つにまとめる。残差の動きを分けて記録できなくなる                                     |

## 3. 推奨案の中身

### 3.1 22-A: 待ちからの 1 発目

- `weapons.ts` の `DEFAULT_WEAPON_MODEL` に `aimOutFrames: 13` を足す（C-0110。紅蓮BS 13f・ラム 12〜13f）。
- `cadence.ts` の `firstShotFrames`（戦闘開始と窓の明けで使う）を、チャージ武器はチャージ + `chargeReleaseFrames` − `aimOutFrames` にする。`reloadFirstShotFrames`（リロードの後。`loadChunks`・`refillAmmo`・`resumeShooter`）は、チャージ武器は今の値（チャージ + `chargeReleaseFrames`）のまま。
- calc の平均の刻み（`cycleFrames`）は、リロードの後の待ちで決まるので変わらない。発の列の起点だけが動く（`shots.ts` の `planShots`、`cadence.ts` の発の列の式）。
- 紅蓮BS の較正（`MEASURED_CHARGE_CADENCE`）は発と発の間とリロードの後の刻みなので変えない。待ちからは 43 − 13 = 30f になり、`046-19` と合う。

### 3.2 22-B: 部分チャージ

- `frame/shooter.ts` の `hideShooter` の前に、`partialChargeShot(state, shot, model, params)` を足す。窓の始まりのフレームで、撃てる状態（`ready`）のチャージ武器について:
  - 次の発までの残りの待ち r から、チャージの進み p = clamp((C − (r − 1)) / C, 0, 1) を出す（C は `params.chargeFrames`。r ≤ 1 なら p = 1）。
  - p > 0 なら 1 発撃つ（残弾を 1 減らす。最終弾なら「最後の弾丸」も付く）。発の記録に、フレームと p を足す。p = 1 はフルチャージの発として扱う。
  - それから今の `hideShooter`（ハイドしてリロード）に進む。
- `frame/shots.ts` の `ShotLog` に `partialShots?: { frame: number; progress: number }[]` を足す（`frames` にも含める）。
- 回数トリガー: `ShotEvent.fullCharge` を、発ごとに「チャージ武器で、部分チャージの発でない」にする（`firstPass.ts` の 520 行目、`skills/triggers.ts` の `replayEvents`、`skills/cycles.ts` の `cycleShotFrames`）。段の循環・ゲージの予約（`firstPass.ts` の 399・434 行目）も発ごとに見る。
- 1 発の値: `damage.ts` の `computeTriggerDamage` に、チャージの進みを受け取る形（`chargeProgress`、既定 1）を足す。倍率は 1 + (M − 1) × p。追加ダメージなどの `perShot` は変えない。
- sim（`sim/engine.ts`）: 区間ごとに、部分チャージの発の値を p ごとに計算して足す（部分チャージの発は窓の数しか無いので、発ごとに計算してよい）。
- calc（`calc/model.ts`）: 発の列を数える形のとき、部分チャージの発を区間ごとに別に数え、その p の値で足す。平均の形（窓の無い戦闘）には部分チャージは出ない。
- ゲージ: 部分チャージの発は、`energyPerTrigger` のフルチャージ倍率を 1 + (F_e − 1) × p にする（2 節。未確認として注記）。
- 画面: 区間の行に「うち部分チャージ N 発」を出し、倍率の仮定（「チャージの進みに比例と仮定」）を注記に出す。

### 3.3 やらないこと

- 押下チャージ型（0.4 節）。
- 的に当たらなかった発（C-0108 のコンテナ）。的の動きの時刻の表が要る。
- 硬直の項目（`maintain_fire_stance`）の扱い。レイヴン・A2 の刻みは確かめていない（6 節の 2）。

## 6. 決めてほしいこと（2026-09-29 に 5 点とも推奨案で承認）

1. **段の分け方** — 推奨: **22-A（待ちからの 1 発目）→ 22-B（部分チャージ）**。
2. **待ちからの 1 発目を、どの武器に入れるか** — 推奨: **UP 型のチャージ武器すべて**（撃った後の区間 13f は、硬直の項目の無いラムにもあった。0.1 節）。別案は、硬直の項目のある 3 体（紅蓮BS・レイヴン・A2）だけに入れる案。オーナーの知見の「射撃後硬直」が、紅蓮BS の 13f のことか、別の区間のことかを教えてほしい。レイヴン・A2 は、硬直の値（83・84）から撃った後の区間がもっと長い見込みだが、実測が無い。→ 承認。構え・構え解除のモーションはすべての武器種にあり、紅蓮BS 等は射撃と構え解除の間に硬直が入る（オーナー。0.1 節）。硬直の長い武器（レイヴン・A2）の刻みは、この Stage では確かめない（3.3 節）
3. **部分チャージの発のゲージ** — 推奨: **ダメージと同じくチャージの進みに比例**（未確認として注記）。別案は、フルチャージ倍率を掛けない（素のゲージ）。
4. **チャージのバフがある場合の部分チャージの値** — 推奨: **バフ込みのフルチャージ倍率 M で 1 + (M − 1) × p**（未確認として注記）。
5. **C-0110 を確定にするか** — 22-A の検証（紅蓮BS・ラムの 1 発目がモデルと合う）の後に、反復実測で確定にしてよいか。

## 7. 実施の記録

### 7.1 22-A（2026-09-29）

- `weapons.ts` の `WeaponModel` に `aimOutFrames`（13）を足した。`cadence.ts` の `firstShotFrames` は、チャージ武器ではチャージ + `chargeReleaseFrames` − `aimOutFrames`。`reloadFirstShotFrames` は、チャージ武器ではチャージ + `chargeReleaseFrames`（今まで `firstShotFrames` を返していたのを分けた）。射手（`frame/shooter.ts`）は、戦闘開始と窓の明けが `firstShotFrames`、リロードの後が `reloadFirstShotFrames` を使っていたので、呼び出しは変えていない。
- 発の時刻を固定していたテストを新しい値に直した（`shooter.test.ts`・`cadence.test.ts`・`stage16Events.test.ts`・`stage10Shooter.test.ts`・`stage11ScarletBsTeam.test.ts`・`stage11ModerniaTeam.test.ts`）。バーストの発動フレームちょうどの発を使うテスト（`firstPass.test.ts`）は、構え解除を 0 にしたモデルで回すようにした。ラムの 1 発目（69f・リロードの後 82f）のテストを足した。sim と calc の整合のテストは変えずに通った。
- 残差の一覧の変化は V-0041。1 回目の満タンの +11〜+12f の遅れがほぼ消え、`040-04`・`043-06` が許容の外（−34・−33f。仮説の結論 C-0106 の観測値）に出た。確定の結論の観測値は許容の中に残った。C-0110 を確定にした（6 節の 5）。

### 7.2 22-B（2026-09-29）

- `frame/shooter.ts` に `partialChargeShot` を足した。1 パス目（`frame/firstPass.ts`）は窓に入るフレームに、これを `hideShooter` の前に呼び、撃ったら発の記録（`ShotLog.partialShots`）に進みを残す。部分チャージの発は `fullChargeShot` に数えない（`ShotEvent.fullCharge`・`replayEvents`・`cycleShotFrames`・段の循環とゲージの予約の追跡）。
- 1 発の値は `damage.ts` の `partialChargeTriggerDamage`（倍率 1 + (M − 1) × p）。sim は部分チャージの発ごとに値を出し直し、calc は区間ごとに部分チャージの発を別に数えて足す。区間の結果に `partialCharge`（発の数と与ダメージ）を足した。ゲージは `burst/dynamic.ts` の `partialGaugeRatio`。
- 画面: 区間の表のトリガー数に「うち部分チャージ N 発」と、仮定の注記（title）を出す。ブラウザで、紅蓮BS 単騎・射撃場・3 分モードの calc と sim の両方に出て、値が同じことを確かめた。
- テスト: `stage22PartialCharge.test.ts`（射手・1 発の値・ゲージの比・回数トリガー・sim と calc の一致）。窓の中で撃たないことを確かめるテスト（`stage16Events.test.ts`）は、窓の始まりのフレームの部分チャージの発を除いて見る形にした。
- 残差の一覧の変化は V-0042。射撃数は 177 → 180 発（実機は総ダメージに出た 179 発 + コンテナに当たった 1 発）。`046-02` が +2.07% で許容の外に出たので、オーナーの判断で C-0057 の根拠から外し、`055-02` と同じ比べ方（自動の条件。結論に結び付けない）にそろえた。
