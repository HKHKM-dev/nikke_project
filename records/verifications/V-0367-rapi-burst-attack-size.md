# V-0367: ラピのバーストの自分の攻撃力▲の大きさを撮る前の予測で確かめる

- 問い: ラピ（10）のバーストの「自分に攻撃力 60.75%▲・10 秒」の大きさ（60.75%）を、いまの定義のとおりと読んで、モデルは撮る前に予測を固定した最小構成の新しい録画と合うか
- 話題: スキル・キャラ固有
- 日付: 2026-10-08
- Stage: plan/design-minimal-relevance.md 11 節の束 4（根拠の無い効果）。V-0361 の撮影計画 R1
- 状態: 調査中
- 派生元: `V-0361`

## 条件

**確かめる効果**: `data/skills/10.json` の burst の effects[1]（`timed`・`burstUse`・自分・攻撃力・値 2（Lv10 で 60.75%）・値 3（10 秒））。窓の長さ（フルバーストと同じ）は C-0457（確定）で済んでいる。大きさは V-0201 の観測値 `221-08` で見ていたが、撮る前の予測と比べていない（後付け）ので、C-0457 の根拠に入っていない（V-0361）。

**録画**: 撮影計画 R1（「次に撮るもの」）の新しい録画 1 本。`221` と同じ編成（ココア（I・AI）+ デルタ（II・AI）+ ラピ（III・操作・AUTO 射撃 ON））で、ほかの枠は機構の確定したキャラだけ（V-0361 の「最小構成の録画」）。

**ラピのほかの要素**（V-0361 と同じ）

- S1（20 回攻撃を受けると自分に攻撃力▲・20 秒）: 3 分モードでは的が反撃するので付く（前提の外・モデルに無い）。`221` では 2・4 回目のフルバーストの時点で付いていた（`221-07`）。比べるのは S1 の付いていない回の 1 発だけ（C-0457 の minimal の印と同じ見方）。
- S2（ミサイル。C-0403 仮説）: 別のヒットなので、通常攻撃の 1 発の値は変えない。HUD の増分で分ける。

## 予測（撮る前に書く）

R1 を撮る前に書いた（2026-10-08）。仮説と指標は V-0361 の予測ファイルから引き継ぎ、条件を手入力（`setup` に `condition` を書かない。指標の `frame`・`distance` で区間と距離ボーナスを指定する。plan/design-minimal-relevance.md 11.7 節）にした。数値は予測ファイル（records/predictions/V-0367.json）。

| 仮説     | 中身                                           | 見え方（予測ファイルの指標）                                                                                      |
| -------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| H1       | いまの定義（60.75%・発動のフレームから 10 秒） | フルバーストの頭の 1 発（`fb1-early`）が▲とフルバースト補正の付いた値。終わりの直前も同じ値、直後は `base` と同じ |
| H0       | ▲が無い                                        | `fb1-early` がフルバースト補正だけの値（H1 より約 4 割低い）。**大きさの対立仮説**                                |
| H2-short | 窓がフルバーストより短い（代表 8 秒）          | `fb1-late` がフルバースト補正だけの値。C-0457 で外れている（繰り返しの確かめ）                                    |
| H2-long  | 窓がフルバーストより長い（代表 12 秒）         | `after1` が `base` より約 6 割高い。C-0457 で外れている（繰り返しの確かめ）                                       |

- 主に見るのは `fb1-early`（・`fb1-early-nd`）。1 発の値はスペック固定 ON で端数まで決まる（許容 ± 1）ので、H1 の値に乗れば大きさ 60.75% が厳密に合う。H1 とも H0 とも違う値に乗ったら（S1 の付いた発を除き）、大きさの読みが違う。
- H0 の `fb1-early`（胴体）は、▲の無い会心の値と同じになる（`221-17` の注記と同じ重なり）。1 発で見分けず、フルバーストの中の発の格子（胴体・会心・コアの組）で見分ける。
- `burst-hit` はどの仮説も同じ（撃つ側のバフを III の発動の直前で固定する規則。plan/design-burst-landing.md 9 節）。C-0227 の再現の確かめ。
- 距離ボーナスは、1 回目（モデルでは中近）で乗る見込みで、3 回目（遠）では乗らない。両方を予測ファイルに出した。
- **H1 を予想する**。
- 当たったときの影響: burst の effects[1] の大きさの結論を作り、`claims` に結び付ける（確定の候補）。
- 外れたときの影響: 値 2（攻撃力▲の率）の読みを直す。ラピのフルバーストの中の通常攻撃の 1 発がすべて動く。

## 読み方

1. 取り込み: `node tools/captures/intake.ts <元ファイル> --id NNN --name sr+sr+ar_cocoa+delta+rapi_rapi-auto --rid 311,20,10 --controlled 3 --target BigArms --element Fire --mode range-3min --fixed-spec on --auto-fire on --auto-burst on`。冒頭に「録画」を足す。
2. HUD の増分（`npm run records:read -- NNN --recipe hud-jumps`）から、ラピの 1 発（AR の増分。S2 のヒットとココア・デルタの SR の発を除く）を、▲の付いた格子・無い格子・S1 の付いた格子に当てる。
3. 1 回目のフルバーストの前・頭（止まりの明けから数秒）・終わりの直前・直後のラピの胴体の 1 発を、`base`・`fb1-early`・`fb1-late`・`after1` の観測値にする（距離ボーナスは乗るほうの指標。乗っていなければ `-nd`）。1 回目のバーストの倍率ダメージの 3 ヒットの和を `burst-hit`（会心なら `burst-hit-crit`）にする。
4. 2 回目以降は、S1 の付いていない回だけ `fb3-late`・`after3` に足す。S1 の付いた回は記録の観測値に書く。
