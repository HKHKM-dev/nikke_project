- 関連: V-0761（根拠）・V-0748・C-1142、[design-skill-stage13.md](design-skill-stage13.md) 2.1〜2.6 節（チェーンの攻撃・チェーンバインドの定義）、[design-raven-s1.md](design-raven-s1.md) 4 節（持続ダメージのゲージの 1 パス目の追い方）、[design-split-first-pass.md](design-split-first-pass.md) 3.4 節（1 パス目のゲージの作り手）

## 1. 根拠と範囲

- 溜めるもの（V-0761 の撮り方 C1・C2 の差 47〜53 発が、3 つ全部の 49 発に合う）:
  - S1 の攻撃（`data/skills/162.json` の skill1 の effects[2]。`{ counterFull }` のきっかけの damage、チェーンの数だけ 15f ごと）
  - チェーンバインドの付与のヒット（effects[4] の dot の `hitOnApply`。攻撃の 2f 前ごと）
  - チェーンバインドの tick（同じ dot。最後に付けた時から 0.5 間隔後と、その後 59.25 ごと）
- 1 ヒットの量は射手の `target_burst_energy_pershot`（ミハラ：ボンディングチェーンは 1,000。ゲージ速度は掛ける）。撃たない持ち主でも同じ量（撮り方 C1。アニス：スターの味方のゲージ C-0246 の半分の形にならない）。
- 範囲の外（確かめていないので溜めない。スキル定義の注記に残す）:
  - S2 のフルバースト中のスタック量▲（skill2 の effects[1]）の 1 スタックぶんのヒット
  - バーストのプリング・チェーン（burst の effects[0]）の tick
  - 味方のゲージ（アニス：スターの allyGaugeAdd）の回数に数えるか

## 2. スキル定義の項目

既にある項目を、`{ counterFull }` のきっかけにも書けるようにする（新しい項目は足さない）。

| 効果 | 項目 | 足す読みの規則 |
| --- | --- | --- |
| damage（`{ counterFull }`） | `gaugePerHit: true` | perCount `{ counter }` を perCountIntervalFrames で 1 つずつ出し、delayFrames がある（どのヒットも発火より後のフレーム）。条件は組まない |
| dot（`{ counterFull }`） | `gaugeOnApply: true` | 付けるフレーム（発火の applyDelayFrames 後から間隔ごと）に 1 ヒットぶん。`gaugeOnApplyDelayFrames` は組まない |
| dot（`{ counterFull }`） | `gaugeOnTick: true` | firstTick `halfAfterLatest` だけ（刻みは frame/dot.ts の latestDotTicks と同じ） |

## 3. 1 パス目

- 新しい作り手 `frame/firstPass/counterGauges.ts` に置く（gaugeEffects.ts の射撃の回数の追跡とは発火の元が違う）。フレーム f の手順 3（件の登録）の後に呼ぶ。
- 発火: 件の一覧のカウンタの記録で、上限に届いたきっかけが f + 1 に発火するとき（戦闘開始時の記録は f = 0 で 1）。数は上限（届いた時の値）。
  - 攻撃と付与のヒットのフレームは、2 パス目（frame/plan.ts の planSkillHits）と同じ関数（effectHitFrames・perCountFrames）で出し、そのフレームのゲージに予約する。
- tick: 同じ状態の dot ごとに、最後の付与（基点）と次の刻みを持ち、f の終わりに f + 1 が刻みなら f + 1 のゲージに予約する。2 パス目の latestDotTicks と同じ規則にそろえる:
  - 付与（予約した付与のフレームと、S2 のスタック量▲の付与）で基点を付け直す。次の付与のフレームちょうどの刻みは出さない。
  - 消去（cancelState。バーストの使用）のフレームより後の刻みは出さない（消去のフレームちょうどの刻みは出る）。消去の後は、次の付与まで刻みが無い。
  - S2 のスタック量▲は、2 パス目と同じきっかけ（出来事の列の TriggerTracker）と条件（発火のフレームに敵がその状態か）で追う。▲のヒット自体のゲージは溜めない（1 節）。
- 1 フレームの差の残し: f の終わりに f + 1 の刻みを予約するので、f + 1 に S2 のスタック量▲が付く（f + 1 の手順 3 で分かる）と、2 パス目はその刻みを出さないが、1 パス目は刻みの分を予約する。S2 の▲はフルバーストの中だけで、バーストの状態機械はフルバーストの中のゲージを足さない（溜めている段だけ足す。burst/controller.ts の stepBurstController）ので、時刻表には効かない。0754 で 1 回ある（f5391）。
- 記録: 予約したゲージを `FirstPassResult.counterGauges`（攻撃・付与・刻みの別、フレーム、量）に残す（テストと照合用）。

## 4. モデルの値の動き（2026-11-14 のモデル）

- 単騎・操作（撮影 B の B2）の 1 回目の満タンまでの発: 1000 発 → 951 発（録画 954・955 発）。
- 撮り方 C1 のクラウンの発: 1000 発 → 951 発（録画 956・957 発。C2 はモデルの 1000 発に録画 1004〜1009 発で、AI の数発のずれは同じ形）。
- 0754 の 1 回目のゲージの満タン: 414f → 398f（0755 と同じ。C-1142）。
- 0747（リター・デルタ・ミハラ：ボンディングチェーン）は、ゲージが早く溜まり、4 回目のフルバーストのチェーンが録画と替わる（録画は I の後に II の CT を約 570f 待ったチェーンで、モデルは I の後に CT が窓に間に合わず切れる）。4 回目のバーストのプリング・チェーンの値を比べる `0747-10`（C-0746）は、モデルのチェーンの時刻に依っていたので、録画の I の本当の発動の並び（`0747-16`。入力）を比べる設定の `manualBursts`（[design-compare-setup-extension.md](design-compare-setup-extension.md) 3 節）で渡して比べる（[verification-guide.md](verification-guide.md) 付録 B）。オートバーストの録画でも、I を並びのフレームと満タンの 23f 後の遅い方で撃つ形はそのまま使える。
