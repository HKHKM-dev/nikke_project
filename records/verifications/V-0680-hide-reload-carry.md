# V-0680: ハイド中のリロードの後の、最初のふだんのリロードの長さ（端数の持ち越しをハイド中のリロードで変えるか。0469・0470・0727・0728・0250・0251 の読み直し）

- 問い: 敵のジャンプの間のハイド中のリロード（取り消し）の後の、最初のふだんのリロード（最終弾 → 込め終わり）は、ほかのふだんのリロードと長さが違うか。ゲームはリロードの端数を次へ持ち越すのか、ハイド中のリロードで数え直すのか
- 話題: 射撃（間隔・リロード・チャージ）
- 日付: 2026-11-07
- 録画: `0469`、`0470`、`0727`、`0728`、`0250`、`0251`
- 結論: `C-0964`
- 状態: 完了
- 派生元: `V-0676`

## 条件

- 型: 読み直し。案 D（[design-hide-reload.md](../../plan/design-hide-reload.md) 10 節。C-0959）で、モデルはハイド中のリロードの 1 回分を切り上げた長さ（1.67 秒は 99f）にしたが、端数の持ち越し（`reloadCarry`）は切り捨て（98f）として進めたまま。ハイド中のリロードの後のふだんのリロードが、モデルでは 1f 違って出る回がある。持ち越しの扱いを変えるか（同 11 節）を、録画で決められるかを見る。
  - 仮説の出どころはモデルのコード（`frame/shooter.ts` の `hideShooter`・`startReload`・`nextChunkFrames`）で、録画ではない。
- 録画: ミハラ（161。AR・60 発・リロード 1.67 秒。操作）の `0469`・`0470`（ラム・デルタ・ミハラ）と `0727`・`0728`（アニス：スター・デルタ・ミハラ）、マナ（290。AR・リロード 1.67 秒）の単騎 `0250`・`0251`。どれも射撃場 BigArms・3 分モード・オート射撃（V-0676・V-0648 と同じ録画）。
- 見分けの要: 1.67 秒は 98.24f（ゲーム内の時計の 1 フレーム 0.017 秒。C-0145・C-0502）。モデルの持ち越し（1 回分ごとに端数を足して切り捨て、残りを次へ）なら、ふだんのリロードは約 4 回に 1 回（0.235 の割合）が 99f、ほかが 98f で、込め終わりが 1f 遅い回が混ざる。ゲームが同じように持ち越すなら、ハイド中のリロードの後の回で並びがずれるかを見分ける。ゲームが持ち越さないなら、どの回も同じ長さで、ハイド中のリロードで数え直すかは見えない。
- 最小構成: ミハラ・マナのリロードに効く効果は、本人にも味方にも無い（C-0959 の `minimal` と同じ）。アニス：スターのバーストの効果はミハラのリロードに効かない（C-0964 の `minimal`）。

## 予測

なし（読み直し）。

## 読み方

1. 録画は Drive から取り寄せた（`node tools/captures/fetch.ts`）。
2. `node tools/captures/reload.ts <動画> --mode fit --shots <hud.ts --mode jumps の出力>` で、リロードごとの RELOADING のバーの長さ 0 に遡った点（0 の点）・消えたフレーム（込め終わり。照準の残弾が満タンに戻るのと同じフレーム）・当てはめの残差を読んだ。
3. `node tools/captures/reticle-ammo.ts <動画> --mode series` の照準の残弾で、各リロードの前に 1 を読んだ最後のフレームの次を最終弾にした（リロードの間は残弾が出ない）。HUD の増分の最終弾（`reload.ts` の `lastShot`）とは多くの回で同じフレーム。
4. ハイド中のリロードは、照準の残弾が 1 より多いまま（マガジンの途中で）バーが満ちる前に消えた回（V-0676 の明けと同じフレーム）。その後で最初に撃ち切ったリロードを「ハイド中のリロードの後の最初のふだんのリロード」にした。
5. ほかのふだんのリロードは、窓をまたいだ回・取り消しの回・最終弾か 0 の点が読めない回（照準の残弾が読めない、当てはめの残差 1.2 より大きい、0 の点 − 最終弾が −2.8〜1.2f の外）を除いた。
6. モデルの側は、持ち越しの扱いを (b1) ハイド中のリロードで 0 にする、(b2) ハイド中のリロードでは進めない、の 2 つに変えて、全部の観測値の残差（`npm run records:residual`）をいまのモデルと比べた（コミットしていない）。

### 読み

- ハイド中のリロードの後の最初のふだんのリロードは 14 回（ミハラ 7 回: `0469-16`・`0470-16`・`0727-22`・`0728-23`、マナ 7 回: `0250-18`・`0251-13`）。0 の点 → 込め終わりは 110.02〜111.10f で、同じ録画のほかのふだんのリロードの幅に入る。最終弾 → 込め終わり（整数）は 109〜111f。
- ほかのふだんのリロードは 70 回（`0469-17`・`0470-17`・`0727-23`・`0728-24`・`0250-19`・`0251-14`）。0 の点 → 込め終わりの録画ごとの平均は 110.51〜110.86f で、多くの回が平均から ±0.3f に入る。111.4f 以上（平均より 1f 近く長い）は 3 回（111.86・111.7・111.7f）。最終弾 → 込め終わりは 109f が 12 回・110f が 56 回・111f が 2 回で、109f の回は 0 の点 − 最終弾が約 −1.7f（ほかの回は約 −0.8f）、0 の点 → 込め終わりはほかの回と同じ（最終弾のフレームの読みが 1f 遅れた形）。
- いまのモデルの持ち越しなら、70 回のうち約 16 回が 1f 長い。3 回以下になる見込みは 1 万分の 1 より小さい。ゲームは 1.67 秒のリロードを 1 回ずつ同じ長さで込め、端数を次のリロードへ持ち越していないとみられる（スキルの CT を 1 回ごとに ceil で数え直す C-0502 と同じ向き）。

### モデルの持ち越しの扱い（(b1)・(b2)）

- どちらでも、比べる観測値（2798 件）の状態は 1 件も変わらない。
- 値が動くのは、それぞれ 10 件（与ダメージ・ジャンプの前後の発の時刻・部分チャージの進み・▲の切れた回数）: (b1) は `0250-16`（ジャンプの前の最後の発 → 明け。差の最大が +5 → +1f）・`0103-01`（与ダメージ +1.42% → +2.03%）・`0122-31`・`0122-34`・`0123-25`、(b2) は `0250-16`・`0251-11`・`0306-16`・`0284-10` など。どちらの向きにも動く。`0250-16` が (b1) で合う側に動くのは、リロードの 1f の並びがずれて 3 回目のジャンプの前の発の位置が変わったためで、ゲームが持ち越していない（上の読み）ので、(b1) の根拠にはしない。

## 分かったこと・分からないこと

- 分かった: ハイド中のリロードの後の最初のふだんのリロードは、ほかのふだんのリロードと同じ長さ（14 回）。ふだんのリロードも 1 回ずつ同じ長さで、モデルの持ち越しの 1f 長い回が見えない（C-0964）。
- 決めた: ゲームが持ち越していないので、ハイド中のリロードで持ち越しを数え直すか（(b1)・(b2)）は録画では見分けられず、モデルはいまのまま（持ち越しはハイド中のリロードの後もふだんのリロードと同じに進める）にした（[design-hide-reload.md](../../plan/design-hide-reload.md) 11 節）。
- 分からない: 1.67 秒だけで見た。リロードの秒の端数が 0 に近いキャラなら、持ち越しても長い回は出ない。ほかのリロードの秒でも 1 回ずつ同じ長さか、1 回ごとに丸めるならどの向きか（1.67 秒の 0 の点 → 込め終わり約 110.7f は、98.24f + 約 12.5f で、整数の向きは足す長さ（C-0135・C-0148 で合わせた値）と分けられない）。モデルを持ち越さない形にするかは backlog の 2-58。
