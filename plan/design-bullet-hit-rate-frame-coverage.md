## Context

- 命中率▲は弾丸命中率を上げ、SMG の遠では H2 の形と合った（C-0192、仮説。V-0118）。オーナーの判断で、モデルには入れず、命中率の調査として別に起案し直す（backlog 2-1）。
- オーナーが挙げた射撃場の的の前提:
  1. 形は、コアのある中心の塊から細い上半身と脚が生えている。
  2. 照準円の大きさの増減と、照準円の中で的が占める面積の増減が比例しない。
  3. 的は左右に動き、向きによって、同じ距離でも照準円の中の的の面積が変わる。
- 求められていること:
  - **射撃場の的に限らず**、ほかの形・ほかの動きの敵にも、同じ計算式で対応できること（将来、別の敵を実装する）。
  - **実装までの時間**が見合うこと。
- この案は、形と動きを式でモデル化しない。**録画のフレームごとに「照準円のうち当たり判定に入る割合」を数え、時間で平均する**。敵ごとに違うのは道具に通す録画だけで、計算式と core のコードは敵によらない。

## 0. 今わかっていること

### 0.1 関係する結論

- 照準円の画面上の半径は、約 0.285 × CDN の `*_accuracy_circle_scale`（C-0038）。▲で半径 × (1 − N) と矛盾しない（C-0041。×1/(1 + N) とは区別できていない）。
- 照準円は、撃たない間は CDN の速さで戻る（C-0039）。MG は 1 発ごとに縮む（C-0040、仮説）。
- 常時の▲はコア命中率を 1/(1 − N)² 倍にする（C-0036、確定）。これは「弾が照準円の中で一様」「コアが照準円の中に収まる」「半径 × (1 − N)」の 3 つから、そのまま出る式。
  - **N が小さく、コア命中率が小さいときは、一様と正規分布を区別しない**。コアが照準円より十分小さければ、中心の密度が半径² に反比例する散らばりは、どれも 1/(1 − N)² になる。根拠のうちクルミのキューブ（N = 0.0509）の倍率は、どちらの形の予測も信頼区間に入る。
  - **N が大きいと区別できる**。根拠のうち旧のクエンシー：エスケープクイーン（SMG、N = 0.4942。verification.md Stage 18-A「照準円と命中率▲」）では、実測が一様の式とほぼ一致した。同じ集計の値から正規分布（σ = R/√2。1.1 節）で出すと、約 0.09 低くなる（帯の重みを無視した概算）。旧の 1 本で、帯ごとには分けていないので、決め手にはしないが、一様を支持する材料になる。
  - C-0183（ミサトの 3 スタック、N = 0.1512）の帯ごとの倍率は、揺れが大きく、2 つの形を分けられていない。
  - C-0192 の H2（外れの割合の対数が 1/(1 − N)² 倍）は、「正規分布の散らばり + 中心に円の的」でそのまま出る形（外れ = exp(−r²/2σ²)）。ただし、一様の散らばりでも、的の形（前提 1・2）しだいで H2 に近い効き方になりうる。一様の散らばりで的がまるごと照準円に収まると H3 になる。
  - 散らばりの形は、この案でいちばん先に確かめるもの（5.1）。**散らばりの形はコアにも胴体にも同じものが効くので、正規分布を選ぶと、C-0036 のモデル側（p ÷ (1 − N)²）と食い違う**（10 節の 5）。
- コアの当たり判定は、半径が距離に反比例する円とみなせる（C-0046、仮説）。
- ▲は弾丸命中率を上げる。H3（当たり全体を 1/(1 − N)² 倍）より弱い（C-0192、仮説）。
  - 一様な散らばりのもとで H3 になるのは、的の当たり判定がまるごと照準円の中に収まっている場合。外れたのは、手足が照準円の外まで伸びているためと説明できる（前提 1・2）。
- 弾丸命中率の表は、距離帯ごとの値（C-0034）で、▲には効かせていない。

## 1. 方式の要点

### 1.1 式

着地点（場面）L、照準円の大きさ s（CDN の単位。▲の後の値 = CDN の値 × (1 − N)）について、次のように置く。

- 弾丸命中率 h(L, s) = 発射の瞬間のフレーム t（1 発 1 標本。2 節 1）での C_t(s) の平均。
- C_t(s) = フレーム t で、照準の中心 a_t に置いた散らばり K（半径 R = 0.285 × s）のうち、的の当たり判定 M_t（マスク）に入る割合。

決めていること:

- **散らばり K は一様を主の仮説にする**。正規は対立仮説として、下見（5.1）で比べるだけにする。
  - 一様（主）: 半径 R の円の中に一様。C-0036（確定）と同じ前提で、N の大きい旧の 1 本も一様を支持する（0.1）。
  - 正規（対立）: 中心を a_t とする 2 次元の正規分布で、σ = R/√2（打ち切らない）。中心の密度が一様と同じになる σ で、コアが小さいときのコア命中率（C-0036・C-0046）は一様と変わらない。**調整する係数は持たない**。
  - 正規の表は、2 節 4 の動径の数え方で一様と同じ画素の数え上げから出せるので、道具の手間はほとんど増えない。増えるのは判断の手間なので、選び方を「既定は一様。正規に替えるのは、決めた規則で一様がはっきり負けたときだけ」にする（5.1 の 2）。
  - K を比べる材料には、弾丸命中率（マスクから作る表）のほかに、マスクの要らないコアの▲の倍率（5.1 の 0）を使う。散らばりの形は、コアにも胴体にも同じものが効くため。
  - 正規に替えると、C-0036 のモデル側と食い違う（0.1）。その場合は 5.2 に進む前に、C-0036 の扱いをオーナーに諮る（10 節の 5）。
  - K は、5.2 の予測の前に commit して固定する。
- **照準の中心は、実際に読んだ位置を使う**。コアに合っているとは仮定しない。照準の遅れ（0.2 の (a)）も C_t に入る。
- **形と動きは、M_t と a_t の時系列に入っている**。向き・移動・姿勢の変化・跳ぶ前後を、式では表さない。フレームの標本が、そのまま時間の重みになる。
- **距離の推定は要らない**。画面の px のまま数えるので、C-0045（推論）に頼らない。
- s を変えた表を作れば、▲（N）と武器種（CDN の値）の違いは、同じ表を引く s の違いになる。▲の弾丸命中率の式（C-0192 の H2 など）を別に持たない。

### 1.2 敵によらない部分と、敵ごとの部分

| 部分                               | 中身                                                   | 敵によるか                         |
| ---------------------------------- | ------------------------------------------------------ | ---------------------------------- |
| 照準円の大きさ                     | 0.285 × CDN の値 × (1 − N)（C-0038・C-0041）           | よらない                           |
| 散らばり方                         | 一様（主）。正規（σ = R/√2）は対立仮説で、5.1 で比べる | よらない                           |
| 被覆率の数え方                     | 道具（2 節）の計算                                     | よらない                           |
| 当たり判定の形・動き・照準の追い方 | 録画から読んだ M_t と a_t                              | **敵ごと**（録画を道具に通すだけ） |

### 1.3 前提 1〜3 との関係

- 前提 1・2（中心の塊 + 細い手足で、比例しない）: 形の仮定を置かないので、そのまま入る。
- 前提 3（向きで面積が変わる）: 向きの分布を推定せず、フレームの標本の重みとして入る。
- ほかの敵（部位が分かれる・宙に浮く・大きく姿勢が変わる）も、M_t が読めれば同じ式で入る。
- 大型のボスで照準円が当たり判定の中に収まるなら、C_t は 1 に近くなり、特別な扱いをしなくても片付く（確かめる。7 節）。

## 2. 道具（`tools/captures/coverage.ts`。新規。`aim.ts` の処理を使う）

1. **フレームを選ぶ**:
   - **発射の瞬間のフレームだけ**を使う。残弾の列（`ammo.ts`）で残弾が 1 減ったフレームを 1 発とし、1 発を 1 標本にする（重みは等しい）。命中は撃った瞬間に決まるので、発射の間の待ちのフレームは使わない。
   - 録画のフレームと発射の瞬間のずれ（±1f）は、照準の動きが 1f で数 px 以内なら効かないとみる。5.1 の 1 で、照準の中心の 1f あたりの動きを出して確かめる。
   - 区間（着地点）の境目は、既存の読み方（ジャンプ・着地の時刻）で切る。各区間に着地点の id（`nearA`・`nearB`・`midNear`・`midFarA`〜`C`・`far`）を付ける。中遠は足元の高さ（V-0089 の読み方）、近は C-0155 の分け方で決める。
2. **照準の中心 a_t**: `aim.ts` の照準の検出をそのまま使う。信頼度の低いフレームは落とす。
3. **的のマスク M_t**:
   - `aim.ts` の背景差分の連結成分を、外接矩形ではなく画素のマスクとして出すように広げる。いまは半分の解像度で探しているので、輪郭だけ全解像度で取り直す。
   - 次のフレームは落とし、落とした割合を出力に残す。
     - `fx` が高い（爆発など）。
     - 的が探す範囲の端に接している。
     - 遮蔽物（緑の箱）が的とつながっている。遮蔽物に当たった発の扱い（C-0108）は、別の欄で数える。
   - **マスクの前処理**（どれも 5.1 の 1 で、デバッグ画像を見て要否と量を決め、設定（2 節 6）に固定する）:
     - 穴埋め: 的の明るい所（金属の光沢・白飛び）は「背景より暗い」を満たさず、マスクに穴が開く。閉じる処理（closing）と、外側につながらない穴の塗りつぶしで埋める。
     - 影: 足元に影が落ちていれば、背景より暗いので足とつながり、マスクが下に広がる（下に外れた弾を当たりと数える）。影があるかを先に見て、あれば、着地点ごとの足元の高さ（V-0089 の読み方。影の無い足の下端）より下の画素を除く、などの切り方を決める。
     - 霧の脚（5.1 の 1）も、ここで扱いを決める。
4. **被覆率 C_t(s)**（照準の中心からの距離ごとの画素の数で、全部の s を一度に出す）:
   - 1 発ごとに、a_t からの距離が r_max 以内のマスクの画素を、距離（画素の中心まで。0.5px 刻み）ごとに数えた列 m(r) を作る。
   - 一様（主）: C_t(s) = （r ≤ R の m(r) の和）÷ πR²（R = 0.285 × s）。照準円に入るマスクの面積の割合そのもの。
   - 正規（対立）: C_t(s) = Σ_r m(r) × exp(−r² / 2σ²) ÷ 2πσ²（σ = R/√2）。r_max は 3R まで取る（裾の残りは 1% 未満）。
   - 計算の量: 1 発あたり、半径 r_max の円の中の画素を 1 回なめるだけで、s の格子の点の数によらない。範囲の武器（AR・SMG）の s は 130 までで足りる（4 節。▲は s を小さくするだけで、▼は扱わない）。正規でも r_max = 3 × 0.285 × 130 ≈ 111px で、1 発あたり約 4 万画素、SMG の 180 秒の約 3,300 発（V-0118 の撃った数）で約 1.3 億回の加算。一様だけなら約 4,000 画素で 10 分の 1。点の組を s ごとに置き直す形（1 発 × 点 2,000 × s 30 点）より少なく、点の組の作り方（ひまわり型・レイリー分布の分位）も要らない。
   - 小さい s の分解能: R が数 px（s ≲ 20）では、画素の数え方の粗さが残る。範囲の武器では、▲ 80% 以上でないとこの大きさにならないので、表には出すが、注記に粗いと書く。
   - s の格子（例: 0 と、5〜130 の CDN の単位で 26 点程度）。s = 0 は「照準の中心の画素がマスクに入る割合」で、▲が 100% 以上のとき（C-0037）にそのまま引く。
   - 1 発ごとの C_t（s = 範囲の武器の値）も出力に残す（5.3 の発ごとの突き合わせに使う）。
   - **単調にそろえる処理はしない**。照準の中心が的の外にあるとき、C_t(s) は s とともに増える（円が広がって的に届く）ので、h(L, s) が s に対して単調に減るとは限らない。全部の s を同じ発の同じ画素から出すので、s の間の揺れは互いにそろい、ノイズで局所的に逆転することはほとんど無い。
5. **出力**:
   - 着地点ごとに、s の格子と h(L, s) の表を出す。採ったフレームの数、落としたフレームの割合、録画の中でのばらつき（区間ごとの h の標準偏差）も出す。
   - これは録画から読んだ値なので、観測値（`records/observations/`）として置く。
   - マスクの画像は、証拠フレームと同じ扱いにして `E:/nikke_project_captures/` に置く（コミットしない）。
6. **設定の固定**: 背景差分のしきい値・マスクの前処理（穴埋め・影の切り方・霧の扱い）・フレームを落とす条件（`fx` のしきい値など）・s の格子・K は、設定ファイルに書き、出力に設定の版を残す。判定の撮影（5.2）の前に commit し、撮った後は変えない（6 節）。

## 3. データの形（`data/enemies.json`）

`targetProfiles[*]` に、着地点ごとの被覆率の表を任意の欄として足す（例）。

```json
"bulletCoverage": {
  "unit": "accuracyCircleScale",
  "landings": {
    "far": { "s": [0, 5, 10, 20, 40, 75, 110, 130], "h": [/* 観測値から */], "source": "観測値の ID" },
    "midFarB": { "s": [/* 同じ格子 */], "h": [/* 観測値から */], "source": "観測値の ID" }
  },
  "source": "plan/design-bullet-hit-rate-frame-coverage.md。値は観測値（ID）"
}
```

- **鍵は着地点の id**（`profile.landings` の id）にする。距離帯（`near`・`midFar`）や配分の id では持たない。
  - h(L, s) は s について線形でないので、中遠の A・B・C を 1 つの表にまとめると、配分の重みと▲の効き方が混ざる。録画の区間に着地点の id を付けて（2 節 1）、着地点ごとに表を作る。
  - core は、配分の id を `landingMix` で着地点に分けた後に、着地点ごとに表を引く（いまの `autoConditionAt` と同じ順）。配分の重みは、着地点ごとの値に掛かる。
  - 着地点ごとに独立に引く。ある配分の中で表のある着地点と無い着地点が混ざってもよく、無い着地点は、次の行の順でいまの表に戻る。どの着地点が表から取れたかは、注記に出す（4 節）。
  - 中遠 A は 1 本の録画に出ないことが多い（10 回中 3 回。C-0044）。A の表は、A が出た録画が集まるまで作らず、いまの表に戻す。
- `bulletCoverage` の無い敵・着地点は、いまの `bulletHitRate` の表を使う（後戻りできる形）。
- どちらの表も無い敵・着地点は、いまのとおり手入力の弾丸命中率で計算し、未測定と注記する（`autoConditionAt` の `manual`）。**形の分類や形の関数から推計した値は出さない**（8 節）。
- 表は武器種で分けない。武器種の違いは s（CDN の値）に入る。ただし、照準の追い方が武器種で違うかは分からない（9 節の 3）。その分が確かめで出たら、武器種ごとに表を分けられるよう、`landings` の下に武器種の鍵を置ける形にしておく。

## 4. 入れ方（core）

### 4.1 表の引き方

- 着地点ごとの弾丸命中率を、次の順で決める。
  1. 枠の武器種が **AR か SMG**。かつ、`bulletCoverage` にその着地点がある。この場合は、s = `accuracy.autoStart` × (1 − clamp(N, 0, 1)) で表を線形に引く。N ≥ 1 なら s = 0 の値（C-0037。2 節 4）。
  2. それ以外は、いまの `bulletHitRate` の表を使う（▲を見ない）。
- 条件を「照準円が撃つたびに変わらない（`accuracy.autoChangePerShot` が 0）」にしない。それだと SR・RL・ふつうの SG も満たし、下の範囲外の武器が被覆率の表に置き換わる（CDN のデータで、SR・RL は 10/10、ふつうの SG は 250/250 で、どれも 0）。
- **命中率▼（N < 0）は扱わない**。N を 0 で切り、s は CDN の値のまま引く。コア命中率の `coreHitRateWithHitRateUp` も N ≤ 0 では変えない（▼の効き方は測っていない。design-sustained-hit-rate-core.md 5 節）ので、それとそろえる。
- 表の格子の外は端の値で止める（s が最大の格子より大きければ最大の格子の値）。範囲の武器では s ≤ CDN の値 ≤ 格子の最大（2 節 4）なので、ふつうは起きないが、配列の外を引かないための守り。

### 4.2 持続の▲（区間ごとの N）

- いまの `autoConditionAt` は計画の時点（`planLandings`）で常時の N だけを受け取り、持続の▲は `landingPartsWith` がコア命中率だけを出し直している（0.4）。弾丸命中率を▲で変えるには、`landingPartsWith` でも出し直す必要がある。
- `LandingPart` に、被覆率の表から取ったときの材料を持たせる: `coverage?: { s: number[]; h: number[] }`（その着地点の表）と `accuracy`（枠の `accuracy.autoStart`）。表から取らなかった部分は持たない。
- `planLandings` は、常時の N で 4.1 の値を `condition.hitRate` に入れる（いまの計画の値と同じ役目）。
- `landingPartsWith(plan, slot, slotIndex, landing, hitRateUp)` は、コア命中率と同じく、`coverage` のある部分の `condition.hitRate` を、区間の N（常時 + 持続）で 4.1 のとおり引き直す。
  - いまの早い戻り（「`tableCoreHitRate` のある部分が無ければ計画の配分をそのまま返す」）は、「`tableCoreHitRate` も `coverage` も無ければ」に直す。
  - キャッシュの鍵（枠・着地点・N）は今のままでよい。
- N は、コア命中率と同じ値（`state.buffs.hitRate`。常時の和 + その区間の持続の和）。

### 4.3 1 パス目（ゲージ）との境目

- **1 パス目のゲージの弾丸命中率は、計画の値（常時の N）のままにする**。持続の▲で上がった弾丸命中率は、2 パス目（calc・sim の与ダメージ）にだけ効く。
  - 理由: 1 パス目の弾丸命中率の区間は、`frame/plan.ts` が `runFirstPass` の前に `hitRateSpansOf(plan)` で作っており（0.4）、持続の▲の窓はその時点で分からない。持続の `hitRate` は「状態だけの stat」として、射撃に効く窓とは別に置かれている（design-sustained-hit-rate-core.md の経過）。
  - 持続の▲の中は、ゲージが実際より遅く溜まる側にずれる。その枠の注記に「持続の命中率▲は弾丸命中率の与ダメージに入れ、ゲージには入れていない（未実装）」と出す。
- ゲージに入れるのは、別の設計にする。1 パス目はフレーム順に進むので、あるフレームで付いた▲が後のフレームのゲージに効く形にすれば、順序は崩れない（循環にはならない）。ただし、1 パス目が持続の `hitRate` の窓を射撃に効く窓と同じく追う必要があり、この案の範囲より大きい。
- コア命中率はゲージに効かないので、いまの扱い（2 パス目だけで出し直す）と食い違いは無い。

### 4.4 測ったかの判定と表示

- 「弾丸命中率を測ったか」の判定（`frame/landing.ts` の `measuredHitRate` と、未測定の注記 `auto-condition-unmeasured`）も、被覆率の表から取った部分を「測った」側にするよう、4.1 と同じ順で判定する。
- 表示: 条件の注記に、弾丸命中率の出どころ（着地点ごとに「被覆率の表（▲を含む）」か「距離帯の表」か）と、4.3 のゲージの未実装を出す。

### 4.5 範囲外（いまの表のままにする）

- MG・照準円が縮む SG（プリバティ）: 撃つたびに照準円が変わる（C-0039・C-0040）。
- ふつうの SG: ペレットの当たる割合（C-0156）が、照準円の大きさから見込むより高く、照準円とペレットの広がりの関係が分かっていない。
- SR・RL: 弾丸命中率は 1 で確定している（C-0168）。RL は弾が飛ぶ間に的が動き（C-0173）、爆発の範囲もあるので、撃った瞬間の照準と輪郭では表せない。

## 5. 確かめ方

### 5.1 段 A: 下見（撮影なし）

次の順に進め、前の段を通らなければ先に進まない。

0. **コアの▲の倍率で K を比べる（机上。マスクも道具も要らない）**:
   - コアを照準の中心に置いた円（C-0046）とみなし、▲なしのコア命中率 p から、▲ありの値を K ごとに出す。
     - 一様: min(1, p ÷ (1 − N)²)。
     - 正規（σ = R/√2）: 1 − (1 − p) ^ (1 ÷ (1 − N)²)。
   - 比べる材料は、C-0036 の根拠（クルミのキューブ・旧のクエンシー：エスケープクイーン）と、C-0183 の帯ごとの倍率。帯ごとの p で出し、帯の重みはそれぞれの記録のヒットの数で付ける。
   - どれも既に見た値なので、K を選ぶ材料にとどめる。照準の中心とコアのずれ（0.2 の (a)）は、ここでは入れない。
   - 結果は 2 の選び方に入れる（2 の「選び方」）。ここで正規が一様より χ² で 4 以上悪ければ、正規を対立仮説から外し、2 では一様だけを見る。
1. **マスクの質（遠の霧を最初の関門にする）**:
   - 既存の AR・SMG 単騎・AUTO の射撃場の録画（V-0118 の 152〜160 など）を道具に通し、M_t と a_t が読めるかを確かめる。見るもの:
     - 落とすフレームの割合。
     - 遠の脚が霧で欠ける程度。
       - 霧に隠れない上半身の幅と高さで、近と遠の縮みの比を出す。推定距離（C-0045）は使わない（1.1 節）。
       - その比で近のマスクを縮め、遠のマスクと**脚の部分だけ**（長さ・面積）を比べる。全体の面積は、的の向きの分布が近と遠で違う（前提 3）ので比べない。
       - デバッグ画像を目で見る。
     - デバッグ画像を目で見たときの、マスクの誤り。
     - 足元の影でマスクが下に広がっていないか、光沢でマスクに穴が開いていないか（2 節 3 の前処理の要否と量）。
     - 発射の瞬間のフレームの取り方（2 節 1）: 残弾の減ったフレームが発ごとに取れているか（`ammo.ts` の読み落とし）と、照準の中心の 1f あたりの動き。
   - 外れが最も多いのは遠で、判定（5.2）も遠で行う。遠のマスクが使えなければ、この案は判定に進めない。
   - 霧の扱い（そのまま使う・近の輪郭を縮めて補う・遠を範囲の外にする）と、マスクの前処理（穴埋め・影の切り方）は、**h と外れの割合を並べる前に**、マスクの質だけで決めて commit する。並べた後で選ぶと、合うほうを選ぶことになるため。
2. **散らばりの形（K）を決める**（一様が既定。正規に替えるかだけを決める）:
   - 読めた録画から、着地点ごとの h(L, s) を一様と正規の両方で出し（0 で正規を外したら一様だけ）、次のものと並べる。
     - **主な材料**:
       - 同じ録画の実際の外れの割合（V-0118 の判定の指標と同じ数え方）。
       - V-0118 の▲の 2 群。対照の録画から作った表を s × (1 − N) で引き、外れの割合の比 q（V-0118 の指標）で比べる。
     - **参考**（選び方に入れない）: C-0034 の表。旧の別の日の録画で、σ がはっきりしないため。
   - 選び方は、並べる前に決めて commit しておく:
     - 主な材料と 0 の材料について、K ごとに χ² = Σ((予測 − 実測) ÷ σ)² を、0 の材料（コア）と主な材料（弾丸命中率）で別々に出す（σ は録画単位）。
     - **既定は一様**。両方の材料で正規が一様より χ² で 4 以上よいときだけ、正規に替える候補にする。そのときは 5.2 に進む前に、C-0036 の扱いをオーナーに諮る（10 節の 5）。
     - 片方の材料だけで正規がよい、または差が 4 未満なら、一様のまま 5.2 に進む。正規の予測は 5.2 で参考として並べるだけにする（判定には使わない）。
   - 一様が大きく合わなければ（正規でも合わなければ）、5.2 に進まない。当たり判定が見た目の輪郭と違うか（5.3 の結果を見る）、散らばりがどちらの形でもないかを疑う。
   - どれも**既に見た値なので、K を選ぶ材料と再現の確かめにとどめ、結論は作らない**。
3. **表を武器種で共通にするか**（3 節。0.2 の近い側の食い違い）:
   - 同じ着地点について、AR 単騎の録画から作った表 h_AR(L, s) と、SMG 単騎の録画から作った表 h_SMG(L, s) を、同じ s（75 と 110）で比べる。2 つの表の違いは、マスクではなく照準の追い方（a_t の動き）の違いから出る。
   - 線引き（並べる前に commit する）: 全部の着地点・2 つの s で |h_AR − h_SMG| が 2σ（2 つの表の録画単位の σ を合わせたもの）未満なら、武器種で共通の表にする。
   - 1 つでも 2σ 以上なら、その着地点は武器種ごとの表にする（3 節の武器種の鍵）。その場合、別の敵でも「敵 × 武器種」で録画が要るので、7 節の手間の見込みを直す。
   - AR の録画は、18-B の単騎・AUTO の録画など既存のものを使う。足りなければ、5.2 の撮影に AR の対照を足すかを起票のときに決める。

### 5.2 段 B: 判定の撮影（予測を固定してから撮る）

- **最小構成**: SMG 単騎・AUTO・射撃場の遠（V-0118 と同じ。外れが最も多い）。
- **予測の作り方**:
  - 同じ日に撮る対照（▲なし）の録画を道具に通し、表を作る。
  - ▲ありの群の弾丸命中率を、その表から予測する。
  - 撮る前に、道具の版・設定（2 節 6）・K・予測の手順を commit する。対照の表は撮った後に作るので、固定するのは道具と手順と比べる指標。
  - 撮った後に道具や設定を直したら、その撮影は判定に使わず、直した版を固定して撮り直す。
- **比べるもの**（撮る前に 2 つとも指標として固定する）:
  - 絶対値: ▲ありの群の外れの割合の実測と、表から引いた予測。
  - 比 q: ▲ありの群の外れの割合 ÷ 対照の外れの割合（V-0118 の指標）。予測は、表の (1 − h(s × (1 − N))) ÷ (1 − h(s)) で出す。
  - 2 つを分けるのは、マスクに系統的な偏りが残ると▲なしの水準がずれ、▲の効き方が正しくても絶対値で外れと出るため。q が合って絶対値が外れたら、▲の効き方は合い、水準（マスクか、当たり判定）がずれていると読む。
  - 比べのために、H2（C-0192）の予測も並べる。
  - 判定は 5.1 で固定した K（既定は一様）の予測で行う。もう一方の K の予測は、参考として並べるだけにする。
- 群の組み方（例）:
  - 対照（リター）。
  - ミサト・スペック固定 ON（V-0118 の群 2 と同じ）。
  - 可能なら▲がより大きい枠。▲が大きいほど、H2・一様・正規の予測が離れる見込み。
- 判定の目安（σ の幅・何本撮るか）は、5.1 の値を見て、検証記録の起票のときに決める。

### 5.3 当たり判定の探り（5.1 と並行して、5.2 より前に）

- 当たり判定と見た目の輪郭が違えば、マスクから作る表はまるごとずれ、道具の手間が無駄になる。この案でいちばん大きい危険なので、5.1 の結果を待たずに確かめる。
- **主: 既存の AUTO の録画で、発ごとに突き合わせる（撮影なし）**。
  - 5.1 と同じ SMG・AR 単騎・AUTO の録画で、発ごとに、予測の当たる確率 p_t = C_t(s)（2 節 4 で残す 1 発ごとの値）と、当たったか y_t（HUD の増分。`hud.ts`）を並べる。
  - p_t の大きさで発を組（例: 10 組）に分け、組ごとに y_t の平均と p_t の平均を比べる（当てはまりの図）。
  - さらに、照準の中心からマスクの縁までの距離で組に分けて比べる。当たり判定が輪郭より太い（細い）と、照準が縁の近くにある発ほど、実測が予測より多く（少なく）当たる。これで、散らばりの形のずれ（全体に効く）と当たり判定のずれ（縁の近くで効く）を、ある程度分けられる。
  - 発と増分の対応: SMG は約 2.5f に 1 発で、1 フレームに 1 ヒットなら発ごとに分かれる。数ヒットがまとまって読まれた増分（V-0118 の数え方の幅）は、その前後の発をまとめて扱うか、組から落とす。落とした割合を出す。
  - 予測と実測の比べ方（組の数・落とす条件・ずれと見なす幅）は、並べる前に決めて commit する。
  - 弱み: 照準円（SMG で半径約 31px）の中の当たりはランダムなので、1 発ごとの情報は少ない。発の数（1 本で数千発）で補う。
- **従: SR を手で操作した探り（主の結果で、当たり判定のずれが疑われ、場所を絞り込みたいときだけ）**。
  - SR は照準円が約 3px で、ほぼ点として狙える（C-0038 の比から。実際の円は小さくて読めていない）。手足の上・手足の間の隙間・輪郭のすぐ外（数 px）を狙い、当たるかを見る。
  - **近の着地点で、的が止まる・向きを変える瞬間に限って撃つ**。照準の中心の誤差（±2px）と SR の照準円（半径約 3px）を合わせると約 ±5px になり、遠の細い手足や、動いている的では当たりか外れかを照準の位置から言えない。当たり判定の形は距離で縮むだけとみて、近の結果を遠にも使う。
  - 判定のしかた: 撃った瞬間のフレームのマスクに照準の中心が入るか（予測）と、当たったか（ダメージの表示）を、発ごとに並べる。照準の中心がマスクの縁から 5px 以内の発は使わない。マスクの作り方は 2 節の道具の版で固定してから撮る。
  - 撮る前に確かめること:
    - `aim.ts` が見分けるのは、十字（AR など）とリング（MG・SMG）だけ。手で操作する SR の照準を検出できるかは分かっていない。試しの短い録画で確かめ、検出できなければ、SR の照準の検出を道具に足す。
    - 判定に使える発が 1 回の撮影で足りるとは限らない。要る発の数は、起票のときに決める。
- 合わないときは、ずれ方（輪郭より太い・細い、部位ごとに違う）を記録し、マスクを広げる・縮める根拠にする。係数で合わせない。

- 道具の照準と的の検出（`aim.ts`）が既にあるので、いちばん手間のかかる画像の読み取りの大半は書き直さずに使える。
- 当たり判定の確かめ（5.3 の主）は段 2 に入り、撮影は要らない。撮影が要るのは、段 4（要るときだけ）と段 5。
- 段 3 は、段 5 の結果で入れるかが決まる。先に書いておき、表の無いまま（いまの表のまま）で merge できる形にする。
- 別の敵（7 節）は、段 1 の道具が実戦の画面で使えるかに時間が左右される。

## 7. 別の敵への広げ方

- **最初の 1 体は大型のボスにし、「照準円が当たり判定の中に収まるか」だけを先に確かめる**。
  - 大型のボスは、照準円が当たり判定の中に収まり、表がほぼ 1 になる見込み。
  - 手順: 単騎・AUTO の録画から一定の間隔でコマを選び、手で輪郭を付け、照準円が輪郭からはみ出すコマの割合を出す。照準円は、範囲の武器（AR・SMG）でいちばん大きい CDN の値（SMG の 110）で見る。
  - はみ出すコマの割合の線引き（例: 1% 未満）は、輪郭を付ける前に決めて commit する。
  - はみ出すコマが線引きより少なければ:
    - K が一様なら、その敵の表は「どの s でも 1」と置ける（観測値として。外れの割合との再現で確かめる）。手間はコマ数枚の輪郭で済み、道具を実戦の画面に合わせる必要が無い。
    - K を正規に替えていたら（5.1 の 2）、円の外にも裾が出るので 1 にはならない。同じ輪郭のコマで C_t(s) を数えて表にする（コマ数枚で済むのは同じ）。
  - はみ出すなら、下の通常の手順に進む。
- 通常の手順: その敵を単騎・AUTO で撮る（武器は照準円の変わらない AR か SMG）→ 道具に通す → 場面ごとの表を `bulletCoverage` に置く。確かめは、同じ録画の外れの割合との再現と、別の日の 1 本との比べ。
  - 5.1 の 3 で表を武器種ごとに分けることになったら、敵ごとに AR と SMG の両方を撮る（録画の数が倍になる）。
- 背景が動く場面・演出の多い場面（迎撃戦・レイド）:
  - 背景差分が使えない。最初は「一定の間隔で選んだコマに手で輪郭を付け、その間は前後のコマの輪郭を使う」形で補う。
  - 自動の切り出しは、要るようになってから考える。
- 表を作るまでの敵は、手入力の弾丸命中率と未測定の注記のまま（3 節）。
- 部位（破壊できる部位・コア）を分けたいときは、マスクにラベル（胴体・部位・コア）を付け、ラベルごとの割合を出す。弾丸命中率の表とは別の欄にする。最初の範囲ではしない。

## 8. やらないこと（この案の範囲の外）

- コア命中率を被覆率から出し直すこと。コアの検出は信頼できず（0.3）、コア命中率は C-0036 の式で▲まで入っている。被覆率で出すのは弾丸命中率だけにする。
- MG・SG・SR・RL の弾丸命中率（4 節の範囲外）。
- 照準の遅れや向きを、式（モデル）として持つこと。この案では、数える中に入れるだけにする。
- 形の分類（塊型・多肢型など）や、係数を置いた曲線で、未測定の敵の弾丸命中率を推計すること。
  - 被覆率の表 h(L, s) は、敵ごとに測った「照準円の大きさ → 弾丸命中率」の関数にあたる。関数の形を仮定せず、観測値のまま持つ。
  - 曲線の形でまとめるかは、複数の敵で表がそろい、形が共通だと分かってから考える。
- 残差を合わせるための係数。表は観測値で、合わない分は 5.1・5.3 で原因を確かめる。

## 9. 分からないこと・危険

1. **当たり判定 = 見た目の輪郭か**。違えば、マスクから作る表がずれる。いちばん大きい危険なので、5.3 で先に確かめる（主は既存の録画の発ごとの突き合わせ。散らばりの形のずれと完全には分けられない）。
2. **散らばりの形**。
   - 材料が両方に分かれている（0.1）。C-0036 の根拠のうち N の大きい旧の 1 本は一様を支持し、C-0192 の H2 は正規分布で自然に出る形。ただし、H2 は一様でも的の形しだいで近い効き方になりうる。
   - 一様を既定にし、5.1 の 0（コア）と 2（弾丸命中率）の両方で正規がはっきりよいときだけ、正規に替える候補にする。
   - 正規に替えると、確定の結論 C-0036 のモデル側と食い違う（10 節の 5）。
   - どちらでもない形（縁に寄る・偏る）なら、どちらの表も合わない。
3. **照準の追い方は武器種で同じか**。表は武器種で分けない前提（3 節）。AR と SMG の録画で、同じ着地点の表がそろうかを、5.1 の 3 の線引きで決める。近い側の食い違い（0.2）がここに当たる可能性がある。分けることになると、別の敵の手間が倍になる（7 節）。
4. **遠の脚が霧で欠ける**。欠けると h を低く見積もる。判定を行う遠でいちばん弱いので、5.1 の最初の関門にする。補い方は、h と外れの割合を並べる前に、マスクの質だけで決める。
5. **発射の瞬間のフレームの取り方**。残弾の減ったフレームを 1 発とする（2 節 1）。残弾の読み落とし・録画のフレームと発射の瞬間のずれ（±1f）で、h が少し動く。5.1 の 1 で確かめる。
6. ×(1 − N) と ×1/(1 + N) の区別（C-0041）。N が小さいうちは差が小さい。大きな▲の群で h の予測が分かれるかを、5.2 の起票のときに見積もる。
7. **マスクの影と穴**。足元の影がつながるとマスクが下に広がり（h を高く見積もる）、光沢で穴が開くと狭まる（低く見積もる）。2 節 3 の前処理で扱い、量は 5.1 の 1 で、値を並べる前に決める。
8. **持続の▲がゲージに入らない**（4.3）。持続の▲の中は、モデルのゲージが実際より遅く溜まる側にずれる。注記で未実装と出し、入れるのは別の設計にする。

## 10. 決めてほしいこと

1. この方式（フレームごとの被覆率。形と動きをモデル化しない）を、ほかの案と比べる候補に入れてよいか。
2. 最初の範囲を、射撃場の的・AR と SMG の弾丸命中率にしてよいか（コア命中率・MG・SG は範囲の外）。
3. 最初の一歩を、机上のコアの▲の比べ（5.1 の 0）にし、続けて道具（段 1）と、撮影なしの下見（5.1 の 1〜3）・発ごとの突き合わせ（5.3 の主）に進めてよいか。SR を手で操作した探り（5.3 の従）は、要るときだけにする。
4. 未測定の敵は、形からの推計を出さず、いまのとおり手入力と未測定の注記のままにしてよいか（3 節・8 節）。
5. 散らばりの形を「一様が主、正規は対立仮説」にしてよいか（2026-10-03 の版は、2 つを対等に並べて下見で選ぶ形だった。1.1 節・5.1 の 2）。そのうえで、5.1 で正規に替える候補になったとき、確定の結論 C-0036（コア命中率 p ÷ (1 − N)²。モデル側も同じ式）をどう扱うか。次のどれかを、そのときにオーナーが決める。
   - (a) 正規分布を候補から外し、一様だけで進める。
   - (b) C-0036 を見直す検証を、別に起票する。コアの▲を、N の大きい枠で撮る。
   - (c) コア命中率と弾丸命中率で散らばりの形を分けて持つ。物理的に筋が通らないので、推奨しない。
6. 持続の▲で上がる弾丸命中率を、与ダメージ（2 パス目）にだけ入れ、1 パス目のゲージには入れない（未実装と注記する）境目でよいか（4.3）。
