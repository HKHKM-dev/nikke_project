## Context

Stage 11 は、実戦で使う主力キャラを **1 体ずつ**（1 体 1 PR）、そのキャラに要る語彙と専用の撮影で正確にする Stage。順番はユーザー指定のリター → クラウン → アリスで、リターは Stage 10 で完成したので **クラウン（330）から**始める。

クラウンの効果の大半はいまの語彙で書ける（攻撃ダメージ▲・リロード速度▲・発動者基準の攻撃力▲）。書けないのは次の 2 つだけ。

1. **対象「直前にバーストスキルを使用した味方」**（S1）。いまの対象は「自分」「味方全体（武器種で絞れる）」の 2 つで、**どの枠に掛かるかは効果ごとに固定**。クラウンの S1 は発火のたびに対象が変わる（III が 2 体いれば交互に入れ替わる）。
2. **トリガー「回復効果が適用された時」**（S2）。クラウンは通常攻撃 43 回ごとにリラックスを 1 スタック溜め、20 スタックで解除して自分を回復し、その回復をきっかけに味方全体へ攻撃ダメージ▲を配る。「回復」という出来事がいまのモデルに無い。

**設計の芯は「対象を発火のたびに決める」ことと、「回復を出来事として 1 つ足す」こと。** どちらも既存の窓の作り方（Stage 6・8）と 1 パス目のループ（Stage 10）の形はそのままに、入力を 1 つずつ広げるだけにする。

## 0. 設計前に分かったこと（2026-09-23）

### 0.1 クラウンのスキル（Lv 10）

- **S1**: フルバースト発動時、**直前にバーストを使用した味方全体**に 発動者基準で攻撃力 64.51%▲（15 秒）・リロード速度 44.35%▲（15 秒）
- **S1**: 同、**直前にバーストを使用していない味方全体**に 発動者基準で防御力 37.44%▲（15 秒）・リロード速度 44.35%▲（15 秒）
- **S2**: 通常攻撃 43 回ごとに 自分に「リラックス：受ける HP 回復量 4.06%▲」1 スタック（最大 20）
- **S2**: リラックスがフルスタックの時、解除して 自分に 無敵 5 秒・挑発 5 秒・最大 HP の 5.23% 回復
- **S2**: **回復効果が適用された時**、味方全体に 攻撃ダメージ 20.99%▲（7 秒）
- **バースト**: 味方全体に 攻撃ダメージ 36.24%▲（15 秒）・最大 HP 10.45% のバリア（15 秒）

- S1 のリロード速度は「使った味方」「使っていない味方」の両方に同じ 44.35%・15 秒で付くので、結果として**味方全員に付く**。攻撃力だけが使った味方に限られる。

### 0.2 語彙の出現数（202 体の説明文）

- 「直前にバーストスキルを使用した（味方）」: クラウン・アルカナ（フルバースト**終了**時）・レイ（仮称）（MG の味方に絞る）。どれもフルバーストの開始・終了がトリガー
- 「回復効果が適用された時」: クラウン・アスカ・ネロ・シラツル
- 「フルスタックで解除して発動」: 多数。数えるだけで効果の無いスタックなら「N 回 × M スタックごと」と同じ

### 0.3 いまのモデルとの差

- **対象が効果ごとに固定**: `planBuffTimeline` は効果ごとに発火フレームの窓を和集合にしてから、`isEffectTarget` で対象の枠へ同じ窓を配る。`firstPass.ts` の `FiringSource.targets` も効果ごとに 1 つ。クラウンの S1 は発火ごとに対象が違うので、**窓を「効果 × 対象の枠」ごとに作る**形に広げる（3.2 節）。
- **チェーンの記録が無い**: `BurstSchedule` は発動を 1 回ずつ並べているが、「どの発動がどのフルバーストを開いたか」は持っていない。状態機械（`burst/controller.ts`）はチェーンを知っているので、そこで記録する（3.1 節）。
- **回復が無い**: 出来事は射撃・発動・フルバースト開始 / 終了・ゲージ満タンの 5 種類（`FrameEvents`）。ここに「回復を受けた」を足す（3.3 節）。

## 1. Stage 11 の進め方

- **1 体 1 PR**。この設計書にクラウン編（本文）を書き、クラウンの PR がマージされたら、アリス編を同じファイルに章として足して起案 → 承認 → 実装する。
- 各キャラで**足す語彙はそのキャラに要るものだけ**。ただし同じ言い回しの他キャラ（0.2 節）でもそのまま使える形にする（対象に武器種の絞り込みを許す、`fullBurstEnd` でも使える、など）。定義を作るのは撮影で確かめるキャラだけ（Stage 8 以来の方針）。
- 主力キャラは実戦の編成で使うので、完了条件に「そのキャラを含む実戦的な編成で sim と calc が整合する」を入れる。

## 2. DSL の追加（`skills/types.ts`）

### 2.1 対象「直前にバーストスキルを使用した味方」

```ts
export type BuffTarget = 'self' | 'allies' | 'burstUsers';
```

- `burstUsers` = そのフルバーストを開いたチェーンでバーストを撃った枠（3.1 節）。
- 「使用していない味方」（`nonBurstUsers`）は**足さない**。クラウンでそれを対象にする効果は、防御力▲（ダメージに関係しない）と、`allies` にまとめるリロード速度（下）だけで、0.2 節のほかのキャラも使わない。
- **トリガーが `fullBurstStart` か `fullBurstEnd` のときだけ書ける**（「直前」の意味がフルバーストに結び付いているため。アルカナは終了時）。それ以外は検証エラー。
- `targetWeapon` を併用できる（レイ（仮称）の「直前にバーストを使用したマシンガンの味方」）。`parseTargetWeapon` の「`allies` のときだけ」を「`self` 以外」に広げる。
- `passive` には書けない（フルバーストが無いと意味がない）。`timed` と即時効果（`cooldownReduction` / `ammoRefill` / 下の `heal`）に書ける。

**クラウンの S1 のリロード速度は `allies` 1 効果にまとめる**。説明文では「使用した味方」「使用していない味方」に 1 行ずつあるが、どちらも 44.35%・15 秒なので全員に付く。2 効果に分けると、`planBuffTimeline` は効果ごとに和集合を作って区間で加算するため、**同じ枠が 15 秒以内に「使った → 使っていない」と入れ替わると 2 つの窓が重なり、+88.7% になる**。重なるのは、フルバーストの間隔が 15 秒未満（フルバースト 10 秒 + ゲージの溜め直し + チェーン）で、同じ段階の 2 体が交互に撃つ編成に限られる。この場合に実機で 2 つが重なるかどうかは確かめられていないが、1 効果なら上書き延長になり、ふだんの編成では 2 効果のときと数値が変わらない。説明文の 2 行をまとめたことは `notes` に書く。

### 2.2 フルスタックで発火する射撃の回数トリガー

```ts
export type ShotCountTrigger = {
  count: ShotCountKind;
  every?: number;
  everyRef?: number;
  /** フルスタックの数の description_value_NN。every 回ごとに 1 スタック、満ちたら解除して発火（every × スタック数 回ごと） */
  stacksRef?: number;
};
```

- クラウンの S2 は `{ count: 'normalShot', everyRef: 1, stacksRef: 3 }`（43 回 × 20 スタック = 860 回ごと。スキル Lv で 43 が変わるので `ref` で持つ）。
- **スタック自体に効果が無い場合だけ**使う（リラックスの「受ける HP 回復量▲」はダメージに関係しない）。スタックごとに攻撃力が上がるような「効果のあるスタック」はモダニアの Stage で扱う。
- 途中でスタックが消えることはないとみなす（クラウンの説明文にも無い）。
- 解決時に `every = 1 スタックの回数 × スタック数` にし、`stacks` を残す（UI の「通常攻撃 43 回 × 20 スタックごと」）。発火の判定は Stage 8 の `every` のまま。

### 2.3 即時効果「回復」とトリガー「回復効果が適用された時」

```ts
/** 「HP を X% 回復」。数値はダメージに関係しないので、対象に「回復を受けた」出来事を起こすだけ（即時効果） */
export type HealEffect = {
  kind: 'heal';
  trigger: EffectTrigger; // 'healed' は不可（回復の連鎖で無限ループしないように）
  target: BuffTarget;
  targetWeapon?: WeaponType;
  /** 回復量の description_value_NN（UI の表示用） */
  ref: number;
  assumes?: LocalizedText;
};

export type BuffTrigger = /* 既存 7 つ */ 'healed'; // 自分に回復効果が適用された時
```

- `healed` は**その効果を持つ枠自身**が回復を受けたときに発火する（クラウン・アスカ・ネロ・シラツルの説明文はどれも主語が自分）。
- 回復の出どころは、いまは定義にある `heal` 効果だけ。**編成の外（ヒーラーを定義していないキャラ）の回復は扱わない**（10 節 4）。
- HP の値は持たない。**満タンでも回復は「適用された」とみなす**（射撃場で確かめる。7.5 節の 3）。

## 3. 時刻表・トリガー・窓の変更

### 3.1 チェーンの記録（`burst/schedule.ts`・`burst/controller.ts`・`burst/fixedCycle.ts`）

```ts
export type FullBurstWindow = {
  start: number;
  end: number;
  /** このフルバーストを開いたチェーンでバーストを撃った枠（発動順）。「直前にバーストスキルを使用した味方」 */
  burstUsers: number[];
};
```

- **動的サイクル**: 状態機械が `ready`（ゲージ満タン）に入ってから `StepFull` の発動までに撃った枠を集める。リエントリー（段階 I → I）も同じチェーンに含める。**チェーンが途切れた（タイムアウトした）発動は含めない**（フルバーストを開いていないため）。
- **固定サイクル**: そのサイクルで割り当てた I・II・III の 3 枠。
- `FrameEvents` の `fullBurstStart` / `fullBurstEnd` に、その窓の `burstUsers` を添える（`replayEvents` とループの両方で）。

### 3.2 対象を発火のたびに決める

`isEffectTarget(effect, source, target, weapon)` に 5 つ目の引数「発火の文脈」（`FireContext`）を足す。`burstUsers` は文脈の枠だけに掛かり、文脈が無ければ誰にも掛からない。`self` / `allies` は今までどおり文脈を見ない。

- **`planBuffTimeline`**: いまは 効果ごとに発火フレーム → 和集合 → 全対象へ同じ窓。変更後は 効果ごとに発火（フレーム + 文脈）→ **対象の枠ごとに**自分が対象だった発火だけで和集合
- **`firstPass.ts`（射撃系・即時）**: いまは `FiringSource.targets`（固定）・`windows`（効果に 1 列）。変更後は 発火のたびに対象を決め、`windows` を**対象の枠ごとの列**にする。即時効果も発火ごとに対象を決める
- **`triggerFrames` の戻り値**: いまは フレームの列。変更後は `trackTriggerFires`（フレームと文脈の列）を足し、`triggerFrames` はそのフレームだけを返す（互換）

- **退化**: `burstUsers` を使う効果が無ければ、どの枠の窓も今と 1 フレームも変わらない（対象が固定なら「対象ごとの和集合」=「効果ごとの和集合」）。対象が文脈で変わる効果かどうかは `dependsOnContext` で見分け、変わらない効果は今までどおり効果ごとに 1 回だけ和集合を作る。Stage 10 までの全テストが数値を変えずに通ることを退化条件にする。
- 同じ効果が続けて発火し、1 回目は対象・2 回目は対象外という枠は、1 回目の窓だけを受ける（上書き延長は「その枠が受けた発火どうし」でだけ起きる）。

### 3.3 回復の出来事

- `FrameEvents` に `healed: readonly boolean[]`（枠ごと）を足す。
- **回復のフレーム** = `heal` 効果の窓が始まるはずのフレーム。つまり射撃の回数トリガー（クラウン）なら**トリガーになった射撃の次のフレーム**、バースト系なら発火と同じフレーム（Stage 6・8 の窓の規則をそのまま使う）。
- `healed` で付く窓は**回復のフレームから**始める（回復は 1 フレームの中で「回復 → バフ」と続けて起きるとみなす）。クラウンなら 860 発目の射撃の次のフレームから 7 秒。
- **2 段で解く（バッチ側）**: いまの `replayEvents(schedule, shots, frames)` は定義（`slots`）を受け取らないので、`heal` の発火は判定できない。そこで `replayEvents` は定義を知らないまま据え置き、段を分ける。
  1. `planHeals`（`skills/heals.ts`）が、`healed` の無い出来事の列に各枠の `heal` 効果を `TriggerTracker` で流し、回復の記録 `{ frame, sourceSlotIndex, slotIndex }` を返す（`frame` は上の規則。戦闘時間の外は捨てる）。
  2. `replayEvents` に 4 つ目の引数 `heals` を足し、その `frame` に `healed[slotIndex]` を立てる。
  3. `planBuffTimeline` は冒頭で 1 回だけ `planHeals` を呼び、以降の `triggerFrames` / `buffStartFrames` に `heals` を渡す（省略時は回復なし = 今と同じ）。
  - `heal` のトリガーに `healed` を許さないので 2 段で閉じる。`eventsOf` のキャッシュの鍵に `heals` の参照を足す。
- **ループ側（1 パス目）**: いまの即時効果（`cooldownReduction` / `ammoRefill`）は発火したフレーム `f` でその場で当てている。`heal` だけは回復のフレームの規則に合わせ、**射撃の回数起点なら `f + 1` に保留**し、`f + 1` の手順 3 で出来事を組むときに `healed` を立てる（`pendingHeals`）。バースト系の起点なら `f` のうちに立て、同じ `f` の手順 3 の残りの効果（`healed` を条件にするもの）より先に処理する。`f + 1 ≥ frames` なら捨てる。回復の記録（`instants`）は立てたフレームで残す。
  - 既存の `cooldownReduction` / `ammoRefill` の当てるフレームは変えない（射撃の回数起点のものは定義に無く、変えると Stage 10 の退化が崩れる）。
  - ループと `planBuffTimeline` が同じ意味になるよう `TriggerTracker` を通し、**ループが記録した回復と `planHeals` の結果が一致する**ことをテストで固定する（Stage 10 の 1.2 節と同じ考え方）。

- 固定サイクルは割り当ての 3 枠。

### 7.3 トリガー・窓（`timeline.test.ts`・`triggers.test.ts`・`firstPass.test.ts`）

- **退化**: 新しい対象・`heal`・`healed` を使わない編成で、窓・区間・射撃の列・時刻表が Stage 10 と厳密一致（既存の全テストが数値を変えずに通る）。
- **対象が入れ替わる**: III が交互の編成で、S1 の攻撃力の窓が各フルバーストでその回の III にだけ付く。前の回に付いた窓は、次の回で対象外になっても延長されない（3.2 節）。
- **回復（バッチ側）**: `planHeals` を通さない呼び出し（`heals` 省略）は今と同じ出来事の列になる。`eventsOf` のキャッシュが `heals` の違う呼び出しで古い列を返さない。

- **回復**: 860 発目の次のフレームに `healed`、そこから 7 秒の窓。ループ（1 パス目）と `planBuffTimeline` で回復のフレームが一致する。

### 7.4 sim と calc の整合（`simCalc.test.ts`）

クラウンを含む編成を 2 つ足す（録画 0041 の編成と、実戦寄りの リター + クラウン + ドレイク宝物 3 + ラピ）。厳密一致（射撃の列・時刻表・区間・バフ・倍率ダメージ・`'shots'` のグループのトリガー数）と離散化誤差（枠 5%・編成 3%）は既存の基準のまま。

### 7.5 射撃場の実測（新規撮影 1 本 = 録画 0041）

**編成**: **I-DOLL・フラワー（I）+ クラウン（II）+ デルタ（II・操作）+ ラピ（III）**、スペック固定・3 分モード・自動バースト ON。バーストを使う味方の見本にフラワー（毎回のチェーンで I を撃ち、味方のバフを出さない）、使わない味方の見本にデルタ（クラウンの後ろの II の枠で一度もバーストしない）を置く。I・II は 20 秒ごとに撃つが III が 40 秒に 1 回なので、チェーン切れの回もできる。

1. S1 の攻撃力が「使った味方」だけに付くか（フラワーとデルタのダメージ。チェーンが途切れた回はフラワーにも付かない）
2. S1 のリロード速度が「使っていない味方」にも付くか（操作中のデルタのリロード）
3. S2 の回復が 860 発ごとに起き、満タンでも攻撃ダメージ▲を配るか（クラウンの頭上の回復の数値と、そこから 7 秒のデルタのダメージ）
4. 攻撃ダメージ▲どうしは加算か（クラウンのバーストと S2 が重なった区間のデルタのダメージ）
5. バーストの攻撃ダメージ▲はチェーンが途切れた回にも付くか

## 15. Context

1. **対象「最終攻撃力が最も高い味方 N 機」**（S1）。対象が**その瞬間の全員の攻撃力**で決まる。クラウンの `burstUsers` は時刻表（チェーン）だけで決まったが、こちらは**攻撃力のバフの窓**に依存する。しかも S1 のチャージ速度は射撃に効く stat なので、1 パス目のループ（射撃の列を作る前）で対象を決めなければならない。

**設計の芯は「発火のたびに、そのフレームの最終攻撃力で順位を付ける」こと。** クラウン編で作った「発火の文脈で対象を決める」仕組み（`FireContext`・対象の枠ごとの窓）に、文脈として「攻撃力の順位」を 1 つ足すだけにする。攻撃力の窓は `planBuffTimeline` が作れているので、1 パス目のループでも同じ窓を（順位のためだけに）作る。

## 18. 順位の決め方（`skills/ranking.ts` 新設）

```ts
/** 枠ごとの最終攻撃力（空枠は null）。base × (1 + Σ攻撃力%) + Σ発動者基準の固定加算。ダメージの式の攻撃力と同じ */
export function finalAttacksAt(slots, passive, attackWindows, frame): (number | null)[];
/** 最終攻撃力の高い順の枠。同値は枠の若い順。空枠は含めない */
export function rankByFinalAttack(finalAttacks: readonly (number | null)[]): number[];
```

- **最終攻撃力**: その枠のバフ前攻撃力（`casterBaseAttack` と同じ値）に、常時パッシブと、発火のフレーム `f` で効いている攻撃力の窓（`start ≤ f < end`）を足した値。整数に丸めない（順位は丸めで変わらない。同値のときだけ差が出うる）
- **同じフレームに付いた窓**: **入れる**（`start = f` の窓も数える。定数 `RANK_INCLUDES_SAME_FRAME`）。III の `burstUse` と `fullBurstStart` がモデルでは同じフレームなので、入れないとアリス自身のバーストが順位に入らない（16.3 節）。クラウンの S1（同じ `fullBurstStart`）の固定加算も入る。これが実機と合うかは録画 0043 で確かめる（22.6 節）
- **順位で対象が決まる効果**: **順位の材料に入れない**。`topAttack` の効果が出す攻撃力の窓（マクスウェル型）は、他の `topAttack` の順位にも数えない（循環を断つ）。アリスは攻撃力を配らないので影響しない
- **同値**: **枠の若い順**（仮定。未検証）。スペック固定では攻撃力が 12 通りしかないので同値が起きやすい。撮影の編成は同値にならないように組む
- **候補が N 未満**: 候補（`targetWeapon` の条件に合う枠）が N 未満なら全員

- 攻撃力の窓は、`burstUsers` の窓（クラウンの S1）も含めて**対象の枠ごと**に見る（クラウン編で窓を枠ごとにしたので、そのまま使える）。
- 順位を出すフレームは**トリガーが起きたフレーム**（1 パス目と同じ）。射撃の回数トリガーの窓は `f + 1` から始まる（Stage 8 の規則）ので、同じフレームの射撃で付く攻撃力▲は入らない。

### 22.6 射撃場の実測（録画 0043。推奨・クラウンとの同じフレーム）

クラウンの S1（フルバースト開始時、直前にバーストを使った味方に発動者基準の攻撃力の固定加算）とアリスの S1 は同じフレームに発火する。クラウンの固定加算が順位に入るかで、実戦の「クラウン + アリス」編成の 2 枠目が変わる（入るならクラウンの MG に行って無駄になりやすい）。

**編成**: 録画 0042 にクラウン（II）を足した形。クラウンが毎回 II を撃つ（アドミは撃たない）ので、同じフレームの固定加算を**入れる**規則ならクラウンが上位 2 機に入ってアドミは対象外、**入れない**規則ならアドミに付く。**アドミの間隔と 1 発（× 1.028 の有無）だけで決まる**。アリスはどちらの規則でも毎回対象。

- 実機の処理順が枠の順に依存する可能性がある（クラウンが前の枠）。この編成は実戦と同じくクラウンを前の枠に置く。

## 24. リスク・留意点

- **同値**: スペック固定では SSR Attacker（ピルグリム以外）が全員同じ攻撃力で並ぶ。実戦の育成では同値はまれだが、射撃場で SSR Attacker を 2 体以上入れた編成は枠の順の仮定に依存する。UI で「同値を枠の順で決めた」ことを出す。
- **順位は発火の瞬間だけ**: 10 秒の途中で順位が入れ替わっても対象は変えない（説明文どおり「発動した時」に配る）。
- **攻撃力を配る `topAttack`（マクスウェル型）**: 順位に数えない規則は仮。定義するときに実機で確かめる。
- **チャージ速度の上限**: 「発動者のバフ込み」の読みならアリスの回に 100% を超え、チャージが 0 になる（`max(0, 1 − 速度)`）。実機に下限があるかは、その読みになったときに確かめる。

## 26. 決めてほしいこと（推奨付き）

1. **対象の書き方** — 推奨: **`BuffTarget` に `topAttack` を足し、N は `targetCountRef` / `targetCount` で持つ。トリガーは限らず、`passive` は不可、`targetWeapon` 可**（17 節）。「自分を除く」系は今回は足さない。

2. **自分を候補に入れるか** — 推奨: **入れる**。説明文に「自分を除く」「自分と自分を除く」が別にあるので、無印は自分を含む読みが自然。録画 0042 の 1（アリスの × 1.02 と間隔）で確かめる。

3. **同じフレームに付いた攻撃力の窓** — 推奨: **順位に入れる**（18 節）。モデルでは III の発動とフルバースト開始が同じフレームなので、入れないとアリス自身のバーストが順位から落ちる。クラウンの S1 の固定加算も入ることになり、実機と合うかは録画 0043 で確かめる。代替: `burstUse` だけ入れて、同じ `fullBurstStart` の効果は入れない（クラウンの固定加算が入らない。実戦ではアリスの 2 枠目が DPS に行く）。

4. **同値の決め方** — 推奨: **枠の若い順（仮定・未検証）**。撮影の編成は同値を避ける。

5. **「スキル発動者基準でチャージ速度」** — 推奨: **X% をそのまま足す（`scaling: 'ratio'` + `assumes`）**（17 節）。攻撃力の「発動者基準」がバフ前の値だった（Stage 4）ことと同じ読み。録画 0042 の 3 で確かめ、違えば `casterChargeSpeed` を足す。

6. **S2** — 推奨: **定義しない（unsupported + notes）**。貫通は単体の的では関係せず、回復の条件（HP 80% 未満）は HP を持たないので判定できない。

7. **撮影** — 推奨: **録画 0042（必須）と録画 0043（推奨）を同じ日に撮る**（22.5・22.6 節）。録画 0043 を撮らない場合は 3 の規則を仮定のまま残し、UI に出す。

## 27. 射撃場の実測の結果（録画 0042・0043、2026-09-24）

詳細は [verification.md](verification.md) Stage 11 アリス節。録画 0043 は、起案時のマナを III に入れた編成（I-DOLL・フラワー / クラウン / アリス（操作）/ マナ / アドミ）で撮られていたので、その編成で予測を出し直して読んだ。

- **26 節 2（自分を候補に入れる）**: 録画 0042 のアリスの回・サンの回とも、アリスの 1 発が S1 のチャージ倍率 3.57 の予測と一致 → そのまま（確定）
- **26 節 3（同じフレームに付いた攻撃力の窓を順位に入れる）**: 録画 0043 のマナの回のアリスの 1 発がチャージ 3.5（S1 なし）。マナ（FB 開始時の自己バフ）とクラウン（S1 の固定加算）が同じフレームのバフで上位 2 機になった → そのまま（確定）
- **26 節 5（発動者基準のチャージ速度 = X% をそのまま）**: 録画 0042 のアドミ（チャージ 1 秒）がフルバースト中 72f。X% をそのままなら 75f。アリスの基礎チャージ時間 1.5 秒 × 11.67% = **0.175 秒を引く**と 72f → **訂正**: `casterChargeTime`
- **2 位（アドミ）が対象、4 位（フラワー）は対象外**: 録画 0042 のフラワーはフルバースト中も間隔が変わらない。録画 0043 ではアドミは対象外 → そのまま（確定）

- **`scaling: 'casterChargeTime'`**（stat が `chargeSpeed` のときだけ）: 解決時に 発動者の基礎チャージ時間 × X% の秒数にし、`BuffTotals.chargeTimeFlat` に足す。射手はチャージ時間を `時間 × (1 − 速度) − chargeTimeFlat`（0 未満は 0）にする。アリス自身ではこれまでの読み（X% をそのまま）と同じ値になり、チャージ時間の違う味方でだけ差が出る。攻撃力の「発動者基準」（発動者のバフ前攻撃力 × X% を固定で足す）と同じ形。
- 録画 0043 のアリスの間隔は、マナの S2「フルバースト発動時、基本チャージ時間が一番長い味方 1 機にチャージ時間 0.18 秒▼（10 秒）」（定義では未対応。対象が語彙外）を含み、S1 が付いていないことと矛盾しない。
- **残すこと**: 同値の決め方（枠の若い順、未検証）、チャージ速度の上限の有無、マナの S2 のチャージ時間▼（「基本チャージ時間が一番長い味方」の対象を足すとき）。
