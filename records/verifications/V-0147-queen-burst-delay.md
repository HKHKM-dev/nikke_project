# V-0147: クイーン（真）のバーストのヒットは、III の発動から何フレーム遅れるか

- 問い: クイーン（真）（III）のバーストの倍率ダメージのヒットは、III の発動（III のタイマーが 00.00 になるフレーム。フルバーストの始まり）から何フレーム遅れるか。回ごと・録画ごとに揃うか
- 話題: スキル・キャラ固有
- 日付: 2026-10-04
- Stage: plan/design-burst-landing.md 5 節の 2（ほかのキャラの遅れ）。backlog 2-4
- 録画: `021`、`040`
- 状態: 調査中

## 条件

- 撮影なし。既存の録画の読み直し。どちらも射撃場・灼熱の BigArms・3 分モード・スペック固定。
  - `021`: エーテル（I）+ デルタ（II）+ クイーン（真）（III・操作）。ノワールの `019` と同じ形の編成（I・II が別のキャラ）。
  - `040`: アドミ + ユニ + ラム（I・操作）+ クイーン（真）（III）。II はアドミかユニ。
- クイーン（真）の単騎の録画（`012`・`014`・`103`・`104`）は、III だけではバーストを使えないので使えない。
- どちらの録画も最小構成でない（`021` はエーテル、`040` はアドミ・ユニ・ラムの機構が確定していない）。クイーン（真）自身の定義の効果も結論に結び付いていない。結論は仮説までになる。
- III の発動は、イサベル・ヘルム・ノワールと同じく、III のタイマーが 00.00 になったフレーム（V-0078・V-0082・V-0137）。遅れ（モデル）= 動画のフレームでの「III の発動 → ヒット」− 22（フルバーストの入りの止まり。C-0069）。照合の `burstHitDelays` は止まりを含めた動画のフレームで比べる。
- バーストの倍率ダメージは分配ダメージで、単体の的には全額が 1 ヒットで出る（定義の assumes）。値は、バースト 3 段階突入時の分配ダメージ▲が乗った値（定義の notes にある録画 021 の値）。HUD の増分で、ほかの枠の 1 発より桁が大きい。
- クイーン（真）のバーストの効果（自分の攻撃力▲）の遅れは、SG の 1 トリガーの間隔より細かくは読めないので、今回は読まない。表に入れるなら効果の遅れは 0（未測定）。

## 予測（撮る前に書く）

読む前に書いた（2026-10-04）。予測ファイル（records/predictions/V-0147.json）は、いまのモデル（遅れ 0）の値だけを持つ。遅れの値の仮説はここに手で書く。

| 仮説                               | 各回の「III の発動 → ヒット」（動画のフレーム） |
| ---------------------------------- | ----------------------------------------------- |
| D1: 毎回同じ（演出の長さで決まる） | `021`・`040` のどの回も同じ値 ± 1f              |
| D0: 毎回違う                       | 2f 以上ずれる回がある                           |
| H0: いまのモデル                   | 0f（止まりの 22f より短い）                     |

- **D1 を予想する**。ほかの 7 体がどれも回ごとに揃い、I・II のキャラによらなかったため。値は読む前には決められない（III のキャラでは、動画のフレームでドレイク 26〜27f・ヘルム 80〜81f・ノワール 93〜94f・ラピ 111〜112f・イサベル 156f とキャラで違う）。
- `040` はクイーン（真）が枠 4 で、予測ファイルの編成（`021`）と枠が違うので、予測ファイルには入れない。`040` の値は `021` と同じ（± 1f）と予想する。
- 外れたときの影響: D1 なら遅れの表にクイーン（真）の行（ヒット d・効果 0（未測定））を入れる（録画が最小構成でないので、ノワール（C-0226）と同じく、入れるかはオーナーの判断）。ヒットはフルバーストの中に出るので、倍率ダメージの値は撃つ側のバフを発動の直前で固定する規則（plan/design-burst-landing.md 9 節）のまま変わらない見込み。ただし、バースト 3 段階突入時の分配ダメージ▲（撃つ側のバフ）が発動の直前の値に入っているかは、いまのモデルと同じ（突入と発動が同じフレーム）。D0 なら表に入れず、何で決まるかを調べる。

## 読み方

1. 右のバースト欄を 1 フレームずつ並べて（`still.ts` と同じ select）、各回の III のタイマーが 00.00 になるフレームを読む。
2. HUD の増分（`hud.ts --mode jumps`。レシピ `hud-jumps`）から、各回のクイーン（真）のバーストの倍率ダメージのヒットのフレームを取る。
3. `021` の III の発動 → ヒットを観測値（`burstHitDelays`。`compare`）にする。`040` も同じ指標（枠 4）で観測値にする（予測ファイルとは結び付かない）。
