## フレーム番号の約束

**フレーム番号は「デコードされたフレームの通し番号（0 始まり）」とする。** ffmpeg では `-fps_mode vfr` が相当する。`tools/captures/` のツールはすべてこの番号で統一している。

`-fps_mode cfr` で 60fps に引き伸ばすと重複フレームが挿入され、フレーム落ちのある録画（01・07）では番号がずれる。2026-09-22 の較正メモの番号（SR の 551→633→715 など）は別の数え方で、今のツールの出力とは直接比べられない（間隔は一致する）。

## 解析ツール

どれも `node tools/captures/<名前>.ts`。

| ツール            | 何をするか                                                                                                                 |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `intake.ts`       | 録画の取り込み（リネーム・移動・素性・`records/recordings/NNN.json`・Drive への同期）。クラウドは `drive:<パス>`           |
| `read.ts`         | レシピ（`recipes/`）で読んで観測値にする（`npm run records:read`）。中間出力は `derived/<録画 id>/` にキャッシュする       |
| `fb-window-k.ts`  | レシピ `fb-window-cores` の観測値から、フルバーストの窓の中の率の比 K・K_out と σ（jackknife と 2 項分布）を出す（V-0492） |
| `fetch.ts`        | Drive から録画などを取り寄せる（[storage.md](storage.md)「クラウド環境での取り寄せ」）                                     |
| `probe.ts`        | ディレクトリの中の `.mp4` の素性と sha256 を表で出す（写しの突き合わせ）                                                   |
| `probe-result.ts` | 一時停止・戦闘履歴のパネルを探して切り出す（キャラ同定。[index.md](index.md)「誰が写っているかの確かめ方」）               |
| `still.ts`        | フレーム番号で静止画を切り出す（`frames/` に切り出したら Drive にも上げる）                                                |
| `hud.ts`          | HUD の総ダメージ（最後の値・増分）。`--screen interception` で迎撃戦の段階の数値（V-0462）                                 |
| `gauge.ts`        | 右の BURST バーの充填率（V-0483 の `--subpixel` も）                                                                       |
| `ammo.ts`         | 枠アイコンの上の「残弾/最大」（AI の味方の射撃フレームはこれでしか読めない）                                               |
| `reticle-ammo.ts` | 照準の左の残弾（操作キャラ。V-0163）                                                                                       |
| `reload.ts`       | RELOADING のバーから、リロードごとの完了・伸び・最終弾 → 完了（V-0057）                                                    |
| `timer.ts`        | 残り時間の秒の変わり目・止まり・ゲーム内のティック（V-0003・V-0302・V-0379）                                               |
| `banner.ts`       | 左のスキルの帯の立ち上がりと、ヒットまでの差（V-0313・V-0325）                                                             |
| `dups.ts`         | 重複フレーム（V-0004）                                                                                                     |
| `aim.ts`          | 照準・的・コアの位置と大きさ（コアの検出は試作で、まだ信頼できない）                                                       |
| `diff.ts`         | 指定領域のフレーム間差分のピーク（下の表）                                                                                 |

Drive との同期は `npm run drive:sync`（[storage.md](storage.md)「バックアップ」）。

`diff.ts` の領域と閾値は録画ごとに調整が要る。2026-09-22 の較正で有効だった領域（1920×1080 での `x,y,w,h`）:

| 狙うもの               | 領域の目安        | 備考                                             |
| ---------------------- | ----------------- | ------------------------------------------------ |
| SR/RL の発射（反動）   | `300,780,700,280` | 手元。`--sigma 2 --min-gap 20`                   |
| AR の発射（反動）      | `760,620,360,300` | 同じ手元のパルス列。`--sigma 0.2 --min-gap 4`    |
| MG/SMG の命中          | `820,10,280,50`   | HUD 総ダメージカウンター。1 ヒットごとに更新     |
| ダメージ数値の読み取り | `940,220,400,180` | 的の周りに出る数値。`still.ts --crop` で切り出す |

1 ヒットの値を手で読むときは、HUD 総ダメージカウンターを 1 フレームごとに並べて（`select='between(n,A,B)',crop=280:50:820:10,tile=6x30`）差分を取るのが速い。2 体編成では同じフレームに 2 人分が乗ることがある（録画 13 の 930,273 = 686,756 + 243,517）ので、単独で増えたフレームを探す。

## 証拠フレームの切り出し

証拠フレームは `E:/nikke_project_captures/frames/` に置き、公開しない。台帳などの `frames/…` はこのフォルダを指す。録画と一緒に Google Drive へ同期する。

各録画から 2 枚（全体像の 70% / 85% 地点）＋数値の拡大を置いてある。全体像は次のコマンドで作った。

```bash
ffmpeg -v error -i <動画> -vf "select='eq(n,<フレーム>)',crop=1260:420:340:0,scale=900:-1" \
  -fps_mode vfr -frames:v 1 -q:v 3 -y frames/<名前>_f<フレーム>.jpg
```

**証拠フレームには検証に使う部分だけを入れる。**
