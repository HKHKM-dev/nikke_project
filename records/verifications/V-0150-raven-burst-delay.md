# V-0150: レイヴンのバーストのヒットは、III の発動から何フレーム遅れるか（ラム + デルタ + レイヴンの撮影）

- 問い: レイヴン（III）のバーストの倍率ダメージのヒットは、III の発動（III のタイマーが 00.00 になるフレーム。フルバーストの始まり）から何フレーム遅れるか。回ごとに揃うか。ヒットの値は説明文どおり（C-0185）で、同じ発動の S1 の攻撃力▲は乗らないか

## 条件

**何を確かめるか**（定義は `data/skills/851.json` の skill1・burst）

- バーストのヒットの遅れ（遅れの表に無い。backlog 2-4）。レイヴンの録画（`122`・`141`）は単騎で、III だけではバーストを使えないので、新しく撮る。
- C-0185（仮説・推論）のうち、バーストの倍率ダメージ（最終攻撃力の 492.3%）。ヒットの値は、撃つ側のバフを発動の直前で固定する規則（plan/design-burst-landing.md 9 節）で、同じ発動の S1 のフルバースト時の攻撃力▲は乗らない見込み。ヘルムの S2（C-0167）と同じ形の確かめ。
- バースト使用時の効果（A.N.モード）は持続ダメージ▲で、モデルに語彙が無い（定義の notes）。今回は読まない。

**編成**（オーナーの指定。2026-10-04）

- ラム（822。I）+ デルタ（20。II）+ レイヴン（851。III・操作・AUTO 射撃 ON）、オートバースト ON。ヘルムの `079`・ドレイクの `037` と同じ形。
- **最小構成でない**。ラムはスキル定義の notes が結論に結び付いていないので、検査（`records/minimal.ts`）では機構が確定していない扱いになり、「ラム・レイヴンが未確定」の警告が出る。結論は仮説までになる（2026-10-04 にオーナーに伝え、ラムのままと決めた）。ラムのスキル（敵の攻撃力▼・HP・防御力▲・バリア）は与ダメージに効かない見込みで、ヒットの時刻には効かない。
- デルタのスキルは与ダメージに効かない（C-0081）。

**読み方の前提**

- III の発動は、イサベル・ヘルム・ノワール・クイーン（真）と同じく III のタイマーが 00.00 になったフレーム（V-0078・V-0082・V-0137・V-0147）。遅れ（モデル）= 動画のフレームでの「III の発動 → ヒット」− 22（フルバーストの入りの止まり。C-0069）。
- ヒットが止まりの中（FULL BURST の表示が HUD に重なる間）に出ると、`hud.ts` は拾えない。そのときは HUD の数字を 1 フレームずつ拡大して目で読む（V-0147）。
- S1 の持続ダメージの tick（1 秒ごと。全スタックの和）が HUD の増分に混ざる。tick の値はスタックの数の倍数（`122-08` と同じ 1 スタックの値）なので、バーストのヒットと分けられる。

## 予測（撮る前に書く）

撮る前に書いた（2026-10-04）。H0 はいまのモデルで、値は予測ファイル（records/predictions/V-0150.json）。遅れの値の仮説と、S1 の▲が乗る仮説はここに手で書く。

| 仮説                                        | 「III の発動 → ヒット」（動画のフレーム、5 回） | 1 回目のヒットの値（会心なし / 会心）                    |
| ------------------------------------------- | ----------------------------------------------- | -------------------------------------------------------- |
| H0: いまのモデル                            | 0f                                              | 予測ファイルの `raven-burst-hit`・`raven-burst-hit-crit` |
| D1: 毎回同じ遅れ（演出の長さで決まる）      | どの回も同じ値 ± 1f                             | （H0 と同じ）                                            |
| D0: 毎回違う                                | 2f 以上ずれる回がある                           | （H0 と同じ）                                            |
| S1: 同じ発動の S1 の攻撃力▲（47.52%）が乗る | （D1・D0 と組み合わせる）                       | H0 の約 1.475 倍                                         |

- **D1 を予想する**。これまでの 9 体（イサベル・ヘルム・フラワー・ニヒリスター・ノワール・ラピ・ドレイク・ユニ・クイーン（真））がどれも回ごとに揃ったため。値は撮る前には決められない（III のキャラで、動画のフレームでクイーン（真）22〜23f・ドレイク 26〜27f・ヘルム 80〜81f・ノワール 93〜94f・ラピ 111〜112f・イサベル 156f）。
- **ヒットの値は H0（S1 の▲は乗らない）を予想する**。ヘルムの S2（フルバーストの始まりで付く▲）が、フルバーストの中に出たヒットに乗らなかった（C-0167）のと同じ形のため。
- 見分け方: S1 が乗ったときの会心なしの値（H0 の約 1.475 倍）は、H0 の会心の値（1.5 倍）と近い（差は 2% ほど）。HUD の増分の値は端数まで出るので見分けられるが、会心かどうかは的の上の数値の色（会心は橙）でも確かめる。2〜5 回目のヒットも同じ値（会心なしか会心）になる見込み（S1 の▲は 10 秒で、前の回の▲は切れている）。
- 外れたときの影響: D1 なら遅れの表にレイヴンの行（ヒット d・効果 0（未測定））を入れる。最小構成でないので結論は仮説で、表に入れるかはオーナーの判断（ノワール・ユニ・クイーン（真）と同じ）。S1 が当たったら、撃つ側のバフを発動の直前で固定する規則（9 節）がレイヴンでは合わないことになり、規則を見直す（ヘルムとの違いを調べる）。

## 読み方

1. 取り込む: `node tools/captures/intake.ts <元ファイル> --id NNN --name <識別子> --rid 822,20,851 --controlled 3 --target BigArms --element Fire --mode range-3min --fixed-spec on --auto-fire on --auto-burst on`。台帳を埋めて `npm run records:table`。この検証記録の冒頭に「録画」を足す。
2. 右のバースト欄を 1 フレームずつ並べて、各回の III のタイマーが 00.00 になるフレームを読む。
3. HUD の増分（`hud.ts --mode jumps`。止まりの中なら目で読む）から、各回のレイヴンのバーストの倍率ダメージのヒットのフレームと値を取る。
4. III の発動 → ヒットを観測値（`burstHitDelays`。`compare`）、1 回目のヒットの値を観測値（`burstHitDamage`。会心かどうかで `crit` を選ぶ）にする。
