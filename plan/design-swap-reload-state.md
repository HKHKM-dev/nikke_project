# 設計書: 持ち替えの時の「リロード中」と「マガジンの最後の発の後の構え解除」を、ゲームの表示に合わせて判定する

- 関連: 持ち替えの時の状態で最初の発を決める規則 `firstShotAfterSwapFrames`（[design-red-hood.md](design-red-hood.md) 7.1 節の論点 13。C-0897・C-1566・C-1598）、全弾リロードの丸め（[design-reload-rounding.md](design-reload-rounding.md) 案 E）
- 作成日: 2026-11-28
- 状態: 承認待ち

## 1. 目的

`frame/shooter.ts` の `weaponFreeFrameAtSwap` は、使用武器を変えた後の最初の発を、持ち替えの時の基礎の武器の状態で決める（C-0897・C-1566）。規則は次のとおり。

- 構え解除（最後の発から 13f）の途中なら、構え解除の終わり。構え解除は、チャージ武器では毎発の後、チャージの無い武器ではマガジンの最後の発の後にだけある。
- そうでなくリロード中なら、持ち替えのフレーム。
- 構えたままなら、構え解除 1 回分の後。

いまのコードは、「リロード中」と「マガジンの最後の発の後か」を、どちらも射手の状態 `state.phase === 'reloading'` で代わりに見ている。ところが射手の `phase` は、次の 2 つの場合に、結論の「リロード中」（ゲームの RELOADING のバーで読んだもの）とずれる。

1. **全弾リロードの終わりの k フレーム**: 射手は、ゲームの込め終わり（バーが消える）の k 前に残弾を満たし、`phase` を `'priming'` にする（`cadence.ts` の `fullReloadFrames`）。k はチャージの無い武器で 12f、チャージ武器で 11f。この間はゲームではまだリロード中なのに、いまのコードは構えたままと見て `swap + 13` を返す（規則どおりなら `swap`。13f 遅い）。ふつうのリロード速度でも起きる。
2. **1 回分のリロードが 13f より短いとき**: リロード速度は減算の式（`秒 × (1 − 速度)`）で効く。基礎のリロードの短いキャラ（0.23 秒の 271、0.5〜0.67 秒の 7 人）は、リロード速度で 1 回分が 13f を切る。そうなると、最後の発から 13f 以内に `priming`・`ready` へ移る。ここで持ち替えると、いまのコードはマガジンの最後の発の後の構え解除を見落とし、`lastShot + 13` ではなく `swap + 13` を返す（最大 12f 遅い）。

この設計書は、この 2 つを結論（C-1566）の定義に合わせる。

## 2. 案

- 案 A（推奨）: 射手の状態に、ゲームの込め終わりの時の `wait`（`reloadEndWait`）を持つ。
  - 最終弾から始めた全弾リロード（`lastShotReload`。分割でない・ハイド中でない・押下チャージ型でない）で `priming` に入る時に、`wait − k` を書く（k は `cadence.ts` の `fullReloadLeadFrames`）。マガジンを戻す時（`startMagazine`）に消す。
  - `weaponFreeFrameAtSwap` は、`phase === 'reloading'` に加え、`lastShotReload` があって `priming` で `wait > reloadEndWait` の間もリロード中にする（1 の直し）。
  - 構え解除の有無は、`chargeWeapon || reloading` に `lastShotReload` を足す（2 の直し）。`lastShotReload` は最終弾で付き、そのマガジンの 1 発目まで残る（弾丸チャージで満タンにしたとき・構え直しでは消える）。
  - 毎フレームの処理は増えない（`priming` に入る時に 1 回書くだけ）。
- 案 B（採らない）: 射手の状態に、ゲームの込め終わりまでの残りフレームを持ち、毎フレーム減らす。案 A と同じ結果だが、射手の毎フレームの処理（`stepShooter`）に減算が増える。
- 案 C（採らない）: `weaponFreeFrameAtSwap` に射手の `FiringParams` と武器を渡し、`priming` の `wait` とリロード明けの待ちから、その場でゲームの込め終わりを計算する。呼び手（`frame/firstPass/shooters.ts`）に引数が増え、`cadence.ts` の全弾リロードの計算（k・ハイド中・分割）を写すことになる。
- 案 D（採らない）: 直さずに notes にずれを書く。規則は結論で確かめてあり、ずれの原因もコードで特定できているので、モデルに入れられる（AGENTS.md「事実と記録」）。

## 3. 論点

1. **リロードが構え解除より先に終わる場合（1 の 2 番目）**: C-1566 は「リロードに入って構え解除の途中の持ち替えは、構え解除の終わりから数える」とする。録画は、リロードが構え解除より長い場合だけ。推奨: 案 A のとおり、リロードが先に終わっても構え解除は最後の発から 13f 続くと読む（構え解除はマガジンの最後の発に結び付き、リロードの長さに結び付かないという結論の書き方に合わせる）。確かめる録画は、リロード速度の高い編成での持ち替え（撮影の候補）。
2. **変えないもの**: 次の場合は、根拠が無いので今のまま（`swap + 13` か、`phase` による判定）にする。
   - ゲームの込め終わりから 1 発目までの `priming`（構えたままとみなす。今のまま）。
   - 残弾数減少・ハイド中に始めたリロードの途中の持ち替え（今のまま、構え解除の途中なら構え解除の終わり、明けていれば持ち替えのフレーム）。結論の「マガジンの最後の発の後にだけある」に厳しく従うと構え解除は無いが、これらのリロードでの持ち替えの録画が無い。
   - 弾丸チャージで満タンにした・構え直しで `lastShotReload` が消えた後の持ち替え。
3. **影響**: 観測値 5167 件のうち、予測が変わるものは 0 件（`npm run records:residual -- --all --base origin/main --exact`）。今の録画の持ち替えは、どれも 1・2 の区間に入っていない。
