## 改訂の経緯（2026-09-23）

**Stage 8 は「仕組み」だけにし、主力キャラは Stage 9 の後に 1 体ずつ扱う**（ユーザー合意済み）。理由:

- 初版の主力 4 体（モダニア・クラウン・紅蓮：ブラックシャドウ・アリス）は、検証しやすさで選んでいなかった。
- 4 体とも火力の中心が Stage 9 の仕組み（装弾数・リロード速度・チャージ速度）にあり、Stage 8 だけでは大きく欠けた暫定値にしかならない。
- 仕様の分からない点（殲滅モード、満開中のカウンタ、同値の選び方など）が多く、実機と比べる撮影も 1 体ごとに専用のものが要る。

主力キャラの優先順は **リター・クラウン・アリス**（ユーザー指定）。3 体に要る語彙は 12 節に控え、Stage 10 で 1 体ずつ足す。

## Context

Stage 6 で「決まったきっかけで N 秒付くバフ」（`timed`）を、Stage 7 で「いつバーストが起きるか」（ゲージ・CT・チェーンの動的サイクル）を扱えるようにした。ここまでのきっかけは**戦闘の時刻表**（戦闘開始・バースト・フルバースト）だけで決まる。

Stage 8 では、きっかけが**自分の射撃の回数**（「10 回攻撃した時」）や**発動の回数**（「使用回数別の効果」）であるもの、効果が**バフではなく倍率ダメージ**（「最終攻撃力の X% のダメージ」）であるものを扱う。あわせて、Stage 6・7 から段階 C に送られた 3 件を片づける（0.2 節）。

**設計の芯は「射撃のタイミングは、まだバフに依存しない」こと。** 弾数・リロード速度・チャージ速度を変えるバフは Stage 9 に回す。そうすれば射撃の列（どのフレームに誰が撃つか）は編成だけで決まり、「N 回目の射撃」のフレームも戦闘前に静的に決まる。Stage 7 の 2 パス構成と、「sim と calc の差は通常攻撃の離散化だけ」という前提をそのまま保てる。

**語彙は、所持キャラか既存の録画で実機と比べられるものに絞る。** 比べる相手のいない語彙（スタック、状態、新しい対象など）は、必要とする主力キャラの Stage で足す。

## 1. 時間モデル — 2 パスのまま「射撃の列」を共有する

Stage 7 の 1 パス目（`planDynamicSchedule`）は、各枠の射手を回してゲージを溜めるだけで、射撃フレームは捨てていた。Stage 8 ではこの**射撃の列を記録して共有**する。

```
1 パス目（sim と calc で共有・純関数）
  planShots(slots, frames, model)            → ShotLog[]      各枠の発射フレーム列（バフに依存しない）
  planTeamSchedule(shots, gaugeRates, …)     → BurstSchedule  ゲージは ShotLog から溜める（Stage 7 と同じ時刻表）
  planBuffTimeline(slots, schedule, shots)   → BuffTimeline   回数トリガー・発動回数・段階突入（3 節）
  planSkillHits(timeline, shots, schedule)   → SkillHit[]     倍率ダメージの発動（3.4 節）
2 パス目
  sim : フレームループで射撃を数え、区間ごとの 1 トリガー値を足す。SkillHit はそのフレームで足す
  calc: 区間グループごとに 平均レート × 秒数 × 1 トリガー値。SkillHit は同じ列をそのまま足す
```

依存が一方向（循環しない）であることが 2 パスの条件で、Stage 8 の語彙はすべてこれを守る:

- 射撃の列は編成だけで決まる（射撃を変えるバフは Stage 9）。
- 時刻表は射撃の列と**常時の**ゲージ速度だけで決まる（ゲージ速度は `passive` に限る。2.5 節）。
- バフ窓と倍率ダメージの発動は、射撃の列と時刻表から決まる。

1 パス目は `team.ts` の `planTeamRun` にまとめ、sim と calc の両方がこれを呼ぶ（呼び出しの重複をなくすため）。

## 2. DSL の追加（`skills/types.ts`）

新しい `kind` は 1 つ（`damage`）、トリガーは文字列 3 つと回数トリガー 2 種、stat は 2 つ。

### 2.1 段階突入トリガー

```ts
export type BuffTrigger =
  | 'battleStart'
  | 'burstUse'
  | 'fullBurstStart'
  | 'fullBurstEnd'
  | 'burstStage1Enter' // ゲージが満タンになった時（リエントリーで段階 1 に戻った時も）
  | 'burstStage2Enter' // 発動の結果、次の段階が 2 になった時（通常は I の発動フレーム）
  | 'burstStage3Enter'; // 同じく 3 になった時（通常は II の発動フレーム）
```

### 2.2 射撃の回数トリガー

```ts
/** 「通常攻撃で N 回攻撃した時」「通常攻撃が N 回命中した時」「フルチャージして攻撃した時」 */
export type ShotCountTrigger = {
  count: 'normalShot' | 'normalHit' | 'fullChargeShot';
  /** N 回ごと（即値）。every / everyRef とも省略なら毎回（1） */
  every?: number;
  /** N の description_value_NN。every とどちらか片方 */
  everyRef?: number;
};
```

- **数え方（11 節 2）**: 1 回 = 弾薬を 1 消費する 1 トリガー（SG もペレットではなくトリガー）。敵は静止した単体ボスで全弾命中の前提なので、`normalShot` と `normalHit` は同じ列になる（語彙は分けておき、命中率を扱う日に分岐させる）。`fullChargeShot` はチャージ武器（SR・RL）の全射撃（Stage 2 以来、常にフルチャージで撃つモデル）。
- **カウンタはリロードでも戦闘中ずっとリセットしない**。`every: 10` は通算 10・20・30…回目で発火する。
- **トリガーになった射撃自身にはバフが乗らない**: 回数トリガーで付くバフの窓は発火フレームの次のフレームから始める。倍率ダメージ（2.4 節）はそのフレームで、トリガーになった射撃と同じバフ状態で計算する。
- `every = 1`（毎回）の倍率ダメージ（モダニアの毎命中の追加ダメージ）は Stage 8 では**検証エラー**にする（`everyRef` の値が 1 になる Lv も、解決時に弾く）。扱い方（1 トリガーの値に畳み込むか）は使うキャラの Stage で決める。

### 2.3 発動回数の段階（「使用回数別」「開始回数別」）

```ts
/**
 * 「使用回数別の効果・下位効果のスタック適用」: その回数目以降の発動のたびに発火する。
 * burstUse = 自分がバーストスキルを使った回数、fullBurstStart = フルバーストタイムが始まった回数（編成全体）
 */
export type EventCountTrigger = {
  count: 'burstUse' | 'fullBurstStart';
  /** 何回目以降か（1 始まりの即値。説明文の「1 回 / 2 回 / 3 回」） */
  atLeast: number;
};

export type EffectTrigger = BuffTrigger | ShotCountTrigger | EventCountTrigger;
```

- 「下位効果のスタック適用」は、段階ごとに `atLeast: 1 / 2 / 3` の効果を 3 つ書けば表せる（3 回目の発動では 3 つとも発火する）。維持中の再発火は Stage 6 の上書き延長。
- **回数は戦闘中ずっと数え、リセットしない**（11 節 3）。3 回目以降は毎回、段階 1〜3 がすべて付き直す。
- 「各段階の効果のみ適用」（紅蓮：ブラックシャドウ・モラン・アルカナ：フォーチュンメイト）は表せない。使うキャラの Stage で足す。

### 2.4 倍率ダメージ `damage`

```ts
/**
 * Stage 8: トリガー付きの倍率ダメージ（「最終攻撃力の X% のダメージ / 分配ダメージ / 追加ダメージ」）。
 * burst スロットの無条件の発動ダメージは従来どおり burstDamage
 */
export type DamageEffect = {
  kind: 'damage';
  trigger: EffectTrigger;
  ref: number;
  damageType: 'skill' | 'distributed' | 'additional';
  assumes?: LocalizedText;
};
```

- どのスロットにも書ける。発火フレームの列（`SkillHit[]`）にして、バーストヒットと同じく 1 発ずつ計算する。
- 式は `burstDamage` と同じ（11 節 4）: `max(1, 攻撃力 − 防御力) × X/100 × (1 + 会心期待値) × (1 + Σ attackDamage) × 属性有利`。分配ダメージにはさらに `× (1 + Σ distributedDamage)` を**別の乗数**で掛ける（録画 0021）。コア・距離補正は乗せない。フルバースト補正は乗せる（14 節で訂正）。
- バースト系のトリガー（`burstUse` と、その回数トリガー）で出る `damage` は、`burstDamage` と同じく**発動直前のバフ**で計算する（`BURST_HIT_USES_PRE_ACTIVATION_BUFFS`）。射撃の回数トリガーのものは、トリガーになった射撃と同じバフで計算する。
- 対象の数（ドレイク「敵 3 機」、イサベル S2「敵 5 機」）は単体ボスなので 1 ヒット（`assumes` に書く。`burstDamage` と同じ流儀）。
- バーストの段階別の追加ダメージ（イサベル）は、**上がる前の段階を見る**（14 節。段階 2 の追加ダメージは `atLeast: 3`、段階 3 は `atLeast: 4`）。

### 2.5 stat の追加

```ts
export type BuffStat =
  | 'attack'
  | 'critRate'
  | 'critDamage'
  | 'attackDamage'
  | 'chargeDamage'
  /** 分配ダメージの乗数 (1 + Σ)。distributed の倍率ダメージにだけ掛かる（録画 0021 で別枠の乗数と確認） */
  | 'distributedDamage'
  /** バーストゲージのチャージ速度 (1 + Σ)。対象の枠の射撃で溜まるゲージに掛かる。passive にだけ書ける */
  | 'burstGaugeSpeed';
```

- `burstGaugeSpeed` を `timed` に書くと、時刻表 → バフ窓 → ゲージ → 時刻表の循環になるので**検証でエラーにする**。マナは「毎サイクル自分がバーストするので、ゲージが溜まる区間にはいつも付いている」を `assumes` にして `passive` で書く。

## 3. core の共通部分

### 3.1 射撃の列（`sim/shots.ts` 新設）

`planShots` が枠ごとの `ShotLog`（発射フレームの昇順の列。1 要素 = 1 トリガー。チャージ武器なら `fullCharge`）を作る。`planDynamicSchedule` は射手を自分で回す代わりに `ShotLog` を受け取り、フレームごとのゲージ量を `ShotLog` から作る（`energyPerTrigger × (1 + burstGaugeSpeed)`）。ゲージ速度のない編成では時刻表が Stage 7 と 1 フレームも変わらない（退化テスト）。`burst: false` でも回数トリガーのために `planShots` だけは回す。

### 3.2 トリガーの発火フレーム（`skills/timeline.ts`）

`triggerFrames` を `EffectTrigger` に広げる。

| トリガー              | 発火フレーム                                                                |
| --------------------- | --------------------------------------------------------------------------- |
| 文字列（Stage 6 / 7） | 従来どおり                                                                  |
| `burstStageNEnter`    | 時刻表から（3.3 節）                                                        |
| `ShotCountTrigger`    | `ShotLog.frames` の `every`・`2 × every`…番目。バフ窓はその次のフレームから |
| `EventCountTrigger`   | `burstUse` / `fullBurstStart` の発火フレームのうち `atLeast` 番目以降       |

窓の作り方（上書き延長の和集合）・区間分割・グループ化は Stage 6 のまま。

### 3.3 時刻表の追加（`burst/controller.ts`・`burst/schedule.ts`）

- `BurstActivation` に `enteredStep: BurstStepKey | null`（この発動の結果入った段階。フルバーストなら null）を足す。`burstStage2Enter` / `burstStage3Enter` はこれで引き、`burstStage1Enter` は `gaugeFullFrames` と `enteredStep === 'Step1'` の発動（リエントリー）を合わせる。
- **フルバースト時間を枠ごとにする**: `BurstUnit` に `fullBurstFrames = durationToFrames(burstSkill.durationSeconds)` を足し、StepFull に入る発動をした枠の値でフルバーストの窓を作る（イサベルなら 300f、モダニアなら 900f）。固定サイクル（`burstModel: 'fixed'`）は 600f のまま（退化テストを守る）。

### 3.4 倍率ダメージの発動（`skills/skillHits.ts` 新設）

- `planSkillHits` が倍率ダメージの発動の列（`SkillHit[]`: フレーム・枠・効果・発動フレームのバフ状態で計算した期待ダメージ）を作る。計算は `computeBurstHit` を一般化した `computeSkillHit`（2.4 節の式）。`burstDamage` もこの関数を通す（数値は変わらない。退化テスト）。
- sim も calc もこの列をそのまま足す。倍率ダメージの合計は sim と calc で**厳密一致**する。
- 置き場所: `planSkillHits` は `skills/skillHits.ts` ではなく `team.ts` に置く。攻撃力の計算に `TeamSlotInput`（育成値・スペック固定の攻撃力）が要り、`skills/` から `team.ts` を import すると循環するため。式の部分（`computeSkillHit`・`resolveDamageEffects`）は `skills/burstDamage.ts` に置く。

## 4. sim（`sim/engine.ts`）

- 1 パス目を `planShots` → `planTeamSchedule` → `planBuffTimeline` → `planSkillHits` に置き換える。
- フレームループに足すのは、`SkillHit` のフレームでその期待ダメージを足すことだけ。結果に `skillHits`、`trace` に `skillHit` を足す。
- 2 パス目の射撃は射手を回さず、`ShotLog` のフレームを順に読むだけにする。射撃フレームが `ShotLog` と一致することは構造で保証される。Stage 9 で 1 パスに戻すときに射手をフレームループへ戻す。

## 5. calc

### 5.1 core（`team.ts`）

- 1 パス目は sim と同じ関数を呼ぶ。**calc が期待値で置くのは Stage 5〜7 と同じく通常攻撃の区間ごとのトリガー数だけ**で、回数トリガーの発火と倍率ダメージの発動は sim と同じ列を使う（11 節 1）。
- `totalDamage = normalDamage + burst.totalDamage + skillHits.totalDamage`。

### 5.3 UI（最小限）

持続バフのきっかけ表示に回数を足し、倍率ダメージの一覧（回数つき）と編成の「スキルダメージ」の列、時刻表のフルバースト区間の長さを出す。apps/calc の入力と保存キーは変えない。

## 10. リスク・留意点

- **Stage 9 で 2 パスが崩れる**: 射撃が変わるバフが入ると、射撃の列 → 回数トリガー → バフ → 射撃の列…と循環する。Stage 8 の `planBuffTimeline` / `planSkillHits` は「射撃の列と時刻表を受け取るだけ」の形にしておき、Stage 9 で sim を 1 パスにするときに逐次（フレームごと）に呼べる形へ寄せる。Stage 8 のうちに先回りはしない。
- **AI のフルチャージ**: Stage 7 で「AI の SR はゲージにフルチャージ倍率が乗らない」と分かった。AI の射撃がスキルの「フルチャージして攻撃した時」に数えられるかは確かめていない。Stage 8 では全員フルチャージとして数える（ダメージの既存の仮定に合わせる）。使うキャラ（アリスなど）の Stage で確かめる。
- **SG の「命中」**: ゲージではペレットの 75% しか数えないと分かっている。「N 回命中」をペレットで数えるなら SG は 10 倍近く速く発火する。ドレイクは「攻撃した時」なのでこの問題に当たらない。

## 11. 決めてほしいこと（推奨付き）

**決定済み**（2026-09-23 の見直し）: 射撃が変わるバフは Stage 9、主力キャラ（リター・クラウン・アリス）は Stage 9 の後に 1 体ずつ、Stage 8 の語彙は実機で比べられるものに絞る。7 点はいずれも推奨案で承認。

1. **calc の近似方針（要件の未決事項 5）** — **sim の 1 パス目の射撃の列から作った発火フレームを calc も使う**（1 節・5.1 節）。回数トリガーの窓と倍率ダメージの発動は sim と厳密一致し、calc が期待値で置くのは通常攻撃のトリガー数だけ、という Stage 5〜7 の不変条件が保てる。Stage 7 の 9 節 1（時刻表を sim と共有）の延長。採らない案: ロードマップの字面どおり「平均頻度モデル」（発火間隔 = N ÷ 秒間トリガー数）。軽いが、リロードの位相やフルバーストとの重なりで sim との差が数 % 開く。

2. **射撃の回数の数え方** — **トリガー単位（SG もトリガー）・命中 = 攻撃（全弾命中の前提）・カウンタはリセットしない・トリガーになった射撃自身にはバフが乗らない**（2.2 節）。

3. **発動回数の数え方** — **戦闘中ずっと数え、リセットしない。段階 N の効果は N 回目以降の発動のたびに付き直す**（2.3 節）。

4. **倍率ダメージの式** — **`burstDamage` と同じ式**（コア・距離補正なし、会心期待値あり、攻撃ダメージ・属性あり。分配ダメージには `distributedDamage` を掛ける）。補正ごとに名前を付けた定数にして、実測で覆す（フルバースト補正は 14 節で覆った）。

5. **フルバースト時間** — **StepFull に入る発動をしたニケの `burst_duration`**（イサベル・ミハラ・ベスティー 5 秒、モダニア 15 秒、他は 10 秒）。Stage 7 の 9 節 3 で保留したもの。D の「5.04 秒▲」はスキル値なので扱わない。固定サイクルは 10 秒のまま。

6. **ゲージ速度** — **`passive` だけ許し、`timed` はエラー**（2.5 節）。マナは `assumes` で「毎サイクル自分がバーストする」を置く。

7. **検証用に定義するキャラ** — **ドレイク・イサベルを新規、クイーン（真）・マナ・ラピを更新**（6 節）。

## 14. 射撃場の実測の結果（2026-09-23、録画 0036〜0038）

数値は [verification.md](verification.md) Stage 8 節。8.6 節の 5 項目はすべて確認でき、仮定を 2 点訂正した。

| 8.6 節 | 仮定（11 節）                                | 実測                                                    | 対応                                                                            |
| ------ | -------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 1      | 回数はリロードをまたいで数える               | そのとおり                                              | そのまま                                                                        |
| 2      | 倍率ダメージにフルバースト補正は乗らない     | **乗る**（S2 / ペレットの比がフルバーストの内外で同じ） | **`SKILL_HIT_FULL_BURST_BONUS = true`**（フルバースト中に出た倍率ダメージだけ） |
| 3      | 発動回数は戦闘中ずっと数え、N 回目以降に付く | そのとおり。5 回目まで付き直す                          | そのまま                                                                        |
| 4      | バーストは同じ発動で上がった段階を見る       | **上がる前の段階を見る**                                | **イサベルの定義を `atLeast: 3 / 4` に直した**                                  |
| 5      | フルバースト時間は III の `burst_duration`   | イサベルで 5 回とも 300f                                | そのまま                                                                        |

そのほかに分かったこと:

- 倍率ダメージに**距離ボーナスは乗らない**、**攻撃ダメージは乗る**、**追加ダメージは会心する**。2.4 節の式のうち、フルバースト補正以外はそのままでよかった。
- **敵の受けるダメージ▲は別枠の乗数**。敵デバフは語彙にないので未対応のまま。扱うなら stat ではなく「敵側の乗数」として別の仕組みが要る。
- イサベルのバーストスキルダメージは発動から約 2.5 秒遅れて着弾し、S1 の段階のバフもそのころから効く。モデルは発動フレームで付けているので、この差だけ早い（45 秒の段階バフでは影響は小さい）。
- **宝物（お気に入りアイテム）はスペック固定でも反映される**。Blablalink の CDN から取り込んでいるのは基礎スキルだけなので、宝物版のキャラは今のデータでは再現できない。主力キャラ（Stage 10）の前に、宝物版のスキルの取り込みを検討する。
