## Context

いまの公開サイト（`apps/calc`）は calc モデル（`team.ts` の `computeTeamDamage`）だけを使い、sim（`sim/engine.ts` の `runSimulation`）は CLI と整合テストからしか呼ばれない。これを **2 つのモデルとして育て、サイトからどちらも使えるようにする**。

2026-09-25 のユーザー決定:

1. **sim が calc より正確になるもの**
   - 状態に依存する機構: **必須**。実戦ではさまざまな要因がダメージを増減させ、期待値モデルでは再現しにくいケースがある。
   - 乱数（ばらつき）: **将来必要**。期待値だけでなく、どれだけばらつくかを出す。
   - 内訳の表示: あれば良い程度。ただし、ダメージに絡む出来事（バリア・無敵・画面外への移動など）は可視化する。
2. **アプリ**: 当面は 1 つのアプリで calc / sim を切り替える。開発に余力ができたら 2 つのアプリに分ける。
3. **名前**: モデルとアプリを 1 対 1 に揃え、「calc = calc モデルとそのアプリ」「sim = sim モデルとそのアプリ」とする。

## 1. 2 つのモデルの役割

|                        | calc                                                     | sim                                                                      |
| ---------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------ |
| 位置づけ               | すぐ結果が出る期待値モデル。入力を変えるたびに再計算する | 正確さを優先するフレーム逐次モデル（実行のきっかけは 7 節 6）            |
| 実行                   | 乱数なしで 1 回                                          | 乱数なしで 1 回（期待値モード）、または乱数ありで N 回（分布モード）     |
| 合計の出し方           | 区間ごとの期待値                                         | 1 発ごと                                                                 |
| 決定論的な状態         | 共通のフレームループで扱う（sim と同じ）                 | 同左                                                                     |
| 乱数の結果で変わる状態 | 扱わない（未対応・近似の一覧に出す）                     | 扱う（会心・コア命中・命中が起点のトリガーやスタックなど）               |
| 出力                   | 合計・枠別・区間別の内訳                                 | calc と同じ内訳 ＋ 分布（平均・標準偏差・分位点）＋ 出来事のタイムライン |

**芯になる原則**:

- **式・スキル定義・データ・フレームループは 1 つだけ持つ。** 2 つのモデルで違うのは「乱数を振るか」と「区間でまとめるか・1 発ずつ足すか」だけにする。機構を 2 か所に書くと、どちらかが古くなるため。
- **決定論的な状態依存（敵の出来事、経緯で変わるスキル）は共通のフレームループに入れる。** その結果、calc にも効く。calc に入らないのは、乱数の結果に依存する状態だけ。
- **sim の期待値モードと calc の差は、発射サイクルの離散化だけに保つ。** これを今の `simCalc.test.ts` と同じく回帰テストの軸にする。乱数ありの N 回の平均も、期待値モードに収束することをテストする。

## 2. コードの構成

```
packages/core/src/
  damage.ts, stats.ts, skills/, burst/ …   共通（今のまま）
  frame/     共通のフレームループ（今の sim/firstPass.ts・shooter.ts・firing.ts・shots.ts と team.ts の planTeamRun など）
  calc/      calc モデル（今の team.ts の computeTeamDamage と区間の集計）
  sim/       sim モデル（今の sim/engine.ts。16-C で乱数と分布）
apps/web/    1 つのアプリ（今の apps/calc）。calc / sim を切り替える
```

- `team.ts` は共通の型と入力の検証だけにする。
- 2 つのアプリに分けるときは、`apps/web` を `apps/calc` と `apps/sim` に分け、入力の画面を `packages/ui` に切り出す。
- 公開 URL（https://hkhkm-dev.github.io/nikke_project/）は変えない。

## 3. 段取り（1 段 1 PR）

### 16-A 構造の整理（挙動は変えない）

- 2 節の通りにファイルを移し、`team.ts` を分ける。**数値は 1 つも変わらない**（全テストがそのまま通る）ことを完了条件にする。
- `apps/calc` を `apps/web` に改名する（Pages の workflow・README・AGENTS.md も合わせる）。
- 画面に「calc / sim」の切り替えを足す。sim の結果は calc と同じ内訳の表で出し、calc との差を並べる。sim はブラウザでも数十 ms で終わるので、この段ではメインスレッドで実行する。

### 16-B 敵の出来事（バリア・無敵・画面外）

- 敵の出来事の時刻表を core の共通の入力にする（`EnemyEvent`: 種類・開始・終了、仮称）。敵のプリセット（Stage 15）に持たせる。
- 共通のフレームループで出来事を扱うので、calc と sim の両方に効く。
- **出来事の間に何が起きるかは、実測で決める**（ダメージが 0 になるか、ゲージが溜まるか、射撃の回数トリガーを数えるか、画面外の間にリロードするか、など）。単騎・最小構成で撮り、確定するまでは「未実装」のプレースホルダーにする。
- sim の結果に、出来事とダメージの推移のタイムラインを出す（ユーザー決定の「可視化」）。

### 16-C 乱数と分布（将来）

- シードを指定できる乱数で、会心・コア命中・命中を 1 発ごとに判定する（同じシードなら同じ結果）。
- N 回実行して、平均・標準偏差・分位点を出す。N 回ぶんの時間がかかる（N = 100 で数秒の見込み）ので、ブラウザでは Web Worker で回す。
- 乱数の結果で変わる状態（会心時・コア命中時のトリガーなど）は、この段以降に sim だけに入れる。
- 検証: 射撃場のスペック固定の反復のばらつき（σ ≈ 2%、[design-stage12.md](design-stage12.md) 5.3 節）と比べる。

## 6. 用語（承認後に AGENTS.md に書く）

- **calc**: 区間期待値のモデルと、その結果を出すアプリ（今は `apps/web` の calc 表示）。
- **sim**: フレーム逐次のモデルと、その結果を出すアプリ（今は `apps/web` の sim 表示）。
- **共通のフレームループ**: 両モデルが使う 1 パス目（`core/src/frame/`）。

---

## 7. 決めてほしいこと

1. **アプリ 1 つの間のディレクトリ名** — 推奨: **`apps/web`**。`apps/calc` のままだと、sim の画面も入るので名前がまた重なる。
2. **共通のフレームループの置き場** — 推奨: **`core/src/frame/`**。`sim/` の下に置いたままだと「calc が sim を使う」形になり、1 対 1 の名前と合わない。
3. **sim のエンジンの持ち方** — 推奨: **共通のフレームループにオプション（乱数・1 発ごとの記録）を足す**。sim 専用のエンジンを別に書く案は、機構を 2 か所に書くことになるので採らない。
4. **敵の出来事を calc にも効かせるか** — 推奨: **効かせる**（共通のフレームループで扱うため自然に効く）。calc は「すぐ出るが粗い」ではなく「すぐ出る期待値」で、決定論的なものは正確に扱う。
5. **段の順番** — 推奨: **16-A → 16-B → 16-C**（状態依存が必須、乱数は将来、というユーザー決定の順）。
6. **sim の実行のきっかけ** — 推奨: **16-A・16-B では calc と同じく入力のたびに自動で再計算、16-C の分布モードだけボタンで実行**。
7. **Stage 番号** — 推奨: **Stage 16**。Stage 15 の撮影（15-B 迎撃戦など）とは独立しているので、並行して進めてよい。

## 8. 16-A の実装（2026-09-25）

2 節の構成どおりに分けた。設計からの差分と、決めたことは次のとおり。

- **結果の型は `team.ts` に置いた。** `TeamResult`・`TeamSlotResult` などは calc と sim の両方が作る（下の `simTeamResult`）ので、calc の中ではなく共通の型にした。結果に添える `treasureOf`・`skillSupportOf` も同じ理由で `team.ts` に移した。
- **1 パス目は `frame/plan.ts`**（`planTeamRun`・`planSkillHits`・`burstSnapshotState` など）。フレームループの部品（`firstPass.ts`・`shooter.ts`・`firing.ts`・`shots.ts`）は `sim/` から `frame/` に移した。`sim/` に残るのは `engine.ts`（2 パス目）と `teamResult.ts` だけ。
- **画面は sim の結果も `TeamResult` の形で受ける。** `sim/teamResult.ts` の `simTeamResult` が、sim の区間を calc と同じグループに集計する（トリガー数は sim が撃った数で `triggerSource: 'shots'`）。そのために sim の結果にバーストスキルの発動ごとの内訳（`burst.hits`）と倍率ダメージの発動列（`skillHits`）を足した。値は 1 パス目のものなので calc と同じ。
- **計算モデルの選択欄は「編成の内訳」の先頭に置いた。** sim を選ぶと、合計と枠ごとに「calc との差」を並べる。選択は閲覧者ごとの好みなので、編成の保存形式には入れず別のキー（`nikke-web.model`）に置く。編成の保存キー `nikke-calc.team.v1` は、保存済みの編成を読めるように変えない。
- sim は 7 節 6 のとおり入力のたびに自動で回す（ブラウザでも数十 ms）。
- `.claude/launch.json` の開発サーバの名前も `web` にした。
