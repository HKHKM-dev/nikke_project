## 条件

- 目的: ウンファ：タクティカル・アップ（95）のバーストの炸裂弾の着弾が、的の着地点の帯ごとにそろう（C-0509。録画 232・233・287 を読んだ後に立てた仮説 H3）を、予測を固定してから撮る新しい録画で確かめる（backlog 2-4。plan/burst-effect-delay-candidates.md の R4。2026-10-09 のオーナーの判断）。
- 編成（録画 232 と同じ）: I-DOLL・フラワー（304。I・操作・撃たない）+ ウンファ：TU（95。II・AI）。灼熱の的（BigArms）・3 分モード・スペック固定 ON・オートバースト ON。III がいないのでフルバーストは起きない。
- 最小構成: フラワーは機構が確定したキャラ。炸裂弾の発射と着弾の時刻に効きうる未確定の要素は、ウンファの使用武器変更の時刻（この検証の問い）のほかに無い（フラワーの効果はバーストの倍率ダメージとゲージだけ）。
- 見るのは、各回の II の発動（右のバースト欄の六角形が II から III に替わり、III のタイマーの 09.98 が出たフレーム）から、炸裂弾の着弾（HUD の増分）までのフレーム数と、そのときの的の着地点の帯（ジャンプと通常攻撃の距離ボーナスの有無から。V-0390 と同じ）。
- 3 分モードの的は、中近 → 近 → 遠 → 中遠 → 近 → 遠の順に着地する（data/enemies.json の range-3min-jump）。232 では 4 回のバーストが近・遠・中遠・近に当たった。撮影の操作で帯は選べないので、どの帯に当たるかは撮ってみないと分からない。

## 予測（撮る前に書く）

仮説ごとに、この録画で何が見えるはずか。見分けられるか。外れたときの影響。数値は予測ファイル（records/predictions/V-0387.json。npm run records:predict -- V-0387）を指す。既存の録画の読み直しなら、冒頭の「録画」に挙げてから予測を出し、読む前に commit する。

撮る前に書いた（2026-10-09）。

- **H0**（いまのモデル。予測ファイルの `shot-delay-1`〜`4` の H0）: どの回も、どの帯でも、予測ファイルの値（持ち替えの後のフルチャージの待ち）。
- **H3**（C-0509。範囲外。手計算）: 帯ごとに次の範囲に入る（V-0390 の 14 回の幅に、読み取りの ±1f を足した）: **近 21〜24f・中近 23〜26f・中遠 24〜27f・遠 26〜29f**。同じ帯の回どうしの差は 2f 以内で、帯の順（近 < 中近 ≦ 中遠 < 遠）も同じ。
- **H4**（帯によらない。範囲外）: 遅れは 22〜28f に散らばるが、帯との結び付きが無い（同じ帯の回が 3f 以上離れるか、遠の回が近の回より短い）。
- 見分け方: 回ごとに帯と遅れを並べる。H0 は 30f 前後でないと合わない。H3 はすべての回が自分の帯の範囲に入れば合う。範囲を外れる回が 1 つでもあれば H3 は合わない。
- 予想: **H3**。
- 外れたとき: H4 なら、帯（飛ぶ時間）でなく、ほかの何か（発射の待ちのばらつき）で決まる。C-0509 の「帯でそろう」を棄却して書き直す。H0 なら、V-0390 の 3 本の読みを見直す（替わり目の読み方か、炸裂弾の増分の取り違え）。
- 合ったとき: C-0509 を、予測を固定した録画で再現した結論に置き換える（等級は反復実測の候補）。モデルの直し方（発射までの待ちと、炸裂弾の飛ぶ時間の帯ごとの表。アニス：スターの誘導弾の飛ぶ時間 C-0237 と同じ置き方）を設計書にしてオーナーに出す。

## 読み方

1. 撮った録画を取り込む（`tools/captures/intake.ts`。台帳の条件に「V-0387（R4）。録画 232 と同じ編成。操作のフラワーは撃たない」）。
2. HUD の増分（`npm run records:read -- <録画 id> --recipe hud-jumps --source V-0387`）で炸裂弾の着弾（ウンファの通常攻撃の約 2.5〜3 倍の増分）を探す。
3. 各回の II の発動を、着弾の 36〜5f 前の右のバースト欄を 1 フレームずつ並べた一覧（crop=200:70:1720:400・tile）で読む（III のタイマーの 09.98 が出た最初のフレーム）。
4. 帯は、増分の空き（ジャンプ）と、ウンファの通常攻撃の距離ボーナスの有無（遠だけ付く）から、3 分モードの順に当てる。
5. 1〜4 回目を `burstEffectFirstShot`（slot 2・n 0〜3。許容 ±1）の観測値にし、回ごとの帯と遅れを記録にする。`npm run records:check` で予測と比べ、`records:minimal` で警告を確かめてから結論を書く。
