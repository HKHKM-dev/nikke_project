# レシピ charge-shots（チャージ武器の単騎の射撃の列）

- 出どころ: [design-records-automation-log.md](design-records-automation-log.md) 8.6 節の「チャージ武器の単騎の射撃の列のレシピ（V-0090 の経過）」。backlog 5-9。
- V-0090 は、紅蓮：ブラックシャドウ・ラム・I-DOLL・フラワーの単騎 7 本を、`hud-jumps` のキャッシュと使い捨てのスクリプトで読んだ。その数え方を `npm run records:read` のレシピにする。
- 読み取りの約束は [captures/tools.md](captures/tools.md)、検証の流れは [verification-guide.md](verification-guide.md)。

## 1. 何を出すか

SR・RL（チャージ武器）単騎・スペック固定 ON・射撃場 3 分モードの録画から、区間（1〜6 区間目。中近・近・遠・中遠・近・遠。C-0031）ごとに次の数を出す。V-0090 で手で読んだ観測値と同じ形にする。

| 観測値（kind `count`、use `record`） | 中身                                                                                             | V-0090 の手の読みの例           |
| ------------------------------------ | ------------------------------------------------------------------------------------------------ | ------------------------------- |
| 撃った発（6 区間）                   | 部分チャージの発と、総ダメージに出ない発を含む                                                   | `0055-13`・`0075-13`・`0077-12` |
| 総ダメージに出ない発（6 区間）       | 刻みの抜け。抜けたフレームを注記に書く。コンテナの発（C-0108）か外れかは分けない（2 節の論点 1） | `0055-14` + `0055-15`           |
| 総ダメージに出たフルチャージの発     | 部分チャージの発と抜けを除く                                                                     | `0055-17`・`0077-16`            |
| そのうちコアを外した発               | 胴体・胴体会心の値の発                                                                           | `0055-18`・`0077-17`            |
| 撃った発の合計                       | 上の 1 行目の合計。モデルと比べるか（`compare`）は検証記録が決める（レシピは `record` で出す）   | `0055-16`                       |

注記（`method.note`）には、刻み・リロードの空き・装弾数（どれも録画から測った値）、窓（ジャンプで撃たない間）の前後のフレーム、部分チャージの発のフレーム、読めない間（`hud.ts` の gap 列が 2 以上）にかかった発の数、説明のつかない増分を書く。`--opt start` を与えたら、フレームを戦闘開始からの数（V-0090 の観測値と同じ）でも書く。

## 2. 読み方

入力は `hud-jumps` のキャッシュ（`hud-jumps@2`）だけ。新しい画面の読みは足さない。

1. **1 発の値の格子**: `--opt body=<胴体の 1 発>`（フルチャージ・距離ボーナスなし・非会心）から、スペック固定 ON の格子（距離 0.3・会心 0.5・コア 1.0。`smg-hits.ts` の `fixedSpecGrid`）の 8 つの値を作る。増分が格子の値と差 2 以内ならフルチャージの発（コアかどうかも決まる）。
2. **発でない増分**: 格子に乗らず、読めない間の無い増分のうち 2 回以上出る値（S1 の段・バーストのヒットなど）と、その 2 つの和は、発でない増分として捨てる。
3. **割れた読み・遅れた読み**: 格子に乗らない増分は、(a) 格子の値 + 発でない増分（読めない間に重なって出た）、(b) 25f 先までの増分を足して (a) か格子の値になる（桁送りで割れた読み）、なら 1 発にする。発の時刻は、読めない間の始まりから増分のフレームまでの幅で持つ。
4. **刻みの格子**: 読めない間の無いフルチャージの発どうしの間から、刻み I（最頻の間の近くの平均。紅蓮BS 43.0f・ラム 82.0f）、リロードの空き G（I の 1.8〜6 倍の最頻。172f・200f）、装弾数 M（G の空きの間の発の数の最頻。9・6）を測る。
5. **格子をたどる**: 前の発の時刻 p と、いまのマガジンの発の数 c から、次の発が来うる時刻（抜け 0〜2 発。リロードは c が M に達した所だけ）を並べ、増分が ±3f（読めない間の幅つき）に乗る最も抜けの少ない当てはめを取る。抜けのある当てはめは、**先読み**（その後の発を次のリロードまで数え、マガジンの発の数がちょうど M になるか）で確かめる。どれも乗らなければ窓（ジャンプ）にし、c を不明にする（ジャンプの間のリロードで、明けのマガジンは満タンとは限らない）。
6. **部分チャージの発**: 格子に乗らず 2・3 で説明のつかない増分が、前の発から I + 3f 以内にあり、次の発が格子に乗らない（窓が来る）なら、窓の前の部分チャージの発にする（V-0090 の C-0109）。最後の増分なら、窓は戦闘の終わりまで。
7. **区間**: 窓の前の最後の発のフレームを切れ目にし、発をフレームで区間に振る（窓の前の部分チャージの発は前の区間）。窓が 5 つでなければ誤りにして `--opt cuts=<f>,…`（5 つ。動画のフレーム）を求め、候補（窓の一覧とリロードの空き）を出す。

### 論点（オーナーの判断）

2026-10-17 にオーナーが 4 つとも案 A（推奨）に決めた。

1. **コンテナの発を分けるか**: レシピは HUD の増分しか見ないので、抜けがコンテナに当たった発（C-0108）か外れかを決められない。V-0090 は画面で確かめて 2 つの観測値に分けた。案 A（推奨）: レシピは「総ダメージに出ない発」までを出し、分けるのは人（画面で見て別の観測値にする）。案 B: 戦闘の始まり（戦闘開始から 800〜850f）と 4 区間目の始まりのリロードの明けの 1 発目を「コンテナの候補」として注記で印を付ける（決めはしない）。
2. **窓がリロードと重なる録画**（`0071` の 1 回目。最終弾の後のリロードの空き 172f の中にジャンプが収まり、HUD の増分では窓が見えない）: 案 A（推奨）: `sg-pellets` と同じく誤りにして `--opt cuts` を求める。案 B: 3 分モードのジャンプの代表の時刻（`range-3min-jump`）に近いリロードの空きを窓とみなして補い、注記に「補った」と書く。
3. **1 発の値の入れ方**: 案 A（推奨）: `--opt body`（`smg-mags` と同じ。値は録画の観測値か増分の列から人が選ぶ）。案 B: 観測値（`hit` など）から引く（8.6 節の経過の書き方）。キャラごとに観測値の ID と並びがまちまちで、引く規則が要る。
4. **スペック固定 OFF**: 会心の値が録画ごとに違い、格子が決まらない。今回は対象外にし、OFF の録画では誤りにする。

## 4. 実施の記録

- 2026-10-17: `tools/captures/recipes/charge-lattice.ts`（増分の分け方・刻みの測り方・格子のたどり方。純粋な関数）と `charge-shots.ts`（レシピ）を足し、`recipes/index.ts` に登録した。単体テストは `recipes/__tests__/charge-lattice.test.ts`（刻みの抜け・部分チャージの発・割れた読み・段に重なった読み・リロード + 抜けに見える窓）。
- 7 本の値は手の観測値と同じなので、`--write` で観測値を足していない（1 つの事実は 1 か所）。新しい録画を読むときに `--write` で書く。
- 作りながら決めたこと: 抜けのある当てはめの先読みは、マガジンの発の数が分かっているときだけ効く。窓の明けのマガジン（発の数が不明）の後ろで、刻み + リロードの空きと同じ長さの窓が来ると、「抜け 1 発 + リロード」と見分けられない（単体テストの fixture を作るときに見つけた。7 本には無い）。
