- 回数のきっかけの数える窓 `during: { state }` は、状態の付与にだけ書ける（`skills/parse/trigger.ts`。damage・timed にも書けるが、`during: "fullBurst"` だけ）。その状態の件が効いている間の発だけを数え、件が新しく始まったら 0 から数え直す（付き直しで件が続いている間は数え直さない）。N の倍数に届いた発で発火する（`skills/holders/sources.ts` の `stateWindowFires`）。

- 弾丸チャージ（`ammoRefill`）は 1 パス目の即時効果（`frame/firstPass/instants.ts`）。残弾に足して最大で止める（`frame/shooter.ts` の `refillAmmo`）。きっかけに `during` は書けない。

- 状態の付与は、スタックが上限でも付くたびに付いた記録を残す（`skills/holders/fire.ts`）ので、`{ applied }` は上限に届いた後の付与でも発火する。

## 2. 語彙

### 2.1 回数のきっかけの「周期の中の位置」`phase`（論点 1）

- 射撃の回数のきっかけに `phase`（即値の整数。1 以上 `every` 未満）を足す。数えた回数が `every` の倍数 + `phase` に届いた発で発火する（`every: 6, phase: 2` なら 2・8・14…回目）。省略は今のまま（`every` の倍数）。
- 書けるのは、数える窓が自分の状態（`during: { state }`）のときだけ（使い手はフォーチュンメイトだけ）。数え直しは `during` のまま（その状態の件が新しく始まった時）。
- S2 の 3 つの段は、同じきっかけの回数を 3 つの効果がそれぞれ数える（どれも同じ発の列で、同じ窓で数え直すので、同じ回数になる）。
- 代わりの案: `cycle` の段の中身に弾丸チャージと状態の付与を許し、`cycle` のきっかけに `during: { state }`（数え直すと段のポインタも最初に戻る）を許す。説明文の形（段の並び）には近いが、`cycle` は 2 パス目で段を決める作りなので、1 パス目の効果（弾丸チャージ・状態の付与）を段にするには、段の決め方を 1 パス目に移すことになる。紅蓮：ブラックシャドウの間隔の変更（`cycleEvery`）とも絡むので採らない。

### 2.2 弾丸チャージのきっかけに `during: { state }` を開く（論点 2）

- `ammoRefill` の回数のきっかけに `during: { state }`（と 2.1 節の `phase`）を書けるようにする。発火は状態の付与と同じ件の一覧の数え方（`stateWindowFires`）を 1 パス目の即時効果から読む（`instantTracker` が `{ ended }` の残弾数減少で `endedAt` を読むのと同じ置き方）。
- 発火は数えた発のフレームで、その発で減った残弾に 6 発を足す（最大の 9 発で止める）。
- 数える窓は、前のフレームまでに付いた件で見る（実装で決めた）。件の登録の中で読む状態の付与と、登録の後に読む弾丸チャージで、同じフレームに付いた件が見えるかが違い、バーストと同じフレームの発を片方だけが数えたため。バーストと同じフレームの発は数えない。状態の付与だけを使うグレイブ（C-1123）の数値は変わらない（既存のテストで確かめた）。

### 2.3 ペレット数▲を状態の中身に開く（論点 3）

- 状態の中身に `pelletCount`（`flat`）を書けるようにする（`skills/parse/state.ts` の制限を外す）。スタックの値は 1 スタックあたり（3 スタックで 3 個）。件の一覧が当たりの段の件として読む（`holders/views.ts` の `hitStageViewsOf('pelletCount')`）のは timed と同じ。
- 効き方は C-1076 のまま（1 発の総ダメージを変えず、ペレットの数で分ける。ペレットの命中の量とゲージは実効のペレットの数）。フォーチュンメイトにはペレットの命中を数える効果が無いので、与ダメージに出るのはゲージ（1 発の量が 11/10〜13/10 倍）だけ。
- `singlePellet` は今のまま timed だけ（使い手がいない）。

### 2.4 足さないもの

- 青春の記録の「通常攻撃ダメージ 10% 倍率▲」は `normalAttackDamage`（武器倍率に (1 + Σ) を掛けて四捨五入。C-0121・C-1262）で書ける。3 スタックなら 1.3 倍。
- 「SG の味方全体」の対象（`targetWeapon`）と「自分を除く」（`excludeSelf: "always"`）、「× 大切な思い出のスタック数」（`perCount`）は今の語彙のまま。

## 6. 論点（オーナーに決めてもらうこと）

1. **攻撃回数別の効果の書き方**（2.1 節）
   - 推奨: 回数のきっかけに `phase` を足し、3 つの段を、同じ窓で数える 3 つの効果で書く（`every: 6` と `phase: 2`・`4`・なし）。
   - 代わりの案: `cycle` の段の中身に弾丸チャージと状態の付与を許し、段の決め方を 1 パス目に移す。
2. **弾丸チャージの `during: { state }`**（2.2 節）
   - 推奨: 開く（状態の付与と同じ数え方を 1 パス目の即時効果から読む）。
3. **ペレット数▲を状態の中身に開く**（2.3 節）
   - 推奨: 開く（効き方は C-1076 のまま。与ダメージに出るのはゲージだけ）。
   - 代わりの案: 幸せな思い出の中身を空にし、ペレット数▲を間接の notes（経路 `pellet`）にする（フォーチュンメイトにペレットの命中を読む効果は無いが、ゲージの量の違いを落とす）。
4. **撮影の仮説が本命と違ったとき**
   - 推奨: 根拠のある別の読み（K2・R2・P2・A2）は、どれも今の語彙か 2 節の語彙の組み合わせで書ける見込み（K2 は `phase` の代わりに上限の回数が要るので、その時に設計書に足して諮る）。書けないものは未対応の notes にする。
5. **PR の範囲**
   - 推奨: 1 体 1 PR。2 節の語彙・定義・撮影の結論を 1 本にする。
