## 2. A1: 着地点ごとの飛ぶ時間

- 的の表の行（`flightFrames.shots.RL.byProjectile["HomingProjectile:100:750"]`）は「着地点の id → 帯 → all」の順で引く（`frame/landing.ts` の `flightSpansOf`）ので、語彙は足さずに id のキーを足せば入る。
- 足す値（C-0413・C-0461 の録画ごとの中央値の真ん中。フレームは整数なので切り捨て）: `midFarA` 17・`midFarB` 19・`farA` 26・`farB` 28。中近（14）・近（8。近 A・B の差は読んでいない）・中遠 C（読んでいない）は帯の値のまま。
- 効くところ:
  - 画面（`apps/web`）の着地点の時間割りは帯（`range-3min-jump` の `landings` は帯の名前）なので、帯の値を引き、**利用者の計算は変わらない**。
  - 照合は、録画の `setup` で着地点を固定した区間だけ id の値を引く。アニス：スターの録画は着地点を固定していない（試しに id のキーだけ足して `npm run records:residual` を回すと、11 本の 94 件で差は 0）。読んだ着地点（C-0413 の根拠: 161 遠 B、164・211・289・320・321 遠 A、288 遠 B、中遠は 162 が A でほかは B）を `setup.farLanding`・`setup.midFarLanding` に書くと、満タン・発動の時刻の観測値が数 f 動く。
- 2026-10-05 のオーナーの判断（帯の代表値のまま）は、その時の根拠（C-0293。仮説）での判断だった。いまは着地点ごとの値が確定（C-0413・C-0461）。

## 3. A3: 追加ダメージを着弾の時刻で判定するか

- いまのモデル: S1 の追加ダメージ（skill1.effects[4]）は、ゲージだけを着弾のフレームに溜め、ダメージとバフの判定は発射のフレーム（`frame/firstPass.ts` の `damageGaugeTrackers`。V-0406「分かったこと」の「モデルも同じ扱い（追加ダメージは着弾のフレームに出す）」はゲージのことで、ダメージは発射のフレーム）。
- 出どころ: 発動に重なる発で、追加ダメージだけにバーストの攻撃ダメージ▲が乗った（`0165-14` の 3 回。多人数）。単騎の `0320-13` でも、替わり目の 7f 前に撃った発の本体は▲なし・追加ダメージは▲あり（1 回）。どちらも記録で、結論は無い。
- 確かめ方（撮影なし。既存の単騎の録画の読み直し）: ▲の**終わり**（バースト使用時の攻撃ダメージ▲と、S2 のフルバースト開始時の▲の切れ目）を跨ぐ発を使う。切れ目の飛ぶ時間ぶん前までに撃った発は、本体は▲の付いた値、追加ダメージは▲の外れた値になるはず（予測）。切れ目 1 つに 0〜1 発あり（飛ぶ時間 8〜28f・発の間 42f 以上）、単騎の録画 0164（7 回）・0211・0288（7 回）・0289（6 回）・0320・0321（2 回ずつ）で数回ずつ見込める。予測を commit してから HUD の増分を読む（録画は Drive から取り寄せる。`plan/captures/storage.md`「クラウド環境での取り寄せ」）。
- 確定になったら: 射撃ごとの倍率ダメージのうち `additional` で飛ぶ時間のある枠は、ダメージを着弾のフレームに置き、バフをそのフレームで引く。本体は発射のまま。

## 4. A2・B: 的の表の無い敵

- どちらも、効果の定義は書けていて、足りないのは敵の的の表の行（飛ぶ時間・シューティングスターのコアの割合）。通常攻撃のコア命中率・弾丸命中率・飛ぶ時間も、射撃場の的のほかは表が無く、ほかのキャラ（ラピ：レッドフードの粘着榴弾のコア（`16:skill2`）・シンデレラの曲射の飛ぶ時間など）は未対応の notes にしていない。
- 画面で選べる敵は射撃場の的だけで、ボスは撮影で値を測ってから足す（要件の「敵」）。ボスを足すときに表の行も測る。
- 案:
  - **B-i（推奨）**: 未対応の notes から外し、効果の `assumes` に「的の表の無い敵では 0（コアに当たらない・発射のフレームに着く）」と書く（skill1.effects[4] と burst.effects[0] の `assumes` には既に書いてある）。的の表の無い敵で計算したとき、結果の注記（`slotConditionNotes` と同じ所）に「シューティングスターのコアの割合・飛ぶ時間は表に無いので 0」を出す（いまは画面から起きない）。
  - B-ii: 手入力の欄（シューティングスターのコアの割合）をモデルに足す。通常攻撃の手入力と同じ置き方。値の根拠が無いので既定は 0 で、画面の欄はボスと一緒に足す。
  - B-iii: いまのまま（未対応に残す）。

## 5. C: 窓の発のコアの割合

- C1（近・中近・中遠）は C-0424（確定）で窓の中も外と同じ行と分かっている。notes から外せる。
- C2（遠）は C-0425（仮説）。遠の割合は録画の中でコアと胴体の発が連なって固まり（V-0453）、録画どうしで食い違う。窓の中と外の差は、録画の中で対にしないと録画どうしのばらつきに埋もれる。
- 案:
  - **C-i（推奨。撮影なし）**: 既存の単騎の録画で、遠の区間の窓の中と外を**録画の中で対にして**足す読み直し（0164・0211・0288・0289・0320・0321。読んでいない窓だけ新しく読む）。予測は「差 0」と許容（足した数で決まる 95% の幅）を commit してから読む。差が許容内なら C-0425 の窓の部分を確定に分け、notes を外す（遠の割合そのものの食い違いは表の行の問題として C-0425 に残す）。

  - C-iii: いまのまま（未対応に残す）。
