## 2. 分かっていること・いないこと

### 2.1 b（シューティングスターのコア）は 2 つに分けられる

C-0212 は「コアに当たると補正が乗る」と「当たる割合」の 2 つを 1 件にしている。根拠の強さが違うので分けて扱う。

| 部分                    | 根拠                                                                                                                                                                                                                                                                                                                                                                                                      | 等級の見込み                                                                         |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| b1. コアの 1 ヒットの値 | 観測値の注記に、同じ窓の胴体とコア（会心なし・会心）の値がある（`162-10`・`162-11`・`163-07`・`165-06`・`165-07`・`165-08`）。フルバーストの外ではコア / 胴体が 2 倍、中では (1 + 0.5 + 1) ÷ (1 + 0.5) 倍、会心のコアは (1 + 0.5 + 1 + 0.5) ÷ (1 + 0.5) 倍で、**通常攻撃のコアと同じく boost の加算の枠に (コア倍率 − 1) を足す形**と合い、×2 の乗算の形とは合わない（フルバースト中の比が 2 にならない） | 厳密一致になりうる。ただし値はどれも予測の前に注記に読んだもの（3.2 節）             |
| b2. 当たる割合          | `164-07`（単騎の録画 164 の 1 本。距離帯ごとのコア / 読めた数）と `162-13`（単独の I の 2 回。距離帯に分けていない）だけ。割合は誘導弾・範囲 500 の行（C-0174）に近いが、近いと見たのは数えた後                                                                                                                                                                                                           | 単独実測（1 本で数えた割合）。確定には、値を決めるのに使っていない実測での反復が要る |

### 2.2 d（窓の発）は原因が 2 通りある

C-0215 はフルバースト中の発しか見ていない（`162-06`・`163-06`・`165-03`。HUD の増分がコア 1 ヒット + 追加ダメージに分かれる）。窓は「アニス：スターのバースト 10 秒」、フルバーストは「チェーンの III から」なので、2 つは重なるが一致しない。

| 仮説                        | 見えるはずのもの                                                                                                                                        |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1: 爆発範囲▲（窓）で変わる | 窓の中の発は、フルバーストの有無によらず別の形（コアに当たる・1 発 1 ヒット）。窓の外の発は、フルバースト中でも `:750` の行（コア 0・胴体 1〜2 ヒット） |

- 見分けに使える発: (i) 単騎の録画 164 の窓の発（フルバーストが無い。D1 と D2 を分ける）、(ii) 録画 162・163・165 の、窓の中でフルバーストの外の発（フルバーストの後の窓の残りと、単独の I の窓）。
- フルバースト中で窓の外の発は、録画 162・163・165 には無い見込み。フルバーストはどれも約 290f（イサベルのバーストで 5 秒。V-0167 の「読み方を変えたところ」）で、アニス：スターの 10 秒の窓の中に収まる。
- (i) は、フルバーストの外ではコア 1 ヒットと胴体 2 ヒットの値が同じ（HUD では分けられない）なので、的の上のポップアップ（CORE HIT の表示と、胴体の数字の数）で数える。録画 164 は R1 でポップアップの読める画質で撮った（design-anis-star-s2-burst.md 9.4 節の論点 10）が、窓の発のポップアップはまだ数えていない（`164-07` はシューティングスターだけ）。
- (ii) もフルバーストの外なので、(i) と同じくポップアップで数える。多人数の録画で、ほかの枠のポップアップと重なるので、読めた発だけを数える。
- フルバースト中の発（`162-06` など）は、コア 1 ヒット（boost 1 + 0.5 + 1）・胴体 2 ヒット（2 × (1 + 0.5)）・胴体 1 ヒットが値で分かれるので、HUD の増分で数えられる。D1 と D2 はどちらも「フルバースト中はコア」を予測するので見分けには使わないが、割合を数える材料になる。

## 3. 語彙の案

既存の語彙（的の表の行・`flightFrames.autoAttacks` のキー・`timed` の stat）にならい、新しい種類の効果は作らない。どの欄も、**行が無ければ今と同じ値になる**ようにする（4 節）。

### 3.1 シューティングスターのコアの項（b1）

- `computeBurstHit` の boost に、省略できるコアの項を足す: `boostTotal = 1 + 会心期待値 + フルバースト補正 + p × (コア倍率 − 1)`。p はそのヒットのコアに当たる割合、コア倍率はスキルの持ち主の `shot.coreDamageRate`（アニス：スターは 2）。
  - 通常攻撃のコアの項（`damage.ts` の `boostCore = coreRate × (coreDamageRate − 1 + buffs.coreDamage)`）と同じ枠。b1 の根拠はこの形。
  - コアダメージ▲（`buffs.coreDamage`。C-0075）をスキルのコアにも足すかは根拠が無い。**足さない**で、効果の `assumes` と notes（`unimplemented`）に「コアダメージ▲がスキルのコアに乗るかは未確認」と書く（論点 4）。
  - 敵にコアが無い（`enemy.hasCore` が false）ときは p = 0。
- 効果の欄: `autoAttack` に省略できる `core: true` を足す（`projectileExplosion` と同じ置き方）。`true` の効果だけ、ヒットの時刻の p を的の表から引いてコアの項に入れる。`dot`（ニヒリスターの火傷など。C-0100 でコアは乗らない）には足さない。
- S1 の追加ダメージ（C-0190。コアは乗らない）・ほかの倍率ダメージ（`PER_SHOT_DAMAGE_CORE` = false）は変えない。
- 観測値の指標: `dotHitDamage` に省略できる引数 `core`（`hitDamage` の `core` と同じ意味。1 ヒットがコアに当たったときの値）を足す。b1 の比べに使う。

### 3.2 シューティングスターのコアに当たる割合の行（b2）

- 的の表 `coreHitRate` に、飛ぶ時間の表と同じ形の `autoAttacks` を足す: `coreHitRate.autoAttacks["17:burst"]`（キーは `<resourceId>:<スキルのスロット>`、行は着地点の id・帯・all の順で引く。`flightFrames.autoAttacks` と同じ引き方）。
  - `TargetRateTable` は武器種のキーの表なので、`coreHitRate` を `TargetRateTable & { autoAttacks?: Record<string, TargetRateRow | null> }` に広げる（`FlightFramesTable` の `shots` と `autoAttacks` の分け方に寄せる案もあるが、`coreHitRate` の既存の読み手が多いので、足すだけにする）。
  - **行が無い・null のときは p = 0**（いまのモデルと同じ）。通常攻撃の「表に無ければ手入力の値」と違い、手入力の欄はシューティングスターに無いので、未測定は 0 にして notes の `unimplemented` を残す。
- 1 パス目: ヒットの時刻の着地点から p を引く。`firstPass.ts` が飛ぶ時間の帯を `flights[i].autoAttacks[slot]` で引いているのと同じ時間割り（`frame/landing.ts` の着地点の区間）を使う。

### 3.3 窓の発の行（d）

D1 のときの語彙。D2 なら 3.4 節。

- stat `explosionRange`（ratio。`timed`）を足す（design-anis-star-s2-burst.md 2.4 節の案）。アニス：スターのバーストの「爆発範囲 {03}%▲」{02} 秒を `timed`・`burstUse`・`self`・`explosionRange` で書く。
- 窓の中の発は、的の表の弾の種類のキーを実効の範囲（`explosionRange` × (1 + Σ)）で作って引く（`HomingProjectile:100:<実効の範囲>`）。`coreHitRate` と `hitsPerShot` の両方。
  - **行が無いときは、元の範囲の行（`:750`）を引く**（範囲 500 の行 `HomingProjectile:100` には落とさない。2.4 節）。だから行を足すまでは、stat を書いても数値は変わらない。
  - `frame/landing.ts` の `projectileRowKeyOf` は、いま `character.shot.projectile.explosionRange` で引いている。発ごとのバフの合計から実効の範囲を渡す口を足す。
- 爆発範囲▲は、ほかのキャラの説明文にもある（2.4 節の一覧）。キーを実効の範囲で作るので、同じ語彙で書ける。行はキャラ・弾の種類ごとに実測で足す。

### 3.4 D2 のとき

- フルバースト中の通常攻撃の行を分ける欄（例: 的の表の弾の種類の行に `fullBurst` の副行）。D2 は射撃場の的の当たり方がフルバーストで変わるという、ほかの RL にも効く主張なので、ほかの RL（I-DOLL・フラワーなど）のフルバースト中の発でも確かめてから語彙を決める。**この設計書では語彙を決めない**（読み直しで D2 になったら、別に起案する）。

## 5. 確かめ方（撮影なしで読めるもの）

検証記録は `npm run records:new` で 2 件起こす。どちらも既存の録画の読み直しなので、予測ファイルを commit してから読む（design-reread-prediction.md）。

### 5.1 V-A: シューティングスターのコアの 1 ヒットの値（b1）

- 問い: シューティングスターのコアの 1 ヒットは、boost に (コア倍率 − 1) を足す形か（H-add）、ヒットに コア倍率 を掛ける形か（H-mul）。
- 最小構成: シューティングスターの 1 ヒットの値に効く要素は、確定の結論（C-0204・C-0205・C-0209・C-0211・C-0213）で決まる。録画 162・163・165 は C-0211 などの根拠に使った録画で、1 ヒットの値の比べはこれまでも認められている（観測値 `165-06`〜`165-08`）。未確定の要素はコアの形の 1 つだけ。
- 読む値: これまで注記に読んでいない窓の、フルバースト中のコアの 1 ヒット（会心なし・会心）。H-add と H-mul はフルバースト中で値が分かれる（フルバーストの外では同じ値）。注記に読んだ値（2.1 節）は `predicted.seen` に控えて比べる指標にしない。
- 予測: 3.1 節の実装の後に `npm run records:predict`（H-add は実装、H-mul は手で書く）。
- 外れたときの影響: H-mul なら、3.1 節のコアの項を乗算の形に変える（起案し直す）。

### 5.2 V-B: バーストの窓の発のヒットの形（d）

- 問い: 窓の発のヒットの形（コア 1 ヒット / 胴体 2 ヒット / 胴体 1 ヒット）は、窓（D1）とフルバースト（D2）のどちらで変わるか。
- 読む発: 2.2 節の (i) 録画 164 の窓の発（単騎。ポップアップ）と、(ii) 録画 162・163・165 の窓の中でフルバーストの外の発（ポップアップ）。
- 最小構成: (i) は単騎で、未確定の要素は窓の発の形だけ。(ii) はイサベル（S2 のきっかけが未特定。backlog 6 節）を含むが、(ii) で読むのは発ごとのポップアップの形で、イサベルの S2 は発の当たり方に効かない。(ii) を結論の根拠にしてよいかは論点 5。
- 予測（手で書く）: D1 は (i)・(ii) にコア 1 ヒットの発がある。D2 と D0 は (i)・(ii) ともコア 0（`:750` の行の胴体 1〜2 ヒット）。D2 と D0 は、フルバースト中の発（`162-06` などの前に読んだ値）でだけ分かれる。
- 割合の予測は置かない（行の値は D が決まってから数える）。D1 で (i) の割合が誘導弾・範囲 500 の行（C-0174）と合うかは、予測の表に「比べる値」として C-0174 の行を書いておく（合えば、値を決めるのに使っていない実測での再現になる）。
- 外れたときの影響: D1 なら 3.3 節の語彙を入れ、`:1500` の行を足す（行の値は (i) で数えた割合。1 本なので単独実測。反復は 5.3 節）。D2 なら 3.4 節（別に起案）。

### 5.3 撮影が要るもの（この設計では撮らない）

- **b2 の反復**: 当たる割合を数えた録画は単騎の 164 だけで、ほかの録画 162・163・165 は多人数（イサベルを含む）。選択肢は論点 3。
  - 撮るなら: 録画 164 と同じ条件（アニス：スター単騎・操作・AUTO 射撃 ON・オートバースト ON・射撃場の 3 分モード・BigArms（火）・スペック固定）で 1 本。ポップアップの読める画質。予測は `164-07` の割合（H-b1）と誘導弾・範囲 500 の行（H-b2。C-0174）の 2 つを固定してから撮る。
  - 同じ 1 本で、5.2 節の (i) の反復（D1 のときの `:1500` の行の割合）も数えられる。

## 6. 退化

- 行が無いあいだは、p = 0・元の範囲の行なので、既存の観測値の比べは変わらない（`npm test` の確定の結論の比べで確かめる）。
- `core: true` を書いた効果で、`computeBurstHit` の boost に p × (コア倍率 − 1) が足されるのは、行がある的だけ。的の表の無い敵（`range-bigarms` 以外）は p = 0。

## 7. 論点

1. **3 節の語彙を承認するか**: 推奨は、3.1（コアの項・`core: true`・指標の `core`）と 3.2（`coreHitRate.autoAttacks`。行は足さない）を承認し、3.3（`explosionRange`）は V-B で D1 になってから入れる。代案は、V-A・V-B の結果が出るまで語彙を何も足さない（V-A の予測は手で書く）。
2. **C-0212 を b1・b2 に分けるか**: 推奨は分ける（4 節。b1 は新しい結論で、V-A で確定を目指す。C-0212 は b2 に絞り仮説のまま）。代案は C-0212 のまま、割合が測れるまで 1 件で持つ。
3. **b2（当たる割合）の反復をどう取るか**: 推奨は (a) 単騎で 1 本撮る（5.3 節。最小構成で、5.2 節の (i) の反復も兼ねる）。代案は (b) 録画 162・163・165 のシューティングスターを距離帯ごとに数え直す（撮影なし。ただしイサベルの S2 が未確定で、AGENTS.md の「機構が確定したキャラだけで組めば」に当たらない。オーナーが「シューティングスターの当たり方に効かない」と認めるなら使える）。
4. **コアダメージ▲をスキルのコアに足すか**: 推奨は足さない（根拠が無い。notes に未確認と書く）。アニス：スターと同じ編成でコアダメージ▲を配るキャラ（アスカ S2。灼熱のみ。C-0075）がいるときに差が出る。確かめるなら別の検証（アスカ + アニス：スター）。
5. **V-B の (ii)（イサベルを含む録画の、窓の中でフルバーストの外の発）を結論の根拠にしてよいか**: 推奨は、根拠にしてよい（読むのは発ごとのポップアップの形で、イサベルの S2 のきっかけは発の当たり方に効かない。C-0211 などの 1 ヒットの値の根拠にも同じ録画を使っている）。代案は (i) だけで D を決め、(ii) は推移の記録にとどめる（D1 と D2 は (i) だけでも分かれる。(ii) は反復の材料）。
