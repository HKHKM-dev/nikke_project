## 1. 撮影（承認を求める）

V-0430「次に撮るもの」の撮影 A・B。最小構成（単騎・撃たない）で、既存の録画で足りない所（最初から最後まで撃たない・挑発を持たないキャラ・5 回目まで）を埋める。

- **B**: 同じキャラ・同じ設定で、180 秒、的の上の空に向けて撃ち続ける（出ているが的に当てない）。2 本。

A で「撃たない 3 分で縮むか」と「1 回目の 18.9 秒が揃うか」を確かめ、B で「操作キャラが隠れているか」と「的が撃たれるか」を分ける（見分け方は V-0430）。B で SR が空を撃ちにくければ、挑発・デコイ・被弾時の効果を持たない AR・SMG・MG の単騎に替え、A もそのキャラで 1 本撮る。

## 3. モデルに縮みを入れるか（判断を求める）

いまのモデルは 1 組の代表値（1 回目 32.35 秒・間隔 36.34・39.66・36.34・33.17 秒）で、縮みを持たない。代表値は 5 本の中央値（V-0009）で、間隔は縮まない形、1 回目は段の最も遅いものに近い。

- **案 A（変えない・注記を足す）**: 時刻は代表値のまま。web の「扱わないもの」（`NotesSummary.tsx` の MODEL_WIDE）と README に、「的のジャンプの 1 回目と 2→3・3→4 回目は、実際は録画ごとに約 3.6〜4.6 秒の段で早まることがある。モデルは早まらない代表値で、早まりは未実装（C-0533・C-0547・C-0548）」と書く。数値の根拠は変わらず、利用者は未実装だと分かる。
- **案 B（利用者が段を選べる）**: 敵の欄のジャンプのチェックに、1 回目と 2→3・3→4 回目の段（何段早まるか）を選ぶ入力を足す。既定は案 A の代表値。段の幅（約 3.6・4.6 秒）は C-0548 が仮説なので、入れるなら「仮説」と表示する。録画との照合には、すでに `setup.jumpWindows`（V-0086）で録画ごとの窓を渡せる。
- **案 C（期待値で入れる）**: 縮みの起きやすさで重みを付けた平均の時刻にする。起きやすさが何で決まるか分からず、録画の偏り（撃たない多人数が多い）がそのまま入るので、根拠のない係数になる。**採らない**。
- **推奨**: いまは案 A。原因が撮影で分かり、利用者の操作（隠れる・撃つ）で決まると言えれば、そのときに条件と結び付けて入れる（案 B を条件つきにした形）。原因が分からないまま案 B を入れると、利用者が段を選ぶ手がかりが無い。

案 A の作業（承認の後、撮影を待たずに同じブランチで行う）: `NotesSummary.tsx`・README の注記、`enemies.json` の `range-3min-jump` の `source` に縮みの結論 ID を足す。数値は変えない。
