# V-0164: バーストの CT が明けてから発動までの遅れ

- 問い: 自動バーストで CT が律速のとき、CT が 0 になってから発動まで何フレームか。一定か、何で変わるか（段・キャラ・録画）
- 話題: バーストの段階とフルバースト
- 日付: 2026-10-05
- 録画: `018`〜`021`、`042`、`063`
- 結論: `C-0258`
- 状態: 調査中
- 派生元: `V-0021`

## 条件

- モデル（`burst/controller.ts`）: 段の候補は CT が明けたフレーム（`cooldownEnd[i] <= frame`）から撃てる。満タン → I・I → II・II → III の段は各 29f（C-0073）で、段の終わりより後に CT が明けたときは、CT が明けたフレームに撃つ（遅れ 0）。CT はゲーム内の時計で数える（`gameSecondsToFrames`。40 秒 = 2,352f・20 秒 = 1,176f）。フルバーストの入りの止まり（C-0069）のあいだは CT も進まない（C-0070）。
- これまでに見えていたもの（どれも結論にしていない）:
  - V-0017 で、`042-04` を読んだときの 042 の 2・3 回目のフラワー（I）と 3 回目のアリス（III）で、CT が 0 になってから発動まで 4〜7f（V-0021 の「段の長さ」の節）。V-0017 の「CT が律速のフルバーストの間隔」では 2〜7f と書いた。発動のフレームは次の段のタイマーの 10.00 の位置か、欄に「40」が出たフレームで、取り方がそろっていない。
  - CT 40 秒の 7 本（018〜021・038・040・047）で、I の発動の間隔が 2,377〜2,379f（V-0017。止まり 1 回分を引くと、CT の 0 から発動まで数 f）。
  - `163-02`（CT 40 秒のデルタ・イサベルで決まるフルバーストの入りの間隔）は、モデル（遅れ 0）より 7〜9f 長い（`plan/residuals.md`）。
- この検証を起こす前に、042 の 2 回目のフラワーの前後（f2496〜2519）だけを 1 フレームずつ並べて、欄が読めることを確かめた（CT の残り 0.01 → 顔が明るくなる → 新しい CT「20」が出る → II のアイコン、の順に替わる）。この 1 回は予測に引きずられている。
- 右のバースト欄（画面の x 1740〜1920・y 420〜570）は、ゲージが満タンで I を待つあいだと、チェーン中に次の段を待つあいだ、その段のキャラの顔の上に CT の残り秒を出す（1 秒以上は四捨五入の整数、1 秒未満は 1/100 秒。1 フレーム約 0.017 秒で減る。V-0017）。
- 撃つのは自動バースト（どの録画も `autoBurst` が true か、V-0017・V-0021 で自動バーストとして読んだもの）。手動バーストは人の反応の遅れになるので、この検証では扱わない。
- 編成（どれも CT を縮めるスキルが無い。`data/skills/` で `cooldownReduction` を持つのはアニス：スター・ニヒリスター・リター・ラム）:
  - 018〜021: エーテル（I・CT 40 秒）・デルタ（II・40 秒）・III（ラピ・ノワール・マナ・クイーン（真）、40 秒）。2 回目からのフルバーストは、I の CT が律速（満タンで I の CT を待つ）。
  - 042: フラワー（I・20 秒）・アドミ（II・20 秒）・アリス（III・40 秒）・サン（III・40 秒）。I と、III を交互に撃つアリス・サンの CT が律速になりうる。
  - 063: フラワー（I・20 秒）・デルタ（II・40 秒）・アスカ（III・40 秒）。I は 20 秒ごとに撃てるが II のデルタは 40 秒なので、チェーン中に II がデルタの CT を待つ回がある（チェーン中の段の CT 待ち）。

## 予測（撮る前に書く）

既存の録画の読み直し。比べる値（CT の 0 と発動のフレーム）は、上の 042 の 1 回のほかは読む前に書いた。

### 問い 1: CT が 0 になってから発動までの遅れ d

| 仮説                                                                                                         | 見えるはずのもの                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| D0: 遅れは無い（いまのモデル）                                                                               | CT の 0 から新しい CT の秒が出るまで 0〜1f                                                                                                   |
| D1: 一定の遅れ（段・キャラ・録画によらない）                                                                 | どの回も同じ値（4〜7f のどこか）に ±1f でそろう                                                                                              |
| D2: 自動バーストの判定が一定の周期で回る（例えばゲーム内の 0.1 秒 ≈ 6f ごと）                                | d が 0〜周期の範囲で回ごとにばらつき、ほぼ一様に散る。同じ録画の発動のフレームを（止まりを除いた）ゲーム内の時刻にすると、周期の格子にそろう |
| D3: 遅れは段（満タンで I を待つ回・チェーン中に II・III を待つ回）か、撃つキャラ（武器種・射撃の状態）で違う | 段ごと・キャラごとに違う値にまとまる                                                                                                         |

見込み: D1 か D2。これまでの 4〜7f・2〜7f の幅は、発動のフレームの取り方がそろっていなかった分（±1〜2f）を含むので、取り方をそろえれば D1 の幅に収まるかもしれない。

- 予測ファイルの値（records/predictions/V-0164.json）は D0（いまのモデル）の、019 のフルバーストの入りの間隔。D1 なら、2 回目からの間隔は D0 の値 + d（I の CT が律速の回だけ）。D2 なら + 回ごとの d。D3 は段・キャラごとの値で同じように足す。019 の間隔は V-0017 で「2,377〜2,379f」と散文で見ているので、予測との比べは後付けに近い（d の直接の読みが本体）。
- 外れたときの影響: d があると、CT が律速の編成ではフルバーストの周期が 1 回あたり d だけ延びる。CT 40 秒で 180 秒に 4〜5 回なら、終わりのほうのフルバーストの入りが 4d（20f 前後）遅れる。フルバーストの回数は、戦闘の終わりの近くで入りがまたぐときだけ変わる。与ダメージへの効きは小さい（窓が 1 回あたり d ずれるだけ）が、窓の入りの時刻と比べる観測値（`163-02`・`162-01`・`165-12` など）の残差が動く。

### 問い 2: 段の終わりと CT の 0 がほぼ重なるとき

018〜021 の 2 回目からのフルバーストでは、II（デルタ）と III の CT は、I の 29f 後・58f 後に明ける（前の回も 29f ずつ空けて撃ったので）。I が d1 遅れて撃つと、II の段の終わりは II の CT の 0 から d1 後になる。

| 仮説                                                      | 見えるはずのもの                                           |
| --------------------------------------------------------- | ---------------------------------------------------------- |
| E1: 発動 = max(段の終わり, CT の 0 + d)                   | II・III の段は 29f か、II の d2 が d1 より長い回だけ延びる |
| E2: CT が段の終わりより前に明けていれば、段の終わりに撃つ | II・III の段はいつも 29f                                   |

D1（一定の d）なら E1 と E2 は同じ見え方になる（d1 = d2）。D2 なら E1 では段が 29〜35f にばらつく。

## 読み方

1. 右のバースト欄を切り出し（1740,420 から 180×150）、CT の残り秒が 1 秒未満で出ている区間の前後を、フレーム番号を付けて 1 フレームずつ並べる（ffmpeg の select・crop・drawtext・tile）。CT の秒が出ているのは、満タンで I の CT を待つ回か、チェーン中に次の段の CT を待つ回（どちらも CT が律速）。
2. CT の 0: 最後に出た残り秒 u（1/100 秒）とそのフレーム g から、g + u ÷ 0.017。
3. 発動: 欄に新しい CT の秒（「40」「20」）が出た最初のフレーム。CT は発動から始まるので、発動の印として段・キャラによらずそろう（V-0017 の III と同じ取り方）。合わせて、顔が明るくなったフレーム（CT の秒が消えたフレーム）と、次の段のアイコンに替わったフレームも控える。
4. d = 3 − 2。回ごとに、録画・何回目のフルバースト・段・キャラ・d を並べる。
5. 問い 2: 018〜021 の 2 回目からのフルバーストで、I・II・III の発動（新しい CT の秒が出たフレーム）の間隔を並べる。
6. 019 のフルバーストの入り（III のタイマーが 00.00 になったフレーム。`019-11` と同じ取り方）の間隔の最初の 3 つを、予測ファイルの指標と比べる観測値にする。
7. 読んだ値は観測値にする（`source` に `V-0164`）。

### 読み方を変えたところ

- 読み方の 3 は「新しい CT の秒が出たフレームを発動とする（CT は発動から始まる）」とした。読んでみると、CT の 0 → 新しい CT の秒は 2.8〜4.4f でそろうが、CT の 0 どうしの間隔（次の回の CT がいつ明けるか）と合わない（下）。そこで、CT が走り出したフレームを、表示ではなく **CT の 0 どうしの間隔**から出した: 間隔 − あいだの止まり（V-0017 の位相のずれ。`018-05`・`019-05`・`021-03`）− その録画の時計の傾きで数えた 40 秒 = CT が 0 になってから CT がまた走り出すまで（`018-19`・`019-14`・`021-19`）。CT の 0 は欄の 1/100 秒の表示から外挿するので、表示の遅れがあっても両端で同じだけずれ、間隔には残らない。

### 問い 1: CT の 0 から発動まで

- 欄の表示で数えた値（CT の 0 → 新しい CT の秒）は、I で 2.8〜4.4f（11 回）、チェーン中の II・III で 3.4・4.4f（`018-18`・`019-12`・`019-13`・`021-18`）。段（満タンで待つ I・チェーン中の II・III）でもキャラでも差は無い。並びはどの回も「CT の 0 → 次のフレームに顔が明るくなる → 3〜4f 後に新しい CT の秒 → その 3f 後に次の段のアイコン」。
- CT の 0 どうしの間隔から出した、CT が 0 になってから CT がまた走り出すまでは −0.4〜2.0f（8 個。平均約 0.8f。録画ごとの平均 0.3・1.0・1.1f）。新しい CT の秒が出るフレームで CT が走り出すなら、ここは 2.8〜4.4f になるはずだが、そうならない。
- ゲージが律速の I でも、新しい CT の秒 → 次の段のアイコンは 3f（`063-11`）で、CT が律速の回と同じ並び。
- まとめると、本当の発動（CT の再開）は CT の 0 から 1f ほどで、欄の新しい CT の秒はその約 3f 後、次の段のアイコンとタイマーは約 6f 後に出る。V-0017・V-0021 の「4〜7f」「2〜7f」は、CT の 0（遅れの無い表示）と、発動の印（次の段のタイマー・アイコン・CT の秒。遅れて出る表示）を比べた差だった。

### 予測との比べ（019 のフルバーストの入りの間隔）

- `019-15` は D0（いまのモデル）より 3〜4f 長い（許容内）。この差は d ではなく、おもに時計と止まりの違いで説明できる: モデルは 40 秒を 0.017 秒/f で切り捨てて 2,352f・止まりを 22f とするが、019 の時計の傾き（58.845 f/秒）では 40 秒 = 2,353.8f、止まりは 22.6〜22.8f（`019-05`）。残りの約 1f が上の「CT の 0 から 1f ほど」。差の 3〜4f を d として足すと、時計と止まりの違いを係数で埋めることになる。

### 問い 2: 段の終わりと CT の 0 が重なるとき

- 019 の 2 回目では、I・II・III の 3 つとも CT が律速で、どれも CT の 0 から 3.4〜4.4f で新しい CT の秒が出た（I → II は 28f、II → III は 30f。`019-13`）。d が 1f 以内でそろうので、E1 と E2 は見分けられない（どちらでもモデルの振る舞いは同じ）。

## 分かったこと・分からないこと

- **D1・D2・D3 は外れ**: CT が律速のとき、発動は CT の 0 から 1f ほど（0〜2f）で、4〜7f の遅れは無い。4〜7f は、発動を欄の表示（遅れて出る）で数えたための差 → C-0258（仮説・単独実測。録画 018〜021 は最小構成の警告がある）。
- **D0 は 1f の幅で当たり**: いまのモデル（CT が明けたフレームに撃つ）との差は 1f 以内。モデルの CT の切り捨て（40 秒 = 2,352.94 → 2,352f）を、「CT が明けた後の最初のフレームに撃つ」（切り上げ）にすると、平均約 0.8f にさらに近づくが、時計の傾きの録画ごとの違い（下）より小さい。
- **段の長さとの関係**: V-0021 の段の長さ（C-0073）のうち I → II・II → III は、同じ種類の印（次の段のアイコン・タイマー）どうしの間隔なので、表示の遅れは打ち消し合う。満タン → I（BURST バーが消えてから II のアイコンまで）は、バーが消える表示の遅れと、アイコンの遅れ（本当の発動の約 6f 後）が違えば、本当の段の長さとずれる。
- 分からないこと:
  - BURST バーが消える表示が、本当の満タンからどれだけ遅れるか（満タン → I の本当の長さ）。
  - 録画ごとの時計の傾き（V-0017 で当てはめた値。`018-05` などの注記）が、C-0048 の範囲とモデル（0.017 秒/f）より大きい録画があること。`019-15` の残差はこれと止まりの長さでほぼ説明できる。`163-02`（7〜9f）も同じ見込みだが、163 の時計の傾きと止まりは読んでいない。
  - 手動バーストの遅れ（人の反応。モデルは自動バーストだけ）。
