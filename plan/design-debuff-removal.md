## 1. 分かっていること

- ココアのバーストのデバフ解除は、ほろ酔いを外し、その間の▲も消える。次の 1 段階突入で 1 スタックから付き直す（C-0976。V-0683 の撮影 D）。撮影 D ではほろ酔いが 1 スタックの時しか外していない。
- 分からないこと:
  - **Q1**: 「1 個」は、ほろ酔いの全部のスタックを外すのか、1 スタックだけ外すのか。→ 全部（V-0684 の録画 0969・0970。クレアのバーストが 3 スタックと 2 スタックのほろ酔いを外し、次の突入まで付かない）。
  - **Q2**: ココアの S1（ランダムに 2 機・1 個）でも、ほろ酔いが外れるか。→ 外れる（V-0684 の録画 0968。S1 の時にほろ酔いがあった 4 回とも外れた）。
  - **Q3**: 二日酔い（気絶）はデバフか（解除で気絶が明けるか）。
  - **Q4**: 味方に付く時間の▼（プリバティの S1 の最大装弾数▼など、名前の付いた状態でない効果）はデバフ解除で外れるか。

## 2. 語彙の案

### 2.0 いまの置き場所の誤り（論点 0）

- 課題 2-57 の PR で、ココアの S1・バーストの notes を「未対応」にした。ココアは多くの録画に入っているので、マスト：RM のいない編成（デバフ解除が何も外さない）でも、最小構成の検査がこの notes を効きうる未確定の要素に数え、確定の結論の約 80 件の組に警告が出ている（plan/minimal.md の警告のある組が 235 → 611）。警告のある録画からは、新しい結論を確定にできない。
- 案: 間接の notes の経路（[design-indirect-notes.md](design-indirect-notes.md) 1.3 節）に `debuff`（デバフ）を足す。ココアのデバフ解除の notes は種類を間接（経路 `debuff`）にし、ほろ酔いの付与（マスト：RM の S1 の effects[0]）に読む側の印 `reads: ["debuff"]` を付ける。最小構成の検査は、マスト：RM とココアが同じ編成にいる録画でだけ、この notes を効きうるとみる。計算は変えない。
- 2.2 節の効果を入れた後は、notes が効果に替わる。効果の検査も、デバフの印の付いた状態を付ける味方がいない編成では効かないとみる形にする（静的な判定）。
- この直しは、撮影を待たずに先に 1 つの PR にする（6 節の論点 0）。

### 2.1 状態の目録のデバフの印（論点 1）

- `skills/states.ts` の `NamedStateInfo` に `debuff?: true` を足す。味方の状態のうち、デバフ解除で外れると録画で確かめたものだけに付ける。今は `drunken`（C-0976）だけ。
- `hangover`（Q3）と、名前の付いた状態でない時間の▼（Q4）は印を付けない（外さない）。定義の notes に未実装と書く。

### 2.2 効果 `removeDebuff`（論点 2）

- 形: `{ kind: 'removeDebuff', trigger, target, count }`。`count` は説明文の「N 個」（値の参照）。
- 発火のフレームで、対象の味方ごとに、印の付いた状態を `count` 個外す。1 個は状態 1 つで、スタックごと外す（Q1）。印の付いた状態が `count` より多く付いているときの選び方は、今の使い手（マスト：RM はほろ酔いと二日酔いを同時に持たない）では起きないので決めず、起きたら注記を出す。
- 外した状態の間だけ効く効果（ほろ酔いの S1 の▲・命中率▼）は、`removeState` で外したときと同じく、そのフレームで止まる。
- 外すフレームちょうどに同じ状態の付与があると、その件の列は閉じない（前から付いていた件も残り、スタックが 1 つ増える）。`removeState` の「同じフレームの付与が勝つ」（[design-skill-stage1.md](design-skill-stage1.md) 論点の推奨）と同じ規則で、デバフ解除には実機の根拠が無く、規則をそろえただけ。撮るなら、解除の効くフレーム（ココアの S1 の発動の 3f 後・バーストの効果のフレーム）とほろ酔いの付与（1 段階突入）が同じフレームに来た回を録画から拾い、その後のマスト：RM の格子で、前のスタックごと残る（付与が勝つ）・付いたばかりの 1 スタックだけ残る・何も残らない、のどれかを見る（同じフレームは狙って作れない）。
- 対象と外すデバフを選ぶ候補には、この解除で実際に外れる件だけを入れる（2026-11-11 のデイリーレビューの指摘）。効くフレームに始まりのある件の列（上の付与が勝つ規則で外れない）と、同じフレームに別の解除・`removeState` が閉じた件の列（もう外れている）は、候補にしない。候補に入れると、外れない件で `debuffedRandom` の N 機や `count` 個の枠を使い、前から付いていたほかのデバフが残り、要らない注記が出る。実機の選び方の根拠は無く、上の付与が勝つ規則（これも根拠は無い）とモデルの中の筋をそろえるだけの直し。同じフレームの付与は段 1.5・段 2・スタック量の増加でも付くので、対象はそのフレームのすべての段の付与を登録した後に選ぶ（`skills/holders.ts` の `register`。閉じるのは次のフレームなので、同じフレームの判定には効かない）。
- 対象:
  - `allies`（味方全体。バースト・クラストの S2）。
  - `debuffedRandom`（デバフのかかった味方からランダムに N 機。ココアの S1）。デバフのかかった味方が N 機以下なら全員で、決まる。N 機より多いときはランダムで、モデルでは決めず注記を出す（期待値にできない）。

### 2.3 発火の時刻（論点 3）

- バーストのデバフ解除は、ほかのバーストの効果と同じ発火のフレーム（バーストの効果の遅れ）に置く。撮影 D の 12 回では、ほろ酔いの最後のヒットが I → II の替わり目の 2〜20f 後で、I-DOLL・フラワーのバーストのヒット（替わり目の 14f 後。C-0220）と同じくらいの所。
- ココアの S1 は、遮蔽物 HP 回復と同じ時刻（CT ごと・発動の 3f 後。C-0822）に置く。0968 の 4 回は、この時刻と合う。
- クレアのバーストでは、ほろ酔いが替わり目の ±2f で外れ（0969・0970）、ココアのバースト（2〜20f 後）より早かった。キャラごとのバーストの効果の時刻は、モデルではバーストの発動の効果のフレーム（`burst/schedule.ts` の `effectFrameOf`）で決まる。ココアの定義に入れるときに、モデルの発火のフレームが 0968 と撮影 D の外れた時刻に合うかを確かめる（クレアは定義が無いので、定義を書くときに）。

## 3. 撮影（Q1・Q2）

- 最小構成: I-DOLL・フラワー（304。I）・ココア（311。I）・マスト：RM（354。II・操作）。III を置かない（フルバーストが無いので、ほろ酔いは 1 段階突入で増えるだけ）。ココアのほかの効果はダメージに効かない（C-0977）。I-DOLL・フラワーは機構が確定したキャラ。
- オートバーストは同じ段に候補が 2 人いると左の枠を撃たせる（C-0663）ので、オートではココアが撃つ時を選べない。オートバースト OFF にし、I の段で押すキャラを手で選ぶ。I の段は候補が出るまで時間制限なく待ち、II の段は誰も押さなければ 10 秒で時間切れしてゲージ 0 に戻る（`burst/controller.ts`）。
- 押す順: 1・2 回目の I の段はフラワー、3 回目はココア（ほろ酔い 3 スタック）、4 回目はフラワー、5 回目はココア。II の段は押さない。
- 見え方（マスト：RM の 1 ヒットの格子。V-0683 の「読み方」）:
  - Q1: 3 回目のココアのバーストの後、ほろ酔いの格子（攻撃力の段 1.3505）が消えれば全部、残れば 1 スタック（残りのスタック数は、4・5 回目の突入とコア命中率で確かめる）。
  - Q2: 1・2 回目のフラワーの後の長いほろ酔いの区間（それぞれ 30 秒ほど）に、ココアの S1（約 15 秒ごと。左のスキルの帯）が 2 回ずつ来る。その時にほろ酔いの格子が消えれば、S1 でも外れる。
- 録画 0968（1 本）では S1 でもほろ酔いが外れ（Q2）、2 スタック以上にならなかったので、Q1 は見分けられなかった。
- 2 回目の撮影は、ココアを、CT ごとの解除を持たない解除役のクレア（842。RL・I・CT 40 秒）に替える。クレアの S1（フルチャージ 3 回の命中で、最終攻撃力の高い味方 2 機の回復）と S2（バーストの使用で味方全体にバリア）は、マスト：RM の与ダメージに効かない（マスト：RM に回復・バリアを読む効果は無い）。定義は無いが、観測量（ほろ酔いの格子の有無）に効く未確定の要素はデバフ解除だけ。ソラ（S2 がパーツの破壊のきっかけ）・ミカ：スノーバディ（バーストの攻撃力▲・S1 の最大装弾数▲）より、効く要素が少ない。押す順は 1 回目と同じ（3・5 回目をクレア）。
- 検証記録は V-0684（撮影の依頼は「次に撮るもの」）。

## 6. 論点

0. **いまの notes の置き場所**（2.0 節）。推奨: 経路 `debuff` を足し、ココアの notes を間接に、ほろ酔いの付与に `reads` を付ける。撮影を待たずに先に PR にする。
1. **デバフの印**（2.1 節）。推奨: 状態の目録に `debuff` の印を足し、録画で確かめた状態（今は `drunken`）だけに付ける。二日酔いと時間の▼は外さない（未実装と注記）。決定: 推奨どおり。
2. **効果の形**（2.2 節）。推奨: `removeDebuff`（trigger・target・count）。1 個は状態 1 つをスタックごと（Q1）。対象は `allies` と `debuffedRandom`。決定: 推奨どおり。
3. **発火の時刻**（2.3 節）。推奨: バーストはほかのバーストの効果と同じ発火のフレーム、S1 は遮蔽物 HP 回復と同じ時刻。決定: 推奨どおり。ココアのバーストの効果の時刻は、バーストの効果の遅れの表に足した（I の替わり目の 20f 後。C-0980）。
4. **撮影**（3 節）。推奨: フラワー・ココア・マスト：RM（操作）の 3 人、オートバースト OFF で I の段を手で押す、2 本。→ 1 本撮った（録画 0968）。Q1 のため、ココアをクレアに替えて 2 本撮った（録画 0969・0970）。
5. **比べる指標**（7.3 節）。推奨: `eventFrames` に出来事 `stateEnd`・引数 `modulo`・別の枠の発動の基準を足す。C-0980 は `burstEffectDelay`。決定: 推奨どおり。
6. **クレアの定義**（7.4 節）。推奨: 書く（デバフ解除のほかは根拠なし）。決定: 推奨どおり。
7. **撮影**（7.2 節）。推奨: A・B・C（オートバースト ON）を各 2 本。C-0979 の 3 スタックの部分は別の結論に分ける。決定: 推奨どおり。

## 7. 結論を確定に上げる（論点 5〜7。V-0686）

### 7.1 いまの足りないもの

- C-0978（ココアの S1 でも外れる）・C-0979（1 個はスタックごと外す）・C-0980（ココアのバーストの効果は I の替わり目の 20f 後）は、どれも仮説。どれも、モデルと比べた観測値が無い（観測値は記録だけ）。
- 0968〜0970 はオートバースト OFF で、I の段で押すキャラを手で選び、II を押さなかった。モデルの比べる設定（`manualBursts`）は、手で撃ったチェーンの始まりのフレームしか持たず、撃つキャラは左の候補、II はオートのまま。そのため、モデルで再現できない。
- C-0979 はクレアの録画だけが根拠で、クレアには定義が無い。そのため、モデルはクレアの解除を出さない。
- C-0980 は 0968 で値を決め、0964・0965 も見て決めた。再現には別の録画が要る。

### 7.2 撮影（論点 7）

オートバースト ON の 3 つの編成にする。どれもモデルがチェーンを再現できる。オートは同じ段の候補のうち左の枠を撃たせる（C-0663）。

- 撮影 C のクレアの S1（フルチャージの命中で、攻撃力の高い味方 2 機の回復）と S2（バーストの使用で味方全体にバリア）は、マスト：RM の与ダメージに効かない（回復を受けた時・バリアを読む効果が無い。最小構成の検査も外す）。

### 7.3 比べる指標（論点 5）

- 枠の出来事の時刻の指標 `eventFrames`（新しい時刻の比べは指標を足さず、この引数で書く）に、出来事 `stateEnd`（引数 `state`。その枠の状態の件の終わり）を足す。基準は次の 2 つ。
  - C-0978（撮影 B）: 基準 `start` に、引数 `modulo`（割った余り。`eventTallies` と同じ）を足し、883 で割った余りで比べる（S1 の周期。C-0822）。モデルは S1 の発動の 4f 後（3f 後に外し、次のフレームから無い）。録画の動画のフレームはゲーム内の時刻より少し長いので、許容は ±12f にする。S1 で外れないなら、終わりが 1 つも無い。
  - C-0979（撮影 C）: 基準 `activation:<n>` に、別の枠（引数 `from`）の発動を取れるようにし、クレアの n 回目の発動から次の発動までのほろ酔いの終わり。1 スタックだけ外すなら、終わりは無い。
- C-0980（撮影 A）は、いまの指標 `burstEffectDelay`（効果の発火 − 発動の印）で比べる。録画の値は、ほろ酔いの最後のヒットと、無い最初のヒットの間（S1 と重ならない回）。許容は ±2f。

### 7.4 クレアの定義（論点 6）

- クレア（842）の定義を書く。バーストのデバフ効果解除は `removeDebuff`（味方全体・1 個。C-0979）、回復・バリアは語彙のある効果か間接の notes（根拠なし）。バーストの効果の遅れは撮影 C で読む（0969・0970 では替わり目の ±2f。表に無いときの既定に近い）。
- 定義は、この検証の PR に入れる（skills-guide.md の 1 体 1 PR の形。結論はデバフ解除のほかは根拠なし）。

### 7.5 C-0979 の分け方（論点 7）

- C-0979 は 2・3 スタックを含む。撮影 C で再現できるのは 2 スタックだけ。3 スタックの部分（0969・0970 の 3 回目）は、別の結論（仮説）に分ける（verification-guide.md 2.2 節の「結論の一部にだけ再現が無いとき」）。
