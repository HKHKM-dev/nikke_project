## 2. 生成物との一致を見るテストを外す

**いま**

- 生成物は PR に入れず、CI が作り直す（[design-pr-conflicts.md](design-pr-conflicts.md) 3.1 節）。CI（`.github/workflows/ci.yml`）は `npm test` の前に `npm run records:minimal` で生成物を作り直す。`pr:prep` も確認の前に作り直す。
- それでも `npm test` には、コミットしてある生成物が作り直したものと一致するかを見るテストが 10 件残っている（`support.test.ts`・`catalog.test.ts`・`backlog.test.ts`・`skills.test.ts`・`relevance.test.ts` の 2 件（`plan/minimal.md` と感度の新しさ）・`recordings.test.ts`・`verifications.test.ts`・`observations.test.ts` の 2 件（`residuals.md`・`claims.md`））。
- CI と `pr:prep` では、作り直した直後に見るので、この 10 件は落ちようがない（design-pr-conflicts.md 3.1 節も「作り直した後のものを見るので通る」と書いている）。
- 落ちるのは手元だけで、どれも生成物が古いだけ:
  - `pr:prep` は push の前に生成物を main の版に戻すので、その後に手元で `npm test` を回すと落ちる（`pr:prep` が最後に「手元で npm test を回すなら npm run records:minimal で作り直す」と案内している）。
  - マージの後、CI が「生成物を作り直す（CI）」を commit するまでの数分〜数十分に main から始めたセッション。2026-11-12 のデイリーレビューは、この 10 件の落ちを調べて「CI がまだ作り直していないため」と見分けるのに手間を使った（`scratch/daily-review-2026-11-12.md`）。
- [AGENTS.md](../AGENTS.md)「文書の書き方」の「生成」の項は、スキル定義などを変えたら `records:minimal` を回すよう書き、「回し忘れは手元の `npm test` が落とす」としている。今は `pr:prep` と CI が作り直すので、回し忘れても PR には何も起きない。

**案**

- 10 件の一致の比べを外す。`verifications.test.ts` の「検査を通り、一覧と一致する」は、検査の部分だけ残す。検査（棄却の結論を指す `claims`・録画に無い要素を指す印（`marks.test.ts`）など）のテストはそのまま。
- [AGENTS.md](../AGENTS.md) の「生成」の項を「手で書かない。`pr:prep` と CI が作り直す。中身を手元で見たいときは `npm run records:minimal`（`records:check` も回る）」にする。`pr:prep` の最後の案内の行も消す。
- [verification-guide.md](verification-guide.md) の `records:check` を回す指示（5・7 節）は、一覧を見たいときの道具として残す（閉じるときの `records:close` は最小構成の警告を見るのに作り直しが要るので、今のまま）。

**効果**: 手元の `npm test` が生成物の古さで落ちなくなり、`pr:prep` の後とマージの直後のセッションで、落ちの見分けと作り直しが要らなくなる。テストは約 2〜3 秒速くなる（小さい）。

**気をつけること**

- 生成の関数が投げる（壊れた）ときは、CI と `pr:prep` の `records:minimal` が落ちるので、引き続き見つかる。
- 一致の比べが見ていたもののうち、テストの中の描画と、スクリプトが整形した後の出力が同じか（整形の安定）は見なくなる。整形が揺れても、生成物の差分が CI の commit に出るだけで、手で直すものは無い。
