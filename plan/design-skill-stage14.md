### 2.1 チャージ中の周期のきっかけ（PR 2）

- 説明文（S1 の 1〜3 行目）: 「チャージ中の時、値 01（0.2）秒ごとに」。ロックオン・オートファイア準備・受けるダメージ▲の 3 行が同じきっかけ。
- **語彙（論点 3）**: きっかけ `{ chargeTick: { everySeconds } }` を足す。1 パス目の射撃の列で、チャージ武器の溜めの区間（溜め始めから撃つまで）の中で、溜め始めから k × 間隔（k = 1, 2, …）に発火する。溜めの区間は、射撃の列（`ShotLog`）に溜め始めのフレームを持たせて作る（発と発の間はチャージと解放の和。`frame/firing.ts` の `chargeShotIntervalFrames`）。部分チャージの発（Stage 22-B）の溜めでも発火する。リロード・ハイドで溜めが切れたら、次の溜め始めから数え直す。
  - 書けるのは、状態の付与と timed（敵の受けるダメージ▲）。
  - 間隔は読む。0.2 秒は 12 フレームで割り切れるが、段 13 のチェーンの攻撃（端数を持ち越さず 15 フレームおき）と tick（59.25 ティック）の例があるので、`0328-02` と撮影 A の溜めの列で、ゲーム内のティックに直して決める（`timer.ts --mode ticks`）。
- 0328 の読み（`0328-02`）: 部分チャージの溜めの始めと終わりは読んである。溜めの途中でロックオンが付き、長い溜めでオートファイア準備が 3〜4 まで増えた（C-0426 の根拠）。

- 説明文（S1 の 1 行目）: 「ロックオン状態ではない敵の中で照準線に最も近い対象に「ロックオン」機能：セブンスドワーフの攻撃対象を指定する。最大ロックオン対象数：値 03（5）機。解除条件：通常攻撃時とハイド時」。

1. **段 14 の対象**（0.3 節）

3. **チャージ中の周期の書き方**（2.1 節）
   - 推奨: きっかけ `{ chargeTick: { everySeconds } }` を足し、射撃の列の溜めの区間から発火させる。状態の付与（装填数）と timed（受けるダメージ▲）が同じきっかけで書け、ハイド・リロードで切れた溜めも数え直せる。
   - 代わりの案: きっかけを足さず、撃った時に装填数を溜めの秒から算出し（`min(上限, ⌊溜めの秒 ÷ 0.2⌋)`）、受けるダメージ▲は溜め始めの 0.2 秒後からの timed にする。語彙は小さいが、溜めの途中の▲の付き直しと、ハイドの後の数え直しを別に書くことになる。
4. **ロックオンの書き方**（2.3 節）
   - 推奨: 名前を持たず `assumes` に書く（敵 1 体では、最初の周期からその敵がロックオン状態）。前提の中で値が変わらず、使い手もスノーホワイト：ヘビーアームズだけ。
   - 代わりの案: 敵の名前の付いた状態 `lockOn`（付与は `{ chargeTick }`、解除は通常攻撃とハイド）にし、受けるダメージ▲を条件 `enemyState` で書く。敵が複数の時の拡張には近いが、前提の外。
5. **オートファイア準備の装填数の持ち方**（2.2・2.7 節）
   - 推奨: 自分の名前の付いた状態 `autoFireReady` のスタック（上限 5）にし、フルアクティブの上限の増えは状態の中身 `maxStacksUp` で書く。説明文（日本語・英語とも）が名前の付いた状態の形（機能・効果・最大装填数・解除条件）で、防御力▲の中身・解除条件（`removeState`）・数だけのヒット（`perCount: { state }`）がそのまま当たる。
   - 代わりの案: カウンタ（段 10。上限 5）にし、撃った時に 0 に戻す操作と、状態の間だけカウンタの上限を上げる中身を足す（一覧の読みのまま）。防御力▲は別の効果で書く。
6. **使用回数の持ち方**（2.7 節）

7. **撮影の編成**（3.3・3.4 節）

   - 代わりの案: C を撮らず、B だけで 3 段階突入時の▲とバーストの攻撃ダメージ▲を値で分ける（2 つの▲はほぼ同時に付き、窓の終わりの差も SR の発の間隔より短いので、窓では分けられない）。撮影は 4 本で済む。
