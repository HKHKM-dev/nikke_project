# 設計書: バッジを白黒で描き、色を画面で付ける

- 対象: バッジの元の SVG（`apps/web/badges-src/`）・書き出し（`apps/web/scripts/badges.ts`）・画面でバッジを出すところ（`apps/web/src/components/modern/`）と、その色の CSS
- 状態: 実装した（案 A の①②。③はバッジを描き直すたびに進める。6 節）
- 関連: [design-modern-ui.md](design-modern-ui.md) 2.5 節（バッジの置き場所・書き出し・命名規則）、[design-badge-frame.md](design-badge-frame.md)（六角形の枠）
- 作成日: 2026-11-10

## 1. 背景

- オーナーは、バッジのファイルを白黒（色の役ごとに決めた色）で描き、色は画面で付けたい（2026-11-10）。色を変えたい場面:
  - 状態: 限界突破した星は黄色、していない星は灰色、のように。
  - テーマ: ライトなら明るい色、ダークなら暗い色、のように。
- 今は色を元の SVG に描き込み、状態の違いは別のファイルにしている（`grade_filled`・`grade_empty`）。テーマで色は変わらない。

## 2. 調べたこと

- 画面はバッジを `<img src>` で出す（`CharacterTray.tsx`・`CharacterVisual.tsx`・`GrowthMarks.tsx`）。`<img>` の SVG には、画面の CSS（変数も）が届かない。→ 画面で色を付けるには、SVG を文書に入れるか、CSS のマスクにするかが要る。
- テーマ: ルート要素の `color-scheme`（`theme.ts`）がライト・ダーク・システムで切り替わる。CSS の `light-dark(明, 暗)` はこれに従うので、色の変数を `light-dark()` で書けば 3 つのテーマに 1 行で効く（`styles.css` の `--app-border` が既にこの形）。
- 書き出し 57 個の色（`badges.ts` で小さくした後）:
  - 枠のある 40 個は、枠の 3 色（外の線 `#000`・中 `#1a1a1a`・縁 `#fff`）と、図柄の色（白か、属性・段階などの色）。
  - `grade_*`・`ui_main` はグラデーションとフィルタを持つ。`grade_filled` は金の 2 色のグラデーション。
  - `collection_*`・`corporation_*`（3 個）・`weaponType_*`（4 個）・`ui_check` などは、id で引くマスク（Inkscape の powermask）を持つ。
  - 陰は不透明度で付けているものが多い（色を変えても陰は残る）。
- 大きさ: 57 個で 72KB。

## 3. 案

### 3.1 元の描き方（どの案でも同じ）

- 元は「色の役」を決めた少ない色で描く。例: 外の線 = `#000000`、地 = `#1a1a1a`、主の色 = `#ffffff`、差し色 = `#808080`。陰は不透明度で付ける。
- 色の役と元の色の対応は `badges.ts` に表で持つ。表に無い色が元にあれば書き出しが止まる（描き間違いで色が付かないのを防ぐ）。
- 2 色のグラデーション（金の星）は、端の色を 2 つの役（主・差し色）にする。
- Inkscape では白黒に見える。仕上がりの色は画面で確かめる（[design-badge-frame.md](design-badge-frame.md) 7 節の「見たまま」は、形についてだけになる）。

### 3.2 色の付け方

- **案 A（推奨）: SVG のスプライトと CSS の変数。**
  - 書き出しが、全部のバッジを 1 つのスプライト（`<symbol id="badge-<名前>">` を並べた SVG）にまとめる。色の役の色は `style="fill:var(--badge-main, #fff)"` のように CSS の変数に置き換え、マスクなどの id はバッジの名前を前に付けて重ならないようにする。
  - 画面はスプライトを 1 度だけ文書に置き、バッジは `<svg><use href="#badge-<名前>"/></svg>` で出す。CSS の変数は `<use>` の中まで届くので、色は CSS で決まる:
    - テーマ: `--badge-main: light-dark(#d9a400, #ffd500)` のように書く。
    - 状態: クラスで変数を変える（例: `.growth-marks-star.is-filled { --badge-main: …金… }`、無ければ灰）。
    - 値ごと: 属性の色などは、バッジの名前のクラスで変数を決める（例: `.badge-element-Fire { --badge-accent: … }`）。
  - 色の表は CSS に 1 か所。同じ絵を色違いで使える（`grade_filled`・`grade_empty` は 1 つの `grade_star` にできる）。
  - 費用: 画面のバッジを出すところ（3 つのファイル）を `<img>` から `<svg><use>` の部品に替える。スプライトはバッジ 1 つにつき 1 度だけ文書に入るので、同じバッジが何百個並んでも、文書の重さは 1 個分。
- **案 B: 書き出しで色違いを全部作る。**
  - 書き出しが、色の表（バッジ × 状態 × ライト・ダーク）の組ごとにファイルを作る。画面は今の `<img>` のまま、状態とテーマでファイルを選ぶ。
  - 費用: ファイルが組の数だけ増える（今の 57 個 × 2 テーマ × 状態）。システムのテーマでは、OS の設定を JS で見て選び直す（`light-dark()` が使えない）。色の表は CSS でなく `badges.ts` に置く。
- **案 C: CSS のマスク。**
  - バッジを `mask-image` にし、`background-color` で塗る。画面は `<img>` を `<span>` に替えるだけで、`light-dark()` も使える。
  - 費用: 1 枚で塗れるのは 1 色だけ。枠・地・図柄のように色の役が 2 つ以上あるバッジ（今のほぼ全部）は、役ごとに別の書き出しにして重ねることになり、重なりの順が入り組んだ絵は分けられない。

### 3.3 案 A の細部

- 書き出し: 今の `src/assets/badges/*.svg` に加えて、スプライト（例: `src/assets/badges/sprite.svg`、またはスクリプトのモジュール）を作る。画面で使うのはスプライトだけにし、個別のファイルは書き出しの検査と目で見るため（`<img>` で確かめる）に残すかを決める。
- 色の役の名前（例）: `--badge-line`（外の線）・`--badge-ground`（地）・`--badge-main`（主）・`--badge-accent`（差し色）。既定の値は今の色にし、CSS で決めていないバッジは今と同じ見た目になる。
- 移し方: 段を分ける。①スプライトと `<use>` の部品に替える（色は今のまま、見た目は同じ）。②色の役の表を足し、まず `grade_*` を 1 つの白黒の星にして状態で色を変える。③ほかのバッジを白黒にし、テーマの色を決める（オーナーの描き直しに合わせて少しずつ）。
- 確かめ方: ①は画面の写しを前と画素で比べる。②③はオーナーが画面で色を見る。

## 4. 確かめていないこと

- Inkscape の powermask の id を前置きで変えたあと、`<use>` の中でマスクが効くこと（効くはずだが、①の実装で画素の比べで確かめる）。
- アーティファクトの表示枠で、スプライトを文書に置いた `<use>` が描けること（①で確かめる）。

## 5. 決めてほしいこと

1. 色の付け方: 案 A（スプライトと CSS の変数）・案 B（書き出しで色違いを全部作る）・案 C（CSS のマスク）のどれか（3.2 節）
2. 色の役の数と名前（3.1・3.3 節の例でよいか。足りない役があれば）
3. 移す順（3.3 節の①②③。まず①②だけ実装し、③はバッジを描き直すたびに進める、でよいか）

- 2・3: オーナーは案 A を選んで先へ進めた。色の役は 3.3 節の例のまま（line・ground・main・accent）、移す順は ①② を実装し ③ は描き直すたびに進める。変えるときはオーナーが言う。

## 6. 実装

- 書き出し（`badges.ts`）:
  - どのバッジも、viewBox を残し（`removeViewBox` を切る）、id の前にバッジの名前を付ける（svgo の `prefixIds`。`grade_star__a` など）。
  - userSpaceOnUse のマスク・フィルタ・線形のグラデーションの範囲と座標の % と既定の値を、そのバッジの viewBox で数にする（`resolveUserSpace`）。理由は 6.1 節。
  - `MONOCHROME` に挙げたバッジ（いまは `grade_star` だけ）は、塗りと縁の色を色の役（`COLOR_ROLES`）の CSS の変数 `var(--badge-<役>,<元の色>)` にする。役に無い色・陰（白か黒）でないグラデーションの色があれば止める。
- 画面: `badges.ts`（画面）が、glob で読んだバッジ（文字列）を `<symbol id="badge-<名前>">` に並べ、`BadgeSprite` がモダン表示に 1 度だけ置く。バッジは `BadgeIcon`（`<svg viewBox><use href>`）で出す。マスクの形に使う `ui_check`・`ui_controller` は今のまま（URL で読む）。
- 星: `grade_filled`・`grade_empty` を白黒の `grade_star` 1 つにした。地を差し色（上の色）で塗り、その上に主の色を、上が透明で下が不透明のマスクで重ねる（前の 2 色のグラデーションと同じ見た目）。色は `styles.css` の `.growth-marks-star`（灰）と `.is-filled`（金）が決める。ライトとダークで同じ色にした（変えるときは `light-dark()` で書く）。

### 6.1 分かったこと

- `<use>` で出したバッジでは、グラデーションの色に `<use>` の側の CSS の変数が届かない（Chrome。グラデーションはスプライトに置いた場所の変数で決まり、既定の値になる）。塗りと縁には届く。→ 白黒のバッジでは、色の変わる部分を単色の塗りにし、グラデーションは陰（白か黒の不透明度）とマスクにだけ使う（書き出しが止める。3.1 節の「グラデーションは端の色を 2 つの役にする」は取りやめた）。
- `maskUnits="userSpaceOnUse"` で範囲（x・y・width・height）を書かないマスク（Inkscape のマスクはこの形）は、`<use>` では消える。範囲の既定の値（-10%・120%）は一番近い viewport で決まり、`<img>` ではバッジの viewBox だが、`<use>` ではスプライトを置いた 0×0 の svg になるため（4 節の 1 つ目）。→ 書き出しで、`<img>` と同じ値（viewBox で解いた数）を書く。

### 6.2 確かめたこと

- 前の書き出しの `<img>` と、今の書き出しのスプライトの `<svg><use>`（星は前の 2 色を変数で付けたもの）を、3 つの背景（白・暗い紺・灰）と 3 つの大きさ（幅 260・26・13 px）で Chrome で描いて画素を比べた。ui_check など 5 個は全く同じ。画面のスプライトに入るほかのバッジは、縁のなめらかにする画素（幅 260 px で数百画素、差の最大 30/255）と、小さい大きさの数画素だけが違い、目では区別できない（スプライトに入らない ui_main・rarity_* は小さい大きさでもう少し違うが、画面では使わない）。星は幅 13 px で縁の数十画素が最大 58/255 違う（2 つの塗りを重ねたため）。
- モダン表示（worktree の dev サーバー）で、絞り込みのボタン・ニケ一覧の絵のバッジ・限界突破の星（金と灰）・コアの印が出て、コンソールにエラーが無いことを見た（4 節の 2 つ目のアーティファクトの表示枠は、同じ文書に置くので同じと見た。公開した版では確かめていない）。
