## Context

射撃場の的の表（`data/enemies.json` の `range-bigarms`）は、武器種 × 距離帯ごとにコア命中率と弾丸命中率を持つ。枠の条件が自動のとき、モデルはこの表の値を使う（Stage 18-C）。SG はどちらも未測定（null）のままで、手入力の既定（コア命中率 1・弾丸命中率 1）を使っている。つまり、**10 ペレット全部がコアに当たる**として数えている。Stage 18 では、SG のコア命中率とペレットの弾丸命中率を入れることを「やらないこと」にしていた（design-stage18.md 8 節）。

V-0056 で SG の録画 3 本（026・027・074）を読み直し、次のことが分かった。

- ノワール単騎・AUTO の与ダメージ（`074-08`）は、モデルが実測の **2.31 倍**（+131%）。
- SG の 1 トリガーのゲージは、的に当たったペレットの数で決まる（C-0150）。いまのモデルは、1 トリガー一定の 0.75（C-0006）を掛けている。
- 当たったペレットの割合は、区間ごとに 0.68〜0.84（`074-12`）。

この設計書では、SG の 2 つの命中率を的の表に入れ、ゲージを当たったペレットの割合で数えるように変える。

### 0.3 コード（いまの形）

- `data/enemies.json` の `range-bigarms`: `coreHitRate.SG` と `bulletHitRate.SG` は null。表は帯（`near`・`midNear`・`midFar`・`far`）か着地点の id で引く（`frame/landing.ts` の `targetRateOf`）。null の項目は手入力の値を使い、注記を出す（`autoConditionAt`）。
- 与ダメージ: 弾丸命中率は、通常攻撃の 1 発の期待値に掛かる（`damage.ts`）。SG では「当たったペレットの割合」として、そのまま使える。
- ゲージ: `burst/dynamic.ts` の `energyPerTrigger` は、SG のペレット数に `SG_PELLET_GAUGE_HIT_RATE`（0.75）を掛け、さらに枠の弾丸命中率を掛ける。1 パス目（`frame/firstPass.ts`）は、表の値を使う枠では、1 発のゲージを命中率 1 で持ち、撃ったフレームの区間の命中率を掛ける。
- → 表に SG の弾丸命中率を入れるだけだと、ゲージは 0.75 × 0.78 と二重に掛かる。

仮に入れた値: 弾丸命中率は 0.2 節のとおり。コア命中率は、近 0.017・中近 0.018・中遠 0.02・遠 0.02（中遠・遠は試算のためだけの仮置き）。

| 案                                                   | 変わった残差                                                                                                                                 |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| A: `SG_PELLET_GAUGE_HIT_RATE` を外す（どの枠でも 1） | `074-08` が +131% → −0.19%（許容内）。多人数の 1 回目の満タン 7 件が早まり、6 件が許容外になる（`019-10` 0 → −78f、`020-07` −2 → −84f など） |
| B: 表の弾丸命中率を使う枠だけ、0.75 を掛けない       | `074-08` が +131% → −0.19%（許容内）。**ほかの残差は 1 つも変わらない**                                                                      |

- A で多人数の満タンが早まるのは、それらの照合の条件が手入力（弾丸命中率の既定 1）だから。0.75 を外すと、SG のゲージが全ペレット命中になる。
- B のテストで落ちたのは、SG の欄が null なことを確かめる 3 件（`stage18Landing.test.ts`）だけ。

## 1. 何を決めるか

1. SG の弾丸命中率に入れる値。
2. SG のコア命中率に入れる値（中遠・遠は未測定）。
3. ゲージの 0.75（C-0006）をどう扱うか。
4. C-0006 をどうするか。

## 2. データ（`data/enemies.json`）

```json
"coreHitRate": { "SG": { "near": …, "midNear": 0.022, "midFar": …, "far": … } },
"bulletHitRate": { "SG": { "near": 0.829, "midNear": 0.774, "midFar": 0.789, "far": 0.677 } }
```

- 中遠の 3 か所（A・B・C）は、帯の値を共通に使う（AR・SMG・MG と同じ。design-stage18.md 12.9 節の 2）。
- `source` に、SG の値の出どころ（V-0056、`074-10`・`074-12`・`026-03`）を足す。
- 表は武器種ごとで、キャラによらない。ノワール以外の SG（クイーン（真）・エーテル・プロダクト23 など）にも同じ値を使う。照準円の大きさは SG でほぼ同じ（CDN の 250。1 体だけ撃つたびに縮む）なので、同じ値で始め、外れたら測る。

## 3. 入れ方（core）

- `energyPerTrigger` に「SG のペレットの割合」を引数で渡す。1 パス目と `burst/dynamic.ts` の呼び出し側で、次のように決める。
  - 枠の弾丸命中率を的の表から取ったとき（条件が自動で、表の SG が null でないとき）: 1。当たったペレットの割合は、区間の弾丸命中率として掛かる（C-0150）。
  - それ以外（手入力）: 0.75（いまのまま）。
- 与ダメージは変えない（表の値が入れば、いまの仕組みで弾丸命中率とコア命中率が掛かる）。
- 画面・CLI の注記: SG の欄が未測定でなくなる。null の項目が残れば、いまと同じ注記が出る。

## 5. 検証

- `074-08`（ノワール単騎の与ダメージ）が許容内に入る（試算で −0.19%）。
- ほかの残差が動かない（案 B の試算どおり）。
- テスト: SG の表の値を帯ごとに引ける。自動の枠では SG のゲージが「ペレット数 × 区間の弾丸命中率 × 9,000」、手入力の枠では「ペレット数 × 0.75 × 枠の弾丸命中率 × 9,000」。

## 6. やらないこと

- コンテナに当たったペレットのゲージ（C-0139）。的の位置とコンテナの並びで変わるので、区間ごとの割合を測るまで入れない。
- 手入力の弾丸命中率の既定を、SG だけ 0.75 にすること（7 節の 3 の案 C）。
- ノワール以外の SG の当たり方を測ること（表の値を使い、外れたら測る）。
- ボス（迎撃戦）の SG の命中率。

## 7. 決めてほしいこと

1. **SG の弾丸命中率** — 推奨: **0.2 節の 074 の値**（近 0.829・中近 0.774・中遠 0.789・遠 0.677）。1 本の録画からの値で、中近・中遠・遠は会心・コアのぶんを置いた見積もり（数 % 動きうる）。別案は旧の目安（近 0.85 / 0.81・中近 0.79・中遠 0.81・遠 0.63）。今の読み方で読めた 074 のほうを推す。
2. **SG のコア命中率** — 推奨: **段 0 で 074 の CORE HIT を全区間で目で数え、区間ごとの値を入れる**（0.2 節のとおり、中遠・遠は未測定）。
   - 別案 1: 中近の実測 0.022 を全区間に入れる。中遠・遠は推論になる。与ダメージへの効きは ±2% 前後。
   - 別案 2: null のまま。与ダメージが約 1.9 倍に出すぎたまま。
3. **ゲージの 0.75** — 推奨: **案 B**（表の弾丸命中率を使う枠だけ 0.75 を掛けない。手入力の枠は 0.75 のまま）。
   - 別案 A: 0.75 を外す。手入力の既定（1）では SG のゲージが全ペレット命中になり、多人数の満タンが 6 件許容外になる（0.4 節）。
   - 別案 C: 0.75 を外し、手入力の弾丸命中率の既定を SG だけ 0.75 にする。手入力の SG の与ダメージも 0.75 倍になる（画面の既定が変わる。影響は試算していない）。
4. **C-0006** — 推奨: **棄却にし、C-0150 に置き換える**。「1 トリガー一定の 0.75」は外れ（026・027・074 で、当たりの少ないトリガーはバーの伸びも小さい）。手入力の枠に残す 0.75 は、射撃場の平均（`074-12` の平均 0.78）に近い置き値として、`dynamic.ts` の注記に書く。

## 9. 近の着地点（2026-10-01 起案。V-0069）

### 9.1 分かったこと

- クイーン（真）単騎の近が高かった（V-0063）のは、命中率▲でもキャラの差でもなく、**近の着地点が 2 か所あり、クイーン（真）の近 4 区間がどれも、よく当たる方だった**ため（C-0155・C-0156）。
  - 近 A（小さく写る。Stage 18-B2 の近）: SG の当たりは約 0.85（`074-19`・`101-12`）。
  - 近 B（大きく写る。近い）: 約 0.95（`L-SB-05`・`101-13`・`103-06`）。
  - 同じ着地点では、ノワール・プロダクト23・クイーン（真）に差が無い。
- 今の表の SG の近（0.881）は、ノワールの 6 本の近 12 区間（A 6・B 6）の平均だった。
- 10 本（近 20 区間）の内訳は A 8・B 12。1 回目の近は A 6・B 4、2 回目は A 2・B 8。
- 試算（V-0069 の結果 4）: 録画ごとに読んだ着地点の値を使うと、ノワール 074・L-SB・L-SC とクイーン（真）103・104 の与ダメージの残差が、どれも ±2% の中に入る（今は L-SB・L-SC・103・104 が外）。
- 3 体とも命中率▲が無いので、**命中率▲が弾丸命中率に効くかは、この検証では分からない**。

### 9.2 決めてほしいこと

1. **的の表をキャラごとに持つか** — 推奨: **持たない**。同じ着地点ではキャラの差が無い（C-0156）。
2. **近の表の持ち方** — 推奨: **案 A**。
   - 案 A: 近を `nearA`・`nearB` の 2 か所に分け、配分 0.4 : 0.6（20 区間の内訳）で混ぜる。中遠の A・B・C（C-0044）と同じ形。
     - SG の弾丸命中率だけ着地点ごとの値（近 A 0.845・近 B 0.951。V-0069 の 10 本の合計）にし、ほかの武器種とコア命中率は帯の値を共通に使う。
     - 混ぜた期待値は 0.909 で、今の 0.881 より 3% 高い。表を使う SG の枠の与ダメージは、近の区間で 3% 上がる。
     - 照合では、読んだ着地点に固定できるようにする（`compare.setup` に近の 1 回目・2 回目の着地点。中遠の `midFarLanding` と同じ）。SG 単騎の 8 本（074・L-SB〜L-SD・101〜104）に付ける。
   - 案 B: 近は 1 か所のまま、値だけ 20 区間の合計（0.908）に替える。コードは変わらないが、録画ごとの ±4% の残差は残る。
   - 案 C: 今のまま（0.881）。
   - やらないこと: 1 回目と 2 回目で配分を変えること（0.6 : 0.4 と 0.2 : 0.8）。10 本では、順番によるとまでは言えない。
3. **命中率▲を弾丸命中率にも効かせるか** — 推奨: **今は効かせない**（根拠が無い）。画面・CLI の注記に「命中率▲は弾丸命中率に効かせていない（未実装）」を足す。
   - 確かめるなら撮影が要る。案: SG 単騎・AUTO・スペック固定 OFF で、アサルトキューブ（命中率▲）あり 2 本・なし 2 本（Stage 18-B の撮影 1 と同じ形）。
     - 近の区間は当たった数が一意に読めるので、近 A・近 B を的の大きさで分け、同じ着地点どうしで比べる。
     - 近 B はもう 0.95 で上がる余地が小さいので、効くなら近 A に出るはず。
     - 承認されたら、予測を書いた検証記録を起こして撮影待ちにする。
4. **近 A・近 B の距離** — 推奨: **今は測らない**。SG はどちらも距離ボーナスが乗る（増分の刻みから）。AR・SMG・MG の近の表（C-0034）がどちらの着地点から出たかは分からない。弾丸命中率はどれも 0.97 以上で影響は小さいが、コア命中率（AR の近 0.42 など）は着地点で違うかもしれない。気になる残差が出たら、録画の近の的の大きさを読み直す（撮影は要らない）。
