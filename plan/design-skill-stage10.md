## 2. 語彙

### 2.1 値 × 数（`perCount`）

- **形**: 効果の値の欄に `"perCount": { "state": "<id>" }`（状態のスタック数）か `"perCount": { "counter": "<id>" }`（カウンタの値。PR 2）。値 = ref の値 × 数。
- **読む時刻**: 発火のフレームの、効果を出した枠（自分）の数（段 1 の件。条件の `selfState` が見るものと同じ）。維持のある効果は、付いた時の数で維持の間は固定する（説明文の「コピー」の読み。トーブで確かめる。PR 3）。数が 0 の時は効果を出さない（説明文の「〈名前〉をスタックしている場合」「火力ゲージがある状態なら」は、条件 `selfState`・カウンタの条件でも書く。値 0 の件を作らない）。
- **書ける効果**: 使い手のいる組み合わせだけ（PR 1 は即時のダメージ）。使い手のいない組み合わせは書けないようにする。
- **説明文の言い回し**: 「〈名前〉スタックコピー」「X% × 〈名前〉のスタック数」「X% × 〈カウンタ〉のチャージ量」。コピーの読みが「数倍の 1 ヒット」か「数だけのヒット」かは、シンデレラの録画で決める（3.1 節）。
- 段 3 の 1.4 節（スタック数の条件）と同じ件を読むので、段は 1.5（条件つきの件と同じ）。
- **PR 2 の実装で決めたこと（2026-10-26）**: フルバーストの終わりの「バーストゲージのチャージ速度 X% × 火力ゲージのチャージ量▲」は、`timed` の `perCount: { counter }` ではなく、状態の付与の `stacksFrom: { counter }`（1 回の発火で付けるスタックの数をカウンタの値にする）で書いた。ゲーム自身が、火力ゲージの値をスタック数にした「超火力チャージ」として付けていた（V-0503。C-0666）。スタックの状態の件と読み方（段ごとに値を足す）をそのまま使え、件の値を発火ごとに変える仕掛けが要らない。`perCount` は damage の状態のスタック数のまま（PR 1）。
- **PR 3 の実装で決めたこと（2026-10-27）**: トーブの宝物版のバーストも、中身の `perCount` ではなく付与の `stacksFrom: { state }`（発火のフレームの自分のその状態の段の数だけスタックを付ける）で書いた。付いた後は数え元を見ないので、「付いた時の数で固定」がそのまま出る（V-0523。C-0670）。数え元の状態の件を見るので、付与の段は 1.5。ショットガンの味方への 2 つ目の効果は、味方全体の分と重なって乗る（C-0669）ので、別の状態にした（同じ状態の付与は 1 つの件の列にまとまり、中身も 1 つのため）。

### 2.2 順番の攻撃（`burstDamage` の `hitDelays`）

- 「ランダムな敵に 最終攻撃力の X% のダメージ」「N 回順番に攻撃」。敵 1 体の前提では、N 回のヒットがすべてその敵に当たる（`assumes` に書く）。
- **形**: `burstDamage` に `hitDelays?: number[]`（バーストの発動からの各ヒットの遅れ。フレーム。昇順。長さ N）。遅れは録画で読む即値。省略はいままでどおり 1 ヒット。
- **実装で決めたこと（2026-10-26）**: ヒットの遅れの列は、定義の欄ではなく、既存の分かれたヒットの表（`burst/landing.ts` の `MEASURED_BURST_DELAYS`。[design-burst-split-hits.md](design-burst-split-hits.md)）に置いた。キャラごとの実測の遅れはこの表に置く決まりで、ほかの分かれたヒットと同じ所になる。表は 1 回の発動の倍率をヒットの数で等分するので、`burstDamage` には回数の欄 `hitsRef`（倍率を回数倍にする）だけを足した。回数と表のヒットの数がそろうことはテストで確かめる。論点 4 の決定（遅れの列で書き、自動攻撃にしない）の中身は変えていない。
- 自動攻撃（`autoAttack`。周期と維持で書く）にしないのは、ヒットの間が等間隔かが分からず、回数が説明文で決まっているため（論点 4）。録画で等間隔と分かっても、回数で書く形のほうが説明文に近い。
- ヒットがバーストゲージを溜めるかは、いまのバーストスキルダメージと同じ扱い（溜めない）にし、録画のゲージで食い違えば直す。

### 2.3 キャラ固有のカウンタ（PR 2。論点 2）

カウンタは、「火力ゲージ 100 チャージ」「火力ゲージ 100 消費」のように、上限と増減を持ち、時間では外れず、値が「X% × チャージ量」のように数で決まる（分類の別紙 4.2 節）。スタックの状態で書くか、別の語彙にするかが論点 2。

- **推奨: 別の語彙（カウンタ）にする**。スタックの状態と次の所が違い、スタックの状態に寄せると例外の印が増える:
  - 0 まで減る。スタック量の減少は最後の 1 段を残す（段 3 の 1.5 節。V-0437）が、火力ゲージの消費は 0 にする。
  - 付与なしで始まる。スタックの状態は付与が上限と維持を決めるが、火力ゲージは付与の行が無く、戦闘開始時のチャージだけがある。
  - 1 回の増減が大きく、上限も大きい。スタックの状態は段ごとに件を持つので、段の数が増えると件の列も増える。
  - 時間で外れない（維持の秒が無い）。
  - 定義の無い使い手には、値の到達で別の出来事を起こすものがあり、スタックの「フルスタックでスタック解除後」とは形が違う。
- **形**: 目録はカウンタの id と上限（最初の値は 0）。操作は `kind: "counterChange"`（`counter`・`amount` か `amountRef`・`decrease`・`trigger`・`condition`。足した結果は上限で切り、減らした結果は 0 で切る）。条件は `condition.selfCounter: { "counter": "<id>", "atLeast": N }` か `{ …, "below": N }`。値は 2.1 節の `perCount: { "counter": "<id>" }`。
- **時刻の規則**: カウンタは 1 パス目のフレームのループで持ち（射手・ゲージと同じ）、条件はフレーム f − 1 の終わりの値を読み、フレーム f の増減は f のすべての条件を見た後に足す。同じバーストの 2 つの行（「100 未満なら火力チャージと 1 チャージ」「100 なら超火力と 100 消費」）は、どちらも発動の前の値を見る（1 チャージで 100 に届いても、同じ発動で超火力にはならない）。
- **循環**: 火力チャージの付与は火力ゲージを見て、火力ゲージは火力チャージの間の通常攻撃と火力チャージの終わりで増える。時間をまたぐ循環で、同じフレームの中では閉じている（上の時刻の規則）。[design-named-state.md](design-named-state.md) 8.5 節の禁止（付与が自分の付ける状態を見る）には当たらない（付与が見るのはカウンタ）。検証では、カウンタを見てカウンタを変える行だけを、同じフレームの値を見ないことで許す。
- **代わりの案: スタックの状態で書く**。火力ゲージを「持続」・上限 100 の状態にし、戦闘開始時の付与（N スタックで付ける形を足す）・スタック量の増減・消費（減少に「0 まで」の印を足す）・スタック数の条件で書く。条件・`while`・画面の状態の表示がそのまま使える。違いは上の点の印で吸収する。
- **PR 2 の実装で決めたこと（2026-10-26）**: 推奨の案で入れた。目録は `skills/counters.ts`（状態の目録とは別のファイル）、増減のきっかけは parseTrigger のものと `{ ended }`、増減の条件は `selfState`・`selfCounter`。カウンタの値は 1 パス目のループで持ち、時刻の規則のとおりに読む。カウンタの増減の条件 `selfState` は、段によらずそのフレームに効いている状態の件を見る（増減がすべての判定の後なので連鎖しない）。履歴に値の変わった記録を残し、比べる指標が読む。
- **画面の火力ゲージの減り方**（V-0503）: 超火力の間、画面の火力ゲージは約 10 秒かけて 0 まで減るが、ゲージを読むのはバーストの使用とフルバーストの終わりだけで、どちらの時も 0 なので、モデルは使った時に 100 減らす（説明文の「100 消費」のまま）。

### 2.4 `{ ended }`（PR 2）

- 形は段 4 の 1.3 節のまま（`"trigger": { "ended": "<id>" }`。その状態の、この効果を持つ枠の件が外れたフレームに発火する）。PR 2 で `counterChange` のきっかけとして実装する（ほかの効果に開くのは使い手がいる時）。
- 火力チャージは「解除不可」で、時間切れで外れる。外れたフレームちょうどか次のフレームかは、録画では見分けにくい（フレームの差がダメージに効かない）ので、段 4 の 1.3 節の見込みのまま入れる。

### 3.2 PR 2: ネオン：ビジョン・アイの火力ゲージ

- いまのモデルとの違い: 超火力の回だけ、攻撃ダメージ▲・攻撃力▲・S1 の追加ダメージが増える。フルバースト終了時のバーストゲージのチャージ速度▲で、次のチェーンが早まる。

- **撮って分かったこと**: 画面に火力ゲージの値が出ていて、上限 100（H1）と読めた。超火力の回と効果の値も説明文の式と合った（C-0667・C-0665）。フルバーストの終わりの効果は「超火力チャージ」のスタックとして付く（C-0666）。チャージ速度▲の量はチェーンの時刻に出ず、見えない。
- **PR 2 の実装で足したほかのこと**:

### 3.3 PR 3: トーブ（宝物版）のバースト

- 説明文: 味方全体に「その場しのぎの奇跡：スキル発動者基準で攻撃力 X%▲」「応急改造スタックコピー」、ショットガンを所持する味方全体に同じ形の攻撃力▲。

## 6. 論点

決定（2026-10-26、オーナー）: 論点 1〜6 は推奨どおり。論点の文は諮った時のまま。

1. **段 10 の対象**（0.3 節）（決定: 推奨どおり）
   - 推奨: 「数で決まる値」（スタックのコピーとキャラ固有のカウンタ）。定義のある使い手がいちばん多く、「値 × 数」の 1 つの読み方で両方が書け、最初の PR が既存の録画で確かめられる。
   - 代わりの案: バースト段階の変更（ラピ：レッドフード）。1 体で未対応の notes がいちばん多いキャラが片付くが、語彙の重なり（粘着榴弾・発射体付着ダメージ・有利コードの適用）が多く、撮影も戦闘補助の有無の 2 編成が要る。
2. **カウンタの書き方**（2.3 節）（決定: 推奨どおり）
   - 推奨: 別の語彙（カウンタ。`counterChange`・`selfCounter`・`perCount: { counter }`）。0 まで減る・付与なしで始まる・増減が大きい・時間で外れない、がスタックの状態と違う。値の読み（× 数）はスタックと共通にする。
   - 代わりの案: スタックの状態で書く（N スタックの付与・0 までの減少・維持なしの印を足す）。条件・`while`・画面の状態の表示がそのまま使える。
3. **PR 1 を既存の録画の読み直しにするか**（3.1 節）（決定: 推奨どおり）
   - 推奨: する。0480 で読み方を決め、0481 で再現を見る。撮影を待たずに値 × 数と順番の攻撃を入れられる。
   - 代わりの案: シンデレラのバーストも新しく撮る（ヒットの時刻を一時停止やスロー再生で見やすくする撮り方）。
4. **順番の攻撃の形**（2.2 節）（決定: 推奨どおり）
   - 推奨: `burstDamage` にヒットの遅れの列（`hitDelays`）を足す。回数が説明文で決まり、間が等間隔でなくても書ける。
   - 代わりの案: 自動攻撃（`autoAttack`。間隔と維持）で書く。等間隔なら今の語彙のまま書ける。
5. **トーブのバースト（PR 3）を段 10 に入れるか**（3.3 節）（決定: 推奨どおり）
   - 推奨: 入れる。維持のある効果での値 × 数（付いた時の数で固定か）を確かめる、コピーの 2 体目になる。
   - 代わりの案: 段 10 は PR 1・2 で閉じ、トーブのバーストは段の外で 1 体ずつ足す（[design-skill-stages.md](design-skill-stages.md) 3 節の 1 点目と同じ扱い）。
6. **PR の順**（1 節）（決定: 推奨どおり）
   - 推奨: PR 1 → PR 2 → PR 3（PR 1 は撮影を待たない。PR 2 は語彙が大きく、撮影の計画も大きい）。
   - 代わりの案: PR 2 を先にする（カウンタの語彙を先に決め、値 × 数をその上で書く）。
