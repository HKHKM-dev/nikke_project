## 条件

- 目的: モダニア（260）の S1 の effects[1]（クリティカルダメージ▲）・effects[2]（最大装弾数▼）を結論に結び付ける（plan/design-skill-claims-5-2.md 3.2 節の決定。最小構成の録画だけ読み直す）。
- 録画 `045` はモダニア単騎・**操作**・スペック固定 ON・3 分モード。単騎なので未確定の要素はモダニア自身だけ（最小構成）。スペック固定ではキューブが乗らず、S2 の攻撃力▲（自分が命中率増加状態なら）は出ない。バーストも出ない。
- 説明文（`data/characters/260.json` の skill1）: 通常攻撃が 200 回命中した時、自分にクリティカルダメージ▲（5 スタック）と最大装弾数▼（5 スタック）。定義は `data/skills/260.json` の skill1 の effects[1]・effects[2]（`stacks`・付与のたびに全スタックを更新）。
- 操作の録画なので、撃つ時刻はモデルと合わない。比べるのは時刻に依らない値（スタックごとの会心の 1 ヒット・最大装弾数）だけ。モデルの frame は、モデルでそのスタックにある区間を指すだけ。
- 前に読んだもの: `045-01`〜`045-08`（的のジャンプ・ゲージ・リロード）。凍結の verification.md Stage 11 モダニアは、録画 045 から 5 スタックが張り付く区間と 5 → 0 に落ちるフレームを読んだ（スタックの規則の出どころ）。スタックごとの会心の値と、045 のリロード明けの残弾は読んでいない（リロード明けの残弾は録画 044 で読んだ）。そのため、スタックの規則（付与のたびに全スタックを更新）は比べる指標にしない。

2. `npm run records:read -- 045 --recipe hud-jumps` で総ダメージの増分を全フレーム取り、1 増分を「通常攻撃（胴体・コア × 会心 × 距離）+ 追加ダメージ（会心か否か）」の和に分ける。スタック k ごとに、会心の通常攻撃の値を 1 つずつ拾う（指標 `hitDamage`）。

## 分かったこと・分からないこと

- **モダニアの S1 のスタックは、1 つごとに会心の倍率に 0.1425 を足し、最大装弾数を ×(1 − 0.0504k) で四捨五入する** → C-0272（確定・厳密一致）。定義の skill1 の effects[1]・effects[2] に結び付けた。
- 分からないこと: スタック 3 の最大装弾数（255）は、この録画にリロードが無く読めていない（式は他のスタックと同じ）。スタックの規則（付与のたびに全スタックを更新、5 → 0 に一度に落ちる）は、並びでも同じ形が見えたが、凍結の記録で同じ録画から読んだ出どころなので、結論の根拠にしていない。
