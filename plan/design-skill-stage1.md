## 1. 語彙

### 1.1 自分が〈状態〉なら: `condition.selfState`

- **形**: `"selfState": "<id>"`（付いていれば）と `"selfState": { "state": "<id>", "present": false }`（付いていなければ）。フルスタックの `stacks` は段 3 で足す（[design-named-state.md](design-named-state.md) 8.1 節の形）。
- **受ける効果**: `timed`・状態の付与・`damage`（`CONDITION_KEYS_OF` に足す）。ほかの鍵（`selfBuffed`・`inFullBurst`・`enemyState`）と AND。
- **意味**: 発火のフレーム f に、自分（効果を出した枠）がその状態の件を持っているか。件の出どころは問わない（どの定義の付与で付いた件も見る。同 3.5 節）。
- **静的な状態**: 静的な状態（1.4 節の決め方）を見る `selfState` は、編成の段（`skills/composition.ts`）で決める。いつも付いているか、いつも付いていないかなので、満たせば条件を落とし、満たさなければ効果を外す（`burstStepMix` と同じ扱い）。効果の段の印は変わらず、値はいまと同じになる（論点 1）。
- **時間で変わる状態**:
  - `timed`・付与: 段 1.5 で判定し、段 1 の状態の件（同じフレームに付いたものを含む）を見る。いまの `selfBuffed` と同じ見え方で、条件つきの付与が付ける状態どうしは連鎖させない（同 8.5 節）。
  - `damage`: `frame/plan.ts` で、履歴の状態の件を段の印に依らずに見る（同じフレームに付いたものを含む。論点 5）。
- **外れた件**: 解除・消去で外れる件は、そのフレームの判定では付いているとみなす（1.2 節）。
- **検証**: id が目録にあり、`holder` が `ally`。付与は、自分の付ける状態を `selfState` で見ない（循環の禁止。同 5.6 節）。

### 1.2 解除と消去: 効果 `removeState`・`cancelState`

- **形**: `{ "kind": "removeState" | "cancelState", "state": "<id>", "trigger": …, "target": "self", "condition"?: …, 編成の条件? }`。説明文の「〈名前〉解除」（Removes）・「〈名前〉消去」（Cancels）の行に 1 つずつ書く。対象は、説明文の例がどれも自分なので、`self` だけを許す（味方の状態を外す例が出たら広げる）。
- **意味**: 発火のフレーム f に、持ち主のその状態の件（出どころは問わない。スタックはすべて）を、f + 1 で閉じる。f の判定（同じフレームの条件・ダメージ）には付いているとみなす（同 8.2 節の見込みのとおり。論点 2）。
  - 解除（`removeState`）は、解除不可の件（1.3 節）を閉じない。消去（`cancelState`）は閉じる（論点 8 の決定。ツールチップ「消去」）。
  - 同じフレームに同じ状態を付ける付与があれば、付与が勝ち、件は続く（論点 3）。
- **段**: 条件なしは段 1、条件つきは段 1.5。閉じるのは f + 1 なので、段の順は同じフレームの判定に効かない。
- **一覧の操作**（組み直しの設計書 2.3 節に足す）: 件の列に、閉じるフレームの列を持たせる。件は、始まりの列から今と同じ規則で作り、閉じるフレーム c より前に始まった件を c + 1 で切る。c 以降の始まりは、新しい件を作る。
- **静的な状態**: 外す効果がある状態は、静的な状態にしない（1.4 節）。
- **消去の実装は、使い手を定義する時にする**: 消去の使い手（ラピ：レッドフードの戦闘補助・ブレッディ・ミントなど）は、どれもまだ定義が無いか、ほかの家族の語彙（バースト段階の変更・「〈stat〉増加効果が適用された時」・切り替え）も要る。アニス：スターの消去は書かない（2.1 節・論点 4）。

### 1.3 解除不可の印: 付与の `undispellable: true`

- 説明文で「解除不可」の付く付与に書く。読むのは、解除（`removeState`。PR 2）と、後の効果解除と、画面の状態の表示（「解除不可」と出す）。
- 持続の長さは変えない（分類の別紙 4.5 節の 1・2）。

### 1.4 呼び名の付与（論点 4）と、静的な状態の決め方

- **名前の付いた効果は、参照されなくても状態の付与で書き、目録に id を足す**（id の付け方は [design-named-state.md](design-named-state.md) 5.1 節。英語版の名前から）。
  - 中身にできる項目（状態の間だけ持ち主に効く stat の▲▼）は中身に書く。
  - 中身にできない項目（自分の維持の別の効果・即時・別の対象・ダメージ・自動攻撃・バースト再突入）は、今と同じく別の効果で書き、付与は中身なしで足す（同 4.3 節）。中身に種類を足すのは同 8.4 節の後の拡張。
  - 目録に足すのは、定義する・書き直すキャラの分だけ（2 段目の計画の 0 節）。
- **静的な状態の決め方を改める**: いまは付与ごとに形（戦闘開始時・戦闘の終わりまで・自分・条件なし・スタックなし）で決めている（`isStaticStateGrant`）。これを状態ごとにし、その状態のどの付与も静的な形で、外す効果も無い時だけ静的にする。いまは、同じ状態に静的な形の付与と時間で変わる付与（マナのフルバースト終了時の再付与など）があると検証で落とす（「need to be all static」）ので、マナのマターシグマが書けない。PR 2 で、この検証を状態ごとの決め方に置き換える（静的にならない状態は、静的な形の付与も時間で変わる付与として件にする）。
- **画面**: 枠のまとめに、付いた状態（中身の無い状態を含む）の名前・付いた回数・解除不可を出す（`skills/summaries.ts` に状態のまとめを足し、`apps/web` の枠のカードに出す）。中身の stat の▲▼の表示は今のまま。

### 1.5 直前に自分がバーストを使用していれば: `condition.usedBurst: true`

- フルバーストの開始・終了のきっかけ（`fullBurstStart`・`fullBurstEnd`）にだけ書ける。発火の文脈の `burstUsers`（そのフルバーストを開いたチェーンでバーストを撃った枠。いまの対象「直前にバーストスキルを使用した味方」と同じ材料）に自分がいるか。
- 使い手: マナ S2 のマターシグマの再付与。

### 1.6 時間で変わるバーストゲージのチャージ速度▲

- いまは常時の値（`passive`）にしか書けない。1 パス目より前にゲージの速さを決めていたためで、`timed` に書くと時刻表 → 窓 → ゲージ → 時刻表と循環した（`skills/types.ts`）。組み直しの後は 1 パス目がフレームごとに件を作るので、ゲージの速さを件から読める。
- 見え方は射手と同じ（f − 1 までに付いた件）。状態の中身と `timed` に書けるようにする。
- 使い手: マナのマターシグマ（バーストゲージのチャージ速度▲）。

### 1.7 切り替え（`group`）

- 形は [design-named-state.md](design-named-state.md) 8.2 節のまま（目録の `group`。同じグループの状態が付いたら、ほかの件を f + 1 で閉じる。解除不可の件も閉じる）。
- 使い手（ギルティ：マイティバニー・シン：スウィフトバニーのバニーモード、ミントのステージパート）を定義する時に実装する。

## 5. 論点

決定（2026-10-16）: オーナーの指示（自動で進められるところまで進める）で、論点 1〜6 を推奨どおりにして進めた。

1. **静的な状態を見る `selfState` を、編成の段で決めるか**（1.1 節）
   - 推奨: 決める。効果の段の印が変わらず、値がいまとビット単位で同じになる。
   - 代わりの案: 段 1.5 で件を見る。値は同じ見込みだが、効果の段の印が 1 から 1.5 に変わり、ほかの判定（`selfBuffed`・当たり）からの見え方が変わりうる。
2. **外れる時刻**（1.2 節）
   - 推奨: f + 1 で閉じる（同じフレームの判定には付いている）。マナ S2 の、同じ発火で解除しても▲が付く結論（C-0281）と合う。
   - 代わりの案: f で閉じる（同じフレームの判定には付いていない）。
3. **同じフレームの解除・消去と付与**（1.2 節）
   - 推奨: 付与が勝つ（件は続く）。説明文で、外してから付け直す行（アニス：スターの消去と付与）の読みと合う。
   - 代わりの案: 定義の順に当てる。
4. **アニス：スターの消去を書くか**（2.1 節）
   - 推奨: 書かない。編成で決まる入れ替えで、戦闘中は片方しか付かず、書いても値は変わらず確かめられない。消去は使い手のキャラで実装する。
   - 代わりの案: 状態を時間で変わる付与にして消去も書く。PR 1 に消去が入る。
5. **`damage` の `selfState` の見え方**（1.1 節）
   - 推奨: 履歴の件を、段の印に依らずに見る（同じフレームに付いたものも）。ミハラの撮影（PR 3）で確かめる。
   - 代わりの案: 段 1 の件だけを見る（`timed` と同じ）。
6. **PR の順**（0 節）
   - 推奨: PR 1（アニス：スター）→ PR 2（マナ）→ PR 3（ミハラ。撮影を待つ間に 1・2 を出す）。
