## 0. 範囲

- リリー（SR・SMG・支援型・バースト II・風圧。宝物なし）の S1・S2・バーストを `packages/core/data/skills/852.json` に定義し、撮影で結論に結び付ける。
- いまの語彙で書けないのは「ランダムな味方 1 機」（S1・バースト。2 節）。全キャラの説明文で、味方をランダムに選ぶ言い回しは、ほかにビスケットのバースト（遮蔽物が破壊された味方。前提の外）とココアの S1（デバフのかかった味方。`debuffedRandom`）がある。
- コードで確かめた、いまのモデル（2026-11-28）:
  - timed の `target: "allies"` と `targetCount`（「〈絞り込み〉の味方 N 機」）は、候補が N 機より多い時、枠の若い順の N 機に決め打ちで付ける（キリの S1。実機は発ごとに選び直す C-1579）。
  - 確率のきっかけ（`chanceRef`）は、付いている確率を値に掛けた期待値の窓で持つ（`skills/chance.ts`）。攻撃力▲はダメージの式で 1 次なので、1 発の期待値はこの強さで付けた値と同じ。1 パス目の順位（`topAttack` など）も同じ値を使う。きっかけは射撃の回数だけ。
  - 説明文にきっかけの無いアクティブは、時間の周期のきっかけ `{ everySeconds, cooldown: true }` で書く（周期は録画で読む。ジュリアの宝物版 S1 の C-1325）。
  - 遮蔽物は、被弾を扱わないので壊れない（[requirements.md](requirements.md) の前提。ビスケットのバーストの notes と同じ）。

## 2. 語彙: 「ランダムな味方 N 機」（timed の `allies` に `targetRandom` を足す）

```json
{
  "kind": "timed",
  "trigger": "burstUse",
  "target": "allies",
  "targetCount": 1,
  "targetRandom": true,
  "stat": "attack",
  "scaling": "casterAttack",
  "ref": 4,
  "durationRef": 5
}
```

- 意味: 「絞り込みに合う枠（自分も候補。論点 2）から、発動のたびに N 機をランダムに選ぶ」。モデルは期待値で持つ: 候補が k 機（> N）なら、候補の全員に値 × N / k で付ける。k ≤ N なら全員に値のまま付く（キリと同じ）。
- 置き場所:
  - 候補の枠は、`allies` の `targetCount` と同じに `skills/composition.ts` の `fixedTargetsOf` が `fixedTargets` に書く。
  - `skills/targets.ts` は、`targetRandom` なら先頭の N 枠に絞らず、候補の全員を対象にする。
  - 値の N / k は、解決（`skills/resolve.ts` の `resolveTimed`）で `fixedTargets` の数から掛ける。区間・鍵・2 パス目・順位は、ほかの timed と同じに読む（確率のきっかけのような小片は作らない）。
  - sim の枠の注記（`random-allies-expected`）で「実機は発動のたびに k 機から N 機を選ぶ。モデルは全員に N / k で配る（期待値）」と知らせる。
- 期待値が成り立つ理由と範囲:
  - 攻撃力▲はダメージの式で 1 次で、射撃の列を変えない。1 回の発動で各候補が選ばれる確率は N / k なので、各候補の 1 発の期待値は、値 × N / k を付けた 1 発と同じ（防御力で 1 ダメージに張り付く所を除く）。
  - 同じ効果の窓が重ならない時に限って正確。前の窓の中で次の発動が来ると、実機では 1 − (1 − N / k)² の確率で付いているのに、モデルの窓の和集合は N / k のまま（少なめ）。リリーのバーストは CT 40 秒・維持 10 秒で重ならない。S1 は周期 T が 5 秒以上なら重ならない（4 節で読む）。
  - 1 パス目の順位（ほかの枠の「最終攻撃力が最も高い味方」など）も N / k の値で並べる。確率のきっかけと同じ扱い。
- 書けるのは timed の `allies` と `targetCount`（`targetCountRef`）の組だけ。それ以外の効果の種類とは組まない（使い手がいない）。
- キリの S1 は、窓（3 秒）がフルチャージの発ごとに重なるので、この語彙に移さない（重なると少なめになる。移すなら確率のきっかけの小片の形が要る）。

### 2.1 退化

- `targetRandom` を持つ効果はリリーだけで、既存の定義の数値は変わらない。

### 2.2 比べ方

- 期待値の 1 発は、実機の 1 発（▲の有り・無しのどちらか）とは比べられない。比べるのは次の 2 つ。
  - ▲の乗った発の格子: 単騎（k = 1）では、モデルの値がそのまま▲の乗った格子になる。2 機以上の編成では、ランダムの対象を 1 枠に決めて回したモデルと比べる。そのため、sim の入力に「ランダムの対象をこの枠に決める」欄（`randomTargetSlot`。観測値と予測の `setup` からも渡す）を足す。決めた時は、その枠に値のまま付き、ほかの枠には付かない。
  - 選ばれた枠の割合: 発動ごとに▲のアイコンが付いた枠を数え、N / k と二項分布で比べる（検証記録に数え上げを書く。指標は足さない）。

## 3. 定義の案（`data/skills/852.json`）

- 1 節の表のとおり。S1・バーストは効果と前提の外の notes で `supported`、S2 は間接の notes だけで `noEffect` になる。
- S1 の周期 T が撮るまで決まらないので、撮る前の定義は S1 を未対応の notes（きっかけが説明文に無い）にし、バーストだけを効果にする。T を読んだら S1 を効果にする（ソルジャーO.W. の S2 と同じ順）。

## 4. 検証（撮って確かめる問い）

- 撮影は V-0898（編成・予測・撮影の依頼はそちら）。撮影ごとの狙い:
- 撮影 A（リリー単騎）: S1 のきっかけと周期 T、自分が候補に入るか（入るなら毎回リリーに付く）、値（リリーの 1 発の格子）。
- 撮影 B（ルドミラ（I）+ リリー（II））: S1 とバーストの▲がどちらの枠に付くか（発動ごとに変わるか、割合が 1/2 に近いか）、ルドミラの 1 発の格子（ランダムの対象をルドミラに決めたモデル）、バーストの値と窓（10 秒）。

## 5. 論点（オーナーに決めてもらうこと）

1. **「ランダムな味方 N 機」の持ち方**（2 節）
   - 推奨: 案 A（期待値）。timed の `allies` と `targetCount` に `targetRandom: true` を足し、候補の全員に値 × N / k で付ける。ダメージの期待値として正しく、編成の誰にも偏らない。確率のきっかけ（期待値の窓）と同じ考え方で、実装は解決で値を割るだけで済む。
   - 代わりの案 B（決め打ち）: キリと同じく枠の若い順の N 機に付け、sim の注記で知らせる。語彙は `allies` と `targetCount` のままで足さない。リリーの▲は発動者基準の固定量なので、受け手によって伸びるダメージが違い、編成の合計が受け手の選び方で偏る（1 枠目が火力の低いキャラだと少なめ、高いと多め）。
   - 代わりの案 C（未対応）: S1・バーストを未対応の notes にする。リリーの定義は効果を持たず、編成のダメージがリリーの▲の分だけ少なめになる。
2. **候補に自分を含むか**
   - 推奨: 含む形で定義し、撮影 A・B で確かめる。説明文の「味方」は、ほかのキャラの定義でも自分を含む（ビスケットのバーストの「支援型の味方全体」、キリの「防御型の味方 2 機」）。撮影 A で S1 がリリーに付かなければ、自分を除く（`excludeSelf`）に直す。
3. **撮影の編成**（4 節）
   - 推奨: A（リリー単騎・1 本）と B（ルドミラ + リリー・2 本）。A は S1 の周期と値を最小構成で見る。B はバーストに要る I を、機構が確定したルドミラ（S1 は敵の防御力▼で、攻撃力に効かない）だけで足し、候補を 2 機にして選ばれ方を見る。III がいないのでフルバーストは起きず、1 発の格子が単純になる。
   - 代わりの案: B に III（機構が確定した支援でないキャラ）を足して候補を 3 機にする。選ばれ方の見分けは増えるが、フルバーストの補正が 1 発に混ざり、1 機あたりの回数は減る。
4. **バーストの遮蔽物の枝**（1 節）
   - 推奨: 遮蔽物が壊れない前提で、後者の枝（40%・10 秒）だけを効果にし、前者は前提の外の notes にする（ビスケットのバーストと同じ）。

## 経過

- 2026-11-28: 起案。足す語彙は、timed の `allies` と `targetCount` に `targetRandom`（期待値で配る）を許すことと、比べるための sim の入力 `randomTargetSlot`（2 節）。論点 1〜4 をオーナーに諮る。
