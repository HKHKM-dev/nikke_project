## 2. 語彙

### 2.1 自分を除く: `excludeSelf`

```json
{
  "kind": "timed",
  "trigger": "burstUse",
  "target": "topAttack",
  "targetCountRef": 1,
  "excludeSelf": "unlessShort",
  "stat": "attack",
  "ref": 2,
  "durationRef": 3
}
```

- 値は 2 つ。`"always"` = 自分を候補から外す（姫野の型。足りなければ足りないまま）、`"unlessShort"` = 自分を外して上位 N を取り、N に足りなければ自分を足す（ミランダの「対象が足りない場合、自分も対象となる」）。
- 書ける対象は `topAttack` だけ（論点 1）。`self` には意味が無いので落とす。`allies`（「自分を除く味方全体」）はこの設計では使うキャラがいないので、読み込みで落とす。
- 判定（`skills/targets.ts` の `isEffectTarget`）: `topAttack` の順位（`context.attackRank`）から発動者の枠を除いてから上位 N を取る。`unlessShort` で N に足りなければ発動者の枠を足す。候補（`targetWeapon`・`targetElement` で絞った後）が N 未満なら全員（いまの規則）のままで、その「全員」に自分は入らない（`always`）。
- 順位の決め方（`skills/ranking.ts`）は変えない。順位で対象が決まる効果の窓は順位の材料に入れない（設計書 18 節。ミランダのバーストは攻撃力を配るので、この規則で循環が切れる）。
- `canEverTarget`（1 パス目の「窓を持ちうる枠」）: `always` は発動者の枠を外す。`unlessShort` はいまの `topAttack` と同じ（自分も持ちうる）。
- 「自分と自分を除く…N 機」（アニスなど）は、`self` の効果と `topAttack`・`excludeSelf: "always"` の効果の 2 つに分けて書ける。N が自分を含むかは説明文から決まらないので、定義するキャラが出たときに決める。

**ミランダの定義**（基礎のバースト。宝物も同じ形で `targetCountRef` の値が 2）:

| 効果                           | `trigger`  | `target`    | `excludeSelf` | `stat`       |
| ------------------------------ | ---------- | ----------- | ------------- | ------------ |
| 攻撃力▲（10 秒）               | `burstUse` | `topAttack` | `unlessShort` | `attack`     |
| クリティカルダメージ▲（10 秒） | `burstUse` | `topAttack` | `unlessShort` | `critDamage` |

- ミランダはバースト I（`Step1`）なので、順位は II・III が撃つ前のフレームで決まる（その II・III の自分へのバーストの攻撃力▲は入らない）。これはいまの `topAttack` の規則のまま。
- **宝物の S2 の 3 行目（「1 発間維持」のクリティカル確率▲）は、この設計でも未対応のまま残す**。発数の維持（`durationShots`）は `topAttack` に書けない（`types.ts` の `parseTimedDuration` で落とす）。notes の理由を「自分を除く対象は語彙に無い」から「対象への発数の維持が語彙に無い」に直す。

### 2.2 基本チャージ時間が一番長い味方: 対象 `longestChargeTime`

```json
{
  "kind": "timed",
  "trigger": "fullBurstStart",
  "target": "longestChargeTime",
  "targetCountRef": 6,
  "stat": "chargeSpeed",
  "scaling": "flat",
  "ref": 7,
  "durationRef": 8
}
```

- `BuffTarget` に `longestChargeTime` を足す。意味は「`CharacterData.shot.chargeTime`（CDN の基礎のチャージ時間。バフ・使用武器の変更を入れない）の長い順に N 枠」。N は `targetCount` / `targetCountRef`（`topAttack` と同じ欄。どちらか 1 つ）。
- 編成で決まる（戦闘中に変わらない）ので、発火の文脈は要らない。`dependsOnContext` は偽のまま、効果ごとに 1 回だけ対象を決める。
- 同値は枠の若い順（`topAttack` と同じ仮定。未検証）。チャージの無い武器（AR・SMG など。`chargeTime` 0）も候補に入れる。全員 0 なら誰かに付くが、引く秒数が 0 未満にならないので何も変わらない。
- 書ける効果は `timed`（いまの `topAttack` と同じ所）。`passive` にも意味はあるが、使うキャラがいないので落とす。

**「チャージ時間 X 秒▼」**: `stat: "chargeSpeed"` に `scaling: "flat"` を許し、値を秒のまま（100 で割らない）`BuffTotals.chargeTimeFlat` に足す（論点 2）。

- `chargeTimeFlat` はアリスの「スキル発動者基準でチャージ速度 X%▲」（`casterChargeTime`）が使っている欄で、射手は `max(0, 時間 × (1 − 速度) − chargeTimeFlat)` にする（`frame/firing.ts` の `chargeSecondsOf`）。マナの値もここに足す。
- `scaling: "flat"` はいま `maxAmmo`（発数）だけ。単位は stat で決まる（発数・秒）と型の注釈に書く。

### 2.3 同じ部隊に絞る: `targetSquad`

```json
{
  "kind": "passive",
  "target": "allies",
  "targetSquad": "same",
  "stat": "critDamage",
  "ref": 1
}
```

- `targetWeapon`・`targetElement` と同じ絞り込みの欄。`"same"` = 対象の枠のキャラの `CharacterData.squad` が、発動者の `squad` と同じ枠だけ。発動者自身も入る（「同じ部隊の味方全体」に自分を含むと読む。論点 3）。
- 書ける対象は `allies` だけ（`self` には意味が無い。`topAttack`・`burstUsers` と組む言い回しは無い）。`passive` にも `timed` にも書ける（編成で決まるので）。
- 判定: `matchesTargetFilter` は対象の枠だけを見ているので、発動者の部隊を渡す（`TargetSlot` に `squad` を足し、`isEffectTarget`・`canEverTarget` に発動者の枠のキャラを渡す）。キャラのデータの `squad` は [design-ram-s1.md](design-ram-s1.md) 2.2 節で全キャラに入っている。
- 既存の `squad`（「同じ部隊の味方がいれば」の**条件**。効果を持つか持たないか）とは別物。名前が近いので、型の注釈と画面の注記で分ける（画面は「対象: 同じ部隊（アブソルート）の味方」）。

**エマ・ウンファの定義**: S2 の効果 1 に `"targetSquad": "same"` を足し、notes の「対象を部隊で絞るのは未実装」を消す。2 体は同じ部隊（`Absolute`）なので、2 体を並べた編成ではお互いに付く。

### 2.4 表示

- 画面（`SkillSection.tsx` のラベル）: 対象の文言に「自分を除く」「足りなければ自分も」「基本チャージ時間が最も長い N 機」「同じ部隊（〈部隊名〉）の味方」を足す。
- CLI（`scripts/sim-run.ts`）: 対象の列に同じ文言。
- 時刻表の順位の記録（アリス編の `attackRank` の記録）に、除いた枠を出す。

### 4.1 録画 022 の読み直し（エマ：TU S2 の部隊）

- 見るもの: デルタのクリティカルのヒットと、クリティカルでないヒットの比（同じ部位・同じ距離・同じフルチャージ）。クリティカルダメージ▲が付いていればその分だけ比が大きい。
- 未確定の要素: エマ：TU の S1（敵の受けるダメージ▲・再発動周期）とバースト（環境コントロール強化）は定義が無い。どちらも敵に掛かる別枠の乗数（C-0138）で、攻撃力▲（バーストの発動者基準）とともに、同じ 1 発のクリティカルと非クリティカルの比では消える。エマの S2 の効果 2（発射体爆発ダメージ▲）は RL の通常攻撃にだけ掛かるので、デルタ（SR）には効かない。
- 既に読んだ値: デルタのコアヒット（バフの前・中。verification.md Stage 6 の 5）。**クリティカルのヒットは記録に無い**（観測値 `022-01`〜`022-03` は時計とゲージだけ）ので、予測を commit してから読めば読み直しの規則（[design-reread-prediction.md](design-reread-prediction.md)）で根拠にできる。
- 最小構成か: 観測したい事象（デルタにクリティカルダメージ▲が付くか）のほかに、比で消えない未確定の要素は無い、という読み。ただしエマ：TU は「機構が確定したキャラ」（AGENTS.md）ではないので、この読みで結論を作ってよいかはオーナーに聞く（論点 4）。

### 4.2 録画 020 の読み直し（マナ S2）

- 見るもの: フルバースト開始から 10 秒の、デルタの発と発の間（AI。的の上の数値の出るフレームか、HUD の増分で読む）。チャージが 0.18 秒（ゲーム内の時計。C-0140）短くなれば、外より約 11f 短い。
- 未確定の要素: エーテル（291）は定義が無い。S1（受けるダメージ▼）・S2（敵へのダメージ・防御力▼）・バースト（バリア）は、どれもデルタの射撃の間隔に効かない。デルタの 3 スロットはダメージに効かない（C-0081）。マナのほかの効果（攻撃力▲・攻撃ダメージ▲・ゲージ速度▲）も間隔に効かない。
- 既に読んだ値: デルタの射撃の間隔は読んでいない（020 の観測値は時計・ゲージ・ジャンプ）。
- 同じ読みの手がかり: 録画 043（5 人。読み済み）のアリスの間隔（verification.md Stage 11 アリス節）は、マナの回の 101f が −0.18 秒で説明でき、アリスの回は 22f の見込みに対して 24f（チャージ時間の下限の可能性。未確定）。多人数で未確定の要素が混ざり、値を見た後の話なので、仮説の出どころにとどめる。
- 最小構成か: エーテルが「機構が確定したキャラ」でない点だけが外れる（論点 4）。

### 4.3 ミランダのバースト（撮影が要る）

既存の録画では見られない。最小構成の案（論点 4 で読み直しの道を選んでも、ミランダはこちら）:

- 編成: ミランダ（宝物 3。操作）+ バースト II の味方 1 体。宝物のバーストは 2 機なので、自分を除く候補 1 体 + 足りない分の自分、の両方が 1 本で見える。III を入れないのでフルバーストは起きず、宝物 S2（フルバースト開始時）は発動しない。
- 味方の候補: デルタ（II・SR。3 スロットともダメージに効かない。C-0081）。
- 見るもの: ミランダのバーストから 10 秒の、ミランダ自身の 1 ヒット（攻撃力▲・クリティカルダメージ▲が乗るか）と、デルタの 1 ヒット（同じく）。
- 「自分を除く」そのものを見分けるには、ミランダが攻撃力 1 位で、2 体目以降に付くかを見る 3 人の編成が要る（基礎のバースト 1 機の型）。これは上の 1 本の後に決める。

## 6. リスク

- 部隊の絞り込みは、結論ができると**計算の数値が下がる方向に変わる**（エマ：TU・ウンファ：TU を他の部隊と組んだ編成）。結論が仮説のまま入れるなら、画面の `assumes` で仮定と出す（ラムの S1 と同じ扱い）。

   - **決定（2026-10-05）: 推奨どおり**。

   - 推奨: `stat: "chargeSpeed"` + `scaling: "flat"`（秒）。既存の `chargeTimeFlat` の欄にそのまま足せ、新しい stat が要らない。

   - **決定（2026-10-05）: 推奨どおり**。
