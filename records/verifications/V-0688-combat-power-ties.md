# V-0688: 戦闘力が同じキャラの、実機の一覧での順

- 問い: 実機のニケ一覧を戦闘力順にしたとき、戦闘力が同じキャラはどの順に並ぶか
- 話題: 育成・ステータス
- 結論: `C-0989`
- 日付: 2026-11-07
- 状態: 完了

## 条件

- 型: 撮る（実機のニケ一覧の画面録画。戦闘はしない）。派生元は V-0685（「分からないこと」の一覧の並び）と [design-combat-power-sort.md](../../plan/design-combat-power-sort.md) 6.3 節（今は戦闘力が同じキャラを仮に名前順にしている）。
- 戦闘力の値: 撮る日に、撮る前に取った育成データ（`npm run build:fetch`）の `combat`。V-0685 の式で全キャラの値が一致するので、一覧の戦闘力はこの値とみる。戦闘力が同じ組は、この取得から出す。
- 仮説の出どころ: 2026-10-24・10-29 の取得に、戦闘力が同じ組がある（2〜4 体）。組の中のキャラは、凸・コア・Lv が同じで、キャラの番号（CDN の `name_code`。キャラのデータの `nameCode`）・`resourceId`・名前・属性・企業・武器・バーストの段階が違う。取得の API（GetUserCharacters）が返す順は番号の順ではなく、取得の回によって組の中の順が入れ替わる。どの組かはオーナーの育成の状況なので、この記録には書かず、読むときに取得から出す。
- 仮説（どれも合わせ込みの定数を持たない。読む前に挙げた）:
  - H-code: キャラの番号の昇順（または降順）
  - H-rid: `resourceId` の昇順（または降順）
  - H-name: 名前の順（今の画面の仮置き）
  - H-attr: ほかの並べ替えの鍵（属性・バーストの段階・クラス・武器・企業・レアリティ）の順
  - H-acq: 入手の順など、データに無い順（取得の API の返す順を含む）
  - H-none: 決まった順が無い（開き直すと変わる）
- 撮る日の取得に戦闘力が同じ組が無ければ、この撮影では答えが出ない（次の取得で組ができるのを待つ）。
- 2026-10-29 の取得の組のうち 2 つは、番号の大小と `resourceId` の大小が逆なので、H-code と H-rid を見分けられる。

## 予測

なし（組はオーナーの育成で決まり、撮る日の取得まで分からない。読むときに、組ごとに仮説の並びを出して比べる）

## 読み方

- 録画から、戦闘力が同じ組ごとに、一覧に出た順（上から）を読む。組の前後のキャラの戦闘力が取得と合うことも見る（一覧の値と取得の値が同じ時点のものかの確かめ）。
- 仮説ごとに、組の中の並びを取得とキャラのデータから出し、全部の組で読んだ順と同じになる仮説を残す。降順の 2 本が食い違えば H-none。
- 昇順の録画では、組の中の順が降順のちょうど逆か（並べ替えの鍵の全体を逆にしているか）、同じままか（2 つ目の鍵は向きを変えないか）を見る。
- 反復: 仮説はどれも合わせ込みの定数を持たず、読む前に挙げたので、1 本の中の組ごとの並びをそれぞれ再現に数える（[verification-guide.md](../../plan/verification-guide.md) 2.2 節の `parameterFree`）。H-none は、降順と昇順の 2 本で、組の中の順が仮説どおりに決まっているかで見る。

## 分かったこと・分からないこと

- 分かったこと（C-0989）: 実機のニケ一覧の戦闘力順で、戦闘力が同じキャラの順は、手元のデータにある鍵（キャラの番号・`resourceId`・名前・属性・バーストの段階・クラス・武器・企業・レアリティ・取得の API の順）では決まらない。昇順は降順の全体の逆。
- 分からないこと: 実機が使っている 2 つ目の順（入手の順・アカウントのキャラごとの通し番号のような、取得に出ない値か、安定しない並べ替えの結果か）。一覧を開き直したときに変わるかは見ていない（観測したい事象に要らない手順として撮っていない）。
