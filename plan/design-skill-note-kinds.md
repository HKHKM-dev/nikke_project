# スキル定義の notes に種類を持たせる

- 関連: [skills-guide.md](skills-guide.md) 1.2 節（説明文の分け方）・1.5 節（定義を書く）、[requirements.md](requirements.md) 5.2 節（当面扱わないもの）、[backlog.md](backlog.md) 6 節
- 作成日: 2026-10-04
- 根拠: 計算の数値は変えない（notes と `support` の表示だけを変える）。分けの判断に使う結論は 3 節の表の各行に書く
- 状態: オーナーの承認（2026-10-04。6 節の論点はすべて推奨どおり）で実装した。件数は生成物 [skills.md](skills.md) の冒頭に出る

## 1. 何が困っているか

- 定義のスロットの `support`（`supported`・`partial`・`unsupported`）と notes の自由文だけでは、扱っていない効果が **ダメージに関係しないから外した** のか、**モデルの前提（静止単体ボス・被弾なし）では起きないから外した** のか、**ダメージに効くのにまだ手を付けていない** のかが、データから分からない。
  - 例: デルタ（20）は 3 スロットとも「ダメージに関係しない」（C-0081 で確定）だけなのに `unsupported` で、画面には「未対応」の印が出る。ココア（311）・ラム（822）の S2・バーストも同じ。
  - 例: ユニ（160）のバースト・クラウン（330）の 3 スロット・モダニア（260）のバーストは、残りが「ダメージに関係しない」だけなのに `partial`。
  - 画面（`SkillSection.tsx`）は notes の全行に「未対応」の印を付ける。「防御力▲はダメージに関係しない」にも「未対応」と出る。
- notes の理由が古くなっているものがある（4 節）。語彙が足された後も「語彙に無い」と書いたまま。

## 2. 案

### 2.1 notes の種類 `kind`（必須）

notes の 1 行に、次の 4 つのどれか 1 つを持たせる。1 行に種類の違う中身が混ざっているものは行を分ける（3 節）。

| `kind`          | 画面の印     | 意味                                                                                                                                              | 例                                                        |
| --------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `unimplemented` | 未対応       | モデルの前提の中で起き、ダメージに効く（効きうる）のに、定義に入れていない。理由（語彙が無い・撮っていない・きっかけが説明文に無い など）を添える | ミランダの S2、マナのバースト、ヘルムの回復               |
| `outOfScope`    | 前提の外     | モデルの前提（要件 5.2 節。静止単体ボス・被弾なし・味方が倒れない・パーツ／阻止部位／バリアなし）では起きない・効かない                           | 被弾の回数のトリガー、貫通、阻止部位、パーツ、バリア      |
| `noDamage`      | 計算に無関係 | どの編成・どの敵でも与ダメージを変えない                                                                                                          | 防御力▲・最大HP▲・挑発・デコイ・敵の攻撃力▼・遮蔽物の回復 |
| `modeling`      | 補足         | 扱っていない効果ではなく、扱い方の補足（どこから入っているか・近似）                                                                              | 「フルバーストタイム 5 秒▼は burst_duration から入る」    |

- 画面の印「計算に無関係」は、育成の注記（`BuildSection.tsx`）の印に合わせた。
- 回復（味方の HP 回復）は `noDamage` にしない。「回復を受けた時」（`healed`）の効果を持つ味方（アスカ S1・クラウン S2）がいると発動を変えるので、語彙 `heal` で定義していない回復は `unimplemented`（論点 2）。
- バリア（味方に張る）は `outOfScope`。アスカ S2 の「自分がバリア適用状態なら」のように、バリアを条件にする効果がある（要件 5.2 節のシールド）。

### 2.2 `support` は notes から決める（論点 1）

`support` を手で書かず、定義を読むときに効果と notes から決める（1 つの事実を 1 か所に）。

| 効果 | `unimplemented` の notes | `support`          | 画面の印 |
| ---- | ------------------------ | ------------------ | -------- |
| あり | なし                     | `supported`        | 対応     |
| あり | あり                     | `partial`          | 一部対応 |
| なし | あり                     | `unsupported`      | 未対応   |
| なし | なし                     | `noEffect`（新設） | 対象外   |

- `noEffect` は「モデルの前提の中でダメージに効く効果が無い」スロット（notes が `noDamage`・`outOfScope`・`modeling` だけ）。notes が 1 行以上要る（何も書かずに空にしない）。
- JSON の `support` の欄は消す。残っていたら読み込みで落とす（古い定義の取り違えを防ぐ）。
- 宝物版の定義が無いスロット（`skills/treasure.ts`）は、今と同じく `unsupported`。
- コードの `support === 'unsupported'` で効果を飛ばしていた箇所は、効果が空なら何もしないので外した（`noEffect` でも同じ結果）。

### 2.3 表示

- スキル欄（`SkillSection.tsx`）: notes の印を `kind` ごとに出す（未対応・前提の外・計算に無関係・補足）。
- 未対応・近似・仮定の一覧（`NotesSummary.tsx`）: スロットが `supported`・`noEffect` でも、`unimplemented` と `outOfScope` の行は出す。`noDamage`・`modeling` は一覧に出さない（スキル欄で見られる）。`noEffect` のスロットは、前提の外の行のほかは出さない（知らせることが無い）。
- 生成物 [skills.md](skills.md): notes の行に種類を出す（`notes[0] 未対応: …`）。冒頭の件数に、種類ごとの件数と、`unimplemented` のあるキャラ × スロットの数を出す。

## 4. 見つかった古い記述・定義のずれ

- a. ラピ S2 の「倍率ダメージは burst スロットの burstDamage だけが扱える」: S1・S2 の倍率ダメージは `damage`（ドレイク S2 など）で書ける。外している本当の理由は、説明文にきっかけが無いこと（イサベル S2 と同じ）。
- b. 「敵デバフは語彙に無い・スコープ外」（エマ S1・ウンファ バースト）、「部隊の条件は語彙外」（ノワール バースト）: どちらも語彙を足した後（`damageTaken`・`squad`）。理由を直し、`unimplemented` に入れる。
- c. エマ S2 の発射体爆発ダメージ▲: `projectileExplosionDamage` はアニス：スターで足した。
- d. エマ S2・ウンファ S2 の「同じ部隊の味方全体に」のクリティカルダメージ▲・クリティカル確率▲は、定義では `target: allies`（味方全体）になっている。`squad` は「同じ部隊の味方が 1 体以上いるか」の条件で、対象を同じ部隊に絞る語彙ではない。**この設計では定義の効果は直さず**、`unimplemented` の notes で「対象の絞り込みが未実装（いまは味方全体）」と明記する（計算の数値を変えない。論点 3）。
- e. マナ S1 の「10 回攻撃ごとの味方回復は前提では起きない」: 通常攻撃 10 回は起き、マターガンマは味方が倒れない限り続くので起きる。回復を受けた時の効果を持つ味方がいれば効く。
- f. アスカ バーストの「弾丸命中率には効かせていない（未実装）」: 命中率▲を AR・SMG・MG の弾丸命中率に効かせた（C-0192）後も残っている。

## 5. 実装

1. `skills/types.ts`: `SkillNote` に `kind` を足し、`parseNote` で検証。`SkillSupport` に `noEffect` を足す。`parseEntry` で `support` を導き、JSON に `support` があれば落とす。`noEffect` で notes が無ければ落とす。
2. `support === 'unsupported'` で飛ばしていた箇所（`burstDamage.ts`・`cycles.ts`・`resolve.ts`・`types.ts`）は、効果が空なら何もしないので判定を外す（`burstDamage.ts` の早い戻りは `effects.length === 0`）。
3. 定義 27 ファイル: `support` を消し、notes に `kind` を付け、3 節の表どおりに分け・直す。
4. `records/skills.ts`: skills.md に種類と件数を出す。
5. 画面: `skillLabels.ts` の `SUPPORT_BADGE` に `noEffect`、notes の印の表。`SkillSection.tsx`・`NotesSummary.tsx`（2.3 節）。
6. [skills-guide.md](skills-guide.md) 1.2・1.5・4 節を種類に合わせて書き直す。[backlog.md](backlog.md) 6 節の表は skills.md の `unimplemented` を正にして、行を絞る（論点 4）。
7. テスト: 型の検証（`kind` が無い・`support` がある・`noEffect` で notes が無い）、`support` の導き方、既存のテストの数値が変わらないこと。

## 6. 論点
