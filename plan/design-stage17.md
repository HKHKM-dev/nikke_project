## 1. 何を決めるか

- **射撃場の的（BigArms）に対する AI の枠の、武器種ごとのコア命中率と距離ボーナス**（既定値）。
- 操作キャラの枠は人の撃ち方で変わるので、入力のまま（既定はコア命中率 1。距離ボーナスは AI と同じ規則）。
- ボス（迎撃戦）は的の形・動きが違うので、この Stage では扱わない（Stage 15 の 15-B で、ボスのプリセットに持たせる）。

## 2. 読み方

1. **1 ヒットの値を区間で抜き取って読む**。スペック固定の攻撃力から、そのキャラの 1 ヒットの値は「コア × 会心 × 距離」の最大 8 通りに決まる。HUD の的の上のダメージ表示を、録画の最初・中ほど・最後の 3 か所（各 5 秒前後）でコマ送りして読み、どの組み合わせかに分ける（Stage 2-A のフォルクヴァンと同じ方法。切り出しは `tools/captures/still.ts`）。
   - 数えるもの: コアに当たったヒットの割合、距離ボーナスが乗ったヒットの割合（区間ごと。立ち位置が変わるかも見る）、会心の割合（15% 前後なら読み方が正しいことの検算）。
   - SG はペレットの値の和になるので、1 トリガーの値を「ペレット数 × 組み合わせ」の整数の和に分ける（録画 11 のノワールと同じ）。当たったペレットの数も同時に分かる。
2. **戦闘履歴の合計で照合する**。読んだ割合を条件に入れた sim の合計と、戦闘履歴パネルのそのキャラの与ダメージを並べる（係数を合わせに行かない。ずれは射撃の数・ジャンプの位相などの別の要因として残す）。
3. **読み方の検算**: 操作・コア狙いの録画（23・28・31・32）でコアの割合が 1 に近く、操作・胴体の録画（24・29・33・34）で 0 に近いことを確かめてから、AI の録画を読む。

## 4. モデルへの入れ方

1. **既定の条件を「武器種ごとの射撃場の値」にする**。置き場所は敵のプリセット（`data/enemies.json` の射撃場の行）に `aiCondition: { [武器種]: { coreHitRate, distanceBonus } }`（仮称）を足し、出どころ（録画番号）を書く。ボスのプリセットは、測るまで持たせない（持たないときは今の既定）。
2. **枠の条件は「自動」と「手入力」を選べるようにする**。自動は、敵のプリセットの値（AI の枠）か、操作キャラの既定（コア命中率 1）。画面の条件欄には、自動のときに使っている値を出す。
3. **距離ボーナスの既定を確定済みの結論に合わせる**（射撃場では AR・SMG だけ）。読み取りで AI の立ち位置が変わることが分かったら、割合（0..1）で持つ形にするかを 8 節の 5 で決める（いまの型は真偽）。
4. CLI は `--core-hit-rate` / 距離の指定を省略したとき、画面と同じ自動の値を使う。
5. 保存済みの編成は条件を数値で持っているので、読み替えが要る（8 節の 5）。

## 5. 段取り（1 PR。撮影は PR の前）

2. 撮影（3 節の 3 本）と読み取り。予測は撮る前に出す。
3. 型・プリセット・画面・CLI・保存形式（4 節）。既定の変更で数値が変わるテストは、変わる理由を書いて更新する。
4. 確かめ: 録画 39・41・46・48〜50（15-A）・51〜53（15-B）の予測を新しい既定で出し直し、変化を記録する（15-A・15-B の残差は分解しない。値を並べるだけ）。
5. README の「精度と未対応」と、画面の条件欄の説明を更新する。

## 8. 決めてほしいこと（2026-09-26 に 7 点とも推奨案で承認）

1. **次のタスクにするか・番号** — 推奨: **これを Stage 17 にする**。全員に効く条件の既定を先に決めないと、単騎の切り分けを 1 体ずつ進めても同じ要因が毎回混ざる。別案は Stage 15 の続き（15-C）として design-stage12.md に書く。
2. **決める範囲** — 推奨: **射撃場の AI の枠のコア命中率と距離ボーナス（武器種ごと）だけ**。操作キャラは入力のまま、ボスは 15-B で。
3. **読み方** — 推奨: **1 ヒットの値を 3 区間で抜き取って読み、戦闘履歴の合計で照合**（2 節）。別案は合計だけから逆算する方法。コアと距離の 2 つが同時に未知なので、合計だけでは分けられない。
4. **撮影** — 推奨: **既存の AI の 4 本を先に読み、SMG（リター）・RL（紅蓮BS）・MG の 2 体目（クラウン）の 3 本だけ撮る**（各 180 秒、3 分モード、スペック固定 ON）。
5. **既定の持ち方と保存済みの編成** — 推奨: **射撃場のプリセットに武器種ごとの値を持たせ、枠の条件は「自動 / 手入力」**。保存形式は版を上げ、旧版の「コア命中率 1・距離あり」は自動に読み替える（それ以外の値は手入力として残す）。距離が区間で変わると分かったら、割合で持つ。
6. **公開サイトの数値が変わること** — 射撃場のプリセットでは、MG・SR・SG の距離ボーナスが外れ、AI のコア命中率が 1 未満なら、既定の数値が下がる。推奨: **変える**（確定済みの結論に合わせる変更で、実測との差が縮むかどうかに関係なく入れる）。
7. **SG のペレットの当たり数** — 推奨: **録画 26・27 の読み取りで数えて記録するだけ**にし、ダメージへの反映（今は全ペレット命中）は結果を見て別に決める。

### 9.3 読み取りを受けて決めてほしいこと（2026-09-26）

1. **3 分モードの距離ボーナスの持ち方** — 推奨: **承認どおり割合で持つ**（3 分モードの出来事のセットに武器種ごとの割合。SMG 0.77・MG 0.23）。AR・SR・SG の遠い区間は測っていないので、初期位置の値のまま（未測定の注記）。別案は、着地点（近い / 遠い）の列を出来事のセットに持たせ、区間ごとに距離ボーナスを切り替える（16-B で未実装にした「着地後の距離」）。こちらは正確だが、距離を時刻で変わる条件にする変更（共通のフレームループ・区間の鍵）が要り、AR・SR の遠い区間の値も要る。
2. **未測定の武器（SG のコア命中率）の既定** — 推奨: **今の既定（1）のままにし、未測定の注記を出す**。
