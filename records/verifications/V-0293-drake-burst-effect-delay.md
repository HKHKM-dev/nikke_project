## 条件

**何を確かめるか**

- 遅れの表（`burst/landing.ts` の `MEASURED_BURST_DELAYS`）のドレイク（宝物あり）の行は、効果の遅れが 0（未測定）。ヒットの遅れ（4f）は C-0228 で確定した。バースト使用時の効果（宝物版の burst の effects[1] の攻撃ダメージ▲と effects[2] の最大装弾数▲）が、III の発動のフレームで付くのか、ヒットと同じフレームで付くのかを、V-0202 の録画 `222` を読み直して確かめる（2026-10-07 にオーナーが別の作業と決めた）。
- V-0202 では、効果は 1 発の値に出ないとして読んでいない。`222` の既にある観測値（`222-01`〜`222-07`）は、ヒットの時刻と値だけで、ドレイクの通常攻撃の発の値と残弾は読んでいない。

**編成**

- 録画 `222`: ココア（311。I）+ デルタ（20。II）+ ドレイク（101。III・操作・宝物あり（段階 3）・AUTO 射撃 ON）、オートバースト ON。射撃場・灼熱の BigArms・3 分モード・スペック固定。
- **最小構成**: ココアは定義が効果なし（V-0031）、デルタは C-0081 で、どちらも機構が確定している（V-0202 で `minimalWarnings` に警告なし）。観測したい事象（ドレイクの発の値と残弾が替わるフレーム）に効く未確定の要素は、ドレイクのバーストの効果の時刻だけ。

**読み方の前提**

- III の発動は、III のタイマーが 00.00 になったフレーム（V-0078・V-0082・V-0137。`222-01` の f1255・3636・6016・8395・10810）。フルバーストの入りの止まり（C-0069。モデルは 22f）の中は、射撃もダメージも止まる（C-0071）。モデルのフレームへの換算は、動画のフレームの差から、止まりの後なら 22 を引く。
- ヒットは止まりの明けの 4f 後（`222-01` の 26f）。ドレイクの発（SG。モデルでは約 39f おき）が、止まりの明けからヒットまでの 4f の間に来た回だけ、「発動で付く」と「ヒットで付く」を発の値で見分けられる。来なければ、ヒットの後の最初の発に▲が付いていることしか言えない。
- 発の値（HUD の総ダメージの増分）は、10 ペレット（コアと胴体の混ざり）と S2 の倍率ダメージの和なので、1 発ごとに揺れる。フルバーストの始まりには、S1 の攻撃力▲（宝物版の skill1）とフルバースト補正も同時に乗る。攻撃ダメージ▲の有無は、同じ回のヒットの前の発と後の発の比で見る。モデルの 1 ペレット（胴体・会心なし・距離ボーナスなし）は、発動の 1f 後で H0 なら 89,140.9、効果の遅れを 4 にして回すと 67,695.1 で、比は 1.3168（攻撃ダメージ▲ 31.68%。予測ファイルの範囲外の手の計算）。
- 最大装弾数▲は、残弾を増やさず次のリロードで新しい最大まで込める形（C-0364・C-0369。ほかのキャラ）なら、照準の横の残弾には次のリロードの後にしか出ず、発動とヒットの 4f の差は見えない。付いたフレームで残弾が増える形なら、増えたフレームが効果の発火になる（止まりの中でも表示が替わるかもしれない）。
- 指標 `burstEffectFirstShot`（この PR で足した。`packages/core/src/records/observations.ts`）を `fromShot: true` で使い、発動の後の最初の発から、効果の発火以後の最初の発までのモデルのフレーム数を比べる（効果の遅れが発の間に収まれば 0）。

## 予測（撮る前に書く）

読む前に書いた（2026-10-07）。H0 はいまのモデル（効果は III の発動のフレームで付く）で、値は予測ファイル（records/predictions/V-0293.json）。モデルでは、5 回とも発動の後の最初の発が 4f より後（ヒットの後）なので、効果の遅れを 4f にしても予測ファイルの値は変わらない（遅れの表で切り替わる仮説なので、ファイルの範囲外。下の E1 を手で書く）。

| 仮説                                           | 止まりの明けからヒットまで（モデルで 0〜3f）に来た発                         | ヒットの後の最初の発 | 各回の `effect-first-1`〜`effect-first-5`（モデルのフレーム） |
| ---------------------------------------------- | ---------------------------------------------------------------------------- | -------------------- | ------------------------------------------------------------- |
| H0: いまのモデル（発動のフレームで付く）       | 攻撃ダメージ▲の付いた値（ヒットの後の発と同じ格子）                          | ▲の付いた値          | 0                                                             |
| E1: ヒットと同じフレーム（発動の 4f 後）で付く | ▲の無い値（ヒットの後の発の 1 /（1 + 攻撃ダメージ▲）倍。S1 の▲・補正は乗る） | ▲の付いた値          | その間に発が来た回だけ、その発から次の発までの間隔            |
| E2: ヒットより後で付く                         | ▲の無い値                                                                    | ▲の無い値の発がある  | 0 より大きい                                                  |

最大装弾数▲（手で書く。予測ファイルの範囲外）:

| 仮説                                        | 照準の横の残弾                                                             |
| ------------------------------------------- | -------------------------------------------------------------------------- |
| M0: 残弾を増やさない（C-0364・C-0369 の形） | 発動の前後で 1 発ずつ減るだけで、次のリロードの後に▲の付いた最大まで込める |
| M1: 付いたフレームで残弾も増える            | 発動の前後のどこかで、撃たずに残弾が増える（そのフレームが効果の発火）     |

- **H0 と M0 を予想する**。ラピの攻撃力▲は 1 ヒット目より前に付き（V-0201 の `221-08`）、マナの効果は発動の 2f 後だった（C-0301）ので、バースト使用時の効果は発動の近くで付くとみる。ただしイサベル・ニヒリスターは効果がヒットと同じフレーム（C-0165・C-0219）で、根拠は弱い。最大装弾数▲はほかのキャラ（C-0364・C-0369）と同じ形とみる。
- 止まりの明けからヒットまでの 4f に発が来る回は、5 回のうち 0〜1 回の見込み（発の間隔の約 39f のうち 4f）。来なければ、H0 と E1 は見分けられない（E2 だけを外せる）。
- 1f の揺れは録画の重複フレームの位置で出る（V-0137）ので、± 1f を合うとみる（観測値の許容 `abs: 1`）。
- 当たったときの影響: H0 なら、遅れの表のドレイクの行の効果の遅れは 0 のまま（見分けられた回があれば、未測定の注記を外せる）。E1 なら効果の遅れを 4 にする（ヒットの前の発が▲なしになる）。
- 外れたときの影響: E2 なら、効果がヒットより後に付くので、遅れの値を探して表に入れる。M1 なら、最大装弾数▲で残弾が増えることになり、モデル（残弾は増やさない）を見直す。

## 読み方

1. `npm run records:read -- 222 --recipe hud-jumps --source V-0293` で HUD の増分を取る。各回の止まりの明け（`222-01` の発動のフレーム + 22 前後）の前後で、ドレイクの発の増分（桁が SR のココア・デルタと違う）を並べる。
2. 各回の発動の前の最後の発、止まりの明けからヒット（`222-02`〜`222-06` の 1 ヒット目）までの発、ヒットの後の 2〜3 発の値とフレームを取る（記録の観測値。`record`）。
3. ヒットの前に発があった回は、その発の値がヒットの後の発の値と同じ格子か、1 /（1 + 攻撃ダメージ▲）倍かを見る。各回の「発動の後の最初の発 → ▲の付いた最初の発」（モデルのフレーム）を観測値（`burstEffectFirstShot`。`args` は予測ファイルと同じ。許容 `abs: 1`）にする。
4. 照準の横の残弾を `reticle-ammo.ts` で発動の前後と、その後の最初のリロードの完了まで読み、撃たずに増えたフレームがあるかと、リロードの後の最大を取る（記録）。

- ドレイクの発かは、照準の横の残弾が FULL BURST の表示の前後で 1 減ったこと（2 回目は 2 → 1。5 回目は残弾 1 の発の後にリロード）と、値の格子で決めた（ココア・デルタの発はモデルの SR の 1 発の値と合う別の増分）。
- 2 つの発の値（1,022,149・1,129,117）は、どちらも攻撃ダメージ▲の付いたモデルの 1 ペレット（1 ペレットずつ丸める）の 6・7 個の和と端数まで合い、▲の無い 1 ペレットのどの和とも 800 以上離れる。H0（発動のフレームで付く）と合い、E1（ヒットで付く）・E2（ヒットより後）は外れた。モデルのフレームでは 3f・1f（止まり 22f を引いた値）で、効果の遅れは 0〜1f。
- 1・3・4 回目は、発動の後の最初の発がヒットの後で、▲の付いた値（`222-08`・`222-10`・`222-11`）。どの仮説でも 0 なので、比べの表の 5 つのうち見分けたのは `222-09`・`222-12` だけ。3 回目はヒットの 2f 前に 539,659 の増分があるが、ドレイクの格子に乗らず（▲の有無どちらでも）、この回の残弾の減りは 1 発でヒットの 1f 後の発（742,842）に当たるので、ドレイクの発ではない（何の増分かは読んでいない）。
- 最大装弾数▲（`222-14`）: 発動の前後で残弾は増えず、間のドレイクの発の数だけ減った（M0。M1 は外れた）。発動の後の最初のリロードは、▲の付いた最大 20 まで込めた（▲の前は 9。モデルの maxAmmoAt も 9 → 20）。1 回目はリロードの途中に発動が来て、段ごとの込めが 3 から 7 ずつ（round(0.33 × 20)）に替わった。残弾では、効果の時刻は発動の後 38f までとしか言えない。
- 結論: C-0420（確定・厳密一致）。遅れの表のドレイクの行の効果の遅れは 0 のまま（注記の「未測定」を外した）。

## 分かったこと・分からないこと

- **C-0420（確定・厳密一致）**: ドレイク（宝物あり）のバーストの攻撃ダメージ▲は、ヒット（発動の 4f 後）より前に付き、止まりの明けの 1f 後の発にも乗る。最大装弾数▲は残弾を増やさず、その後のリロードで 20 まで込める。
- 止まりの中は発が無いので、発動のフレームと止まりの明けの間のどこで付くかは見分けられない（V-0201 のラピと同じ）。
- 分からないこと: 宝物なしのドレイクのバースト（撮れない）。3 回目のヒットの 2f 前の増分 539,659 が何か。
