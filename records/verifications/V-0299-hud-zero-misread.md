## 予測（撮る前に書く）

探索（旧の読みの再点検。予測なし）。見立ては次のとおり。

- ずれるのはバーストのヒット側だけで、1more と追撃のヒットのフレームは hud.ts と同じ（大きな増分の後は HUD が読めている）。直すと、`258-09` の 5 回目は 47 → 48f、`259-10` の 2 回目の 1more は 46 → 48f、追撃は 102 → 104f になる（V-0292 の「結果」）。

- 1more の差が 48f、追撃の差が 104f のままなら、モデル（`data/skills/871.json` の `delayFrames: 26`・`870.json` の `82`。V-0292）は変わらない。

## 読み方

1. 各録画の HUD（crop=300:38:810:34）を、バーストのヒット・1more・追撃のヒットの前 6f〜後 3f で 1 フレームずつ並べ（ffmpeg の select=between(n,…)・crop・tile）、値が増えたフレームを読む。
2. `node tools/captures/hud.ts <動画> --mode series` で、ずれた回の前後の読みと、落とした読み（「x」）を見る。
3. 差を観測値（`kind: interval`・`use: record`）にし、旧の観測値に `invalid` を付ける。

## 分かったこと・分からないこと

- **hud.ts は HUD の 0 を 8 と読むことがあり、そのフレームは読みを落として、次に読めたフレームを増分のフレームにする**。大きな増分（バーストのヒットなど）のフレームが 1〜34f 後ろにずれる。値（増分）は変わらない。フレームの差を観測値にするときは、HUD を並べた一覧で確かめる（plan/captures/guide.md に足した）。
- 雪子の S1 の 1more は、バーストのヒットの 47〜48f 後（`C-0428`）。クイーン（真）の S1 の追撃の分配ダメージは 103〜104f 後（`C-0429`。仮説のまま。確定にする条件は C-0361 と同じ）。
- 分からないこと: hud.ts の 0/8 の誤読を、見本（`hud-templates.json`）か照合の側で直せるか。ほかの観測値（hud.ts --mode jumps のフレームを使ったもの）に同じずれが無いか。
