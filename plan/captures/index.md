# 録画台帳

- 関連: [../verification.md](../verification.md)、[../../tools/captures/](../../tools/captures/)
- 目的: 録画 1 本ごとに「誰を・どの条件で撮ったか」と「その録画がどの実測値の根拠か」を固定する。動画そのものは Git に入らないため、この台帳と `frames/` の証拠フレームが唯一の追跡可能な記録になる。

## 置き場所

録画は容量が読めないので D: のリポジトリには置かず、**E:（2.8TB HDD）に集約する**。リポジトリ側に残すのは台帳と証拠フレームだけ。

```
E:/record/nikke/                未分類の生録画（既存アーカイブ。Xbox Game Bar の元名のまま）
  動画/                         269 本・約 110GB
  命中/ リザルト/ …              過去の検証素材

E:/nikke_project_captures/      このプロジェクトが採用した録画（種別ごとに分ける）
  range/                        射撃場（1 ヒット・発射サイクル）
  raid/                         ソロ / ユニオンレイドの実戦
  skill/                        スキル発動・バフ持続
  burst/                        バーストゲージ・フルバースト
  ui/                           ステータス画面・ShiftyPad などの画面録画

D:/nikke_project/plan/captures/ リポジトリ側（Git 追跡）
  index.md                      この台帳
  frames/*.jpg                  証拠フレーム
```

種別フォルダは必要になった時点で作る（現状あるのは `range/` だけ）。**種別の語彙はこの一覧に足してから使う。** 台帳の「用途」列と対応させる。

### 運用

1. 撮る → Xbox Game Bar が `E:/record/nikke/` に吐く。検証に使わないものはそのまま置いておく。
2. 検証に採用した録画は `E:/nikke_project_captures/<種別>/` へ**移動**し、規約名を付ける。`E:/record/nikke/` 側には残さない（同じ録画が 2 箇所にあって食い違う状態を作らない）。
3. 台帳に 1 行足し、証拠フレームを `plan/captures/frames/` に切り出してコミットする。
4. Google Drive に同期する（下記）。

## バックアップ

`E:/nikke_project_captures/` を Google Drive にバックアップする。Google Drive for desktop がストリーミングモードで 2 アカウント分マウントされている。**使うのはメインアカウント側の `I:`**（222GB プラン）。`J:` は別アカウント（15GB プラン）なので使わない。

```bash
robocopy "E:/nikke_project_captures" "I:/マイドライブ/nikke_project_captures" /MIR /R:1 /W:1
```

- `/MIR` はコピー先を**コピー元に合わせる**（コピー元で消したファイルはコピー先でも消える）。ミスでコピー元を消したときは、同期する前に気づくこと。
- 録画を足した / 消したタイミングで実行する。
- robocopy の終了コードは 0〜7 が正常（1 = コピーした、0 = 差分なし）。8 以上が失敗。

同期したら sha256 で中身を突き合わせる。`probe.ts` はどのディレクトリにも使える:

```bash
node tools/captures/probe.ts "I:/マイドライブ/nikke_project_captures"
```

2026-09-22 に初回同期を実行し、9 本すべて sha256 が一致することを確認済み。同日 15:07 に録画 10〜13 を足して再同期し（13 本）、新規 4 本の sha256 が一致することを確認済み。

## 命名規約

```
<YYYYMMDD>-<連番2桁>_<種別内の識別子>[_<補足>].<拡張子>
range の例: 20260922-04_AR_kurumi.mp4     （武器種_キャラ英名）
raid の例:  20260930-01_solo_5team-a.mp4  （モード_編成名）
```

- 日付＋連番は**その日の撮影順**（種別をまたいで通し）。Explorer でも時系列に並び、種別フォルダを移しても衝突しない。
- 識別子の付け方は種別ごとに決める。`range` は「武器種_キャラ英名」。キャラ名は `packages/core/data/characters/<rid>.json` の `name.en` を小文字ケバブ化する。
- 日本語・空白は使わない（ffmpeg にそのまま渡せるように）。
- 2 体以上を出撃させた録画は、武器種と英名をそれぞれ `+` で枠順に連結する（`20260922-11_SG+AR_noir+asuka.mp4`）。
- 条件違いの撮り直しだけ `_dist-out`（適正距離外）のような補足を付ける。
- 元の Xbox Game Bar 名は必ず下の表に残す。リネームは可逆。

## 撮影プロトコル（次回以降）

読み取り時の条件の取り違えを防ぐため、**録画の中に条件が写っている状態**にする。

1. 撮影前に、そのニケの部隊画面（攻撃力の表示値が見える状態）を 2〜3 秒撮る。
2. 射撃場に入ったら的の名前（`BigArms` 等）と属性が読めるフレームを含める。
3. 編成はそのニケ 1 体のみ。オートバースト OFF、移動・カバーなし、初期位置から撃つ。
4. 戦闘開始から最初のリロード完了後の 1 発目まで（15 秒以上）を含める。
5. 撮り終えたら即このファイルに 1 行追加する。**後からまとめて埋めない。**

スペック固定で撮る場合、攻撃力は `computeFixedSpecAttack` で決まるので 1 は省略できる。代わりに出撃画面（属性タブとスペック固定 ON の表示）と、戦闘後の一時停止画面（編成と Lv.400）を録画に含める（録画 10〜13 はこの形）。

## 誰が写っているかの確かめ方

見た目（立ち絵・ポートレート）でのキャラ同定は当てにならない。**弾数カウンターで武器種を確定させてから**台帳に書く。

1. 戦闘開始直後のフレームで、照準の左にある弾数カウンターを読む（位置は照準に追従するので録画ごとに違う）。装弾数で武器種がほぼ一意に決まる: MG 300 / SMG 120 / AR 60 / SG 9 前後 / SR・RL 6。
2. 武器種が決まれば、`packages/core/data/characters/<rid>.json` の `shot.damage`（÷10000 が武器倍率）と `element` から 1 ヒットの理論値が出る。画面に出ているダメージ数値と一致すればキャラまで確定する。

実例（この 9 本の同定に使った証拠フレーム）:

| 録画 | フレーム | 弾数 | 判定                | 証拠                                         |
| ---- | -------- | ---- | ------------------- | -------------------------------------------- |
| 03   | 800      | 298  | MG（300 発）＝エマ  | `frames/20260922-03_MG_emma_f800_ammo.jpg`   |
| 04   | 800      | 058  | AR（60 発）＝クルミ | `frames/20260922-04_AR_kurumi_f800_ammo.jpg` |

この 2 本は立ち絵だけで判断すると取り違えやすい（03 のエマは黒い軍服にベレー帽、04 のクルミは金髪でスーツケース型の銃とドローン）。実際に一度取り違え、弾数カウンターで訂正した。

## フレーム番号の約束

**フレーム番号は「デコードされたフレームの通し番号（0 始まり）」とする。** ffmpeg では `-fps_mode vfr` が相当する。`tools/captures/` のツールはすべてこの番号で統一している。

`-fps_mode cfr` で 60fps に引き伸ばすと重複フレームが挿入され、フレーム落ちのある録画（01・07）では番号がずれる。2026-09-22 の較正メモに残っている番号（SR の 551→633→715 など）は別の数え方で取られたもので、現在のツールの出力とは直接比較できない。**間隔（82f など）は一致するので、較正結果そのものは有効。**

## 解析ツール

```bash
node tools/captures/probe.ts                 # 全録画の素性を台帳用の表で出力
node tools/captures/still.ts <動画> --frame 947 --out out.png [--crop x,y,w,h] [--scale 900]
node tools/captures/diff.ts  <動画> --crop x,y,w,h [--from N] [--to N] --peaks [--csv out.csv]
```

`diff.ts` は指定領域のフレーム間差分を取り、閾値を超えた局所ピークをフレーム番号と間隔で返す。領域と閾値は録画ごとに調整が要る。2026-09-22 の較正で有効だった領域（1920×1080 での `x,y,w,h`）:

| 狙うもの               | 領域の目安        | 備考                                             |
| ---------------------- | ----------------- | ------------------------------------------------ |
| SR/RL の発射（反動）   | `300,780,700,280` | 手元。`--sigma 2 --min-gap 20`                   |
| AR の発射（反動）      | `760,620,360,300` | 同じ手元のパルス列。`--sigma 0.2 --min-gap 4`    |
| MG/SMG の命中          | `820,10,280,50`   | HUD 総ダメージカウンター。1 ヒットごとに更新     |
| ダメージ数値の読み取り | `940,220,400,180` | 的の周りに出る数値。`still.ts --crop` で切り出す |

残弾カウンターは数字がロール表示されて毎フレーム変化するので検出には使えない。

1 ヒットの値を読むときは、HUD 総ダメージカウンターを 1 フレームごとに並べて（`select='between(n,A,B)',crop=280:50:820:10,tile=6x30`）差分を取るのが速い。2 体編成では同じフレームに 2 人分が乗ることがある（録画 13 の 930,273 = 686,756 + 243,517）ので、単独で増えたフレームを探す。

## 証拠フレームの切り出し

各録画から 2 枚（全体像の 70% / 85% 地点）＋数値の拡大を `frames/` に置いてある。全体像は次のコマンドで作った。

```bash
ffmpeg -v error -i <動画> -vf "select='eq(n,<フレーム>)',crop=1260:420:340:0,scale=900:-1" \
  -fps_mode vfr -frames:v 1 -q:v 3 -y frames/<名前>_f<フレーム>.jpg
```
