## 1. 何を足すか

モラン（281）の S2 の前半（最後の弾丸で攻撃した時、最終攻撃力が最も高い敵 3 機に挑発 4 秒）は、付けたときに射手の `target_burst_energy_pershot`（5,000）を 1 回溜め、切れるときには溜めない（C-0480。確定・厳密一致）。挑発そのものはダメージに関係しないので、ゲージだけを入れる。

今の語彙では書けない。

- ゲージだけを溜める効果 `burstGaugeHit` は、時間の周期のトリガー（`{ everySeconds }`）しか持たない（design-flower-s2-gauge.md 2 節。「使うキャラが出たときに広げる」としていた）。
- 射撃の回数でゲージを溜める既存の形は、`damage` の `gaugeHits`（倍率ダメージのヒットのゲージ）と、`dot` の `gaugeOnApply`（持続ダメージを付けたときのゲージ）で、どちらもダメージの効果に付く。ダメージの無い挑発には使えない。

モランにはまだ定義（`data/skills/281.json`）が無い。この設計で定義を作り、C-0480 を S2 の効果に結び付ける。ほかの行は notes で書く（4 節）。

## 2. 語彙: `burstGaugeHit` のトリガーを射撃の回数に広げる

```json
{
  "kind": "burstGaugeHit",
  "trigger": { "count": "lastShot" },
  "assumes": { "ja": "…", "en": "…" },
  "claims": ["C-0480"]
}
```

- **意味**: 変えない。トリガーが発火するたびに、射手の 1 ヒットぶんのバーストゲージ（`targetBurstEnergyPerShot` × (1 + バーストゲージのチャージ速度)。フルチャージ倍率は乗らない）を足す。ダメージは出さない。ゲージが溜まる状態のときだけ足される（状態機械の規則のまま。C-0085 と同じ）。
- **書けるトリガー**: 時間の周期（`{ everySeconds }`。今まで）に、射撃の回数のトリガー（`ShotCountTrigger`）を足す。回数の種類（`count`）は `SHOT_COUNT_KINDS` のどれでもよいが、次の欄は書けない（検証で弾く）。
  - `during`・`reset`（`damage` だけの欄）、`stacksRef`（スタック自体に効果が無いときの欄）、`chance`・`chanceRef`（`timed` だけの欄）
  - `every` と `everyRef` は書ける（省略は毎回）。
- **発火のフレーム**: 射撃の回数のトリガーは、その射撃のフレームのゲージに足す。レイヴンの `gaugeOnApply`（撃ったフレームに置く）と同じ扱い。実測の 6f の遅れは入れない（5 節の論点 2）。
- **的を狙えない窓**: 射撃の回数のトリガーは射撃が無ければ発火しないので、窓の扱いは射撃のまま（足すものは無い）。

## 3. 実装

- `skills/types.ts`: `BurstGaugeHitEffect.trigger` を `TimerTrigger | ShotCountTrigger` にし、`parseBurstGaugeHitEffect` で上の欄を検証する。エラーの文言（`burstGaugeHit needs a timer trigger`）を、周期か射撃の回数を求める文言に替える。
- `skills/burstDamage.ts`: `resolveTimerGauges` は周期のトリガーの効果だけを返すように絞る。射撃の回数のトリガーの効果は、新しい `resolveShotGauges`（`everyRef` を Lv の値に解決した `ResolvedShotCountTrigger` の列）で返す。`unsupported` のスロットは空。
- `frame/firstPass.ts`: `resolveShotGauges` の効果を、`damageGaugeTrackers`（ヘルム編）と同じく射撃を数えて追い、発火した射撃のフレームのゲージに足す。飛ぶ時間（`shotFlightAt`）は足さない。付けるのは撃った時で、ヒットではないため（C-0480 は AR なので飛ぶ時間は 0 で、どちらでも同じ）。1 パス目は sim と calc で共有なので、calc の時刻表も同じになる。
- `records/relevance.ts`: `burstGaugeHit` の観測量の出どころは `burstTiming` のまま。
- 表示: Web とCLI には、ゲージだけの効果を出す欄が無い（フラワー編と同じ）ので足さない。
- テスト: `skills/__tests__/` に、検証のエラー（書けない欄）と `resolveShotGauges` の解決値の単体テスト。1 パス目で、最後の弾丸のフレームにだけ 5,000 が乗ることを見るテスト。

## 4. 定義（`data/skills/281.json`）

S2 の前半のゲージだけを効果にし、ほかの行は notes にする（5 節の論点 1）。宝物版（`treasureSkills`）の S2 にも同じ効果を書く（5 節の論点 3）。

| スロット           | 行                                                                              | 書き方                                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| S1                 | 戦闘開始時、自分に失った HP 1% ごとに防御力▲                                    | `noDamage`                                                                                                               |
| S1                 | 武器変更状態で通常攻撃が 5 回命中した時、対象に最終攻撃力の X% の追加ダメージ   | `unimplemented`（撮っていない。武器変更（バースト）の中の命中を数えるトリガーは `weaponChangeShot`（射撃の数）しか無い） |
| S1（宝物版）       | ラプチャーが出現した時、自分に熱血（バーストスキルのクールタイム 20 秒▼、持続） | `unimplemented`（語彙が無い。持続するクールタイム▼。撮っていない）                                                       |

| バースト           | 使用武器を変更（最終攻撃力の X% のダメージ、10 秒）・装弾数無限（10 秒）        | `unimplemented`（撮っていない。語彙は `weaponChange`・`timed` の `infiniteAmmo` がある）                                 |
| バースト           | 攻撃ダメージの X% 回復（自分）                                                  | `unimplemented`（回復を受けた時の効果を持つ味方の発動を変える。フォルクヴァンのバーストの吸収回復と同じ扱い）            |
| バースト           | ヘイト（敵全体を挑発）、味方全体に受けるダメージ▼・発動者基準の防御力▲          | `noDamage`                                                                                                               |
| バースト（宝物版） | 味方全体に発動者基準の攻撃力▲（10 秒）                                          | `unimplemented`（撮っていない。語彙は `timed` の `scaling: casterAttack` がある）                                        |

- S2 の効果の `assumes`: 「対象『最終攻撃力が最も高い敵 3 機』は単体ボスで 1 機。付けるたびに 1 回溜める（3 機いるときに 3 回溜めるかは確かめていない）。実測では撃った 6f 後に溜まるが、モデルは撃ったフレームに置く」。
- 未対応・前提の外の notes には、最小構成の検査が使う `effect` を書く（skills-guide.md 1.2 節）。
- バーストを使う間（チェーン・フルバースト）は、状態機械の規則でゲージが溜まらない。バーストの武器変更・装弾数無限を入れないので、モデルはバースト中も最後の弾丸を撃ち、S2 の発火を数える。ただし、その間のゲージは足されないので、ゲージへの影響は無い。挑発の窓は効果に持たないので、ほかへの影響も無い。
- `checkedAt` は説明文を読んだ日（実装の日）。

### 4.1 結論と観測値の付け替え

- C-0480 の `subject` を、機構（`mechanism: gauge`）から定義の場所（`data/skills/281.json の skill2 の effects[0]`・`treasureSkills.skill2 の effects[0]`）に替え、`model` を書き直す。最小構成の印（「モラン（定義なし）」）は外す。定義ができると、要素は効果と notes ごとになり、検査をやり直す（`npm run records:minimal`）。

## 5. 論点

1. **定義の範囲**（推奨: S2 のゲージだけを効果にし、ほかは notes）
   - S2 のゲージだけが確定の結論（C-0480）を持つ。S1 の追加ダメージ・バーストの武器変更・宝物版の行は、どれも撮っていない。
   - 説明文から効果を書けば（語彙がある行もある）、ダメージやクールタイムが入るが、根拠は説明文だけになる。持続するクールタイム▼（熱血）と、武器変更中の命中の数え方は、語彙を足す設計も要る。
   - 代わりの案: 説明文から全部を書く（仮説・推論の結論を作り、撮って確かめる）。大きな設計になるので、この設計とは分け、撮影の計画から始める。
2. **撃った 6f 後の遅れを入れるか**（推奨: 入れない）
   - 実測では 2 本の 6 回とも撃った 6f 後に溜まる（`369-02`・`370-02`）。レイヴンの S1 を付けたときも 6f 後（C-0181）で、モデルは撃ったフレームに置いている（design-raven-s1.md 5 節の 4）。
   - 6f の遅れが効くのは、満タンに届くのがこの 6f の中に入る場合だけ。C-0480 の比べ（満タンの番号 197）では、最後の弾丸は満タンの 17 ヒット以上前なので変わらない。
   - 入れるなら、レイヴンの `gaugeOnApply` と合わせて、射撃の回数でゲージを溜める効果に共通の遅れ（例: `delayFrames`）を足す。2 キャラ・8 回で同じ 6f なので根拠はあるが、語彙を足すことになるので、この設計とは分ける。
3. **宝物版の S2 にも書くか**（推奨: 書く）
   - S2 の挑発の行は、宝物版でも説明文が同じ（宝物版は 3 つ目の行が足されるだけ）。
   - 録画 369・370 の台帳には宝物の段階が書いていない。撮ったときの段階が分かれば台帳に書き（`treasurePhase`）、C-0480 がどちらの版で測ったものかを根拠に書く。分からなければ、もう一方の版の効果の `assumes` に「同じ行なので同じとみた」と書く。
   - 宝物の段階を台帳に書くかは、オーナーが決める（公開する台帳に育成の状況が載るため）。
4. **フォルクヴァンの S2 のゲージも入れるか**（推奨: この設計では入れない）
   - フォルクヴァンの S2 は約 19.6 秒（1177f）ごとに射手の 4,000 を溜める（C-0422）。周期のトリガーは今の語彙で書け、フラワーの S2 と同じ形になる。いまは notes の `unimplemented`（「説明文にきっかけが無い」）。
   - 周期の秒（約 20.0 秒）を録画から読んだ値として入れれば済むが、モランとは別のキャラの変更なので、別の PR で行う。

## 6. 退化と確かめ

- `burstGaugeHit` を書いた定義はフラワー（304）だけで、周期のトリガーの扱いは変えないので、フラワーの照合の値は変わらない。
- モランの定義を新しく作るので、モランを含む録画の照合が変わりうる。モランを含む録画は 367（main で取り込んだバーストの欄を左に出す録画）・369・370 で、比べる観測値は 4.1 節で戻す `369-01`・`370-01` だけ。どちらもモデルが 197 になる見込み（今は 200）。
- 定義の notes だけのスロットは、ダメージを変えない。
- `npm test` と `npm run records:check` で、ほかの照合の値が変わらないことを確かめる。

## 7. 残るリスク

- 挑発の対象が 3 機いるときに 3 回溜めるか、1 回か（単体の的では確かめられない）。モデルは単体ボスなので効かない。
- `lastShot` は、最大装弾数▲で遅れ、弾丸チャージで出なくなる（Stage 10）。モランの最大装弾数を変える味方と組むと、発火の数が変わる。これはモデルの意図どおりだが、確かめていない。
