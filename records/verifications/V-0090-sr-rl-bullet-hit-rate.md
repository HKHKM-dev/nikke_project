- 日付: 2026-10-02
- Stage: plan/design-stage18.md 12.2 節（的の表の SR・RL の弾丸命中率。起票時は null、閉じたときに 1）。V-0065「次の候補」の 4

## 条件

- 撮影はしない見込み（下の判断）。既存の単騎・AUTO・3 分モード・スペック固定 ON の録画を読み直す。
- 的は BigArms（灼熱タブ）。RL は紅蓮：ブラックシャドウ（`046`・`055`・`070`・`071`。`046` だけ属性なしのタブで自動バースト ON、`071` は撃ち始めを遅らせた）と I-DOLL・フラワー（`077`。オートバースト ON なので、バーストの区間は除く）。SR はラム（`075`・`076`）。アリスの単騎は `089` だけで、スペック固定 OFF・約 1 分（V-0047 の 1 ヒットの値の録画）なので割合は出せない。
- 表は武器種ごとでキャラによらない（C-0028。SG も同じ流儀。plan/design-sg-hit-rate.md 2 節）ので、RL は紅蓮BS・フラワー、SR はラムで測れば表に入れられる。
- 最小構成は単騎（観測したい事象は通常攻撃の当たり外れだけ）。

**いま分かっていること**

- `data/enemies.json` の `range-bigarms` で、SR・RL の弾丸命中率は null（未測定）。自動の条件の枠では手入力の値（既定 1）を使い、注記「SR・RL の弾丸命中率はこの的で未測定」が出る（`frame/landing.ts`）。コア命中率は SR・RL とも 1（C-0028 確定。録画 25 と 55）。
- 紅蓮BS 単騎の 180 秒で、HUD の総ダメージに増分が出た発の数は `046-03`・`055-03`・`071-04`（部分チャージの 1 発を含む）。増分の出ない発は、的がコンテナの後ろを通るときにコンテナに当たった発で、戦闘の始まりの決まった時刻にあり発の番号によらない（C-0108 確定。V-0037）。V-0042 で、モデルの射撃の数との差は部分チャージ（C-0109）を入れた後、このコンテナの 1 発だけになった（残差の一覧の `046-03`・`055-03` は +1 発で許容外のまま。モデルはコンテナを持たない）。つまり、**紅蓮BS の 3 本では、コンテナ以外に外れた発は見つかっていない**。
- ラム単騎にも総ダメージに出ない発がある（`075-03`。82f の刻みの抜け。V-0037 の段 0 の 5 で探した）。
- AR・SMG・MG の弾丸命中率は距離帯で落ちる（遠がいちばん低い。表の値）。SG も遠が低い（`074-26`）。SR・RL で同じ傾向があるかは測っていない。

## 読み方

1. 紅蓮BS の `046`・`055`・`070`（AUTO 射撃・180 秒）: V-0001・V-0037 で読んだ射撃の列（`046-07`・`055-07`。HUD の増分のフレーム）に、43f の刻み（リロードをまたぐ 172f）の抜けを探す。コンテナの時刻（C-0108）の抜けは除く。`070` と `071` は列が観測値に無いので、`npm run records:read`（`hud-jumps` のレシピ）で出す。
2. ラムの `075`・`076`（SR・AUTO・180 秒）: 82f の刻み（リロードをまたぐ 200f。`075-07`・`075-08`）の抜け（`075-03`）が、コンテナの時刻にあるか、ほかの区間にもあるかを見る。射撃の数は観測値に無いので、同じレシピで出す。
3. フラワーの `077`（RL・AUTO・オートバースト ON）: バーストの区間（`077-04`・`077-07`）を除いて同じく抜けを探す。
4. 抜けの位置を区間（距離帯。C-0031 の並び）に当て、武器種ごとに「撃った発・抜けた発（コンテナ以外）」を区間別に数えて観測値（`use: "record"`）にする。割合は観測値から出す。
5. H0 なら `data/enemies.json` の SR・RL の弾丸命中率に 1 を書き（`source` にこの記録の ID）、注記を消す。H1 なら帯ごとの値を書く。どちらも根拠の結論を作ってから（等級は本数で決まる）。

（読んだ手順。2026-10-02）7 本とも `npm run records:read -- <録画> --recipe hud-jumps` で増分の列をキャッシュし（1 本 20〜30 秒）、使い捨てのスクリプトで、増分を 1 発の値（コア・会心・胴体・部分チャージ）と S1 の段・バーストの値の和に分けて発の増分のフレームを取り、発の刻み（紅蓮BS 43f・ラムとフラワー 82f。リロードをまたいで 172f・200f）の抜けを数えた。桁送りで割れた読み（同じ値に足し戻せる）と遅れて出た読み（隣り合う 2 つの空きの和が 2 発分）は刻みで合わせた。区間の切れ目は録画ごとの窓（観測値の注記）。レシピ `hud-jumps` の count は、紅蓮BS では S1 の段の増分が発と同じ組にまとまるので使えない（レシピ化の候補は plan/design-records-automation.md の経過）。コンテナの発かどうかは、刻みの抜けの時刻（C-0108）と、新しく見つけた 075 の 6334f は画面（動画 f7139〜7155）で確かめた。

## 分かったこと・分からないこと

- **SR・RL の弾丸命中率は射撃場の的で 1**（C-0168。紅蓮BS 4 本・ラム 2 本・フラワー 1 本。距離帯によらない）。総ダメージに出ない発はすべてコンテナの発（C-0108）だった。
- コンテナの発は 2 か所: 戦闘の始まり（右のコンテナ。紅蓮BS 808〜820f・ラム 844f。7 本中 6 本）と、**4 区間目（中遠）の始まりの左のコンテナ**（`070` の 6443f・`075` の 6334f。着地の後のリロード明けの 1 発目。046・055・071・076 のその時刻の発は当たっている）。どちらも戦闘の時刻と的の位置で決まり、発の番号によらない。フラワー（`077`）は戦闘の始まりの発が 777f・860f で、どちらも当たった（コンテナの後ろを通る時刻をまたいだ）。
- 紅蓮BS 3 本の撃った発の数（コンテナの発を含む）はモデルと差 0（`046-25`・`055-16`・`070-07`）。`046-03`・`055-03` の +1 発はコンテナの発そのもの（V-0092 の射撃の数の差はこれで数えきれる）。
- フラワー単騎の的のジャンプの始まりは 32.6・69.0・108.9・145.2・178.2 秒（`077-12` の注記）で、紅蓮BS の組より約 8 秒遅い（SG のノワールの組 C-0068 に近い）。画面は見ていない。
- 問いの外で見えたこと: **フラワー（RL）の通常攻撃はコアを外す発が多い**（`077-15`。98 発中 19 発、半分余りが遠の区間）。RL のコア命中率 1（C-0028・C-0033。紅蓮BS の 0.989）はキャラによらないとして表に入れているが、フラワーでは合わない。RL のコア命中率がキャラ（弾速・弾道）や距離で変わるかは、別の検証で確かめる（roadmap「今後の課題」）。
- 分からないこと: アリス（SR・SSR）で同じか（表は武器種ごとなので、ラムで決めた。アリス単騎・スペック固定 ON の録画は無い）。左のコンテナの発が、同じ条件の録画で出たり出なかったりする理由（着地の後の 1 発目の時刻の差は数 f）。フラワーのコアの外れの原因。
