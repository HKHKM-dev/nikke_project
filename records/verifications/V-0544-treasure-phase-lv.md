# V-0544: 宝物の段階は、ShiftyPad の favorite_item_lv から決まるか

- 問い: ShiftyPad（Blablalink）の GetUserCharacterDetails の favorite_item_lv（0〜2）は、ゲーム内の宝物の段階（1〜3）とどう対応するか
- 話題: 育成・ステータス
- 日付: 2026-10-30
- Stage: plan/design-build-snapshot.md 3 節（宝物の段階）・plan/design-stage12.md 11.1 節「分からないまま残るもの」
- 結論: `C-0744`
- 状態: 完了

## 条件

- 型: 撮影なしの絞り込み（録画は撮らない）。オーナーのゲーム内の画面のスクショと、育成データのスナップショット（`private/builds/`）の `favorite_item_lv` を突き合わせる。
- スクショ（2026-10-30。`ui/` の `20261030_status_<キャラ>`・`20261030_treasure_<キャラ>`・`20261030_treasure_<キャラ>_phase1`〜`phase3`。キャラはロザンナ・ファントム）: キャラ画面（宝ものの印の ★）、宝ものの画面（★ の数とスキルの印）、スキル情報の「宝ものスキル」の第 1〜3 段階のタブ（解放済みの段階は宝もの版のスキルが明るく出て、未解放の段階は「解放条件 <宝もの>『N段階』達成」の錠で出る）。
- 育成データ: 2026-10-29 の取得（`npm run build:fetch`）。2026-10-30 の取り直しは ShiftyPad の「request too frequently」（code 212000）で 2 回止まり、取れなかった。
- 段階 3 の側: 録画の台帳の `treasurePhase` は、取り込みのときにオーナーに確かめた値（`tools/captures/intake.ts` の `--treasure`。plan/captures/protocol.md「撮った後」）。

## 予測

なし

## 読み方

- 段階は、スキル情報の「宝ものスキル」で解放済みの段階の数と、宝ものの画面の ★ の数の両方で読む（2 つが一致することも見る）。
- `favorite_item_lv` は、段階を読んだ日のいちばん近いスナップショットの値。

## 分かったこと・分からないこと

- 分かったこと（C-0744）: `favorite_item_lv` が 1 なら段階 2、2 なら段階 3（Lv + 1）。取り込み（`shiftypad.ts` の `treasurePhaseOfLevel`）がスナップショットの段階を埋め、`sim-run.ts --build` は `--treasure` の無い枠にそれを使う。
- 分からないこと: Lv 0 の段階。宝物のステータスは Lv 0 でも乗る（plan/design-stage12.md 11.1 節）ので段階は 1 以上で、Lv 1 = 段階 2 から段階 1 しか残らないが、画面では見ていない。取り込みは Lv 0 の段階を決めず、未確定（`--treasure` で指定）のままにする。
- 取得（10-29）とスクショ（10-30）の日がずれる: その間に 2 体の宝ものを強化して Lv 2 になっていたなら「Lv = 段階」も考えられるが、それでは Lv 2 のキャラが段階 3 の録画の台帳（ドレイクなど 5 体）と合わない。API の Lv は 0〜2 しか出ないので、両方と合うのは Lv + 1 だけ。

## 次に撮るもの

- 撮影は要らない。宝物の Lv 0 のキャラを新しく持ったときに、育成データの取得と同じ日にスキル情報の「宝ものスキル」の画面を 1 枚撮れば、Lv 0 = 段階 1 を確かめられる。
