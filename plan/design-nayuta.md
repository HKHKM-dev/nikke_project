## 0. 範囲

ナユタ（223。SSR・支援・ピルグリム・SMG・風圧・バースト II・CT 20 秒）の全スロット（S1・S2・バースト）を定義する。宝物は無い。所持と育成は撮影に足りる（`private/roster.md`）。既存の録画にナユタの入ったものは無い（`records/` に 223 のキャラとしての記録は無い）。

バーストが II なので単騎ではバーストが起きない。バーストと S1 の「記憶燃焼なら」の効果を撮るには、機構が確定した I・III とのチェーンが要る（3.2 節）。S2 の記憶吸収（バーストに依らない）は単騎で撮れる。

語彙の面では、新しく足すものは**小さい**（2 節）。段 15〜21 の棚卸しが挙げてきた「増減効果の無効」「使用武器の変更を名前の付いた状態にする」は、どちらも足さずに書ける見込み（論点 1・2）。

- 状態の id は英語版の名前（Memory Absorption）の lowerCamelCase（`memoryAbsorption`）で、目録（`skills/states.ts`）に足す。記憶燃焼は状態にしない（論点 2）。
- 記憶吸収の命中率▲は、命中率を読む射撃（コア命中率・弾丸命中率の式）に効く。スタックは戦闘開始から 3 秒ごとに 1（3 秒・6 秒…。0 秒には付かない）で、30 スタックに届くのは 90 秒。1 戦闘（180 秒）の後半はずっと 30 スタック。
- 「スタック量増減効果無効」は、自分の記憶吸収のスタックを増減させる**他の効果**を無効にする。ナユタの定義の側では何も起きず（記憶吸収を増減させる効果はナユタの定義に無い）、増減の効果を持つ味方のいる編成でだけ効く。`assumes` に書く（論点 1）。

## 2. 語彙

### 2.1 記憶吸収（周期のスタックの状態と、`{ applied }` の出来事）

- 付与は 511 の「美しさ」と同じ形（`kind: "state"`・`trigger: { everySeconds: 3 }`・`maxStacksRef`・`durationUntil: "battleEnd"`）で、`hitRate` の中身を持たせる。`hitRate` は `STATE_STATS` に既にある。
- `{ applied: "memoryAbsorption" }` のきっかけ（段 4）は、状態が付くたびに出るはず。**上限（30 スタック）に届いた後の周期の付与が、「適用される時」として出続けるか**は、この定義で読むこと（3.1 節の Q1。上限後も出る前提でモデルを組むと、S1 の味方全体の▲が戦闘の後半でも 5 秒ごとに途切れず続く。出ないなら、90 秒以降は S1 の▲が消える）。

### 2.2 スタック数別の効果

- 段 3 の `condition.selfState.stacksRef`（C-0573 の形。「N スタック以上なら」）で書く。「下位効果のスタック適用」は 3 つの効果が**それぞれ独立に**付くこと（3 段階では 1・2 段階の分も付いたまま）なので、条件を 3 つ別々に書けばそのまま表せる。
- 持続（維持時間なし）の効果が、条件の成立で付き、スタックは減らない（増減効果無効）ので、外れない。書き方は `passive` に条件付き（`selfState` の stacks）が書けるかを実装時に確かめ、書けなければ `{ applied }` の timed（`durationUntil: "battleEnd"`）にする。どちらでもダメージは同じ。
- 閾値は 2・10・30 スタック＝6 秒・30 秒・90 秒。撮影は 90 秒以降の窓が要る（3.1 節）。

### 2.3 S1 の倍率ダメージの種類

- 「最終攻撃力の X% のダメージ」（値 07）は、行の言い回しでは倍率ダメージ（`damageType: "skill"`）。**フルチャージの射撃ごとに出るので、バーストゲージを溜めるか**（`gaugeHits` / `gaugePerHit`）は、既存の同じ形の先例（511 の S1 の追加ダメージの `gaugeHits`、オートファイアの `gaugePerHit`）から決めて、3.2 節の撮影で確かめる。
- 「追加ダメージ」（値 10）は C-0410 の形（ゲージを溜めない追加ダメージ）。

### 2.4 記憶燃焼のチャージ時間の「固定」

- `chargeTimeSeconds: 1.8` で書く。説明文の「固定」が、**チャージ速度▲を受けて 1.8 秒より短くならない**という意味か、**1.8 秒を基礎としてチャージ速度が掛かる**かは分からない。ナユタ自身にチャージ速度▲を足す効果は無いが、編成の味方（チャージ速度▲を持つキャラ）が居ると差が出る。
- 方針: 単騎ではなくチェーンで撮るので、**チャージ速度▲を持つ味方を編成に入れない**最小構成にし、1.8 秒が実測で出るかだけを読む。「固定」の意味は、確かめるまで `assumes` に「チャージ速度▲との関係は未確認」と書く（`unimplemented` にはしない）。
- ジルのバーストのリロード速度の固定（段 20 の候補 9。C-0013 の式）とは別の話（こちらはチャージ時間）。値の固定の家族の語彙（`stat:fixed`）は足さない。

### 2.5 足さない語彙

- **使用武器の変更を名前の付いた状態にする**（段 11 の論点 1 の代わりの案。段 15〜21 の「候補 3 / 4 / 5」）: S1 の「記憶燃焼状態なら」は、`firesDuring: "weaponChange"`（モランの S1 の C-0705。変更の窓の中の発だけ出る）で書ける。使い手がナユタ 1 体のうちは、状態の名前を足さない（論点 2）。
- **増減効果の無効**: ナユタの記憶吸収を増減させる効果が定義のどこにも無い。味方に、スタックを増減させる定義のあるキャラが居る編成で初めて効くので、語彙にはせず `assumes` に書く（論点 1）。

## 3. 検証

話題は `スキル・キャラ固有`。問いは「ナユタのスキルを 1 節の表のとおりに読んで、モデルは実測と合うか」。

### 3.1 S2 の記憶吸収（単騎）

- **Q1**: 周期の付与は 3 秒ごとか（3 秒・6 秒…）。上限の 30 スタックに届いた後も、「適用される時」が 3 秒ごとに出るか（S1 の味方全体の▲の窓が 90 秒以降も 5 秒ごとに更新されるか）。
- **Q2**: 命中率▲が 1 スタックごとに 1.4% 足し算で効くか（スタックごとの命中率のずれ。ナユタの SMG の命中率の帯と、的の命中の帯で読む）。
- **Q3**: スタック数別の効果（2・10・30 スタック）が、スタックの届いた時刻（6 秒・30 秒・90 秒）から付き、外れないか。1 段階の攻撃力▲・2 段階の攻撃ダメージ▲・3 段階のコアダメージ▲を、それぞれ単独の窓で読む。
- 編成: 単騎。バーストが起きないので、S2 と S1 の記憶吸収の▲（ナユタ自身への分）だけが見える。味方全体の▲は単騎なら自分だけに乗る。

### 3.2 バースト・記憶燃焼・S1 の記憶燃焼の効果（チェーン）

- **Q4**: 記憶燃焼の間、チャージ時間は 1.8 秒で固定か（2.4 節）。装弾数無限で 10 秒間リロードが入らないか。ダメージ 値 03 とフルチャージダメージ 250% は説明文どおりか（`fullChargeDamage` の先例はレッドフード）。
- **Q5**: 記憶燃焼の間のフルチャージの発ごとに、S1 の敵全体の倍率ダメージ（値 07）と、ターゲットへの追加ダメージ（値 10）が 1 回ずつ出るか。バーストゲージを溜めるか（2.3 節）。
- 編成: 機構が確定した I と III、ナユタ（II）の 3 体以上のチェーン。ほかの未確定の要素（チャージ速度▲・回復・スタックの増減）を持たない I・III を選ぶ（最小構成。[verification-guide.md](verification-guide.md)）。候補は撮影の依頼の時に決める。

### 3.3 撮る前の予測

- 検証記録の起案の時に、撮る前の予測（`records/predictions/`）を書く。予測の形: Q1 は「上限後も出る」、Q4 は「1.8 秒（チャージ速度▲の無い編成なので固定かどうかは決まらない）」、Q5 は「射撃ごとに両方が 1 回ずつ。倍率ダメージはゲージを溜める」。

## 4. PR の分け方

- **1 体 1 PR**（[skills-guide.md](skills-guide.md) 0 節）。語彙は 2.1・2.2 の `stacksRef` 付きの passive の可否の確認だけで、足す型は無い見込み。語彙を足す場合（passive に条件が書けない・`applied` が上限後に出ない形を表す欄が要る）は、実装の途中でオーナーに諮る。
- 順序: ① この設計書の承認 → ② 定義・目録・単体テスト・編成のテスト（`nayutaTeam.test.ts`）・予測 → ③ 撮影の依頼（単騎 1 本・チェーン 1〜2 本）→ ④ 取り込み・読み取り・結論 → ⑤ 差分の整理（`/simplify`）→ PR。
- ③ の撮影待ちの間は、トピックブランチを保持する（AGENTS.md「コミット手順」）。PR は撮影の結果が出てから。

## 5. 論点

1. **増減効果の無効を語彙にするか**（2.5 節）
   - 推奨: 語彙にせず `assumes` に書く。ナユタの定義の中に、記憶吸収のスタックを増減させる効果が無く、編成の味方にそのような定義のあるキャラが居ないので、ダメージは変わらない。
   - 代わりの案: 状態の欄 `stackImmutable`（仮称）を足し、スタックを増減させる効果（`stackChange`）の側で弾く。使い手がナユタ 1 体で、組むキャラが居ない。
2. **記憶燃焼を名前の付いた状態にするか**（2.5 節）
   - 推奨: しない。S1 の条件は `firesDuring: "weaponChange"` で書く。使い手がナユタ 1 体。
   - 代わりの案: `weaponChange` に状態の名前の欄を足し、S1 は `selfState: "memoryIncineration"` で読む（ギルティ：マイティバニー・シン：スウィフトバニーが後から使える）。型と解決とフレームループに触るので、PR が重くなる。
3. **S1 の自分への HP 回復（最大HP の 25%）**
   - 推奨: `unimplemented`（撮っていない。ナユタ自身の HP は被弾なしの前提で満タンのままで、回復を受けた時を読む効果のある編成でだけ効く）。`heal` の定義は、回復を受けた時を読む味方との撮影が要る。
   - 代わりの案: `heal`（`applied`・`self`）で定義する。HP 満タンで回復が適用されたことになるか（クラウンの S2 の先例）の確認を、撮影に足すことになる。
