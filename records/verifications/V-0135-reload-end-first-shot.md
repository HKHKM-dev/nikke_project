## 予測（撮る前に書く）

比べる値は、`055`・`070`・`071` のリロード完了（RELOADING のバーが消えたフレーム）から次の発の総ダメージの増分まで（レシピ `reload-segments` の「完了 → 次の増分」）。増分は撃ったフレームより遅れて出る（弾が届くまで。紅蓮BS は 1〜9f。`046-19`・`071-16` の注記）ので、遅れを d と書く。

| 仮説                                                                                                | 完了 → 次の増分                                              | 最後の発 → バーの出始め（「最終弾 → 完了」−「バーの長さ」） |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------- |
| H0: モデルの分け方（リロードの完了から、構え解除を含む発と発の間 43f で撃つ）                       | 43 + d（44〜52f）                                            | 最後の発の直後（増分の前後 数 f）                           |

| H2: どちらでもない（遮蔽物から出る動きが別にあるなど）                                              | 40〜43f か 52f より長い、か回ごとに大きく揺れる              | —                                                           |

- 見分けられるか: H0 と H1 は完了 → 次の増分で 13f 違い、d の幅（1〜9f）を入れても重ならない。判定は 3 本の全部の回の値の範囲と中央値で行う（中央値が 31〜39f で、範囲が 44f に届かなければ H1）。
- 予測ファイル（`records/predictions/V-0135.json`）は、いまのモデル（H0）の射撃の数を形の確かめとして固定しただけで、仮説を見分けない（モデルの分け方を仮説ごとに切り替える口が予測ファイルに無いため。README のとおり手で書く）。H1 でも、窓とリロードの完了が重ならない回の射撃の列は同じになる。
- 外れたときの影響: H1 なら、モデルのリロードの分け方は 172f の合計を変えずに直せる（窓の明けにリロードの完了が窓の終わりの 13f 以内に近い回だけ 1 発目が遅くなる）。C-0110 の「リロードの後の 1 発目は発と発の間と同じ」の言い方を直す必要がある（オーナーに確認してから）。H0 なら、`071` の 1 回目の 9f は窓かリロードの読みの問題で、照準の動き出しの読みを見直す。H2 なら、リロードの後の動きを別の記録で切り出す。
- 見込み: H1。
