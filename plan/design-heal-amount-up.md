# 設計書: 与える HP 回復量▲を、量で追う回復に掛ける

- 関連: [design-hp-heal-restore.md](design-hp-heal-restore.md) 2.2 節（回復量の式）・2.5 節（足さないもの）・8 節（回復量の手の計算）、[design-named-state.md](design-named-state.md)（状態の目録）
- 課題: `records/backlog/skill-hp-heal-restore.json`（6 節）
- 検証: V-0797（録画 1234・1235）
- 作成日: 2026-11-15

## 0. 範囲

- ミサト（833）の S2 の「射撃マニュアルのフルスタック状態の時のみ、与えるHP回復量 30.05%▲」を、S1 の回復の量に掛ける。いまは間接の notes（`skill2.notes[1]`）で、量に掛けない。
- 量で追う回復（heal の `scaling: "casterFinalMaxHp"`）の量にだけ効く。量で追わない回復（持続回復・吸収回復・満タンの枠への回復）は量を持たないので、▲を読まない。
- 受ける HP 回復量▲は足さない（論点 3）。

## 1. 撮影で分かったこと（V-0797）

- 撮影 B（ミサト・紅蓮）: 紅蓮への回復の伸び（`1235-01`）は、2 回目からの 25 回がどれも、説明文の式に▲を掛けた量に合い、掛けない量とは合わない。射撃マニュアルが 2 スタックの 1 回目の回復（`1235-02`）は、▲を掛けない量に合う。
- 撮影 A（ミサト・I-DOLL・フラワー・エード）: ミサト自身・フラワーへの回復の伸び（`1234-03`）も、▲を掛けた量に合う。射撃が止まってスタックが切れた後の 1 回（2 スタック）だけ、掛けない量に合う。
- 撮影 A のミサト自身への伸びは、エードの最大HP のみ▲ の区間（S2 だけ・バーストだけ・重なり）に依らず同じ画素で、発動者の最終最大HP に、発動者自身に付いた最大HP のみ▲ を入れる読み（いまのモデル。design-hp-heal-restore.md 2.2 節）に合う。入れない読みでは、区間ごとに伸びが 2〜4 画素小さくなる。
- 窓の中の 2 回目の回復の対象（`1234-01`）は C-1316 のとおりで、モデルと合う（▲の有無に依らない）。

## 2. 足す形

### 2.1 語彙（論点 1）

- stat `healDealt`（与える HP 回復量▲。持つ枠が出す回復の量を上げる）を足す。timed・passive に書け、値は足して重ねる。
- 量で追う回復の量 = 発動者の最終最大HP × X × (1 + 発動者の healDealt の和)。和は、回復の発火のフレームより前に付いた件と常時の分（最終最大HP と同じ読み。`skills/holders/views.ts` の `restoreAmountOf`）。
- 置き場所: `healDealt` の件は、最大HP の件（`maxHpViews`）と同じく、件の列から枠ごとの views を作って読む。ダメージの式・射撃の列は読まない（HP を読む効果のある編成でだけ効く。間接の notes の `path: "hp"` と同じ見え方）。
- 代わりの案: 語彙を足さず、notes のまま（量に掛けない）。撮影の結果とモデルの回復量が合わないまま残る。

### 2.2 ミサトの定義（論点 2）

- S1 の命中率▲（`skill1.effects[0]`）を、名前の付いた状態「射撃マニュアル」（`shootingManual`。`skills/states.ts` の目録に足す）の付与にし、中身を命中率▲にする（上限 3 スタック・5 秒・数え直しはいまと同じ。C-0183・C-0184）。命中率の値と効く区間は変わらない。
- S2 に `healDealt` 30.05%（`ref`）の passive を書き、`while: { selfState: { state: "shootingManual", present: true, stacks: "full" } }` で、フルスタックの間だけ効かせる。`skill2.notes[1]`（間接）は消す。
- S1 の回復の `assumes` の「与えるHP回復量▲・受けるHP回復量▲は掛けない」を、「与えるHP回復量▲（S2）は掛け、受けるHP回復量▲は掛けない」に書き直す。
- 代わりの案: 状態にせず、S2 の▲を「S1 の命中率▲が 3 スタックの間」の条件で書く語彙を別に足す（スタックの条件を、名前の無い timed にも書けるようにする）。条件の語彙が 2 つになる。

### 2.3 受ける HP 回復量▲（論点 3）

- 足さない。持つキャラ（アリス：ワンダーランドバニーのバースト、フローラの S1、フォルクヴァン・マルチャーナの S1、クラウンの S2、シンの S2、レッドフードのバースト、鈴原サクラの S2、エマの S2、エマ：タクティカル・アップのバースト、エヌ：ミラクルフェアリーの S2）の間接の notes はそのまま。
- 理由: 撮っていない。与える HP 回復量▲と同時に付いた時に、足して重ねるか掛けて重ねるかが分からない。
- 代わりの案: `healTaken` も足し、量に (1 + 受ける▲の和) を掛ける（与える▲とは掛けて重ねる）。重ね方は仮説の結論にする。

### 2.4 ほかの与える HP 回復量▲

- プリカの S1（パフォーマンスの間の自分の与える HP 回復量▲）は、プリカの回復が持続回復（量で追わない）だけなので、`healDealt` を書いても量に効かない。間接の notes のまま。
- アンカー：イノセントメイドの S1 の「HP回復量▲」は、与えるか受けるかが説明文で決まらず、アンカーの回復も量で追わない。間接の notes のまま。

## 3. 退化の見込み

- 量で追う回復の量が変わるのは、ミサトの S1 の回復が、割合の下がった枠に当たる編成だけ（録画 1088・1089・1121・1234・1235）。比べる観測値のうち、当たる枠（`windowFirstHealTargets`・`windowNthHealTargets`）は、回復量が大きくなっても変わらない見込み（1088・1089・1121 は窓の中に 2 回目の回復が来ず、1234 は回復量の読みに依らない。V-0797「条件」）。実装の後に全部の録画で比べ、変わった観測値を経過に書く。
- 射撃マニュアルを状態にしても、命中率▲の区間は変わらない。ミサトのいる録画の比べる観測値が変わらないことで確かめる。

## 4. 結論（論点 4）

- C-1316 を確定にする。根拠は `1234-01`（比べる指標 `windowNthHealTargets`。4 回とも合う）と `1234-02`。1234 は仮説の出どころでない。
- 新しい結論 1: 「ミサトの S2 の与えるHP回復量▲は、射撃マニュアルのフルスタックの間、S1 の回復の量に (1 + 30.05%) を掛ける。フルスタックでない回復には掛からない」。根拠は `1235-01`・`1235-02`・`1234-03`。
- 新しい結論 2: 「『スキル発動者の最終最大HP の X%』の回復の量は、発動者自身に付いた最大HP のみ▲ を入れた最終最大HP で決まる」。根拠は `1234-03`。
- 結論 1・2 の根拠の観測値は、モデルと比べない（record）。HP のバーは 1 画素（1.12%）の刻みでしか読めず、また録画 1235 では、モデルの射撃の列でフルスタックでない見込みだった回（的のジャンプの後の 2 回）も▲の量だったので、回ごとの比べがモデルの射撃の列のずれで外れる。推奨: 指標を足さず、人の判断（`judgment` の `overrides: ["指標なし"]`）で確定にする。25 回が 1 つの読みにだけ合い、合わせ込みの定数は無い（式と値は説明文だけ）。
- 代わりの案: 回復ごとの伸びの指標（`healRatioGains`）を足し、許容 1.2%（1 画素）で比べる。モデルの射撃の列のずれで外れる回は、観測値から外す。

## 5. 実装の順とリスク

- 1 段ごとに `npm test`。
  1. `skills/types.ts`: stat `healDealt`（timed・passive に書ける。ダメージの式と射撃の列は読まない）。`skills/states.ts`: `shootingManual`。
  2. `skills/holders/views.ts`: `healDealt` の views と、`restoreAmountOf` で発火のフレームより前の和を掛ける。
  3. 定義: ミサトの S1 の effects[0] を状態の付与に、S2 に passive を足し、notes と `assumes` を直す。
  4. 既存のテストが数値を変えずに通ること（退化）。新しいテスト: フルスタックの間の回復だけ量が (1 + 30.05%) 倍になる、スタックが切れた後の回復は掛からない。
  5. 結論（4 節）と backlog の課題の書き直し（量で追う回復の▲は済み。受ける▲・持続回復・吸収回復が残る）。
- リスク:
  - 状態の付与にすると、ミサトの命中率▲の区間の作り方（timed の stacks から状態の stacks へ）が変わる。区間の数値が変わらないことを、ミサトのいる録画の観測値（コア命中率など。C-0183）で確かめる。
  - 録画 1235 で、モデルの射撃の列では的のジャンプの後にスタックが切れる見込みの回が、▲の量だった（4 節）。ジャンプの間のミサトの射撃か、スタックの維持（C-0184。仮説）がモデルとずれている。V-0797 の「分からないこと」に残す。

## 7. 論点（オーナーに決めてもらうこと）

1. **与える HP 回復量▲の語彙**（2.1 節）
   - 推奨: stat `healDealt` を足し、量で追う回復の量に、発火のフレームより前の発動者の和を (1 + 和) で掛ける。
   - 代わりの案: 足さず、notes のまま（撮影と回復量が合わないまま）。
2. **ミサトの S2 の条件の書き方**（2.2 節）
   - 推奨: 射撃マニュアルを名前の付いた状態にし、S2 を `while` の `stacks: "full"` で書く。
   - 代わりの案: 名前の無い timed のスタックを見る条件の語彙を、別に足す。
3. **受ける HP 回復量▲**（2.3 節）
   - 推奨: 足さず、間接の notes のまま。課題に残す。
   - 代わりの案: `healTaken` も足し、与える▲と掛けて重ねる（仮説）。
4. **結論の確定のしかた**（4 節）
   - 推奨: C-1316 は比べる指標で確定。新しい結論 1・2 は指標を足さず、人の判断（指標なし）で確定。
   - 代わりの案: 回復ごとの伸びの指標を足し、合う回だけで比べて確定。

## 経過

- 2026-11-15: 起案。V-0797 の録画 1234・1235 で、ミサトの S2 の与えるHP回復量▲が S1 の回復にフルスタックの間だけ乗り、発動者の最終最大HP が自分の最大HP のみ▲ を入れると分かった（1 節）。論点 1〜4 をオーナーに諮る。
- 2026-11-15: オーナーが論点 1〜4 を推奨どおりに決めた。stat `healDealt` と状態 `shootingManual` を足し、ミサトの S1 の effects[0] を状態の付与に、S2 に `healDealt` の passive を書いた。結論は C-1334・C-1335（C-1316 は確定）。
