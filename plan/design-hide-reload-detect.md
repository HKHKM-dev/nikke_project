## 0. 要約

- 窓の長さ（明けから 2 秒前まで。録画の窓は明けから決める）はそのままで、窓の中の出来事の始まりが、窓の始まりより約 8f 遅い（明けの約 110f 前。以下 D）。
  - チャージの途中で窓に入ったチャージ武器は、D から満ちてから撃つまで（H）の後に部分チャージで撃つ。いまのモデルは窓の始まりに撃つ（C-0109）。
  - ハイド中のリロードは D から始まる。射撃姿勢維持型は、D と前の発の射撃姿勢の終わり（撃ってから ⌈S⌉ − H）の遅い方から始まる。いまのモデルは窓の始まりから（C-0828）、射撃姿勢維持型は前の発の 19f 後から（C-0829）。
- この形で、アドミ・A2・紅蓮：ブラックシャドウ・レイヴン・ベスティー：タクティカル・アップ・I-DOLL・フラワーの、部分チャージの発の時刻・バーの 0 の点・明けまでの長さが、0〜3f の差でそろう（2 節）。レイヴンは、形を立てた後に既存の録画を、撮る前に固定した予測で読んだ（V-0615）。
- 外れる回が 1 つある: 窓の始まりにチャージが満ちていてフルチャージの発を撃った回（V-0609 の 0863 の 4 回目）は、その発からリロードが始まった（D からではない）。3 節の案 A はこれを別の扱いにする。

## 1. いまのモデル

- `frame/firstPass.ts` が窓の始まりのフレームに `partialChargeShot`（チャージの途中なら、その時点の進みで撃つ）と `hideShooter`（撃てる状態で残弾が減っていればハイド中のリロードを始める）を呼ぶ（`frame/shooter.ts`）。
- ハイド中のリロードは窓の始まりから始まり、リロードの秒 + 12f（`hideReloadExtraFrames`）で満ちる。射撃姿勢維持型は、前の発から 19f（`hideReloadStanceLeadFrames`）より前には始めない。明けまでに満ちなければ取り消す（`unhideShooter`）。
- そのため、射撃姿勢維持型でない武器は、リロードの秒 + 12f がモデルの窓（117〜118f）に収まれば終える（リロード 1.79 秒以下）。

## 3. 案

- **案 A（推奨）**: 窓の始まりの状態で 3 つに分ける。
  1. チャージが満ちている（満ちてから撃つまでの間か、このフレームに撃つはずだった）: いまの `partialChargeShot` と同じく窓の始まりに撃つ（進み 1）。リロードは、射撃姿勢維持型でない武器はその発から、射撃姿勢維持型はその発の姿勢の終わり（撃ってから ⌈S⌉ − H）から。
  2. チャージの途中: W + D に満ちたことにして、H の後に部分チャージで撃つ。リロードは、射撃姿勢維持型でない武器は W + D から、射撃姿勢維持型は W + D + ⌈S⌉ から。
  3. ほか（チャージしていない・チャージの無い武器・押下チャージ型）: リロードは W + D と、前の発の姿勢の終わり（射撃姿勢維持型だけ）の遅い方から。
  - D は 1 つの定数（8f。明けの約 110f 前）で、2 節の 6 キャラ・7 つの形に共通。H・⌈S⌉ はキャラのデータから決まり、合わせない。
  - ハイド中のリロードが満ちるのは、いままでどおり始まりからリロードの秒 + 12f（C-0828・C-0135）。
- 案 B: 1 を分けず、窓の始まりに満ちていても D を待つ。0863 の 4 回目が合わない（モデルでは終えない）。
- 案 C: 窓の長さを明けの 110f 前からにする（窓の始まりを D に動かす）。部分チャージの発は H の分だけ、射撃姿勢維持型でないキャラで 1f ずれるだけで済むが、ジャンプの間隔の観測値（C-0546・C-0547）と着地点の区間の切れ目（`setup.jumpWindows` の始まり）が動き、0863 の 4 回目も合わない。採らない。

## 4. 案 A の形

- `WeaponModel` に `hideDetectFrames`（D = 8）を足し、`hideReloadStanceLeadFrames`（19f）を消す。
- `frame/firstPass.ts` の窓の始まり:
  - チャージが満ちている枠は、いまの `partialChargeShot` で撃ち、`hideShooter` でリロードを始める（射撃姿勢維持型は姿勢の終わりまで待つ。待ちは `chargeElapsed` から決める。いまの lead の 19f を ⌈S⌉ − H に替えた形）。
  - ほかの枠は、`hideShooter` で「W + D まで待つ」状態にする（`ShooterState` に `hideDetect` の待ちを足す。窓の間は撃たない `blocked` のまま）。W + D のフレームに、チャージの途中だった枠は部分チャージの発を H の後に予約し、リロードの始まりを決める（射撃姿勢維持型は W + D + ⌈S⌉、ほかは W + D）。
  - 部分チャージの発を窓の中（`blocked` の間）に撃つ道を足す（いまは窓の始まりのフレームだけ）。発の記録（`partialShots`・ゲージ・倍率ダメージのきっかけ）はいまの部分チャージの発と同じ扱い。
- D の前に明けが来ることは無い（窓は 117f 以上）。窓の中で込め終えた後の明けの扱い（`unhideShooter`）は変えない。
- 窓の始まりにチャージの途中かどうかは、いまの `chargeProgressFrames` で決める（進みが 0 より大きく 1 より小さい）。

### 効くところ

- 射撃姿勢維持型でない武器のハイド中のリロードは、案 A の 2・3 の回では、リロードの秒 + 12f が約 110f に収まるときだけ終える（リロード約 1.67 秒以下）。いまのモデルとの違いが出るのは、1.73 秒のアドミ（案 A の 1 の回のほかは終えなくなる）と、境の上の 1.67 秒のキャラ（6 体。端数の持ち越しで回によって分かれうる）。1.8 秒以上は、いまも終えない。
- 部分チャージの発が D + H だけ遅れる（射撃姿勢維持型でない武器は 9f、A2 は 32f）。発の値・ゲージの時刻・発をきっかけにする効果の時刻が動く。
- 射撃姿勢維持型のハイド中のリロードの始まりが動く（紅蓮：ブラックシャドウは早まり、レイヴン・A2 は遅れる）。リロード 2 秒の紅蓮：ブラックシャドウ・レイヴンは、どちらでも終えない。A2 は、窓の始まりの約 2〜9f 前に撃っていた回（案 A の 3）だけ、いままで終えていた回が終えなくなる（ほかの回は終えるか終えないかが変わらない）。
- ジャンプを挟む観測値（発の時刻・数、バーストのチェーン）が動きうる。実装の PR で `npm run records:residual` の前後を比べ、外れた観測値は録画のジャンプの前後で説明がつくかを確かめる（[design-hide-reload.md](design-hide-reload.md) 7・9 節と同じ進め方）。

## 5. 結論の扱い（実装の PR で）

- C-0109（窓の始まりに部分チャージで撃つ）は時刻の部分を棄却し、新しい結論（W + D + H に撃つ。案 A の 1 は窓の始まり）で置き換える。値の部分（チャージの表示に比例）は 6 節の 1 を確かめてから。
- C-0828（窓の始まりから始まる）と C-0829（前の発の 19f 後）を棄却し、案 A の 1〜3 のリロードの始まりの結論で置き換える。込め終わり（リロードの秒 + 約 12f）と、2 秒のキャラが終えないことは引き継ぐ。
- D（8f）は録画に合わせた値で、`decidedOn` は D を決めた録画（V-0609・V-0610 の録画と、`0815`・`0816`・`0077`）。レイヴンの `0122` は D を決めた後に予測を固定して読んだので、再現に数える。

## 6. 確かめてから入れること・残る論点

1. 部分チャージの発の値（進み）: いまは窓の始まりの進みで値を決める（C-0109）。録画の部分チャージの発の増分は、アドミではフルチャージの約 0.7〜1 倍で、レイヴン（`0122-04` の注記の f7149）では進みがほぼ 0 の値。進みを W・W + D・撃つ時のどれで決めるか（射撃姿勢維持型は H の間をどう数えるか）を、実装の前に既存の観測値で確かめる。決まらなければ、値はいまのまま（窓の始まりの進み）にして、時刻だけを動かす。確かめた結果は 8 節。
2. 案 A の 1 の根拠は 0863 の 4 回目の 1 回（と A2 の 3 回目の近い形）。射撃姿勢維持型で窓の始まりに満ちていた回の扱いは、A2 の 3 回目の撃ったフレームが読めていないので、2〜3f の差が残る。
3. チャージの無い武器（AR・SMG・MG・SG）の D: 押下チャージ型の `0815-13`・`0816-10` は合うが、チャージの無い武器では読んでいない（クラウンの▲の中の 2 回は、どちらの形でも終える）。案 A では同じ D を使う。
4. `0077-47` の 1 回目の約 115f。
5. 分割リロード（SG）は範囲の外（[design-hide-reload.md](design-hide-reload.md) 6 節の 4 と同じ）。

## 9. 部分チャージの発の値を D の時点の進みにする（2026-11-01）

- 読み直し（V-0624）: 8 節の A2・レイヴンの「どの時点とも合わない」は、部分チャージの発が胴体に当たった回を、フルチャージの発と同じコアとして読んでいたため。値を部位（胴体・会心・コア・コアの会心）の格子に当てると、A2・レイヴン・紅蓮：ブラックシャドウの 15 回とも、溜めたフレーム数がちょうど整数になり、D（窓の始まりの約 8f 後）の時点のモデルの溜めたフレーム数と 0〜1f の差だった。A2 の `0123` は、値を見る前に予測を書いてから読んだ。
- H が 1f の紅蓮：ブラックシャドウ（チャージ 18f で 1f が進み 0.057）も、6 回とも撃った時（D の 1f 後）ではなく D の時点と合う。チャージ約 59f のアドミ・ラムは、8 節の読みでは D と撃った時を見分けられない。
- 決めたこと（オーナー）: 部分チャージの発の値を、H によらず D の時点の進みで決める。満ちてから撃つまで（H）の間に溜まった分は乗らない。
- 形: `frame/shooter.ts` の `HidePending.progress` は、窓の始まりの進み（チャージの途中だったかの判定）を持ち、待ちの残りが H になったフレーム（D）に `partialChargeProgress` で置き換える。撃つのは今までどおり D の H 後（C-0840）。H が 1f の武器は値が 1f 分小さくなり、H の長い射撃姿勢維持型は窓の始まりから D までの 8f 分大きくなる。
- 比べる指標 `partialChargeProgress`（`records/observations.ts`。window 回目の窓の中の部分チャージの発の進み）を足し、A2・レイヴンの 9 回を比べる観測値にした。紅蓮：ブラックシャドウは、モデルの発を増分にそろえた録画の窓では飛ぶ時間（約 6f）が進みの差に出るので、比べない。
- 残すこと: A2・レイヴンの部分チャージの発は 7 回のうち 5 回が胴体に当たった（紅蓮：ブラックシャドウは 6 回ともコア）。モデルは部分チャージの発もふだんのコア命中率で数える。別の課題にする（`records/backlog/`）。

## 10. チャージの無い武器の、窓の始まりから D までの発（2026-11-03）

### 10.1 分かったこと（V-0648）

- 6 節の 3 を既存の録画（マナ AR・エマ MG・ルドミラ SMG・エーテル SG の単騎 8 本）で読んだ。チャージの無い武器のハイド中のリロードも D から始まり、モデルと合う（C-0844 の根拠に足した）。
- 同じ録画で、ジャンプの前の最後の発（増分）がバーの 0 の点（D）とほぼ同じフレームにあった（AR・MG・SMG。`0250-16`・`0251-11`・`0443-07`・`0444-08`・`0305-15`・`0306-16`）。チャージの無い武器は、窓の始まりから D までの間も撃ち続け、最後の発の直後からハイド中のリロードが始まる。増分が出ているので、この間の発は的に当たっている。
- モデルは窓の始まりで撃つのを止める（`frame/firstPass.ts` の `slotBlocked` の間は `stepShooter` が撃たない。D までは `stepHide` が待つだけ）。録画の窓で回すと、ジャンプの前の最後の発から明けまでが録画より約 9f 長く、ジャンプごとに約 D 分の発が少ない（MG のエマで約 8 発、AR のマナで約 2 発。読んだのはマガジンの途中に来たジャンプ）。
- チャージ武器は、窓の始まりにチャージの途中なら D まで溜めて部分チャージで撃ち（C-0840）、満ちていれば窓の始まりに撃つ。どちらも「D までは撃てる状態のまま」と読めば同じ形で、チャージの無い武器だけが、モデルで窓の始まりから止まっていた。

### 10.2 案

- **案 A（推奨）**: チャージの無い武器（`chargeTime` が 0）は、窓の始まりから D まで撃てる状態のまま（`stepShooter` を blocked にしない）にし、D に `hideShooter` でハイドする（いまの `stepHide` の待ちの終わり）。この間に弾切れになれば、ふだんの弾切れのリロードが始まり、D のハイドでもそのまま続ける（いまの `hideShooter` の扱い）。
  - ハイド中のリロードの始まり（D）・窓の長さ・明けの扱いは変えない（V-0648 の比べる観測値は動かない）。
  - D までの発の着地点の条件（コア命中率・距離ボーナス・弾丸命中率）は、窓の前の区間のもの（的はまだ跳んでいない）。着地点の区間の切れ目（`setup.jumpWindows` の始まり）をそのままにして、D までの発を前の区間で数えられるかは、実装で確かめる。
  - オートバーストが止まる時刻（`stepBurstController` の blocked）は根拠が無いので変えない。
  - チャージ武器は変えない（窓の始まりにチャージしていなかった回（V-0620 の (iii)）で D までにチャージを始めるかは、まだ録画が無い）。
- 案 B: モデルは今のまま、窓の始まりから D までの発が少ないことを未実装として書く。

### 10.3 効くところ

- ジャンプを挟むチャージの無い武器の観測値（発の数・区間ごとのヒットの数・マガジンの発の数・ゲージ・ダメージ）が、ジャンプごとに約 D 分の発だけ動く。3 分で 5 回のジャンプのうち、撃っていた回の分。実装の PR で `npm run records:residual` の前後を比べ、外れた観測値はジャンプの前後で説明がつくかを確かめる（4 節と同じ進め方）。
- SG（発と発の間 約 40f）は、窓の始まりから D までに次の発が来る回だけ 1 発増える。

### 10.4 決めてほしいこと

1. 案 A（推奨）・案 B のどちらにするか。
2. 案 A なら、課題（`records/backlog/`）として起こし、実装の PR で観測値の前後を比べて入れる進め方でよいか。

決めたこと（オーナー、2026-11-03）: 案 A。課題は起こさず、V-0648 と同じ PR にまとめる。
