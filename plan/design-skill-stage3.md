## 1. 語彙

### 1.1 スタック量の増減: 効果 `stackChange`

- **形**: `{ "kind": "stackChange", "state": "<id>", "trigger": …, "target": "self", "amountRef": N }`（`amount` で即値も書ける）。説明文の「スタック量 N 個▲」の行に 1 つ書く。減少（`decrease`）は PR 3 で足す。
- **意味**: 発火のフレーム（射撃の回数のきっかけは次のフレーム。付与と同じ）に、持ち主のその状態に N スタックを足す。足したスタックの上限・維持・中身は、同じ定義のその状態の付与のもの（論点 2）。スタックは付与と同じく「発火のたびに全スタックの維持を数え直す」（`skills/stacks.ts` の `STACK_REFRESH`）ので、持続の状態なら戦闘の終わりまで残る。
- **件の作り方**: 状態の件の列の始まりの列に、同じフレームの始まりを N 個入れる（スタックの段は始まりの数で上がる。いまの段ごとの窓の作り方のまま）。付いた記録（`applications`）は発火 1 回で 1 件。
- **検証**: 対象は自分だけ。同じ定義に、その状態をスタックで付ける付与（`maxStacks` か `maxStacksRef`。対象は自分）が要る。トリガーの確率のきっかけ・`{ applied }`・時間の周期のきっかけは書けない（解除と同じ）。条件は解除と同じ鍵。

### 1.2 回数のきっかけの数える窓を `timed`・付与に開く

- `{ "count": …, "every": N, "during": "fullBurst", "reset": "fullBurstStart" | "never" }` を、`damage` のほかに `timed` と状態の付与にも書けるようにする。意味は `damage` と同じ（フルバーストの窓の中の射撃だけを数える。クルミ S2 編）。トリガーを追う側（`skills/triggers.ts`）は対応済みで、読み込みの検証だけを開く（論点 3）。

### 1.3 フルスタックの消費のきっかけ（PR 2）

- **形**: トリガー `{ "fullStack": "<id>" }`。持ち主（自分）のその状態の件がフルスタックになったフレームに発火する。発火したら、その状態のスタックを全部外す（次のフレームで閉じる。同じフレームの判定には付いている）。説明文の「フルスタック状態の時、スタック解除後、〈効果〉」の行に、効果ごとのトリガーとして書く（論点 5）。
- **解除との違い**: フルスタックになるのは、最後のスタックを付けた付与と同じフレームなので、解除の「同じフレームに付いた件の列は閉じない（付与が勝つ）」規則を当てない。

### 1.4 スタック数の条件（PR 3）

- **形**: `"selfState": { "state": "<id>", "stacks": "full" | N }`（N スタック以上。[design-named-state.md](design-named-state.md) 8.1 節の形）。判定は `selfState` と同じ段（段 1.5・`damage`）で、そのフレームの状態の件のスタックの段の最大を見る。
- 説明文の値の N は `stacksRef`（description_value_NN。解決で `stacks` にする。`amount`・`amountRef` と同じ流儀）。`present: false` とは組み合わせない。静的な状態は 1 段とみなす。

### 1.5 スタック量の減少（PR 3）

- `stackChange` の `"decrease": true`。発火のフレームに、上の段から N スタックを次のフレームで閉じる（段ごとの件の終わりを切る）。
- 減らす先は、足す先と同じ（同じ定義の付与の、自分の件の列）。同じフレームの始まりは減少の前に数え、付いている段より多く減らしても最後の 1 段は残す（V-0437 の録画 463・471。C-0574）。後の付与は減った段から数える（`skills/stacks.ts` の `stackWindows` の `decreases`。数え直しが `'all'` のときだけ）。付いた記録（`applications`）は作らない。

### 1.6 回数のきっかけの発火の窓（V-0443）

- **形**: `{ "count": …, "every": N, "firesDuring": "fullBurst" }`。射撃は窓の外も含めて戦闘中ずっと数え、N の倍数に届いた発がフルバーストの窓（[start, end)）の中のときだけ発火する。窓の外で届いた回は発火せずに過ぎる（持ち越さない）。`during`（窓の中の発だけを数える）とは組み合わせない。書ける効果は `during` と同じ（`damage`・`timed`・付与。`stacksRef`・`lastShot`・`weaponChangeShot`・確率とは組み合わせない）。
- **使い手**: ソーダ：トゥインクルバニーの S1（ゴールデンチップの付与）。録画 463・471 の 10 回のフルバーストで、増えた発がどれも戦闘開始からの通し番号の 3 の倍数で、フルバーストの外の 3 の倍数では増えなかった（C-0580）。
- **条件 `inFullBurst` にしない理由**: 条件の `inFullBurst` は件を見る鍵なので、付与を段 1.5 に上げる。段 1.5 の状態の件は、スタック数の条件（1.4 節）が見る段 1 の件に入らないので、バーストのスタック量別の効果が付かなくなる。窓の中かどうかはトリガーを追う側（`skills/triggers.ts`）がフレームの出来事で分かるので、付与は段 1 のまま書ける。

## 5. 論点

決定（2026-10-16）: オーナーの指示（段 3 に進む）で、論点 1〜5 を推奨どおりにして進めた。

1. **スタック量の増減の書き方**
   - 推奨: 付与とは別の効果の種類（`stackChange`）。説明文では別の行で、付与は 1 回で 1 スタック。減少（PR 3）も同じ種類に足せる。
   - 代わりの案: 付与に「1 回で付けるスタックの数」の欄を足す（減少は別の種類になる）。
2. **足したスタックの維持**
   - 推奨: 同じ定義の付与のもの（上限・維持・中身）。いまの数え直し（`STACK_REFRESH` = 'all'）のまま。
   - 代わりの案: 足したスタックだけ別の維持を持つ（説明文の例が無い）。
3. **`during` を `timed`・付与に開くか**
   - 推奨: 開く。トリガーを追う側は対応済みで、意味は `damage` と同じ。
   - 代わりの案: 付与にだけ開く。
4. **PR の順**
   - 推奨: PR 1（ソーダ：TB S1。既存の録画）→ PR 2（クラウン。既存の録画）→ PR 3（ソーダ：TB バースト。撮影を待つ間はブランチに置く）。
   - 代わりの案: クラウンを先にする。
5. **フルスタックの消費の書き方（PR 2）**
   - 推奨: トリガー `{ fullStack }` で、発火したらスタックを全部外す（同じフレームの付与でも閉じる）。説明文の「フルスタック状態の時、スタック解除後」は、効果ごとに同じきっかけを書く。
   - 代わりの案: きっかけ（`{ fullStack }`）と解除（`removeState`）を別々に書く。この場合、解除の「同じフレームの付与が勝つ」規則で、フルスタックになった付与と同じフレームの解除が効かなくなるので、規則に例外が要る。
