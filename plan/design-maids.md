## 2. 語彙

### 2.1 timed の値 × 状態のスタック数 `perCount: { state }`（論点 1）

- いまの `perCount` は damage だけ（シンデレラ・ラプラス：UH の追加ダメージ）。timed の stat の値に、発火のフレームの自分のその状態のスタック数（発火のフレームより前に付いた件。条件 `selfState` と同じ見え方）を掛ける形を足す。0 なら出さない。
- 掛けた値は付いた時に決まり、維持の間にスタックが増減しても変えない（damage の `perCount` と同じ。トーブのその場しのぎの奇跡も付いた時の数のまま。V-0523）。
- 書けるきっかけ: `burstUse`・`burstStage1Enter`〜`burstStage3Enter`・`fullBurstStart`・`fullBurstEnd`（出来事のきっかけ）。周期・回数のきっかけには書かない（使い手が無い）。
- [skill-catalog.md](skill-catalog.md) の「X% × 〈状態〉のスタック数」（語彙なし）の最初の使い手。アルカナ：フォーチュンメイトにもそのまま使える見込み。

### 2.2 気絶: `shotPause` のきっかけ `{ applied: <状態> }`（論点 2）

- 二日酔い（`hangover`）を、中身の無い状態（10 秒）として目録に足し、`shotPause` のきっかけに「その状態が自分に付いた時」を足して、止まりの長さを状態の維持（600f）にする。止めている間の扱いはいまの `shotPause` と同じ（撃たず、待ち・リロードも進めない。明けは構え直す）。
- 気絶の間にバーストを撃てるか（チェーンの候補になるか）は、説明文に無い。推奨は、モデルでは撃てないとし（候補から外す）、撮影 B で確かめる（3.2 節）。
- スタック解除と二日酔いの付与は同じフレーム（フルバーストの終わり）。付与の条件「フルスタック状態なら」は、解除の前の件で判定する（同じフレームの効果の順を、条件を先に全部見てから外す形にする。実装で確かめる）。

### 2.3 発動の回数の種類 `fullBurstEnd`（論点 3）

- `EventCountKind` に `fullBurstEnd`（フルバーストタイムが終了した回数。編成全体）を足す。数え方は `fullBurstStart` と同じ（戦闘中ずっと数え、リセットしない）。「使用回数別の効果」で、きっかけがフルバーストの終わりのスキル（アンカー：IM の S2）に使う。

### 2.4 状態の目録

- `drunken`（ほろ酔い／Drunken。味方・スタックあり）、`hangover`（二日酔い／Hangover。味方・スタックなし）を `skills/states.ts` に足す。保存（アンカー：IM のバースト）は notes なので足さない。

## 3. 機構の問い

### 3.1 命中率▼の効き方（論点 4）

- モデルは命中率▼をコア命中率にも弾丸命中率にも効かせていない（`frame/landing.ts`。▼は測っていない、と注記を出す）。マスト：RM は自分にだけ、1 スタック 20%（Lv10）の▼が最大 3 スタック（60%）で付き、自分の通常攻撃のコアの当たりと外れが変わる。
- 旧プロジェクトの記録に、マスト：RM 単騎で▼20% のときコア命中率が約 −64% という読みがある（[design-stage18.md](design-stage18.md) 0.5 節。写していない）。▲の式（p ÷ (1 − N)²。C-0036）を N = −0.2 に延ばすと −31% で、合わない。
- 撮影 A（単騎）でスタック 0 と 1 の、撮影 B でスタック 1〜3 の、マスト：RM の発のコア命中率と弾丸命中率を数え、▼の N ごとの値を観測値にする。式は、数えた値を見てから決める（候補を撮る前に予測として書く）。
- 式が決まるまでは、定義には▼を書き、モデルはいまのまま効かせない（注記が出る）。マスト：RM の自分の発のコアと外れ（とゲージ）は、モデルが多めに出す。

### 3.2 撮影で確かめる状態機械の問い

- **Q-A1**: バースト 1 段階突入（ゲージの満タン）でほろ酔いが 1 スタック付くか。単騎ではチェーンが進まず、1 段階のまま止まるので、スタックは 1 のまま増えない見込み（モデルの `burstStage1Enter` は満タンとリエントリー）。
- **Q-B1**: チェーンが 2・3 段階で時間切れして 1 段階に戻った時（リエントリー）にもスタックが増えるか。マスト：RM の CT 40 秒が明けないうちにゲージが溜まれば起きる。
- **Q-B2**: 3 スタックで迎えたフルバーストの終わりに、マスト：RM が 10 秒撃たなくなり、ほろ酔いが外れる（S1 の▲が消え、次の 1 段階突入から付き直す）か。
- **Q-B3**: 気絶の間にチェーンの II が回ってきたら、マスト：RM が撃つか（起きなければ分からないまま。予測で起きる回があるかを先に見る）。

### 3.3 撮影の結果と、命中率▼の扱い（論点 7）

- 状態機械（Q-A1・Q-B1・Q-B2・Q-B4）と、アンカー：IM の回数の段（Q-C1・Q-C3）は、2 本ずつで説明文どおり・モデルどおりだった（V-0668・V-0669 の「結果」）。気絶の間はマスト：RM の発が止まり、明けにほろ酔いが外れている。
- 命中率▼は、どの仮説（V-0668 の H0〜H2）とも合わない。1 スタック（−20%）で、マスト：RM のコア命中率は着地点で大きく違う割合で下がる（近で約 0.6 倍、中遠 B・C で約 0.19 倍、遠で約 0.09 倍）。遠では弾丸命中率も下がる。2・3 スタックは、撮影 B でほかの 2 人の発と分けきれないが、さらに下がる（0〜0.13）。
- 単騎ではチェーンが 1 段階で止まり、ほろ酔いは 1 スタックまでしか付かない。2・3 スタックのきれいな値は、マスト：RM の発だけを読める編成（ほかの枠が撃たないか、格子の重ならない武器種）で撮らないと取れない。
- 論点 7 の案:
  - 案 A（推奨）: 命中率▼は、この 2 つの PR では効かせない（いまの注記のまま）。定義の注記に、着地点で違う下がり方と V-0668 を書き、式か表を決める仕事を課題に起こす。PR 1 は、状態機械・× スタック数・気絶の結論で出す。モデルは、ほろ酔いの間のマスト：RM の自分の発のダメージを多めに出す（コアの差で、1 スタックの近で約 1.2 倍、遠で約 1.8 倍）。
  - 案 B: 1 スタックの着地点ごとの値を、命中率▼の表（MG・N = −20%）としていまモデルに入れる。2・3 スタックの値が無いので、2・3 スタックの区間は未実装のまま残り、表と式の境目が中途半端になる。
- 決定: 案 A（オーナーの承認）。

## 7. 論点

1. **× スタック数の形**（2.1 節）。推奨: timed に `perCount: { state }` を足す（damage と同じ名前・同じ見え方）。値は付いた時のスタック数で決め、維持の間は変えない。
2. **気絶の形**（2.2 節）。推奨: `shotPause` のきっかけに `{ applied: "hangover" }` を足し、止まりを状態の維持にする。気絶の間はバーストの候補から外す（撃てないとみる）。撮影 B で外れていたら直す。
3. **フルバーストの終わりの回数**（2.3 節）。推奨: `EventCountKind` に `fullBurstEnd` を足す。
4. **命中率▼**（3.1 節）。推奨: 定義には▼を書き、モデルの効き方（式）は撮影 A・B で数えた値を見てから決める。決まるまでは効かせない（いまの注記のまま）。
5. **分配ダメージ▲**（1.2 節の後の注）。推奨: 定義に効果として書く（stat は語彙にある）。値の根拠は、同じ timed の組の▲（マスト：RM はリロード速度 × スタック数、アンカー：IM は録画で見える回数の段階）を見た結論に含め、分配ダメージを出す味方の編成では確かめない（撮影を増やさない）。
6. **撮影の編成**（4 節）。推奨: A・B・C の 3 つ（各 2 本）。I・III はリター・サン。2 体を同じ録画に入れない。
7. **命中率▼の扱い**（3.3 節）。推奨: 案 A（この PR では効かせず、式か表を決める仕事を課題に起こす）。決定: 案 A。

## 8. 命中率▼の効き方（課題 2-57。論点 8・9）

### 8.1 分かったこと（V-0683）

- I-DOLL・フラワー（I）+ マスト：RM（II）の 2 人（III なし）で、ほろ酔い 1〜3 スタックのコア命中率と弾丸命中率を、着地点ごとに数えた。値は V-0683 の「結果」（観測値は同じ所）。
- **コア命中率**: 1 スタックで着地点ごとに違う割合で下がり（V-0668 と同じ）、その先はスタックが 1 つ増えるごとに、近・遠・中遠のどこでもほぼ同じ倍率で下がる。撮る前の仮説（H-lin・H-geo・H-N の (1 − N) の例）はどれも合わない。着地点どうしの比がスタック数によらず同じ、という H-N の形だけが合う。
- **弾丸命中率**: 近・中近では▼で下がらない。遠は 1 スタックで少し、2・3 スタックで大きく下がり、中遠は 1 スタックでは下がらず 3 スタックで大きく下がる。着地点 × スタック数で形がそろわない。
- 取れていないセル: 中近の 2・3 スタック、中遠の 2 スタック（この編成ではスタックの増える時刻と着地点が合わない）。▲と▼が同時に乗るとき。

### 8.2 コア命中率の入れ方（論点 8）

- マスト：RM の自分の発で、条件が自動（射撃場の的の表がある敵）の枠、かつ区間の N（命中率の和）が −0.2k（k = 1〜3。ほろ酔いだけ）のとき、`coreHitRateWithHitRateUp` の N ≤ 0 の枝で、的の表の値の代わりに▼の表の値を使う。▲と同じく、区間の N で使う時点に出し直す（[design-sustained-hit-rate-core.md](design-sustained-hit-rate-core.md) の `landingPartsWith`）。
- 値は的の表（`data/enemies.json` の射撃場の的）に MG の▼の表として置く（▼なしの表と同じ置き場所。ほかの敵は未測定なので▼を効かせず注記）。
- 案 A（推奨）: **着地点の 1 スタックの値 × スタックの倍率**の形。1 スタックの値は着地点ごとの実測（近は V-0668 と V-0683 の和、中近は V-0683、中遠・遠は V-0668）。倍率は 2 スタック 0.46・3 スタック 0.20（1 スタックの値との比。近は同じ録画 0966・0967 の 1 スタック、遠・中遠は V-0668 の 1 スタックとの比で、近・遠の 2 スタックと近・遠・中遠の 3 スタックから）。測ったセルは、どれも実測から 1.4σ 以内に入る。測っていない 3 セル（中近の 2・3、中遠の 2）も同じ形で出す（形は近・遠・中遠の 3 か所で確かめた）。数は 6 つ。
- 案 B: 測ったセルだけを表に入れ、測っていない 3 セルは▼を効かせずに注記（未実装）。中近は 1 スタックより 2・3 スタックが高く出る（表の値に戻る）など、続きが切れる。
- 案 C: 測ったセルは実測の値、測っていない 3 セルだけ案 A の形で埋める。案 A との差は小さい（測ったセルで 1.4σ 以内）が、表の作り方が 2 通りになる。

### 8.3 弾丸命中率の入れ方（論点 8）

- 近・中近: 変えない（実測で下がらない）。いまの扱い（N ≤ 0 は表のまま）と同じ値になる。
- 遠・中遠: 測ったセル（遠の 1〜3、中遠の 1・3）を▼の表に置き、`bulletHitRateWithHitRateUp` の N ≤ 0 の枝で使う。中遠の 2 スタックは測っておらず、1 と 3 の間で形が決まらないので、表のまま（下げない）で注記に未実装と出す。
- ▲と同じ経路（`landingPartsWith`）で出し直すので、1 パス目のゲージ（C-0362）と命中の回数（C-0363）にも入る。

### 8.4 そろえないもの（未実装として注記）

- ▲と▼が同時に乗る区間（N が −0.2k でない）: いまの扱い（▲の式だけ。▼は効かせない）のまま、注記に未実装と出す。和で効くかを測っていない。
- MG 以外の武器種、射撃場の的以外の敵: ▼の使い手がマスト：RM だけで、測っていない。

### 8.5 ココアのデバフ解除（論点 9）

- 撮影 D（ココア + マスト：RM）で、ココアのバーストの「味方全体のデバフ効果解除」が、ほろ酔いを外した（V-0683 の「結果」。12 回とも替わり目の約 20f 後までに外れた）。C-0092（確定）は、ココアのデバフ解除を「味方の与ダメージを変えない」とし、定義（`data/skills/311.json`）も notes（計算に無関係）にしている。ほろ酔いのある編成では食い違う。
- 案（推奨）: C-0092 を棄却し、「デバフ解除は、ダメージに効くデバフを持たない味方の与ダメージは変えない」と「ココアのバーストのデバフ解除は、ほろ酔いを外す」の 2 つに分けて結論を起こす。モデルの語彙（デバフ解除で状態を外す。どの状態がデバフか。外れるのが全スタックか N 個か）は、この PR に入れず、課題を起こす（デバフ解除を持つキャラは 5 体）。直すまでは、ココアの定義の notes を「ほろ酔いのある編成では効く（未実装）」に直す。
