## Context

- 命中率▲は弾丸命中率を上げ、SMG の遠では H2 の形と合った（C-0192、仮説。V-0118）。オーナーの判断でモデルには入れず、命中率の調査として起案し直した（backlog 2-1）。
- 射撃場の的の前提（オーナー）: (1) コアのある中心の塊から細い上半身と脚が生えた形、(2) 照準円の大きさと、照準円の中で的が占める面積が比例しない、(3) 的は左右に動き、向きで照準円の中の面積が変わる。
- 求められていること: 射撃場の的に限らず、**ほかの形・ほかの動きの敵にも同じ計算式で対応できる**こと。**実装までの時間**が見合うこと。
- この設計は、形と動きを式でモデル化しない。**録画の発ごとに「照準円のうち当たり判定に入る割合」を数え、平均する**。敵ごとに違うのは道具に通す録画だけで、計算式と core のコードは敵によらない。

## 0. 今わかっていること

### 0.1 関係する結論

- 照準円の画面上の半径は約 0.285 × CDN の `*_accuracy_circle_scale`（C-0038）。▲で半径 × (1 − N)（C-0041。×1/(1 + N) とは区別できていない）。撃たない間は CDN の速さで戻り（C-0039）、MG は 1 発ごとに縮む（C-0040、仮説）。
- 常時の▲はコア命中率を 1/(1 − N)² 倍にする（C-0036、確定）。「弾が照準円の中で一様」「コアが照準円の中に収まる」「半径 × (1 − N)」から出る式。
  - N とコア命中率が小さいときは、一様と正規分布を区別しない。クルミのキューブ（N = 0.0509）はどちらの予測も信頼区間に入る。
  - N が大きいと区別できる。旧のクエンシー：エスケープクイーン（SMG、N = 0.4942。verification.md Stage 18-A「照準円と命中率▲」）は一様の式とほぼ一致し、正規分布（σ = R/√2）では約 0.09 低くなる（概算。旧の 1 本なので決め手にはしない）。C-0183 の帯ごとの倍率は揺れが大きく、分けられない。
  - C-0192 の H2 は「正規分布 + 中心に円の的」で出る形だが、一様でも的の形しだいで近い効き方になりうる。一様で的がまるごと照準円に収まると H3 になり、外れたのは手足が照準円の外まで伸びているためと説明できる（前提 1・2）。
  - **散らばりの形はコアにも胴体にも同じものが効くので、正規分布を選ぶと C-0036 のモデル側と食い違う**（10 節の 5）。
- コアの当たり判定は、半径が距離に反比例する円とみなせる（C-0046、仮説）。
- 照準は、距離ボーナスが乗っているとき水色になる（C-0043。区間ごとの色で確かめた）。
- 弾丸命中率の表は距離帯ごとの値（C-0034）で、▲には効かせていない。

## 1. 方式

### 1.1 式

着地点 L、照準円の大きさ s（CDN の単位。▲の後は CDN の値 × (1 − N)）について:

- 弾丸命中率 h(L, s) = 発射の瞬間のフレーム t（1 発 1 標本）での C_t(s) の平均。
- C_t(s) = 照準の中心 a_t に置いた散らばり K（半径 R = 0.285 × s）のうち、的の当たり判定 M_t（マスク）に入る割合。

決めていること:

- **K は一様を主の仮説にする**。正規分布（σ = R/√2。中心の密度が一様と同じ。打ち切らない）は対立仮説として、下見で比べるだけにする。正規の表も同じ数え上げから出る（2 節 4）。正規に替えるのは、決めた規則で一様がはっきり負けたときだけで、そのときは C-0036 の扱いを先にオーナーに諮る（5.1 の 2、10 節の 5）。**調整する係数は持たない**。K は判定の撮影の予測の前に固定する。
- **照準の中心は実際に読んだ位置を使う**（コアに合っているとは仮定しない）。照準の遅れも C_t に入る。
- **形と動きは M_t と a_t の時系列に入っている**。向き・移動・姿勢・跳ぶ前後を式では表さず、発の標本がそのまま重みになる。
- **距離の推定は要らない**。画面の px のまま数える（C-0045 に頼らない）。
- ▲（N）と武器種（CDN の値）の違いは、同じ表を引く s の違いになる。▲の弾丸命中率の式（H2 など）を別に持たない。

### 1.2 敵によらない部分と、敵ごとの部分

| 部分                               | 中身                                         | 敵によるか                         |
| ---------------------------------- | -------------------------------------------- | ---------------------------------- |
| 照準円の大きさ                     | 0.285 × CDN の値 × (1 − N)（C-0038・C-0041） | よらない                           |
| 散らばり方                         | 一様（主）。正規は対立仮説                   | よらない                           |
| 被覆率の数え方                     | 道具（2 節）                                 | よらない                           |
| 当たり判定の形・動き・照準の追い方 | 録画から読んだ M_t と a_t                    | **敵ごと**（録画を道具に通すだけ） |

- 前提 1〜3 は、形の仮定も向きの分布の推定も置かないので、そのまま入る。部位が分かれる・宙に浮く・姿勢が大きく変わる敵も、M_t が読めれば同じ式で入る。
- 照準円が当たり判定の中に収まる大型のボスは、C_t が 1 に近くなって片付く見込み（7 節で確かめる）。

## 2. 道具（`tools/captures/coverage.ts`。新規。`aim.ts` の処理を使う）

1. **発を選ぶ**: 残弾の列（`ammo.ts`）で残弾が 1 減ったフレームを 1 発とし、1 発を 1 標本にする（重みは等しい）。命中は撃った瞬間に決まるので、発射の間の待ちのフレームは使わない。録画のフレームと発射の瞬間のずれ（±1f）は、照準の 1f あたりの動きで確かめる（5.1 の 1）。区間の境目はジャンプ・着地の時刻で切り、着地点の id（`nearA`・`nearB`・`midNear`・`midFarA`〜`C`・`far`）を付ける。中遠は足元の高さ（V-0089 の読み方）、近は C-0155 の分け方で決める。
2. **照準の中心 a_t**: `aim.ts` の検出をそのまま使い、信頼度の低い発は落とす。
3. **マスク M_t**: `aim.ts` の背景差分の連結成分を画素のマスクとして出す（輪郭は全解像度で取り直す）。
   - 落とす発（割合を出力に残す）: `fx` が高い、的が探す範囲の端に接している、遮蔽物（緑の箱）が的とつながっている。遮蔽物に当たった発（C-0108）は別の欄で数える。
   - 前処理: 光沢・白飛びの穴は、閉じる処理（closing）と外につながらない穴の塗りつぶしで埋める。足元の影がマスクにつながるなら、着地点ごとの足元の高さより下を除くなどで切る。霧の脚の扱いもここで決める。要否と量は下見で画像を見て決め、設定に固定する（5.1 の 1）。
4. **被覆率 C_t(s)**（照準の中心からの距離ごとの画素の数で、全部の s を一度に出す）:
   - 1 発ごとに、a_t から r_max 以内のマスクの画素を距離（画素の中心まで。0.5px 刻み）ごとに数えた列 m(r) を作る。
   - 一様: C_t(s) = （r ≤ R の m(r) の和）÷ πR²。正規: C_t(s) = Σ_r m(r) × exp(−r²/2σ²) ÷ 2πσ²（σ = R/√2。r_max は 3R）。
   - 計算の量: 1 発あたり r_max の中の画素を 1 回なめるだけで、s の格子の点の数によらない。範囲の武器の s は 130 までで足りる（▼は扱わない。4.1）。正規でも r_max ≈ 111px（1 発約 4 万画素）で、SMG の 180 秒（V-0118 の撃った数）で約 1.3 億回の加算。一様だけなら 10 分の 1。
   - s の格子: 0 と、5〜130 の 26 点程度。s = 0 は「照準の中心の画素がマスクに入る割合」で、▲が 100% 以上のとき（C-0037）に引く。小さい s（R が数 px）は画素の粗さが残るので、注記に書く（範囲の武器では▲ 80% 以上でないと届かない）。
   - 1 発ごとの C_t（s = 範囲の武器の値）も出力に残す（5.3 の副）。
   - **単調にそろえる処理はしない**。照準の中心が的の外にあると C_t(s) は s とともに増えるので、h(L, s) は単調に減るとは限らない。全部の s を同じ発の同じ画素から出すので、ノイズによる局所の逆転はほとんど起きない。
5. **出力**: 着地点ごとの s の格子と h(L, s)、採った発の数、落とした割合、区間ごとの h の標準偏差。録画から読んだ値なので観測値（`records/observations/`）として置く。マスクの画像は証拠フレームと同じ扱いで `E:/nikke_project_captures/` に置く（コミットしない）。
6. **設定の固定**: 背景差分のしきい値・前処理・落とす条件・s の格子・K は設定ファイルに書き、出力に設定の版を残す。判定の撮影（5.2）の前に commit し、撮った後は変えない（撮った後に直したら撮り直す）。

## 3. データの形（`data/enemies.json`）

`targetProfiles[*]` に、着地点ごとの被覆率の表を任意の欄として足す（例）。

```json
"bulletCoverage": {
  "unit": "accuracyCircleScale",
  "landings": {
    "far": { "s": [0, 5, 10, 20, 40, 75, 110, 130], "h": [/* 観測値から */], "source": "観測値の ID" },
    "midFarB": { "s": [/* 同じ格子 */], "h": [/* 観測値から */], "source": "観測値の ID" }
  },
  "source": "plan/design-bullet-hit-rate-frame-coverage.md。値は観測値（ID）"
}
```

- **鍵は着地点の id**。距離帯や配分の id では持たない（h は s について線形でないので、まとめると配分の重みと▲の効き方が混ざる）。core は `landingMix` で着地点に分けた後に着地点ごとに引き、配分の重みは着地点ごとの値に掛かる。
- 着地点ごとに独立に引く。表の無い着地点は、いまの `bulletHitRate` の表に戻る（後戻りできる形）。どの着地点が表から取れたかは注記に出す（4.4）。中遠 A は録画に出ることが少ない（C-0044）ので、A が出た録画が集まるまで表を作らない。
- どちらの表も無い敵・着地点は、いまのとおり手入力の弾丸命中率で計算し、未測定と注記する。**形の分類や形の関数から推計した値は出さない**（8 節）。
- 表は武器種で分けない（武器種の違いは s に入る）。照準の追い方が武器種で違うと分かったとき（5.1 の 3）のために、`landings` の下に武器種の鍵を置ける形にしておく。

## 4. 入れ方（core）

### 4.1 表の引き方

- 着地点ごとに、次の順で決める。
  1. 枠の武器種が **AR か SMG** で、`bulletCoverage` にその着地点がある: s = `accuracy.autoStart` × (1 − clamp(N, 0, 1)) で表を線形に引く（N ≥ 1 なら s = 0）。
  2. それ以外: いまの `bulletHitRate` の表（▲を見ない）。
- 条件を「`autoChangePerShot` が 0」にしない。SR・RL（10/10）・ふつうの SG（250/250）も満たし、範囲外の武器が置き換わる。
- **命中率▼（N < 0）は扱わない**（N を 0 で切る）。`coreHitRateWithHitRateUp` も N ≤ 0 では変えない（design-sustained-hit-rate-core.md 5 節）のと揃える。
- 格子の外は端の値で止める（配列の外を引かないための守り。範囲の武器ではふつう起きない）。

### 4.2 持続の▲（区間ごとの N）

- `LandingPart` に、表から取った部分の材料を持たせる: `coverage?: { s: number[]; h: number[] }` と `accuracy`（枠の `accuracy.autoStart`）。
- `planLandings` は常時の N で 4.1 の値を `condition.hitRate` に入れる（いまの計画の値と同じ役目）。
- `landingPartsWith` は、コア命中率と同じく、`coverage` のある部分の `condition.hitRate` を区間の N（`state.buffs.hitRate`。常時 + 持続）で引き直す。早い戻りの条件は「`tableCoreHitRate` も `coverage` も無ければ」に直す。キャッシュの鍵（枠・着地点・N）は今のまま。

### 4.3 1 パス目（ゲージ）との境目

- **1 パス目のゲージの弾丸命中率は計画の値（常時の N）のまま**にし、持続の▲で上がった弾丸命中率は 2 パス目（calc・sim の与ダメージ）にだけ効かせる。
  - 理由: 1 パス目の弾丸命中率の区間は `runFirstPass` の前に作られ（0.4）、持続の `hitRate` は「状態だけの stat」で射撃に効く窓とは別に置かれている（design-sustained-hit-rate-core.md の経過）。
  - 持続の▲の中は、モデルのゲージが実際より遅く溜まる側にずれる。その枠の注記に未実装と出す。
- ゲージに入れるのは別の設計にする。1 パス目はフレーム順に進むので、付いた▲を後のフレームのゲージに効かせれば循環にはならないが、1 パス目が持続の `hitRate` の窓を追う必要がある。
- コア命中率はゲージに効かないので、いまの扱いと食い違わない。

### 4.4 測ったかの判定と表示

- `measuredHitRate` と未測定の注記（`auto-condition-unmeasured`）も、表から取った部分を「測った」側にするよう、4.1 と同じ順で判定する。
- 条件の注記に、着地点ごとの弾丸命中率の出どころ（被覆率の表（▲を含む）か距離帯の表か）と、4.3 のゲージの未実装を出す。

### 4.5 範囲外（いまの表のままにする）

- MG・照準円が縮む SG（プリバティ）: 撃つたびに照準円が変わる（C-0039・C-0040）。
- ふつうの SG: ペレットの当たる割合（C-0156）が照準円の大きさから見込むより高く、照準円とペレットの広がりの関係が分かっていない。
- SR・RL: 弾丸命中率 1 で確定（C-0168）。RL は弾が飛ぶ間に的が動き（C-0173）、爆発の範囲もあるので、撃った瞬間の照準と輪郭では表せない。

## 5. 確かめ方（本文は別紙）

本文は別紙 [design-bullet-hit-rate-frame-coverage-verify.md](design-bullet-hit-rate-frame-coverage-verify.md)（節の番号は 5.1〜5.3 のまま）。要点:

- **5.1 下見（撮影なし）**: 0. コアの▲の倍率で K を比べる（机上）→ 1. マスクの質（遠の霧を最初の関門にし、前処理と霧の扱いを値を並べる前に固定）→ 2. K を決める（既定は一様。χ² の差 4 の規則）→ 3. 表を武器種で共通にするか（AR と SMG の表の差 2σ の線引き）。どれも既に見た値なので、結論は作らない。
- **5.2 判定の撮影**: SMG 単騎・AUTO・遠で、▲の大きさを変えた群を同じ日の対照と比べる。予測は対照の表から引き、絶対値と比 q の 2 つを撮る前に固定する。
- **5.3 当たり判定の確かめ**: 主は SG の着弾点（既存の録画）、副は発ごとの突き合わせ（既存の録画）、従は照準の水色（手で操作する撮影。要るときだけ）。

0. コアの▲の倍率で K を比べる（5.1 の 0）。小（机上）。撮影なし。
1. 道具: マスクの出力・前処理・発射の瞬間の選別・距離ごとの画素の数え上げ。中（新しく書く本体。数え上げそのものは数十行）。撮影なし。
2. 下見（5.1 の 1〜3）と当たり判定の確かめ（5.3 の主・副）。SG の着弾点の読み取りを道具に足す。中。撮影なし。
3. core（4 節）: `bulletCoverage` の読み込み、`LandingPart` と `landingPartsWith` の出し直し、表示・注記・テスト。小〜中。撮影なし。
4. 照準の水色（5.3 の従）。段 2 で場所の絞り込みが要るときだけ。試しの録画 + 手で操作する撮影（遠は SR の照準の検出を足す）。
5. 判定の撮影（5.2）。撮影 1 回分 + 取り込み。
6. 結論と、`range-bigarms` の表の差し替え（3 を有効にする）。小。

- 段 0 は道具より先にできる。`aim.ts` があるので、画像の読み取りの大半は書き直さずに使える。撮影が要るのは段 4（要るときだけ）と段 5。
- 段 3 は段 5 の結果で入れるかが決まる。先に書き、表の無いまま（いまの表のまま）で merge できる形にする。
- 別の敵（7 節）は、道具が実戦の画面で使えるかに時間が左右される。

## 7. 別の敵への広げ方

- **最初の 1 体は大型のボスにし、照準円が当たり判定の中に収まるかだけを先に確かめる**。単騎・AUTO の録画から一定の間隔でコマを選び、手で輪郭を付け、照準円（SMG の 110）がはみ出すコマの割合を出す（線引きは輪郭を付ける前に決める。例: 1% 未満）。
  - 収まれば、K が一様ならその敵の表は「どの s でも 1」と置ける（観測値として。外れの割合との再現で確かめる）。K を正規に替えていたら、裾が出るので同じコマで C_t(s) を数える。
  - はみ出すなら、通常の手順に進む。
- 通常の手順: 単騎・AUTO で撮る（AR か SMG）→ 道具に通す → 着地点（場面）ごとの表を `bulletCoverage` に置く。確かめは、同じ録画の外れの割合との再現と、別の日の 1 本。5.1 の 3 で武器種ごとに分けることになったら、AR と SMG の両方を撮る。
- 背景が動く・演出の多い場面（迎撃戦・レイド）では背景差分が使えない。照準の水色（5.3 の従）で輪郭を取るか、一定の間隔のコマに手で輪郭を付けて前後のコマに使う。あまり動かない大型のボスなら、SG の着弾点（5.3 の主）を重ねるだけで、照準の届く範囲の当たり判定の形が分かる。自動の切り出しは、要るようになってから考える。
- 表を作るまでの敵は、手入力の弾丸命中率と未測定の注記のまま（3 節）。
- 部位（破壊できる部位・コア）を分けるときは、マスクにラベルを付け、ラベルごとの割合を別の欄に出す。最初の範囲ではしない。

## 8. やらないこと

- コア命中率を被覆率から出し直すこと（コアの検出は信頼できず、コア命中率は C-0036 の式で▲まで入っている）。
- MG・SG・SR・RL の弾丸命中率（4.5）。
- 照準の遅れや向きを式（モデル）として持つこと（数える中に入れるだけ）。
- 形の分類や係数を置いた曲線で、未測定の敵の弾丸命中率を推計すること。表 h(L, s) は関数の形を仮定せず観測値のまま持ち、曲線でまとめるかは複数の敵で表がそろってから考える。
- 残差を合わせるための係数。合わない分は 5.1・5.3 で原因を確かめる。

## 9. 分からないこと・危険

1. **当たり判定 = 見た目の輪郭か**。いちばん大きい危険なので 5.3 で先に確かめる。主の SG の着弾点は、点の仕組みを確かめてから使う。
2. **散らばりの形**。材料が両方に分かれている（0.1）。一様を既定にし、コアと弾丸命中率の両方で正規がはっきりよいときだけ替える候補にする（替えると C-0036 と食い違う）。どちらでもない形なら、どちらの表も合わない。
3. **照準の追い方は武器種で同じか**。5.1 の 3 の線引きで決める。0.2 の近い側の食い違いがここに当たる可能性がある。分けると別の敵の手間が倍になる。
4. **遠の脚が霧で欠ける**と h を低く見積もる。判定を行う遠でいちばん弱いので、下見の最初の関門にする。
5. **発射の瞬間の取り方**。残弾の読み落とし・±1f のずれで h が少し動く。
6. ×(1 − N) と ×1/(1 + N) の区別（C-0041）。大きな▲の群で予測が分かれるかを、判定の撮影の起票のときに見積もる。
7. **マスクの影と穴**。影がつながると h を高く、穴が開くと低く見積もる。前処理で扱う。
8. **持続の▲がゲージに入らない**（4.3）。注記で未実装と出す。

## 10. 決めたこと（2026-10-04 オーナー承認）

1. この方式（発ごとの被覆率。形と動きをモデル化しない）を採用する。
2. 最初の範囲は、射撃場の的・AR と SMG の弾丸命中率（コア命中率・MG・SG・SR・RL は範囲の外）。
3. 最初の一歩は机上のコアの▲の比べ（5.1 の 0）。続けて道具（段 1）、撮影なしの下見（5.1 の 1〜3）と当たり判定の確かめ（5.3 の主・副）。照準の水色（5.3 の従）は要るときだけ。
4. 未測定の敵は形から推計せず、手入力と未測定の注記のまま（3 節・8 節）。
5. 散らばりの形は「一様が主、正規は対立仮説」。下見で正規に替える候補になったら、C-0036 の扱いをそのときにオーナーが決める（(a) 正規を外し一様だけで進める、(b) C-0036 を見直す検証を別に起票する、(c) コアと胴体で形を分ける（筋が通らないので推奨しない））。
6. 持続の▲で上がる弾丸命中率は与ダメージ（2 パス目）にだけ入れ、1 パス目のゲージには入れない（未実装と注記する。4.3）。
