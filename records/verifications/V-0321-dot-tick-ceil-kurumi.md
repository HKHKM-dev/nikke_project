# V-0321: クルミのハッキングの tick も、起点から k 秒に達した最初のフレーム（ceil）に出るか（録画 058・059・060 の読み直し）

- 問い: 持続ダメージの tick は起点から k 間隔に達した最初のフレーム（C-0454。レイヴン単騎の 122 で確かめた）という形は、別のキャラ（クルミの S1 のハッキング。afterInterval・1 秒ごと・付き直しで刻みを変えない C-0129）の長い tick の列でも繰り返すか
- 話題: スキル・キャラ固有
- 日付: 2026-10-08
- 録画: `058`、`059`、`060`
- 状態: 調査中
- 派生元: `V-0317`

## 条件

- C-0454（仮説・反復実測）: tick は、まとまりの起点 O から O + ceil(k × 間隔 ÷ 0.017)。いまのモデル（`dot.ts`）は四捨五入で、約半分の tick で 1f 違う。根拠はレイヴン単騎の 122（176 tick で ceil の形が 166 回・四捨五入が 96 回）と、出どころの `093-03`（クルミの 1 回だけ付いた回の 5 tick）。
- 録画 058・059・060: クルミ単騎・操作・AUTO 射撃・スペック固定 OFF・キューブなし（057・061・062 はキューブあり）。ハッキングは 36 回の命中ごとに付き直り、1 秒ごとの tick が途切れずに 34〜74 回続く列がある（`057-06`。V-0051）。
- V-0051 は、HUD の増分を 1 発（40,904.29 × 8 通りの倍率）と tick（92,507。会心 1.5 倍）に分けて tick の列を取り、列の長さと付き直しで刻みが変わらないこと（C-0129）を見た。tick のフレームの並び（58f と 59f の並び）は観測値に残しておらず、起点からの ceil・四捨五入とは比べていない。この記録では、同じ分け方で tick を取り直し、並びを比べる。
- 最小構成: 単騎・バーストなし。tick の時刻に効くのは、問いの刻み方と、発動と関係しない止まり（C-0262）だけ。

## 予測（撮る前に書く）

既存の録画の読み直し。tick の並びは、この節を commit した後に読む。予測ファイルは作らない（予測ファイルによる数値の予測なし）。

| 仮説                    | まとまりの起点 O からの tick |
| ----------------------- | ---------------------------- |
| H-C（ceil。C-0454）     | O + ceil(k × 58.8235)        |
| H-R（四捨五入。モデル） | O + round(k × 58.8235)       |

- 起点 O: 1.5 秒以上途切れたら新しいまとまりとし、その最初の tick の 59f 前（k = 1 の 59f はどちらの仮説でも同じ）。
- 見分け方: V-0317 と同じ。まとまりを止まりの段で区間に分け、区間ごとに ceil(φ + k × 58.8235) の φ と段を当てはめた一致の数と、四捨五入（φ = 0.5 にあたる）の一致の数を比べる。H-C なら最良の φ は 0 付近（起点の端数のずれで 0.2 程度まで）で、一致はほぼすべて。H-R なら最良の φ は 0.5 付近。
- 外れたときの影響: H-C なら C-0454 の根拠に足す（2 体目）。H-R なら、刻み方はキャラ（持続ダメージの種類）で違うとみて C-0454 を見直す。

## 読み方

1. `hud.ts --mode jumps` の増分を、1 発（40,904.29 × {1, 1.3, 1.5, 1.8, 2, 2.3, 2.5, 2.8} の四捨五入）0〜3 個と tick（92,507・会心 138,761）0〜2 個の和に分け（V-0051 と同じ）、tick を含む増分のフレームを取る（tick 2 個の増分は同じフレームに 2 つとして扱わない。1 つのフレーム）。
2. まとまりに分け、V-0317 の当てはめを回す。
3. 読んだ値は観測値にする（`source` に `V-0321`）。
