# 設計書: CDN のデータの取り直しを壊れにくくする

- 対象: `packages/core/scripts/fetch-data.ts`・`normalize.ts`・`data-diff.ts`（と `data-diff/compare.ts`）
- 作成日: 2026-10-29
- 状態: 決定（2026-10-29。オーナーが 2 節のとおり決めた）・実装済み

## 1. 背景

- CDN のデータ（キャラ・宝物・育成のマスタ）は `npm run fetch-data -- --refresh` で手で取り直している。前回は 2026-10-08 の更新の取り込み（PR #461）で、そのときは説明文を除いた値の変化と、定義済みキャラの説明文の変化を手で確かめた。
- 2026-10-29 に取り直したところ、CDN の roledata の `shot_detail.uptype_fire_timing` が `fire_timing` に改名されていた（全キャラで値は前と同じ）。`normalize.ts` は古い名前を読んでいたので値が `undefined` になり、JSON に書くと `uptypeFireTiming` が黙って消えた。取り直しはエラーなく終わり、`npm test` が射撃姿勢維持型の刻みと残差表のテストで落ちて初めて分かる形だった（落ちたテストからは原因が読めない）。

## 2. 決めたこと（2026-10-29）

1. 取り直しを壊れにくくする（3 節）。
2. 溜まっていた差分（2026-10-08 以後の CDN の更新）を 1 回取り込む（5 節）。
3. 取り直しの定期実行（ルーティン化）はしない。取り直しはこれまでどおり手で行う（4 節）。

## 3. 道具

### 3.1 項目の欠けで止める（`normalize.ts` の `assertComplete`）

- キャラ・キューブ・コレクションの正規化の結果に、`undefined` か数でない数（`NaN` など）があれば、その場所の一覧を出して止める。CDN の項目の改名・削除は、読む側の型を直すまでここで止まる。
- 取得・正規化が 1 つでも失敗したら（キャラ・宝物・マスタのどれでも）、失敗の一覧を出して、`data/` には何も書かない（2026-10-30 に直した。それまではキャラごとの失敗を飛ばして `index.json` を書いていたので、失敗したキャラが `index.json` から抜け、古いキャラのファイルと食い違った）。`fetch-data:diff` は、キャラを `index.json` に載っている分で集める。
- `null` は「無い」と決めた値（`corporationSubType`・`bonusRange`・スキルの `values` の空き）なので通す。
- 個々の項目を名指しで確かめる形にはしない（読む項目が増えるたびに一覧を直す手間を避ける。結果を見れば、どの項目でも欠けは分かる）。

### 3.2 差分を分けて出す（`npm run fetch-data:diff`）

作業ツリーの `data/characters`・`data/masters` を git の版（既定 `HEAD`、`-- --base <ref>` で変える）と比べ、Markdown で出す。PR の本文にそのまま貼る。

- キャラの増減（ID・名前・レア度・クラス・属性・武器・バースト段階）
- 値の変化（説明文とスキル名を除く。射撃のパラメータ・stat・レベル曲線・スキルの `values` など）。定義済みキャラ（`data/skills/index.json`）に印を付ける
- 説明文・スキル名の変化。キャラごとに「ja の文言」「en の文言」「改行・空白だけ」に分ける。定義済みキャラの ja の文言の変化は前後の全文を出す（スキル定義の `ref` が指す値の意味が変わっていないかを読むため。plan/design-stage4.md の「説明文の更新」）
- マスタの変化（キューブ・コレクションは ID で突き合わせ、増減と項目の変化を出す）と、対応表（`src/buildEffects.ts` の `CUBE_SKILL_EFFECTS`・`COLLECTION_SKILL_EFFECTS`）に無いスキル

判断（定義済みキャラの値の変化がスキル定義と結論に効くか、新しいマスタのスキルの対応）は人がする。道具は分けて見せるだけ。

## 4. 取り直す手順

1. `npm run fetch-data -- --refresh`
2. 3.1 節で止まったら、出た場所の CDN の生の JSON（`packages/core/.cache/`）を見て、改名なら `normalize.ts` の `Raw*` の型と読む側を直す。値が前と同じことを確かめ（git の版の `data/characters` と比べる）、もう一度回す（キャッシュから）。
3. `npm run fetch-data:diff` で差分を出して読む。
   - 定義済みキャラの値の変化: スキル定義・結論・観測値の比べ方に効くかを確かめる。効くならオーナーに確かめてから取り込む（AGENTS.md「事実と記録」）。
   - 定義済みキャラの ja の文言の変化: `ref` の指す値の意味が変わっていないかを読む。
   - 新しいキャラ: スキルは定義しない（`plan/skills.md` に未定義として出る）。
   - 対応表に無いマスタのスキル: 説明文から `src/buildEffects.ts` に足す。ダメージに効くが未対応のものは `unsupported` の notes にする。
4. キャラの数を直書きしたテスト（`src/frame/__tests__/stage10Shooter.test.ts`）の数を直す。
5. `npm run records:minimal`（生成物を作り直す）→ `npm run ci`。
6. PR の本文に 3. のレポートと、読んだ結果を書く。

## 5. 2026-10-29 の取り込み

- 項目の改名: `uptype_fire_timing` → `fire_timing`（1 節）。CharacterData の名前（`uptypeFireTiming`）は変えない。
- キャラが 3 体増えた（19 マリアン：クイーン・472 紅蓮：神殺・473 ラプンツェル：サンクチュアリ）。スキルは未定義。
- 472 紅蓮：神殺（AR）の弾の種類は、これまでに無かった `InstantBox` だった（弾速・爆発の範囲は 0。貫通 1）。中身は分かっていないので、モデルは即着弾の弾と同じに計算し、`damage.ts` が「弾の種類 InstantBox は未対応」の注記を出す（貫通の未対応の注記は前からある）。「fire_type が Instant でない武器は RL だけ」はこの 1 体で崩れたが、入力が UP のチャージ武器を fire_type で見分けるところ（`weapons.ts`）はチャージ武器だけを見るので、紅蓮：神殺には掛からない。
- 既存のキャラは、説明文を除いた値の変化が無い。定義済みキャラの説明文は en の文言と改行だけで、ja の文言の変化は未定義のキャラだけ。
- キューブが 1 つ増えた（1000318 レリックベゼルキューブ）。1 つ目のスキル（フルバースト時の最大 HP▲）はダメージに無関係（`ignored`）、2 つ目のアンチコード HC はほかのキューブのアンチコードと同じ対応にした。
