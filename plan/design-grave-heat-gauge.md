## 0. 範囲

- グレイブ（514）の S1「放熱状態の時に限り、味方全体にバーストゲージのチャージ速度 38.96%▲（Lv10）」を、`data/skills/514.json` の skill1 の効果として定義する。いまは C-1122（確定。「増やさない」）に結び付けた補足の notes[0] で、効果に入れていない。
- 足す語彙は、`allyGaugeAdd` の窓（`while`）と、編成の中の持ち主を 2 つ以上にすること（2 節）。比べる指標を 1 つ足す（2.3 節）。

## 1. 分かったこと（V-0751）

- 放熱の間、味方（鈴原サクラ）のゲージ 1 回ごとに一定の量が足される。量はグレイブの 1 発のゲージ（`targetBurstEnergyPerShot` 9,000）× 38.96% = 3,506 と合い、掛け算（× 1.3896）・`burstEnergyPerShot`（4,500）を元にする形・効かない形とは合わない（V-0751 の結果。観測値 `1125-04`〜`1125-06`）。アニス：スターの S1 の味方の分（C-0244・C-0245）と同じ形。
- 放熱の外では足されない（`1125-05`。1 回目のバーストの前）。
- V-0735 で SR の 1 発（56,000）の増分が放熱の間も外も同じに見えたのは、足す量（約 0.5px）が 1 発ずつの読みの揺れより小さかったため。足す形をモデルに入れると、V-0735 のフルバーストの始まりから満タンまで（`1101-22`・`1102-21`）の残差が縮む（4 節）。C-1122 の根拠の値とは矛盾しないが、結論の文（「増やさない」）は、SR の 1 発で 1.39 倍にならないことの言い過ぎになる。

## 2. 語彙

### 2.1 `allyGaugeAdd` の窓 `while`

- `allyGaugeAdd` に任意の `while: { "selfState": "<状態>" }` を足す（`passive` の `while` と同じ形。`skills/types.ts` の `WhileCondition` の `selfState`）。持ち主にその状態が付いている間に着いたほかの枠のゲージ 1 回にだけ足す。
- 状態の見え方は、ほかの `selfState` の条件と同じ（フレームより前に付いた件）。窓の端のフレームは確かめていない（論点 3）。
- 量の元はいまのまま（持ち主の最初の発の着弾の前は `burstEnergyPerShot`、後は `targetBurstEnergyPerShot`）。グレイブは放熱の間は込めていて撃たないが、量は `targetBurstEnergyPerShot` の元で合った（V-0751。`burstEnergyPerShot` の元の読みは合わない）。
- `while` の無い `allyGaugeAdd`（アニス：スター）は、いまと同じに動く。

### 2.2 持ち主を 2 つ以上にする

- いまの 1 パス目は、編成の中で `allyGaugeAdd` を持つ最初の枠だけを使う（`frame/firstPass.ts`。1 つまで）。アニス：スターとグレイブを同じ編成に入れると、後の枠の分が黙って落ちる。
- 持ち主ごとに量と窓を持ち、ほかの枠のゲージ 1 回ごとに、持ち主ごとの量を足し合わせる。2 人の量が足し合うかは確かめていない（論点 2）。
- 1 つの定義に 1 つまで（`parse/definition.ts`）はそのまま。

### 2.3 比べる指標

- `shotGaugeRatioInHolderState`（引数 `slot`・`holder`・`state`）: 枠 `slot` のゲージ 1 回の量（足された量を入れる）の平均を、枠 `holder` に状態 `state` が付いている間と、ほかの時で比べた比（小数 4 桁）。`shotGaugeRatioAfterFullBurst`（V-0638）と同じ考え方で、録画ではバーの 1 回の伸びの比（1px の換算に左右されない）と比べる。
- 1 パス目は、足した量を発の記録（`shotGauges`）に入れていない（持ち主の発だけ）ので、足した量を受けた枠と着いたフレームごとに別に記録する。
- 観測値は、窓の中の傾き（`1125-04`）と窓の外の対照（`1125-05`）の比を新しい観測値にして、この指標と比べる。許容は、窓ごとの傾きの揺れ（0.736〜0.741px）と対照の読みの揺れから決める。

## 3. 定義の案（`data/skills/514.json` の skill1）

- effects に `{ "kind": "allyGaugeAdd", "ref": 4, "while": { "selfState": "heatEmission" } }` を足す。根拠は V-0751 の新しい結論。
- notes[0]（補足。ゲージ速度▲を定義しない）を消す。
- 自分の分（「味方全体」のグレイブ自身の弾）は定義しない。放熱の間、グレイブは撃たず（C-1120・C-1124）、ゲージを溜めるスキルのヒットも無いので、どの編成でも効かない。計算に無関係の notes にする（論点 4）。
- C-1122 を棄却にし、新しい結論の「置き換え」に書く（論点 1）。

## 4. 退化の見込み

- アニス：スター（17）の定義と、アニス：スターを入れた録画の照合は変わらない（`while` が無く、持ち主が 1 つ）。
- グレイブを入れた録画（1099〜1102・1125）で動くのは、一時の変更で見積もると、`1101-22`・`1102-21`（フルバーストの始まりから満タンまで。実測 987f）が 996f から 988f になるだけ（許容 ±10f の内のまま、差が 9f から 1f に縮む）。ほかの比べる観測値は変わらない。実装した後に `npm run records:check` で確かめる。

## 5. 論点

1. C-1122 を棄却にし、「放熱の間、味方のゲージ 1 回ごとに、グレイブの `targetBurstEnergyPerShot` × 38.96% を足す」の新しい結論に置き換える。推奨: そうする（AGENTS.md「事実と記録」。いまの確定の結論と矛盾する変更なので、オーナーの確認が要る）。
2. 持ち主を 2 つ以上にするときの足し方: 足し合わせる（推奨。確かめていないことを `assumes` に書く）か、2 つ目を弾く（定義の読み込みでなく編成の組み立てで誤りにする）か。
3. 窓の端: 状態の付いた次のフレームから外れたフレームまで（ほかの `selfState` と同じ。推奨）。V-0751 の録画では、窓の始まりはチェーンの切れ目と重なり、終わりはグレイブの撃ち直しの直前で、端のフレームは見分けていない。
4. グレイブ自身の分: 定義せず、計算に無関係の notes（放熱の間は撃たない）にする（推奨）か、アニス：スターと同じく自分の分を `passive` の `burstGaugeSpeed`（対象 self・`while`）で書くか。後者は効く場面が無く、根拠も取れない。
5. 比べる指標 `shotGaugeRatioInHolderState` を足す（推奨）か、時刻の指標（チェーンの切れ目から満タンまで）だけで比べるか。時刻は鈴原サクラのリロードと的のジャンプにも左右され、1 回の量を直接見られない。
