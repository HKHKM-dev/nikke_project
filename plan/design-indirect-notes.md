## 0. 目的

- 防御力▲・最大HP▲・バリア・デコイ・遮蔽物・貫通特化などは、それ自体は与ダメージを変えず、その値や有無を読む効果（防御力の比べの対象・最大HP 基準の攻撃力▲・バリア適用状態の条件など）が編成にいる時だけ効く。いまは計算に無関係・前提の外の notes にしていて、読む側のいる編成でも最小構成の検査が見ない。
- notes の種類に「間接」を足し、経路の欄と読む側の印から、検査が「読む側のいる時だけ効きうる」とみなすようにする。計算（calc・sim）は変えない。

## 1. 語彙

### 1.1 notes の種類 `indirect`（間接）

| `kind`     | 画面の印 | 意味                                                                                                                               |
| ---------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `indirect` | 間接     | それ自体は与ダメージを変えないが、前提の中で経路（`path`）の値や有無を動かし、その経路を読む効果が編成にいる時だけ与ダメージに効く |

- 欄 `path`（間接だけ。必須。経路の id を 1 つ）。1 行に 2 つの経路や種類の違う中身が混ざる notes は分ける（論点 1）。
- `effect`（効く先の形）は書いてよい。`refers` は書けない。
- スロットの対応状況（`support`）は未対応に数えない（[design-skill-note-kinds.md](design-skill-note-kinds.md) 2.2 節の表のまま）。

### 1.2 読む側の印 `reads`

- 効果と、未対応・前提の外・補足（`refers` の無いもの）の notes に、`reads`（経路の id の列）を書ける。その経路の値や有無で、値・対象・条件・きっかけ・維持が決まるもの。
- 間接と計算に無関係の notes には書けない。間接の連鎖（HP → 失った HP に応じた防御力▲ → 防御力の比べ）は追わない（論点 2）。

### 1.3 経路の id

| id        | 経路     | 動かす側（間接の notes）                      | 読む側（`reads`）                                                                 |
| --------- | -------- | --------------------------------------------- | --------------------------------------------------------------------------------- |
| `hp`      | HP       | 最大HP▲・現在のHP▼・受ける・与える HP 回復量▲ | 最大HP 基準の攻撃力▲、HP の条件、HP 順の対象、HP で終わる状態                     |
| `defense` | 防御力   | 防御力▲                                       | 防御力の比べ・順位の対象                                                          |
| `barrier` | バリア   | バリアの付与                                  | バリア適用状態なら・バリア適用時                                                  |
| `decoy`   | デコイ   | デコイ（分身）                                | デコイが存在する時                                                                |
| `cover`   | 遮蔽物   | 遮蔽物の HP 回復・復活                        | 遮蔽物が破壊されていない限り・遮蔽物の HP を回復した時                            |
| `pierce`  | 貫通     | 貫通特化                                      | 貫通ダメージ▲                                                                     |
| `pellet`  | ペレット | ペレット数▲                                   | 当たったペレットを数えるきっかけ（1 発の総ダメージは変わらない。ツールチップ T3） |

- 回復は HP を動かすが、経路に入れない（論点 4）。いまの回復の規則（「回復を受けた時」の効果を持つ味方がいる時だけ効く。[design-minimal-relevance.md](design-minimal-relevance.md) 11.8 節）のまま。
- 被弾を通す分（受けるダメージ▼・バリアの HP・挑発・不屈など）は、いまの種類のまま（被弾の経路。分類の別紙 6.6 節）。
- 使い手のいない経路（いまの定義では遮蔽物・貫通の読む側、ペレット）も、分類の別紙 6 節の経路として id を持つ。

## 2. 最小構成の検査（`records/relevance.ts`）

- 間接の notes は要素にする（計算に無関係は今までどおり要素にしない）。
- **効きうるか**: 同じ録画の編成に、同じ経路を読む要素（`reads` を持つ効果か notes。宝物の段階と編成の条件を当てた後）があり、その要素がその録画で起きえて、その観測値に効きうる（静的な判定で外れない）時だけ効きうるとみなす。読む側がいなければ「〈経路〉を読む味方がいない」で外す。間接の要素の効く分類と対象は、自分の形ではなく、読む側の要素で見る。
- **未確定か**: 間接の要素は、読む側のいる編成では、いつも未確定とみなす（理由「間接（〈経路〉）: 読む側のいる編成の根拠なし」）。いま間接の notes に付いている結論（C-0081 など「与ダメージを変えない」）は、読む側のいない編成の根拠なので、読む側のいる編成の確定には使わない（論点 5）。効かないと判断できる組は、人の判断の印（結論の `minimal`）で外す。
- 読む側が同じ定義にある（キャラ自身が読む）なら、そのキャラのいる編成ではいつも効きうる。
- 2 段目の段 7（[design-skill-stage7.md](design-skill-stage7.md) 1.4 節）: 防御力▲ の効果（`stat: "defense"`。状態の中身が防御力▲ だけの付与も）も与ダメージの式を読まないので、効きうるかは経路 `defense` の間接の要素と同じに見る（未確定かは効果の結論で見る。感度の結果があれば感度で決める）。読む側が「自分と自分より最終防御力が低い味方」（`targetDefense`）なら、発動者はいつも対象なので、観測した枠が発動者の枠だけの観測値には効かないとみる。
- 感度（sim の回し直し）は効果だけなので、間接の notes は静的な判定のまま。感度の鍵からは `reads` を除く（計算に効かない欄。`claims`・`notes` と同じ）。

## 3. 「機構が確定したキャラ」

- 間接の notes は、計算に無関係と同じく、キャラ単位の判定（`records/minimal.ts` の `mechanismConfirmed`）から外す。読む側のいる編成では、最小構成の検査が録画ごとに見る。AGENTS.md の定義の括弧書きを「計算に無関係・間接の notes は除く」に直す。

## 5. 表示

- `plan/skills.md`: notes の種類「間接」と経路（「間接（防御力）」）、読む側の印（「読む: 防御力」）。冒頭の notes の種類の説明に間接を足す。
- 画面: スキルの欄の notes の印「間接」（経路を添える）。結果の注記（`NotesSummary.tsx`）には出さない（計算に無関係・補足と同じ）。

## 6. 論点

決定（2026-10-16）: 論点 7 の承認で進めた。細部の 1〜6 は推奨どおりにした（異論があれば戻す）。

1. **1 行の notes の経路**
   - 推奨: 1 つ。混ざる notes は分け、分けた片方は末尾に足す（番号を指す結論・印を変えない）。
   - 代わりの案: `path` を経路の列にする。種類の違う中身（挑発など）が混ざる行は、どのみち分けることになる。
2. **読む側の印を書ける所**
   - 推奨: 直接に効く要素（効果・未対応・前提の外・補足）だけ。間接の連鎖は追わない。
   - 代わりの案: 間接の notes にも読む側を書き、連鎖を流す（読む側が効きうる時だけ効きうる、を繰り返す）。使い手がいない。
3. **読む側が同じ定義にある、未対応の動かす側**
   - 推奨: 未対応のまま（そのキャラのいる編成でいつも効きうる。スロットの対応状況も変えない）。
   - 代わりの案: 間接にする（検査の結果は同じだが、スロットが noEffect に変わり、効くものが無いように見える）。
4. **回復を HP の経路に入れるか**
   - 推奨: 入れない。回復の規則は 2026-10-08 のオーナーの決定（[design-minimal-relevance.md](design-minimal-relevance.md) 11.8 節）で、HP を読む側との関係は段 6（HP の経路）で決める。
   - 代わりの案: 回復も HP の動かす側にし、HP を読む側のいる編成でも効きうるとみなす。
5. **間接の notes に付いている結論（「与ダメージを変えない」）**
   - 推奨: 結論は変えない（根拠の録画の編成に読む側はいない）。検査は、読む側のいる編成ではこの結論で確定とみなさない。
   - 代わりの案: 結論の文に「読む側のいない編成で」と書き足す（確定の結論の文を直すので、オーナーの確認が要る）。
6. **新しく出る最小構成の警告**
   - 推奨: 人の判断の印は付けず、警告をオーナーに出す（[minimal.md](minimal.md)）。
   - 代わりの案: エージェントが印の案を付けて出す。
