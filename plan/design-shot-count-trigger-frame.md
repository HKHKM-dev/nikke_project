# 判断の文書: 射撃の回数で起きる効果は、いつ付くか（ほかの組み合わせでも確かめるか）

- 状態: 実装済み（6 節。第 2 段は 6.6 節、残りは 6.7 節）
- 関連: [backlog.md](backlog.md) 2-38、[roadmap.md](roadmap.md)「回数トリガーで付く持続の効果の付き始めの遅れ」、V-0489（C-0593）・V-0490（C-0628）・V-0265・V-0374（C-0408）、[design-delayed-skill-hit.md](design-delayed-skill-hit.md)（`delayFrames`）、[design-raven-s1.md](design-raven-s1.md) 5 節の 4・[design-moran.md](design-moran.md) 5 節の 2（撃った後の遅れを入れていない所）
- 何のための文書か: 射撃の回数で起きる効果（回復・持続の効果・倍率ダメージ・ゲージ）の付くフレームについて、既存の結論を並べ直し、どこが未確定かと、確かめるならどう撮る（読む）かを示して、オーナーが「確かめる・確かめない」と順番を決められるようにする。

## 1. 決めてほしいこと

1. 2 節の「対象を選ぶ効果だけが遅れる」読み（H-sel）を、確かめに行くか。
2. 行くなら、5 節の 4 つの手（読み直し 2 つ・撮影 2 つ）のどれを、どの順でやるか。
3. 確かめ終わるまで、モデル（いまは遅れを入れていない）をどう扱うか。

推奨は 7 節。

## 2. 既存の結論を並べ直すと

起票（backlog 2-38）の時点では、「回復はすぐ（同じか次のフレーム）、持続の効果と倍率ダメージは約 6f 後」と、効果の種類で分かれているように見えていた。射撃の回数で起きる効果を全キャラの定義から拾い、付くフレームを測っている結論を並べ直すと、種類では分かれない。

### 2.1 付くフレームを測った結論

「遅れる」は、きっかけの発（またはその HUD の増分）から約 6f 後に付く・出るもの。「すぐ」は、同じフレームか次のフレーム（C-0628 の枠の順の規則を含む）。

- **遅れる**: ナガ S2（攻撃力が最も高い味方への持続。C-0593）、ドレイク S2（残りの HP が最も低い敵への倍率ダメージ。V-0265）、プリバティ：UM S1（照準線に最も近い敵への倍率ダメージ。C-0408）、レイヴン S1（照準線に最も近い敵への持続ダメージの付与。C-0181）、モラン S2（最終攻撃力が最も高い敵への挑発のゲージ。C-0480）、紅蓮：ブラックシャドウ S1 の段 A・B・C（撃ったフレームの 9〜10f 後。段 C は敵全体。V-0498）。
- **遅れる？**: ミサト S1・I-DOLL・オーシャン S1（残りの HP の割合が最も低い味方への回復。C-0567・C-0591）。受けたアスカの S1 のアイコンで測っていて、アイコンが効果の何フレーム後に出るかは測っていなかった（※1）。R1（V-0497）で、アイコンは効果が付いたフレームに出ると分かり、回復そのものが遅れていると読めた。
- **すぐ**: マナ S1（味方全体への回復。C-0628）、モダニア S2（自分。C-0124）、鈴原サクラ S1・ルドミラ S1（当たった対象への持続。C-0315・C-0556）、ネオン：VE・シンデレラ・クルミ（当たった対象への追加ダメージ。C-0410・C-0583・C-0276）、ユニ S2（味方全体。窓の終わりだけで測った参考。C-0390）。

## 3. 未確定の点

1. **遅れるかどうかを何が決めるか**（2.2 節）。いまは H-enemy が合うが、確かめていない。遅れの大きさが効果ごとに違う理由も分からない。
2. **対象を選ぶ回復のフレーム**。モデルは C-0628 の規則（マナの「味方全体」から決めた規則）をすべての射撃の回数起点の回復に当てていた。
3. **遅れる効果に枠の順が効くか**。
4. **遅れの値そのものの再現**（値を決めていない録画での再現）。
5. **C-0628 の後ろの枠の側の再現**。
6. **ほかの回数の種類・離れた枠**（フルチャージ・最後の弾丸で起きる「味方全体」の回復や、撃つ枠と受ける枠が 3 つ以上離れたとき）。

1〜4 をまとめて進め、5・6 は優先が低い。

## 4. ダメージへの影響の大きさ

- 遅れが効くのは、窓の付き始め（と、遅れた分だけ後ろにずれる終わり）の数フレームだけ。倍率ダメージは、出るフレームのバフの窓の端に当たったときだけ値が変わる。1 戦闘の総ダメージに効くのは小さく、この遅れのために許容外になっている観測値は無い。
- 効きが大きくなりうるのは、効果を受けて別の効果が起きる連鎖（ミサトの回復 → アスカの S1 のように、受けた側の 1 発の値が大きく変わるもの）と、付き始めのフレームを比べる観測値（`buffWindowStarts`）。

確かめる価値は、ダメージの数値よりも、**C-0628 の規則をほかの回復に広げてよいか**（いまのモデルの前提）と、**`startOfFire`・`healFrameOf`・倍率ダメージの発火の 3 か所に散った規則を 1 つにできるか** にある。

## 5. 確かめる案

最小構成（AGENTS.md）で選んだ。どれも、仮説の出どころの録画（2.1 節）を使わない。

### 5.1 R1（読み直し）: アスカの S1 のアイコンが、効果の何フレーム後に出るか

マナの回復でアスカの S1 が付いたフレーム（1 発の値で決まっている）から、アイコンが出るまでのフレーム数を、録画 0583〜0586 で読む。約 6f ならミサト・オーシャンの「6f 後」はアイコンの遅れだけ、0〜1f なら回復そのものが遅れている。結果は V-0497（C-0649）。

### 5.2 R2（読み直し）: 紅蓮：ブラックシャドウ S1 の段ごとの出るフレーム

1 キャラの中に、対象を選ぶ段（A）と選ばない段（B・C）がある。単騎の既存の録画で、予測を固定してから、撃ったフレーム（照準の横の残弾が減ったフレーム）からの段のヒットのフレームを読む。H-sel を出どころでない録画で検査する最初の手。結果は V-0498（C-0651）。

### 5.3 S-A（撮影 2 本）: ミサトの回復は、前の枠のアスカの何発目から乗るか

◎アスカ（1 枠目）→ ミサト（2 枠目）で、ミサトの回復のきっかけの発の後、アスカのどの発から S1 が乗るかを、S1 なし・ありで約 2 倍違うアスカの 1 発の値で見る。いまのモデルならきっかけの 1〜5f 後の発から、約 6f 遅れるなら次の発から。結果は V-0499（C-0652）。

### 5.4 S-C（撮影 2 本・任意）: ナガの遅れは、受ける側が後ろの枠でも同じか

V-0489 の枠順を入れ替えた ナガ（1 枠目）→ ◎エマ（2 枠目）で、▲が乗り始めるフレームを見る。枠の順（3 節の 3）と値の再現（3 節の 4）を同時に見る。結果は V-0500（C-0653）。

## 6. モデルに遅れを入れる設計（2026-10-26。論点は推奨どおりに決め、第 1 段を実装した）

R1〜S-C の結論（8.1 節）を受けて、射撃の回数で起きる効果の遅れをモデルに入れる設計（R2 で H-sel が外れたので、「対象を選ぶ効果に一律の遅れを入れる」案から書き直した）。

### 6.1 根拠のある遅れ（いまの結論）

遅れは、きっかけの射撃の HUD の増分（RL は照準の横の残弾が減ったフレーム）からのフレーム数。

| 効果                                                                                    | 結論           | 状態                        |
| --------------------------------------------------------------------------------------- | -------------- | --------------------------- |
| ナガ S2 のコアダメージ▲（`timed`）。受ける枠の順に依らない                              | C-0593・C-0653 | 第 1 段で入れた             |
| ミサト S1 の回復（`heal`）。前の枠のアスカの +5 の発には乗らない                        | C-0652・C-0649 | 第 1 段で入れた             |
| モラン S2 の挑発のゲージ（`burstGaugeHit`）                                             | C-0480         | 第 1 段で入れた             |
| レイヴン S1 の持続ダメージの付与のゲージ（`dot` の `gaugeOnApply`）。撃った 6f 後       | C-0181         | 入れた（6.6 節）            |
| 紅蓮BS S1 の段のダメージ（`cycle`）。撃ったフレームから A 10f・B の 1 ティック目と C 9f | C-0651         | 入れた（6.6 節）            |
| プリバティ：UM S1 の倍率ダメージ（`damage`）                                            | C-0408・C-0659 | 入れた（6.6 節）            |
| ドレイク S2 の倍率ダメージ（`damage`。宝物版）                                          | C-0660         | 入れた（6.6 節）            |
| I-DOLL・オーシャン S1 の回復（`heal`）                                                  | C-0650         | 入れた（経過の 2026-10-31） |

遅れない側（いまのモデルのまま）: マナ S1 の回復（C-0628）、モダニア S2（C-0124）、鈴原サクラ S1・ルドミラ：WO S1（命中で数える持続の効果は次のフレームから。C-0645）、ルドミラ S1（C-0556）、ネオン：VE・シンデレラ・クルミの「対象」への追加ダメージ（C-0410・C-0583・C-0276）。

### 6.2 案

- **案 A（推奨）: 効果ごとに、測った遅れを `delayFrames` で書く。** いまの `delayFrames`（倍率ダメージとゲージ。バースト使用・追撃・時間の周期のきっかけ。[design-delayed-skill-hit.md](design-delayed-skill-hit.md)・[design-timer-ceil.md](design-timer-ceil.md) 7 節）を、射撃の回数のきっかけ（`count`）にも開き、`timed` と `heal` にも書けるようにする。書いた効果は、きっかけの射撃のフレーム f の d 後のフレームに起きる。書かない効果はいまのまま。値はスキル定義の即値で、効果の `claims` に根拠の結論を結び付ける（design-delayed-skill-hit.md 3.2 節と同じ）。
- 案 B: 効果の対象の種類から遅れるかを決め（2.2 節の H-enemy）、値は一律にする。H-enemy は確かめていない。遅れを測っていない効果にまで当てることになり、値もそろっていない（約 6f と 9〜10f）。根拠の無い変更になるので採らない。
- 案 C: 入れない（いまのまま「未実装」の注記を残す）。ダメージへの効きは小さい（4 節）が、確定の結論とモデルが食い違ったままになる（C-0652 の判定の発の観測値を比べる指定にできない）。

### 6.3 論点（推奨つき）

1. **遅れの持ち方**: 案 A（効果ごとの `delayFrames`）。理由は 6.2 節。
2. **遅れた効果は、そのフレームのどの枠の発から効くか**: 「d 後のフレームの始めに起き、どの枠の発にもそのフレームから効く（枠の順に依らない）」。根拠: ナガの▲は、受けるエマが前の枠でも後ろの枠でも +6 の発から乗る（C-0593・C-0653）。ミサトの回復は前の枠のアスカの +5 の発には乗らない（C-0652）ので、これと矛盾しない。C-0628 の枠の順の規則（後ろの枠は同じフレーム、前の枠は次のフレーム）は、`delayFrames` を書かない回復だけに残す。
   - 代案: 遅れた効果にも C-0628 の枠の順の規則を重ねる（前の枠は d + 1 から）。C-0653（前の枠のエマでも +6 から）と合わないので採らない。
3. **遅れを数える起点（モデルの射撃のフレームとの合わせ方）**: 「モデルの射撃のフレームから数え、値は HUD の増分から測った値をそのまま使う」。SG・AR・SMG は、モデルの射撃のフレームが HUD の増分（ヒット）のフレームと同じ扱いなので、6 をそのまま書ける。RL は、測った起点が「撃ったフレーム」で、着弾はその数 f 後と揺れるので、モデルの RL の射撃のフレームが撃ったフレームと着弾のどちらに当たるかを確かめてから値を書く（6.6 節で確かめた）。
4. **今回入れる範囲**: 2 段。
   - 第 1 段: ナガ S2・ミサト S1 の回復・モラン S2 のゲージ（宝物版の S2 も同じ値）。どれも値が確定の結論で決まっていて、起点の問題が無い。
   - 第 2 段: 紅蓮BS の段とレイヴンの付与のゲージ（論点 3 の起点を確かめる）、プリバティ：UM S1・ドレイク S2（値を 5 か 6 に決める読み直し）。
   - 入れない: オーシャン S1 の回復（C-0650 は仮説だった）。効果の `assumes` に書く。
5. **回復の対象を選ぶフレーム**: いまのまま（きっかけのフレームで選ぶ）。枠の HP の割合の想定を戦闘中一定とみなしているので、きっかけのフレームで選んでも f + d で選んでも同じになる。
6. **戦闘の終わり**: f + d が戦闘の終わり以降なら、その効果は起きない（いまの `delayFrames` と同じ）。
7. **sim と calc**: 1 パス目（`frame/firstPass.ts`・`skills/holders.ts`）の窓の始まり・回復のフレーム・ゲージの予約で入れるので、sim と calc は同じフレームを見る。calc の数え方は窓の位置を読むだけで、変えない。
8. **観測値の比べ**: 第 1 段を入れたら、ミサトの判定の発（`0659-04`・`0660-04`）を比べる指定（`hitDamage`）に替える。ナガの付き始めは、録画の戦闘開始からモデルのフレームへの換算が要るので、記録のままにする。

### 6.6 第 2 段（2026-10-26。実装した）

- **プリバティ：UM S1・ドレイク S2**: V-0505・V-0506 の読み直しで、どちらも 6f に決まった（C-0659・C-0660）。`damage` の `delayFrames` を射撃の回数のきっかけにも開き、313.json の skill1 の effects[0] と 101.json の treasureSkills.skill2 の effects[0]・[1] に 6 を書いた（`planSkillHits` が d 後のフレームのバフで出す）。`gaugeHits`・`sequential` のスキル・射撃ごとに畳み込む効果（every 1）とは組み合わせない。宝物なしの skill2 は測っていないので入れず、`assumes` に書いた。
- **RL の起点（論点 3）**: モデルの RL の射撃のフレームは、撃ったフレームで較正してある（`firstShotFrames`。C-0218 のモデル側）。R3（V-0519）で、紅蓮BS 単騎の sim の射撃のフレームが撃ったフレームに合い、着弾には合わないことを確かめた（C-0661）。
- **紅蓮BS・レイヴン**: 段（`cycle` の step）に `delayFrames`（A 10・B 9・C 9。C-0651）を書けるようにし、段のダメージを射撃の d 後に出す（B は 3 ティックを 1 ヒットにまとめたまま 1 ティック目に置く）。レイヴンは `dot` の `gaugeOnApplyDelayFrames: 6` で付けたときのゲージだけを 6f 後に足す（C-0181）。段のゲージと、レイヴンの tick の起点は、このときは動かさなかった（6.7 節）。

### 6.7 第 2 段の残り（2026-10-31。点検と読み直し）

第 2 段の後に残った 4 件を、既存の録画で測れるか点検した。

- オーシャン S1 の回復（C-0650）: 既存の録画では測れない（回復を受けて変わる発があるのは仮説の出どころの 2 本だけ）。撮影で確かめた（V-0558。経過）。
- 宝物なしのドレイク S2: 録画がどれも宝物版で撮れない（[burst-effect-delay-candidates.md](burst-effect-delay-candidates.md) と同じ事情）。定義の `assumes` に未測定と書いたままにし、課題からは外す。
- レイヴンの tick の起点: V-0556 → C-0765。最初の tick はモデルより 5f 遅い。
- 紅蓮BS の段のゲージとダメージの関係: V-0557 → C-0764。段 A・B のゲージはダメージと同じフレームで、モデルより 4〜5f 早かった。段 C はバーが隠れて読めない。

モデルに入れる案（2026-10-31 のオーナーの判断で、論点 9〜11 を推奨どおりにし、実装した）:

9. **レイヴンの tick の起点**: `dot` に射撃の回数のきっかけだけで書ける欄 `tickDelayFrames`（d）を足し、tick の刻み・スタックの数・付いている区間を、射撃のフレームの d 後を起点に数える（851.json の skill1 の effects[0] に 5。付けたときのゲージの `gaugeOnApplyDelayFrames: 6` はそのまま）。
   - 代案: 付けたフレーム（F + 6）を起点にし、afterInterval の tick を「付けたフレームの 1f 前から」に変える。クルミ（afterInterval。命中で付ける）の起点まで変わり、そちらは測っていないので採らない。
10. **紅蓮BS の段のゲージ**: 段の `gaugeHits` を段のダメージのフレームに合わせる（A [10]・B [9, 23, 38]・C [9]。C-0764）。データだけの変更。段 C はバーが隠れて読めないので、A・B から推す（効果の `assumes` に書く）。
