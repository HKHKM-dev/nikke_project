# V-0681: 全弾リロードの 1 回ずつの長さと丸めの向き（リロードの秒の端数の違う 9 本の読み直し）

- 問い: 全弾リロードの最終弾から込め終わりまでは、どのリロードの秒でも 1 回ずつ同じ整数か（端数を持ち越さないか）。1 回ごとに丸めるなら、どの向き・どの足す長さか
- 話題: 射撃（間隔・リロード・チャージ）
- 日付: 2026-11-07
- 録画: `0073`、`0005`、`0054`、`0008`、`0045`、`0072`、`0305`、`0099`、`0006`、`0032`、`0033`、`0002`、`0077`、`0046`、`0055`、`0070`、`0071`、`0815`、`0816`、`0122`、`0886`、`0887`、`0123`、`0864`、`0865`、`0098`、`0060`、`0056`、`0076`、`0082`、`0001`、`0012`、`0003`、`0089`
- 状態: 調査中
- 派生元: `V-0680`

## 条件

- 型: 読み直し。backlog の 2-58。C-0964（V-0680）で、リロード 1.67 秒のミハラ・マナのふだんのリロードは 1 回ずつ同じ長さで、モデルの端数の持ち越し（C-0145 の model。`frame/shooter.ts` の `nextChunkFrames`）の 1f 長い回が見えなかった。1.67 秒は端数が 0.24 だけなので、端数の違うリロードの秒で、1 回ずつ同じ長さかと、丸めの向きを見る。
- 録画: C-0145 の根拠（V-0057・V-0058）と V-0264 の単騎（操作キャラ）。リロードの秒（÷ 0.017 の端数）は、ラピ（AR）1 秒（58.82f。0.82）・ミサト（SMG）1 秒・リター（SMG）1.5 秒（88.24f。0.24）・イサベル（SG・分割でない）1.86 秒（109.41f。0.41）・モダニア（MG）2.3 秒（135.29f。0.29）・エマ（MG）2.5 秒（147.06f。0.06）・ルドミラ（SMG）2.76 秒（162.35f。0.35）・ルドミラ：ウィンターオーナー（MG）3 秒（176.47f。0.47）。ラム（SR）2 秒（117.65f。0.65）は、照準の残弾が読めないので、V-0057 の HUD の増分の値（`0075-10`）を使う。リロード 1.67 秒は V-0680。
- 見分けの要:
  - 持ち越す形（いまのモデル）なら、1 回分は ⌊x⌋ と ⌈x⌉ が端数の割合で混ざる（1 秒なら 5〜6 回に 1 回 ⌊x⌋、2 秒なら 3 回に 1 回 ⌊x⌋）。
  - 1 回ごとに丸めるなら、どの回も同じ整数。向きは、端数が 0.5 以上の秒（1 秒・2 秒）と 0.5 未満の秒で、最終弾 → 込め終わりから ⌊x⌋ を引いた値が同じ（切り捨て・切り上げの仲間）か、1 違う（四捨五入）かで見分ける。切り捨てと切り上げは、足す長さが 1 違うだけで見分けられない。
- 最終弾は、照準の残弾の 1 が消えたフレームで取る（HUD の増分はキャラごとに 0〜1f 遅れる。V-0057「読み方で変えたこと」）。
- 最小構成: どれも単騎で、リロードに効く効果を持たない（V-0057 と同じ）。

## 予測

なし（読み直し）。

## 読み方

1. 録画は Drive から取り寄せた（`node tools/captures/fetch.ts`）。
2. `node tools/captures/reload.ts <動画> --mode fit --shots <hud.ts --mode jumps の出力>` で、リロードごとの RELOADING のバーの 0 の点・消えたフレーム（込め終わり）を読んだ。
3. `node tools/captures/reticle-ammo.ts <動画> --mode series` で、各リロードの前に照準の残弾 1 を読んだ最後のフレームの次を最終弾にした（V-0680 と同じ）。
4. 取り消し・窓をまたいだ回・当てはめの残差が 1.2 より大きい回・最終弾の前の照準の残弾が読めない回を除き、最終弾 → 込め終わり（整数）を回ごとに並べた（観測値）。
5. モデルの側は、`nextChunkFrames` の 1 回分を、持ち越さずに 1 回ごとに丸める形（切り捨て・切り上げ・四捨五入・下の ⌈x + c⌉）に変えて、全部の観測値の残差（`npm run records:residual`）をいまのモデルと比べた（コミットしていない）。

### リロードの始まりを 0 の点にすると、c は 1 つ

- バーの 0 の点（端数つき）からの込め終わりは、どの録画も ⌈0 の点 + x + c⌉ の形に乗り、c の幅は録画ごとに (0 の点 → 込め終わりの中央値 − 1 − x, 0 の点 → 込め終わりの中央値 − x]。3 回以上読めた録画（AR・SMG・SR・RL（射撃姿勢維持型・押下チャージ型を含む）・MG）に共通の幅は 11.76〜11.95f（下限は A2、上限はラピ）で、2 回ずつの SG（イサベル・クイーン（真））とベロータもこの幅に入る。武器種で分けなくてよい。
- 武器種による最終弾 → 込め終わりの違いは、0 の点が最終弾のフレームからずれる量（0 の点 − 最終弾）の違いになる。AR・SMG・SG のずれは、モデルの発射レートの蓄積（C-0058）の最終弾の余りから出す「本当の発の時刻」（最終弾のフレーム − 余り ÷ 1 フレームの蓄積）と合う:

- チャージ武器（SR・RL）のずれは、チャージの発の時刻で決まる（入力が UP は約 −0.1〜−1.1f、押下チャージ型は約 +0.6〜+2f、射撃姿勢維持型は姿勢の分だけ後）。モデルのどの値から出るかは見ていない。

## 分かったこと・分からないこと

- 分かった: 全弾リロードの最終弾 → 込め終わりは、どのリロードの秒でも 1 回ごとに同じ整数で、端数を持ち越さない。丸めは四捨五入でなく、⌊x⌋ + 12（＝ ⌈x⌉ + 11）の仲間で、MG の 2 本は 1f 長い（⌈x + c⌉ の形で c が MG で約 0.7f 大きい）。
- 分からない: MG の足す長さが MG の全部で違うのか（エマは端数 0.06 で見分けられない）。SMG 1 秒（ミサト）の 1f 長い値。RL（HUD の増分で最終弾が取れない）。
- 読み足しの後（上の 2 つの節）: 「MG の c が約 0.7f 大きい」は、SMG 1 秒が入らないので取り下げる。全弾リロードは、始まり（バーの 0 の点。端数つき）から数えて ⌈始まり + x + c⌉ で込め終わり、c は全部の武器種で 1 つ（11.76〜11.95f）。始まりは最終弾のフレームから、AR・SMG・SG では発射レートの蓄積の余りのぶん前にずれる。
- 分からない（読み足しの後）: MG の始まりのずれ（蓄積の余りと合わない）。チャージ武器（SR・RL）の始まりのずれを、モデルのどの値から出すか。射撃姿勢維持型の、最終弾からバーの始まりまで（紅蓮BS 約 12f、レイヴン・A2 約 40f）と、いまのモデルの 11f（C-0149）との関係。
- モデルの変え方は [design-reload-rounding.md](../../plan/design-reload-rounding.md)（8 節の判断待ち）。
