## 2. 語彙

説明文の値はスキル Lv10（description_value_NN を「値 NN」と書く）。

### 2.1 千束（PR 1）

- **超感覚**（論点 2）
  - 持ち方: キャラ固有のカウンタ `extrasensory`（目録 `skills/counters.ts`。上限 値 02（100））。説明文の「チャージ」「最大」「持続」「解除不可」はカウンタの形（上限と増減を持ち、時間では外れない）。
  - 増減:
    - 戦闘開始時に 100: `counterChange`（`battleStart`・`amountRef` 1）。
    - 値 10（2）秒ごとに 1 減らす: `counterChange`（`{ everySeconds: 2 }`・`amountRef` 11・`decrease`）。周期は戦闘開始から数え、端数を持ち越す見込み（C-0502 の形）。
    - バースト使用時に 100: `counterChange`（`burstUse`・`amountRef` 1。上限で切る）。
  - 「自分が超感覚状態なら」は、カウンタが 0 より大きい間。単騎の 180 秒でも 0 にならない（100 − 90）ので、条件としては書かない。
- **段階の効果**（「下位効果のスタック適用」）: 閾値ごとに `passive`（`self`）と `while: { selfCounter: { counter: "extrasensory", atLeast } }` を 1 つずつ書く。高い段階では下位の効果も満たすので、重ねて付く形はそのまま出る。
  - 70 以上: `attack` 値 05（53.69）%。
  - 55 以上: `trueDamage` 値 07（48.62）%。
  - 25 以上: `hitRate` 値 09（22.37）%（C-0192 の形で弾丸命中率とコア命中率を上げる）。
  - 100 の時の射撃予測：無敵は計算に無関係の notes。
  - 閾値は即値（値 04・06・08 の説明文の値）。`while` の `atLeast` が即値だけなら、そのまま書く。
- **S2**:
  - 「バーストスキルを使用した時、自分に通常攻撃を防御力無視ダメージに変更（値 01（10）秒）」: `timed`（`burstUse`・`self`・`trueDamageConversion`・`durationRef` 1）。変更の中の通常攻撃の式は、ウンファ：タクティカル・アップのカモフラージュ（C-0311・C-0525）と同じ見込み。
  - 「通常攻撃が 値 02（48）回命中した時、対象に最終攻撃力の 値 03（472.18）% の防御力無視ダメージ」: `damage`（`{ count: "normalHit", everyRef: 2 }`・`damageType: "true"`・`ref` 3）。式は C-0783（コアは乗らず、会心とフルバースト補正が乗る）の見込み。命中の数え方は、モデルの弾丸命中率で数える当たり（C-0363）。
- **バースト**: 超感覚 100 チャージは上の `counterChange`、攻撃力 値 02（73.16）%▲（値 03（10）秒）は `timed`（`burstUse`・`self`・`attack`）。
- まだ組んだ例の無い組み合わせ（周期のきっかけの `counterChange`、`while` の `selfCounter` と `hitRate`）は、検査（`parseSkillDefinition`）と 1 パス目に通るかを PR 1 で確かめる。通らなければ、通すのは検査の許可だけの見込み（語彙の形は変えない）。

### 2.2 ベスティー：タクティカル・アップ（PR 2）

- **S1 のミサイルガイド**（論点 3）
  - 状態: 自分の名前の付いた状態 `missileGuide`（目録 `skills/states.ts`）。付与は `{ count: "fullChargeShot" }`・条件 `selfState`（`missileGuide`・`present: false`）。中身は `chargeSpeed` 値 01（100）%（値 02（3）発間維持）と `chargeDamage` 値 03（58.5）%（値 04（3）発間維持）。
  - チャージ速度 100%▲ はチャージ時間を 0 にし（C-0013）、発射レート（180rpm）で撃つ見込み（シンデレラの S1 と同じ形。C-0603）。ガイドの付いた発もフルチャージの発に数える見込み（シンデレラの S1 の追加ダメージと同じ）。
  - 「最大弾数のリロードが完了した時、自分にミサイルガイド解除」: `removeState`（`missileGuide`）のきっかけに、リロードの込め終わり `reloadEnd` を足す。発火は 1 パス目の射撃の列の込め終わり（`ShotLog.reloadEnds`。`durationUntil: "reloadEnd"` の窓の終わりと同じフレーム）。
  - 読むもの: 3 発に、付けた発（きっかけの発）を数えるか。
    - 数えない形: マガジン 8 発が「溜める 1 発 + ガイドの 3 発」の 2 回で撃ち切れ、解除は起きない。
    - 数える形: 溜める発が 3 発ごと（1・4・7 発目）に来て、リロードの時にガイドが 1 発残り、解除が効く（次のマガジンの 1 発目は溜める）。
    - 撮影 B1 の撃つ間隔の並び（溜める発の位置。値と独立）で分かれる。
- **S2**（どれも「フルチャージ攻撃が命中した時」。`{ count: "fullChargeShot" }`。全弾命中の前提は RL の弾丸命中率 1（C-0168））
  - 対象に最終攻撃力の 値 01（266.6）% の防御力無視ダメージ: `damage`（`damageType: "true"`・`ref` 1）。式は C-0783 の見込み。
  - 自分が戦場コントロール状態なら、自分に攻撃力 値 02（20）%▲（値 03（3）秒）: `timed`（条件 `selfState`（`battlefieldFormation`））。
  - 対象が徹甲炸裂弾状態なら、自分に発射体爆発ダメージ 値 04（20）%▲（値 05（3）秒）: `timed`（条件 `enemyState`（`explosiveRound`）・`projectileExplosionDamage`）。
- **戦場コントロール・徹甲炸裂弾の書き直し**（論点 4）
  - エマ：タクティカル・アップのバーストの effects[0]（`timed`・`burstUse`・`allies`・`attack`・`casterAttack`）を、味方に付く状態 `battlefieldFormation`（中身は同じ攻撃力▲）の付与にする。
  - ウンファ：タクティカル・アップのバーストの effects[0]（`timed`・`{ count: "weaponChangeShot" }`・`damageTaken`）を、敵に付く状態 `explosiveRound`（中身は同じ受けるダメージ▲。エレグのバーストの敵の状態と同じ形）の付与にする。窓の始まり（撃った次のフレーム。いまの assumes）は変えない。
  - どちらも値は変わらない見込みで、既存の観測値で確かめる（[design-skill-stages.md](design-skill-stages.md) 2.2 節の書き直しと同じ扱い。値が変われば近似が外れていたことになり、直さずにオーナーに諮る）。
- **バースト**
  - 防御力無視のバーストスキルダメージ（敵全体（パーツ含む）に最終攻撃力の 値 05（492.3）%）（論点 5）: `burstDamage` の `damageType` に `true` を足す（`damage` と同じ鍵）。式は読む: 防御力を引かない最終攻撃力 × 492.3% に、フルバースト補正・会心・コアのどれが乗るか、防御力無視ダメージ▲（同じ発動の▲を含む）が乗るか。

## 6. 論点

決定（2026-10-31、オーナー）: 論点 1〜7 は推奨どおり。論点の文は諮った時のまま。

1. **段 16 の対象**（0.1 節）
   - 推奨: 千束とベスティー：タクティカル・アップの全スロット。足す語彙が小さくこの段の中で閉じ、どちらも単騎（S1・S2）と機構が確定した I・II とのチェーン（バースト）に分けて撮れる。撮影は 10 本。
   - 代わりの案 A: アインを PR 3 に足す（ニアフェザーの機数を、カウンタか状態のスタックで持つ語彙を決める。撮影は単騎とチェーンの 4 本を足して 14 本）。
   - 代わりの案 B: 千束だけにする（語彙を足さない。撮影 4 本）。
2. **千束の超感覚の持ち方**（2.1 節）
   - 推奨: キャラ固有のカウンタ（`extrasensory`）と、`passive` の `while` の `selfCounter` 3 つ。上限と増減を持ち時間で外れない形はカウンタの定義どおりで、閾値の効果はラプラス：アルティメットヒーローの S2 と同じ書き方になる。
   - 代わりの案: 名前の付いた状態のスタック（最大 100 スタック・持続・解除不可）にし、2 秒ごとの▼をスタック量の減少（段 3）で書く。説明文の「超感覚状態なら」をそのまま状態で読めるが、閾値の条件（スタック数が N 以上の間）を `while` の `selfState` の `stacks` で書くことになり、「N 以上」の形が無い。
3. **ミサイルガイドの解除の書き方**（2.2 節）
   - 推奨: `removeState` のきっかけに `reloadEnd`（リロードの込め終わり）を足す。一覧の「きっかけ: リロード完了時」と同じ形で、ジル（「戦闘開始時および最大弾数のリロードが完了した時」に付与）にもそのまま使える。
   - 代わりの案: 状態の付与に、発数の維持と `durationUntil: "reloadEnd"` の両方を書けるようにする（どちらか早い方で外れる）。シンデレラの S1 の形に近いが、ジルの付与のきっかけには使えない。
4. **戦場コントロール・徹甲炸裂弾の書き方**（2.2 節）
   - 推奨: エマ：タクティカル・アップ・ウンファ：タクティカル・アップのバーストの effects[0] を名前の付いた状態（味方の `battlefieldFormation`・敵の `explosiveRound`）に書き直し、ベスティー：タクティカル・アップの S2 は `selfState`・`enemyState` の条件で読む。値が変わらないことを既存の観測値で確かめる。画面の状態の表示にも説明文の名前で出せる。
   - 代わりの案: 書き直さず、S2 の 2 行を未対応の notes にする（撮影 B3 を撮らない。撮影 8 本）。タクティカル・アップの 3 体の編成でだけ値が足りなくなる。
5. **防御力無視のバーストスキルダメージの書き方**（2.2 節）
   - 推奨: `burstDamage` の `damageType` に `true` を足す（`damage` と同じ鍵）。説明文が「バーストスキルダメージ」なので、バーストスキルダメージ▲を持つ味方と組んだ時の扱いを `burstDamage` の群に合わせられる。式は撮影 B2 で読む。
   - 代わりの案: `damage`（`burstUse`・`damageType: "true"`）で書く。いまの語彙のままだが、バーストスキルダメージ▲が乗るかを `damage` の側で分けることになる。B2 の編成にバーストスキルダメージ▲を持つ味方はいないので、どちらでも B2 の値は同じになりうる。
6. **撮影の編成**（3.1〜3.3 節）
   - 推奨: A1・A2・B1・B2・B3 を 2 本ずつ（10 本）。観測するものごとに未確定の要素を 1 つか、効く所で分けられる 2 つにできる。
   - 代わりの案: B1 を撮らない（8 本）。ベスティー：タクティカル・アップの S1・S2 は B2 のバーストの窓の外で読む。窓の外でもリター・デルタの▲（確定）が乗る区間があり、撃つ間隔の並びはチェーンの待ちで途切れる。
7. **PR の順と撮影の依頼の時期**（1 節）
   - 推奨: PR 1 → PR 2。撮影の依頼は論点が決まったらすぐ 1 回で出す（PR の順は撮影の編成を変えない）。
   - 代わりの案: PR 1 の撮影（A1・A2）だけを先に頼み、千束の結果を見てから B1・B2・B3 を頼む。
