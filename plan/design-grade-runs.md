# 反復実測の数え方: 録画の中の回と、合わせ込みの定数を持たない仮説

- 関連: [verification-guide.md](verification-guide.md) 2.2 節（確定にできる条件。この設計で改めた）、[design-investigation-review.md](design-investigation-review.md) 1.3 節（`decidedOn`）・1.4.2 節の 1（録画の中の反復は回で数える）、[design-records-automation.md](design-records-automation.md) 3.5 節（等級の候補）、[design-minimal-relevance.md](design-minimal-relevance.md) 11.7 節（1 本の録画の中の反復と `gradeReason`）
- 作成日: 2026-10-29
- 状態: 承認（2026-10-29。オーナーの指示「この二つを実施して」。2 節と 3 節の形はこの設計書の案で、PR で確かめる）。実施済み（5 節）

## 1. 目的

反復実測の再現に、仮説・値・読み方を決めるのに使った録画（`decidedOn`）を数えない規定（verification-guide.md 2.2 節）は残したまま、次の 2 つを機械で扱えるようにする。

1. **録画の中の回**。1.4.2 節の 1 で「同じ録画でも、決めた回より後の回が合えば再現に数える」と決めた。ところが機械（`claims.ts` の `gradeCandidate`）は録画で数えるので、人が `gradeReason` に文で書き、claims.md には「書いた等級のほうが上」と出ていた。
2. **合わせ込みの定数を持たない仮説**。式と定数を説明文・データ・確定の結論だけから決めた仮説では、`仮説の出どころ` の録画（残差を見て仮説を思いついた録画）も、許容内で合えば再現に数える。厳密一致では、もう数えている（1.3 節）。

## 2. 録画の中の回（`runs`）

- 結論に欄 `runs` を足す。録画ごとに `{ recording, decided?, reproduced, observations }`。
  - `decided`: 仮説・値・読み方を決めた回（例「1 回目」）。その録画が `decidedOn` にあるときに書き、無いときは書かない（決めるのに使った回があるなら、その録画を `decidedOn` に書く）。
  - `reproduced`: 決めた回より後に合った回（決めた回が無ければ、合った回）。
  - `observations`: その回を載せた観測値。根拠にある、その録画の観測値に限る。
- 等級の候補: `runs` に書いた録画は、`observations` のどれかが許容内なら 2 回と数え、後の回を再現にする。そのため 1 本の録画だけでも反復実測になる。回の数は、許容内の観測値のある録画の数に、こうして 2 回と数えた録画の数を足したもの。
- 機械が確かめるのは、載せた観測値が許容内なことだけ。後の回を本当に載せているか、どの回で決めたかは、`decidedOn` と同じく自己申告になる。観測値の値に回ごとの値が並んでいない（注記にしか無い）ときは、その注記を書いた観測値を挙げる。
- `gradeReason` は、回のほかの理由で等級を候補より上にするときのために残す。

## 3. 合わせ込みの定数を持たない仮説（`parameterFree`）

- 結論に欄 `parameterFree` を足す。式と定数の出どころ（説明文・CDN のデータ・確定の結論の ID）を文で書く。
- 等級の候補: `parameterFree` のある結論は、`decidedOn` の `仮説の出どころ` の録画も再現に数える。`読み方を合わせた` の録画は、これまでどおり数えない。
- 検査（`validateParameterFree`）。
  - `decidedOn` に `値を合わせた` の録画があれば書けない。値を録画に合わせたのなら、合わせ込みの定数を持っているので両立しない。
  - 出どころに書いた結論の ID は、確定の結論に限る（自分は書けない）。仮説の値は、同じ録画に合わせて決めたものかもしれないので出どころにしない。
  - `decidedOn` が要る（無ければ `[]`）。
- 残るおそれ: 仮説を思いついた録画では、候補の仮説のうち合うものを選んでいる。定数を合わせていなくても、その選び方の分だけ自由度がある。これは許容の幅（`compare.tolerance`）と最小構成の検査で抑え、合う仮説が予測ファイルで 2 つ以上なら、これまでどおり下書きと `records:close` が止める。

## 4. 道具

- `records:new -- claim` に `--run "<録画>|<観測値,…>|<後の回>[|<決めた回>]"`（いくつでも）と `--parameter-free "<出どころ>"` を足した。形の誤りは、下書きを作る前に止める。
- claims.md には「録画の中の反復」と「合わせ込みの定数なし」の行を出す。等級の定義の「反復実測」にも、この 2 つを書き足した。
- `records:check` は `validateRuns`・`validateParameterFree` で形を検査する。

## 5. 実施（2026-10-29）

- 1.4.3 節で、録画の中の後の回で再現するとした結論（C-0050・C-0101・C-0133・C-0162・C-0165・C-0216・C-0232・C-0236・C-0394・C-0452・C-0456・C-0490）と、根拠の文に同じ数え方を書いた C-0537 に `runs` を書いた。回と観測値は根拠の文のとおりで、状態と等級は変えていない。
- 機械の候補が変わったのは C-0165・C-0456（単独実測 → 反復実測）。どちらも `gradeReason` を外した。C-0165 の `gradeReason` にだけあった予測の順は根拠の文に移した。ほかの結論は、比べる観測値が無いか、もう厳密一致なので、候補は変わらない。
- `parameterFree` は、まだどの結論にも書いていない。いまある結論で、`仮説の出どころ` を数えると反復実測の候補になるものは無かった（2026-10-29 の main で調べた）。これから確定にする結論で使う。
