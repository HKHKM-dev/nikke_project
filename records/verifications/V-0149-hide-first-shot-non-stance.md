# V-0149: 射撃姿勢維持型でない RL・SR のハイドからの 1 発目が、モデルより長いのはどの区間か

- 問い: 射撃姿勢維持型でない入力が UP のチャージ武器（RL のフラワー、SR のラム・ヘルム・アリス）の単騎 AUTO で、ハイドしていた状態（戦闘開始・敵のジャンプの明け）から 1 発目までがモデルより 1〜2f 長いのは、構え・チャージ・満ちてから撃つまでのどこが長いためで、戦闘開始と明けで、RL と SR で違うか
- 話題: 射撃（間隔・リロード・チャージ）
- 日付: 2026-10-04
- Stage: plan/roadmap.md「今後の課題」。plan/backlog.md 2-20
- 録画: `075`、`076`、`077`、`082`、`088`、`089`、`126`、`127`、`135`
- 状態: 調査中
- 派生元: `V-0143`

## 条件

**何を確かめるか**

- モデルのハイドからの 1 発目は、射撃姿勢維持型でないチャージ武器では、発と発の間から構え解除を引いた長さ（`cadence.ts` の `firstShotFrames`: チャージ + `chargeReleaseFrames` − `aimOutFrames`。1 秒チャージで 69f、アリスの 1.5 秒チャージで 99f）。敵のジャンプの明けは、入力が UP の RL だけ 1f 短い（C-0229。フラワー 68f）。
- 発と発の間（82f）の内訳は、撃った後 → 100% を超えるまで 23f・チャージ 58f・満ちてから撃つまで 1f（`075-05`・`077-26`。境の数え方をフラワーにそろえた値）。モデルの「構え解除 13f を引く」は、ハイドからの構え（ハイド → 100% を超えるまで）を 23 − 13 = 10f（RL の明けは 9f）と置いているのと同じ。
- 射撃姿勢維持型（紅蓮BS・レイヴン・A2）は、ハイドからを 構え（`aimInFrames` 12f）+ チャージ + 満ちてから撃つまで − 1 で出し（plan/design-fire-stance-cadence.md 3.2 節）、明けの構えは 11f（C-0229）。
- 使う録画は、射撃姿勢維持型でない入力が UP のチャージ武器の単騎・AUTO 射撃の録画（最小構成）。ラム `075`・`076`、ヘルム `082`・`088`、アリス `089`（1.5 秒チャージ。チャージ速度の効果はフルバーストとバーストだけで、単騎・オートバースト OFF では乗らない）、フラワー `126`・`127`・`135`（オートバースト OFF）。`077` は前に読んだ値の出どころとして挙げるだけで、読み直さない。

**予測より前に見ている値（後付けになる。比べに数えない）**

- フラワー `077`: 戦闘開始 71f（`077-27`）、区間（構え・チャージ・満ちてから撃つまで）は明けで 11・58・1、戦闘開始で 12・58・1（`077-33`〜`077-35`）。この記録の仮説の出どころ。
- ラム: 戦闘開始から 70f（`075`・`076`。`075-04`）、2 回目の明け（スコープが開いて 100% が出たフレーム）から 70f で、約 11f 100% のまま（`075-06` の注記）。リロードの完了から 71〜72f（`075-07`）。
- ヘルム: 明け（RELOADING が消えて 100% が出たフレーム）から 70f が 3 回で、100% のまま 11f（`082-11`・`082-13`）。戦闘開始（表示が出たフレーム）から `082` 71f・`088` 70f（`082-12`・`088-04` の注記）。リロードの完了から 71f（`082-09`）、100% を超えるまで 12f（`082-14`）。
- つまり SR の和はすでに見ていて、明けは 70f、戦闘開始は 70〜71f。区間（どこが長いか）と、アリス・`126`・`127`・`135` は読んでいない。

**読みの境目**（V-0143 と同じ）

- 戦闘開始: 残り時間の表示が出たフレーム（`timer.ts --mode changes` の +89f 前後の変わり目。C-0229・`122-14`・`123-07` と同じ。モデルの射撃姿勢維持型の式はこの数え方の 86f・94f に合っている）。ヘルムのように、そのフレームに 03:00 が 1 フレームだけ出て次から 02:59 のときも、03:00 のフレームから数える。
- 明け: RELOADING のバーが消えたフレーム（窓の中でリロードを込め終えた回は、照準が動き出したフレーム）。SR はスコープが 2f 後に出る（`082-11`）が、スコープからは数えない。
- 構え: 待ちの始まり → チャージの表示が 100% を超えたフレーム。チャージ: → 250% になったフレーム。満ちてから撃つまで: → 撃ったフレーム（照準の横の残弾が 1 減ったフレーム。SR は総ダメージの増分のフレームと同じ）。

- 見分け: 区間は重ならないので、構えの長さで H0・H4 と H1〜H3 が分かれ、H4 はチャージか満ちてから撃つまでで分かる。H1〜H3 は SR の 2 つの欄で分ける（SR の戦闘開始の構えが 12f なら H1・H2、11f なら H3。SR の明けの構えが 11f なら H1・H3、12f なら H2）。読みの幅は ±1f（重複フレーム）なので、録画ごとの回を並べ、多い値で決める。
- 新しく比べる値: フラワー `126`・`127`・`135` の戦闘開始と明け（`135` は戦闘開始だけ）、ラム `075`・`076` の区間（戦闘開始と、`075` の 2 回目を除く明け）、ヘルム `082`・`088` の戦闘開始の区間、アリス `089` の戦闘開始と明け。ヘルムの明けの区間と、ラム・ヘルムの和は前に見ている（「条件」）ので、比べに数えない。

## 読み方

1. 戦闘開始: `node tools/captures/timer.ts <動画> --mode changes` の +89f 前後の変わり目。前に読んだ録画は注記の値（`075` f805・`076` f825・`082` f845・`088` f1596・`089` f1806）を `timer.ts` で確かめる。
2. 明け: `npm run records:read -- <録画> --recipe reload-segments`（`reload.ts --mode fit`）の取り消された区間の終わり（RELOADING のバーが消えたフレーム）。窓の中で込め終えた回は、照準が動き出したフレームを目で読む。弾切れのリロードと重なった回は読まない。
3. 待ちの始まりから 1 発目まで、照準の周りを 1 フレームずつ切り出し（ffmpeg。V-0143 の読み方。切り出す位置は `aim.ts` の照準の位置。SR はスコープの CHARGE の表示も見る）、100% を超えたフレーム・250% になったフレーム・撃ったフレームを読む。戦闘開始で表示が出たときに既にチャージが伸びていれば、表示の % から伸び（1 フレームあたり約 2.55%。アリスは約 1.7%）で遡る。
4. 観測値: 録画ごとに、構え・チャージ・満ちてから撃つまでを 3 つの `interval`（並びは 明け 1 回目〜・戦闘開始）にする。`source` はこの記録。
5. 比べ: 「予測」の表のどの行に合うかを見る。

## 分かったこと・分からないこと

（起票時）

- 分かっていること: 「条件」のとおり。フラワー `077` では構えが長く（戦闘開始 12f・明け 11f）、チャージと満ちてから撃つまではモデルと同じ。SR の和は明け 70f・戦闘開始 70〜71f で、モデル（69f）より 1〜2f 長い。
