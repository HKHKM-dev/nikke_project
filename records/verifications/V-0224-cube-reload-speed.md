# V-0224: キューブのリロード速度▲は、リロードの長さにどう効くか

- 問い: スペック固定 OFF のマナ単騎で、レリックベアーキューブの「リロード速度▲」は、リロードの長さ（RELOADING のバー）にどう効くか
- 話題: 射撃（間隔・リロード・チャージ）
- 日付: 2026-10-06
- 録画: `252`、`250`、`251`
- 結論: `C-0331`
- 状態: 完了

## 条件

- Stage 13 の残り（[design-stage12.md](../../plan/design-stage12.md) 3.5 節の 6）。
- 録画 3（V-0221「次に撮るもの」）: マナ単騎にレリックベアーキューブを付ける。ほかの条件は V-0221 の録画 1 と同じ。
- 最小構成: リロードの長さに効くのは、CDN のリロードの秒（1.67 秒）をゲーム内の時計で数えた長さ（C-0145）と、問いのキューブだけ。マナのスキルにリロード速度の効果は無く、OL の行にリロード速度は無い。全弾リロードなので、OL の最大装弾数増加で弾数が変わってもリロードの長さは変わらない。
- キューブの値は data/masters/cubes.json の段階の値（Lv15 は段階 3）。キューブのアンチコード（有利コードの攻撃ダメージ▲）は、灼熱の的では乗らない（C-0119）。

## 予測（撮る前に書く）

H1 はいまのモデル（リロードの秒 × (1 − 値)。スキルのリロード速度▲と同じ C-0013 の形）、H0 はキューブが乗らない形で、値は予測ファイル（records/predictions/V-0224.json）にある。H2（リロードの秒 ÷ (1 + 値)。C-0013 で棄てた形）は式を切り替える仮説なので、ここに手で書いた。

| 仮説           | バーが 0 から満ちるまで（f） |
| -------------- | ---------------------------- |
| H1: × (1 − 値) | 予測                         |
| H0: 乗らない   | 予測                         |
| H2: ÷ (1 + 値) | 75.746                       |

- 見分け方: RELOADING のバーの長さ（`reload-segments` のバーの長さ）。H1 と H2 は約 7f、H1 と H0 は約 29f 離れる。
- 合えば: H1 ならモデルはそのまま。
- 合わなければ: キューブのリロード速度▲の入り方（`firingParams` の `reloadSpeed`）を直す。

## 読み方

- `npm run records:read -- <録画 id> --recipe reload-segments --source V-0224 --write` で、リロードごとのバーの長さを読み、その中央値を観測値にする（`reloadFramesAt`。指標の `args`・`setup` は予測ファイルと同じ）。

2026-10-06 にオーナーが 4 本を撮った（録画 1〜4 = `250`〜`253`）。予測の commit の後に撮った。取り込みのときに、どの録画も冒頭のキャラ画面の攻撃力が予測の `build` と同じ（`251`・`252` はキューブの攻撃力を足した見込みどおり）で、キューブの Lv（8・15）も合うことを確かめ、録画の素性の `build` に書いた。

- **予測の指標の誤り**: 予測ファイルの指標 `reloadFramesAt`（リロードの秒をゲーム内の時計で数えた長さ）は、RELOADING のバーの長さと比べる形にしたが、バーの長さには、リロードの秒のほかに武器種ごとの切片（約 11〜13f。C-0135・C-0145）が入る。撮る前にこれを含めなかったので、予測の値（H1 69.069f）とバーの長さ（`252-03` の中央値 80.5f）は、そのままでは比べられない。予測の表の「実測なし」はこのため（観測値は記録用にした）。
- そこで、撮る前に固定した値どうしの差（H0 − H1 = 29.17f、H0 − H2 = 22.49f）を、キューブの無い録画との差と比べた。キューブの無い録画（`250`・`251`、スペック固定 ON・OL なしの `010` も）のバーは約 110f（`250-08`・`251-04`）で、予測の H0（98.2f）＋ 切片と合う。
  - バーの長さの差: 110.0 − 80.5 = 約 29.5f（H1 29.2f・H2 22.5f・H0 0）。
  - 最終弾 → 次の 1 発目の間隔（HUD の増分。モデルはリロード + 24f。C-0148）: キューブなしは 122f が 8 回・9 回（モデル 122.2f）、`252` は 92f が 8 回（モデルの H1 は 93.1f、H2 は 99.7f）。
- H1 の形だけが残り、H2・H0 は外れた。ただし、短縮は H1 より約 0.3〜1f（約 1%）大きい。

## 分かったこと・分からないこと

- 分かったこと: キューブのリロード速度▲は、スキル（C-0013）と同じく × (1 − 値) の形で効く（C-0331。オーナー決定 2026-10-06 で仮説として閉じた。等級は単独実測）。モデルは変えない。
- 分からないこと: 短縮が予測より約 1% 大きい理由（キューブの実際の値が表示の 29.69% と違うか、切片がリロード速度で縮むか、など）。残差は係数で埋めない。

## 次に撮るもの

- 残差を確かめるなら、指標をモデルの通る形（最終弾 → 次の 1 発目。C-0148）にした予測を撮る前に固定し、リロードの長い別のキャラにレリックベアーキューブを付けて撮る（短縮が値に比例するかを見る）。
