- 作成日: 2026-10-04
- 状態: 承認（2026-10-04、6 節の 5 点とも推奨どおり）。実装した（9 節）

## 1. 何を決めるか

- CDN の射撃の項目 `maintainFireStance`（射撃姿勢維持）と `uptypeFireTiming` が 0 でない武器は、データの全キャラで紅蓮：ブラックシャドウ（225）・A2（811）・レイヴン（851）の 3 体だけ（V-0130「条件」）。
- いまのモデルは、紅蓮BS だけを実測の較正表（`frame/firing.ts` の `MEASURED_CHARGE_CADENCE`）で合わせ、レイヴン・A2 はほかのチャージ武器と同じ刻みで撃たせて「射撃姿勢維持型の武器は未対応」と注記している。そのため、レイヴン・A2 の単騎 AUTO の射撃の数がモデルより約 3 割少なく、残差の一覧で許容外（`122-06`・`123-05`）。
- V-0130 で、レイヴン・A2 の 1 回の発の内訳（C-0216）と、ハイドからの 1 発目（C-0218）を確かめた。内訳は `maintainFireStance`・`uptypeFireTiming` から出る見込み（C-0217、仮説）。
- この設計書は、射撃姿勢維持型の刻みをモデルにどう入れるか（式にするか較正表にするか）、ハイドからの 1 発目・リロード・部分チャージをどう扱うかを決める。

## 3. 実測から組み立てた刻み

### 3.1 1 回の発の区間

V-0130 の読み（`122-13`・`123-06`・`077-26`）と、紅蓮BS の内訳（plan/design-stage22.md 0.1 節）を、モデルの数え方（チャージの伸びと満ちたフレームを合わせて C。`075-05` の数え方）に並べ直すと、射撃姿勢維持型の 1 回の発は次の 4 つの区間になる。

1. 姿勢の残り: 撃ってから、表示が 100% に戻るまで（表示は 250% のまま）。
2. 構え: 100% のまま待つ区間。3 体とも同じ長さで、ハイドからの構え（C-0114 の `aimInFrames`）と同じ。
3. チャージ: C − 1 フレーム伸びて、満ちる。
4. 満ちてから撃つまで: 満ちたフレームから撃つまで（ほかのチャージ武器は 1f）。

1 と 4 の和（満ちてから 100% に戻るまで）が射撃の姿勢を保つ長さで、`maintainFireStance` から、4 の位置は `uptypeFireTiming` から出る（C-0217）。

### 3.2 式

ゲーム内の時計（1 フレーム 0.017 秒。`GAME_SECONDS_PER_FRAME`）で数える。

- 姿勢の長さ S = `maintainFireStance` ÷ 100 ÷ 0.017（端数つき）。
- 満ちてから撃つまで H = max(1, ⌈S × `uptypeFireTiming` ÷ 10000⌉)。
- 発と発の間 = ⌈S⌉ + `aimInFrames` + C − 1（区間 1〜4 の和。1 は ⌈S⌉ − H、4 は H）。
- ハイドからの 1 発目 = `aimInFrames` + C + H − 1（姿勢の残りが無い。C-0218 の形）。
- リロードの後の 1 発目 = 発と発の間（いまのまま）。リロードに 11f を足す（3 体とも約 11f。下の 3.4）。
- 部分チャージの進み p = min(1, (C + H − k) ÷ C)。H = 1 でいまの式と同じ。満ちてから撃つまでの間に窓が始まれば p = 1（表示は 250%）。

### 3.3 3 体で確かめた値（CDN の値から計算。実測は観測値の ID）

| キャラ   | S（f） | H（f） | C（f） | 発と発の間（f）    | ハイドからの 1 発目（f） | 実測                                   |
| -------- | ------ | ------ | ------ | ------------------ | ------------------------ | -------------------------------------- |
| レイヴン | 48.82  | 16     | 59     | 49 + 12 + 58 = 119 | 12 + 59 + 15 = 86        | `122-13`・`122-14`（どれも一致）       |
| A2       | 49.41  | 24     | 59     | 50 + 12 + 58 = 120 | 12 + 59 + 23 = 94        | `123-06`・`123-07`（どれも一致）       |

- 区間ごとにも合う: 姿勢の残り ⌈S⌉ − H はレイヴン 33・A2 26・紅蓮BS 13、満ちてから撃つまで H は 16・24・1（`122-13`・`123-06`、plan/design-stage22.md 0.1 節の紅蓮BS の 13・12・17・1）。
- 丸めは ⌈⌉（切り上げ）にした。四捨五入では A2 の発と発の間が 119f になり、`123-06` と 1f 合わない。丸め方は 3 体に合うものを選んだので、C-0217 と同じく仮説の一部（6 節の論点 2）。

### 3.4 リロードの前後の 11f

- 紅蓮BS は、最終弾から次のマガジンの 1 発目までが、リロード + 11f + 発と発の間（C-0149。いまの `reloadExtraFrames`）。レイヴン・A2 も、リロードをまたぐ間から同じ形で約 11〜12f（V-0130「条件」。`122-04`・`123-03` の注記）。射撃姿勢維持の項目の無いフラワーは 0（`077-12` の注記）。
- 内訳（最終弾の後の姿勢とリロードの重なり方）は分かっていない（V-0130「分からないこと」）。3 体に共通の定数として持つ（`WeaponModel` の新しい項目）。A2 はモデルで約 219.2f、録画では 220〜221f で、1 回に 1f ほど短い見込み（射撃の数への効きは 180 秒で 1 発未満）。

## 5. 推奨案（A）の実装

### 5.1 武器の定数（`weapons.ts`）

- `WeaponModel` に `stanceReloadExtraFrames: 11` を足す（3.4。C-0149 の値）。射撃姿勢維持型の構えは `aimInFrames`（12。C-0114）を使い、新しい定数は足さない。
- `aimOutFrames`（13）と `chargeReleaseFrames`（23）は、射撃姿勢維持型でない武器だけに使う（コメントで分ける）。

### 5.2 射撃の実効値（`frame/firing.ts`）

- `FiringParams` に `stance: { frames: number; holdFrames: number } | null` を足す。`frames` = ⌈S⌉、`holdFrames` = H。射撃姿勢維持型でないか、チャージ武器でなければ null。
- `MEASURED_CHARGE_CADENCE`・`measuredChargeCadence`・`MeasuredChargeCadence` を消す。`chargeFrames` は較正の分を足さない値になり、リロードは `stance` があれば `stanceReloadExtraFrames` を足す。
- `chargeShotIntervalFrames(params, model)` の引数を `WeaponModel` に替え、`stance` があれば ⌈S⌉ + `aimInFrames` + C − 1、無ければいまの式（チャージ時間の固定なら C、ほかは C + `chargeReleaseFrames`）。射撃姿勢維持型とチャージ時間の固定が重なるキャラはいない（重なったら `stance` を優先し、テストで固定する）。
- S と H の計算は 1 か所（`stanceFrames(shot)`）にまとめ、`GAME_SECONDS_PER_FRAME` を使う。

### 5.3 刻み（`cadence.ts`）と射手（`frame/shooter.ts`）

- `firstShotFrames`: `stance` があれば `aimInFrames` + C + H − 1。無ければいまのまま。
- `reloadFirstShotFrames`・`simulateShotFrames`・`fire`: `chargeShotIntervalFrames` の新しい引数で、いまの形のまま。
- `partialChargeShot`: p = min(1, (C + H − k) ÷ C)。H は `stance?.holdFrames ?? 1`。
- calc（`computeCadence` の `cycleFrames`）は、上の関数から作るので変えない。

### 5.4 注記（`damage.ts` の `modelNotes`）

- `fire-stance`（未対応）と `measured-cadence`（近似）を、`fire-stance`（近似）1 つにする。文言の案: 「射撃姿勢維持型の刻みは、CDN の射撃姿勢維持の項目からの式（仮説。射撃場の AUTO で紅蓮：ブラックシャドウ・レイヴン・A2 を実測）」。

### 5.5 結論の「モデル側」

- C-0216・C-0217・C-0218: 「未反映」を、`frame/firing.ts` の `stance`・`cadence.ts` の `firstShotFrames` に書き換える。
- C-0149: 「較正表」を、3.2 の式（C-0217）で同じ値になる、に書き換える（結論の文は変えない）。

### 5.6 テスト

- 退化: 紅蓮BS の発と発の間 43f・リロードをまたいで 172f・ハイドからの 1 発目 30f・部分チャージの進みを固定しているテスト（`stage10Shooter.test.ts`・`cadence.test.ts`・`stage11ScarletBsTeam.test.ts` ほか）が、値を変えずに通る。射撃姿勢維持型でない武器の数値は 1 つも動かない（`npm test` の全件）。
- 新規: レイヴン・A2 の発と発の間 119f・120f、ハイドからの 1 発目 86f・94f、リロードをまたぐ間、満ちてから撃つまでの間に窓が始まったときの p = 1。S と H の計算（3 体の表）。
- 較正表の「202 体で紅蓮BS だけ」のテストは、「射撃姿勢維持の項目を持つのは 3 体だけ」に替える（新しいキャラが増えたら気づけるように）。

## 6. オーナーに決めてほしいこと

1. **案**: A（式にする。推奨）・B（較正表に 2 行）・C（いまのまま）。推奨の理由: 項目を持つ 3 体すべてを同じ式で再現でき、外挿が無い。紅蓮BS の較正表が要らなくなる。
2. **丸め**: S・H とも切り上げ（推奨。3 体すべてに合う唯一の組）。四捨五入は A2 で 1f 合わない（3.3）。
3. **満ちてから撃つまでの間に窓が始まったときの発**: p = 1（フルチャージの発として数える。推奨。表示が 250% なので）。部分チャージの発としては数えない。実測は無い（7 節で確かめる）。
4. **操作の枠**: AUTO と同じ刻みにする（推奨）。操作で満ちたまま待つか、すぐ離すかで満ちてから撃つまでが変わるはずだが、実測が無い。注記の文言に「射撃場の AUTO で実測」と書く。
5. **確かめの検証**: 実装の後、新しい検証記録で、レイヴン・A2 の敵のジャンプの明けからの 1 発目（C-0218 で未読）を、予測を固定してから録画 122・123 で読む（推奨。撮影は要らない）。読み直しの予測（plan/design-reread-prediction.md）なので、`122-06`・`123-05` の射撃の数は後付けとして数え、明けの 1 発目が予測と合うかで式を確かめる。

## 7. 確かめ（推奨案のとき）

- `npm run records:check` で、`122-06`・`123-05` が許容内に入ること（4 節の試算）と、紅蓮BS を含む録画（046〜053・055・070・071・084）の残差が 1 つも動かないことを見る。
- 6 節の 5 の検証記録: 予測ファイルに、レイヴン・A2 の窓の明けからの 1 発目（モデルでは `aimInFrames` + C + H − 1）と、窓の始まりの部分チャージの発の有無を入れ、commit してから読む。窓の明けは照準の下の RELOADING が消えたフレーム（V-0091 の読み方）、撃ったフレームは照準の横の残弾（V-0130 の読み方）。
- 実装・確かめ・結論の「モデル側」の書き換えを 1 本の PR にする。

## 8. やらないこと

- リロードの前後の 11f の内訳（3.4）。定数のまま持つ。
- チャージ速度のバフで、姿勢の長さ（S・H）が縮むか。C だけが縮むとする（いまの扱いのまま。射撃姿勢維持型にチャージ速度のバフが掛かる録画は無い）。
- 押下チャージ型（DOWN_Charge）の刻み（backlog 2-18。別の設計）。

## 9. 実装で 5 節から変えたこと・分かったこと（2026-10-04）

- 部分チャージの進み p の分母（C）が、紅蓮BS では 20f（較正表のチャージの後の 2f を含んでいた）から 18f（0.3 秒のチャージ。伸びの 17f + 満ちたフレーム）になった。発と発の間・リロード・ハイドからの 1 発目は変わらないが、窓の始まりの部分チャージの発の値が動き、紅蓮BS 単騎の与ダメージ（`046-02`・`055-02`）のモデルが約 0.01% 下がった（許容の判定は変わらない）。チャージの伸びが 17f なのは plan/design-stage22.md 0.1 節の内訳のとおりで、較正表の 2f はチャージの外の長さだった。
- リロードの後の 1 発目は、射撃姿勢維持型だけ発と発の間の式（`chargeShotIntervalFrames`）を使い、ほかはいまの式（チャージ + 解放。チャージ時間の固定の窓でも解放を足す）のままにした。
- `chargeFrames` は、0 秒のチャージで切り上げが −0 を出すのを 0 にそろえた（較正表の 0 を足していたことで、いままで 0 になっていた）。
- 残差: `122-06`・`123-05` が許容内に入った（4 節の試算と同じ値）。ほかに動いたのは `046-02`・`055-02` だけ。
