## 0. 範囲

- キリ（SSR・RL・支援型・バースト III・風圧。宝物なし）の S1・S2・バーストを `packages/core/data/skills/33.json` に定義し、撮影で結論に結び付ける。
- 説明文のうち、いまの語彙で書けないのは 1 つ。S1 の「防御型の味方 2 機」（2 節）。選び方の句（「最終攻撃力が最も高い」「部隊の一番左側にいる」など）が無く、クラスで絞った候補から N 機を選ぶ。全キャラの説明文で、この言い回しはキリの S1・S2 だけ。
- コードで確かめた、いまのモデル（2026-11-28）:
  - 「〈クラス〉型の味方」は timed・passive の `target: "allies"` と `targetClass` で書ける。N（`targetCount`・`targetCountRef`）は、選び方の決まった対象（`topAttack`・`longestChargeTime`・`lowestHpRatio` など。`isCountedTarget`）にだけ書ける。
  - 編成で決まる対象は、最上位の `skills/composition.ts`（`fixedTargetsOf`）が枠を決めて効果の `fixedTargets` に書き、`skills/targets.ts` が絞る（`longestChargeTime` は順位の先頭の N 枠、`targetLeftmost` は絞り込みの後の先頭の 1 枠）。
  - 「スキル発動者基準で攻撃力 X%▲」は `scaling: "casterAttack"`（発動者のバフ前の攻撃力 × X を足す）。「フルチャージして攻撃した時」は timed のきっかけ `{ "count": "fullChargeShot" }`（発の次のフレームから付き、その発自身には乗らない）。
  - 持続回復（1 秒間隔）は、付いた時に 1 回だけ「回復効果が適用された時」を起こす（C-1174）。

## 2. 語彙: 「〈絞り込み〉の味方 N 機」（timed の `allies` に N を許す）

```json
{
  "kind": "timed",
  "trigger": { "count": "fullChargeShot" },
  "target": "allies",
  "targetClass": "Defender",
  "targetCountRef": 3,
  "stat": "attack",
  "scaling": "casterAttack",
  "ref": 4,
  "durationRef": 5
}
```

- timed の `target: "allies"` に `targetCount`・`targetCountRef`（どちらか 1 つ）を書けるようにする。意味は「武器種・コード・クラスの絞り込みに合う枠（自分も候補）から N 機」。
  - 候補が N 機以下なら全員に付く。
  - 候補が N 機より多いときは、枠の若い順の N 機に付く（選び方は説明文から決まらない。論点 1・2）。デバフ解除の `debuffedRandom` と同じ扱いで、選んだ時は sim の枠の注記を出す。
- 枠は編成で決まるので、`fixedTargetsOf` が絞り込みの後の候補を枠の順で `fixedTargets` に書き、`skills/targets.ts` が先頭の N 枠に絞る（`longestChargeTime` と同じ流れ）。
- 書けるのは timed だけ（キリに要る形）。部隊・特定のキャラ・〈状態〉・両隣・基本バースト段階・一番左側・自分を除く・最終防御力の比べとは組まない（使い手がいない）。
- S2 の「防御型の味方 2 機」は間接の notes なので、語彙を使わない。

- 使い手はキリだけで、既存の定義の数値は変わらない。

## 4. 検証（撮って確かめる問い）

- 撮影は V-0882（編成・予測・撮影の依頼はそちら）。撮影ごとの狙い:
- 撮影 A（キリ + デルタ）: デルタの 1 ヒットに、キリのフルチャージの発から 3 秒だけ S1 の攻撃力▲が乗るか。
- 撮影 B（ルドミラ + デルタ + キリ）: キリのバーストの窓の中で、ルドミラの会心の割合が上がるか。防御型がちょうど 2 機の時に S1 が両方に付くか。
- 撮影 C（防御型 3 機 + キリ）: S1 の▲のアイコンがどの 2 機に付くか（論点 2）。

## 5. 論点（オーナーに決めてもらうこと）

1. **「防御型の味方 2 機」の書き方**（2 節）
   - 推奨: timed の `target: "allies"` に `targetCount`・`targetCountRef` を許す。候補が N 機以下なら全員、多いときは枠の若い順（`debuffedRandom` と同じ決め打ちと注記）。対象の値を 1 つ増やさずに済み、`allies` の絞り込みの判定と編成で決まる枠の流れをそのまま使える。
   - 代わりの案 A: 新しい対象（例: `filteredAllies`）を足す。意味は同じだが、対象の値ごとの分岐（`isEffectTarget`・画面と CLI のラベル）が増える。
   - 代わりの案 B: 候補が多いときは、各候補に N / 候補の数 の割合で付ける（期待値）。発ごとにランダムに選ぶ形なら近いが、いまの timed には割合で配る形が無い。撮影 C でランダムと分かった時に決める。
2. **候補が N 機より多い編成を撮るか**（4 節の撮影 C）
   - 推奨: 撮る（A・B と同じ日に 1 本）。防御型が 3 機以上の編成は多くないが、選び方は語彙の決まりなので、アイコンだけで読める 1 本で決めておく。合わなければ、2 節の選び方を撮れた形に直す（ランダムなら案 B を設計する）。
   - 代わりの案: 撮らない。候補が N 機より多いときの選び方は `assumes` に「確かめていない」と書き、sim の注記で知らせる。
3. **撮影の編成**（4 節の撮影 A・B）
   - 推奨: A（キリ + デルタ）と B（ルドミラ + デルタ + キリ）の 2 通り。A は S1 を最小構成（キリと防御型 1 機）で見る。B はバーストに要るチェーン（I・II・III）を、機構が確定した防御型だけで組む。どちらも 2 本ずつ。
   - 代わりの案: B だけを撮る（S1 もルドミラ・デルタで見る）。ルドミラの S1 の敵の防御力▼（確定）がデルタのヒットに混ざるが、未確定の要素は増えない。本数は減るが、S1 の最小構成ではなくなる。
4. **バーストの持続回復**（1 節）
   - 推奨: heal で定義し、結論は仮説にする（ビスケットの S1 の持続回復の C-1224 と同じ）。撮影 B の編成には「回復を受けた時」の効果を持つ味方がいないので、付く時と対象は枠の下のアイコンで見る。
   - 代わりの案: 未対応の notes にする（回復を受けた時の効果を持つ味方と組む編成の数値に効かない）。

決定（2026-11-28、オーナー）: 論点 1〜4 は推奨どおり。
