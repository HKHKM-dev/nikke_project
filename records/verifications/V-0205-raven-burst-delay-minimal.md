## 条件

**何を確かめるか**

- C-0233（仮説・単独実測）は、録画 `173`（ラム + デルタ + レイヴン）の 1 本だけから出した値で、ラムの機構が未確定なので最小構成でない。また `173` の予測の commit は録画の後だった（V-0150 の注記）。最小構成の新しい録画で、予測を撮る前に commit して、同じ値が出るかを見る。値を決めるのに使っていない録画で再現すれば、等級の候補は反復実測になる（plan/skills-guide.md 1.8 節）。
- あわせて、ヒットの値に同じ発動の S1 の攻撃力▲が乗らないこと（C-0234。仮説・厳密一致。`173` の 1 本だけで、最小構成でない）も、同じ予測ファイルの値で比べる。
- バースト使用時の効果（A.N.モード。持続ダメージ▲）は語彙に無いので、今回も読まない。

**編成**

- ココア（311。I）+ デルタ（20。II）+ レイヴン（851。III・操作・AUTO 射撃 ON）、オートバースト ON。射撃場・灼熱の BigArms・3 分モード・スペック固定。`173` の I をラムからココアに替えただけの編成。
- **最小構成**: ココアは定義が効果なし（V-0031）、デルタは C-0081 で、どちらも機構が確定している。ラムは C-0235 が仮説で未確定なので I にしない（backlog 2-4）。2026-10-05 に `records/minimal.ts` の検査（`minimalWarnings`）にこの編成をかけ、警告が出ないことを確かめた（未確定はレイヴンだけ）。

**読み方の前提**

- III の発動は、III のタイマーが 00.00 になったフレーム（V-0078・V-0082・V-0137）。遅れ（モデル）= 動画のフレームでの「III の発動 → ヒット」− 22（フルバーストの入りの止まり。C-0069）。照合の `burstHitDelays` は止まりを含めた動画のフレームで比べる。
- ヒットは止まりの明けた後に出るので、`hud.ts` で単独の増分として読める見込み（V-0150）。
- S1 の持続ダメージの tick（1 秒ごと。全スタックの和）が HUD の増分に混ざる。tick の値はスタックの数の倍数なので、バーストのヒットと分けられる（V-0150）。

## 予測（撮る前に書く）

撮る前に書いた（2026-10-05）。H0 はいまのモデル（遅れの表のレイヴンの行、ヒットの値に S1 の▲は乗らない）で、値は予測ファイル（records/predictions/V-0205.json）。

| 仮説                                    | 5 回の「III の発動 → ヒット」（動画のフレーム） | 1 回目のヒットの値                                   |
| --------------------------------------- | ----------------------------------------------- | ---------------------------------------------------- |
| H0: いまのモデル（C-0233・C-0234 の値） | 予測ファイルの `raven-delays` ± 1f              | `raven-burst-hit`・`raven-burst-hit-crit` のどちらか |
| D2: 毎回同じだが C-0233 と違う          | どの回も同じ値 ± 1f で、H0 から 2f 以上ずれる   | （H0 と同じ）                                        |
| D0: 毎回違う                            | 2f 以上ずれる回がある                           | （H0 と同じ）                                        |
| S1: 同じ発動の S1 の攻撃力▲が乗る       | （H0・D2・D0 と組み合わせる）                   | `raven-burst-hit` の約 1.475 倍（V-0150 の予測）     |

- **H0 を予想する**。遅れの表のどのキャラも回ごとに揃い、I・II の顔ぶれを替えた録画（ドレイクの `037`・`039`、クイーン（真）の `021`・`040`）でも同じ値だったため。ヒットの値は `173` で H0 と端数まで合った。
- 1f の揺れは録画の重複フレームの位置で出る（V-0150）ので、± 1f を合うとみる（観測値の許容 `abs: 1`）。
- 当たったときの影響: C-0233・C-0234 を確定（反復実測）にできる。遅れの表の値は変わらない。
- 外れたときの影響: D2 なら、遅れが I・II の顔ぶれで変わることになり、遅れを演出の長さで決まる値とみる前提（plan/design-burst-landing.md）を見直す。D0 なら、何で決まるかを調べる。S1 が当たったら、撃つ側のバフを発動の直前で固定する規則（plan/design-burst-landing.md 9 節）を見直す（`173` と食い違うので、ラムが何かを変えていたことになる）。

## 読み方

1. 取り込む: `node tools/captures/intake.ts <元ファイル> --id NNN --name sr+sr+rl_cocoa+delta+raven_raven-auto --rid 311,20,851 --controlled 3 --target BigArms --element Fire --mode range-3min --fixed-spec on --auto-fire on --auto-burst on`。台帳を埋めて `npm run records:table`。この検証記録の冒頭に「録画」を足す。
2. 右のバースト欄を 1 フレームずつ並べて、各回の III のタイマーが 00.00 になるフレームを読む。
3. HUD の増分（`npm run records:read -- <録画 id> --recipe hud-jumps`）から、各回のレイヴンのバーストの倍率ダメージのヒットのフレームと値を取る。
4. III の発動 → ヒットを観測値（`burstHitDelays`。許容 `abs: 1`）、1 回目のヒットの値を観測値（`burstHitDamage`。会心かどうかで `crit` を選ぶ）にする。`args`・`setup` は予測ファイルの指標と同じにする。
