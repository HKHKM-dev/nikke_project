## 0. 範囲

- 足りない語彙は 3 つ（2.1〜2.3 節）。どれも、既にある語彙の制限を開くか、欄・種類を 1 つ足す形。カウンタと状態の目録に 1 つずつ足す（2.4 節）。

### 0.1 コードで確かめた、いまのモデル（2026-11-15）

- 回数のきっかけの数える窓 `during: { state }` は、状態の付与と弾丸チャージにだけ書ける（`skills/parse/trigger.ts`）。発火の読み（`skills/holders/fires.ts` の `firesOf` → `skills/holders/sources.ts` の `stateWindowFires`）は効果の種類によらない作りで、カウンタの増減・解除の出どころも `firesOf` で発火を作る（`createCounterSources`・`createRemoveSources`）。
- `stateWindowFires` は、自分のその状態の件が効いている間の自分の発（`ev.shots[slotIndex]`）だけを数え、件が新しく始まったら 0 から数え直す。味方の発は数えない。
- 味方全体の回数のきっかけは `teamAmmo`（味方が消費した弾の合計）だけで、命中の合計は無い。`teamAmmo` は burstGauge と damage にだけ書け、`during` とは組めない。
- カウンタの増減（`counterChange`）は、そのフレームのすべての判定の後に足し、0 と上限の間で切る（`skills/holders/register.ts` の `registerCounters`）。下限を上げる欄は無い。条件 `selfCounter`（`atLeast`・`below`）は前のフレームの終わりの値を見る（ネオン：ビジョン・アイのバーストが `below`・`atLeast` で分岐している）。
- カウンタの段階の効果は、閾値ごとの `passive` と `while.selfCounter`（千束の超感覚）。`while` は対象を選ばない（`allies`・`targetElement`・`scaling: "casterAttack"` と組める）。
- 状態の付与は時間の周期のきっかけ（`{ everySeconds, carry }`）を受ける。damage は `burstUse` と `hitsRef`・`hitIntervalFrames`・条件 `selfCounter` を組める（ラプラス：アルティメットヒーローのバーストが `burstUse` の damage に `selfCounter` を書いている）。
- モデル（定義なし・スペック固定・単騎・灼熱の BigArms・3 分モード）では、エレグの射撃は約 6.6 秒撃って約 2.9 秒のリロードと立ち上げの繰り返し（マガジン 300 発）。戦闘開始から 6 秒ごとの窓のうち 30 本中 7 本ほどは、窓の中の発が 100 に届かない（リロードと的のジャンプに当たる窓）。

## 2. 語彙

### 2.1 回数の種類「味方全体の命中」`teamHit`（論点 2）

- 射撃の回数の種類に `teamHit` を足す。自分を含む編成の全員の通常攻撃の発の、命中の期待値（その発の弾丸命中率。SG はトリガー 1 回を 1 回）を足し、累計が N の倍数に届いた発で発火する。自分が撃たないフレームでも、味方の発で発火する（`teamAmmo` と同じ数え方で、量が命中）。
- 書けるのは、数える窓が自分の状態（`during: { state }`）のときだけ（使い手はエレグ：ブーム・アンド・ショックだけ。窓の無い使い手が出たら、そのとき開く）。窓は持ち主（自分）のその状態の件で見る。
- 実装は `stateWindowFires` の量の足し方を、`teamHit` のときだけ全部の枠の `ev.shots` の和にする。

### 2.2 `during: { state }` を、カウンタの増減・倍率ダメージ・解除に開く（論点 3）

- `counterChange`・`damage`・`removeState` の回数のきっかけに `during: { state }` を書けるようにする。発火の読みは今の `firesOf` のまま（効果の種類によらない）で、変えるのは読み込みの制限（`skills/parse/trigger.ts` の `during: 'withState'` を渡す所）と、同じ定義に自分に付けるその状態の付与があるかの検査（`skills/parse/crossChecks.ts` の `needGrant`）。
- damage は、倍率ダメージの発動を作る所（1 パス目）が `firesOf` を使っているかを実装で確かめる。射撃ごとに畳み込む形（毎回・条件なし）には書けないまま（`every` が 1 でなく条件もあるので、エレグ：BS の S2 は当たらない）。
- 同じきっかけの 3 つの効果（キャプチャー・解除・S2 のダメージ）は、どれも同じ発の列と同じ窓で数えるので、同じフレームに発火する。解除はそのフレームで件を閉じ、次のフレームからは数えない。

### 2.3 カウンタの減少の下限 `floor`（論点 4）

- `counterChange` に `floor`（1 以上の即値の整数。`decrease` のときだけ）を足す。減らした結果が `floor` を下回るなら、`floor` と減らす前の値の小さい方で止める（減らす前が `floor` 未満なら変えない）。説明文の「最低 N を維持」。
- 同じフレームに同じカウンタの増減が重なったら、増減の和を足した後に、そのフレームで発火した `floor` の最大で止める（エレグ：BS では、バーストのフレームにキャプチャーが重なる回だけ。和の後で止めるので、+1 と −6 が重なれば −5 として扱う）。

### 2.4 目録に足すもの・足さないもの

- カウンタ `ghostCapture`（幽霊キャプチャー数・上限 13。説明文の「最大 13」）を `skills/counters.ts` に足す。
- 状態 `ghostPossession`（憑依）を `skills/states.ts` に足す。持ち主は味方（`ally`）にする。説明文では敵に付くが、モデルで要るのは「数える窓」だけで、窓は `stateWindowFires` が自分の状態の件で読むため。敵 1 体の前提（[requirements.md](requirements.md) 4.2 節）では、敵に付く憑依の窓と、自分の状態の窓は同じ。中身は書かない。扱い方の補足（`modeling`）の notes にこのことを書く。
- 足さない: 段階の効果（`while.selfCounter`）、水冷コードの味方（`targetElement`）、発動者基準の攻撃力▲（`casterAttack`）、有利コードの攻撃ダメージ▲（`elementDamage`）、N 回順番に攻撃（damage の `hitsRef`・`hitIntervalFrames`）、カウンタでの分岐（条件 `selfCounter`）は今の語彙のまま。

## 3. 定義の案（`data/skills/502.json`。値は `ref`）

- 1 節の表のとおり。閾値（1・4・13）は `while.selfCounter`・条件 `selfCounter` が即値しか取らないので即値で書き、どの説明文の値（S1 の description_value_04・06）かを `assumes` に書く。
- バーストの順番の攻撃の最初のヒットの遅れ（`delayFrames`）とヒットの間（`hitIntervalFrames`）は説明文に無いので、録画で読んで即値で書く（読むまでは予測のための仮の値で、PR の前に読んだ値に置き換える）。
- S2 のダメージとバーストの順番の攻撃がバーストゲージを溜めるか（`gaugePerHit`）は、説明文に無い。4 人の録画のゲージで読めなければ、溜めないまま未対応の notes にする。
- `assumes`:
  - S1 の憑依: 「憑依は戦闘開始時と、そこから 6 秒ごと（端数を持ち越す）に付き、6 秒で外れる。敵 1 体なので、憑依の窓を自分の状態として持つ」。
  - キャプチャー: 「命中回数は憑依の間の味方全体の通常攻撃の命中の期待値を数え、100 に届いた発でキャプチャー数を 1 増やして憑依を外す。憑依が付くたびに 0 から数え直す（届かなかった憑依の回数は持ち越さない）」。

## 4. 撮って確かめる問い

撮影は V-0789（編成・予測・撮影の依頼はそちら）。単騎の録画で S1・S2 の数え方を、4 人（I・II と、発の多い AR を足す）の録画でバーストと味方の命中を見る。

- R（付き直し）: R1（本命）戦闘開始から 6 秒ごとに付く／R2 前の憑依が外れて（キャプチャーか時間切れ）から 6 秒後に付く。
- E（キャプチャーの後）: E1（本命）キャプチャーで憑依が外れ、6 秒に最大 1 回／E2 同じ憑依の中で 100 回ごとに何回でもキャプチャーする。
- C（届かなかった憑依）: C1（本命）次の憑依で 0 から数え直す／C2 回数を持ち越す。
- T（味方の命中）: T1（本命）味方の通常攻撃の命中も数える／T2 自分の命中だけ。4 人の録画で、自分の命中が 100 に届かない窓でもキャプチャーが起きるかで見分ける。
- F（最低 1）: キャプチャー数が 6 以下でバーストを使うと 1 になり、攻撃力▲が残る（F1・本命）／0 になって攻撃力▲も外れる（F2）。
- バースト: 13 でない時の 6 ヒットと 13 の時の 13 ヒット、ヒットの間、キャプチャー数の減り（13 → 4 で有利コードの攻撃ダメージ▲が残る）。
- S1 の▲の値（攻撃力▲はエレグ自身にも乗る。有利コードの攻撃ダメージ▲は灼熱の敵への発に乗る）、S2 の攻撃力▲と 1100% のダメージの値。

## 5. 退化の見込み

- 足す語彙は、どれも書かなければ今と同じ振る舞い（`teamHit`・`floor` は新しい欄、`during: { state }` は今まで書けなかった所に開くだけ）。既存のテストの数値は変わらない見込み。
- `stateWindowFires` の量の足し方を変えるのは `teamHit` のときだけで、グレイブ・フォーチュンメイトの数え方は変えない。

## 6. 論点（オーナーの判断）

1. 定義の範囲: 1 節の表のとおり、全スロットを定義する（未対応の notes を残さない見込み。ゲージは 3 節の扱い）。
2. 語彙: 味方全体の命中 `teamHit` を、自分の状態の窓だけに足す（2.1 節）。
3. 語彙: `during: { state }` を、カウンタの増減・倍率ダメージ・解除に開く（2.2 節）。
4. 語彙: カウンタの減少の下限 `floor` を足す（2.3 節）。減らす前が下限未満なら変えない読みでよいか。
5. 憑依を、敵の状態でなく自分の状態の窓として持つ（2.4 節）。
6. 撮影: 単騎を 2 本（1 回目・4 回目のキャプチャーは 1 本に 1 回なので型 C）と、I-DOLL・フラワー（I）+ ノア（II）+ エレグ：BS（III・操作）+ ソルジャーE.G.（III・AR）を 2 本（バーストを手で 2 回。キャプチャー数が 4〜5 の間と、13 になった後）。ソルジャーE.G. は味方の命中を数えるか（T）を見分けるために入れる（RL の 2 人だけでは、自分の命中が届かない窓を埋める味方の命中が 1〜2 回の差になる）。編成と手順は V-0789。

## 7. 撮った後に決めたこと

- 本命の読み（4 節の R1・E1・C1・T1・F1）で、どの比べる値も合った（C-1312〜C-1315）。語彙は 2 節のまま。
- バースト使用時の効果の発火を、遅れの表（`burst/landing.ts`）の 502 の行で III のタイマーの 00.00 の 1f 後にした（C-1315）。順番の攻撃はフルバースト補正の乗った値で出て、キャプチャー数の表示は 00.00 から 1 ヒット目までの間に減る。行の無いキャラの効果は本当の発動（00.00 の 6f 前）で発火し、「N 回順番に攻撃」は発火のフレームの値で出る（C-0735）ので、行が無いとフルバースト補正が乗らない。遅れ 0 の行は本当の発動になるので、読んだ範囲（00.00 から 1 ヒット目の 6f 後まで）の中の 1f にした。
- 予測の指標の出来事に、カウンタが増えたフレーム（`eventFrames` の `counterUp`）を、指標に、発動の後のカウンタの値（`counterAfterBursts`）を足した。
