# V-0363: 旧の hud.ts の 0/8 の誤読で増分の値が違っていた、照合に使う観測値を洗う

- 問い: 旧の hud.ts（0 を 8 と読むことがあった）の増分で読んだ、照合に使う hit・rate・count の観測値のうち、直した hud.ts の増分で読むと値が変わるものはどれか

- 日付: 2026-10-08
- 録画: `245`、`278`、`279`、`283`、`285`
- 結論: `C-0324`、`C-0334`
- 状態: 完了

- 訂正: `V-0217`、`V-0241`、`V-0245`、`V-0246`

## 条件

- 撮影なし。V-0327 の「分からないこと」（旧の誤読で増分の値が違っていた観測値）と backlog.md 5-3 を調べる。
- 対象は、`use: compare` の `hit`・`rate`・`count` の観測値のうち、`method` が hud.ts の増分（`--mode jumps`・`--mode series`、レシピ hud-jumps のキャッシュを含む）を使うもの（2026-10-08 の main の時点。失効したものを除く）。冒頭の「録画」は、観測値を訂正した録画。
- `use: record` の観測値と、フレームの差（`interval`・`timing`。V-0327 で洗った）は対象の外。
- 録画はクラウド環境に Drive から 1 本ずつ取り寄せて読んだ（読んだら消した）。比べのスクリプトと出力は追跡しない（scratchpad）。

## 予測（撮る前に書く）

探索（旧の読みの再点検。予測なし）。見立ては次のとおり。

- 1 ヒットの値（`hit`）は、同じ値が何度も出る格子の値なので、誤読の増分が混ざっても値は変わらない。
- 数え上げ（`rate`・`count`）のうち、割れた読みを足し戻す読み方のものは変わらない。旧で「分けられない」「格子に乗らない」として除いた増分が、直した読みで数えられるようになるものは変わる。

## 読み方

1. 対象の観測値のある録画（hud.ts の増分を使う hit・rate・count の観測値のある 246 本。照合に使うものは 137 本）を、旧の hud.ts（`ff5ea516` の読み方）と直した hud.ts（V-0327）で全フレーム読む。1 回のデコードで両方の読みを出すスクリプトで読み、出力が旧と新の hud.ts の `--mode jumps` と同じになることを録画 `019` で確かめた。
2. 旧と新の増分の列から、値の違う所を出す。増分の両端の総ダメージの値（前の値, 値）の組で比べ、片方にしかない増分を、総ダメージの値の範囲が重なるものでまとめて「違う区間」にする（フレームだけが違う増分は数えない。それは V-0327 で洗った）。
3. 違う区間のある録画の観測値ごとに、観測値の読み方（説明・注記・`source` の検証記録）に戻って、使った増分が違う区間にかかるかを確かめる。
   - 増分の値そのものの `hit`: 旧と新の増分の中の、その値（差 2 以内）の数を比べる。
   - 分解・割り算で出した `hit`: 注記のフレームが違う区間にかかるかと、違う区間の新の増分が同じ単位の格子に乗るかを見る。
   - `rate`・`count`: 読み方を旧と新の増分で回し直し、旧で観測値と同じ値が出ることを確かめてから新の値を出す。回し直せないものは、違う区間ごとに旧と新でどう数えが変わるかを見る。

## 結果

### 違う区間

- 照合に使う観測値のある 137 本のうち、違う区間のある録画は 114 本（観測値は 433 件。内訳は hit 334・count 70・rate 29）。違う区間の無い 23 本の 67 件は値が変わらない。
- 違う区間の大半は、隣り合う 2〜3 フレームの割れ（例: 旧の +80 と +330,284 が新の +330,364）と、旧で読みを落として数発がまとまった増分（例: 旧の 136,726 が新の 30,028 × 3 + 46,642 の 4 増分）。どちらも区間の中の増分の和は旧と新で同じ。

### 値が変わらないもの

- **hit（334 件）**: 値が増分そのもの（259 件）は、どれも新の増分にも同じ値がある（新で数が減ったものは無い）。分解・割り算で出したもの（75 件）は、注記のフレームが違う区間にかからないか、違う区間の新の増分が同じ単位の格子に乗る（`259-01` は新で f10474 の 1,293,757 = 185 単位が加わりうるが、同じ胴体 104,899.2 にちょうど乗るので 0.1 の桁で同じ）。
- **値の組の比**（`022-04`・`022-05`）: 同じ値どうしの比なので変わらない。
- **値で特定したヒットの回数**（`019-19`・`162-33`・`165-35`・`221-10`・`081-19`）: 値の一致するフレームは旧も新も同じ。
- **満タンまでのヒットの番号**（`045-03`・`055-12`・`075-21`・`076-13`・`127-05`）: 違う区間は満タンの後か、満タンの前でも増分の数が旧と新で同じ。
- **残弾の表示で決まる発の数**（V-0188 の 18 件 `137-14`〜`172-03`、`162-24`・`165-24`・`099-10`・`266-06`・`266-07`・`274-06`・`274-07`・`275-06`・`275-07`）: 総ダメージは当たりの確かめにしか使っていない。
- **割れた読みを和で数える読み方**（`055-03`・`055-04`・`055-16`・`070-07`・`122-06`・`123-05`・`056-21`・`212-05`・`242-02`）: 違う区間の和は旧と新で同じで、数えは変わらない。`056-21` の HUD の読めない区間（f3823〜3842）の和も旧と新で同じ（31,341）。
- **式で回し直したもの**: V-0118 の撃った発の数（`154-03`・`157-03`・`160-03`。まとまりの式で旧も新も 3,252・3,250・3,270）、レシピ hud-jumps の組み方のトリガーの数（`L-S-08`・`L-SB-09`・`L-SC-08`。旧も新も 232・233・231）、殲滅モードの発の数（`044-18`・`317-07`。最初と最後の発のフレームが旧も新も同じ）、▲が切れた回数（`278-11`・`279-11`・`283-11`。旧も新も 11・9・5）。

## 分かったこと・分からないこと

- **旧の hud.ts の 0/8 の誤読は、照合に使う hit・rate・count の値をほとんど変えない**。500 件中、値が変わるのは 7 件で、どれも旧の読み方が「分けられない増分」「格子に乗らない増分」を数えなかったもの（会心の割合・▲の割合）。差は割合で 0.006 以内で、許容の中。1 ヒットの値と、割れた読みを和で数える読み方のものは変わらない。
- 分からないこと: `use: record` の hit・rate・count（例: V-0241 の格子に乗った数 `278-09`・`279-09`・`283-09`、V-0206 の会心の数 `242-01`、V-0217 の窓ごとの数）は洗っていない。値の変わり方は、ここで変わった 7 件と同じ形（数えなかった増分が数えられる）になるはず。
