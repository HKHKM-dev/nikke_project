# 予測の後のモデルの変更を知らせる（backlog 5-10）

- 出どころ: [design-investigation-review.md](design-investigation-review.md) 5 節「予測の後のモデルの変更」。main のモデルの変更で、出した後の予測が古くなり（V-0387・V-0389）、`predicted.commit` が古いわけを本文で説明していた（V-0370・V-0371・V-0376・V-0378・V-0388〜V-0390）。
- 目的: 予測（`records/predictions/V-NNNN.json`）を出した後にモデル（`packages/core/src`・`packages/core/data`）が変わったら、`npm run records:check` が注意を出す。本文で説明しなくてよくする。
- 予測は任意で、確定の条件ではない（AGENTS.md）。この注意も確定の条件にしない（落とさない）。
- 状態: 2026-10-17 にオーナーが 5 節の論点を推す案どおりに承認し（C・開いている検証だけ・3 か所）、実装した（`predictionStaleness`・`openStaleness`。テストは `packages/core/src/records/__tests__/predictions.test.ts`）。

## 1. 何で見分けるか

| 案                      | 記録するもの                                                       | 見分けられること                                | 弱み                                                                                                                                                                                                                         |
| ----------------------- | ------------------------------------------------------------------ | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A. commit の差分        | いまの `predicted.commit`                                          | その commit から HEAD までに 2 か所が変わったか | 予測の commit はトピックブランチのもので、スカッシュマージ・リベース・振り直し（filter-branch）で main から辿れなくなる（V-0389・V-0370 の注記）。クラウド環境の浅い clone には無い。コメントや records の道具の変更でも出る |
| B. 内容のハッシュ       | 新しい欄 `predicted.modelHash`（2 か所のファイルの中身のハッシュ） | 2 か所の中身が予測のときと同じか                | git に頼らないが、コメント・整形・`src/records`（道具）の変更でも出る。既存の予測ファイル 200 件には欄が無く、出し直すまで分からない                                                                                         |
| **C. 出し直して比べる** | 何も足さない（いまの `predicted.values`）                          | いまのモデルで出し直すと、指標の値が変わるか    | 計算の時間（全 200 件で約 5 秒。開いている検証だけなら数件分）                                                                                                                                                               |

- 推す案は **C**。知りたいのは「ファイルが変わったか」ではなく「予測の値が古くなったか」で、C はそれを直接見る。値に効かない変更（コメント・道具・ほかのキャラの定義）では出ず、git の履歴に頼らず、既存の予測ファイルにもそのまま効く。スキル定義・敵・録画の台帳（`loadRecordsData` が読むもの）の変更も拾う。
- 比べ方: 仮説 × 指標の値が、保存した値と厳密に同じか（同じコードとデータなら計算は決定的で、JSON の往復でも倍精度の値は変わらない）。配列の指標は長さと各要素で比べる。仮説の `override` がいまのモデルで回らない（例外）ときは「出し直せない」と出す。
- `predicted.commit` はいまのまま残す（いつのモデルで出したかの手がかり。見分けには使わない）。

## 2. どの予測を見るか

- **開いている検証（状態が `調査中`・`保留`）の予測だけ**を見る。閉じた検証の予測は、そのときの撮影計画の記録で、後のモデルの変更で値が変わるのは当たり前（いま全 200 件を出し直すと 113 件で値が変わる）。閉じた後まで注意を出すと、意味の無い注意で埋まる。
- 閉じるときに古いまま閉じたかは、`records:close` では検査しない（予測は確定の条件ではないので）。

## 3. 出し方

- `plan/verifications.md` のその検証記録の項（「予測との比べ」の行の下）に、1 行と変わった指標を出す:
  - `  - **予測の後にモデルが変わった**: いま出し直すと、仮説 × 指標 2 つの値が変わる（\`npm run records:predict -- V-NNNN\` で出し直す）`
  - `    - H1 asuka-hit-5s: 23,350.205 → 23,410.5` のように、仮説 × 指標ごとに旧 → 新（多いときは先頭の 5 つと残りの数）
- 検証記録の「結果」の生成ブロック（予測との比べの表）の冒頭の「予測は … に出した。」の後にも、同じ 1 行を出す（撮影計画を見る人が予測の表から気付けるように）。
- `records:check` の標準出力にも、`予測 V-NNNN: …` の行に「（モデルが変わった。出し直すと 2 指標の値が変わる）」を足す。
- 開いている検証が無ければ何も出ない（いまは 0 件）。

## 4. テスト

- `packages/core/src/records/__tests__/` に、出し直しの比べの関数のテストを足す:
  - 保存した値がいまの計算と同じ予測ファイル → 注意なし
  - データ（スキル定義の値）を変えた後 → 変わった指標が出る
  - 保存した値を書き換えた予測ファイル（モデルを変えたのと同じ見え方）→ 出る。閉じた検証の予測 → 見ない
- 生成の行（`plan/verifications.md` の項の行）のテストも足す。

## 5. 論点とオーナーの判断（2026-10-17）

1. 見分け方は C（出し直して比べる）でよいか。B（内容のハッシュ）を併せて記録するか → C だけ（ハッシュは記録しない）。
2. 見る範囲は開いている検証だけでよいか → 開いている検証だけ。
3. 出す先は `plan/verifications.md` の項・検証記録の予測の表・標準出力の 3 つでよいか → 3 か所。
