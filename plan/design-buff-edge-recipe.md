## Context

バーストなどの効果の遅れ（backlog 2-4）は、事象（II の発動など）の前後で、味方の 1 発の HUD の増分を「▲の無い値」と「▲の乗った値」の格子に当て、▲の無い最後の発と▲の乗った最初の発で挟んで読んできた（V-0368 の `0042-32`、V-0378 の `0302-14`〜`0302-23`、V-0389 の `0402-01`〜`0402-10` など）。当て方は毎回の使い捨てのスクリプトで、観測値の `method.tool` は「使い捨てのスクリプトでの分け方」になっている（同じ値を機械で出し直せない）。

このレシピは、その当て方を 1 つにする。格子はモデルの 1 発の値（指標 `hitDamage` と同じ組み立て）から作り、HUD の増分（`hud-jumps` のキャッシュ）を当てる。

## 1. 入力

`npm run records:read -- <録画 id> --recipe buff-edge --source V-NNNN --opt …`

| `--opt`      | 中身                                                                                                                                                            |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `slot`       | 値を当てる枠（1 始まり）。▲を受ける味方                                                                                                                         |
| `off`        | ▲の無い格子を取るモデルのフレーム（`,` 区切りで複数）。各フレームの区間で `hitDamage` を コア × 会心 × 距離 の 8 通り出す（フルバースト補正はその区間のもの）   |
| `on`         | ▲の乗った格子を取るモデルのフレーム（同上）                                                                                                                     |
| `events`     | 事象の時刻（動画のフレーム）。`,` 区切りの数か、値が数の列の観測値の ID（例: `0042-31`）                                                                        |
| `from`・`to` | 事象からの動画のフレームの範囲（既定 −60・60）。フルバーストの入りの止まりの後の発を入れない、などは人が決める                                                  |
| `tol`        | 値の許容（既定 1.5。HUD は整数）                                                                                                                                |
| `scale`      | モデルに無い状態の倍率（任意。`,` 区切り）。両方の格子に「× 倍率」の版を足す（例: サンの S2 の攻撃力▲ 1.091。C-0275）。観測値の note に書き出す（6 節の論点 2） |
| `edge`       | `start`（既定。▲の付き始め）か `end`（▲の切れ目）                                                                                                               |
| `setup`      | モデルを回す条件（的・出来事）。`compare` を持つ観測値の ID か、予測の指標（`V-NNNN:<指標 id>`）。省略すると `--source` の予測ファイルの最初の指標の `setup`    |

モデルは、録画の台帳（`records/recordings/<id>.json`）の編成と `setup` で `buildTeamInput` → `runSimulation` を回す（`records:predict` と同じ組み立て）。`off`・`on` を省くと、枠の区間の一覧（モデルのフレーム・フルバースト補正・胴体の会心なし / 会心の値）を出して止まる。フレームはこれを見て選ぶ。

## 2. 分け方

- 範囲の中の HUD の増分を 1 つずつ、`off` の格子と `on` の格子に `tol` で当てる。片方だけに合えば「▲なし」か「▲あり」、両方に合えば「区別できない」（会心なしの発に会心ダメージ▲など）、どちらにも合わなければ「外れ」（ほかの枠の発・和になった読み）。
- `edge=start`: 事象ごとに、▲ありの最も早い発（`firstPresent`）と、それより前の▲なしの最も遅い発（`lastAbsent`）を出す。`firstPresent` の後の▲なしの発は「食い違い」として数えて出す。`edge=end` は役を入れ替える（▲ありの最後の発 `lastPresent` と、それより後の▲なしの最初の発 `firstAbsent`）。
- 時刻は HUD の増分の読みのフレーム（`hud-jumps` の行。手で読んだ境と同じ）から事象のフレームを引いた動画のフレーム。フルバーストの入りの止まりを跨ぐときの換算はしない（人が `from`・`to` で跨がないようにするか、記録で引く）。
- 標準エラーに、事象ごとに発の時刻・値・分類を並べる（人が目で確かめる）。

## 3. 出力（観測値）

`kind: timing`・`unit: f`・`use: record`。比べる指定（`compare`）は人が足す（指標は `burstEffectDelay`・`burstEffectFirstShot` など、検証ごとに違う）。

1. 事象ごと: 値は幅の真ん中、`spread` は `range`（`lastAbsent + 1` 〜 `firstPresent`）。片側が無い回は出さない（標準エラーに出す）。
2. 全回の共通部分: 下端は各回の下端の最大、上端は各回の上端の最小。値は真ん中。共通部分が空なら出さずに止める（終了コード 2）。
3. `method.note` に、格子のフレームと値（胴体の会心なし）、`scale`、`tol`、範囲、外れ・区別できない・食い違いの数を書く。

## 6. 論点

1. **格子の出どころ**: モデルのフレームを `off`・`on` で指し、その区間の `hitDamage` の 8 通りを使う（推奨）。対案は、値と倍率を手で与える（使い捨てのスクリプトと同じ）。推奨の理由: 予測の 1 発の値と同じ組み立てで、▲の掛かり方（会心ダメージ▲は会心の項だけ、攻撃ダメージ▲は全体）を人が書かない。
2. **モデルに無い状態の倍率 `scale`**: 認める（推奨）。042・302 の 9 回目は、サンの S2 の攻撃力▲（攻撃を受けた時。モデルは被弾を扱わない。C-0275）の乗った発が境になっていて、モデルの区間には出ない。認めないと、042 の上端が 24f になり手の読み（22f）と食い違う。残差を埋める係数ではなく、別の結論で決まった状態を格子に足すだけなので、note に倍率と結論の ID を書く約束にする。
3. **出力の形**: 事象ごとの幅と全回の共通部分を、`use: record` で出す（推奨）。比べる指定は人が足す。
4. **照合の記録の置き場**: 照合の結果は、この設計書の実施の記録とテストに置き、検証記録は起こさない（推奨）。新しい事実（ゲームの機構）は出ず、道具が手の読みを再現することの確かめなので。対案は V-0079 と同じく検証記録にする。
5. **`edge=end`（切れ目）も入れるか**: 入れる（推奨）。役の入れ替えだけで、V-0368 の `0042-33` の読み方と同じ。
6. **名前**: `buff-edge`（推奨）。backlog の旧案 `team-grid`（多人数の増分の分解。design-records-automation-log.md）は範囲が広いので、この名前は使わない。
