# V-0443: ソーダ：トゥインクルバニー S1 のフルバースト中の 3 回ごとの付与の数え方

- 問い: ソーダ：トゥインクルバニー（314）の S1「フルバーストタイム持続中に通常攻撃で 3 回攻撃した時、ゴールデンチップ 1 個▲」は、通常攻撃の回数をどう数えるか（フルバーストごとに数え直す・フルバースト中の発だけを持ち越す・フルバーストの外の発も数えて付与だけフルバースト中に限る）
- 話題: スキル・キャラ固有

- 録画: `0463`、`0471`
- 派生元: `V-0437`

## 条件

- 録画 0463・0471 の読み直し（V-0437 の撮影。V-0437 では 2 本で合わない回があり、S1 の `assumes` のままにした。ラム（I）・デルタ（II）・ソーダ：トゥインクルバニー（III・操作・AUTO 射撃 ON）、オートバースト ON、射撃場・灼熱のタブ・BigArms・3 分モード・スペック固定 ON）。戦闘開始の直後と 5 回の発動ごとに一時停止画面を開いている。
- 仮説の出どころ: 録画 0471 の 2・3 回目のフルバーストで、最初の 1 発の後に増えた（V-0437 の `0471-07`）。録画 0463 は V-0437 で数え直しと合うと読んでいた（この検証の前は仮説を立てるのに使っていない）。
- 最小構成: 観測量は、録画で読んだ発の通し番号と、右下の数が増えた発と、その発がフルバーストの中か（画面中央のフルバーストの残り時間の表示）。ラム・デルタはソーダ：トゥインクルバニーの射撃と S1 に効かない（V-0437 の条件）。S2 の持続時間▲（未対応）は窓の長さを変えるが、窓は画面で読むので、モデルの窓とは比べない。

## 予測

なし（読み直し。3 つの仮説が録画のどの発で増えるとするかは「結果」に書く）。

| 仮説 | 読み                                                                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A    | フルバースト中の発だけを数え、フルバーストごとに数え直す（V-0437 までの定義。`reset: fullBurstStart`）。どのフルバーストも、中の 3・6・9… 発目で増える |
| B    | フルバースト中の発だけを数え、余りを次のフルバーストに持ち越す（`reset: never`）                                                                       |
| C    | 戦闘の始めから全部の発を数え、通し番号が 3 の倍数の発がフルバーストの中なら増える（フルバーストの外の 3 の倍数は何も起きずに過ぎる）                   |

## 読み方

1. **発**: ソーダ：トゥインクルバニーの通常攻撃を、照準の左の残弾（`reticle-ammo.ts --mode series`）の 1 減ったフレームで拾い、HUD の総ダメージの増分（`hud.ts --mode jumps`）のフレームに合わせた（残弾の読みは数フレーム遅れることがある）。弾倉の最後の 1 発は残弾の表示が 0 にならず装填に移るので、前の発から約 39f 後の増分で確かめた。発の間隔は 39f と 40f で、ほかの増分（ラム・デルタの一定の値）と分けられる。
2. **一時停止をまたぐ発**: 一時停止の前後で残弾の表示が同じ値なら、その間に発は無い（例: 463 の f4449 の後は f4936 まで 7 発のまま。V-0437 で一時停止の明けの f4904 の増分を発と数えて揺れた原因はこれ）。
3. **右下の数**: 画面右下のゴールデンチップの数は、カメラの動きで位置が変わる。黄色の数字の連結成分を探して追い、切り抜きを並べて目視で読んだ（照合の見本は 471 のフレームから作った。読みの列はフレームごとに出し、増えたフレームは切り抜きの並びで確かめた）。証拠フレームは frames/463_s1count-_.png・frames/471_s1count-_.png・frames/463_471_s1count-fb-end*.png。
4. **フルバーストの始まりと終わり**: 始まりは右下の数が 17 減った（4・5 回目は 1 になった）フレーム、終わりは画面中央のフルバーストの残り時間が 00.00 になったフレーム。
5. **観測値**（どれも `record`）: `0463-08`・`0471-08` は増えた発の通し番号、`0463-09`・`0471-09` はフルバーストの中の最初の発の通し番号。

## 分かったこと・分からないこと

- 分かったこと: S1 の 3 回ごとの付与は、通常攻撃の回数を戦闘中ずっと（フルバーストの外も）数え、3 の倍数の発がフルバーストの中のときだけ 1 個付く（C-0580）。定義は回数のきっかけの発火の窓（`firesDuring: "fullBurst"`。[design-skill-stage3.md](../../plan/design-skill-stage3.md) 1.6 節）で書き、`assumes` を外した。
- モデルとは比べていない（S2 の持続時間▲が未対応で、モデルのフルバーストの窓が実測と違う）。2026-10-17 のオーナーの判断で「指標なし」を上書きして確定にし、`firesDuring` の語彙も承認を得た。モデルの V-0437 の観測値（段階の効果の有無・17 個▼）は、定義を変えても許容内のまま。
- 分からないこと: S1 の「フルバーストタイム中の通常攻撃 3 回ごとの攻撃ダメージ▲」（未対応の notes）が同じ数え方か。
