# 設計書: 遅れのある周期の倍率ダメージの値を、発動の時で決める範囲（課題 2-74・2-70）

- 関連: [design-delayed-skill-hit.md](design-delayed-skill-hit.md)（倍率ダメージの遅れ `delayFrames`）、[design-timer-ceil.md](design-timer-ceil.md) 6 節（周期の倍率ダメージの遅れ）、課題 2-74（ネヴェの S1）・2-70（ブリッドの S2）
- 検証: V-0853
- 作成日: 2026-11-22
- 状態: 起案（論点 1 をオーナーが決める）

## 1. 何が困っているか

- 遅れのある倍率ダメージ（発動の数 f〜百 f 後にヒットが出るもの）の値を、モデルは既定でヒットのフレームのバフで出す（`frame/plan.ts` の `planSkillHits`。C-0453 の model）。発動の時の値で出すのは、定義に `valueBeforeFire` を付けた効果だけ（イサベルの S2・スノーホワイトの S2・スノーホワイト：イノセントデイズの S1 と S2・アスカ：WILLE の S1）。
- V-0853 で、ラピの S2（発動の 101f 後のヒット）も**発動の時の値**だと分かった（C-1509）。フルバーストの終わりの前に発動して終わりの後にヒットした 10 回すべてで、フルバースト補正とラピのバーストの攻撃力▲が乗った。いまのモデルでは、比べる 9 件がどれも許容外。
- 課題 2-74 の 2 つの説明のうち、「ヒットの時の値で、フルバーストの効き目がパネルより遅れる」は、ラピの S2 では外れた（終わりの 64〜93f 後のヒットに、フルバーストと関係のない攻撃力▲も乗る）。ネヴェの S1 の `1336-12` の 2 回は、発動の時の値で 2 回とも合う（いまのモデルは 1 回目を 512,466 で出し、実測は 151,888）。
- 同じ「周期のきっかけで、遅れて出る倍率ダメージ」は、ほかにも 12 件ある（3 節の表）。どこまでを発動の時の値にするかを決める。

## 3. 案

### 3.1 論点 1: どの効果に `valueBeforeFire` を付けるか

周期のきっかけ（`everySeconds`）の遅れのある倍率ダメージ（`valueBeforeFire` の無いもの）:

<!-- prettier-ignore -->
| キャラ | 効果 | 遅れ |
| --- | --- | --- |
| ラピ（10） | skill2 の effects[0] | 101f |
| ノベル（212） | skill1 の effects[0] | 64f |
| エーテル（291） | skill2 の effects[0] | 52f |
| ブリッド（70） | skill2 の effects[0] | 49f |
| マリアン：クイーン（19） | skill1 の effects[1] | 19f |
| ネヴェ（193） | skill1 の effects[0] | 15f |
| ニヒリスター（261） | skill2 の effects[0] | 15f |
| ヘルム：アクアマリン（353） | skill2 の effects[0] | 13f |
| ドロシー（233） | skill2 の effects[0] | 8f |
| ペッパー（131） | skill2 の effects[0] | 7f |
| ミルク：ブルーミングバニー（143）・リトルマーメイド（513）・シンデレラ：クリスタルウェーブ（515）・エイダ（840） | 1〜5 秒ごとの持ち越しの周期 | 6f |

- **案 A（推奨）: 値の根拠のある 2 件（ラピの S2・ネヴェの S1）に付ける。** ほかの 12 件はヒットの時のまま、定義の `assumes` に「値を発動の時とヒットの時のどちらで決めるかは確かめていない（周期の倍率ダメージのラピ・イサベル・スノーホワイトは発動の時。C-1509・C-0864・C-1417）」と書く（ブリッドは今の `assumes` を書き換える）。
  - 良い点: 実測で値を確かめた効果だけを変える（AGENTS.md「根拠のない変更は行わない」）。ネヴェは、いまのモデルが `1336-12` と合わない。
  - 悪い点: 同じ形と見込まれる 12 件が、ヒットの時のまま残る（ヒットの時の値にも根拠は無い）。
- 案 B: 周期のきっかけの 14 件の全部に付ける。ラピとネヴェのほかの 12 件の `assumes` に「発動の時の値は、周期の倍率ダメージのラピ・イサベル・スノーホワイトと同じ形とみた（この効果では見分けていない）」と書く。
  - 良い点: 周期の倍率ダメージの扱いが 1 つにそろう。確かめた 4 体はどれも発動の時で、ヒットの時の例は無い。既存の比べる観測値は変わらない。
  - 悪い点: 12 件は類推で変える。遅れの短い件（6〜8f）は、端をまたぐ回がまれで、確かめる見込みも薄い。
- 案 C: ラピの S2 だけに付ける。
  - ネヴェの `1336-12` を説明しないまま残す（2-74 は閉じない）。採らない理由は、ネヴェの値の根拠（発動の時でしか合わない 1 回目）を使わないこと。

### 3.2 決まっていること（論点にしない）

- 語彙は足さない。`valueBeforeFire`（発動の 1 フレーム前の値で決める）を使う。データだけの変更で、`frame/`・`sim/` のコードは変えない。
- 回数のきっかけ（命中・射撃の回数）の遅れのある倍率ダメージ（2B の S2・リバーレリオの S1 など）は、この設計書の範囲の外。スノーホワイト：イノセントデイズのほかは見ていない。
- バースト使用時のきっかけのものは、ヒットの時のまま（2 節の例）。

## 4. 実装の順（論点 1 が決まったら。案 A の場合）

1. `data/skills/10.json` の skill2 の effects[0] に `valueBeforeFire` を付け、`assumes` に値の時点（C-1509）を足す。C-1509 の model を「反映」にし、確定にできる条件を見直す（`parameterFree`。0221 の出どころも再現に数える）。
2. ネヴェ: `1336-12` の 2 回を比べる観測値にし（`skillHitDamage` の 1 回目は会心なし、2 回目は会心）、ネヴェの S1 の値の時点の結論（仮説）を作って、`data/skills/193.json` の skill1 の effects[0] に `valueBeforeFire` と `assumes` を足す。
3. ブリッド: `data/skills/70.json` の skill2 の effects[0] の `assumes` を 3.1 節の文に書き換える。
4. C-0453 の model の「ヒットはそのフレームのバフで出る」に、発動の時の値で出す効果（C-0864・C-1509）の例外を足す。
5. `npm test` と `npm run records:residual -- --all --base origin/main`（変わる行が V-0853 とネヴェの観測値だけか）。
6. 課題 2-74 を閉じ、2-70 の「いま分かっていること・次の 1 手」を書き換える（2-70 は、1284 で見分けられない回のまま。次の 1 手は課題の文の単騎の撮影）。2 つは 1 行にまとめない（2-74 は閉じ、2-70 だけ残る）。

案 B なら、1〜3 に 12 件の `valueBeforeFire` と `assumes` を足し、2-70 も閉じる（類推で入れた旨を 2-70 の代わりに `assumes` に残す）。

## 5. 退化の見込み

- 既存の比べる観測値は変わらない（2 節）。変わるのは V-0853 の 9 件（許容外 → 許容内）と、案 A・B のネヴェの観測値。
- 画面の 1 秒ごとのダメージは、窓の端をまたぐ回だけ変わる（ラピが III の編成では、1 回おきの S2 がフルバーストの終わりをまたぐので、その回が大きくなる）。
