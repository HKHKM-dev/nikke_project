## Context

Stage 17 で、射撃場の単騎の録画から武器種ごとのコア命中率と距離ボーナスを読んだ。その結果、次の 2 点が分かった（2026-09-26）。

- 距離ボーナスは「割合」ではなく、的のジャンプの着地点ごとに区間単位で切り替わる。
- AI のコア命中率は武器種で 0.14〜1.00 と大きく違う。

同じ日のユーザー決定で、既定はまだ変えないことにした。距離は時間ごとに切り替える判定にし、実装は、測っていない武器（AR・SR・SG）の遠い区間の値と、着地点ごとの距離の決め方をそろえてから起案することにした。

ユーザーは以前、別プロジェクト `D:\NIKKE_Damage_Calculator`（以下「旧プロジェクト」）で同じ射撃場の命中率と距離を調べている。**この Stage の方針（2026-09-26 ユーザー決定）**は次のとおり。

1. 距離ボーナスと命中率（照準円）を、コア命中率とのつながりまで含めて 1 つの Stage で扱う。Stage 17 で保留した「距離を時間ごとに切り替える」実装もここに入れる。
2. 最初の一歩は、旧プロジェクトの知見から必要なものだけを選んで取り入れること。取り入れる値は、**出典つきで [verification.md](verification.md) に写し、このリポジトリの録画で検算する**。
3. 命中率▲の効き方は、**キューブとスキル**で測る。オーバーロード（OL）は、資源を使う抽選で自由に付け替えられないので使わない。

## 0. 設計前に分かったこと（2026-09-26）

### 0.1 呼び名

旧プロジェクトの言い分けに合わせる。**このリポジトリの `hitRate`（`SlotCondition.hitRate`、Stage 15）は「弾丸命中率」**で、ゲーム内の「命中率▲」とは別物。

| 呼び名         | 意味                                                        | このリポジトリでの今の扱い                                                             |
| -------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| **弾丸命中率** | 撃った弾（SG はペレット）のうち的に当たった割合             | `condition.hitRate`（0..1、既定 1）。画面では「命中率」と表示している                  |
| **コア命中率** | 当たった弾のうちコアに当たった割合（P(コア｜命中)）         | `condition.coreHitRate`（既定 1）                                                      |
| **命中率▲**    | 照準円を小さくする効果（スキル・キューブ・OL）              | stat `hitRate`。「命中率増加状態なら」の判定と表示にだけ使う（ダメージには効かせない） |
| **照準円**     | 弾が散らばる円。CDN の `*_accuracy_circle_scale`            | データに無い（正規化で捨てている。0.3 節）                                             |
| **距離帯**     | 射撃場の的までの距離の区分。近 / 中近 / 中遠 / 遠（0.4 節） | 無い。距離ボーナスは枠ごとの真偽                                                       |

- 旧プロジェクトの表のうち、`マスタデータ.xlsx`「命中率実測」シートのコア行は、条件付きではなく**無条件の P(コア)＝コア命中率 × 弾丸命中率**になっている（例: AR 近 0.4244 × 0.9975 = 0.4233）。**写すのは条件付きの値**（`docs/実測突合記録_2026-08.md` §131 の表）。

### 0.6 机上で照らし合わせた結果（撮影なし）

写す前に、このリポジトリの記録と矛盾しないかを見た。

1. **区間の並び**: Stage 17 の区間ごとの距離ボーナスは、旧の並び（中近 → 近 → 遠 → 中遠 → 近 → 遠）で説明できる。

### 0.7 照準円とコア命中率の仮説（推測。検算の対象）

旧プロジェクトの表と CDN の円の大きさを並べると、次の形でおおむね説明できる。**私の推測で、まだ確かめていない。**

> コア命中率 ≈ min(1, k ÷ (R × d)²)
> R = 照準円（命中率▲込み）、d = 的までの実距離、k = 的のコアの大きさで決まる定数

- 同じ距離帯なら、AR と SMG のコア命中率の比は (110 ÷ 75)² = 2.15 になるはず。旧の表では、近 1.61、中近 1.93、中遠 2.33、遠 2.06。近は、上の 3 のとおり揺れが大きい。
- SR・RL・MG（R = 10）は、どの帯でも 1 で頭打ちになるはず。実測は 0.96〜1.00。
- 常時の▲で 1/(1 − N)² 倍になる（0.4 節の (4)）のは、この式で R が (1 − N) 倍になった場合と同じ。
- 当てはまれば、帯ごとの表を武器種ごとに持たなくても、R（CDN）と距離帯から出せる。**当てはまるかどうかを 3 節で確かめ、モデルに入れるかは 18-C で決める**。

## 1. 何を決めるか

1. **射撃場の距離帯のモデル**:
   - 区間ごとの距離帯（中近 → 近 → 遠 → 中遠 → 近 → 遠）と中遠の q を、的のジャンプの出来事のセットに持たせる。
   - 距離ボーナスは、区間ごとに `bonusRange` で決める。
2. **距離帯ごとのコア命中率と弾丸命中率**: 射撃場の的に対する武器種ごとの値。旧の表を写し、このリポジトリの録画で検算する。
3. **命中率▲がコア命中率をどう変えるか**: 円 × (1 − N) と、コア命中率 × 1/(1 − N)²。キャラの常時の▲とバーストの▲で確かめる。
4. **呼び名の整理**（0.1 節）。

既定値を変えるか（Stage 17 で保留）は、18-C の実装のときに決める（9 節の 6）。

**コードのいまの形**

1. **条件は枠ごとに一定**。`TeamSlotInput.condition`（`SlotCondition` = `coreHitRate`・`distanceBonus`・`fullCharge`・`hitRate`）が、calc（`calc/model.ts`）でも sim（`sim/engine.ts`）でも、そのまま `computeTriggerDamage`（`damage.ts`）に渡る。時刻で変わる入り口は無い。
2. **区間の鍵**（`skills/timeline.ts` の `keyOf`）は「フルバーストか + その枠の `BuffTotals` + 効いている持続効果の出どころ」。区間の境目は、バフの窓・フルバーストの窓・バーストの発動だけ。

3. **弾丸命中率（`condition.hitRate`）**は、通常攻撃のダメージと 1 パス目のゲージ（`firstPass.ts` の `energyPerTrigger(…, slot.hitRate)`）に掛かる。どちらも枠ごとに一定。
4. **命中率▲（stat `hitRate`）**:
   - 常時の分（育成の効果層のアサルトキューブ・OL の命中率、常時パッシブ）は、枠の `BuffTotals.hitRate` に入る。**区間の鍵には入れていない**（`BUFF_FIELDS` に無い）。
   - 持続（timed）の分は `STATE_STATS` で、区間に入れず `stateWindows` に置いている（「命中率増加状態なら」の判定と表示だけ）。
   - いまのデータで持続の▲を書いているのは、ドレイク（101、`fullBurstStart`・味方）・モダニア（260、`fullBurstStart`・味方）・ノワール（271、`burstUse`・SG の味方）の 3 体で、**どれもフルバーストの頭で味方に配るもの**。自分に掛ける持続の▲（アスカのバーストなど）は、定義が無い。
5. **コアと距離が効くのは通常攻撃だけ**。バーストスキル（`skills/burstDamage.ts`）・倍率ダメージ・射撃ごとの倍率ダメージ（`PER_SHOT_DAMAGE_CORE = false`）は、コア命中率も距離ボーナスも読まない。着地点が変えるのは、通常攻撃の 1 トリガーの値とゲージだけ。
6. **射撃場の的**は、`data/enemies.json` に属性違いで 5 つ（`range-bigarms-*`）あり、属性のほかは同じ。画面の既定の敵（`apps/web/src/team.ts` の `SHOOTING_RANGE_ENEMY`、属性なし）は、どのプリセットとも一致しない。3 分モード（`range-3min-jump`）は、敵の値がプリセットと一致するときだけ効く（`enemyWithEvents`）。
7. **既定の条件**は、画面（`DEFAULT_SLOT_CONDITION`）・CLI（`scripts/sim-run.ts`）・照合ランナー（`records/observations.ts` の `buildTeamInput`）の 3 か所で、どれも「コア命中率 1・距離あり・弾丸命中率 1」。照合ランナーの比べる観測値 24 件は、この既定か、1 ヒットの値（コア・距離を引数で指定）で比べている。
8. **保存形式**は `TEAM_FORMAT_VERSION = 1`。条件は数値で持つ。版を上げて「自動」に読み替える方針は、Stage 17 の 8 節の 5 で承認済み。
9. **画面の「命中率」**は `SlotCard.tsx` の条件欄（`condition.hitRate`）、`NotesSummary.tsx`、`damage.ts` の `conditionNotes`、README の 2 か所。スキルの表示（`skillLabels.ts` の `hitRate: '命中率'`）は命中率▲の stat なので、こちらは変えない。

### 12.1 何を決めるか

1. **着地点の時間割り**: 3 分モードの出来事のセットに区間ごとの着地点を持たせ、「時刻 → 着地点 → 武器の `bonusRange`」で距離ボーナスを決める。中遠は 3 か所を期待値で配分する。
2. **着地点ごとの表**: 射撃場の的に、武器種 × 着地点のコア命中率・弾丸命中率を持たせる。MG のコア命中率は撃ち始めからの発数で持つ。
3. **命中率▲の効き**: 自動の条件のコア命中率に 1/(1 − N)²（上限 1）を掛ける。
4. **呼び名**: 画面と文書の `condition.hitRate` を「弾丸命中率」と表示する（9 節の 5 で承認済み。識別子と保存形式はそのまま）。
5. **既定値**: 画面・CLI の既定を「自動」（射撃場の表）にするか（Stage 17 で保留した分）。
6. **着地直後の数発の外れ**を扱うか。

### 12.3 入れ方（core）

**(1) 敵の入力に着地点を足す**（`damage.ts` の `EnemyInput`）

- `target?: TargetProfile` と `landings?: readonly LandingSpan[]` を足す。`LandingSpan` は秒の `{ start, end, landing }` で、`landing` は着地点の id か配分の id（`midFar`）。省略すれば今と同じ。
- `enemies.ts` に `enemyLandingsOf(master, setIds, durationSeconds, profile)` を足す。出来事が無ければ、戦闘時間全体を `initialLanding`（中近）にする。

**(2) 枠の条件を「自動 / 手入力」にする**（`team.ts`）

- `TeamSlotInput.conditionMode?: 'manual' | 'auto'` を足す。**省略は manual**。core の既定は変えないので、今のテストと照合ランナーの 24 件は 1 の位まで変わらない。
- 自動のときの解決は、新しいファイル `frame/landing.ts` にまとめる。着地点 k・武器種・撃ち始めからの発数 i・常時の▲ N から、`coreHitRate`・`distanceBonus`・`hitRate`（弾丸命中率）を出す。`fullCharge` は手入力のまま。
  - `coreHitRate` = min(1, 表の値 ÷ (1 − N)²)。N ≥ 1 なら 1（C-0036・C-0037）。N は枠の常時の `BuffTotals.hitRate`（育成の効果層・常時パッシブ）。
  - 表が null の項目と、プロファイルの無い敵では、手入力の値を使う。
- 手入力の値には▲を掛けない。手入力は「実際のコア命中率」として読む（今と同じ）。

**(3) 区間の鍵に着地点を入れる**（`skills/timeline.ts`。Stage 17 の 9.3 節の別案）

- `planBuffTimeline` に着地点の区間（フレーム）を渡し、境目に足す。区間（`TimelineSegment`）に `landing` を持たせる。
- 鍵（`keyOf`）には、**自動の枠だけ** `L:<着地点>` を足す。手入力の枠のグループは今と同じになる（境目が増えても、calc のグループと sim の 1 発の値は変わらない）。
- 中遠のように配分する区間は 1 つの鍵（`L:midFar`）にし、1 トリガーの値を配分の重みで足し合わせる（下の (5)）。

**(4) ゲージ**（`frame/firstPass.ts`）

- 1 パス目のゲージに掛ける弾丸命中率を、枠ごとの定数から「フレーム → 着地点 → 弾丸命中率」（中遠は重みで平均）にする。着地点は敵の出来事だけで決まり、射撃やバフには依らないので、循環は生じない。
- 自動の枠で弾丸命中率が 1 未満の着地点があると、ゲージと時刻表が変わる（SMG の遠 0.76 など）。

**(5) 1 トリガーの値**（calc・sim で共通の関数にする）

- 1 トリガーの値は、コア命中率 p について 1 次式になる（T(p) = T0 + (T1 − T0) × p。弾丸命中率 h は T0・T1 に掛かる）。これを使い、区間（calc はグループ）ごとに、着地点 k の T0・T1 を先に計算しておく。
- 1 発の値は Σ_k w_k × (T0_k + (T1_k − T0_k) × p_{k,i})。w は配分の重み（配分しない着地点は 1 つで w = 1）、p_{k,i} は着地点 k・撃ち始めから i 発目のコア命中率。
- **sim**（`sim/engine.ts`）: 区間ごとに T0・T1 を持ち、射撃の列の 1 発ごとに p を当てて足す。MG 以外は p が発数に依らないので、区間の値は 1 つで済む。
- **calc**（`calc/model.ts`）: 自動の枠は、狙えない窓が無くても射撃の列を数える（`countAllShots` と同じ扱い。MG の撃ち始めは平均レートでは置けないため）。グループの発数と Σp から値を出すので、calc と sim の通常攻撃は一致する。
- 表示用の内訳（`SlotSegmentResult.trigger`）は、重みと発数で平均した値にする。
- 撃ち始めからの発数は、1 パス目の射撃の列（`ShotLog.frames`）から `frame/plan.ts` で 1 度だけ数え、`TeamPlan` に持たせる。

**(6) 注記**（`frame/events.ts`・`damage.ts`）

- 自動の枠: 「射撃場の表（単騎 AUTO の実測）を使用。中遠の着地点は 3 か所を 3 : 3 : 4 で配分。フルバースト中に配られる命中率▲はコア命中率に効かせていない」（approx）。
- 未測定の項目（SG のコア命中率など）: 「手入力の値を使用（未測定）」（unsupported）。
- `enemyEventNotes` の「着地後の距離の変化（距離ボーナス）は扱わない」は、自動の枠があるときは出さない。

**(7) 結果に足すもの**: 枠ごとに、自動で使った条件の平均（発数で重みを付けたコア命中率・距離ボーナスが乗った発の割合・弾丸命中率）。画面の条件欄と CLI に出す。

### 12.4 入れ方（CLI・照合ランナー・画面）

**CLI**（`scripts/sim-run.ts`）

- `--condition auto|manual` を足す（既定は 12.9 節の 5）。`--core-hit-rate`・`--hit-rate` を指定したら manual。
- `--mid-far A|B|C` で中遠の着地点を 1 つに固定できるようにする（録画と比べるとき用。省略は配分）。
- 枠ごとに、自動で使った条件の平均を出力する。

**照合ランナー**（`records/observations.ts`）

- `CompareSetup` に `condition?: 'auto' | 'manual'`（**省略は manual**。既存の 24 件の予測は変わらない）と `midFarLanding?` を足す。
- 比べる観測値を足す: 単騎 AUTO の録画 54（リター、中遠 A）・55（紅蓮BS）・56（クラウン、中遠 A）の与ダメージを、自動の条件で予測する。係数は合わせに行かず、許容外でも残差として並べる（結論には結び付けない）。
- 旧の単騎（L-AD・L-AI・L-AN・L-HC）も、スペック固定の単騎なので比べられる。ただし表の値の一部はこの録画から出ているので、表そのものの検算にはならない（時間割り・射撃の数・ゲージまで含めた通しの確認になる）。

**画面**（`apps/web`）

- 枠の条件欄に「自動（射撃場の表）/ 手入力」の切り替えを足す（`SlotState.conditionMode`）。自動のときは、使った条件の平均を読み取り専用で出す。手入力の値は、切り替えても残す。
- 「命中率」を「弾丸命中率」と表示する（`SlotCard.tsx`・`conditionNotes`・`NotesSummary.tsx`・README・CLI の説明）。stat の「命中率」（命中率▲）はそのまま。
- 自動が効く敵は、射撃場のプリセットと一致するときと、既定の敵（`SHOOTING_RANGE_ENEMY`。属性なしの射撃場の的）のとき（12.9 節の 5）。3 分モードが OFF なら、全体を初期位置（中近）で計算する。
- sim のタイムラインに、区間ごとの着地点（近・中近・中遠・遠）を帯で出す。
- 保存形式を 2 に上げる（12.9 節の 5）。

### 12.9 決めてほしいこと（推奨案つき）

1. **中遠の配分** — 推奨: **3 か所を 0.3 : 0.3 : 0.4（C-0044 の 10 回の内訳）で期待値として配分**し、CLI と照合ランナーでは 1 か所に固定もできるようにする。別案は、旧の q = 0.30 で「A」と「B・C」の 2 つに分ける案。B と C は距離ボーナスの付き方が同じなので、今の表ではどちらでも同じ数値になる。
2. **着地点ごとの表の値** — 推奨: **表の形は着地点ごとにし、値は C-0034 の帯の値（旧の表）を入れる。中遠の 3 か所は同じ帯の値で、分けるのは距離ボーナスだけ**。理由は 2 つ。
   - 着地点ごとのコア命中率・弾丸命中率の違いは、まだ結論（claims.md）になっていない。
   - 着地点が分かる単騎の録画は、1 か所につき 1 本（約 330 ヒット。コア命中率の標準誤差 ±15% 前後）しかない。
   - 別案は、着地点が分かる単騎の録画の値で中遠を埋める案。AR（キューブなし）は A 0.141（録画 58）・B 0.112（60）・C 0.097（59）、SMG は A 0.065（54、弾丸 0.983）・C 0.042（旧 L-AI、弾丸 0.902）で、SMG の B は帯の値で埋める。AR を 3 : 3 : 4 で平均すると 0.115 で、帯の値 0.120 と大きくは違わない。
3. **MG のコア命中率** — 推奨: **撃ち始めからの発数で持つ**（1〜5 発 0.042・6〜10 発 0.230・11〜15 発 0.896・以後 1。C-0035）。マガジンの大きさ・リロード・ジャンプの回数で平均が変わる仕組みが、そのまま入る（装弾数▲で撃ち始めが減るなど）。別案は、帯の値（0.96 前後）を AR・SMG と同じ表で持つ案。実装は簡単だが、撃ち始めの回数が録画と違う MG・編成ではずれる。
4. **命中率▲** — 推奨: **自動の条件のコア命中率にだけ、常時の▲（育成の効果層・常時パッシブ）で 1/(1 − N)²（上限 1、N ≥ 1 で 1）を掛ける**。持続の▲（いまのデータではフルバーストの頭で味方に配るものだけ）は効かせず、注記を出す。手入力の値と弾丸命中率には掛けない。別案は持続の▲にも同じ式を掛ける案で、旧の結果（配られた▲は弱く効く）からは効きすぎる見込み。
5. **既定値** — 推奨: **変える**。
   - 画面の新しい枠と CLI の既定を「自動」にする。core（`conditionMode` の省略）と照合ランナーの既定は manual のまま（既存の検証を変えないため）。
   - 自動が効くのは、射撃場のプリセットと一致する敵と、既定の敵（属性なしの射撃場の的）。それ以外の敵では、自動でも手入力の値（1・あり・1）を使い、「この敵の条件は未測定」と注記する。
   - 操作キャラの枠も自動にする（AUTO で撃つ前提。単騎 AUTO の MG は AI と同じ程度だった。Stage 17 の 9.3 節の 3）。人が狙う操作は、手入力にしてもらう。
   - 保存形式を 2 に上げる。版 0・1 の枠は、条件が（コア命中率 1・距離あり・弾丸命中率 1 か欠落）なら自動に読み替え、それ以外は手入力として残す（Stage 17 の 8 節の 5 のとおり）。
   - 別案は、今の既定のまま「自動」を選べるようにするだけの案。確定済みの結論（C-0026・C-0028）と既定の食い違いが残る。
6. **着地直後の数発の外れ** — 推奨: **18-C では別の仕組みとして扱わない**。
   - MG は 3 の撃ち始めに含まれる（ジャンプ明けも撃ち始め）。AR・SMG は、表の値（区間の平均）に含まれている。
   - RL・SR は表を 1 にし、「着地直後の 1 発を外すことがある（紅蓮BS 単騎で 180 秒に 2 発、約 1%）」を未実装の注記に書く。
   - 別案は「着地後の k 発はコア 0」とする案。根拠が RL 2 発・アスカ 3 発で k が決まらないので、12.8 節の撮影案にする。
7. **PR の分け方** — 推奨: **18-C1（core・CLI・照合ランナー。既定は変えない）→ 18-C2（画面・保存形式・既定の変更）の 2 つ**（12.5 節）。18-C1 の残差を見てから、画面の既定を変える。別案は 1 PR にまとめる案。
