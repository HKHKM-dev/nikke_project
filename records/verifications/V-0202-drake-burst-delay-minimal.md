# V-0202: ドレイク（宝物あり）のバーストの 3 ヒットの遅れを最小構成で確かめる（ココア + デルタ + ドレイク）

- 問い: ドレイク（III・宝物あり）のバーストの倍率ダメージは、I・II が機構の確定したキャラの編成でも、III の発動からモデルのフレームで 4〜5f の 1 ヒット目と、その 27〜28f・55f 後の 2・3 ヒット目に分かれるか（C-0228）
- 話題: スキル・キャラ固有
- 日付: 2026-10-05
- Stage: plan/design-burst-landing.md 5 節の 2（ほかのキャラの遅れ）、plan/design-burst-split-hits.md。backlog 2-4
- 状態: 調査中
- 待ち: 撮影（この記録の「次に撮るもの」）
- 派生元: `V-0140`

## 条件

**何を確かめるか**

- C-0228（仮説・単独実測）は、録画 `037`（ラム + デルタ + ドレイク）と `039`（リター + デルタ + ドレイク）から出した値で、どちらも最小構成でない（ラム・リターの機構が未確定）。最小構成の新しい録画で、1 ヒット目の遅れと 3 ヒットの間隔が同じに出るかを見る。予測を撮る前に commit し、値を決めるのに使っていない録画で再現すれば、等級の候補は反復実測になる（plan/skills-guide.md 1.8 節）。
- 宝物なしのドレイクのバーストは、今回も撮れない（オーナーのドレイクは宝物あり）。
- バースト使用時の効果（自分の最大装弾数▲）は 1 発の値に出ないので、今回も読まない（V-0140 と同じ）。

**編成**

- ココア（311。I）+ デルタ（20。II）+ ドレイク（101。III・操作・宝物あり（段階 3）・AUTO 射撃 ON）、オートバースト ON。射撃場・灼熱の BigArms・3 分モード・スペック固定。
- **最小構成**: ココアは定義が効果なし（V-0031）、デルタは C-0081 で、どちらも機構が確定している。ラムは C-0235 が仮説で未確定なので I にしない（backlog 2-4）。2026-10-05 に `records/minimal.ts` の検査（`minimalWarnings`）にこの編成をかけ、警告が出ないことを確かめた（未確定はドレイクだけ）。

**読み方の前提**

- III の発動は、III のタイマーが 00.00 になったフレーム（V-0078・V-0082・V-0137）。遅れ（モデル）= 動画のフレームでの「III の発動 → 1 ヒット目」− 22（フルバーストの入りの止まり。C-0069）。照合の `burstHitDelays` は止まりを含めた動画のフレームで、`burstHitOffsets` は 1 ヒット目からの動画のフレームで比べる。
- 倍率は 3 ヒットに等分する（plan/design-burst-split-hits.md）。予測ファイルの `drake-burst-hit` は 1 回目の発動の 3 ヒットの合計なので、HUD の 3 ヒットの和と比べる。`037` と違い I がココアなので、1 ヒットの値は回ごとに同じ（会心を除く）見込み。

## 予測（撮る前に書く）

撮る前に書いた（2026-10-05）。H0 はいまのモデル（遅れの表のドレイクの行）で、値は予測ファイル（records/predictions/V-0202.json）。

| 仮説                            | 5 回の「III の発動 → 1 ヒット目」（動画のフレーム） | 3 ヒットの間隔                            | 1 回目の 3 ヒットの和                                |
| ------------------------------- | --------------------------------------------------- | ----------------------------------------- | ---------------------------------------------------- |
| H0: いまのモデル（C-0228 の値） | 予測ファイルの `drake-delays` ± 1f                  | `drake-offsets-1`〜`drake-offsets-5` ± 1f | `drake-burst-hit`・`drake-burst-hit-crit` のどちらか |
| D2: 毎回同じだが C-0228 と違う  | どの回も同じ値 ± 1f で、H0 から 2f 以上ずれる       | （H0 と同じか違うかを書く）               | （H0 と同じ）                                        |
| D0: 毎回違う                    | 2f 以上ずれる回がある                               | ずれる回がある                            | （H0 と同じ）                                        |

- **H0 を予想する**。`037`・`039` で I のキャラ（ラム・リター）を替えても同じ値で、遅れの表のどのキャラも回ごとに揃ったため。
- 1f の揺れは、`037`・`039` でもどちらの値にも偏らずに出た（V-0140）ので、± 1f を合うとみる（観測値の許容 `abs: 1`）。
- 当たったときの影響: C-0228 を確定（反復実測）にできる。遅れの表の値は変わらない。
- 外れたときの影響: D2 なら、遅れが I・II の顔ぶれで変わることになり、遅れを演出の長さで決まる値とみる前提（plan/design-burst-landing.md）を見直す。D0 なら、何で決まるかを調べる。

## 読み方

1. 取り込む: `node tools/captures/intake.ts <元ファイル> --id NNN --name sr+sr+sg_cocoa+delta+drake_drake-auto --rid 311,20,101 --controlled 3 --target BigArms --element Fire --mode range-3min --fixed-spec on --auto-fire on --auto-burst on`。台帳を埋めて（宝物ありを注記に書く）`npm run records:table`。この検証記録の冒頭に「録画」を足す。
2. 右のバースト欄を 1 フレームずつ並べて、各回の III のタイマーが 00.00 になるフレームを読む。
3. HUD の増分（`npm run records:read -- <録画 id> --recipe hud-jumps`。止まりの中なら HUD の数字を 1 フレームずつ拡大して目で読む。V-0147）から、各回のドレイクのバーストの 3 ヒットのフレームと値を取る。
4. III の発動 → 1 ヒット目を観測値（`burstHitDelays`。許容 `abs: 1`）、各回の 3 ヒットの間隔を観測値（`burstHitOffsets`。`n` は 0〜4）、1 回目の 3 ヒットの和を観測値（`burstHitDamage`。会心かどうかで `crit` を選ぶ）にする。`args`・`setup` は予測ファイルの指標と同じにする。
