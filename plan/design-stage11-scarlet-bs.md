## Context

Stage 11 の 4 体目。モダニア（PR #18）がマージされたので、ロードマップの順どおり **紅蓮：ブラックシャドウ（225。以下 紅蓮BS）** に進む。紅蓮BS は III・RL の Attacker で、火力の大半が **S1 の「攻撃回数別の効果」（3 発ごとに 283.03% → 565% → 848.03% を循環）** から出る。バーストはこの循環を「1 発ごと」に速め、攻撃力とチャージダメージを上げる。

S2 とバーストの数値の効果（最大装弾数▲・弾丸チャージ・攻撃力▲・チャージダメージ▲）は、どれも **Stage 10 までの語彙でそのまま書ける**。語彙の外にあるのは次の 2 つだけ。

- 「攻撃回数別の効果」「各段階の効果のみ適用」（**段を順に循環**する。S1）: 回数トリガーは「N 回ごとに同じ効果」だけ。段は発動の回数の段階（イサベル。上がったら戻らない）
- 「スキル 1 のフルチャージ攻撃回数の条件が 1 回 / 2 回 / 3 回に変更」（10 秒。バースト）: 別のスキルのトリガーを書き換える効果が無い

**設計の芯は「循環を 1 本の通算カウンタで表す」こと。** 先行撮影の録画 0047 を読み直すと、S1 の回数は**戦闘開始からの通算のフルチャージ攻撃回数**で、窓の外では通算が 3 の倍数の射撃で次の段、窓の中では毎回次の段になり、**窓の中の毎回の段は 3 の倍数の位置をずらさない**と読むと、未解決だった「FB 明けの次の段が 1 発目か 2 発目か」が 5 回のフルバーストすべてで説明できる（0.3 節）。これを `planSkillHits`（Stage 8）の射撃の列の上の 1 本のループにし、窓は区間に入れない。射手・区間・1 トリガーの値は変えない。

あわせて、紅蓮BS の**射撃間隔が実機 43f・モデル 40f**（リロードをまたぐと 172f・160f）とずれていて、フルバーストの 10 秒に入る発数（実機 13 発）が変わるので、較正値を足す（3.3 節）。

## 0. 設計前に分かったこと（2026-09-24）

### 0.1 紅蓮BS のスキル（Lv 10、宝物なし）

- **S1**: フルチャージして攻撃した時、「攻撃回数別の効果」「各段階の効果のみ適用」。**3 回**: 最終防御力が最も低い敵 1 機に 最終攻撃力の **283.03%** のダメージ。**6 回**: 攻撃範囲内の敵に **565%** の分配ダメージ。**9 回**: 敵全体に **848.03%** の分配ダメージ
- **S2**: フルバースト発動時、自分に **最大装弾数 60%▲**（10 秒）・**弾丸チャージ 100%**
- **バースト**: 自分に **「スキル 1 のフルチャージ攻撃回数の条件が 1 回 / 2 回 / 3 回に変更」（10 秒）**・攻撃力 **115.12%▲**（10 秒）・**チャージダメージ 169.63%▲**（10 秒）

- **射撃のパラメータが 202 体で紅蓮BS だけ違う**: チャージ 0.3 秒（ほかの UP 型チャージ武器は 1〜2 秒）、`maintainFireStance` 23・`uptypeFireTiming` 1（ほかは 0 / 0。レイヴン・A2 は別物）。モデルの射撃間隔（チャージ + 22f）の較正は 1 秒チャージの SR / RL だけで行っている（[verification.md](verification.md) Stage 2 節）。
- 「チャージダメージ▲」は `applyChargeBuffs` がフルチャージ倍率に**加算**する。録画 0047 の 1 発で合う（0.2 節）。

### 0.2 先行撮影（録画 0046・0047）で分かっていること

ユーザーが設計書の前に撮った 2 本（スペック固定・3 分モード）。録画 0046 は紅蓮BS 単騎（操作。FB なし）、録画 0047 はラム（I）+ デルタ（II）+ 紅蓮BS（III・操作）で自動バースト（FB 5 回・約 40 秒周期）。ラム・デルタは攻撃力▲・会心▲・チャージ系を配らないので、紅蓮BS の数値の変化は紅蓮BS 自身のスキルだけで説明できる。HUD の総ダメージカウンターを全フレーム読み、1 フレームの増分を分解した（値は [verification.md](verification.md) Stage 11 紅蓮BS 節）。

- 通常攻撃の 1 発は、窓の外・中ともモデルの式で 1 の位まで一致し、**チャージダメージはフルチャージ倍率に加算**（いまのモデルどおり）。
- S1 の段: **コア・距離は乗らず、会心・FB 補正 +0.5・攻撃力▲は乗る**（Stage 8 の倍率ダメージの式どおり）。段のダメージは射撃のポップアップの約 5〜6f 後に出る。
- **段 B は的 1 体だと 1/3 ずつ 3 ティック**（約 14〜15f おき）で、合計は 565% の全額。
- **間隔 43f**、9 発撃ってリロード（最後の射撃 → 次の射撃 **172f**）。モデルは 40f・160f。
- S2: FB 開始で**リロードなしに残弾 14**（9 × 1.6 = 14.4 の四捨五入）に満タン。1 回の FB で 14 発撃ち、**うち 13 発がバーストの窓（10 秒）の中**、14 発目は FB が終わった後。FB 開始から 1 発目までは 55〜62f。
- **段の順番（A → B → C）は FB の前後でも途切れない**。窓の中は 1 発ごとに段が出る。
- 単騎（録画 0046）では戦闘開始から 3・6・9 発目に A・B・C（リロードをまたいでも 12・15・18 発目に A・B・C）。

### 0.3 S1 の回数の数え方（録画 0047 の読み直し）

先行の読み取りでは「FB 明けに次の段が出るのが FB2 は 1 発目、FB1・FB3 は 2 発目」が未解決だった。射撃の列を 43f の刻みで見直すと、HUD の増分の中に他のキャラのヒットと重なって見落としていた紅蓮BS の射撃が 3 発あった（f3468・3553・5978。どれも前の射撃のちょうど 43f 後で、増分の合計から通常攻撃 1 回分がちょうど引ける）。それを入れた FB ごとの流れ（窓の前の段なしの発数 p、窓の中の段 13 発、窓の後で次の段が出たのが k 発目）:

- **FB1**: f1250 で C、その後すぐ FB（p = 0）→ 窓の中 A → … → A → 窓の後 **2 発目**（f2142 で B）
- **FB2**: f3553 で A、f3596 の 1 発（p = 1）→ B → … → B → **1 発目**（f4346 で C）
- **FB3**: f5892 で B、f5935・5978 の 2 発、f6225 で C（p = 0）※ → A → … → A → **2 発目**（f6994 で B）
- **FB4**: f8403 で A、f8447 の 1 発（p = 1）→ B → … → B → **1 発目**（f9186 で C）
- **FB5**: f10857 で C、その後すぐ FB（p = 0）→ A → … → A → 録画の終わり（1 発目 f11569 は段なし）

通算で数える読みの予測 p + 13 + k ≡ 0 (mod 3) は 5 回とも合い、段ごとに数え直す読み（窓の後の最初の段は 3 発目）は 4 回とも外れる。

※ f6225 の射撃はバーストのカットイン中（HUD が 29 フレーム止まっていた）で、通常攻撃はバフなし・段 C はバフありだった。通算では 3 の倍数（p = 2 の次）なので、窓に関係なく段が出る。

- **読み**: S1 のカウンタは戦闘開始からの通算のフルチャージ攻撃回数。窓の外では**通算が 3 の倍数**の射撃で次の段、窓の中では**毎回**次の段。窓の中の段はカウンタを 0 に戻さないので、窓が終わった後の最初の段は「通算の 3 の倍数」の射撃に戻る。段のポインタ（A → B → C → A …）はカウンタと別に 1 つだけ持つ。
- 「窓の中の射撃は数えない」読みも FB1 で 3 発目になり外れる。
- 説明文の「3 回 / 6 回 / 9 回」→「1 回 / 2 回 / 3 回」は、この読みでは「段の間隔 3 → 1」と同じ。
- 見落としていた 3 発は刻みと増分の合計からの推定。実装後に sim の射撃の列と録画の残弾表示（照準横の N/9・N/14）で裏を取る（7.5 節の 2）。

### 0.4 語彙の出現数（202 体の説明文、スキル Lv 10、宝物版を含む）

- 「攻撃回数別の効果」は紅蓮BS とアルカナ：フォーチュンメイト（固有の状態付きで、段の中身は弾丸チャージ・スタック）だけ。
- 「各段階の効果のみ適用」はほかにもあるが、マクスウェル：オーディナリーメカニック・モランのものは循環しない。
- 「スキル N の回数の条件を変える」は紅蓮BS とスノーホワイト：イノセントデイズ（「N 回▼」の形）。今回は「間隔を即値にする」だけ足し、「減らす」は使うキャラの Stage で足す。

### 0.5 いまのモデルとの差

- **回数トリガーに順番が無い**: `ShotCountTrigger` の `every: 3` は「通算 3・6・9 … 回目ごとに**同じ**効果」。段を順に替えるには、効果の側に「何段目か」を持たせる必要がある。イサベル（231）の段階は発動の回数（`EventCountTrigger.atLeast`）で、上がったら戻らない。
- **別の効果の数え方を変える効果が無い**: 窓（`timed`）が変えられるのは stat の値だけで、トリガーの間隔は変えられない。
- **射撃間隔**: 0.1 節のとおり紅蓮BS だけ実機と 3f ずれ、録画 0047 の編成では FB の 10 秒に 14 発入る（実機 13 発）。

## 2. DSL の追加（`skills/types.ts`）

### 2.1 段の循環（`cycle`）

```ts
/**
 * Stage 11 紅蓮BS: 「攻撃回数別の効果」「各段階の効果のみ適用」の循環。
 * trigger の回数（射撃の通算カウンタの every の倍数）ごとに steps を 1 段ずつ順に発動し、最後の次は最初に戻る。
 * 段のポインタはカウンタと別に 1 つだけ持ち、戦闘中ずっと続く（リロードでもフルバーストでも戻さない）
 */
export type CycleEffect = {
  kind: 'cycle';
  /** 1 段進むきっかけ。射撃の回数トリガーだけ（every = 段の間隔。「3 回 / 6 回 / 9 回」なら 3。stacksRef・lastShot は不可） */
  trigger: ShotCountTrigger;
  /** 段の中身（2 つ以上）。今は倍率ダメージだけ */
  steps: CycleStep[];
  assumes?: LocalizedText;
};

/** 段の中身。DamageEffect から trigger を除いた形 */
export type CycleStep = { kind: 'damage'; ref: number; damageType: SkillDamageType; assumes?: LocalizedText };
```

- 段の中身を `damage` だけにするのは、紅蓮BS に要るのがそれだけだから（1 節の方針）。アルカナ（弾丸チャージ・スタック）が来たら `ammoRefill` / `timed` を段に足せる形にしておく。
- 各段の倍率ダメージは Stage 8 の `damage` と同じ式（`computeSkillHit`: 会心・FB 補正・攻撃ダメージあり、コア・距離なし）。分配ダメージは「単体ボスでは全額」の今の仮定のまま。
- **段 B の 3 ティックは 1 ヒットにまとめる**（10 節 4）。合計は全額で同じ。ティックごとの会心は期待値では 1 ヒットと同じ。ずれるのは「最後のティックが窓の境目をまたぐ」ときだけ（30f 以内）。
- 1 つの定義に `cycle` は 1 スロットに 1 つまで（2.2 節の `cycleEvery` がどの循環を指すかを曖昧にしないため）。

### 2.2 循環の間隔の変更（`cycleEvery`）

```ts
/**
 * Stage 11 紅蓮BS: 「スキル N の（フルチャージ）攻撃回数の条件が … に変更」。維持時間のあいだ、自分のスロット slot の cycle を
 * every 回ごとに進める（通算カウンタの every の倍数。1 なら毎回）。カウンタは変えない（0.3 節）
 */
export type CycleEveryEffect = {
  kind: 'cycleEvery';
  trigger: EffectTrigger;
  /** 対象の cycle を持つ自分のスロット */
  slot: SkillSlot;
  /** 変更後の段の間隔（即値。説明文の「1 回 / 2 回 / 3 回」は 1） */
  every: number;
  durationRef?: number;
  durationSeconds?: number;
  assumes?: LocalizedText;
};
```

- 対象は常に自分（説明文が「自分に」だけで、他キャラの循環を変える効果は無い）。
- 検証: `slot` にちょうど 1 つの `cycle` があること、`every` は 1 以上でその `cycle` の `every` 未満（定義の検証と、`everyRef` の場合は解決時の両方。宝物版にも掛ける）、トリガーは射撃の回数トリガー以外（自分の射撃で自分の循環を速めると判定が循環するため。今は `burstUse` だけ使う）。
- 窓の作り方は `timed` と同じ（発火・維持・上書き延長）。**区間には入れない**（ダメージの式も射手も読まない。3.2 節）。
- 「1 回 / 2 回 / 3 回」を `every: 1` と読むのは 0.3 節の実測による（窓の中は毎回段が出る）。説明文どおり「窓の中だけ別の閾値 1・2・3 で数え直す」読みは 0.3 節で外れる。

### 2.3 既存の語彙で書くもの

- **S2 最大装弾数 60%▲（10 秒）**: `timed` fullBurstStart / self / maxAmmo。9 × 1.6 = 14.4 → **14**（`MAX_AMMO_ROUNDING = 'round'`、Stage 10 で確定）。
- **S2 弾丸チャージ 100%**: `ammoRefill` fullBurstStart / self。**同じフレームの最大装弾数▲の後に当てる**（1 パス目のループの順「射撃に効く窓 → 即時効果」）ので 14 まで込める。リロード中ならリロードを終える。
- **バースト 攻撃力▲・チャージダメージ▲（10 秒）**: `timed` burstUse / self。チャージダメージはフルチャージ倍率に加算（0.2 節）。

- S2 の弾丸チャージは 100% なので、`AMMO_REFILL_ROUNDING`（切り捨てか四捨五入か）は**この録画では確かめられない**（[design-stage11.md](design-stage11.md) 11 節の申し送りは持ち越し）。

## 3. 計算の変更

### 3.1 循環の発動（`team.ts` の `planSkillHits`）

`planSkillHits` に、`damage` の発動と並べて `cycle` の発動を足す。射撃の列（`shots[slotIndex]`、1 パス目で確定済み）の上を 1 回なめるだけ（`skills/cycles.ts` の `cycleFires`）。

```text
n = 0（通算のフルチャージ攻撃回数）、step = 0（段のポインタ）
各射撃 s（昇順）について:
  n += 1
  e = s が cycleEvery の窓 [start, end) に入るなら その every、入らないなら cycle.every
  n % e == 0 なら steps[step] を s で発動し、step = (step + 1) % steps.length
```

- 発動のフレームは射撃のフレーム（Stage 8 の射撃の回数トリガーと同じ）。値はその射撃と同じバフ（その射撃で付くバフは次のフレームから）、FB 補正はそのフレームが FB 中なら乗る（`SKILL_HIT_FULL_BURST_BONUS`）。窓が重なったら小さいほうの間隔を使う。
- 窓の判定も射撃のフレームで行う（10 節 3）。実機の RL は着弾が数フレーム遅れ、0.3 節の f6225 のようにカットイン中の 1 発で「射撃はバフなし・段はバフあり」がありうるが、1 回の FB で高々 1 発なので扱わない（9 節）。
- 数えるのは `fullChargeShot`（チャージ武器の全射撃。AI の射撃もフルチャージに数える、Stage 10 で確定）。
- sim と calc は同じ `planSkillHits` を使うので、倍率ダメージは今までどおり厳密一致（`skill hits (sim=calc)`）。
- 段ごとの倍率ダメージは `ResolvedDamageEffect` として作り、段の番号 `cycle: { step, steps }` を持たせる（UI の段ごとの回数とテスト用）。

### 3.2 窓（`skills/timeline.ts`）

- `cycleEvery` は `planBuffTimeline` の 1 段目で `timed` と同じく窓にし（発火のフレームから、上書き延長は和集合）、専用の列 `BuffTimeline.cycleWindows` に置く。モダニア編の状態の窓（`stateWindows`）は命中率の条件の判定が stat ごとに読むので、stat でない窓を混ぜると解決後の stat の型（`EffectStat`）と条件の判定に手を入れることになるため。区間の境界にも `timedEffects` にも入らないので、既存の編成の区間は 1 つも変わらない。
- 射撃に効かないので、1 パス目のループ（`firstPass.ts`）では追わない。

### 3.3 射撃間隔の較正（`weapons.ts`・`sim/shooter.ts`・`cadence.ts`）

紅蓮BS の射撃は、チャージ 18f に対して間隔 43f（モデル 18 + 22 = 40f）、リロードをまたぐと 172f（モデル リロード 120 + 40 = 160f）。このままだと単騎 180 秒で約 8% 多く撃ち、FB の 10 秒に 14 発入る（実機 13 発）。**S1 の段の位置は通算の発数で決まるので、1 発の差が段の列を丸ごとずらす**。

- 実測の較正表 `MEASURED_CHARGE_CADENCE`（`sim/firing.ts`）を、**射撃のパラメータの組**（チャージ 0.3 秒・`maintainFireStance` 23・`uptypeFireTiming` 1）で `firingParams` の中で引く（`measuredChargeCadence`）。`ShotParams` に resourceId が無く、キャラの読み込みの経路（アプリの fetch・テスト・CLI の直読み）が 3 つあって、読み込み時に resourceId で載せると取りこぼすため。組は 202 体で紅蓮BS だけ（テストで固定）。
- 較正値は、チャージのフレームに **+3f**（`chargeExtraFrames`）、リロード 1 回分に **+9f**（`reloadExtraFrames`）を足す形で持つ。射手・`simulateShotFrames`・`computeCadence` はどれも `FiringParams.chargeFrames` と `reloadChunkFrames` を読むので、呼び出し側を変えずに済む。チャージ速度▲は元のチャージ時間の側にだけ効く（+3f は縮まない）。
- CDN の値ではなく実測の較正値なので、`CharacterData` の JSON には書かない（`chargeReleaseFrames` と同じ扱い）。表に無いキャラは今までと 1 ビットも変わらない。較正表の武器の注記は「未対応」ではなく「近似（射撃場の実測で較正）」にする（`damage.ts` の `modelNotes`）。
- 規則（`uptypeFireTiming` や `maintainFireStance` からの式）にしないのは、同じパラメータのキャラが他にいなくて 1 点では式が決まらないため（10 節 5）。
- FB 開始から 1 発目までの実機 55〜62f（モデル 43f）は、バーストのカットインで射撃が止まる分とみられる。13 発目が窓に入り 14 発目が窓の外になるのはどちらでも同じなので、この Stage では扱わない（9 節）。

### 3.4 退化

新しい語彙（`cycle`・`cycleEvery`）と較正表を使わない編成で、射撃の列・時刻表・区間・バフ・倍率ダメージ・1 トリガーの値が**モダニア編の完了時点と厳密一致**。

## 7. テスト・検証（PDCA）

### 7.1 DSL（`skills/__tests__/stage11ScarletBs.test.ts`）

- `cycle`: トリガーは射撃の回数トリガーだけ（`stacksRef`・`lastShot` は不可）、`steps` は 2 つ以上・中身は `damage` だけ、1 スロットに 1 つまで。
- `cycleEvery`: `slot` にちょうど 1 つの `cycle`、`every` は 1 以上で `cycle.every` 未満、射撃の回数トリガーは不可、`durationRef` / `durationSeconds` のどちらか。

### 7.2 循環の規則（合成した射撃の列）

- **退化**: 3.4 節（既存のテストが数値を変えずに通る）。
- **窓なし**: 通算 3・6・9・12 … 発目に A・B・C・A …（録画 0046 の並び）。
- **0.3 節の型**を合成した射撃の列で固定する: 窓の前の端数 p = 0 / 1 / 2 と窓の中 13 発の組で、窓の後の最初の段が 2 発目 / 1 発目 / 3 発目になり、段のポインタが途切れない。
- 窓の中で通算が 3 の倍数の射撃でも段は 1 回だけ。
- `cycleEvery` の上書き延長（窓の中でもう一度発火）で窓が延びる。

### 7.3 射撃の刻み

- 紅蓮BS の単騎の射撃の列が 43f おき、9 発目 → 次の 1 発目が 172f。
- FB 開始の弾丸チャージ（リロード中・マガジンの途中の両方）で残弾 14、窓の中 13 発・14 発目は窓の外。
- 較正表に無いキャラの刻みが変わらない（退化に含む）。

### 7.4 sim と calc の整合

紅蓮BS を含む編成を 2 つ足す（録画 0047 の編成と、実戦寄りの編成 = 例えばリター + クラウン + 紅蓮BS + アリス + アドミ）。厳密一致（射撃の列・時刻表・区間・バフ・倍率ダメージ）と離散化誤差（枠 5%・編成 3%）は既存の基準のまま。

### 7.5 録画 0046・0047 との照合（撮影済み）

1. **1 発の値**: 0.2 節の 1 発の値（窓の外・中と会心）を回帰テストに固定する
2. **射撃の列と見落とした 3 発**: 録画 0047 の照準横の残弾（N/9・N/14）を f3400〜3600・f5900〜6000 で読み、f3468・3553・5978 に射撃があるか（0.3 節の前提）
3. **FB ごとの段の列**: sim の FB ごとの「窓の前の端数・窓の中の段・窓の後の最初の段」が 0.3 節と同じ型になるか（FB の時刻は実機とずれうるので、型で比べる）
4. **FB の中の発数**: sim で FB ごとに 14 発・窓の中 13 発
5. **180 秒の合計**: 単騎・録画 0047 の編成とも、sim の合計と戦闘履歴の与ダメージの差を記録する（3 分モードの的の停止の分は差し引かない。録画 0041 と同じ扱い）

- 2 で見落とした射撃が無かった場合は 0.3 節の読みが崩れるので、録画 0048（録画 0047 と同じ編成で、FB の前後の照準横の残弾をはっきり映す）を検討する。それ以外は追加の撮影をしない（10 節 6）。

## 9. リスク・留意点

- **較正値は 1 キャラ 1 点**: 43f・172f は操作キャラの録画 2 本から。AI のときも同じかは確かめていない。表の値は操作・AI 共通として置く。
- **窓の判定は射撃のフレーム**: 実機は着弾（RL）で判定しているかもしれない。カットイン中の 1 発（0.3 節の f6225）のように、窓の境目の 1 発で段のバフの有無が変わりうる（1 回の FB で高々 1 発、差は 1 段ぶん × 約 3 倍）。
- **段 B の 3 ティック**を 1 ヒットにまとめるので、B が窓の終わりをまたぐと最後のティックの FB 補正・攻撃力▲の有無がずれる（窓の最後の射撃が B のときだけ）。
- **FB 開始から 1 発目の遅れ**（実機 55〜62f、モデル 43f）: Stage 7 の演出時間と同じく範囲外にする（13 節）。
- **複数の敵**: S1 の段の対象（最も防御の低い敵・攻撃範囲内・敵全体）と分配ダメージの割り方は、単体ボスの前提で全部同じ敵・全額にしている。

## 10. 決めてほしいこと（推奨付き）

1. **設計書の構成** — 推奨: **このファイル（`design-stage11-scarlet-bs.md`）に分け、`design-stage11.md` の冒頭とロードマップからリンクする**。録画 0046・0047 の台帳も同じ PR に入れる。代替: 台帳だけ先に別 PR にする（小さく入るが、PR が 2 つになる）。

2. **S1 の循環の表し方** — 推奨: **kind `cycle`（射撃の回数トリガー + 段の列）を足し、カウンタは戦闘開始からの通算、段のポインタは別に 1 つ**（2.1・3.1 節、0.3 節の実測）。代替: 段ごとに `damage` を 3 つ書き、`every: 9` と「何発目から」（オフセット）を足す（語彙は小さいが、バーストで間隔が変わると 3 つの効果の位置関係が崩れて表せない）。

3. **バーストの「条件の変更」** — 推奨: **kind `cycleEvery`（自分の `cycle` の間隔を窓のあいだ即値にする）を足し、窓は区間に入れずに射撃のフレームで判定する**（2.2・3.2 節。窓の置き場所は実装で `stateWindows` から専用の `cycleWindows` にした）。代替: 窓の判定を着弾（射撃 + 数フレーム）にする（実機に近いかもしれないが、着弾の遅れの値が無く、他の射撃の回数トリガーとも揃わない）。

4. **段 B の 3 ティック** — 推奨: **1 ヒット（全額）にまとめる**（2.1 節。合計・期待値は同じ）。代替: 射撃のフレームから 0・14・29f 後の 3 ヒットにする（窓の境目の 1 段だけ実機に近いが、分配ダメージの他キャラ（クイーン（真）など）と扱いが分かれる）。

5. **射撃間隔の較正** — 推奨: **実測の較正表 `MEASURED_CHARGE_CADENCE` を足す**（3.3 節。引き方と値の持ち方は実装で、射撃のパラメータの組で引き、チャージ +3f・リロード +9f を足す形にした）。紅蓮BS は段の位置が通算の発数で決まり、FB の窓に入る発数（13 か 14）で段の列が丸ごとずれるため。代替 A: パラメータ（`uptypeFireTiming` など）からの規則にする（同じパラメータのキャラが他にいないので式が決まらない）。代替 B: 較正せず範囲外に残す（約 8% 多く撃ち、窓の中が 14 発になる）。

6. **撮影** — 推奨: **追加の撮影はしない**。録画 0046・0047 で 7.5 節の 1〜5 を照合し、録画 0047 の残弾で見落とした 3 発の裏が取れなかったときだけ録画 0048 を検討する。代替: 裏取りのために録画 0048（紅蓮BS を操作、自動バースト、I・II は録画 0047 と同じ）を先に撮る。

7. **範囲** — 推奨: **循環・間隔の変更・射撃の較正・紅蓮BS の定義を 1 PR で入れる**（1 体 1 PR の方針どおり）。代替: 射撃の較正を先に別 PR にする（較正だけで既存の数値は変わらないので小さく入るが、紅蓮BS の定義なしでは確かめる相手が単騎の射撃の刻みだけになる）。

## 13. 録画 0046・0047 との照合の結果（2026-09-24）

詳細は [verification.md](verification.md) Stage 11 紅蓮BS 節。

1. **1 発の値**: 0.2 節の値と会心が 1 の位まで一致（回帰テストに固定）。
2. **見落とした 3 発**: 録画 0047 の照準横の残弾の減り方から、**f3468・3553・5978 の射撃は実在**した。0.3 節の読み（通算カウンタ・窓の中の段はカウンタを戻さない）の前提が確定。
3. **FB ごとの段の列**: sim の 5 回とも実機と同じ型（p + n + k ≡ 0 (mod 3)、段のポインタは途切れない）。
4. **FB の中の発数**: FB1 は実機と同じ 13 発（14 発目は窓の外）。FB2〜5 は、sim では FB 開始のとき紅蓮BS がマガジンの途中にいてチャージの待ちがそのまま続くので 1 発目が早く、14 発入る。実機の 5 回は FB 開始時にどれもリロード中（直後）だった。
5. **180 秒の合計**: sim のほうが多く、3 分モードの的の停止の分を引くとほぼ合う。

**紅蓮：ブラックシャドウ編の範囲外として残すこと**:

1. **FB 開始から 1 発目まで**: 実機はリロード中から 55〜62f、モデルは弾丸チャージでリロードを終えてからチャージして 43f。差はバーストのカットインで止まる分とみられる。FB 開始時にマガジンの途中だった場合の実機の例は無い。窓に入る発数（13 か 14）がこの位相で決まるので、1 回の FB で段 1 つ分変わりうる。
2. 段 B の 3 ティックは 1 ヒットにまとめた（合計・期待値は同じ）。
3. 窓の判定は射撃のフレーム。実機は着弾で判定しているかもしれない。
4. `AMMO_REFILL_ROUNDING` は S2 の弾丸チャージが 100% なので確かめられない（持ち越し）。
5. 較正した射撃の刻みは操作キャラで読んだ値。AI の紅蓮BS は確かめていない。
