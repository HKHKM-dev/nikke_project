# 設計書: 読めない編成の保存を、知らせずに上書きしない

- 何のための文書か: 画面がブラウザに保存した編成（選んでいる編成と、保存した編成の一覧）を起動時に読めなかったとき、どう扱うかを決める
- 関連: 課題 `records/backlog/web-legacy-team-save.json`（backlog 5 節）、[design-combat-power-sort.md](design-combat-power-sort.md) 8 節の 2026-11-08 の行（育成状況の読めない保存は、消さずに理由を出す）
- 起案: 2026-11-09
- 状態: 承認待ち（4 節の論点）

## 1. いまの動き

- 編成の保存（`nikke-calc.team.v1`）は版つき（`TEAM_FORMAT_VERSION`）。起動時に `parseTeamState` で読み、読めなければ null（`readTeamJson` の失敗の理由は捨てる）。
- 保存した編成の一覧（`nikke-calc.parties.v1`）は `parseParties` で読む。全体が読めなければ null。1 つの編成だけ形が合わないときは、その編成を空にする。
- App.tsx は、読めなければ初期値のまま `restored` にし、直後の effect が初期値（と空にした編成）で保存を上書きする。利用者には何も出ない。
- 読めない保存になるもの: 版の無い旧形式（Stage 3〜13）・未知の版（新しい版の画面で保存した後に古い画面を開いたなど）・形が合わない・キャラの一覧に無いニケ・同じニケが 2 枠。

## 2. 案

### 案 A（推奨）: 退避して知らせる

- 起動時に読めなかった保存は、上書きする前に、その文字列のまま別のキー（`nikke-calc.unreadable.v1`）に退避する。退避は一覧で持ち、1 件は「どの保存か（編成・保存した編成の一覧）・元の文字列・読めない理由（`readTeamJson` の error など）・退避した日時」。同じ文字列がもうあれば足さない。
- 退避してから、いまと同じく初期値で始めて保存する（画面は使える）。
- 退避が 1 件でもある間は、毎回の起動で、ページの上（見出しの下。モダン UI・クラシックの両方）に知らせを出す。
  - 文: 「ブラウザに保存した編成を読めなかったので、初期値で始めました。元の保存は残してあります。」と、1 件ごとの理由。
  - 1 件ごとに「書き出す」（元の文字列を JSON のファイルに落とす）と「消す」（退避を消す。知らせも消える）。
- 退避を書けなかった（ブラウザの保存が満杯など）ときは、この画面では編成を保存しない（元の保存を残す）。
- 長所: 育成状況の扱い（消さずに理由を出す）とそろう。何も失わず、画面は止まらない。旧形式に限らず、どの読めない保存にも効く。
- 短所: 退避を戻す（読み込み直す）手段は画面に無い（いま編成の取り込み欄が無い）。書き出したファイルは、将来の取り込みか手作業で使う。

### 案 B: 了承するまで保存しない

- 読めなかったら知らせを出し、利用者が「初期値で上書きする」を押すまで保存しない。
- 短所: 押さずに編成を作ると、閉じたときに失われる。元の保存は書き出せない限り、押した時点で消える。保存が毎回の変更で走るいまの作りと合わない。

### 案 C: 旧形式の読み込み（移し替え）を足す

- 版の無い旧形式（Stage 3〜13）を git の履歴から引き、版 1 に移し替えて読む。
- 短所: 旧形式は Stage 14 より前のもので、その後に画面を開いた人の保存はもう上書きされている。残っている見込みが小さいのに、旧形式の読み手を持ち続けることになる。未知の版・形が合わない・一覧に無いニケには効かないので、案 A か B は別に要る。

## 3. 推奨

案 A。育成状況の扱いとそろい、旧形式に限らずどの読めない保存でも何も失わない。案 C は残っている見込みが小さく、ほかの読めない保存に効かない。

## 4. 論点

1. 扱う範囲: 旧形式・未知の版・形が合わない・一覧に無いニケ・同じニケが 2 枠を、すべて同じ扱い（退避して知らせる）にする。推奨: 同じにする（どれも利用者から見れば「保存した編成が消えた」で、分ける理由が無い）。
2. 保存した編成の一覧で、1 つの編成だけ読めないとき: いまはその編成を空にする。推奨: 読める編成はいまどおり使い、一覧の元の文字列を退避して「編成03 を読めなかった」と知らせる。
3. 選んでいる編成の 1 枠だけ読めない（一覧に無いニケなど）とき、その枠だけ空にして残りを読むか。推奨: 読まない（編成ごと退避して初期値）。いまの検査（`readTeamJson`）のままで、枠ごとの読み捨ての判断を足さない。
4. 知らせの置き場所: ページの上（見出しの下）。推奨: そこ（App.tsx で両方の表示モードに 1 か所で出す。読み込みの失敗の表示と同じ所）。育成状況の知らせはアカウントのメニューの中だが、編成は開かなくても気づける所に出す。
