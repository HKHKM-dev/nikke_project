## 条件

**何を確かめるか**

- C-0231（仮説・単独実測）は、録画 `021`（エーテル + デルタ + クイーン（真））と `040`（アドミ + ユニ + ラム + クイーン（真））から出した値で、どちらも最小構成でない（エーテル・アドミ・ユニ・ラムの機構が未確定）。最小構成の新しい録画で同じ値が出るかを見る。予測を撮る前に commit し、値を決めるのに使っていない録画で再現すれば、等級の候補は反復実測になる（plan/skills-guide.md 1.8 節）。
- バースト使用時の効果（自分の攻撃力▲）は、SG の 1 トリガーの間隔より細かくは読めないので、今回も読まない（V-0147 と同じ）。

**編成**

- ココア（311。I）+ デルタ（20。II）+ クイーン（真）（870。III・操作・AUTO 射撃 ON）、オートバースト ON。射撃場・灼熱の BigArms・3 分モード・スペック固定。
- **最小構成**: ココアは定義が効果なし（V-0031）、デルタは C-0081 で、どちらも機構が確定している。ラムは C-0235 が仮説で未確定なので I にしない（backlog 2-4）。2026-10-05 に `records/minimal.ts` の検査（`minimalWarnings`）にこの編成をかけ、警告が出ないことを確かめた（未確定はクイーン（真）だけ）。

**読み方の前提**

- III の発動は、III のタイマーが 00.00 になったフレーム（V-0078・V-0082・V-0137）。遅れ（モデル）= 動画のフレームでの「III の発動 → ヒット」− 22（フルバーストの入りの止まり。C-0069）。照合の `burstHitDelays` は止まりを含めた動画のフレームで比べる。
- ヒットは FULL BURST の表示の中に出るので、`hud.ts` は拾えない。HUD の数字を 1 フレームずつ拡大して目で読む（V-0147）。
- バーストの倍率ダメージは分配ダメージで、単体の的には全額が 1 ヒットで出る（定義の assumes）。値は、バースト 3 段階突入時の分配ダメージ▲が乗った値。

## 予測（撮る前に書く）

撮る前に書いた（2026-10-05）。H0 はいまのモデル（遅れの表のクイーン（真）の行）で、値は予測ファイル（records/predictions/V-0204.json）。

| ------------------------------- | ----------------------------------------------- | ---------------------------------------------------- |
| H0: いまのモデル（C-0231 の値） | 予測ファイルの `queen-delays` ± 1f              | `queen-burst-hit`・`queen-burst-hit-crit` のどちらか |
| D2: 毎回同じだが C-0231 と違う  | どの回も同じ値 ± 1f で、H0 から 2f 以上ずれる   | （H0 と同じ）                                        |
| D0: 毎回違う                    | 2f 以上ずれる回がある                           | （H0 と同じ）                                        |

- **H0 を予想する**。`021`・`040` で I・II の顔ぶれを替えても同じ値で、遅れの表のどのキャラも回ごとに揃ったため。
- 1f の揺れは録画の重複フレームの位置で出る（V-0147）ので、± 1f を合うとみる（観測値の許容 `abs: 1`）。止まりを引いた 1f が HUD の表示の遅れかゲーム内の遅れかは、今回も見分けない（C-0231 の注記）。
- 当たったときの影響: C-0231 を確定（反復実測）にできる。遅れの表の値は変わらない。
- 外れたときの影響: D2 なら、遅れが I・II の顔ぶれで変わることになり、遅れを演出の長さで決まる値とみる前提（plan/design-burst-landing.md）を見直す。D0 なら、何で決まるかを調べる。

## 読み方

1. 取り込む: `node tools/captures/intake.ts <元ファイル> --id NNN --name sr+sr+sg_cocoa+delta+queen_queen-auto --rid 311,20,870 --controlled 3 --target BigArms --element Fire --mode range-3min --fixed-spec on --auto-fire on --auto-burst on`。台帳を埋めて `npm run records:table`。この検証記録の冒頭に「録画」を足す。
2. 右のバースト欄を 1 フレームずつ並べて、各回の III のタイマーが 00.00 になるフレームを読む。
3. 各回の止まりの中の HUD の数字を 1 フレームずつ拡大して、クイーン（真）のバーストの倍率ダメージのヒットのフレームと値を取る。
4. III の発動 → ヒットを観測値（`burstHitDelays`。許容 `abs: 1`）、1 回目のヒットの値を観測値（`burstHitDamage`。会心かどうかで `crit` を選ぶ）にする。`args`・`setup` は予測ファイルの指標と同じにする。
