## 0. 要約

- シンデレラ S1 の説明文: 「フルチャージして攻撃した時、自分に「チャージ速度 100%▲」「最大弾数リロード完了時に解除」」（スキル Lv1〜10 とも 100%）。いまは未対応の notes で、モデルの発と発の間は 59f（1 秒のチャージ。押下チャージ型なので解放を足さない。C-0222）。
- 単騎の既存の録画 124・178・179（V-0101・V-0153。AUTO・自動バースト OFF）の HUD の増分のフレームでは、マガジンの中の発と発の間は 20・20・19f の繰り返し、リロードを挟む間は約 200〜202f。
- 説明文どおりなら、1 発目（フルチャージ）の後はチャージ時間が 1 × max(0, 1 − 1) = 0 秒（C-0013）になり、発と発の間はチャージでは決まらない。20・20・19f の並びは、発射レート 180rpm（`rateOfFire`）をゲーム内の時計（1 フレーム 0.017 秒）で 1 フレームずつ蓄積し端数を持ち越す刻み（AR・SMG・SG の C-0058 と同じ。平均 19.61f）と一致する。
- リロードを挟む間 200〜202f は、「リロード 2 秒（117.6f）+ ▲の無い 1 秒のチャージ 59f + 解放 23f」（C-0222 のアニス：スターの 200〜202f と同じ形）と合う。▲が解除されずに残るなら約 141f になる。
- 足すもの: (1) 維持の終わり「最大弾数リロード完了時」（`durationUntil: "reloadEnd"`。論点 1）、(2) 押下チャージ型の発と発の間の下限（発射レートの蓄積。論点 2）、(3) シンデレラ S1 の定義（論点 3）。
- これで、V-0446 で見分けられなかった「追加ダメージがバーストゲージを溜めるか」（C-0583 の `assumes`）を、録画 480・481 の 1 回目のフルバーストの時刻で読み直せる（4 節）。

## 1. 語彙

### 1.1 維持の終わり `durationUntil: "reloadEnd"`（論点 1）

- 説明文の「最大弾数リロード完了時に解除」（グレイブ S2 の「最大装弾リロード完了時に解除」も同じ）。
- 意味: 効果の窓は、発火のフレームから、その後に持ち主（効果の対象。シンデレラでは自分）のリロードが最大装弾数まで込め終わったフレームまで（そのフレームで閉じる）。窓の間に再発火したら和集合（上書き延長と同じ）。
- 「込め終わったフレーム」は、射手（`frame/shooter.ts`）が最大装弾数に届いて 1 発目の遅延（priming）に入るフレーム。1 パス目が `ShotLog.reloadEnds` に書き、持ち主ごとの一覧（`skills/holders.ts`）が件の終わりに使う（使用武器の変更の `ammoSpent` と同じ置き方）。
- ハイド中のリロード（的のジャンプの窓）の込め終わりも数える。弾丸チャージで最大に届いたリロードは数えない（使い手のシンデレラ・グレイブには弾丸チャージが無く、確かめていない）。込め終わりを書くのは、この維持の効果を持つ枠だけ（ほかの枠の射撃の列は変えない）。
- 書ける効果: `timed`（対象は自分だけ）。1 パス目で窓を追う stat（チャージ速度など）にも書ける（`battleEnd` と同じ。`fullBurstEnd` とは違う）。

### 1.2 押下チャージ型の発と発の間の下限（論点 2）

- いまのチャージ武器は、発と発の間をチャージ（と解放・姿勢）だけで決め、発射レート（`rateOfFire`）を見ない。チャージ時間が 0 秒になると、毎フレーム撃つ。
- 推奨: 押下チャージ型（`DOWN_Charge`）のマガジンの中の 2 発目以降は、AR・SMG・SG と同じく、前の発の次のフレームから毎フレーム発射レートを蓄積し（`rateAfterShots`）、1 発分たまったフレームより前には撃たない（チャージが満ちていても待つ）。蓄積は 1 発分で止める（チャージの待ちが長い間に貯め込まない）。
- 入力が UP のチャージ武器には掛けない。どれも発射レートが 60rpm（1 発分 58.8f）で、紅蓮：ブラックシャドウ（43f。C-0149）・アリス（31f。C-0523）は確定の結論でそれより速く撃つ（実装の途中で、全部のチャージ武器に掛けたらこの 2 体のテストが落ちて分かった）。押下チャージ型（アニス：スター 120rpm・シンデレラ 180rpm・ベスティー：TU 180rpm・リバーレリオ 200rpm・ラプラス：UH 300rpm・ネオン：ビジョン・アイ 300rpm）は発射レートがキャラごとに違い、アニス：スターの最も短い間（チャージ時間の固定の 42f。C-0222）も 1 発分（29.4f）より長い。
- チャージが発射レートの 1 発分より長いうちは、チャージが満ちた時には蓄積が 1 発分に届いているので、値は変わらない（既存の観測値の残差は変わらなかった。3 節）。
- マガジンの 1 発目（リロードの後・戦闘開始・ハイドの明け）は今のまま（蓄積は startMagazine で 0 に戻し、1 発目はレートを待たない）。
- 確かめていないこと: チャージが発射レートの 1 発分より少しだけ短い（0 < チャージ < 20f）場合に、蓄積とチャージのどちらが後に満ちた方で撃つ形か（推奨の形）。シンデレラはチャージ 0 秒なので見分けない。

### 1.3 シンデレラ S1 の定義（論点 3）

```json
{
  "kind": "timed",
  "trigger": { "count": "fullChargeShot" },
  "target": "self",
  "stat": "chargeSpeed",
  "ref": 3,
  "durationUntil": "reloadEnd"
}
```

- 付き始めは、フルチャージの発のフレーム（射撃の回数のきっかけは次のフレームから効く。いまの規則のまま）。2 発目以降はチャージ 0 秒のフルチャージとして撃ち、そのたびに付き直す。
- 解除の後のマガジンの 1 発目は▲の無いチャージ（59f）。

## 3. 結果

- V-0463（結論 C-0603・C-0604）。単騎の 3 本のマガジンの中の間と、リロードを挟む間がモデルと許容内。追加ダメージのゲージは、溜める読みが 1 回目のフルバーストの時刻と合い、溜めない読みは約 75f 遅い。
- 既存の観測値: 単騎の録画と、シンデレラを含まない編成の残差は変わらない。シンデレラを含む編成（録画 482〜488）で、モデルのフレームの決め打ちで 1 ヒットを比べる観測値（`484-07`・`484-08`・`485-07`・`485-08`・`487-09`・`487-10`・`488-06`・`488-07`）は、モデルの時刻表が変わって別の場面を指したので、比べるフレームを、モデルの 2 回目のフルバースト（アニス：スターの I の約 1 秒後に始まる回。録画の場面と同じ）の開始からの相対にした（指標 `hitDamage`・`perShotHitDamage` の省略できる引数 `fullBurst`）。値と許容は変えていない。相対にすると、アニス：スターの仮説の効果（C-0244・C-0521）を外しても比べる状態が同じフルバーストに残り、最小構成の検査の感度も出ない。予測ファイル V-0448・V-0449 の指標は、引数が変わったので観測値の ID で結び付けた（予測の値は変えない）。
- テスト: 防御力の経路の編成のテスト（`defensePathTeam.test.ts`）は、どのフルバーストでも同じ形になる前提で書いていた。シンデレラの発が速くなり、アニス：スターがバーストを撃つ回と撃たない回が混ざるので、前提の回（防御力▲ が効いている・いない）に絞って確かめる形にした。録画 482・483 の 2 回目以降（`482-11`・`483-11`）でもアニス：スターはバーストを撃っている。

## 5. 論点

1. **リロード完了で解除の書き方**（1.1 節）
   - 推奨: `timed` の維持の終わりに `durationUntil: "reloadEnd"` を足す（`fullBurstEnd`・`battleEnd` と同じ並び）。窓は込め終わったフレームで閉じる。
   - 代わりの案: 名前の付いた状態（中身にチャージ速度▲）と、解除（`removeState`）のきっかけ「リロード完了時」を足す。状態の名前が説明文に無く（「」の中の効果そのものが解除される）、状態にする理由が無い。
2. **チャージ武器の発と発の間の下限**（1.2 節）
   - 推奨: 押下チャージ型のマガジンの中の 2 発目以降に、発射レートの蓄積（1 発分で止める）を下限として掛ける。チャージ 0 秒のシンデレラで 20・20・19f の並びが合い、ほかのチャージ武器は値が変わらない。入力が UP のチャージ武器は発射レート（60rpm）より速く撃つ確定の結論があるので掛けない（1.2 節）。
   - 代わりの案: チャージ時間が 0 秒になったときだけ、発射レートの蓄積で撃つ（0 < チャージの場合は今のまま）。式は狭くなるが、チャージが少しだけ残る時に発射レートより速く撃てる形になり、根拠のない分かれ目を作る。
3. **シンデレラ S1 の定義と確かめ**（1.3・2 節）
   - 推奨: 1.3 節のとおり定義し、単騎の録画 124・178・179 の読み直しで確かめる（124 は出どころ、178・179 が再現）。追加ダメージのゲージ（4 節）は、同じ PR で録画 480・481 を読み直し、合う方に `assumes` を直す（見分けられなければそのまま）。
   - 代わりの案: 定義だけ入れ、確かめは撮影（単騎で、リロードの前後を一時停止して適用中の効果を映す）を待つ。
