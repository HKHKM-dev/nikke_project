# V-0170: モダニアの S1（クリティカルダメージ▲・最大装弾数▼のスタック）は説明文どおりか（録画 045 の読み直し）

- 問い: モダニアの S1 を「通常攻撃 200 回命中ごとに、自分にクリティカルダメージ▲と最大装弾数▼を 1 スタック（最大 5）」と読んで、モデルは単騎・操作の録画 045 の会心の 1 ヒットとリロード明けの残弾に合うか
- 話題: スキル・キャラ固有
- 日付: 2026-10-05
- 録画: `045`
- 状態: 調査中

## 条件

- 目的: モダニア（260）の S1 の effects[1]（クリティカルダメージ▲）・effects[2]（最大装弾数▼）を結論に結び付ける（plan/design-skill-claims-5-2.md 3.2 節の決定。最小構成の録画だけ読み直す）。
- 録画 `045` はモダニア単騎・**操作**・スペック固定 ON・3 分モード。単騎なので未確定の要素はモダニア自身だけ（最小構成）。スペック固定ではキューブが乗らず、S2 の攻撃力▲（自分が命中率増加状態なら）は出ない。バーストも出ない。
- 説明文（`data/characters/260.json` の skill1）: 通常攻撃が 200 回命中した時、自分にクリティカルダメージ▲（5 スタック）と最大装弾数▼（5 スタック）。定義は `data/skills/260.json` の skill1 の effects[1]・effects[2]（`stacks`・付与のたびに全スタックを更新）。
- 操作の録画なので、撃つ時刻はモデルと合わない。比べるのは時刻に依らない値（スタックごとの会心の 1 ヒット・最大装弾数）だけ。モデルの frame は、モデルでそのスタックにある区間を指すだけ。
- 前に読んだもの: `045-01`〜`045-08`（的のジャンプ・ゲージ・リロード）。凍結の verification.md Stage 11 モダニアは、録画 045 から 5 スタックが張り付く区間と 5 → 0 に落ちるフレームを読んだ（スタックの規則の出どころ）。スタックごとの会心の値と、045 のリロード明けの残弾は読んでいない（リロード明けの残弾は録画 044 で読んだ）。そのため、スタックの規則（付与のたびに全スタックを更新）は比べる指標にしない。

## 予測（撮る前に書く）

仮説ごとに、この録画で何が見えるはずか。見分けられるか。外れたときの影響。数値は予測ファイル（records/predictions/V-0170.json。npm run records:predict -- V-0170）を指す。既存の録画の読み直しなら、冒頭の「録画」に挙げてから予測を出し、読む前に commit する。

| 仮説               | 中身                                                                                             | 会心の 1 ヒット（`s1-k*-crit`） | 最大装弾数（`s1-k*-maxammo`）                                |
| ------------------ | ------------------------------------------------------------------------------------------------ | ------------------------------- | ------------------------------------------------------------ |
| H1（予測ファイル） | 説明文どおり。スタックごとに会心の倍率に +0.1425、最大装弾数を ×(1 − 0.0504k) で丸める（C-0017） | スタック k の値（予測ファイル） | 300・285・270・255・240・224（予測ファイル）                 |
| H2（手で書く）     | 最大装弾数▼を四捨五入でなく切り捨てる                                                            | H1 と同じ                       | 300・284・269・254・239・224（k = 1〜4 で H1 より 1 少ない） |

- 見分け方: 会心の 1 ヒットは、モダニアの 1 発の総ダメージの増分（通常攻撃 + S1 の追加ダメージが同じフレーム）から、追加ダメージの値（会心・非会心）を引いて出す。スタック k はその時点の値から決まるので、「どれかの k の値に端数まで合うか」と「k が 200 ヒットごとに 1 つずつ上がるか」の両方を見る。
- 外れたときの影響: 会心の値が格子に乗らなければ、クリティカルダメージ▲の値か置き場所（会心の倍率に足す）を見直す。最大装弾数がずれれば、丸め（C-0017）かスタックの値を見直す。

## 読み方

1. `node tools/captures/fetch.ts 045` で取り寄せる。
2. `npm run records:read -- 045 --recipe hud-jumps` で総ダメージの増分を全フレーム取り、1 増分を「通常攻撃（胴体・コア × 会心 × 距離）+ 追加ダメージ（会心か否か）」の和に分ける。スタック k ごとに、会心の通常攻撃の値を 1 つずつ拾う（指標 `hitDamage`）。
3. リロードの区間（`reload-segments` レシピか、`reload-bar.ts`）の直後のフレームの照準の横の残弾を、`reticle-ammo.ts` で読む。その時点のスタックを 2 の値から決めて、スタックごとに 1 つ拾う（指標 `maxAmmoAt`）。
