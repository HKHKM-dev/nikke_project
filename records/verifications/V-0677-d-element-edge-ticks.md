# V-0677: D の S1・S2 の▲の窓の端を、ゲーム内のティックで読み直す

- 問い: V-0662 の窓の端の数 f の差（S2 は録画が 3〜4f 遅く、S1 は 0946 が 1f 早い）は、フルバーストの入りの止まりの長さと窓の起点の数え方のどちらで説明できるか
- 話題: スキル・キャラ固有
- 日付: 2026-11-06
- 録画: `0946`、`0947`
- 結論: `C-0960`、`C-0961`
- 状態: 完了
- 派生元: `V-0662`

## 条件

- 型: 読み直し。V-0662 の録画 0946・0947（リター・デルタ・D、鉄甲の的）。
- V-0662 は、窓の端を動画のフレームで比べた。モデルは動画のフレームに直すとき、入りの止まりを 22f 一律、I・II の発動の止まりを 1f 一律で足す（`videoFrameOf`）。録画の止まりは回ごとに揺れる（入りは 21〜24f。C-0069）ので、端の差がこの揺れか、窓そのもの（起点・長さ）の差かは、動画のフレームでは分けられない。
- ここでは、窓の端の発のフレームを、残り時間の秒の変わり目からゲーム内のティック（止まりを除いたフレーム）に直し、モデルのフレーム（ゲーム内のティック）と比べる。止まりの長さの揺れは、直した値に入らない。
- 分けたいこと:
  - S1: 起点（00.00 の前か後か）と、窓の長さに入りの止まりを含めるか。ティックで 00.00 から 882 なら、モデルの窓は合っていて、差は止まりの長さだけ。
  - S2: 戦闘開始から 882 ティックか。切れ目までの止まり（I・II の発動と 1 回目の入り）をモデルが多く数えていないか。

## 予測

なし（読み直し）。

## 読み方

1. 止まりの無い区間: `timer.ts --mode runs`（この検証で足した）。区間の中の変わり目はどれも c = ceil(戦闘開始 + a + k × 58.8235) を満たし、a（止まりの累計 + 時計の位相の定数）の範囲が区間ごとに出る。区間の中のフレーム f のティックは f − 戦闘開始 − a。`--mode ticks`（直後の 3 点の o の最小を引く）は、鋸歯の位相で最大 1 小さく出るので使わない。
2. 採らない変わり目: `timerOffsets` は、近くに位相のそろう変わり目が 2 つ要るので、フルバーストの直前の 1〜2 個（本物）も落とす。`--mode runs` は採らなかった変わり目の o を出す（a は (o − 1, o]）。本物かは still の画で数字を確かめ、近くの区間の a の端数にそろえて a を決めた（端数は数十秒で 0.1 前後しか動かない）。
3. 止まりの内訳: 区間どうしの a の差（`0946-14`・`0946-15`・`0947-14`・`0947-15`）。戦闘開始の a は、I の発動の後の最初の変わり目（0946 は f877、0947 は f905）の a から I の止まり 1f を引いた値（I を 1f とすると、2 本とも 02:59 が出たフレームが、a の起点の次のフレームにそろう。0946 は戦闘開始の後の 2 フレームが 03:00、0947 は 1 フレーム）。
4. 窓の端: V-0662 の buff-edge の発（`0946-09`・`0946-10`・`0947-09`・`0947-10` の注記の、▲の乗った最後の発と乗らない最初の発）のフレームを、ティックに直した（`0946-16`・`0946-17`・`0947-16`・`0947-17`）。
   - S1 は、2 回目のフルバーストの 00.00 のティックからの差。00.00 の a は、II の発動の後・00.00 の前の変わり目があればその a（0947 の f3872）、無ければ I の後の変わり目の a に II の止まり 1f を足した値（0946）。比べるのは `buffEdgeFromActivation` の `ticks: true`（この検証で足した。00.00 からのモデルのフレームの差）。
   - S2 は、戦闘開始からのティック。比べるのは `buffWindowEnds`（モデルのフレーム）。

## 結果

| 観測                                     | 0946                | 0947                    | モデル             |
| ---------------------------------------- | ------------------- | ----------------------- | ------------------ |
| 1 回目の入りまでの止まり（I・II + 入り） | `0946-14`           | `0947-14`               | I 1・II + 入り 23  |
| 2 回目のチェーンの止まり                 | `0946-15`           | `0947-15`               | I 1・II 1・入り 22 |
| S1 の切れ目（00.00 からのティック）      | `0946-16`: 874〜882 | `0947-16`: 877.1〜882.1 | 882                |
| S2 の切れ目（戦闘開始からのティック）    | `0946-17`: 886〜887 | `0947-17`: 885〜887     | 882                |

- S1: ティックで数えると、2 本ともモデルの 882 が「▲の乗った最後の発 〜 乗らない最初の発」の幅に入る（どちらも幅の上の端）。窓は 00.00 から 882 ティックで、モデルの起点と長さのまま。0946 の動画のフレームでの 1f の早さは、2 回目の入りの止まりの長さ: 0946 は II の発動の止まりと入りの止まりの和が 22f（II を 1f とすると入りは 21f）、0947 は入りが 21.9f で、モデルの 22f 一律より短いか同じ。0946 の II の止まりが 2f でも、切れ目は 875〜883 で 882 を含む。
- S2: ティックで数えても、2 本ともモデルより 4〜5 遅い（0946 は 886〜887 で、切れ目は 887 ティックに決まる）。切れ目までの止まりは 2 本とも 23f（I の 1f と、II と 1 回目の入りの和の 22f）で、モデルが動画のフレームに直すときの 24f より 1f 少ない。止まりの数え方では説明できず、ゲーム内の時間で S2 の窓が遅く切れる。
- 0946 の 2 回目のチェーンの前に、発動と関係しない 1f の止まりがある（f3665〜3725。C-0262 の形）。0946 の 2547〜3665 には、変わり目が 1f 遅く拾われる所が 3 か所ある（stalls の ±1 の区切り）が、前後の区間の a は同じ端数にそろう。
- 止まりの無い区間の a の端数は、整数の止まりだけでは変わらないはずだが、0947 の 2 回目の入りの前後で 0.1 ずれ、後半は数十秒で 0.1 ずつ増える（動画とゲームの時刻のずれ。C-0260 の 1 秒の幅）。窓の 15 秒の中では 0.1 より小さい。

## 分かったこと・分からないこと

- 分かった: S1 の窓は、ゲーム内のティックで 00.00 から 882（モデルどおり）。V-0662 の S1 の差は、入りの止まりの回ごとの揺れ（C-0069）で、モデルの窓の起点や、止まりを窓に含めるかの数え方の差ではない（C-0960）。入りの止まりは videoFrameOf で動画のフレームに直すときだけ足す代表の 22f で、回ごとの値はモデルに持てない（どの回が何 f かは決まっていない）ので、モデルは直さない。窓の端を比べるときは、ティックで比べる（`ticks: true`）。
- 分かった: S2 の窓は、ゲーム内のティックで戦闘開始から 886〜887 で切れ、モデルより 4〜5 遅い。止まりの数え方の差ではない（C-0961）。
- 分からない: S2 の差の出どころ。S2 の▲の付き始めが戦闘開始より 4〜5 ティック遅いのか（同じ S2 のゲージのチャージは戦闘開始の次のフレーム。C-0918）、S2 の窓だけ長さが違うのか。S2 の付き始めは D の 1 発目（戦闘開始の約 12f 後。C-0114）より前で、この編成では読めない。原因を単独で確かめていないので、モデルは直さない（AGENTS.md「残差を係数で埋めない」）。backlog の 2-56 に残す。
