# V-0224: キューブのリロード速度▲は、リロードの長さにどう効くか

- 問い: スペック固定 OFF のマナ単騎で、レリックベアーキューブの「リロード速度▲」は、リロードの長さ（RELOADING のバー）にどう効くか
- 話題: 射撃（間隔・リロード・チャージ）
- 日付: 2026-10-06
- 状態: 調査中

## 条件

- Stage 13 の残り（[design-stage12.md](../../plan/design-stage12.md) 3.5 節の 6）。
- 録画 3（V-0221「次に撮るもの」）: マナ単騎にレリックベアーキューブを付ける。ほかの条件は V-0221 の録画 1 と同じ。
- 最小構成: リロードの長さに効くのは、CDN のリロードの秒（1.67 秒）をゲーム内の時計で数えた長さ（C-0145）と、問いのキューブだけ。マナのスキルにリロード速度の効果は無く、OL の行にリロード速度は無い。全弾リロードなので、OL の最大装弾数増加で弾数が変わってもリロードの長さは変わらない。
- キューブの値は data/masters/cubes.json の段階の値（Lv15 は段階 3）。キューブのアンチコード（有利コードの攻撃ダメージ▲）は、灼熱の的では乗らない（C-0119）。

## 予測（撮る前に書く）

H1 はいまのモデル（リロードの秒 × (1 − 値)。スキルのリロード速度▲と同じ C-0013 の形）、H0 はキューブが乗らない形で、値は予測ファイル（records/predictions/V-0224.json）にある。H2（リロードの秒 ÷ (1 + 値)。C-0013 で棄てた形）は式を切り替える仮説なので、ここに手で書いた。

| 仮説           | バーが 0 から満ちるまで（f） |
| -------------- | ---------------------------- |
| H1: × (1 − 値) | 予測                         |
| H0: 乗らない   | 予測                         |
| H2: ÷ (1 + 値) | 75.746                       |

- 見分け方: RELOADING のバーの長さ（`reload-segments` のバーの長さ）。H1 と H2 は約 7f、H1 と H0 は約 29f 離れる。
- 合えば: H1 ならモデルはそのまま。
- 合わなければ: キューブのリロード速度▲の入り方（`firingParams` の `reloadSpeed`）を直す。

## 読み方

- `npm run records:read -- <録画 id> --recipe reload-segments --source V-0224 --write` で、リロードごとのバーの長さを読み、その中央値を観測値にする（`reloadFramesAt`。指標の `args`・`setup` は予測ファイルと同じ）。
