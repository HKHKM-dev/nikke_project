# フラワーの S2 のバーストゲージ（周期でゲージだけを溜める効果）

- 関連: [skills-guide.md](skills-guide.md) 1.4 節、[design-nihilister.md](design-nihilister.md) 8.1 節（時間の周期のトリガー `everySeconds`）、[design-helm.md](design-helm.md)（`damage` の `gaugeHits`）、[backlog.md](backlog.md) 2-3・6 節
- 作成日: 2026-10-03
- 根拠: C-0178（V-0108）
- 状態: オーナーの指示（2026-10-03「S2 のゲージを実装して」）で実装した。下の 4 節の論点は推奨どおりにした

## 1. 何を足すか

I-DOLL・フラワー（304）の S2（フラワーカラー）は、戦闘開始から 15 秒ごとに発動し、そのたびにバーストゲージが BURST バーで約 4px 溜まる。射撃や的のヒットに依らない（C-0178）。S2 の説明文の効果（敵の攻撃力▼）はダメージに関係しないので、ゲージだけを入れる。

今の語彙では書けない。

- 時間の周期のトリガー（`{ everySeconds }`）は `damage` と `dot` にしか書けない。
- ゲージを溜める効果は、`damage` の `gaugeHits`（射撃の回数トリガーだけ）、`cycle` の段の `gaugeHits`、即時効果 `burstGauge`（最大値の X%。量は説明文の値）の 3 つで、どれも「周期で、射手の 1 ヒットぶん、ダメージなし」を書けない。

## 2. 語彙: `burstGaugeHit`

```json
{
  "kind": "burstGaugeHit",
  "trigger": { "everySeconds": 15 },
  "assumes": { "ja": "…", "en": "…" },
  "claims": ["C-0178"]
}
```

- **意味**: トリガーが発火するたびに、射手の 1 ヒットぶんのバーストゲージ（CDN の `target_burst_energy_pershot`。フルチャージ倍率は乗らない）を、発火のフレームのゲージに足す。ダメージは出さない。
- **量**: `damage` の `gaugeHits`・`cycle` の段の `gaugeHits`（C-0085）と同じく、射手の `targetBurstEnergyPerShot` × (1 + バーストゲージのチャージ速度)。ゲージが溜まる状態（満タン・チェーン・フルバーストの外）のときだけ足される（状態機械の規則のまま）。
- **トリガー**: 今回は時間の周期のトリガー（`{ everySeconds }`）だけを許す。ほかのトリガーは検証で弾く（使うキャラが出たときに広げる）。発火のフレームは `skills/timeline.ts` の `timerFrames`（戦闘開始から k × N 秒。ニヒリスターと同じ）。
- **書ける場所**: どのスロットにも書ける。
- **的を狙えない窓**: 時間の周期のトリガーは的のジャンプに依らない（C-0091 と同じ扱い）ので、窓の間も足す。

## 3. 実装

- `skills/types.ts`: `BurstGaugeHitEffect` を `SkillEffect` に足し、`parseEffectBody` で検証する（トリガーは `{ everySeconds }` だけ、ほかの欄は `assumes`・`claims`）。
- `skills/burstDamage.ts`: `resolveTimerGauges`（定義の `burstGaugeHit` を、周期の秒の列に解決する。`unsupported` のスロットは空）。
- `frame/firstPass.ts`: ループの前に、各枠の `burstGaugeHit` の発火フレームへゲージを予約する（`pendingGauge`。段のヒットのゲージと同じ入れ物）。1 パス目は sim と calc で共有なので、calc の時刻表も同じになる。射撃に効く窓や出来事の列（`replayEvents`）は変えない（ゲージは状態機械に入るだけで、射撃には効かない）。
- 表示: Web の定義の表示とCLI は、ゲージだけの効果を出す欄が無いので足さない（スキルの対応状況の一覧 `plan/skills.md` には `supported` として出る）。
- 定義: `data/skills/304.json` の skill2 を `supported` にし、上の効果を書く。`assumes` に「周期の 15 秒は録画から読んだ値（説明文に無い）」「1 回の量は的の 1 ヒットぶん（28,000）とみた」。攻撃力▼の note は残す。

## 4. 論点（推奨どおりにした）

1. **1 回の量**: 推奨は `targetBurstEnergyPerShot`（28,000）。6 本の録画で 1 回 3〜4px で、物 1 個（35,000 = 約 4.7px）より小さい（C-0178）。紅蓮BS のスキルのヒットと同じ形（C-0085）。代わりの案の 35,000（フルチャージ倍率込み）は px と合わない。
2. **周期**: 推奨は 15 秒（`timerFrames` で 882〜883f ごと）。録画の間は 883〜885f で、1 回あたり 1〜2f 長い（ニヒリスターの 10 秒と同じ形。design-nihilister.md 8.2 節の 2）。1 回目は録画が約 5f 遅い。端数は根拠が無いので入れない。
3. **チェーンの間の発動**: 状態機械の規則どおり捨てる（ゲージは charging のときだけ足す）。録画ではチェーンの間はバーが読めず、確かめていない（V-0108）。

## 5. 退化と確かめ

- フラワーを含まない編成は、数値が 1 つも変わらない（`burstGaugeHit` を書いた定義は 304 だけ）。
- フラワーを含む編成（単騎の 077 と、AI のフラワーを含む多人数の録画）は、15 秒ごとにゲージが溜まるぶん、2 回目以降の満タン・フルバーストが早まりうる。1 回目の満タンは、多人数の録画ではどれも 15 秒より前なので変わらない見込み。照合（`npm run records:check`）の差は roadmap に書く。
- 単騎の 077 では、1 回目の満タンがモデルの 15 発目から 14 発目になる見込み（980,000 + 28,000 ≥ 1,000,000。C-0176）。
