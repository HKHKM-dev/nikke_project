# 生成物の表の列幅と差分

- 日付: 2026-10-25
- 関連: [skill-catalog.md](skill-catalog.md)（同じ理由で prettier の対象から外した前例。`.prettierignore`）、AGENTS.md「コミット手順」（生成物の衝突の扱い）
- 状態: 2026-10-25 にオーナーが承認（論点 1 は A、論点 2 は厳しくする。どちらも推奨どおり）し、同日に実装した（7 節）

## 1. 何が困っているか

- prettier は Markdown の表の列幅を、その列でいちばん長いセルにそろえる。長いセルが 1 つ増える・減るだけで、表の全部の行が書き換わる。
- 生成のコード（`renderResiduals`・`renderRecordingsDoc`）は列をそろえずに書き、`records:check`・`records:table` の後の `tools/format-retry.ts`（prettier）が列をそろえている。そろえる処理は、生成物の側には要らない。
- 列そろえは、ファイルの大きさにも効いている。`plan/residuals.md` は 1 行がおよそ 2,400 字で、その大半が空白（3 節）。エージェントが `grep` で 1 行を引くたびに、その空白を読む。

## 2. どこで起きているか

origin/main の直近 60 件の PR で、生成物ごとの変更行数を `git log --stat` で数えた（#691 の録画の番号の振り直しは、中身が全部の行で変わるので除いて見る）。

| 生成物                        | 表           | 列幅だけで全部の行が変わった PR    |
| ----------------------------- | ------------ | ---------------------------------- |
| `plan/residuals.md`           | 2 つ         | #675（7,014 行）                   |
| `plan/captures/recordings.md` | 3 つ         | #639（1,022 行）・#627（1,008 行） |
| `plan/claims.md`              | 無い（列挙） | —                                  |
| `plan/verifications.md`       | 無い（列挙） | —                                  |
| `plan/skills.md`              | 無い（列挙） | —                                  |
| `plan/minimal.md`             | 無い（列挙） | —                                  |

- 表を持つ生成物は 2 つだけで、起きているのもその 2 つ。ほかの 4 つは列挙の形なので、prettier が書き換える幅が無い。
- 生成物のほかの PR の変更行数（数行〜百数十行）は、残差の値が変わった行など、中身の変化だった。

## 3. 列をそろえない形での試算

各 PR の前後の版から、表の行のセルの前後の空白を落とした版を作り（区切り行は `| --- |`）、差分の行数と大きさ（字数）を比べた。

| PR   | 生成物                        | 差分（今） | 差分（そろえない） | 大きさ（字数。今 → そろえない） |
| ---- | ----------------------------- | ---------- | ------------------ | ------------------------------- |
| #675 | `plan/residuals.md`           | 7,014 行   | 24 行              | 1,073 万字 → 95 万字            |
| #639 | `plan/captures/recordings.md` | 1,022 行   | 12 行              | 69 万字 → 21 万字               |
| #627 | `plan/captures/recordings.md` | 1,008 行   | 2 行               | 68 万字 → 21 万字               |
| #689 | `plan/residuals.md`           | 85 行      | 85 行              | 1,191 万字 → 104 万字           |

- 列幅で膨らんだ差分は、足した行・変わった行だけに縮む。中身の変化の差分（#689 など）は変わらない。
- 字数は `plan/residuals.md` で約 1/11、`plan/captures/recordings.md` で約 1/3 になる。

## 5. 推奨と論点

### 論点 1: どの案にするか

**推奨: A**。前例（`plan/skill-catalog.md`。列をそろえると 2 倍の大きさになるので整形しない）と同じ扱いにする。

- 生成のコードは今も列をそろえずに書いているので、生成の形は変えない。prettier をかけるのをやめるだけ。
- 読む側の見た目は、GitHub とエディタのプレビューでは変わらない。生の文字で列が並ばなくなるのは、今の 2,400 字の行でも並びが読めないので、失うものは小さい。
- B・D は差分の膨らみを狭めるだけで無くせない。C は 1 件 1 行の引き方を失う。E は行数を減らさず、中身の変化まで畳む。

### 論点 2: 最新かの検査を厳しくするか

**推奨: 厳しくする**。今の `npm test` は、2 つの生成物を列幅と区切り行を落として比べている（`normalizeTable`・`normalizeGeneratedDoc`。prettier の整形の違いを許すため）。prettier をかけなくなれば、生成の結果と 1 字まで一致を見られる（ほかの 4 つの生成物と同じ `toBe`）。手で列をそろえ直したり、エディタの整形が走ったりしたら `npm test` が落ち、作り直しの手順（`records:check`・`records:table`）に戻れる。

## 6. 実装

- `.prettierignore` に `plan/residuals.md` と `plan/captures/recordings.md` を、理由のコメントつきで足す。
- `package.json` の `records:check`・`records:table` の `format-retry.ts` の引数から 2 つを外す（渡しても prettier は対象外のファイルを読まないが、整える物の一覧を正しくする）。
- `npm test` の 2 つの検査を `toBe` にする（論点 2）。
- 2 つの生成物を作り直し、表の行の集合（セルの前後の空白と区切り行・空行を落とした形）が作り直しの前と同じことを確かめる。
- 観測値を 1 件足したときの差分が、足した行の周りだけに収まることを確かめる（足した観測値はコミットしない）。

## 7. 実装の結果（2026-10-25）

- 6 節のとおりに変えた。`normalizeTable`・`normalizeGeneratedDoc` は使う所が無くなったので消した。
- 作り直しの前後で、2 つの生成物の行（セルの前後の空白と区切り行・空行を落とした形）は、並びまで同じだった。
- ファイルの大きさ（バイト）は、`plan/residuals.md` が約 12.8MB → 1.9MB、`plan/captures/recordings.md` が約 1.0MB → 0.43MB になった。
- 長い説明（今のどのセルよりも長い）を持つ観測値を 1 件足して `records:check` を回すと、`plan/residuals.md` の差分は件数の見出しの 1 行と、足した 1 行だけだった（足した観測値はコミットしていない）。
