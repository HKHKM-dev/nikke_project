# V-0060: クルミが命中のハッキングの付いている最中にバーストを使うと、tick の刻みと終わりはどうなるか

- 問い: 命中で付くハッキングが付いている最中にクルミがバーストを使うと（バースト使用時のハッキングが同じハッキングとして付く。C-0136）、tick の刻みは命中のハッキングのまま続き、終わりがバーストから 5 秒まで延びるか（C-0137）
- 話題: スキル・キャラ固有
- 日付: 2026-10-01
- Stage: キャラの定義（plan/design-kurumi.md 2.2 節）
- 録画: `100`
- 結論: `C-0146`、`C-0147`
- 状態: 完了
- 派生元: `V-0054`

## 条件

- **編成**: クルミ（862）単騎・操作。
- **設定**: 射撃場・灼熱タブ・BigArms・3 分モード・スペック固定 ON・AUTO 射撃 OFF・オートバースト OFF。バーストは手で使う。
- **撃ち方**（繰り返す）:
  1. ゲージが満タンになるまで撃つ。
  2. 満タンになっても止めずに、さらに 5 秒以上撃ち続ける（命中のハッキングが確かに付いたままにする。36 回の命中は撃ち続けると約 3〜4 秒ごと）。
  3. 撃ち続けたままバーストを使い、使ったらすぐ撃つのをやめる（V-0054 の Y との違い。バーストの後に命中で付き直さないので、終わりまで見られる）。
  4. 8 秒以上、撃たずに待つ。
- 的のジャンプの前 8 秒ほどはバーストを使わない（ジャンプの頃に tick の列が切れることがある。V-0051）。
- 見込みは 180 秒で 4〜5 回。

## 予測（撮る前に書く）

撮る前（2026-09-30）に会話でオーナーに示した撮影条件と予測を、録画を読む前（2026-10-01）にここへ写した。

バーストを使ったフレームを B とする。値は V-0054 と同じ（tick 41,322・会心 61,984。B の後 10 秒は受けるダメージ▲で × 1.1806 の 48,785・73,178。C-0138）。

| 仮説                                                     | B の後の tick                                                                              |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| H1: C-0137 ＋ 延長（**モデル**。C-0129・C-0133・C-0136） | 命中のハッキングの刻みのまま続き、B から 5 秒以内（5 秒ちょうどを含む）に 5 回出て終わる   |
| H2: バーストで刻みを数え直す                             | B の 1・2・3・4・5 秒後の 5 回（命中のハッキングの刻みとずれる）                           |
| H3: 付いている最中のバーストは何もしない                 | 命中のハッキングの刻みのまま、最後に命中で付いてから 5 秒で終わる。B の後は 5 回より少ない |

- H1 と H2 は、B の後の最初の tick が命中のハッキングの刻み（B の前の最後の tick + 59f）か、B の約 1 秒後（57〜59f）かで分ける。B の前の最後の tick と B がほぼ同じ時刻だと、2 つの刻みが重なって見分けられない。
- H1 と H3 は、B の後の tick の数（5 か、それより少ないか）で分ける。最後に命中で付いたのが B の直前だと、H3 でも 5 回に近くなる。
- **外れたときの影響**
  - H1 なら: いまのモデルのまま。C-0137 を確定にする候補になる。
  - H2 なら: 同じ status の発火で刻みを数え直す扱いに `dotTickFrames` を直す（命中のハッキングの付き直し（C-0129）とは違う扱いになる）。
  - H3 なら: 付いている最中のバーストは、付き直しにも数えない扱いにする。

## 読み方

- 戦闘開始は、`timer.ts --mode changes` の +89f の変わり目（C-0078）。
- B は、`gauge.ts --mode events` の、満タンの後に一瞬溜まって消える動きの満タンのフレーム（録画 085・095 と同じ）。
- `hud.ts --mode jumps` の増分を、クルミの 1 発（8 通りと、その × 1.1806）と tick（41,322・61,984 と、その × 1.1806）の組み合わせに分ける（V-0054 と同じ）。
- 命中を戦闘開始から数え、36 の倍数の命中のフレームを命中のハッキングの付いたフレームとする。
- B ごとに、次を並べる。
  - B の前の最後の tick と、最後に命中で付いたフレーム。
  - B の後の tick のフレーム・数・最後の tick までのフレーム数。
- 読んだ値は観測値にする（`source` に `V-0060`）。

## 結果

- 録画 100（2026-10-01 撮影）。
  - 戦闘履歴で、クルミ単騎・Lv.400・交戦時間 03:00 を確かめた。
  - AUTO 射撃・オートバーストとも OFF。戦闘開始は f478。
  - HUD の最後の値は、戦闘履歴の与ダメージと一致。
  - 録画の番号は、E: で別の作業の 098・099 と重なったので 100 にした。
- バーストは 4 回（B = f2371・4695・6947・9185）。
  - どれも撃ち続けたまま使っていて、最後に命中で付いたのは B の 56・41・33・25f 前。
  - 使った後も 0.1〜1.8 秒ほど撃っていた（B の後の発は 22・4・6・5 発）。
- **刻みは命中のハッキングのまま**（`100-01`）。
  - B = f2371・4695・9185 の 3 回で、B の後の最初の tick は 8・16・31f 後。B の前の刻みの続き（7・14・29f）と ±2f で合い、B の約 1 秒後（57f 前後）ではない。
  - B = f6947 は 2 つの刻みが重なって見分けられない。
- **B の後の tick は 4 回とも 5 回で、最後の tick は 5 秒以内**（`100-02`。244・251・293・266f 後）。
- **終わりが B から延びた回**（`100-03`）
  - B = f6947 は、最後に命中で付いてから 5 秒なら B の 262f 後で終わる。実際は 293f 後にも tick が出た。
  - ほかの 3 回は、最後に命中で付いたのが B に近く、延びるかを見分けられない（B = f2371 の 244f 後は、命中で付いてから 300f 後で、命中の数の誤差の範囲）。

## 分かったこと・分からないこと

- **H2（バーストで刻みを数え直す）は外れ**。
  - 刻みは命中のハッキングのまま続く。録画 095 の 1 回と合わせて 4 回。
  - C-0137 を 2 つに分け、刻みの部分を **C-0146（確定・反復実測）** にした。
- **H3（付いている最中のバーストは何もしない）は、1 回（B = f6947）で外れ**。
  - 終わりの部分は **C-0147（仮説・単独実測）** にした。4 回とも H1（モデル）と合う。
- C-0137 は棄却にし、C-0146・C-0147 に置き換えた。
- モデルはもともと H1 の形なので、変えていない。
- **分からないこと**
  - 終わりが B から延びることの 2 回目以降の確かめ。
    - 最後に命中で付いてから B まで 1 秒以上空けると、見分けやすい。
    - 撃ち続けて満タンにした後、1 秒ほど撃つのを止めてからバーストを使う。
