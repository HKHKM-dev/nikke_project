## 2. 語彙

### 2.1 stat `projectileExplosionDamage`（発射体爆発ダメージ▲）

- `BuffStat` に足す。値は ratio。`passive`・`timed` に書ける。
- **どのヒットに掛かるか**（モデルの既定。実測で確かめる。4 節）: 発射体の爆発を持つ武器（`shot.projectile.explosionRange > 0`。RL）の通常攻撃のヒット。1 発の 2 ヒット目（C-0197）にも掛ける。射撃ごとの倍率ダメージ（S1 の追加ダメージ）・倍率ダメージ・自動攻撃には掛けない（掛かるかは 4 節で見る）。
- **式の中の置き場所**は実測で決める。次の 3 つを見分ける（どれも 1 つの定数の切り替えで、根拠の結論の ID を添える）。

| 仮説 | 式                                                               | 根拠の見込み                                       |
| ---- | ---------------------------------------------------------------- | -------------------------------------------------- |
| E1   | 攻撃ダメージ▲と同じ枠: (1 + Σ攻撃ダメージ + Σ発射体爆発ダメージ) | 説明文の言い回しが「攻撃ダメージ▲」と同じ形        |
| E2   | 別の乗数: (1 + Σ攻撃ダメージ) × (1 + Σ発射体爆発ダメージ)        | 受けるダメージ▲（C-0138）・分配ダメージ▲と同じ扱い |
| E0   | RL の通常攻撃には掛からない（粘着弾などの爆発のヒットだけ）      | レッドフード（16）の S2 の「発射体爆発ダメージ」   |

- アニス：スターのフルバーストの 1 ヒットでは、S2 と バーストの攻撃ダメージ▲が重なるので、3 つの仮説の値は互いに 2 割以上離れる（4.1 節の 1）。
- **対象「自分と、自分より最終防御力が低い味方全体」**: `allies` と書き、`assumes` に「味方全員の最終防御力が自分より低いとみなす」と書く（論点 2）。
  - アニス：スターは Defender で防御力の成長が大きく、S2 の発火（フルバーストの入り）の時点では自分のバーストの防御力▲が乗っている（I を撃った直後）。
  - この stat が効くのは RL の味方だけなので、比べが結果を変えるのは「アニス：スターより最終防御力が高い RL の味方」がいる編成だけ。モデルは味方の最終防御力（装備・OL・防御力のバフ）を持たない。
- エマ：TU（93）・ウンファ：TU（95）ほかの notes の「発射体爆発ダメージは未対応」は、この stat で書けるようになる。この設計の範囲はアニス：スターだけ（それぞれの定義を次に触るときに書く）。

### 2.2 効果 `autoAttack`（周期の自動攻撃）

「機能：…自動攻撃する／ダメージ：最終攻撃力の X%／攻撃間隔：N 秒／維持時間：Y 秒」の形。ベスティー（91）のバーストのミサイルコンテナも同じ形なので、名前は特定のキャラに寄せない。

```json
{
  "kind": "autoAttack",
  "trigger": "burstUse",
  "ref": 1,
  "intervalSeconds": 0.25,
  "durationRef": 2,
  "firstTick": "afterInterval",
  "gaugePerHit": true
}
```

- 1 ヒットの式は `damage`・`dot` と同じ倍率ダメージ（会心の期待値・フルバースト補正 +0.5・攻撃ダメージ▲・受けるダメージ▲・属性。コアなし）。刻みは `dot` の `dotTickFrames` を使い回す（`firstTick` の意味も `dot` と同じ）。
- `gaugePerHit`: ヒットごとに射手の `target_burst_energy_pershot`（フルチャージ倍率なし）をヒットのフレームに足す（`dot` の `gaugeOnTick` と同じ量。C-0181・C-0196）。
- 対象は敵 1 体の前提（「ランダムな対象」はすべてその敵に当たる）。`assumes` に書く。
- **`dot` をそのまま使わない理由**: 説明文に「持続ダメージ」と書かれておらず、画面のラベル（持続ダメージ）が実態と違う。後で「持続ダメージ▲」の stat を足したときに、誤って掛かる。内部では `dot` と同じ道（解決・刻み・calc）に流し、種類だけを分ける（論点 3）。

### 2.3 stat `fixedChargeTime`（チャージ時間 N 秒に固定）

- 射撃に効く stat（`FIRING_STATS`）に足す。`timed` だけに書け、値は秒（ref の値を 100 で割らない。`scaling` は書かない）。
- 効いている窓のあいだ、`firingParams` の `chargeFrames` を `chargeSecondsToFrames(N)` に置き換える。チャージ速度▲（`chargeSpeed`・`casterChargeTime`）は無視する（「固定」の読み）。チャージの後の解放の分は変えない。
- 同じ枠に 2 つの固定が重なる定義は今は無いので、重なりは検証で弾く。
- 同じ言い回しは、ドレイク：グレイトヴィラン（104）・ナユタ（223）・ギルティ：マイティバニー（404）・シン：スウィフトバニー（405）・シンデレラ：クリスタルウェーブ（515）にもある。

### 2.4 爆発範囲▲（実測で決める）

- 1 発で胴体が 2 ヒットする割合（C-0197。表の `HomingProjectile:100:750` の行）が、バースト中に変わるかを先に読む（4.1 節の 3）。
- **変わらない**なら、notes に「ダメージに関係しない」と書き、結論を作る。
- **変わる**なら、stat `explosionRange`（ratio。`timed`）を足し、的の表のキーを実効の範囲（750 × (1 + Σ)。今回は 1500）で引く。範囲 1500 の行は、バーストの窓の発を数えた割合にする。行が無いときは元の範囲の行を引く（範囲 500 の行に落ちない）。
- 爆発範囲▲は、ほかのキャラの説明文にもある（ラプラス・レッドフード・ネオン：ビジョンアイ・ベロータ・パワー・A2・エミリア・ベスティー・ベスティー：TU）。

### 2.5 既存の語彙で書くもの

- S2 の攻撃力▲（`casterAttack`。発動者のバフ前攻撃力 × {01}% の固定加算。自分にも付く）・攻撃ダメージ▲、バーストの攻撃ダメージ▲。`timed` の `squad` は S1 で足した。
- フルバーストが 5 秒のとき（イサベルのバースト）は、S2 の 10 秒の窓がフルバーストの後にも 5 秒残る。

### 4.2 撮影（2 本。予測を固定してから）

- S2 はフルバーストが要る。段階 3 に機構が確定したキャラはいない（design-anis-star-rest.md 3 節。イサベルの未確定はチェーンにも 1 回目のフルバーストの値にも効かない）。

## 5. 実装

1. `skills/types.ts`: `projectileExplosionDamage`・`fixedChargeTime` の stat、`autoAttack` の型と検証（`intervalSeconds` は維持時間以下、`firstTick` は `dot` と同じ値、`gaugePerHit` は真）。単体テスト。
2. `skills/buffs.ts`・`damage.ts`: 発射体爆発ダメージ▲の乗数（定数 `PROJECTILE_EXPLOSION_BUCKET`。爆発を持つ武器の通常攻撃だけ）。`frame/firing.ts`: `fixedChargeTime` の窓で `chargeFrames` を置き換える。
3. `autoAttack` を `dot` の解決（`skills/burstDamage.ts`）と刻み（`frame/plan.ts`）に流す。ゲージは `dotGauges` と同じ列に積む。
4. 退化の確かめ（6 節）→ calc（`calc/model.ts`）→ 画面のラベル（`SkillSection.tsx`）と CLI（`sim-run.ts`）。
5. 2.4 節で範囲が効くと分かったら、`explosionRange` と表の行を足す。
6. テスト: `skills/__tests__/anisStarS2Burst.test.ts`（検証・Lv ごとの値・`squad` の分岐）、編成のテスト（`anisStarTeam.test.ts` に S2・バーストの入った編成で sim と calc の整合）。

## 6. 退化

- 新しい stat と効果を持つ定義はアニス：スターだけ。ほかのキャラの数値は変わらない。
- アニス：スターを含む編成は、与ダメージ（S2 の味方全体のバフ・自動攻撃）とバーストの時刻（ゲージ・発の間隔）の両方が変わる。既存の確定の観測値のうち、録画 162・163 に結び付くもの（`162-02` など）は、照合が通るかを確かめる。通らなければ、その理由（バーストの時刻のずれ）を PR に書く。

## 7. 残るリスク

- E0・E1・E2 のどれでもない（たとえば胴体の 1 ヒット目だけに掛かる）ときは、2.1 節の置き場所を作り直す。
- 自動攻撃の会心・フルバースト補正・攻撃ダメージ▲の掛かり方は、`damage` と同じと置いている。R1 の非会心・会心の 2 つの値と、フルバーストの窓の値（4.1 節の 1）で見る。
- バーストの窓の発の数は少ない（1 回 10 秒）。距離帯によっては 2 ヒットの割合の数が足りず、2.4 節が決まらないことがある。そのときは notes に「未確認」と書き、表は変えない。
- 発射体爆発ダメージ▲の対象の比べ（2.1 節）は確かめない（`assumes`）。
