# 撮影と読み取りの手引き

- 関連: [index.md](index.md)（録画台帳・撮影プロトコル・キャラ同定・解析ツール）、[../verification.md](../verification.md)、[../claims.md](../claims.md)（結論の一覧）
- 位置づけ: 撮影と読み取りで繰り返し効く注意を、話題別に引ける索引。**根拠と数値はリンク先が正**で、ここは 1〜2 行の要約にとどめる。食い違ったらリンク先に合わせてここを直す。
- 足し方: 新しい知見は、まず verification.md（または設計書）に根拠つきで書き、繰り返し効くものだけをここに足す。

## 原則

- 単騎・最小構成で要因を切り分けて測る。多人数の録画は分解しない（[../../AGENTS.md](../../AGENTS.md)「事実と記録」）。
- キャラを候補に挙げるときは、**実装済みで所持しているか**を確かめる。Blablalink のデータにはゲーム未実装のキャラが混ざる（例: シン：スウィフトバニー（405））。所持の一覧はメインのチェックアウトの `private/`。
- 予測と合わない数値が出たら、**まず宝物を疑う**。宝物はスペック固定でも反映され、CDN の roledata には宝物版スキルが無い（[../verification.md](../verification.md)「Stage 8 › 射撃場の実測（録画 36〜38）」、[../design-stage9.md](../design-stage9.md)）。
- 宝物の段階は画面から読まず、オーナーに確かめる。出撃画面のカードの右上の紫のバッジは宝物と関係ない（V-0033）。
- 撮影後は、まず一時停止 / 戦闘履歴のパネルで編成と枠順を確かめ、その編成で予測を出し直す。設計書の古い編成で撮られることがある（[../verification.md](../verification.md)「録画 43」）。
- 単騎の与ダメージの合計は、会心の偏りだけで動く（紅蓮BS 単騎 180 秒で 1σ 約 1.3%）。モデルと比べるときは合計だけでなく、回数（射撃・段）と、会心を期待値に置き換えた合計も見る（V-0001）。
- 同じ武器種の 3 人（SR など）は同じフレームに撃つので、HUD の増分が重なる。会心の有無だけが違う増分どうしの差（会心の 0.5 の分）から 1 発の値を取り出し、候補の値の組み合わせで分ける（V-0033）。
- SR の AUTO 射撃（操作・AI とも）は、的のジャンプの始まりの直後にチャージの途中の発を撃つことがあり、その 1 発はフルチャージの値の組に入らない。HUD の増分を分けるときは、ジャンプの始まりの増分を除いて数える（録画 081 で 5 回のジャンプの 5 件。`081-04`）。

## 動画と道具

- フレーム番号の数え方は [index.md](index.md)「フレーム番号の約束」に従う。フレーム落ちのある録画は時間計測に使わない（index.md「素性」）。
- 録画は AV1。時刻（PTS）は 1/60 秒おきにそろっている（V-0005。以前は VFR と書いていた）。`fps=1/10,tile` の一覧に `%{pts}` で焼いた時刻はずれるので、時刻の判断に使わない。
- **録画は OBS で撮る**（既存の録画も OBS とみられる。録画 46 で確かめた。時刻が 1/60 秒おきにそろい、映像と音声もそろう）。Game Bar は約 24fps で、1 フレームずつの読み取りに使えない。ShadowPlay は使えるが時刻が揺れる（V-0005）。
- **動画のフレームはゲーム内の時間とそろっていない**。ゲーム内の時計（3 分モードの残り時間・フルバーストの残り時間）の 1 秒は、動画の約 58.82〜58.84f（60f ではない。撮影日・人数によらない。C-0048）。スキルの持続もこの時計で進む（C-0050）。録画の重複フレーム（`dups.ts`）のあいだもゲーム内の時間は進むので、重複を除かずに数える（C-0051）。フルバーストに入るたびに、III の発動から「FULL BURST!」の表示が消えるまで約 22f、ゲーム内の時間がまるごと止まる（残り時間も CT も進まない。C-0069・C-0070）。フルバーストをまたいで動画のフレームで時間を数えるときは、この分を引く。戦闘開始は残り時間の 02:59 が出たフレーム（V-0002）。読むのは `timer.ts`。`timer.ts --mode changes` の最初の大きな変わり目（+320f 前後）は画面の切り替えで、戦闘開始はその次の +89f の変わり目（表示が出たフレーム。V-0023）
- ffmpeg の drawtext は fontconfig が無いと落ちるので、`fontfile='C:/Windows/Fonts/arial.ttf'` を明示する。コンタクトシートは crop → drawtext(`%{n}`) → select → tile の順で元のフレーム番号を焼き込む。
- robocopy は Git Bash から実行しない（index.md「バックアップ」）。
- 戦闘開始 S（タイマーが出たフレーム）はカメラの切り替えと同じフレームで、照準の横の残弾は S+2、背中からの視点は S+6〜8 に出る。リロード完了は、RELOADING のバーが消えて照準の横の残弾が最大に戻ったフレームで読める（旧の録画は枠アイコンの上の残弾表示が無い）。照準の横の残弾が 1 減ったフレームは、単騎なら総ダメージの増分（`hud.ts --mode jumps`）のフレームと一致した（V-0045）
- RELOADING のバー（1920×1080 で x 760〜1160・y 約 527 の白い線）の長さを全フレーム測ると、リロード完了（バーが消えたフレーム）が 1 回ずつ取れる。バーは最終弾から一定の速さで伸び、SG は段ごとに満ちて空に戻る。総ダメージの増分は、SMG などで最初の発より 1〜3f 遅れることがあるので、最初の発は照準の横の残弾で読む（V-0046）
- HUD の総ダメージの全フレーム OCR は `node tools/captures/hud.ts <動画> --mode final|jumps|series`（Stage 19-D）。0 と 8 の読み違いは、総ダメージが減らないことを使って落とす（[index.md](index.md)「解析ツール」）。
- 旧プロジェクトの録画（`E:/old_nikkecalc/`）も同じ切り出し（`fps=60,crop=190:38:865:34`）で読める。持続ダメージなど 1 発の組み合わせで表せない固定値は、別の項目として分けて数える（verification.md「Stage 18-A」「Stage 18-B › 撮影 1」、index.md「旧プロジェクトの録画」）。

## データの取得

- スキル文の用語（分配ダメージ・フォーカス・デコイ など）の意味は、ゲーム内のツールチップの画像を見る（`E:/nikke_project_captures/reference/tooltips/<用語>.png`、[index.md](index.md)「参照資料」）。未実装キャラのスキルは先行公開の画像（同 `prerelease/`）にあるが、実装時に数値が変わることがある。
- 宝物版スキルは CDN の `/equip/favorite_rare_map.json` と `/equip/{locale}/favorite_{id}.json`（[../design-stage9.md](../design-stage9.md) 0.1 節）。
- 装備・キューブ・コレクションなどのマスタの所在と、CDN に無いもの（OL の Lv 別の数値など）は [../design-stage12.md](../design-stage12.md) 0.2 節。
- 実ビルドは ShiftyPad の API から取れる（[../design-stage12.md](../design-stage12.md) 11.1 節）。取得したデータは `scratch/` に置き、コミットしない。ShiftyPad のキャラページの攻撃力は、一部のキューブ・コレクションが抜けるので正解値に使えない（verification.md「Stage 12 › 実測」）。
- `burst_duration` はフルバースト時間（[../design-stage8.md](../design-stage8.md) 0.2 節）。
