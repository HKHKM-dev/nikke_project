## 2. A: 最初の発の物のゲージ（C-0243）

### 2.1 量

- 物 1 個 = `burstEnergyPerShot`（キャラデータ。アニス：スターは 14,000）×（操作のチャージ武器ならフルチャージ倍率）×（1 + その枠のゲージ速度）。C-0177 の式で、C-0243 の操作 3.71%・AI 1.48% と同じ値になる。
- 枠のゲージ速度は、ゲージの 1 発（`energyAt`）と同じ値を使う。アニス：スター自身は S1 の ×1.06（C-0198）。味方の分は C-0244〜C-0246（未反映）の影響を受けるが、A の入力を書く録画（2.2 節）は単騎だけ。

### 2.2 入力

- どの発が何個壊すかは、モデルでは決めない。射撃場の障害物の配置と壊れ方の表が無く、C-0177 も AUTO の伸びがどの物に当たった分かを特定していない。**録画の画で数えた個数を入力にする**（的のジャンプの窓 `jumpWindows` と同じ、録画ごとの条件）。
- `TeamInput.obstacleBreaks?: { slotIndex: number; shot: number; count: number }[]`（`shot` はその枠の発の番号、1 始まり）。
- 照合の条件 `CompareSetup.obstacles?: { slot: number; shot: number; count: string }[]`。`count` は個数を持つ観測値の ID（`use: input`）。個数そのものは観測値に置く（1 つの事実は 1 か所）。
- 新しい観測値（V-0157 の「結果」に書いた数え方を観測値に移す。値は V-0157 のとおり）
  - `161-16`: 録画 161 の最初に的のほうへ届いた発で無くなった物の数（柱 2 段）。
  - `181-04`: 録画 181 の同じ数（空に撃った発の後の、最初に的に届いた発）。
- `161-13`・`181-03` の `setup` に `obstacles: [{ slot: 1, shot: 1, count: "161-16" }]`（181 は `181-04`）を足す。録画 181 の空に撃った発はモデルに無いので、モデルの 1 発目が録画の最初の的への発にあたる。
- 既定は空。利用者の計算（`apps/web`）には出さない（射撃場の物は実戦に無い）。

### 2.3 時刻

- その発のゲージと同じフレームに足す（B を入れれば着弾のフレーム）。

### 2.4 入れないもの（未実装として残す）

- 録画で数えずに、どの発が何個壊すかを予測すること（射撃場の障害物の配置と壊れ方の表）。
- AI（録画 150・182）の物の入力。182 は崩れた物を読んだ（`182-03`。V-0193）が、比べる観測値が無いので入力にしていない。150 は読んでいない。
- 多人数（録画 162・163・165）は、最初に柱を壊したアニス：スターの発と個数を読み（`162-22`・`163-13`・`165-22`。V-0169・V-0193）、2026-10-05 から、その録画の比べるすべての観測値の条件（`setup.obstacles`）に入れた（V-0193。物の個数は録画の条件で、1 個の量は C-0283 のため。同じ録画の照合を同じ条件で回す）。1 個の量が多人数でも同じかは C-0284（仮説）。
- 壊れずに爆発だけ当たった物のゲージ（V-0157「分からないこと」）。

### 2.5 結論の扱い

- C-0243 は仮説のまま（推奨）。モデルに入れて `161-13`・`181-03` が許容内に入っても、「柱 = 2 個」の数え方は V-0157 の予測の後に決めた（予測の O の行は撃つ前の数え方で外れた）。確定にするなら、V-0157「次に撮るもの」（柱を別のキャラで先に壊してから、アニス：スターの最初の発が 0px・10 発目で満タン）が要る。
- `model` の欄は「`TeamInput.obstacleBreaks`（録画で数えた個数の入力。既定は空）」にする。
- 2026-10-05: オーナーの指摘で、縦長の柱は 1 個のオブジェクト。最初の発が壊す 2 個は柱と柱の左の樽（V-0183）。C-0243 と C-0263（多人数）は棄却し、C-0278 に置き換えた（仮説）。その後、単騎の操作の C-0283（確定。V-0184 で 181・186 も合った）と、多人数・AI の C-0284（仮説）に分けた。入力の値（`161-16`・`181-04` は 2）は変わらず、`162-22`・`165-22` は 3 から 2 に直した。

## 3. B: 誘導弾の飛ぶ時間（C-0237）

### 3.1 置き方

- 発のゲージ（`energyAt`）と、射撃ごとの倍率ダメージのゲージ（`damage` の `gaugeHits`。S1 の追加ダメージのヒット）を、発射のフレーム `f` ではなく `f + T` に予約する（いまの `pendingGauge`）。`T` は発射のフレームの距離帯の飛ぶ時間。
- 満タン（`gaugeFullFrames`）と I の発動（満タンの 29f 後。C-0236）は `T` だけ遅れる。
- 最初の発の物のゲージ（A）も同じ `f + T` に入れる（爆発は着弾で起きる）。
- 射撃の列（`shots`）・ダメージを置くフレーム・バフの判定は発射のフレームのまま。

### 3.2 飛ぶ時間の値

- 射撃場の的の表（`targetProfiles` の `range-bigarms`）に `flightFrames` を足す。形は `hitsPerShot` と同じ `TargetRateTable`（武器種 → 弾の種類の行 → 着地点の id・帯・all の順で引く）。値はフレーム。
- 行は `RL` の `HomingProjectile:100:750`（C-0197 と同じキー）だけ。値は `161-15`・`164-18` の発の帯ごとの中央値（偶数個は 2 つの平均）。

| 帯     | 中近 | 近  | 中遠 | 遠  |
| ------ | ---- | --- | ---- | --- |
| T（f） | 14   | 8   | 17   | 28  |

- 着地点ごと（近 A・B、中遠 A・B・C）の値は読んでいない。C-0237 の「録画ごとに 2〜3f 違う」は着地点の違いとみているが、遠（着地点は 1 か所）でも 2〜3f 違うので、着地点だけでは説明できない。帯の代表値にとどめ、着地点ごとの読み直しは backlog 2-18 に残す。
- 表に行の無い弾（ほかの RL・SR など）と、的の表の無い敵（実戦）は `T = 0`（いまと同じ）。ほかの RL にも飛ぶ時間はある（guide「RELOADING のバー」）が、測っていないので未実装と注記する。

### 3.3 距離帯の決め方

- 発射のフレームの距離帯は、着地点の時間割り（`landingFrameSpans`。出来事のセットの着地点の列と的のジャンプ）で決める。
- いまは条件が自動の枠だけが着地点を使う（`planLandings` は自動の枠が無ければ null）。飛ぶ時間は条件の決め方（命中率・コアを表で決めるか手で入れるか）に依らず、敵の位置で決まるので、**的の表のある敵なら手入力の枠にも使う**。
- `apps/web` の `enemyForCalc` は、射撃場の敵には条件の決め方に依らず的の表と着地点を付けている。照合の `buildTeamInput` は自動のときだけ付けていたので、web と同じく常に付ける。手入力の枠の命中率・コアは `planLandings` が null を返すので変わらない（実装で全観測値の残差が変わらないことを確かめる）。

### 3.4 変えないもの（未実装として残す）

- ダメージを置くフレームとバフの判定は発射のフレーム。`165-14` の注記（発動に重なる発では、追加ダメージだけにバーストの攻撃ダメージ▲が乗る）は、追加ダメージを着弾で判定している兆しだが、ゲージの時刻とは別の設計にする。
- 的のジャンプの直前に撃ち、狙えない窓の中に着く発のゲージ（溜まるかは確かめていない）。モデルは着弾のフレームに溜める。
- `gaugeFullShotIndex`（撃った発のうち満タンのフレームまでの数）は、`T` が発と発の間（42f 以上）より短いので、着弾で数えるのと同じ値になる。指標は変えない。

### 3.5 フルバーストの終わりを跨ぐ発

- 窓の終わりの `T` フレーム前までに撃った発は、着弾が窓の後になり、ゲージになる。C-0240（チェーンの待ちの明けの後に当たったヒットは溜める）と同じ規則を、フルバーストの終わりにも当てる。
- V-0167（7 節の V-A）で確かめた: 窓の中で撃って窓の後に着いた発は溜まる（窓の終わりの 1f 前に撃った発も。C-0259）。`165-10`・`165-13` の許容外は、録画とモデルで窓の終わりの前後の発の位相（跨ぐ発の有無）がそろわないことで説明できる（後付け）。C-0259 は確定、`165-10`・`165-13` は許容外のまま残す（2026-10-05 のオーナーの判断）。

## 4. C: シューティングスターの飛ぶ時間（C-0240）

### 4.1 置き方

- `autoAttack` の tick のゲージ（`gaugePerHit`）を、刻みのフレーム + `T_ss` に予約する。チェーンの待ちの明け（発動 + 10 秒。最後の刻みと同じフレーム）より後に着いたヒットが、次の回の始めのゲージになる（C-0240）。フルバーストの終わりも 3.5 節と同じ。
- ダメージの tick のフレームは変えない（3.4 節と同じ）。

### 4.2 飛ぶ時間の値

- `164-24` の「明けから最後のヒットまで」は、モデルの最後の刻み（発動 + 10 秒）からの遅れと同じ量。
- `164-24` の回（2〜7 回目）は、その前の窓（1〜6 回目の発動）の終わりの区間で決まる。区間は `164-07` の帯ごとの読めたヒットの数と `164-06` の窓ごとの数を合わせて割り当てた（推論）: 1 回目の窓は中近、2 回目は近、3 回目は的のジャンプの後の遠（`164-06` で途切れた窓。C-0240 が「分からない」とした回）、4 回目は遠、5 回目は遠から中遠、6 回目は中遠。
- 帯ごとの値は誘導弾（3.2 節）と 1〜5f の差でそろう。シューティングスターの弾の種類は分からないので、誘導弾の行を流用せず、的の表の別の行に置く（推奨。論点 5）。

| 帯        | 中近 | 近  | 中遠 | 遠  |
| --------- | ---- | --- | ---- | --- |
| T_ss（f） | 12   | 9   | 17   | 23  |

- 遠は、的のジャンプの重なった 3 回目の窓を除いた 1 回の値（含めても同じ）。中遠は 2 回の平均の切り捨て。
- 行のキーは `autoAttack:17:burst`（resourceId とスロット）。`flightFrames` に `autoAttacks?: Record<string, TargetRateRow | null>` を足す。表に行の無い自動攻撃（ベスティーのミサイルコンテナなど）は 0。
- `162-13` の「最初のヒットは I の表示の約 24f 後」は、刻み（15f）+ 約 9f で、近の値の幅に入る（録画 162 の窓の帯は読んでいない）。

### 4.3 効き

- 明けの後に着くヒットは、刻み（約 15f）より短い `T_ss` で 1 つ、長いと 2 つ。この表なら中近・近で 1、中遠・遠で 2 になり、`164-24` の 1・1・（3 回目は除く）・2・2・2 と合う。
- 単騎では 1 ヒット 2.97% で、満タンの発の数を変えるほどではない（モデルの回ごとの発の数は変わらない。6 節）。多人数ではフルバーストの終わりの後のヒットが増える。

## 5. calc と sim への効き

- A〜C は 1 パス目のゲージ（`runFirstPass`）だけを変える。時刻表（満タン・発動・フルバーストの窓）が変わり、それに乗る与ダメージ（窓の中の発の数・フルバースト補正の乗る範囲）が、sim と calc の両方で同じく変わる。
- 変わる編成は、アニス：スター（B・C の表に行のある弾と自動攻撃）を含み、敵に的の表がある（射撃場）ものだけ。A は入力を書いた照合だけ。
- `apps/web` では、射撃場の敵でアニス：スターを入れると、満タンと発動が飛ぶ時間ぶん遅れる。画面の変更は無い。スキル定義の notes と assumes（S1 の追加ダメージのヒットは「発と同じフレーム」）を「着弾のフレーム（飛ぶ時間は的の表）」に書き直す。

## 9. 論点

1. **A の形**: 推奨は録画で数えた個数の入力（2.2 節）。対案は、3 分モードの出来事のセットに「最初の区間の柱 2 個を、最初に届いた誘導弾の発が壊す」を代表値として置くこと（予測にも効くが、ほかの武器・多人数で壊す発を決める根拠が無く、録画 185 のようにほかのキャラが先に壊す編成を外せない）。
2. **C-0243 の等級**: 推奨は仮説のまま（2.5 節）。
3. **B を入れるか**: 推奨は入れる。満タンが着弾で決まることは確定（C-0236）で、飛ぶ時間は発射と着弾を直に読んだ値。`165-13` が許容外に出るが、AGENTS.md の「根拠のある変更は、乖離が広がっても実施する」に当たる。窓の終わりの扱いは V-A で確かめる。対案は V-A の結果まで B を保留すること（C は B と独立に入れられる）。
4. **T の値**: 推奨は帯ごとの中央値（3.2 節）。対案は録画ごとの値を入力にすること（`jumpWindows` と同じ形。読んだ録画は 161・164 だけで、照合の多い 162・163・165 は読んでいない）。
5. **C の T_ss**: 推奨は誘導弾と別の行に、`164-24` の帯ごとの値を置く（4.2 節。帯の割り当ては推論）。対案は誘導弾の行を流用する（明けの後のヒットの数は同じになる）。
6. **距離帯を手入力の枠にも使う**（3.3 節）: 推奨は使う（web と照合で敵の扱いをそろえる）。
7. **読み直し（7 節）の扱い**: 推奨は、この PR は実装・テスト・照合までにし、V-A・V-B・着地点ごとの読み直しは backlog 2-18 の次の 1 手にする。
8. **`165-09` の照合の範囲**: 推奨は、この PR では範囲を変えず（許容外のまま）、backlog 3 節に「範囲がモデルの窓とずれている」と書く。範囲を直すなら、固定のフレームでなく「n 回目の発動からの窓」で数える指標を足すのがよい（モデルが変わるたびにずれない）が、この設計の外。
