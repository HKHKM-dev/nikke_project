## Context

いまの公開サイト（`apps/calc`）は calc モデル（`team.ts` の `computeTeamDamage`）だけを使い、sim（`sim/engine.ts` の `runSimulation`）は CLI と整合テストからしか呼ばれない。これを **2 つのモデルとして育て、サイトからどちらも使えるようにする**。

2026-09-25 のユーザー決定:

1. **sim が calc より正確になるもの**
   - 状態に依存する機構: **必須**。実戦ではさまざまな要因がダメージを増減させ、期待値モデルでは再現しにくいケースがある。
   - 乱数（ばらつき）: **将来必要**。期待値だけでなく、どれだけばらつくかを出す。
   - 内訳の表示: あれば良い程度。ただし、ダメージに絡む出来事（バリア・無敵・画面外への移動など）は可視化する。
2. **アプリ**: 当面は 1 つのアプリで calc / sim を切り替える。開発に余力ができたら 2 つのアプリに分ける。
3. **名前**: モデルとアプリを 1 対 1 に揃え、「calc = calc モデルとそのアプリ」「sim = sim モデルとそのアプリ」とする。

## 1. 2 つのモデルの役割

|                        | calc                                                     | sim                                                                      |
| ---------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------ |
| 位置づけ               | すぐ結果が出る期待値モデル。入力を変えるたびに再計算する | 正確さを優先するフレーム逐次モデル（実行のきっかけは 7 節 6）            |
| 実行                   | 乱数なしで 1 回                                          | 乱数なしで 1 回（期待値モード）、または乱数ありで N 回（分布モード）     |
| 合計の出し方           | 区間ごとの期待値                                         | 1 発ごと                                                                 |
| 決定論的な状態         | 共通のフレームループで扱う（sim と同じ）                 | 同左                                                                     |
| 乱数の結果で変わる状態 | 扱わない（未対応・近似の一覧に出す）                     | 扱う（会心・コア命中・命中が起点のトリガーやスタックなど）               |
| 出力                   | 合計・枠別・区間別の内訳                                 | calc と同じ内訳 ＋ 分布（平均・標準偏差・分位点）＋ 出来事のタイムライン |

**芯になる原則**:

- **式・スキル定義・データ・フレームループは 1 つだけ持つ。** 2 つのモデルで違うのは「乱数を振るか」と「区間でまとめるか・1 発ずつ足すか」だけにする。機構を 2 か所に書くと、どちらかが古くなるため。
- **決定論的な状態依存（敵の出来事、経緯で変わるスキル）は共通のフレームループに入れる。** その結果、calc にも効く。calc に入らないのは、乱数の結果に依存する状態だけ。
- **sim の期待値モードと calc の差は、発射サイクルの離散化だけに保つ。** これを今の `simCalc.test.ts` と同じく回帰テストの軸にする。乱数ありの N 回の平均も、期待値モードに収束することをテストする。

```

  damage.ts, stats.ts, skills/, burst/ …   共通（今のまま）
  frame/     共通のフレームループ（今の sim/firstPass.ts・shooter.ts・firing.ts・shots.ts と team.ts の planTeamRun など）
```

- シードを指定できる乱数で、会心・コア命中・命中を 1 発ごとに判定する（同じシードなら同じ結果）。

## 6. 用語（承認後に AGENTS.md に書く）

- **calc**: 区間期待値のモデルと、その結果を出すアプリ（今は `apps/web` の calc 表示）。
- **sim**: フレーム逐次のモデルと、その結果を出すアプリ（今は `apps/web` の sim 表示）。
- **共通のフレームループ**: 両モデルが使う 1 パス目（`core/src/frame/`）。

---

## 7. 決めてほしいこと

1. **アプリ 1 つの間のディレクトリ名** — 推奨: **`apps/web`**。`apps/calc` のままだと、sim の画面も入るので名前がまた重なる。
2. **共通のフレームループの置き場** — 推奨: **`core/src/frame/`**。`sim/` の下に置いたままだと「calc が sim を使う」形になり、1 対 1 の名前と合わない。
3. **sim のエンジンの持ち方** — 推奨: **共通のフレームループにオプション（乱数・1 発ごとの記録）を足す**。sim 専用のエンジンを別に書く案は、機構を 2 か所に書くことになるので採らない。
4. **敵の出来事を calc にも効かせるか** — 推奨: **効かせる**（共通のフレームループで扱うため自然に効く）。calc は「すぐ出るが粗い」ではなく「すぐ出る期待値」で、決定論的なものは正確に扱う。
5. **段の順番** — 推奨: **16-A → 16-B → 16-C**（状態依存が必須、乱数は将来、というユーザー決定の順）。
6. **sim の実行のきっかけ** — 推奨: **16-A・16-B では calc と同じく入力のたびに自動で再計算、16-C の分布モードだけボタンで実行**。
7. **Stage 番号** — 推奨: **Stage 16**。Stage 15 の撮影（15-B 迎撃戦など）とは独立しているので、並行して進めてよい。

## 8. 16-A の実装（2026-09-25）

2 節の構成どおりに分けた。設計からの差分と、決めたことは次のとおり。

- **結果の型は `team.ts` に置いた。** `TeamResult`・`TeamSlotResult` などは calc と sim の両方が作る（下の `simTeamResult`）ので、calc の中ではなく共通の型にした。結果に添える `treasureOf`・`skillSupportOf` も同じ理由で `team.ts` に移した。
- **1 パス目は `frame/plan.ts`**（`planTeamRun`・`planSkillHits`・`burstSnapshotState` など）。フレームループの部品（`firstPass.ts`・`shooter.ts`・`firing.ts`・`shots.ts`）は `sim/` から `frame/` に移した。`sim/` に残るのは `engine.ts`（2 パス目）と `teamResult.ts` だけ。
- **画面は sim の結果も `TeamResult` の形で受ける。** `sim/teamResult.ts` の `simTeamResult` が、sim の区間を calc と同じグループに集計する（トリガー数は sim が撃った数で `triggerSource: 'shots'`）。そのために sim の結果にバーストスキルの発動ごとの内訳（`burst.hits`）と倍率ダメージの発動列（`skillHits`）を足した。値は 1 パス目のものなので calc と同じ。
- **計算モデルの選択欄は「編成の内訳」の先頭に置いた。** sim を選ぶと、合計と枠ごとに「calc との差」を並べる。選択は閲覧者ごとの好みなので、編成の保存形式には入れず別のキー（`nikke-web.model`）に置く。編成の保存キー `nikke-calc.team.v1` は、保存済みの編成を読めるように変えない。
- sim は 7 節 6 のとおり入力のたびに自動で回す（ブラウザでも数十 ms）。
- `.claude/launch.json` の開発サーバの名前も `web` にした。

### 9.0.1 承認時にユーザーから（2026-09-26）

- 撃てない期間は、**敵が画面外へジャンプする**ため。ジャンプには移動を伴い、**着地後は敵との距離が変わる**。
- 敵がジャンプのモーションに入ってから移動が終わるまで、**AUTO の射撃は中断**される（撮影は AUTO なので全員が止まる）。**ジャンプ中はオートバーストも発動しない**ので、バーストの発動がずれる原因にもなる。
- 攻撃できる敵がいないと**ハイド**（遮蔽物に隠れる）する。ハイド中は可能ならリロードするので、**リロード時間が一定以内なら、ジャンプのたびにリロードが終わる**。リロードが長いキャラは、終わる前に敵のジャンプが終わって撃ち始めるので、**リロードは終わらない**。

録画 41 のクラウンの残弾で裏が取れた: 停止中に込め直した 2 回（残弾 227・81 → 300）はリロード速度▲の中で、込め直しに約 95f（素の 2.5 秒 = 150f が約 37% 縮んだ値）。込め直さなかった 3 回は素のリロード（150f）で、2 秒の窓に収まらない。

### 9.1 最初に入れる出来事

**射撃場 3 分モードの的の停止**を、敵の出来事の最初の 1 つにする。

- 材料があり、単騎で撮れる（撮影場所が射撃場なので、いつでも撮り直せる）。
- 検証済みの録画（41・45〜50）の残差のうち、いちばん大きい既知の分を説明できる。
- ボスの出来事と仕組み（狙えない区間）は同じなので、あとでボスのプリセットに同じ型で足せる。

### 9.2 型

```ts
// core/src/enemies.ts（仮）
type EnemyEventKind = 'untargetable' | 'invulnerable' | 'barrier';
type EnemyEvent = { kind: EnemyEventKind; start: number; end: number }; // 秒。[start, end)
```

| 種類           | 意味                                           | 16-B での扱い                                                      |
| -------------- | ---------------------------------------------- | ------------------------------------------------------------------ |
| `untargetable` | 狙えない（射撃場の的の停止・ジャンプ・画面外） | **実装**。9.3 の挙動（確定したものだけ）                           |
| `invulnerable` | 撃てるがダメージが通らない                     | 型とタイムラインの表示だけ。数値には効かせず「未実装」の注記を出す |
| `barrier`      | ダメージを吸う盾（量がある）                   | 同上。量（HP）を持つ形は、バリアのあるボスを撮るときに決める       |

- `TeamInput.enemy`（`EnemyInput`）に `events?: EnemyEvent[]` を足す。省略・空なら**今と 1 フレームも違わない**（全テストがそのまま通る）ことを完了条件の 1 つにする。
- プリセット（`data/enemies.json`）には周期で書く: `{ kind, first, duration, every?: [間隔…], until? }` を秒で持ち、読み込み時に `EnemyEvent[]` に展開する。射撃場の 5 属性で同じなので、トップレベルの `eventSets` に 1 回だけ書き、プリセットは id で参照する。

### 9.3 狙えない間の挙動と、その決め方

共通のフレームループ（`frame/firstPass.ts`・`frame/shooter.ts`）に入れる。**calc と sim の両方に効く**（7 節 4）。

| 項目                          | いまの材料                                   | 決め方                                                   |
| ----------------------------- | -------------------------------------------- | -------------------------------------------------------- |
| 射撃                          | 全員撃たない（録画 41）                      | **確定**。窓の間、射手は撃たない（残弾・位相は止まる）   |
| MG のスピンアップ             | やり直す（録画 41）                          | **確定**。`rateOfFireResetTime` 以上撃たなければ最初から |
| 停止中のリロード（AI）        | 5 回中 2 回（規則不明）                      | 既存の録画 45（MG 単騎）・46（RL 単騎）で読む            |
| チャージ武器（SR・RL）        | なし                                         | 既存の録画 46（RL 単騎）・47（SR+SR+RL）で読む           |
| ゲージ                        | 撃たないので溜まらない（自然にそうなる）     | 仕組みから確定（射撃起点のゲージしか無い）               |
| バーストの発動・FB の時間・CT | なし                                         | 既存の録画 47・49・50 で、停止と FB が重なった回を探す   |

```
  damage.ts              1 発分の式。期待値の式を「判定の結果を受けて 1 発の値を出す式」の特別な場合として書き直す
  skills/burstDamage.ts  同じく、倍率ダメージ・バーストスキルの 1 発動の値
  frame/                 共通のフレームループ。オプション random を受けたときだけ命中を振り、射撃の列に記録する
  sim/engine.ts          2 パス目。random があれば 1 ヒットごとに会心・コアを振って足す
  sim/distribution.ts    N 回の実行と要約（平均・標準偏差・分位点）
apps/web/src/simWorker.ts  Web Worker（distribution.ts を呼ぶだけ）
```

1. **乱数はカウンタ方式にする**（`random.ts`）。

   ```ts
   export type RandomOptions = { seed: number }; // 32 bit の整数
   export type RollKind = 'hit' | 'core' | 'crit' | 'perShotCrit' | 'skillCrit' | 'burstCrit';
   /** [0, 1) の一様乱数。同じ引数なら必ず同じ値（整数演算だけで作るので Node とブラウザで同じ） */
   export function roll(seed: number, kind: RollKind, slot: number, index: number, sub?: number): number;
   /** N 回のうち run 回目のシード（run 回目だけを取り出して再現できる） */
   export function runSeed(seed: number, run: number): number;
   ```

   `index` は枠ごとの射撃の通し番号（バーストスキル・倍率ダメージなら発動の通し番号）、`sub` はペレット・効果の番号。**乱数を順番に取り出す形（ストリーム）にしない**のは、(a) 1 パス目を使い回すときと丸ごと回し直すときで結果を同じにするため、(b) ループの処理順を直しても結果が変わらないようにするため。

2. **1 発分の式は 1 つだけ**（`damage.ts`）。

   ```ts
   /** 1 トリガーの判定の結果。期待値モードでは割合（コア命中率など）、分布モードでは数えた数 ÷ ペレット数 */
   export type ShotOutcome = { hit: number; core: number; crit: number }; // それぞれ 0..1
   /** TriggerDamage の部品から、判定の結果に応じた通常攻撃の 1 トリガーの値を出す */
   export function normalDamageOf(t: TriggerDamage, o: ShotOutcome): number;
   ```

   `computeTriggerDamage` の `normal` は `normalDamageOf(t, { hit: 命中率, core: コア命中率, crit: 会心率 })` で出す（**式の置き場所は今と同じ 1 か所**）。`perShot` とバーストスキルも同じ形にする（`perShotDamageOf`・`skillHitDamageOf`）。期待値モードの数値が 1 つも変わらないことをテストに固定する。

3. **命中の判定は共通のフレームループの中**（7 節 3 の「共通のフレームループにオプションを足す」）。
   - `planTeamRun(input, { random })` の `random` があり、`hitRate` < 1 の枠があるときだけ、射撃のたびに `roll(seed, 'hit', 枠, 射撃の番号)` で当たり外れを決める。外れたらゲージを足さず、`ShotEvent` に `hit: false` を載せる（トリガーの `normalHit` は当たりだけ数え、`normalShot` はすべて数える）。
   - 結果は射撃の列に `ShotLog.misses?: number[]`（外れたフレーム。`lastShotFrames` と同じ部分列の形）として残し、`replayEvents`（バフの区間を作り直す側）もこれを読む。**ループの中とあとの作り直しで判定が食い違わない**（Stage 10 の TriggerTracker と同じ考え方）。
   - calc は `random` を渡さない。calc と sim の期待値モードでは今と 1 フレームも違わない。

4. **会心・コアの判定は 2 パス目**（`sim/engine.ts`）。`SimInput.random?: RandomOptions` があれば、射撃ごとにペレット数だけ `roll(…'core'…)`・`roll(…'crit'…)` を振り、区間の `TriggerDamage` と `normalDamageOf` で 1 発の値を出して足す。外れたトリガー（`misses`）は 0。バーストスキルと倍率ダメージは発動ごとに効果の数だけ振る。
   - 将来、コア命中・会心を起点にする効果を足すときは、同じ `roll` を 1 パス目でも呼ぶ（カウンタ方式なので 2 パス目と同じ判定になる）。16-C では入れない。

5. **N 回の実行**（`sim/distribution.ts`）。

   ```ts
   export type DistributionOptions = { runs: number; seed: number; onProgress?: (done: number) => void };
   export type Summary = {
     mean: number;
     sd: number;
     cv: number;
     min: number;
     max: number;
     quantiles: { p5: number; p25: number; p50: number; p75: number; p95: number };
   };
   export type SimDistribution = {
     runs: number;
     seed: number;
     /** 期待値モードの合計（同じ入力の runSimulation） */
     expected: number;
     /** 1 パス目を 1 回だけ回して使い回したか（乱数が 1 パス目に効かない編成） */
     reusedFirstPass: boolean;
     total: Summary;
     slots: (Summary | null)[];
     /** 回ごとの合計（ヒストグラム用。回の順） */
     totals: number[];
     notes: ModelNote[];
   };
   export function runDistribution(input: TeamInput, options: DistributionOptions): SimDistribution;
   ```

   - **1 パス目が乱数に依存しない編成（命中率がすべて 1）では、1 パス目を 1 回だけ回し、2 パス目だけを N 回回す**。依存する編成では N 回とも丸ごと回す。どちらも同じ `roll` を使うので、使い回しても結果は同じ（テストで固定する）。
   - 標準偏差は標本の不偏分散（N − 1）、分位点は線形補間。

### 10.3 挙動

- **期待値モード（今の sim）**: 変えない。`random` 省略で今と 1 フレームも違わない（全テストがそのまま通る）ことを完了条件の 1 つにする。
- **分布モード**: `runDistribution` を N 回。回ごとのシードは `runSeed(seed, 回)`。
- **退化**: 確率がすべて 0 か 1（会心率 0、コア命中率 0 か 1、命中率 1）なら、分布モードの各回は期待値モードと 1 の位まで一致する。
- **乱数の結果で変わる状態**: 16-C で入るのは、命中率 < 1 のときの「ゲージ」と「`normalHit` の回数」だけ。これらはバーストの時刻表とバフの区間を変えるので、分布の平均は期待値モードとずれてよい（期待値モードは全弾命中で数える近似）。
- **注記**: 分布モードの結果に、10.1 の「仮定」と「未実装」の行を注記（`approx` / `unsupported`）として出す。命中率 < 1 の枠がある分布モードでは、注記 `hit-rate` の「命中を数えるトリガーは全弾命中のまま」の部分を外す。

### 10.4 画面

- 入力: 回数 N（既定 100、10〜1,000）とシード（既定 1。数値の欄と「別のシード」ボタン）。N・シードは閲覧者の好みなので、編成の保存形式に入れず、`nikke-web.model` と同じく別のキーに置く。
- 実行中は進み具合（回数）と「中止」を出す（中止は Worker を止める）。**入力を変えたら結果を消す**（古い入力の分布を残さない）。結果は保存しない。
- 結果（期待値モードの表の下）:
  - 合計: 平均・標準偏差・CV・5% / 50% / 95% 点・最小 / 最大と、期待値モードとの差（平均 ÷ 期待値 − 1）。
  - 枠ごと: 平均・CV・5% / 95% 点。
  - 合計のヒストグラム（20 本の棒。期待値モードの位置に線）。16-B のタイムラインと同じく SVG の手書き。
  - 注記（10.3）。「分布に入っていないもの（ジャンプの位相・AI の揺れ）」は常に 1 行で出す。

### 10.7 決めてほしいこと

1. **乱数で振るものの範囲** — 推奨: **会心・コア命中・命中（命中率 < 1 のとき）の 3 つだけ**（10.1）。SG のペレットの当たり数・ジャンプの位相・AI の揺れは振らず、「分布に入っていないもの」として注記する。別案は、ジャンプの位相を代表値の前後で一様に振る（9.0 節の約 410f の幅）。何で決まるか分からないものを分布に混ぜることになるので推奨しない。
2. **判定の単位** — 推奨: **1 ヒットごとに独立（SG はペレットごと）**。倍率ダメージ・バーストスキルは「1 発動の効果 1 つにつき 1 回」、`perShot` は通常攻撃と別に判定する。会心のペレットごとの判定は録画 11 で裏付けがあり、ほかは仮定として注記する。
3. **乱数の作り方** — 推奨: **カウンタ方式（シード・判定の種類・枠・番号から作る）**（10.2 の 1）。別案は順番に取り出す擬似乱数（sfc32 など）。こちらは 1 パス目を使い回す経路と丸ごと回す経路で結果が変わり、処理順の変更でも変わる。
4. **命中率 < 1 を振って、状態（ゲージ・`normalHit` の回数）まで変えるか** — 推奨: **変える**（3 節の「乱数の結果で変わる状態は sim だけに入れる」の最初の例）。この場合だけ N 回とも 1 パス目から回す（15-A の編成で N = 100 が Node で約 4 秒）。別案は、16-C では命中は期待値のまま（ダメージに命中率を掛けるだけ）にし、会心・コアだけ振る。
5. **確率・コア命中・会心を起点にする効果の語彙** — 推奨: **16-C では足さない**（定義済みの 15 体に無い。10.0.2）。命中の結果を `ShotEvent` に載せ、コア・会心も同じ `roll` を 1 パス目から呼べる形にするところまでにして、使うキャラの定義を書くときに足す。
6. **検証の基準** — 推奨: **退化（誤差 0）・再現性・収束（±4 標準誤差）を自動テストにし、実機の反復との比較は記録だけ**（10.6）。単騎の反復の撮影は完了条件に入れない。別案は、SR 単騎の反復（5 回）を撮ってから完了にする。
7. **画面の既定** — 推奨: **N = 100・シード 1（入力と「別のシード」ボタン）、Worker 1 本、結果は合計と枠ごとの要約＋合計のヒストグラム**（10.4）。別案は、枠ごとのヒストグラムや、1 秒ごとのダメージの分位点の帯（タイムラインに重ねる）も出す。
