## 2. 語彙

### 2.1 吸収回復 `lifesteal`（新しい kind。V-0022 の後に取り下げ）

**意味**: 維持時間の窓のあいだ、対象の枠の通常攻撃が命中するたびに、その枠が回復を受ける（トリガー `healed` の出来事が起きる）。回復量（%）はダメージに関係しないので、表示にだけ使う。

```json
{ "kind": "lifesteal", "trigger": "burstUse", "target": "self", "ref": 4, "durationRef": 5 }
```

- **書ける項目**
  - `trigger`: 文字列のトリガーか、回数トリガー。
  - `target`: `self`・`allies`・`burstUsers`。
  - `targetWeapon`・`targetElement`・`ref`・`durationRef`（または `durationSeconds`）・`assumes`。
- **検証の規則**（`heal` と同じ理由で閉じる）
  - トリガーに `healed` は書けない。回復の連鎖を作らないため。
  - 対象に `topAttack` は書けない。順位が攻撃力▲に依り、攻撃力▲が `healed` に依るので、循環する。
  - 維持時間は必須。
- **回復のフレーム**: 命中の次のフレーム。射撃の回数起点の `heal` と同じ規則で、`skills/heals.ts` の `healFrameOf` を使う。窓の中の命中かどうかは、命中したフレームで見る。
- **命中に数えるもの**: 通常攻撃の命中だけ（`normalHit` と同じ数え方）。倍率ダメージ（`burstDamage`・`damage`）の命中は数えない。いまのモデルには、倍率ダメージの命中という出来事が無いため。これは `assumes` に書く。アスカのバーストには倍率ダメージが無いので、アスカには効かない。
- **`healed` を受ける効果の窓**: 命中ごとに再発火する。いまの規則「同じ効果の再発火は上書き延長（窓の和集合）」（[design-stage6.md](design-stage6.md) 8 節の 2）のままなので、連続した命中の窓は 1 つにまとまる。アスカの S1 は、吸収回復の窓の最後の命中から 25 秒で切れる。
- **HP が満タンのとき**: 回復は適用されたものとみなす。クラウンの S2 と同じ扱いで、録画 41 で確かめてある（[verification.md](verification.md) Stage 11 クラウン節の 3）。吸収回復でも同じかは、録画 063 で間接に確かめる（4 節の H3）。

**実装**。回復の記録を作る 2 段（[design-stage11.md](design-stage11.md) 3.3 節）に、吸収回復を足す。

1. **`planHeals`**（`skills/heals.ts`）
   - 回復の無い出来事の列から、吸収回復の発火を拾い、対象の枠ごとに窓 `[発火, 発火 + 維持)` を作る。
   - 射撃の列（`ShotLog`）のうち、窓の中で命中したものごとに、回復の記録 `{frame: 命中 + 1, sourceSlotIndex, slotIndex}` を足す。
   - 窓は `healed` に依らないので、2 段で閉じるのは変わらない。
2. **1 パス目のループ**（`frame/firstPass.ts`）
   - `heal` と同じ場所で、発火から吸収回復の窓を開く。
   - 対象の枠の命中を見て、次のフレームの `healed` に送る。
   - `planHeals` と同じ規則にし、sim と calc の整合のテストで食い違いを見る。
3. **計算量**: 1 回のバーストの窓で、アスカは約 70 発撃つ（720rpm で撃ち、20 発ごとにリロードを挟む。実装後の予測で 65〜72 発）。回復の記録は 1 本の戦闘で数百件。`healed` の窓は和集合で 1 つにまとまるので、区間は増えない。

**同じ言い回しの他のキャラ**: 全キャラの説明文に、「攻撃ダメージの〜回復」「吸収」は 25 体ある。この語彙で書けるものの例:

- フォルクヴァンのバースト（対象が攻撃力最高の味方 2 機なので、`topAttack` の禁止に当たる。定義するときに別途決める）
- プロダクト23 の S2
- ユニの S2（定義済み。8 節の論点 4）

### 2.2 属性で絞る対象 `targetElement`

`targetWeapon`（「〈武器〉を所持する味方」、Stage 9）の属性版。「〈コード〉コードの味方」を表す。

```json
{
  "kind": "timed",
  "trigger": "fullBurstStart",
  "target": "allies",
  "targetElement": "Fire",
  "stat": "coreDamage",
  "ref": 3,
  "durationRef": 4
}
```

- **書ける場所**: `targetWeapon` を書ける効果（passive・timed・即時効果）と、`lifesteal`。
- **対象**: `target` が `allies`・`burstUsers`・`topAttack` のときだけ（`targetWeapon` と同じ）。
- **両方あるとき**: `targetWeapon` と両方あれば、両方を満たす枠だけ。
- **値**: `Element`（`types.ts`）の 5 つ。

**実装**

- `skills/targets.ts` の `isEffectTarget` と `canEverTarget` の引数を、対象の枠の武器種 `targetSlotWeapon` から、枠のキャラの `{ weaponType, element }` に変える。
  - 省略可能にしないのは、いまと同じ理由（渡し忘れたときに、黙って全員へ掛かるのを防ぐ）。
  - 呼び出し側（timeline・firstPass・heals・ranking ほか）は、キャラを渡すだけの機械的な変更。
- `skills/ranking.ts` の `attackRankFor` の候補も、属性で絞る。

**同じ言い回しの他のキャラ**: 全キャラの説明文に 14 体ある。例: レイ・アルカナ・メアリー：ベイゴッデス・ソーダ。

### 2.3 足さないもの

- **バリア適用状態の条件**（S2 前半）
  - 「自分がバリア適用状態なら」を判定するには、バリアを配る効果（ラムのバースト・フォルクヴァンなど。どれも notes）と、その持続を語彙に持つ必要がある。これはアスカの範囲を超える。
  - S2 前半は notes（未対応）にする。
  - 射撃場の灼熱の敵ではアスカ（灼熱）は有利でないので、仮に発動しても `elementDamage` は数値に効かない（`element.ts` の `elementMultiplier`）。録画 063 の編成にもバリアを配る味方はいない。
- **HP**: 吸収回復の量・HP の割合は持たない（Stage 11 と同じ）。

## 4. 検証（V-0022。録画 063 の読み直し）

- **フレームの換算**: 動画のフレームからゲーム内の秒へは、1 フレーム 0.017 秒（C-0048 のモデル側）に、フルバーストの入りの止まり（C-0069）を足して換算する。

## 6. リスク・留意点

- **命中の次のフレームに回復する規則**は、射撃の回数起点の `heal` からの類推。S1 の窓の終わりが 1 フレームずれても、4 節の見分けには効かない。
- **吸収回復の窓の中の命中の数え方**: 敵のジャンプで狙えないあいだは命中が無く、回復も起きない。バーストの窓がジャンプをまたいだ回は、S1 の終わりが早まる（録画 063 の 3 回目のバースト。旧記録の表で「ジャンプをまたいだ」回）。予測にはそのまま出る。
- **ユニ（160）の S2 の吸収回復**: いまは「防御系でダメージに関係しない」として notes にある。クラウン・アスカのように `healed` を受けるキャラと組むと、実際には効く。直すかは 8 節の論点 4。
- **HP を持たない**: 「自分の HP が〜% 未満なら吸収回復」（アリスの S2）のような条件付きは、この語彙でも書けない。

## 7. 申し送り（この設計の外）

- 持続の命中率▲をコア命中率に効かせるなら、ドレイク（101）・モダニア（260）・ノワール（271）の定義にある持続の `hitRate` の数値も動く（8 節の論点 1）。
- バリアの語彙（配る効果・持続・「バリア適用状態なら」）は、ラム・フォルクヴァンを定義するときに決める。
- フォルクヴァンの吸収回復（対象が攻撃力最高の味方 2 機）は、`lifesteal` の `topAttack` の禁止に当たる。定義するときに、順位を回復の前に決めるなどの別の規則が要る。

## 8. 論点（オーナーに決めてもらうこと）

1. **持続の命中率▲をコア命中率に効かせるか**
   - いまのモデルは、常時の▲だけを効かせている（C-0036・C-0037 のモデル側は「持続の▲は未反映」）。
   - **推奨: この PR には入れない**。別の小さな Stage にする。
   - 理由 1: ドレイク・モダニア・ノワールの数値も動く。
   - 理由 2: C-0036 の式 min(1, p ÷ (1 − N)²) は、常時の▲で確かめたもの。持続の▲でも同じかの根拠が要る。N ≥ 1 で 1 になること（C-0037）はアスカの録画 063 が根拠なので、アスカについては根拠がある。
   - 入れない場合、アスカのバーストは `partial` にし、合計ダメージはバースト中に少なめに出る（4 節）。
2. **吸収回復を新しい kind にするか**
   - **推奨: 新しい kind `lifesteal`**。`heal` は 1 回の回復で、吸収回復は窓のあいだ命中ごとに回復するので、意味が違う。
   - 代わりの案: `heal` に `durationRef` を足して「窓のあいだ命中ごと」と読ませる。定義は短くなるが、`heal` の意味が 2 通りになる。
3. **S2 前半（バリア条件）を notes の未対応にするか**
   - **推奨: notes にする**（2.3 節）。射撃場の灼熱の敵では、発動しても数値に効かない。
4. **ユニ（160）の S2 の吸収回復を、この PR で `lifesteal` にするか**
   - **推奨: しない**。手順書 0 節「既存の定義は次に触るときに直す」のとおり、roadmap の今後の課題に起票する。
   - ただしユニは、クラウン・アスカと組むと S1・S2 の発動が増えるので、主力の編成で使うなら早めに直す。
