# V-0317: 持続ダメージの tick は、起点から k 間隔に達した最初のフレーム（ceil）か、四捨五入か（録画 122 の後半の読み直し）

- 問い: 持続ダメージの k 回目の tick は、起点（付いたフレーム）から k × 間隔のゲーム内の時刻に達した最初のフレーム（起点 + ceil(k × 間隔 ÷ 0.017)）に出るか、いまのモデル（起点 + round(k × 間隔 ÷ 0.017)）のとおりか
- 話題: スキル・キャラ固有
- 日付: 2026-10-08
- 録画: `122`
- 結論: `C-0454`
- 状態: 完了
- 派生元: `V-0316`

## 条件

- いまのモデル（`frame/dot.ts` の `dotTickTracker`）は、k 回目の tick を、まとまりの起点から `gameSecondsToFrame`（四捨五入）で置く。afterInterval（レイヴン・クルミ）は round((k + 1) × 間隔 ÷ 0.017)、atApplication（ニヒリスター・マナ）は 1 回目を起点に、2 回目以降を round((k + 0.5) ÷ 0.017)。付き直しは刻みを変えない（C-0129）。
- 仮説の出どころ（この記録の前に読めていた列。比べには使わない）:
  - クルミのハッキング `093-03`: 付いたフレームから 59・118・177・236・295f。round なら 59・118・176・235・294f、ceil なら 59・118・177・236・295f。
  - レイヴンの S1 `122-07`（起点 f842 = 最初の tick の 59f 前）: 起点から 59・118・177・236・295・353・412・471・530・589・648・706・765・824f の 14 回で、ceil の列とすべて一致し、round の列（176・235・294・529・588・647）とは 6 回で 1f 違う。
  - マナ（`212-06`・`020-17`〜`020-21`）とニヒリスター（`081-12`）の atApplication の列は、1 回目の tick の 1f 前を起点にすると、2 回目以降が起点 + ceil((k + 0.5) ÷ 0.017) とすべて一致する（V-0316「分かったこと」）。
- C-0432（V-0302）の周期のスキルも「N 秒に達した最初のフレーム」の形（ただし発動のたびに数え直す）。持続ダメージは付き直しで刻みを変えないので、起点からの時刻が積み上がる（端数を持ち越す）とみる。
- 録画 122: レイヴン単騎・AUTO・スペック固定 ON・灼熱の的。S1 の持続ダメージ（1 秒ごと。フルチャージの発を撃った約 6f 後に付く。C-0181）は、フルチャージの発（約 119f ごと）で付き直す。122-07 は 1 回目の満タン（f1666）までの 14 回だけで、その後（約 150 秒分）の tick は読んでいない。
- 最小構成: 単騎。tick の時刻に効くのは、問いの刻み方と、発動と関係しない止まり（C-0262。1 本に数個）だけ。バーストは無い（III のレイヴン単騎）。

## 予測（撮る前に書く）

既存の録画の読み直し。f1666 より後の tick は、この節を commit した後に読む。モデルの指標で刻み方だけを比べる形が無いので、予測ファイルは作らない（予測ファイルによる数値の予測なし）。

| 仮説                    | まとまりの起点 O からの tick         |
| ----------------------- | ------------------------------------ |
| H-C（ceil）             | O + ceil(k × 58.8235)（k = 1, 2, …） |
| H-R（四捨五入。モデル） | O + round(k × 58.8235)               |

- 起点 O: 持続ダメージが切れずに続くまとまりは、122-07 と同じ f842 を起点に数え続ける。tick が 1.5 秒以上途切れたら（的のジャンプの窓などで付き直しが切れたら）新しいまとまりとし、その最初の tick の 59f 前を O とする（k = 1 の 59f はどちらの仮説でも同じ）。
- 見分け方: tick ごとに、H-C の列からの残差 r = 実測 − (O + ceil(k × 58.8235)) を並べる。H-C なら r は 0 のまま続き、発動と関係しない止まりの所でだけ 1 段上がる（以後その値で続く）。H-R なら、round と ceil の違う k（およそ半分）で r が −1 になり、0 と −1 が混ざる。
- 外れたときの影響:
  - H-C なら: 持続ダメージの tick の置き方を ceil にする変更をオーナーに提案する（`dot.ts` の `gameSecondsToFrame` を ceil の形にする。atApplication は起点を 1 回目の tick の 1f 前と読む形も含めて）。与ダメージの効きは、窓の端をまたぐ tick の 1f だけ。
  - H-R なら: 122-07 の一致は偶然とみて、モデルは変えない。

## 読み方

1. HUD の増分（`hud.ts --mode jumps`）から、レイヴンの S1 の tick を取る: 1 スタック 82,012.3（会心は 4 / 3 倍）の整数倍の増分（122-08 と同じ）。フルチャージの発のヒット（367,175・458,968 など）と同じフレームの増分は、発の値を引いて残りが整数倍なら tick とする。
2. まとまりに分け、起点からの k を振り、H-C の列からの残差 r を並べる。
3. 止まりの位置（r の段）を、3 分モードの残り時間の段（V-0302 の読み方）と突き合わせる。
4. 読んだ値は観測値にする（`source` に `V-0317`）。

## 結果

2026-10-08 に、予測の commit（0a5319fa）の後で読んだ。観測値は `122-23`・`122-24`。

- tick は 180 秒で 176 回（増分を 1 スタック 82,012.3 の整数倍（会心は 1.5 倍）と発の値に分けた。分けられなかった増分は 6 つ）。1.5 秒以上途切れた所で、まとまりは 3 つ（起点 f842・2136・5195。21・51・104 tick）。f842 のまとまりの最初の 14 回は `122-07` と同じ。
- ceil の列からの残差 r: f842 のまとまりは k 1〜16 が 0 のまま、k 17 から 1 段上がる（1 つ外れ）。f5195 のまとまりは k 1〜42 が 0（3 つ外れ）、k 43 から 1 段上がって続く（4 つ外れ）。段の所は、発動と関係しない止まり（C-0262）とみる。
- f2136 のまとまり（51 tick）は、r が 0 のまま続くが、6 tick に 1 回ほど 1 tick だけ +1 になる（k = 6・12・17・23・29・34・40・46・51 あたり）。この tick は発と重ならない純粋な tick（10 スタック 820,123）で、HUD の読みの揺れではない。起点を 0.12〜0.17 フレーム後ろにずらした ceil(φ + k × 58.8235) なら、+1 の回も含めて 49/51 が一致する（k × 58.8235 の端数が 0.83 を超える回だけ 1f 遅れる）。
- 区間ごとに φ と段を当てはめた一致は 166/176。四捨五入の列（いまのモデル）は、どの区間でも最良でなく 96/176（3〜4 tick ごとに 0 と 1 が入れ替わる）。
- 予測との比べ: H-C は「r は 0 のまま、止まりでだけ段が上がる」の形で当たり（f2136 のまとまりの 1f の外れは、起点の端数のずれで説明がつく）。H-R は外れた。

## 分かったこと・分からないこと

- **持続ダメージの tick は、起点から k 間隔に達した最初のフレーム（ceil）に出る**（端数は起点からの時刻として持ち越す）→ C-0454（仮説・反復実測）。atApplication（ニヒリスター・マナ）は、1 回目の tick の 1f 前を起点に k + 0.5 秒で同じ形（`081-12`・`212-06`・`020-17`〜）。いまのモデル（四捨五入）は約半分の tick で 1f 遅い（マナの V-0316 の「モデルより 1f 早い tick」と、レイヴン・クルミの 176・235・294f の読みのずれは、これで説明がつく）。
- 周期のスキル（C-0432。発動のたびに数え直す）と同じく「時刻に達した最初のフレーム」の形で、持続ダメージは付き直しで数え直さない（C-0129）ので端数が積み上がる。
- 起点の端数のずれ（f2136 のまとまりで 0.12〜0.17 フレーム）は、ゲーム内の時刻を 0.017 秒ずつ浮動小数で積み上げる誤差とみられる（止まりの無い所の残り時間の 1 秒が 58.8235f より少し長い V-0302 の読みとも合う）が、確かめていない。
- モデルは変えていない。`dot.ts` を ceil の形にするかはオーナーの判断（backlog 4-19）。
- 分からないこと: 起点の端数のずれの出どころと、まとまりごとに違う理由。
