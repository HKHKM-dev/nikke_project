- 問い: 雪子（III）のバーストの倍率ダメージ（分配ダメージ）のヒットは、III の発動から何フレーム遅れるか

## 条件

**何を確かめるか**

- 遅れの表（`packages/core/src/burst/landing.ts` の `MEASURED_BURST_DELAYS`）に雪子（871）の行が無く、バーストの分配ダメージ（C-0351）のヒットは III の発動のフレーム（遅れ 0）として扱われている。ヒットのフレームは観測値（`258-09` など）にあるが、III の発動からの差は読んでいない。
- S1 の 1more の分配ダメージは、バーストのヒットの 46〜48f 後に出る（C-0359）。定義（`data/skills/871.json` の skill1 の `delayFrames`）はいまのモデルでは発動からの遅れと同じなので、バーストのヒットが遅れていれば、1more の時刻も同じだけずれる。

**録画と編成**

- `258`（風圧）・`260`（灼熱）: ラム（822・I）+ デルタ（20・II）+ 雪子（871・III・操作）。V-0232 の録画で、最小構成の警告なし（ラム・デルタはこの編成で与ダメージにもバーストの時刻にも効かない）。比べる指標はこの 2 本。
- `259`（風圧）: ココア + ユニ + クイーン（真）（III・操作）+ 雪子（III・AI）。V-0233 の録画（最小構成の警告ありだが、2026-10-06 のオーナーの判断で通した）。雪子は 4 枠目で、編成が違うので予測ファイルの指標にはしない。同じ遅れが出るかを、補いとして読む。
- 読み直しなので、この検証記録の冒頭の「録画」に挙げてから `records:predict` を回し、比べる値を読む前に commit した（plan/skills-guide.md 2 節）。

**読み方の前提**（V-0201・V-0205 と同じ）

- III の発動は、III のタイマーが 00.00 になったフレーム（V-0078・V-0082・V-0137）。遅れ（モデル）= 動画のフレームでの「III の発動 → ヒット」− 22（フルバーストの入りの止まり。C-0069）。ただし、ヒットが発動のフレームのとき（遅れ 0）は止まりの前に出るので、動画の差は 0 になる（いまのモデルの予測）。
- 指標 `burstHitDelays` は止まりを含めた動画のフレームで比べる（許容 `abs: 1`。録画の重複フレームの位置で 1f 揺れる。V-0137）。

## 予測（撮る前に書く）

比べる値（III の発動のフレーム）を読む前に書いた（2026-10-07）。H0 はいまのモデルで、値は予測ファイル（records/predictions/V-0292.json）。ほかの仮説は遅れの表の切り替えなので、ここに手で書く。

| 仮説                                       | 5 回の「III の発動 → ヒット」（動画のフレーム）           |
| ------------------------------------------ | --------------------------------------------------------- |
| H0: いまのモデル（遅れ 0）                 | 予測ファイルの `yukiko-delays-wind`・`yukiko-delays-fire` |
| Q: クイーン（真）と同じ（C-0231。遅れ 1f） | どの回も 22〜23f                                          |
| D2: 毎回同じで、H0・Q と違う               | どの回も同じ値 ± 1f で、23f より 2f 以上大きい            |
| D0: 毎回違う                               | 2f 以上ずれる回がある                                     |

- **Q を予想する**。雪子のバーストは、クイーン（真）と同じ「敵全体に最終攻撃力の X% の分配ダメージ」で、ペルソナの組の対になるキャラなので、演出が同じ長さとみる。根拠は弱い（遅れはキャラごとに 1〜134f と幅がある。遅れの表）。H0 は、ヒットがフルバーストの止まりの前に出ることになり、遅れの表のどのキャラにも無い形なので、外れると予想する。
- 風圧と灼熱で同じ値を予想する（1more は発動の後のことで、ヒットの演出は変わらない見込み）。
- 当たったとき（Q か D2）の影響: 遅れの表に雪子の行を足す（オーナーに諮る）。S1 の 1more の時刻（`delayFrames`）は C-0359 でバーストのヒットからの遅れなので、行を足すなら、発動からの遅れ（ヒットの遅れ + 46〜48f）に直すかをあわせて諮る。バーストのヒットの値は発動の直前のバフで出る（C-0351）ので変わらない見込み。
- 外れたとき（D0）の影響: 何で決まるかを調べる。表には足さない。

## 読み方

1. 各録画の右のバースト欄を 1 フレームずつ並べ、各回の III のタイマーが 00.00 になるフレームを読む（V-0201 と同じ）。
2. 各回の雪子のバーストのヒットのフレームを HUD の増分（`npm run records:read -- <録画 id> --recipe hud-jumps`）から取る（`258-06`・`260-05` などの値の増分）。
3. 「III の発動 → ヒット」を観測値（`burstHitDelays`。`args`・`setup` は予測ファイルの指標と同じ。許容 `abs: 1`）にする。`259` は雪子の回だけを並べ、記録の観測値にする。

2026-10-07 に読んだ（予測は commit 657e716 で固定し、読んだ観測値は次の commit で足した）。

- III のタイマーが 00.00 になるフレームは、右のバースト欄を 1 フレームずつ並べた一覧で、14 回ともはっきり読めた（00.00 の前のフレームはどの回も 09.5x の表示）。
- バーストのヒットは、HUD の値がバーストのヒットの値だけ増えたフレーム。**どの回も 00.00 の 1f 前**だった: 風圧 5 回（`258-12`）・灼熱 5 回（`260-07`）・`259` の雪子の 4 回（`259-14`。記録）。予測の H0（いまのモデル。動画で 0f）の ± 1f の中で、Q（クイーン（真）と同じ 22〜23f）・D2・D0 は外れた。**予想した Q は外れた**。
- ヒットは、ほかのキャラ（遅れの表）と違い、フルバーストの入りの止まり（22f）の**前**に出る。風圧と灼熱で同じで、1more の有無によらない。
- 1f の差はどの回も同じ向き。段の発動は六角形の替わり目で、III のタイマーの 00.00 はその 1f 後に出る（plan/captures/guide.md「バーストの段の切り替わり」）ので、ヒットは発動のフレームそのものとみる。
- **既存の観測値のヒットのフレームの読み違い**（値は変わらない）: `hud.ts` が HUD の 0 を 8 と読んで読みを落とし、次の読めたフレームをヒットとしていた回がある。HUD を並べた一覧で読み直した: 258 の 5 回目は f11155（`258-09` は f11156）、260 の 3・4 回目は f6303・f8680（`260-05`・`260-06` は f6304・f8714）、259 の 1・2 回目は f2574・f5063（`259-10` は f2576・f5065）。1more のヒットまでの差（`258-09`・`259-10`）は、直すと 258 の 5 回目が 48f、259 の 2 回目が 48f になる（1more のヒットのフレームは読み直していない）。
- **1more と追撃の時刻のずれ（モデル）**: S1 の 1more の分配ダメージ（定義の `delayFrames: 48`）は、モデルでは発動の 48f 後（止まりの後）に出るので、動画ではバーストのヒットの **70f 後**になっていた（モデルを回して確かめた。1 回目は発動 f731・1more f779 で、動画では 731 と 801）。録画は 47〜48f（C-0359）。48 は、ヒットを発動のフレームとみて、止まり（22f）を含む動画のフレーム数をそのままモデルのフレームに入れた値。クイーン（真）の S1 の追撃の分配ダメージ（`delayFrames: 104`。C-0361）も同じ形で、動画では雪子の発動の 126f 後になっていた（録画は 102〜104f。`259-10`）。値はどちらの時刻でもフルバーストの中で同じバフなので変わらない（V-0232・V-0233）。

**オーナーの判断（2026-10-07）**

1. 遅れの表に雪子の行を足すか → **足す**（hitFrames 0・effectFrames 0。計算は変わらず、測った値と根拠の結論を表に残す）。
2. 1more の `delayFrames` → **この PR で直す**。動画の差 48f から止まりの 22f を引いた **26** にした。クイーン（真）の追撃の分配ダメージは原因が同じなので、同じ PR で 104 から **82** に直した（動画の差 104f − 22f）。直した後のモデルで、動画の差は 1more が 5 回とも 48f（258 の編成）・4 回とも 48f（259 の編成）、追撃が 4 回とも 104f（259 の編成）。読み直した `258-09`・`259-10` の差（直すと 47〜48f・48f・104f）と合う。値の観測値の残差は変わらない（`records:check`）。

## 分かったこと・分からないこと

- **C-0419（確定・反復実測）**: 雪子のバーストの分配ダメージのヒットは、III の発動と同じフレーム（遅れ 0）で、フルバーストの入りの止まりの前に出る。いまのモデル（遅れの表に行が無い既定）と合う。
- 雪子の S1 の 1more（C-0359）とクイーン（真）の追撃の分配ダメージ（C-0361）の時刻は、定義の `delayFrames`（48・104）ではモデルで 22f 遅かった。結論の文（動画でバーストのヒットからの差）は正しく、モデル側の写し方が違っていた。26・82 に直した。
- 止まりの前に出るヒットからの動画の差を、発動からの遅れ（`delayFrames`）に写すときは、止まりの 22f を引く。
- 分からないこと: 雪子のバースト使用時の効果（1more の攻撃力▲・真紅の華の分配ダメージ▲）の発火のフレーム（表の効果の遅れは 0 のまま。未測定）。1more と追撃のヒットのフレームそのものは読み直していない（`258-09`・`259-10` のヒット側の読み違いだけを直して差を出した）。
