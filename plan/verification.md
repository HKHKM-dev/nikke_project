## Stage 2-A: ダメージ式（1 ヒットの実測）

射撃場で通常攻撃 1 ヒットの表示値を読む。敵は雑魚（防御 100）とし、属性相性なし・距離ボーナスは適正距離で撃つ（RL は距離ボーナスなし）。バーストは撃たない。通常攻撃に影響するスキル（自己バフ・攻撃ダメージ増加・弾数変化）を持たないキャラを選ぶ。

期待値の式（1 ヒット、期待値ではなく実値）:

```
基礎     = 攻撃力（ゲーム内表示の実攻撃力。ここは上乗せ込みの値をそのまま使う） − 100
1 ヒット = 基礎 × 武器倍率（SG は 1 ペレット分 = damage / shotCount）
           × (1 + コア命中なら (coreDamageRate − 1) + 会心なら (crit.damage − 1) + 距離ボーナスなら 0.3)
           × 属性有利なら 1.1
           （小数点以下は四捨五入。SR/RL はさらに × fullChargeDamage）
```

### 測定条件（2-A 共通）

### 属性ボーナス・距離ボーナスの見落とし（訂正、2026-09-23）

上記の測定はすべて **風圧（Wind）属性の的（"BigArms" という名の中型ラプチャー、9 本の録画全てで同一個体と確認）** に対して行っていた（ユーザー確認）。加えて、録画は敵が初期位置にいる状態で撮っており、**AR と SMG のみ適正距離ボーナス（+0.3）が乗る**（RL・SR・MG・SG は乗らない）こともユーザーが確認した。当初の逆算はいずれも考慮していなかった。

属性については `packages/core/src/element.ts` の相性表（炎→風→鉄→電撃→水→炎、左が右に有利、倍率 ×1.1）に 6 体の属性を照らすと、**6 体中エマ（灼熱）のみ**が風属性の的に対して有利になる。残り 5 体（デルタ＝風圧、クルミ＝鉄甲、ベロータ＝電撃、ミサト＝鉄甲、フラワー＝風圧）はいずれも中立で影響なし。距離については AR（クルミ）・SMG（ミサト）の読み取りはもともと「距離あり」で解釈しており訂正不要。**訂正が必要なのはエマ（属性 ×1.1 の見落とし、かつ元々「距離あり」と誤って解釈していた MG の読み取り）だけ**だった。

2026-09-23、ユーザーがエマの録画を 4 パターンとも読み取り直し、正確な値（非会心非コア 6,116・会心非コア 9,174・非会心コア 12,233・会心コア 15,291）を提供。この 4 値の比は 1 : 1.4999 : 2.0002 : 2.5002 と、**距離ボーナスなし**（boost = 1.0/1.5/2.0/2.5）の場合の理論比 1:1.5:2.0:2.5 に極めて高い精度で一致し、以前の「距離あり（1.3x）」という解釈が誤りだったことを裏付ける。攻撃力 A（＝実攻撃力−100）と武器倍率 0.0557・属性倍率 ×1.1 を使い、4 値すべてを四捨五入で再現できる整数 A を 90,000〜110,000 の範囲で全探索すると **A=99,825 の一意解**が得られた（4 パターン全て誤差 0）:

```
攻撃力 = 100 + A = 99,925
```

この値は旧データ（84,573、距離ありと誤解釈・属性補正なし）とは全く別物で、以前この節で行った「エマのデータを無効化する」という判断は撤回する。

結論:

- 倍率グループの構造（1 + コア 1.0 + 会心 0.5 + 距離 0.3 の加算、チャージ倍率と武器倍率の乗算）は 6 武器種で一致した。
- 「戦闘中の攻撃力（逆算値）」と「Lv400 無凸の計算値」の関係を、当初は「一律 ×1.12365 の乗算係数」と解釈していたが、**2026-09-23 に誤りと判明**。正しくは後述のとおり「装備・好感度はいずれも割合ではなく固定値の加算」であり、キャラごとに基礎攻撃力が異なるため一律の乗算係数では説明できない（SR を 2 凸として再計算したことで偶然 ×1.12365 に近い値が出ていた）。詳細は次項。

### スペック固定の仕様（2026-09-23 再検証）

公式のお知らせ・パッチノート・ヘルプで「スペック固定」の数値仕様（Lv・凸・装備ティア等）を明記した一次資料は見つからなかった（下記「調査した情報源」）。そのため、ユーザーが過去に独自作成・検証してきた計算ツール（`D:\NIKKE_Damage_Calculator\シミュレーター本体.html`、以下「参照シミュレータ」）の `applyFixedSpecBuilds()` / `applyFixedSpecBuildForRid()` 実装と、本リポジトリの 1 ヒット実測（上表）を突き合わせて仕様を再構成した。参照シミュレータの成長曲線（レベル×グレード/コアの式）はユーザー本人が「計算式で無理やり近似させたもの」と明言しており誤差を含むため、**素のステータスは本リポジトリの `computeStat`（Stage 1 で ShiftyPad と一致確認済み）を正とし、参照シミュレータからは装備・好感度の離散テーブル値のみを採用した**。

- Lv400（`state.syncLevel = 400`）
- 限界突破・コア強化: レア度の**上限まで**（SSR は 3 凸+コア 7、SR は 2 凸、R は凸なし。2026-09-23 に SSR も含め確認済み）
- スキル 1・2・バースト: 全 Lv10

**コア強化の適用対象（2026-09-23 解決）**: 当初は「本リポジトリの `computeStat`（grade/core 込み） + 好感度 + 装備」という単純な加算で突き合わせており、SSR（コア強化を持つ唯一のレア度）だけ +0.19% の誤差が残っていた。原因を調べたところ、[arca.live の解説記事](https://arca.live/b/nikketgv/95503431)（"명함과 돌파, 호감도/장비별 딜량 정리"）に次の記述を発見した:

> 돌파는 "기본 스탯의 2% 비율 + 고정수치 20 보정"의 비율로 상승 후 호감도/콘솔 스탯 합계<br>
> 코어강화는 "최종 합계된 풀돌 상태의 스탯"의 2% 비율로 상승
> （突破は「基礎ステータスの2%比率＋固定値20補正」で上昇後、好感度・コンソールのステータスを合算。コア強化は「最終的に合算された全突破状態のステータス」の2%比率で上昇）

つまり **コア強化の +2%/段は、突破適用後の素のステータスに「好感度」を加算した値に対してかかり、装備には掛からない**。本リポジトリの `computeStat` は突破後の素のステータスのみにコア%を掛けており（Stage 1 で ShiftyPad の「装備・好感度抜き」表示と一致確認済みなので、この式自体は正しい）、好感度分にはコア%がかかっていなかった。これが SR/R では誤差が出ず（コア強化を持たないため無関係）、SSR でだけ +0.19% の系統誤差になっていた原因である。

**戦闘中攻撃力の正しい計算式**:

```
gradeBase   = computeStat(char, 'attack', { level: 400, grade: <レア度上限>, core: 0 })  // 突破のみ、コアなし
withAffinity = gradeBase + 好感度加算(クラス, rank)
withCore     = withAffinity × (1 + 0.02 × core)                                          // コアはここに掛かる
combatAttack = round(withCore) + 装備加算(クラス, T9Lv5)                                  // 装備はコアの外
```

この式で、SSR 3 体すべてが**誤差ゼロで完全一致**した:

| キャラ         | レア | grade/core | 好感度 | gradeBase | +好感度 | ×(1+0.02×7) | +装備  | 計算値  | 実測    | 差                 |
| -------------- | ---- | ---------- | ------ | --------- | ------- | ----------- | ------ | ------- | ------- | ------------------ |
| エマ           | SSR  | 3/7        | rank30 | 79,840    | 81,207  | 92,575.98   | +7,349 | 99,925  | 99,925  | **±0（完全一致）** |
| フォルクヴァン | SSR  | 3/7        | rank30 | 63,884    | 64,978  | 90,969.08   | +5,879 | 79,954  | 79,954  | **±0（完全一致）** |
| イサベル       | SSR  | 3/7        | rank40 | 95,797    | 98,137  | 111,875.82  | +8,818 | 120,694 | 120,694 | **±0（完全一致）** |

SR/R は元々コア強化を持たない（コア = 0 固定）ため、この式は既存の「単純加算」モデルと数学的に同一になり、以前の突き合わせ結果（9 体中 7 体で誤差 0.01% 以内）はそのまま有効。**これで SR・R・SSR 全 9 体が、レア度に応じた単一の式で誤差ゼロ〜0.01% 以内に収まった**。

**好感度 rank30 と rank40 の切り分け（旧未確定 2）も解決**: 非ピルグリムの SSR 2 体（エマ・フォルクヴァン）は rank30 で完全一致。ピルグリムのイサベルは rank30 では大きくズレるが rank40 で完全一致し、**「ピルグリム所属のみ好感度上限が rank40」という参照シミュレータの仮説が正しい**と確定した。これは [game8.jp の解説記事](https://game8.jp/nikke/537260) や検索で見つかった複数の攻略記事とも整合する（「無凸は rank10、2 凸で rank30 に更新、ピルグリム所属のみ 3 凸以降 rank40」）。また [dcinside/arca.live の記事](https://arca.live/b/nikketgv/95503431) により「コア強化は好感度と無関係に 2% ずつ素のステータスを底上げするだけで、好感度ランクには影響しない」ことも確認済み（SSR は 3 凸で好感度上限に達し、コア強化を追加しても好感度ランクは変わらない）。

装備データ自体（T9Lv5 のクラス別固定値）は、この式変更によって R（プロダクト23、完全一致）・SR（4 体、誤差 0.01% 以内）・SSR（3 体、完全一致）のすべてで矛盾なく説明でき、**データ自体に誤りはなかった**と判断できる。

4. R・SR の「好感度上限が凸段階に紐づく」という仮説自体の裏付けは、複数の攻略記事（game8.jp 等）で「無凸=rank10、2凸=rank30、ピルグリムは3凸以降=rank40」という記述が見つかり、裏付けが取れた。ただし「そのレア度の好感度絶対上限」との違いを完全に切り分けたわけではない（R/SR は無凸〜2凸の範囲でしか検証していないため）。

式の検証としては、**SR・R・SSR 全レア度で Stage 2 の完了条件を満たした**。grade/core はレア度上限、好感度は非ピルグリム rank30・ピルグリム rank40、コア強化の +2%/段は「突破後の素のステータス＋好感度」に対して掛かり装備には掛からない、装備は T9Lv5 の固定値加算（コアの外）——このモデルで、9 体中 8 体が誤差 0.01% 以内、残り 1 体（クルミ）も −0.01% で実質誤差なしと言える。系統誤差は解消済みで、追加の未確定事項はない。
