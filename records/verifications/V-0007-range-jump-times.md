# V-0007: 射撃場 3 分モードの的のジャンプの時刻（ゲーム内の秒）

- 問い: 3 分モードの的のジャンプは、戦闘開始（残り時間 02:59 が出たフレーム）から数えてゲーム内の何秒に来るか。180 秒に何回か。時刻は録画ごとに同じか、違うなら何で決まるか
- 話題: 敵・的・場面
- 日付: 2026-09-27
- 録画: `018`〜`022`、`038`〜`050`、`054`〜`063`
- 状態: 調査中
- 派生元: `V-0006`

## 条件

- 3 分モードの録画のうち、180 秒を通して撮ったもの（動画が 185 秒以上）。単騎 11 本（045・046・054〜062）、多人数 17 本。
- モデルの代表値（C-0025、`data/enemies.json` の `range-3min-jump`）は、Stage 16-B で録画 41・43・44・48〜50 の HUD の総ダメージが止まる区間から読んだもの。最初のジャンプを「最初のダメージから」数え、動画のフレームを 60 で割って秒にしていた。Stage 21-B で、読んだフレームのままゲーム内の秒に直した（最初 31.62 秒・37.128 秒ごと・2 秒）。この換算では 180 秒に 4 回になり、実測（5 回）と食い違う（V-0006）。
- 読む前に分かっていること:
  - 録画 46・55（紅蓮BS 単騎・同じ条件）は、ジャンプの時刻が戦闘開始から数えて 1f 以内で同じ。窓の始まりは残り時間で約 24.9・61.4・100.9・137.2・170.5 秒（V-0002）。
  - Stage 16-B: 同じ編成の録画 49・50 は 4f 以内で一致し、録画 48 は約 410f 早かった。最初の停止は「最初のダメージから」25.7〜32.7 秒、間隔は 2,014〜2,382f。
  - 録画 47（3 人）は、1・2 回目の停止が録画 46 より約 1 秒遅かった（V-0002）。
  - 多人数の録画では、ジャンプの間もスキルのダメージが入り、フルバーストの入りでも HUD が止まる（V-0002）。

見込み: H3 と H4。代表値は、ゲーム内の秒で読んだ最初の窓と間隔の中央値にすれば、180 秒に 5 回を再現できる。

外れたときの影響:

- H1・H2 のどちらかが成り立てば、ジャンプの時刻をモデルで決められる（H2 なら与ダメージの累計から）。
- H3 なら、代表値は中央値にし、録画と比べるときの散らばり（合計で 1〜2%）を注記する。Stage 16-C（乱数と分布）の材料になる。
- H4 が外れる（4 回の録画がある）なら、5 回目の有無が位相で変わることになり、合計の予測の幅に効く。

## 読み方

1. 戦闘開始 S: `tools/captures/timer.ts --mode changes` の変わり目のうち、58〜60f おきの並びが始まるフレーム（残り時間 02:59 が出たフレーム。V-0002 と同じ）。
2. 停止の区間: `tools/captures/hud.ts --mode jumps` の HUD の総ダメージの増分から、増分の無い区間が 90f 以上続く所を拾う。始まりは停止の前の最後の増分のフレーム、終わりは停止の後の最初の増分のフレーム。
3. 単騎の録画は、停止の区間をそのままジャンプとする（単騎はバーストを使わないので、フルバーストの入りの停止は無い）。多人数の録画は、フルバーストの入り（残り時間の間隔が延びる所、C-0049）と重なる停止を除く。除けない停止は「判定できない」として残す。
4. 時刻は S から数えたフレームを 0.017 秒で掛けてゲーム内の秒にする。停止の始まり（最後の増分）の秒・停止の長さ・間隔を、録画ごとに並べる。H2 のために、停止の始まりの HUD の総ダメージも並べる。
5. 読んだ値は観測値にする（`source` に `V-0007`）。
