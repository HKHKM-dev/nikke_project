## Context

Stage 8 までは「**射撃のタイミングはバフに依存しない**」を芯にしてきた。射撃の列は編成だけで決まり、1 パス目（`planTeamRun`）は次の一方向の流れで作れた。

```
planShots（射撃の列）→ planTeamSchedule（ゲージ → 時刻表）→ planBuffTimeline（バフの区間）→ planSkillHits（倍率ダメージ）
```

Stage 10 で扱う「最大装弾数▲」「リロード速度▲」「チャージ速度▲」は射撃の列を変え、「バーストスキルクールタイム▼」は時刻表を変える。どちらもバフの窓（バーストを使った時・フルバースト時など）から来るので、**射撃の列 → 時刻表 → バフ → 射撃の列…と循環する**。Stage 7・8 の設計書で予告したとおり、ここで 1 パス目を「フレームを 1 つずつ進めながら射手・ゲージ・バースト・射撃に効くバフを同時に回す」形に変える。

**設計の芯は「循環を 1 フレームずつほどく」こと。** フレーム f の射撃は f − 1 までに付いたバフで決まり、f に起きた発動・フルバーストで付くバフは f + 1 からの射撃に効く。因果が前向きなので、フレームループ 1 回で射撃の列と時刻表が確定する。そのあとは Stage 8 と同じく、確定した射撃の列と時刻表からバフの区間と倍率ダメージを作る（ここは変えない）。

**語彙は、既存の録画か新規の撮影で実機と比べられるものに絞る**（Stage 8 の方針）。今回は既存の録画 19・37 の弾数表示から、装弾数の仕組みがかなり読めた（0.2 節）。

## 1. 時間モデル — 1 パス目をフレームループにする

### 1.1 流れ

```
1 パス目（sim と calc で共有・純関数。sim/firstPass.ts 新設）
  runFirstPass(slots, frames, …)   フレームループ（下の 4 手順）
    → ShotLog[]（残弾 0 にした射撃の印つき）, BurstSchedule, 即時効果の記録
  planBuffTimeline(slots, schedule, frames, shots)   ← Stage 8 のまま（射撃に効くバフの窓もここで作り直す）
  planSkillHits(…)                                    ← Stage 8 のまま
2 パス目（変更なし）
  sim : 射撃の列を読み、区間ごとの 1 トリガー値を足す
  calc: グループごとに（5 節のハイブリッドで）トリガー数 × 1 トリガー値
```

フレーム f の中の順番（**既存の 1 パス目と同じ順**で、射撃に効く効果の処理を最後に足すだけ）:

1. **射手を進める**。各枠の射撃パラメータ（最大装弾数・リロード・チャージ）は、f − 1 までに付いた射撃に効くバフで決まる。撃ったら射撃の列に記録する（残弾を 0 にした射撃には「最後の弾丸」の印）。
2. **ゲージを足して状態機械を進める**（`stepBurstController`。Stage 7 と同じ）。発動・フルバーストの開始 / 終了・満タンが起きる。
3. **このフレームに発火したトリガーを判定する**（射撃に効く効果だけ）。`timed` なら窓を登録し（窓の開始は Stage 8 と同じ規則。射撃の回数トリガーは f + 1 から）、即時効果（CT 短縮・弾丸チャージ）はその場で状態機械・射手に当てる。
4. f + 1 へ。

射撃に効かない効果（攻撃力・会心など）はループで扱わない。ループが終わってから `planBuffTimeline` が確定した射撃の列と時刻表から全部の窓を作る。**射撃に効く効果の窓は、ループの中で見た窓と `planBuffTimeline` が作り直した窓が一致する**（トリガーは f までの出来事だけで決まるので）。これはテストで固定する（8.3 節）。

### 1.2 トリガーの判定を 1 か所にする

ループの中の判定（3 番）と、`planBuffTimeline` の中の `triggerFrames` は同じ意味でなければならない。二重実装を避けるため、`skills/timeline.ts` に「出来事の列を 1 つずつ受け取って、どのトリガーが発火したかを返す」小さな追跡器（`TriggerTracker`）を作り、

- ループは出来事が起きるたびにこれへ流し、
- `triggerFrames` は確定した射撃の列・時刻表を同じ順で流し直して発火フレームを集める

形にする。射撃の回数・発動の回数はこの追跡器の中の数え上げになり、どちらも同じコードを通る。

### 1.3 退化

射撃に効く効果が 1 つも無い編成では、射手はバフを見ないので射撃の列は `planShots` と、時刻表は `planDynamicSchedule` と**1 フレームも変わらない**（既存の 1 パス目は「射手を全部回してからゲージのループを回す」だったが、射手が互いに独立なので 1 つのループにまとめても同じ）。Stage 9 までの全テストが数値を変えずに通ることを退化条件にする。

固定サイクル（`burstModel: 'fixed'`）は時刻表が射撃に依存しないので、ループは射手だけを回す。CT 短縮は固定サイクルでは効かない（時刻表が CT を見ないため。UI には出さない比較用モデルなのでこのまま）。

### 1.4 採らなかった案: 不動点の反復

「バフなしで射撃の列 → 時刻表 → バフ → 射撃の列を作り直す…を変わらなくなるまで繰り返す」も考えた。既存の関数を 1 つも変えずに済むが、反復回数が射撃に効くトリガーの発火回数ぶん（回数トリガーなら数百回）要りうる。calc は入力を変えるたびに計算し直すので、1 パスのほうが確実に速い。

## 2. DSL の追加（`skills/types.ts`）

### 2.1 stat（射撃に効くもの）

```ts
export type BuffStat =
  | /* 既存 7 つ */
  /** 最大装弾数。scaling 'ratio' は比率（%）、'flat' は発数（100 で割らない） */
  | 'maxAmmo'
  /** リロード速度（%）。1 回分のリロード時間 × max(0, 1 − Σ)（仮。11 節 4） */
  | 'reloadSpeed'
  /** チャージ速度（%）。チャージ時間 × max(0, 1 − Σ)（仮。解放遅延 22f は変えない） */
  | 'chargeSpeed';

export type BuffScaling = 'ratio' | 'casterAttack' | 'flat'; // flat は stat が maxAmmo のときだけ
```

`BuffTotals` に `maxAmmoRatio` / `maxAmmoFlat` / `reloadSpeed` / `chargeSpeed` を足す（`attackRatio` / `attackFlat` と同じ分け方）。区間の鍵 `keyOf` にも入るので、これらが変わる区間は別のグループになる。

- `passive` にも `timed` にも書ける（`burstGaugeSpeed` と違い、1 パスなので `timed` でも循環しない）。
- ダメージの式（`computeTriggerDamage`）はこの 4 つを読まない。

### 2.2 即時効果（新しい kind 2 つ）

効果時間がなく、発火の瞬間に 1 回だけ状態を動かすもの。

```ts
/** 「バーストスキルクールタイム X 秒▼」: 対象の残りの CT を X 秒減らす（0 未満にはしない） */
export type CooldownReductionEffect = {
  kind: 'cooldownReduction';
  trigger: EffectTrigger;
  target: BuffTarget;
  targetWeapon?: WeaponType;
  /** 秒数の description_value_NN */
  ref: number;
  assumes?: LocalizedText;
};

/** 「弾丸チャージ X%」: 対象の残弾に 最大装弾数 × X% を足す（最大で止める。端数は仮に切り捨て） */
export type AmmoRefillEffect = {
  kind: 'ammoRefill';
  trigger: EffectTrigger;
  target: BuffTarget;
  targetWeapon?: WeaponType;
  ref: number;
  assumes?: LocalizedText;
};
```

- どのスロットにも書ける。発火の判定は `timed` と同じトリガー（`TriggerTracker`）を使う。
- 「弾丸チャージ N 発」は形が同じなので、使うキャラが出たら `scaling: 'flat'` を足す（今回は検証相手がいないので足さない）。

### 2.3 トリガー「最後の弾丸」

```ts
export type ShotCountKind = 'normalShot' | 'normalHit' | 'fullChargeShot' | 'lastShot';
```

- `lastShot` = 残弾を 0 にした射撃（マガジンの最後の 1 発）。`every` は Stage 8 と同じ（「最後の弾丸で 3 回攻撃した時」があれば 3）。全弾命中の前提なので「攻撃した時」「命中した時」を分けない。
- 最大装弾数▲の間は最後の弾丸が遅れ、弾丸チャージで残弾が戻ると 0 にならないので出なくなる。この相互作用はループの中で自然に出る。

## 3. 射手（`sim/shooter.ts`）

### 3.1 射撃パラメータ

```ts
/** 射撃に効くバフの合計（BuffTotals の 4 フィールド） */
export type FiringBuffs = Pick<BuffTotals, 'maxAmmoRatio' | 'maxAmmoFlat' | 'reloadSpeed' | 'chargeSpeed'>;

/** フレームごとに射手へ渡す実効値 */
export type FiringParams = {
  maxAmmo: number; // max(1, floor(基礎 × (1 + ratio)) + flat)   … 丸め・順番は仮（11 節 4）
  reloadChunkFrames: number; // secondsToFrames(reloadTime × max(0, 1 − reloadSpeed))
  chargeFrames: number; // secondsToFrames(chargeTime × max(0, 1 − chargeSpeed))（チャージ武器だけ）
};
```

`stepShooter(state, shot, model, params)` の 4 番目の引数にし、省略時は基礎値（今と同じ動き）。

### 3.2 規則（0.2 節の読み取りに合わせる）

| 場面                         | 規則                                                                                                                                                  | 根拠                                             |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 最大装弾数が増えた           | 残弾は増えない。マガジンを撃ち切るまでの発数が増える                                                                                                  | 録画 37（3 のまま）                              |
| 最大装弾数が減った（切れた） | 残弾が新しい最大を超えていたら最大に削る（仮）                                                                                                        | 未確認（`MAX_AMMO_CLAMP_ON_DECREASE`）           |
| 分割リロード                 | **1 回分ずつ込める**。1 回分 = `max(1, round(その時点の最大 × reloadBullet))`、所要 `reloadChunkFrames`。残弾が最大に届いたら、1 発目の遅延の後に撃つ | 録画 37・19                                      |
| リロード中に最大が変わった   | 次の 1 回分から新しい最大で数える。新しい最大に届くまで続ける                                                                                         | 録画 37（3 → 10 → 17 → 20）・19（0 → 5 → 8 → 9） |
| リロード速度                 | 次に始まる 1 回分から効く（込めている途中の 1 回分は変えない）                                                                                        | 仮                                               |
| チャージ速度                 | 次に始まるチャージから効く                                                                                                                            | 仮                                               |
| 弾丸チャージ                 | 残弾 += floor(最大 × X)、最大で止める。リロード中なら込めた分に足し、最大に届けばリロードを終える                                                     | 仮（録画 19 は満タンからで区別できない）         |

最大装弾数が一定なら「1 回分ずつ」でも込め終わる時刻は今の「回数 × 時間」と同じなので、退化テストはそのまま通る（`cadence.ts` の `reloadChunks` と同じ回数になる）。

### 3.3 `cadence.ts`（calc の平均レート）

`computeCadence(shot, model, firing?)` に `FiringBuffs` を受ける引数を足す。常時分の射撃バフ（`passive`）は平均レートに畳み込む（最大装弾数・リロード時間・チャージ時間を差し替えて 1 周期を作るだけ）。

## 4. バースト（`burst/controller.ts`）

- `reduceCooldown(state, slotIndex, frames, frame)` を足す。`cooldownEnd[slot] = max(frame, cooldownEnd[slot] − frames)`。**そのフレームの発動の後に当てる**（III の発動 = フルバースト開始のフレームでリターの CT 短縮が起きると、今撃った III の CT も縮む）。この順番は撮影で確かめる（8.6 節）。
- `BurstSchedule` に `cooldownReductions: { frame, slotIndex, sourceSlotIndex, frames }[]` を足す（UI・CLI・テスト用）。
- 秒 → フレームは `durationToFrames`（既存。切り上げ）。

| グループ                                  | トリガー数                                                                       |
| ----------------------------------------- | -------------------------------------------------------------------------------- |
| 持続の射撃バフ（`timed` の 4 stat）が無い | 今までどおり 平均レート × 秒数（常時分の射撃バフは平均レートに畳み込む。3.3 節） |
| 持続の射撃バフが掛かっている              | **射撃の列のうち、そのグループの区間に入る発数**（sim と同じ数）                 |

理由: 最大装弾数▲は「マガジンを撃ち切るまで」を延ばすバフで、10 秒程度の窓の中の発数は窓の始まりの残弾・リロードの位相でほぼ決まる。平均レートで置くと、ドレイク（1 周期 約 14 秒 > 窓 10 秒）のようにフルバースト中の発数が 1 割以上ずれうる。フルバースト中はダメージが集中するので、ここを実数にする。

- `SlotSegmentResult` に `triggerSource: 'average' | 'shots'` を足す（UI で「実数」と出す）。
- `TeamSlotResult.cadence` は常時分を畳み込んだ平均レート（表示用）。
- 射撃の列は 1 パス目ですでに計算済みなので、calc の計算量は変わらない。

**採らなかった案**: (a) 全グループをバフ込みの平均レートで置く（不変条件は保てるが、上の誤差がそのまま残る）。(b) 全グループを射撃の列から数える（calc = sim になり、平均レートの「状態ごとの秒間トリガー数」という説明ができなくなる）。

## 10. リスク・留意点

- **ループと `planBuffTimeline` の窓の食い違い**: 1.2 節の `TriggerTracker` で判定を 1 か所にし、8.3 節で窓の一致を固定する。
- **1 フレームの前後**: 射撃に効くバフは「f に付いたら f + 1 の射撃から」、ダメージのバフは Stage 6 以来「f に付いたら f の射撃から」（sim の 2 パス目で発動が射撃より先）。射撃パラメータが変わる瞬間の 1 発だけ扱いが違うが、ダメージには影響しない（パラメータは発数を変えるだけ）。
- **AI の射撃**: AI がリロードを残弾 0 まで待つか（途中でリロードしないか）。録画 37・19 では撃ち切ってからリロードしていた。操作キャラの自動リロードも同じ前提。
- **CT 短縮の対象の範囲**: 「味方全体」に、CT が明けている枠（短縮しても変化なし）と、今発動した枠が含まれるか。8.6 の 1 で見る。
- **リロード速度・チャージ速度の式が仮のまま残る**（11 節 6）。仮の式の根拠は説明文の「100% 上限」だけ。
- **ラムの CT 短縮は条件付き**（「同じ部隊の味方がいれば」。ラムの部隊はレム・エミリア）。録画 37・38 の編成では発動しないので定義しない（`notes` のまま）。

## 11. 決めてほしいこと（推奨付き）

1. **1 パス目の作り方** — 推奨: **フレームループ 1 回で射手・ゲージ・バースト・射撃系のバフを回し、その後のバフの区間と倍率ダメージは Stage 8 の関数のまま作る**（1 節）。判定は `TriggerTracker` で 1 か所にする。代替: 不動点の反復（1.4 節。既存関数を変えずに済むが遅い）。

2. **calc の近似（要件の未決事項 5）** — 推奨: **ハイブリッド。持続の射撃バフが掛かっているグループだけ射撃の列から数え、それ以外は今までどおり平均レート**（5 節）。代替: 全部を平均レート（誤差がフルバースト中に残る）/ 全部を射撃の列（calc = sim）。

3. **語彙の範囲** — 推奨: **最大装弾数（比率・固定）・リロード速度・チャージ速度・CT 短縮・弾丸チャージ（比率）・最後の弾丸トリガー**（2 節）。最後の弾丸は、所持キャラ（I-DOLL・フラワー / オーシャン、プロダクト23）の効果が数値に出ないので、**トリガーだけ入れて単体テストで固定し、キャラ定義は作らない**。装弾数無限・最大装弾数▼・スタック・状態は主力キャラの Stage。代替: 最後の弾丸を見送る（Stage 8 の「比べられるものだけ」をより厳密に守る）。

4. **仮の式（定数）** — 推奨: 次を名前付きの定数で置き、8.6 の撮影で確定する。
   - 最大装弾数 = `max(1, floor(基礎 × (1 + Σ比率)) + Σ固定)`（加算は録画 37 で確認済み。切り捨てか四捨五入かは 8.6 の 2 で）
   - 最大が減った時に残弾を削る（8.6 の 4）
   - 分割リロードは 1 回分ずつ、その時点の最大で 1 回分を決める（録画 19・37 で確認済み）
   - リロード時間・チャージ時間 × max(0, 1 − Σ速度)（説明文の 100% 上限から）
   - CT 短縮は即時・同じフレームの発動の後（8.6 の 1）
   - 弾丸チャージの端数は切り捨て

5. **リターの扱い** — 推奨: **CT 短縮の検証役として、この Stage でリターを完成させる**（S1・バーストとも Stage 10 の語彙で書き切れる）。Stage 11 はクラウンから始める（ロードマップを直す）。代替: Stage 10 はテスト用の仮定義で CT 短縮を確かめ、リターの定義は Stage 11 に残す（同じ撮影が 2 回要る）。

6. **リロード速度・チャージ速度の実測** — 推奨: **語彙と仮の式だけ入れ、実測は Stage 11 のクラウン（リロード速度）・アリス（チャージ速度）の撮影で行う**。どちらも Stage 10 の検証編成に入れると、それぞれの特殊な対象（「直前にバーストスキルを使用した味方」「最終攻撃力が最も高い味方 2 機」）が数値に混ざって切り分けにくいため。ただし、次のキャラを所持していれば、単純な検証役として Stage 10 で 1 本撮れる: **アドミ**（172。バースト 味方全体 リロード速度 50.91%）、**ルピー：ウィンターショッパー**（203。バースト 味方全体 リロード速度 63.17%）、**ユニ**（160。フルバースト時 味方全体 チャージ速度 8.97%）。所持しているか教えてほしい。

7. **撮影** — 推奨: **8.6 の 1 本（リター + デルタ + ドレイク宝物 3・ドレイク操作・3 分モード）**。フルバーストの回数・間隔（CT 短縮）と、デルタ・リター・ドレイクの弾数表示（丸め・加算・削り）を 1 本で読む。

8. **ブランチ** — 推奨: **今のブランチ `claude/stage-10-progress-3e7e62`（main = Stage 9 マージ後から分岐）で実装し、main 向けの PR にする**。
