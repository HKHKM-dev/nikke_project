# 自動マージを予約した PR の後片付けを、マージを待って行う

- 何のための文書か: マージの後の後片付け（`tools/git/sync-after-merge.ts`。メインのチェックアウトの main の早送りと、マージ済みのブランチを origin/main に揃えること）が、PR を出した後の次の発言まで行われない問題の、案・決定と経過。
- 関連: AGENTS.md「コミット手順」、[design-workflow-simplification-10.md](design-workflow-simplification-10.md) 2 節（同じ道具の `--prune-branches`）。

## 1. いま

- 後片付けは、Claude Code のフックでセッションの始め・発言・応答の終わりに回る。
- PR は、出した直後に自動マージを予約する。CI が終わってマージされるのは数分後で、そのときの応答の終わりのフックはもう回り終えている。
- そのため、マージの後もオーナーが次の発言をするまで、メインのチェックアウトの main は古いままで、セッションの差分の表示にもマージ済みの変更が残る。
- マージの後、main の CI が生成物を作り直して commit する（数分から 10 分ほど）。この commit も、次の発言まで main に入らない。

## 2. 案と決定

応答の終わりのフック（`--wait-merge`）で、いまのブランチの PR が次のどちらかなら、マージを待つ裏の処理（`--wait-pr <番号>`）を切り離して起こす（`sync-after-merge-lib.ts` の `shouldWaitMerge`）。

- 開いていて、自動マージを予約している。
- マージしてから 30 分たっていない（main の CI がまだ生成物を作り直しているかもしれない）。

裏の処理の動き:

- 1 分ごとに PR を見る。マージされたら後片付けをする。
- その後は、マージのコミットの CI がすべて終わるのを待ってから、もう一度後片付けをして終わる。CI の終わりを待つのは、マージから 30 分まで。
- PR が閉じた、または自動マージの予約が外れたら、何もせずに終わる。マージを待つのは 3 時間まで。
- 同じ PR を待つ裏の処理が動いていれば、新しく起こさない。印は worktree どうしで共有する `.git` の `sync-after-merge-wait-<番号>.json`（プロセス ID と時刻。3 時間半を過ぎた印は効かない）。

後片付けの条件は、フックから回すときと同じ。作業中の変更がある、または HEAD が PR の最後のコミットと違う（続けて作業している）なら、ブランチは揃えない。

**理由**

- フックが自分で待つ形（Stop のフックを長い時間止める）は、応答の終わりを遅らせるので取らない。
- 裏の処理は、起こした親が終わった後も残る。Windows で、Bash から起こして親が終わった後も子が動き続けることを確かめた。
- 裏の処理の結果は、チャットに知らせられない。次のフックは、もう揃っているので何も言わない。

## 3. 経過

- 2026-11-10: オーナーの依頼（PR の後、次の発言まで同期されない）で起案し、実装した。`--wait-pr 1053`（マージ済みの PR）で、マージを見て後片付けをし、CI の終わりを見てもう一度後片付けをして終わり、印を消すことを確かめた。
