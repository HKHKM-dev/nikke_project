- 関連: [design-modern-ui.md](design-modern-ui.md)（ニケ一覧）、[design-skill-catalog.md](design-skill-catalog.md)（効果の分類。第 2 段で使う）、[design-combat-power-sort.md](design-combat-power-sort.md)（戦闘力の表。表の作り方の手本）

## 1. 背景

- オーナーのコメント（2026-11-16）: 絞り込みを実装したい。旧プロジェクト（old_nikkecalc の `シミュレーター本体.html`）の「絞り込み（その他）」を手本に、項目を足す。
- 旧プロジェクトの項目は 6 つ。
  1. 特殊攻撃: 貫通・持続・分配・防御力無視・順番に攻撃・使用武器変更
  2. 特性: バースト再突入・宝もの・分割リロード
  3. バースト CT（秒の値ごと）
  4. スキルの効果: 分類ごとに、効果（攻撃力・チャージ速度など）を「自（自分）」「味（味方）」で選ぶ。敵へのデバフも選べる
  5. 名前の検索
  6. スキル名・説明文の検索
- 旧プロジェクトは 1・4 を説明文の正規表現で作っていた。いまのリポジトリには説明文の効果を分ける道具（`packages/core/src/skills/catalog.ts`）があり、自分・味方・敵の区別も持つ。

## 2. 決めたこと（2026-11-17、オーナー「案の通り進めて」）

1. 2 段に分けて作る。第 1 段は 5・6・3（データがそのまま使える）。第 2 段は 4・1・2（catalog の分け方から項目の表を作る）。
2. 「絞り込み」のボタンは、押すと開く窓に項目を置く。項目のボタンは、旧プロジェクトと同じく文字のボタンにする。
3. ニケ一覧の上のバッジの絞り込み・お気に入りとは AND。

## 3. 絞り込みの表（filter.json）

- 説明文は 1 体あたり数 KB あり、キャラのデータ（1 体 40KB 前後）を全員分読むのは重い。戦闘力の表（`combat.json`）と同じく、絞り込みに要る値だけを全キャラ分 1 つにまとめた表を作り、窓を初めて開いたときに 1 回だけ読む。
- 表は `packages/core/src/filterTable.ts` の `buildFilterTable(characters)` が作る。書くのは `fetch-data`（キャラのデータと一緒に）と `npm run filter-table`（手元のキャラのデータから作り直す）。テストが、手元のデータから作ったものと一致するかを見る（`combat.json` と同じ）。
- 1 体の値（第 1 段）:
  - `burstCooldown`: バースト CT（秒。`burstSkill.cooldownSeconds`）
  - `skillText`: スキル名と説明文（スキル 1・2・バーストと、宝物版）。説明文は色・用語の印を除き、値の差し込み（`{description_value_NN}`）を最大 Lv の値にする。検索用に正規化（4.2 節）した文字列
- 読み込みは版と形を確かめ、違えば窓に読めなかった旨を出す（戦闘力の表と同じ。デプロイの直後に古い JS と新しい表が混ざっても画面を落とさない）。

## 4. 第 1 段: 文字の検索とバースト CT

### 4.1 窓

- 「絞り込み」のボタンで、ボタンの下に開く窓（`Popover`。並べ替えと同じ）。窓の中は上から次の順。
  1. 名前: 文字の入力欄
  2. スキル: 文字の入力欄（スキル名・説明文）
  3. バースト CT: 値ごとのボタン（表にある値を小さい順に。いまは 20 秒・40 秒・60 秒）
  4. 「すべて外す」のボタン
- 絞り込んでいる間は、「絞り込み」のボタンを押している色にする（バッジの絞り込みのボタンと同じ考え）。
- 状態は保存しない（バッジの絞り込みと同じ）。

### 4.2 合い方

- 文字は、全角・半角（NFKC）と大文字・小文字をそろえ、ひらがなをカタカナにしてから比べる（「らぴ」で「ラピ」が出る）。空白で区切った語は、すべてを含むものに絞る（AND）。
- 名前は日本語名と英語名のどちらかに含めば合う。
- バースト CT は、押した値のどれか（OR）。全段階のニケ（バースト段階が全）は値どおりに扱う。
- 項目どうしは AND。ニケ一覧の上のバッジ・宝物・お気に入りとも AND。
- 名前の検索は表を待たずに効く（index にある）。スキルの検索とバースト CT は表を読み終えるまで絞らない（読み込み中と出す）。

## 5. 第 2 段: スキルの効果・特殊攻撃・特性

- スキルの効果: catalog の効果の句（`classifyCharacters` の `effects`）から、stat の▲（`stat.canon`・`dir: 'up'`）を「自」（side が self）「味」（ally）に、▼で side が enemy のものを「敵」に分ける。分類（ダメージ・クリティカル・敵デバフ・連射と武器・回復と耐久・バースト・マイナス効果）は旧プロジェクトの並びを手本に、canon から分類への表を作る。
- 項目は `FILTER_EFFECTS`（分類: ダメージ・クリティカル・連射と武器・回復と耐久・バースト・敵デバフ）。自・味は stat の▲と、受けるダメージの▼、stat でない効果（回復・バリア・弾丸チャージ・バースト CT 短縮・バーストゲージ増加・フルバースト時間延長）。敵は受けるダメージ▲・防御力▼・攻撃力▼・挑発・スタン。挑発には、自分の側の句に読まれる「敵全体を挑発」（ヘイト。`control:selfTaunt`）も数える。窓には、表にある項目と側だけを出す。
- 旧プロジェクトの「マイナス効果」（自分の HP の消費・装弾数の減少など）は置かない（件数が少なく、絞る用途が見えない）。
- 同じ効果の自・味は OR、効果どうしは AND（旧プロジェクトの `matchesSkillTagFilter` と同じ）。特殊攻撃・特性は、押したもののどれか（OR。バッジの絞り込みの同じ種類と同じ）。
- 特殊攻撃: 貫通（説明文の「貫通特化」。単独の句のほか、使用武器変更の中の「追加効果:貫通特化」にも書かれる）・持続（`damage:dot`）・分配（`damage:distributed`）・防御力無視（`damage:true`・`damage:burstTrue`・`flag:trueDamageConversion`）・順番に攻撃（説明文の「順番に攻撃」）・使用武器変更（kind `weaponChange`）。
- 特性: バースト再突入（`burst:reentry`）・分割リロード（`shot.reloadBullet < 1`）。宝ものはニケ一覧の上のバッジの絞り込みにあるので、窓には置かない。
- 表（filter.json）には、1 体ごとのタグの配列（`effects`・`special`・`traits`）を足す。作る関数（`filterTableBuild.ts`）は catalog を使うので、画面と Worker が読み込む `index.ts` からは出さない。
