# 設計書: 維持時間のある回復（吸収回復）の付き直しで `healed` を起こさない

- 状態: 実装済み
- 根拠: V-0024（録画 078）、C-0082（仮説・単独実測）。関連: V-0022・C-0077、[design-asuka.md](design-asuka.md)、[design-stage11.md](design-stage11.md) 3.3 節（回復の 2 段）、[design-stage6.md](design-stage6.md) 8 節の 2（上書き延長）

## Context

- アスカ（830）の S1「回復効果が適用された時、自分の攻撃力▲（25 秒）」は、トリガー `healed` で書いてある。`healed` は、`heal` 効果の対象になったフレームに起きる（design-stage11.md 3.3 節）。
- V-0024 で、ユニ（160）の S2 の吸収回復（フルチャージの攻撃ごとに味方全体へ「攻撃ダメージの 2.77% 回復」「10 秒間維持」）と組むと、S1 は最初の 1 回だけ付き、25 秒で切れた後、付き直しが 64 回あっても付かなかった（C-0082）。
- いまの `heal` でユニの S2 を書くと、付き直しのたびに `healed` が起き、S1 は切れない（V-0024 の仮説 A）。録画 078 と合わないので、V-0024 ではユニの S2 を定義に足していない。
- その結果、いまのモデルでは「ユニ + アスカ」の編成で S1 が一度も付かない。実測は最初の 25 秒だけ付く。アスカの 1 発で約 2 倍の差が 25 秒続く。

## 1. 案

### 1.1 `heal` に維持時間を足す（推奨）

**意味**: 維持時間のある回復（吸収回復・持続回復）。対象の枠に、同じ効果の窓が付いていないときだけ `healed` を起こす。付いている間に付き直したら、窓を延ばすだけで `healed` は起こさない。

```json
{ "kind": "heal", "trigger": { "count": "fullChargeShot" }, "target": "allies", "ref": 3, "durationRef": 4 }
```

- **書ける項目**: いまの `heal` の項目に、`durationRef`（または `durationSeconds`）を任意で足す。無ければいまのまま（付くたびに `healed`）。
- **窓の単位**: 効果（出どころの枠 × 効果）ごと、対象の枠ごと。出どころの違う吸収回復は別の窓とみなす（2 節の論点 1）。
- **窓の延び方**: 付き直しで `[付き直し, 付き直し + 維持)` まで延ばす（上書き延長。design-stage6.md 8 節の 2 と同じ）。
- **回復のフレーム**: いまの `healFrameOf` のまま（射撃の回数起点なら次のフレーム）。窓もそのフレームから数える。
- **検証の規則**: いまの `heal` と同じ（トリガーに `healed`・対象に `topAttack` は書けない）。

**実装**（2 か所を同じ規則にする。design-stage11.md 3.3 節の 2 段は変わらない）

1. `skills/heals.ts` の `planHeals`: 効果ごと・対象の枠ごとに窓の終わりを持ち、回復のフレームが窓の中なら記録を足さずに窓を延ばす。
2. `frame/firstPass.ts` の回復の当て方: 同じ規則で、窓の中なら `healed` を立てず、`instants` にも積まない（CLI の「instant effects」の表に出るのは、`healed` を起こした回復だけになる）。
3. `skills/types.ts` の `HealEffect` に `durationRef?`・`durationSeconds?`、`parseSkillDefinition` の検証、`resolve.ts` の解決。単体テスト。
4. sim と calc の整合のテスト（ユニ + アスカの編成）。

**定義**

- ユニ（160）の S2: 上の `heal` を足す（`ref: 3`・`durationRef: 4`）。notes の「攻撃ダメージの回復はダメージに関係しない」は、「回復量はダメージに関係しない」に直す。
- アスカ（830）のバーストの `heal`: `durationRef: 5` を足す。バーストの間隔は 10 秒より長いので、数値は変わらない見込み（既存のテストで確かめる）。`assumes` の文言を、窓の読みに合わせて直す。
- ほかの `heal`（クラウンの S2 など、1 回の回復）は触らない。

**退化の見込み**: 維持時間を書かない `heal` の振る舞いは変わらない。アスカのバーストの `heal` に維持時間を足しても、アスカのバーストの間隔（約 40 秒）では窓が重ならないので、既存のテストの数値は変わらない見込み。

**録画 078 での予測**: ユニの最初のフルチャージの攻撃（モデルでは 1.92 秒）で S1 が付き、25 秒で切れ、以後は付かない。ユニの 1 発の間隔（モデルで最長 5.61 秒）は 10 秒より短いので、窓は切れない。

### 1.2 ユニの S2 を足さないまま（代わりの案）

- いまのまま、ユニの S2 の吸収回復を notes の未対応にする（「付いた時の 1 回だけ S1 などの `healed` を起こす。付き直しでは起こさない。未実装」）。
- 語彙は増えないが、ユニ + アスカ（やクラウンなど `healed` の効果）の編成で、最初の 1 回が欠ける。

## 2. 論点（オーナーに決めてもらうこと）

1. **出どころの違う吸収回復を別の窓にするか**
   - **推奨: 別の窓にする（仮置き）**。録画 078・063 のどちらにも、出どころの違う吸収回復が重なる場面が無く、根拠が無い。別の窓なら、ユニの吸収回復が付いている間のアスカのバーストでも S1 が起き、いまのモデル（バーストで S1 が付く）の振る舞いを変えない。
   - 見分ける撮影は V-0024 の「次に撮るもの」（ユニ + I + アスカ）。別の検証記録にする。
2. **1.1 を V-0024 の PR に入れるか、別の PR にするか**
   - **推奨: 別の PR**。V-0024 の PR は、撮影・観測値・結論（C-0082）と、この起案まで。手順書 0 節の「1 体 1 PR」はユニの定義の PR として、1.1 の語彙と一緒に出す。
3. **`healed` で起きる効果が、発動中にもう一度起きたときに延びるか**
   - この設計では扱わない（上書き延長のまま）。録画 078・063 のどちらにも、S1 の発動中に S1 が起きる場面が無い。論点 1 の撮影で、出どころが違えば起きる場合に、延びるかも見える。

## 3. リスク・留意点

- `healed` を起こす効果が「窓の中の付き直しでは起きない」のは、アスカの S1 で 1 本の録画に基づく（C-0082 は仮説）。クラウンの S2 など、ほかの `healed` の効果にも同じ規則が効くことになる。1 回の回復（維持時間なし）は変わらない。
- ユニ以外の吸収回復（全キャラの説明文に「攻撃ダメージの〜回復」は 25 体。design-asuka.md 2.1 節）は、定義するときに `durationRef` を付ける。
