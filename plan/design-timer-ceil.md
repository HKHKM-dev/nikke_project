## 0. 分かったこと

| 結論   | 中身                                                                                                                                                                                                            | いまのモデル                                          |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| C-0432 | N 秒ごとのスキル（ソルジャーE.G.・ニヒリスター・イサベル・エーテル・ラピの S2）の発動の間隔は ceil(N ÷ 0.017) ティック（9 秒 530・10 秒 589・15 秒 883・20 秒 1,177）。発動のたびに数え直し、端数を持ち越さない | `timerFrames` は k × N 秒を四捨五入（端数を持ち越す） |
| C-0453 | 倍率ダメージのヒットは、発動から一定の遅れ（ラピ 98f・エーテル約 50f・イサベル約 44f・ニヒリスター約 12〜13f）で出る。「1 回目の遅れ」（ニヒリスター 18f など）はこれ                                           | 遅れなし（発動のフレームにヒット）                    |
| C-0454 | 持続ダメージの k 回目の tick は、起点から k 間隔（atApplication は 1 回目の tick の 1f 前から k + 0.5 秒）に達した最初のフレーム（ceil）。付き直しで数え直さないので端数が積み上がる                            | `dotTickTracker` は四捨五入                           |

3 つとも「ゲーム内の時刻が T に達した最初のフレームで起きる」形で、モデルの四捨五入とは 1f ずつ違う。

- 2026-10-08 の追記: たきなの S2 の帯（`308-02`。単騎・バーストなし）は 8 回の間隔がすべて 883f で、ceil の形と合う（持ち越しなら約 5 回は 882f）。フルバーストのある多人数の録画では、入りをまたぐ周期が入り 1 回あたり約 0.5 ティック長い（V-0325。モデルには入れない）。

- 2026-10-08 の追記（V-0321）: クルミのハッキング（058〜060、456 tick）も ceil(φ + k × 58.8235) の形だが、起点の位相 φ はまとまりごとに違い、77% の tick は 0 付近、23% は 0.3〜0.65（四捨五入に近い）。レイヴン（122）は 0 付近が多い。付く瞬間の時刻がフレームの途中として扱われるためかもしれない（未確かめ）。φ がばらつくなら、四捨五入（φ = 0.5）は平均の形として悪くないので、論点 2 の持続ダメージの側は「レイヴン型（φ = 0）に合わせるか、今のままにするか」になる。
- 2026-10-08 の追記（V-0326。探索）: ミハラのチェーンバインド（持続・スタックのまま約 1 秒ごと）の tick は、ゲーム内のティックで平均 59.25 で、端数を持ち越す形（58.82）より、1 回ごとに数え直す形（59。周期のスキルと同じ）に近い。持続ダメージの種類で刻み方が違うかもしれない（ミハラの定義は無いので、このブランチの実装には効かない）。

## 2. 論点（オーナーの判断）

1. **C-0432・C-0454 を確定にするか**。どちらも最小構成の単騎の録画（ソルジャーE.G. 3 本・レイヴン 122）で、読む前に固定した予測のうち ceil だけが合った（反復実測）。モデルと比べる観測値が無く、道具は等級の候補を出せない（C-0289 と同じ扱いの判断）。
2. **`timerFrames` と `dotTickTracker` を ceil にするか**（推奨: する。上の表のとおり残差が縮み、悪くなる所が無い）。与ダメージの効きは、窓の端をまたぐ発動・tick の 1f だけ。
   - 周期のスキルで根拠の無いもの: エマ：TU の環境コントロール（再発動周期 30 秒）・I-DOLL・フラワーの S2（15 秒）も `everySeconds` なので一緒に動く。フラワーは表示の `077-25` が ceil と合う（V-0302 の出どころ。883.14 ティック）。エマ：TU は読んでいない。
3. **アニス：スターのシューティングスターの刻み**: いまのモデルは「最後の刻みがチェーンの待ちの明け（I の発動から 10 秒 = `gameSecondsToFrames(10)` = 588f。切り捨て）と同じフレームで、溜まらない」（`anisStarGaugeTiming.test.ts`。C-0240）。持続ダメージの刻みを ceil にすると最後の刻みは 589f になり、明けの後になる。明けの側も「10 秒に達した最初のフレーム」（589f）で数えるのか、刻みだけを変えるのかを決める必要がある。
   - 案 A: 刻みだけ ceil にし、シューティングスターの刻みは今の置き方のまま残す（C-0240 は「明けの 9〜24f 後の当たり」で、ここを変える根拠はまだ無い）。
   - 案 B: チェーンの待ち・持続の終わりなど、ほかの時計も ceil で揃える（C-0050 の「7 秒は 411f」など、確定の結論の読み方の見直しが要る。範囲が広いので別の設計にする）。
   - 案 C（採用）: 持続ダメージの刻みは、シューティングスターも含めてすべて ceil にし、チェーンの待ちの明けは今のまま（切り捨て）。例外を作らず、飛ぶ時間のある実際のモデルでは比べる観測値が動かない（3 節の 3）。合成テストの最後の刻みは明けの 1f 後になる
4. **周期のスキルのヒットの遅れ（C-0453）を `delayFrames` で書くか**: ニヒリスターの S2（定義あり）は、ceil の周期 + 約 15f の遅れで `084-11` の −17 が消える見込み（backlog 4-11 の「1 回目を 18f 遅らせるか」の答えになる）。イサベル・ラピ・エーテルの S2 は、定義に入れるとき（4-12〜4-14）に一緒に書く。 2026-10-08 の手元の試し: `delayFrames` の検査（いまはバースト使用時と「付いた時」だけ）に周期のきっかけを足し、ニヒリスターの S2 に `delayFrames: 15` を書くと、`084-11` は −17 → −2（許容内）。イサベル・ラピ・エーテルの S2 を定義に入れるなら、いまの観測値の setup が S2 を `addEffects` で足しているので（`019-19`・`162-33`・`221-10` など）、そこから外す直しと、`038-24`〜`038-26` の n の直しがセットになる。

## 3. 実装（このブランチに用意したもの）

1. `time.ts` に、ゲーム内の秒 → その時刻に達した最初のフレーム（`Math.ceil(seconds ÷ 0.017 − 1e-9)`）を足す。
2. `timerFrames`: 発火は k × ceil(N ÷ 0.017)。戦闘の終わりの判定はフレームで。
3. `dotTickTracker` の `offset`: afterInterval は ceil((k + 1) × 間隔)、atApplication の k ≥ 1 は ceil(k × 間隔 + 0.5) − 1。シューティングスターの刻みも同じ置き方になり、合成テスト（`anisStarGaugeTiming.test.ts`。飛ぶ時間なし）の最後の刻みはチェーンの待ちの明けの 1f 後になる。飛ぶ時間のある実際のモデルでは、比べる観測値は動かない（1 節の試し）。論点 3 の案 A（刻みを今のまま残す）にするなら、ここを分ける。
4. 単体テストの期待値を直す（`dot.test.ts` の atApplication の列は録画 081 の 0・88・147・205・264・323・382・441・499・558 になる）。
5. `npm run records:check` で 1 節の表の動きを確かめ、C-0432・C-0454 の `model` を書き換える。

## 4. 参考: 発動の止まり（C-0289）を動画のフレームの換算に足すと（手元の試し。2026-10-08）

1 節の ceil の変更の上に、`burst/schedule.ts` の `videoFrameOf` で、frame より前の I・II の発動（フルバーストの入りでないもの）ごとに 1f を足した（[design-clock-stalls.md](design-clock-stalls.md) 2.3 節の案 B。決定は A = 足さない。C-0261 が仮説だったため。その後 C-0289（発動のたびにゲーム全体が 1 ティック止まる）は確定になった）。

- 縮んだもの: `084-10`（−1 → 0）・`162-34`（−1.2 → +0.1）・`165-36`（−1.3 → 0）が許容内に入る。戦闘の終わりの動画のフレーム `018-06`・`019-06`・`020-04`・`021-04`・`047-08` は −8〜−10 → 0〜+2。`221-11` は −1.97 → −0.54、`163-02`・`162-01` も縮む。
- 広がったもの: 発動からヒットまでを測るバーストの遅れ `063-10`・`080-08`・`081-20`・`085-06` が +1 → +2 で許容外（ほかに `077-28`・`084-07`・`134-06` が 0 → +1）。これらの遅れの定数は、発動の止まりの 1f を含んだ動画のフレームで決めてあるので、止まりを換算に足すなら定数を 1f 減らす直しとセットになる。

## 5. 決定（2026-10-08。オーナー）

1. C-0432 を確定（反復実測）にする。
2. C-0454 は仮説のままにする（クルミの起点の位相 φ のばらつき（V-0321）と、ミハラのチェーンバインドの刻み（V-0326）が分かるまで）。モデルは ceil の形（φ = 0）にする（論点 2）。
3. C-0453 を確定（反復実測）にする。
4. `timerFrames` と `dotTickTracker` を ceil にする（論点 2。3 節の実装）。最新の main（イサベル・ラピ・エーテルの S2 が定義に入った後）で、許容外の残差は 32 → 28。新しく許容外になったものは無い。
5. 論点 3 は案 C（3 節の実装のまま）。
6. 論点 4（周期のスキルのヒットの遅れを `delayFrames` で書く）は、この設計とは分けて行う（backlog 4-20）。
7. 論点 5（発動の止まりを動画のフレームの換算に足す）は、足す方向で、バーストの遅れの定数の見直しとセットの別の設計にする（backlog 4-21）。

## 6. 周期のスキルのヒットの遅れの実装（backlog 4-11〜4-14・4-20。2026-10-09）

2026-10-09 のオーナーの判断（推奨どおり）で、2 節の論点 4 を実装した。

1. **語彙**: 時間の周期のトリガー（`{ everySeconds }`）の `damage` にも `delayFrames` を書けるようにした（`skills/types.ts` の検査。いままでは `burstUse` と `{ applied }` だけ）。ヒットは発動のフレームの `delayFrames` 後に、そのフレームのバフで出る（`frame/plan.ts` の `planSkillHits` は変えていない）。画面の注記は「発動の X 秒後」と出す。
2. **値**（C-0453）: 遅れは、モデルの発動のフレーム（戦闘開始から k × ceil(N ÷ 0.017)）からヒットまで。帯（左の「スキル2」）は発動の約 2 ティック後に出るので、帯からヒットまでより長い。
   - 単騎の録画の 1 回目のヒットがあるキャラは、それから決めた: イサベル 45f（`008-05` のヒット 928f − 883）、ラピ 101f（`028-06`・`029-04`・`030-03` の 1,277〜1,278f − 1,177 の多いほう）。
   - 無いキャラは、帯からヒットまでの典型値に、発動から帯までの約 2 ティック（1 回目の帯が ceil + 1.6〜3.1 ティック。V-0313・V-0320）を足した: ニヒリスター 13 + 2 = 15f、エーテル 50 + 2 = 52f。
3. **ゲージ**: S2 のヒットのゲージ（`burstGaugeHit`。イサベル C-0404・エーテルとラピ C-0409。どちらも仮説・推論）は、定義にあるまま、発動のフレームに足す。ゲージが発動とヒットのどちらで溜まるかは V-0313 で「分からないこと」としたので、遅らせなかった（backlog 4-22）。手元の試しでゲージにも同じ遅れを入れると、モデルのラピのフルバーストの 3 回目が 10f 早まり（5458 → 5448）、代表のフレーム 6040 で比べる `221-18`・`366-05`（確定の C-0457・C-0469 の根拠）が窓の外になった（−18,300）。代表のフレームが窓の終わりの 6f 前にあったためで、遅らせるなら代表のフレームの置き直しとセットになる。ニヒリスターの S2 のヒットがゲージを溜めるかは根拠が無いので、定義には入れず notes（未対応）に書いた。
4. **残差**（`npm run records:check`）: `084-11` が −17 → −2 で許容内に入った。ほかに動いた観測値は無い（イサベル・ラピ・エーテルの S2 の平均の間隔・回数・値は、遅れでは変わらない。`038-24`〜`038-26` の n は許容内のままで、直す必要は無かった）。
5. **結論**:
   - C-0403（ラピ）を確定（厳密一致）にした。根拠の観測値はどれも許容内。最小構成の警告に残ったラピの S2 のゲージ（時刻と回数の組）とラピの S1（値の組）には、11.6 節の付け方で印を付けた（[design-minimal-relevance.md](design-minimal-relevance.md) 11.6 節）。
   - C-0401（ニヒリスター）・C-0402（イサベル）は仮説のまま。根拠の平均の間隔 `084-10`・`162-34`・`165-36` が、I・II の発動の止まり（C-0289）を動画のフレームの換算に足していないため許容外に残る（確定の結論の根拠は `npm test` で落ちる。許容外の観測値を根拠から外す案は 2026-10-08 にとらないと決まっている）。backlog 4-21 の後に確定にする。
   - C-0091（棄却。C-0401 に置き換え済み）の「周期 590.2f」は ceil の 589 ティックとあいだの止まり、「1 回目の 18f」は遅れ 15f と 1 回目の前の I・II の発動の止まりで説明がつく（C-0401 の根拠に書いた）。
   - C-0405（エーテル）は確定のまま、C-0453 の `model` を反映にした。
