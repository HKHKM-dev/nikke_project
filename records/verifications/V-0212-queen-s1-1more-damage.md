## 条件

- 説明文（スキル Lv10）:
  - S1「1more が適用された時、敵全体に最終攻撃力の 548.99% の分配ダメージ」
  - バースト「対象が風圧コードなら自分に 1more」
  - 「1more が適用された時」は、風圧の敵にバーストを撃った時と読む（設計書 3.6 節）。
- 定義（このブランチ）: S1 に `damage`・`burstUse`・`distributed`・`enemyElement: Wind`（C-0309。仮説・推論）。ヒットの値は、ほかのバースト使用時の倍率ダメージと同じ規則で決まる。
  - 撃つ側のバフは、発動の直前で固定する（`frame/plan.ts` の `BURST_HIT_USES_PRE_ACTIVATION_BUFFS`）。同じ発動で付く 1more の攻撃力▲と S2 の▲（V-0211）は乗らない。
  - フルバースト中に出た倍率ダメージには、フルバースト補正 +0.5 が乗る（`damage.ts` の `SKILL_HIT_FULL_BURST_BONUS`）。バーストの倍率ダメージには乗らない。
  - バースト使用のフレームはフルバーストの始まりと同じなので、モデルでは乗る。
- **分からないこと（仮説で分ける）**: このヒットに、次の 3 つのどれが乗るか。どれも 1more と同じフレームの出来事で、説明文からは決まらない。
  - フルバースト補正
  - 1more の攻撃力▲
  - S2 の▲
- **バーストのヒットとの比で読む**:
  - 1more のヒットとバーストのヒット（最終攻撃力の 1421.69% の分配ダメージ）は、同じ攻撃力・攻撃ダメージ▲・分配ダメージ▲・S1 の▲を持つ。
  - 比は 548.99 / 1421.69 に、上の 3 つのうち 1more のヒットにだけ乗るものを掛けた値になる。
  - バーストのヒットの値そのもの（バーストの effects[0] と S2 の分配ダメージ▲。C-0231 は時刻だけ）は、灼熱の録画で先に確かめる。凍結の記録の録画 021 で端数まで合っているが、最小構成でない。
- **最小構成と V-0171・V-0211 との関係**:
  - 編成と録画は V-0211 と同じ（ラム + デルタ + クイーン（真）、風圧タブと灼熱タブ）。
  - ヒットの値は S1 の▲の形（V-0171）で変わる。比べる順は次のとおり。
    1. V-0171
    2. 灼熱のバーストのヒット（この記録の `burst-fire`）
    3. 風圧のバーストのヒット（`burst-wind`）
    4. 1more のヒット（`onemore-wind`）
  - 2 と 3 が合えば、1more のヒットの未確定の要素は、このヒットの式と、上の 3 つの乗り方だけになる。
  - V-0211 の結論（S2 の▲と攻撃力▲の値）は、このヒットに乗る仮説の値を決めるのに使う。

## 読み方

1. V-0211 の読み方の 1 と同じく、戦闘開始と III の発動を決める。
2. III の発動の後のバーストのヒット（灼熱で 420 万ほど）を、V-0147 と同じく HUD の数字を 1 フレームずつ読んで拾う（FULL BURST の表示が HUD に重なり、`hud.ts` は拾えない）。
3. 風圧では、その前後のフレームの HUD の増分と、的の上のポップアップから 1more のヒットを探す。値は仮説の表の 200 万〜500 万ほど。
4. 1 回目のバーストは S1 の戦闘開始時の攻撃力▲（15 秒）の中なので、比べるのは 2 回目以降にする。1 回目は記録だけする。
5. 観測値の `compare` は、予測ファイルの指標と同じ `metric`・`args`・`setup` にする（n は予測ファイルの値のまま。2 回目以降のどの回でも同じ値になる）。

## 分かったこと・分からないこと

- **S1 の 1more の分配ダメージは、風圧の敵にバーストを撃つたびに 1 回、バーストのヒットの 23〜24f 後に出る。値は最終攻撃力の 548.99% の分配ダメージ（分配ダメージ▲が乗る）で、フルバースト補正と、同じ発動で付く 1more の攻撃力▲・S2 の▲が乗る**（G3。`229-05`〜`229-07`・`230-05`）。C-0309（同じ発動の効果は乗らない）は外れた。
- **バーストの倍率ダメージのヒットは、風圧の敵でも発動の直前のバフで固定される**（`229-04`。1more の攻撃力▲も S2 の▲も乗らない）。分配ダメージにも S1 の▲（C-0296）が乗る。
- モデル: G3 を表す語彙 `delayFrames`（damage のきっかけの後のフレームに、そのフレームのバフで出す）を足し、クイーン（真）は 24（2026-10-06 にオーナーが承認。plan/design-delayed-skill-hit.md）。`229-05`〜`229-06`・`230-05` は許容内になった。C-0309 を棄却し、C-0310 で置き換えた。
- 分からないこと: 雪子（871）の S1 の同じ言い回しは撮っていない（遅れの値は雪子では測っていない）。
