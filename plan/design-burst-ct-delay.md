## Context

- roadmap の「バーストの段の間隔」（2026-09-28）は、段の間隔を 29f に較正した（C-0073）残りとして、「CT が明けてから発動までの 4〜7f（モデルに無い）」を挙げていた。出どころは V-0017・V-0021 の散文で、結論にはなっていなかった。値は、CT が 0 になるフレーム（右のバースト欄の 1/100 秒の表示）と、発動のフレーム（次の段のタイマー・アイコン、欄の新しい CT の秒）を比べたもの。
- この設計のために V-0164 で既存の録画（018・019・021・063）を読み直した。読む前に予測を commit した（`records/predictions/V-0164.json`）。

## 0. 今わかっていること

- **モデル**: `burst/controller.ts` の `pickCandidate` は、CT が明けたフレーム（`cooldownEnd[i] <= frame`）から撃つ。CT は `gameSecondsToFrames`（ゲーム内の 0.017 秒/f、切り捨て）。段の長さは各 29f（C-0073）で、段の終わりより後に CT が明けたら、明けたフレームに撃つ。状態機械は `frame/firstPass.ts` の 1 パス目で回り、sim と calc は同じ時刻表を使う。手動バーストはモデルに無い（どの枠も自動バースト）。
- **4〜7f は表示の遅れだった**（C-0258、仮説）:
  - 欄の表示は、CT の 0 → 顔が明るくなる → 新しい CT の秒 → 次の段のアイコン、の順に替わる（`018-18`・`019-12`・`019-13`・`021-18`）。ゲージが律速の回も、新しい CT の秒 → 次の段のアイコンの並びは同じ（`063-11`）。
  - 本当の発動（CT がまた走り出すフレーム）は、表示ではなく、CT の 0 どうしの間隔から出した: 間隔 − あいだのフルバーストの入りの止まり（C-0069。録画ごとの値）− その録画の時計で数えた CT（`018-19`・`019-14`・`021-19`）。CT の 0 から 1f ほどで、新しい CT の秒が出るフレーム（3〜4f 後）ではない。
  - したがって、CT が律速のときの発動は、いまのモデル（遅れ 0）と 1f 以内で合う。4〜7f は、遅れの無い表示（CT の 0）と遅れて出る表示（発動の印）を比べた差。
  - 段（満タンで I を待つ回・チェーン中の II・III）でもキャラでも違いは見えない（V-0164 の D3 は外れ）。
- **フルバーストの入りの間隔の残差**: CT が律速の編成で、入りの間隔はモデルより数 f 長い（`019-15`・`163-02` など。どれも許容内）。`019-15` の差は、モデルの時計（40 秒 = 2,352f。0.017 秒/f の切り捨て）と止まり（22f）が、その録画の時計の傾きと止まりの長さより短いことでほぼ説明でき、残りが 1f ほど（C-0258 の幅）。

## 1. 方針

- **4〜7f の遅れはモデルに入れない**。遅れは表示のもので、ゲームの中の発動は遅れていない（C-0258）。入れると、フルバーストの入りの間隔の残差のうち、時計と止まりの違いの分まで遅れの定数で埋めることになる（AGENTS.md「残差を係数で埋めない」）。
- 残る 1f 以内の差（CT の切り捨てと、明けた後のフレームに撃つことの差）をどう扱うかを 2 節で決める。

## 2. 論点（オーナーの判断）

### 2.1 CT 明けの 1f 以内の差

| 案                       | 中身                                                                                                                             | 効き                                                                                                                                                                  |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A（推奨）: 変えない**  | 遅れ 0 のまま。C-0258 を記録し、課題 2-10 を閉じる                                                                               | なし                                                                                                                                                                  |
| B: CT の明けを切り上げる | 枠の CT を `ceil(秒 ÷ 0.017)` にする（「CT が明けた後の最初のフレームに撃つ」）。CT▼（`reduceCooldown`）の秒も同じ丸めにそろえる | CT が律速の発動が 1 回あたり最大 1f 遅れる（40 秒は 2,352 → 2,353f、20 秒は 1,176 → 1,177f）。180 秒でフルバーストの入りが最大 4〜9f 遅れ、与ダメージはほぼ変わらない |
| C: 4〜7f の定数を足す    | 却下（1 節）                                                                                                                     | —                                                                                                                                                                     |

- A を推す理由:
  - B の 1f は、録画ごとの時計の傾きの違い（2.3 節）より小さく、いまの観測値ではどちらが合うか見分けられない（許容は ±90f）。
  - C-0258 は仮説（等級は単独実測。録画 018〜021 は最小構成の警告がある）で、切り上げの根拠には弱い。
  - スキルの持続は切り捨てで端数まで合っている（C-0050）。CT だけ丸めを変えるなら、時計の傾きの検証（2.3 節）で CT の秒の数え方を確かめてからにしたい。
- B にするなら、実装は 4 節。

### 2.2 C-0258 の状態

- `records:new` の候補どおり **仮説・単独実測** にする（推奨）。3 本の録画でそろっているが、エーテル・ラピなどの機構が確定していない（最小構成の警告）。ただ、見ている事象は右のバースト欄の CT と発動で、未確定のスキルのうち CT に効くもの（`cooldownReduction`）はこの編成に無い。オーナーが「CT に効かないスキルの未確定は、この事象には影響しない」と判断するなら、反復実測・確定にしてよい。

### 2.3 派生した問い（起票するか）

V-0164 の読み直しで、次の 2 つが見えた。どちらもこの課題とは別の機構なので、起票するかを決めてほしい（起票するなら roadmap の「今後の課題」に書き、backlog に 1 行足す）。

1. **満タン → I の段の長さ**: C-0073 の I の段は「BURST バーが消えてから II のアイコンまで」で数えた。II のアイコンは本当の発動の約 6f 後に出る（V-0164）ので、バーが消える表示の遅れがそれより短ければ、本当の満タン → I は 29f より短い。モデルはゲージが律速の回の I を数 f 遅く撃っているかもしれない。I → II・II → III は同じ種類の印どうしなので影響しない。既存の録画の読み直しで確かめられる（ゲージが律速の回で、満タンの発（V-0025 の「消えるのは発が当たったフレーム」）から新しい CT の秒まで）。
2. **録画ごとの時計の傾き**: V-0017 で録画ごとに当てはめた時計の傾き（`018-05`・`019-05`・`042-02` などの注記）は、C-0048 の範囲とモデル（0.017 秒/f）より大きい録画がある。CT が律速の編成のフルバーストの入りの間隔の残差（`019-15`・`163-02` など）の大半はこれと止まりの長さの差とみられる。C-0048 の範囲を見直すか、録画の素性として扱うかの検証になる。

## 3. 自動バースト・手動バースト、calc と sim、残差の見込み

- **自動バースト**: A ではモデルは変わらない。B なら CT が律速の発動だけ最大 1f 遅れる。ゲージが律速の発動（段の 29f で決まる）は変わらない。
- **手動バースト**: モデルに無い（どの枠も自動バースト。撃つ時刻は人の反応で決まる）。この課題では扱わない。録画では 064・065・085・189 が自動バースト OFF。
- **calc と sim**: 時刻表は 1 パス目の状態機械（`frame/firstPass.ts`）で 1 つだけ作り、両方が使う。A では両方とも変わらない。B なら両方のフルバーストの窓が同じだけずれる。
- **残差の見込み**:
  - A: `plan/residuals.md` は変わらない。
  - B: CT が律速の編成のフルバーストの入りの間隔（`019-15`・`163-02`・`162-01`・`165-12`）が 1 回あたり最大 1f ずつ実測に近づく。戦闘の長さ（`018-06` など。止まりの回数で決まる）は変わらない。フルバーストの入りと比べるほかの観測値（着弾の遅れ・`fullBurstToNextActivation` など）は、CT が律速の回だけ 1f 以内で動く。戦闘の終わり近くで入りがまたぐときだけ、フルバーストの回数が変わりうる。

## 4. 実装

### A（推奨）の場合

コードは変えない。

1. V-0164 を閉じる（`npm run records:close -- V-0164 --mark`）。
2. C-0258 の `model` は「遅れ 0 のまま。1f 以内の差は未反映」（いまの文）。
3. roadmap の「バーストの段の間隔」の項に、残りの 4〜7f は表示の遅れだった（V-0164、C-0258）と書いて閉じる。
4. `plan/backlog.md` の 2-10 の行を消す（課題が閉じたら行を消す）。2.3 節を起票するなら、roadmap に書いてから 1 行ずつ足す。
5. この設計書の状態を「決定（モデルは変えない）」にする。

### B の場合

1. `time.ts` に CT 用の換算（切り上げ）を足し、`burst/dynamic.ts` の `burstUnitOf` の `cooldownFrames` と、CT▼の秒の換算をそれにする。根拠の ID（C-0258）をコメントに書く。
2. `burst/__tests__/controller.test.ts` ほか、CT のフレーム数を直書きしているテストを直す（値が変わるだけ）。
3. `npm test` と `npm run records:check` で残差の動きを確かめ、3 節の見込みと比べて検証記録に書く。
4. 以降は A の 1〜5 と同じ（C-0258 の `model` は B の実装を書く）。
